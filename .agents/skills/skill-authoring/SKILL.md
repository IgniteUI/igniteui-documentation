# Ignite UI documentation — Skill Authoring

Quick-reference for writing a `SKILL.md` that agents can discover and load reliably.

## Where a skill belongs

Every skill in this repo is internal — contributor-facing tooling, not something shipped to users.
There are two canonical directories, and which one you pick is decided by tooling, not by taste:

- **`.agents/skills/<name>/SKILL.md`** — the default. Codex scans this path, and it is where the
  Agent Skills ecosystem has converged.
- **`.github/skills/<name>/SKILL.md`** — only when GitHub Agentic Workflows must see the skill. The
  gh-aw compiler bakes `GH_AW_SKILL_DIR: ".github/skills"` into every `*.lock.yml`, so a skill moved
  out of there becomes invisible to the JP sync workflows.

A name may exist in **one** of those directories, never both. `.claude/skills/` is generated; never
put a canonical skill there.

## Naming

- Plain kebab-case, lowercase letters, numbers and single hyphens.
- No product prefix is required. Internal skills are named after the task
  (`docfx-sync`, `skill-authoring`), and the older `igniteui-` and `xplat-docs-` prefixes are kept
  for continuity rather than copied into new skills.
- **The folder name and the `name` field must be identical.** This is a spec requirement, and
  `npm run skills:check` fails when they diverge.

## Frontmatter

| Field | Rules |
|---|---|
| `license` | Required here. Use `MIT`, matching `igniteui-angular` and `igniteui-webcomponents`. |
| `name` | Required. Max 64 characters. Lowercase letters, numbers and hyphens only. No leading, trailing or consecutive hyphens. Must match the folder name. |
| `description` | Required. Non-empty, **max 1024 characters**. No XML tags. |
| `user-invocable` | Set `true` so the skill can be invoked by name as well as matched automatically. |

Write the description in the third person: say what the skill covers, then add both markers:

- `WHEN TO USE:` the tasks or triggers that should load the skill.
- `WHEN NOT TO USE:` nearby tasks it does not cover, naming the skill to use instead.

Agents see only `name` and `description` until they load the skill, so the description decides
whether it is ever used. The 1024-character limit is a hard one — a description over it is invalid,
and the pointer copies it verbatim, so the breach is duplicated.

## Token budget

- Keep the `SKILL.md` body under 500 lines.
- If it grows past that, use progressive disclosure: keep the overview and core rules in `SKILL.md`
  and move detail into `references/<topic>.md`.
- Link each reference file directly from `SKILL.md`, one level deep, and say when to read it, so
  agents load it only when they need it.

## One rule, one place

A rule is stated once, in the skill that owns it, and referenced everywhere else. Do not restate
another skill's rules, and do not copy them into `.github/CONTRIBUTING.md`, a README or a guide
under `docs/`. If two files disagree, readers follow the longer one, which is how the ApiLink
guidance drifted before it was consolidated.

Point at the owner instead:

- Topic structure and templates → `igniteui-doc-topics`
- MDX topic frontmatter → `igniteui-topic-frontmatter`
- `ApiLink` markup → `xplat-docs-api-links`
- `PlatformBlock` → `xplat-docs-platform-block`
- docfx sync conversions → `docfx-sync`

## Pointers

`.claude/skills/<name>/SKILL.md` is generated by `scripts/sync-agent-skills.mjs`, because Claude Code
discovers project skills only from `.claude/skills/`. A pointer carries the canonical `name` and
`description` verbatim and redirects to the canonical file. It holds no rules.

Never edit a pointer. After changing any `name` or `description`:

```sh
npm run skills:sync     # regenerate
npm run skills:check    # verify; also runs in CI and in npm run verify
```

## Checklist

1. The skill is in `.agents/skills/`, or in `.github/skills/` with a gh-aw reason.
2. Frontmatter passes the table above, and the folder name matches `name`.
3. The description includes `WHEN TO USE:` and `WHEN NOT TO USE:`, and is within 1024 characters.
4. The body is under 500 lines, and every reference file is linked from `SKILL.md`.
5. The skill states no rule another skill owns.
6. It is listed in the Skills table in [`.agents/README.md`](../../README.md).
7. `npm run skills:sync` has been run and the generated pointer is committed.
