## Specifying a Layout

### Overview

The `igLayoutManager` control supports several layouts. For a conceptual overview of each layout is and information about what it looks like, refer to `igLayoutManager` [**layouts summary chart**](#config-individual-layouts-summary-chart). ## Configuring the Border Layout

### Overview

The Border layout is configurable through the <ApiLink type="igLayoutManager" member="options:layoutMode" pkg="core" label="layoutMode" /> property of the control. The host HTML element of the control is `<div>` element. Child `<div>`s can be defined in the HTML markup of the host element, and upon initialization, the control will add the respective HTML elements and CSS classes.

Items are arranged through the respective class for each region. The Tile Manager uses the classes’ names to identify the regions and to position the items. The following table maps the regions to the mandatory class names that implement them.

| Region        | Class name |
| ------------- | ---------- |
| Header        | header     |
| Body          | center     |
| Footer        | footer     |
| Left Sidebar  | left       |
| Right Sidebar | right      |

<DocsAside type="note">
  If there are any children that do not have any of the above classes, they will not be used.
</DocsAside>

The visibility of the Header, Footer, and Sidebars is configurable, as well as the relative width of the Body and the Left Sidebar and Right Sidebars.

The default settings of the Border layout configure it with all regions visible with the width of the Left Sidebar set at 20% of the total container's width and the width of the Right Sidebar – at 10%. To hide some of the regions, you need to set the respective property (<ApiLink type="igLayoutManager" member="options:borderLayout.showHeader" pkg="core" label="showHeader" />, <ApiLink type="igLayoutManager" member="options:borderLayout.showFooter" pkg="core" label="showFooter" />, <ApiLink type="igLayoutManager" member="options:borderLayout.showLeft" pkg="core" label="showLeft" />, <ApiLink type="igLayoutManager" member="options:borderLayout.showRight" pkg="core" label="showRight" />) to false.

## <a id="confg-column-layout" />Configuring the Column Layout

### Overview

The Column Layout is a based on a 12-column grid system in which columns can be merged to accommodate the width of the items. This layout is implemented entirely in CSS so it doesn’t require the `igLayoutManager` to be instantiated. Its main advantages compared to the other layouts are:

- Minimum CSS to get it working properly – very few lines of CSS
- Simplest markup structure

When defining CSS classes, make that all their names are prefixed with an ig class on the container, so that that no other rules get overwritten. The items’ placeholders’ widths are defined through merging the desired number of columns on a particular row. A container can merge up to 12 columns, but the total number of columns merged/occupied by containers on an individual row must be 12. The naming convention of the `<div>` classes that implement the columns is `<colN>` where N is the number of columns merged for the class, e.g. col4 means that the placeholder merges over 4 columns while col1 means that the column is not merged, i.e. the placeholder occupies only one column of the grid.

Any number of rows can be nested in other containers marked as `<colN>`. In this case, the parent container that is marked as `<colN>` will be divided in 12 columns and the nested rows will calculate their widths according to the width of the parent. This means that if the parent container has a class col6 applied, it will merge six columns of the main container's 12 columns. If you place three rows in this container and each of them has a class col4 applied, then each one of them will merge 2 columns of the main container on the page.

### Minimum requirements

With the Column layout, there is no need to instantiate the `igLayoutManager`. You can only assign row class to a `<div>` element and a `<colN>` class to its children elements. This way, the layout will use the browser width to calculate the widths of the 12 columns. If you want to define the width of the main container yourself, then you should instantiate the `igLayoutManager` and set its width property.

## Configuring the Grid Layout

### Overview

The layout of the `igLayoutManager` is configured to Grid layout by setting the <ApiLink type="igLayoutManager" member="options:layoutMode" pkg="core" label="layoutMode" /> property of the control to “grid”. The Grid layout is a complex of absolutely positioned boxes that allows for merging rows and columns. Initializing this layout from the HTML markup is not supported.

You can specify the number of rows and columns for the grid and the items’ height and width. The latter is configured through the <ApiLink type="igLayoutManager" member="options:gridLayout.columnHeight" pkg="core" label="columnHeight" /> and <ApiLink type="igLayoutManager" member="options:gridLayout.columnWidth" pkg="core" label="columnWidth" /> properties which serve to set the size of the regular (non-spanning) items (that is, the size of the items that do not span over multiple rows and columns and each of them occupies only one cell in the grid).

When setting <ApiLink type="igLayoutManager" member="options:gridLayout.columnWidth" pkg="core" label="columnWidth" />/<ApiLink type="igLayoutManager" member="options:gridLayout.columnHeight" pkg="core" label="columnHeight" /> as `*`, the width/height will be equally distributed between all of the columns.

When specifying the <ApiLink type="igLayoutManager" member="options:gridLayout.columnWidth" pkg="core" label="columnWidth" />/<ApiLink type="igLayoutManager" member="options:gridLayout.columnHeight" pkg="core" label="columnHeight" /> as an array (e.g. `["100px", "20%", "*", "*"]`), if you have more than one column set as `*`, the remaining space will be equally distributed between these columns. If <ApiLink type="igLayoutManager" member="options:gridLayout.columnWidth" pkg="core" label="columnWidth" /> is set as an array, its length will override the <ApiLink type="igLayoutManager" member="options:gridLayout.cols" pkg="core" label="cols" /> property. And if <ApiLink type="igLayoutManager" member="options:gridLayout.columnHeight" pkg="core" label="columnHeight" /> is set as an array, its length will override the <ApiLink type="igLayoutManager" member="options:gridLayout.rows" pkg="core" label="rows" /> property.

Custom arrangement of the items is supported through the <ApiLink type="igLayoutManager" member="options:items" pkg="core" label="items" /> property which is set to an array of objects. You can disable the automatic re-arrangement of items upon resizing the container; this gives you some extra control of the user experience.

## Configuring the Vertical Layout

### Overview

The Vertical Layout is configurable through the <ApiLink type="igLayoutManager" pkg="core" label="layoutMode" /> property of the control. The host HTML element of the control is DIV element. Child DIVs can be defined in the HTML markup of the host element, and upon initialization, the control will add the respective CSS classes, or they can be defined as an array of item objects in the control options, and the `igLayoutManager` will generate the corresponding markup. The number of items is specified through the <ApiLink type="igLayoutManager" pkg="core" label="itemCount" /> property.
