# igTextEditor Known Issues

## Known Limitations

- When the input element is a `<textarea>` (textMode=”multiline”) element the caret position behaviour can be inconsistent. In some browsers, Gecko-based (Firefox) and WebKit-based (Chrome, Opera, Safari) when a is focused, the insertion point is placed at the beginning of the text by default, instead of at the end as observed in Internet Explorer. To provide consistent behavior the <ApiLink type="igTextEditor" member="options:selectionOnFocus" pkg="core" label="selectionOnFocus" /> default value is set to `selectAll` instead of `browserDefault`
- Multi-line text mode not supported in an `<input>` base element. If the base element is `<input>`, setting the <ApiLink type="igTextEditor" member="options:textMode" pkg="core" label="textMode" /> option to *multiline* is not supported.
- If the base element is `<textarea>`, the <ApiLink type="igTextEditor" member="options:textMode" pkg="core" label="textMode" /> option is set to *multiline* and cannot be changed.
- Changing value after initialization for <ApiLink type="igTextEditor" member="options:buttonType" pkg="core" label="buttonType" />, <ApiLink type="igTextEditor" member="options:textMode" pkg="core" label="textMode" />, <ApiLink type="igTextEditor" member="options:dropDownOnReadOnly" pkg="core" label="dropDownOnReadOnly" />, <ApiLink type="igTextEditor" member="options:visibleItemsCount" pkg="core" label="visibleItemsCount" />, and <ApiLink type="igTextEditor" member="options:dropDownAttachedToBody" pkg="core" label="dropDownAttachedToBody" /> options is not supported
