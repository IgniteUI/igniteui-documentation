# Card (カード)

{ProductName} Card は、関連するメディア、テキスト、アクションを 1 つの柔軟なコンテンツ コンテナーにまとめます。

Card を使用して、製品、記事、連絡先、場所、ダッシュボード アイテムなど、単一の対象に関するコンテンツをグループ化します。

## 作業の開始

{Platform} Card を使用するには、基本的なプロジェクトのセットアップについて <PlatformBlock for="Angular">[{ProductName} の作業の開始](../general/getting-started.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[{ProductName} の作業の開始](../general-getting-started.mdx)</PlatformBlock> トピックを参照し、対象プラットフォーム向けにコンポーネントを登録します。

<PlatformBlock for="React,WebComponents">

**{PackageCommon}** パッケージを使用する {Platform} の場合、パッケージをインストールします:

```cmd
npm install {PackageCommon}
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

次に、<ApiLink pkg="core" type="Card" />、そのテーマ CSS をインポートし、以下のようにコンポーネントを登録する必要があります:

```ts
import { defineComponents, IgcCardComponent } from 'igniteui-webcomponents';
import 'igniteui-webcomponents/themes/light/bootstrap.css';

defineComponents(IgcCardComponent);
```

Card を登録すると、カード ヘッダー、メディア、コンテンツ、アクションの各サブコンポーネントも登録されます。Avatar、Button、Icon Button など、カード コンテンツで使用するその他のコンポーネントも登録します:

```ts
import {
  defineComponents,
  IgcAvatarComponent,
  IgcButtonComponent,
  IgcCardComponent,
  IgcIconButtonComponent,
} from 'igniteui-webcomponents';

defineComponents(IgcCardComponent, IgcAvatarComponent, IgcButtonComponent, IgcIconButtonComponent);
```

</PlatformBlock>

<PlatformBlock for="React">

次に、以下のように、Card ラッパーとテーマ CSS をインポートする必要があります:

```tsx
import {
  IgrCard,
  IgrCardActions,
  IgrCardContent,
  IgrCardHeader,
  IgrCardMedia,
} from 'igniteui-react';
import 'igniteui-webcomponents/themes/light/bootstrap.css';
```

`IgrAvatar`、`IgrButton`、`IgrIconButton` など、カード コンテンツで使用するその他のラッパーもインポートします。

</PlatformBlock>

<PlatformBlock for="Blazor">

{ProductName} のサービスを登録します。

```csharp
// in Program.cs file

builder.Services.AddIgniteUIBlazor();
```

<ApiLink pkg="core" type="Card" /> のクライアント リソース モジュールである <ApiLink pkg="core" type="CardModule" /> の登録は**任意**です。コンポーネントは初めてレンダリングされるときにリソースを読み込みます。ただし、`builder.Services.AddIgniteUIBlazor(typeof(IgbCardModule))` のように指定すると、リソースを事前に読み込んだり、クライアント側でのみ作成される要素に対応したりできます ([コンポーネント モジュール](../general-getting-started.mdx#コンポーネント-モジュール)を参照)。

また、追加の CSS ファイルをリンクして、スタイルを <ApiLink pkg="core" type="Card" /> コンポーネントに適用する必要があります。以下は、アプリのホスト ページ (スタンドアロンの Blazor WebAssembly アプリまたは Blazor Hybrid アプリでは **wwwroot/index.html**、Blazor Server アプリでは **Pages/_Host.cshtml**、Blazor Web App では **Components/App.razor**) に配置する必要があります:

```razor
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
```

</PlatformBlock>

<PlatformBlock for="Angular">

**igniteui-angular** パッケージを使用する Angular の場合、パッケージをインストールします:

```cmd
npm install igniteui-angular
```

```ts
import { IGX_CARD_DIRECTIVES } from 'igniteui-angular/card';
```

<PlatformBlock for="WebComponents, React, Blazor">

</PlatformBlock>

</PlatformBlock>

### レイアウト

カードのセクションを水平に配置したり、メディアとコンテンツの領域に分割したりする場合は、レイアウト ラッパーを使用します。

水平カードの場合、ヘッダーとコンテンツを 1 つのラッパーにグループ化し、そのラッパーの横にアクションを追加して、カード コンテンツに行方向の flex レイアウトを適用します。

<PlatformBlock for="WebComponents">

```html
<igc-card>
  <div class="card-horizontal">
    <div>
      <igc-card-header>
        <img src="https://dl.infragistics.com/x/img/music/rozes.jpg" slot="thumbnail" alt="Rozes album cover" />
        <span slot="title">Rozes</span>
        <span slot="subtitle">Under the Grave (2016)</span>
      </igc-card-header>
      <igc-card-content>
        <p>As I have always said: I write what's real and what's true, even if it means throwing myself under the bus.</p>
      </igc-card-content>
    </div>
    <div class="divider"></div>
    <igc-card-actions>
      <igc-icon-button variant="flat" name="skip_previous" aria-label="Previous track"></igc-icon-button>
      <igc-icon-button variant="flat" name="play_arrow" aria-label="Play"></igc-icon-button>
      <igc-icon-button variant="flat" name="skip_next" aria-label="Next track"></igc-icon-button>
    </igc-card-actions>
  </div>
</igc-card>
```

</PlatformBlock>

<PlatformBlock for="Angular">


## アクセシビリティ

Card はコンテナーです。グループ化とメディアのセマンティクスはカードの各領域から提供され、キーボード操作性とアクセシブルな名前は、その中に配置するコンテンツから提供されます。

### キーボード インタラクション

Card とそのヘッダー、メディア、コンテンツ、アクションの各領域は、キー ハンドラーを宣言せず、タブ順序にも含まれません。フォーカスは、その中に配置したフォーカス可能なコンテンツの間を DOM 順に移動します。

| キー | アクション |
| -- | -- |
| <kbd>Tab</kbd> | コンテンツまたはアクション領域のボタンやリンクなど、カード内の次のフォーカス可能な要素にフォーカスを移動します。 |
| <kbd>Shift</kbd> + <kbd>Tab</kbd> | カード内の前のフォーカス可能な要素にフォーカスを移動します。 |

アクション領域は常に、先頭の領域、中央のコンテンツ、末尾の領域の順にレンダリングされます。アクションを垂直レイアウトに切り替えても、DOM の順序は変更されずにスタイルのみが変更されるため、キーボードとスクリーン リーダーの順序は変わりません。

### スクリーン リーダー / ARIA

<PlatformBlock for="Angular">

- カード ホストは `role="group"` と、`igx-card-1` の形式で生成された `id` をレンダリングします。情報アーキテクチャに別のグループ化ロールが適している場合は `role` 入力を設定し、グループにアクセシブルな名前を付けるために、カード タイトルを `aria-labelledby` で参照します。
- `igx-card-media` は `role="img"` をレンダリングします。これによりメディア領域全体が単一の画像として公開され、その子要素はプレゼンテーション扱いになるため、内部の画像の `alt` 属性では名前を付けられません。領域自体に `aria-label` または `aria-labelledby` で名前を付けるか、メディアが装飾目的の場合は `role` 入力を `presentation` に設定します。
- ヘッダー、タイトル、サブタイトル、コンテンツ、アクションの各メンバーは、スタイル クラスのみを追加します。ロールや `aria-*` 属性は追加しません。
- アクション領域のアイコンのみのボタンには、アクセシブルな名前を付けてください。アイコンだけでは名前は提供されません。
- カード全体で 1 つのアクションを実行する場合は、コンテナーにクリック ハンドラーを割り当てるのではなく、単一のインタラクティブな要素を使用して、アクションがロールと名前を保持するようにします。

</PlatformBlock>

<PlatformBlock for="WebComponents, React, Blazor">

- Card とすべてのカード領域は単純なスロットをレンダリングし、`role` や `aria-*` 属性を設定しません。ヘッダー内のラッパー要素にはアクセシブルな名前がなく、ランドマークも作成しません。情報アーキテクチャで必要な場合は、カード ホストにロールとアクセシブルな名前を自分で追加してください。
- `title` および `subtitle` スロットは、渡された要素をそのままレンダリングし、見出しレベルを強制しません。
- メディア領域内の画像には `alt` テキストを追加します。
- アクション領域のアイコンのみのボタンには、アクセシブルな名前を付けてください。アイコンだけでは名前は提供されません。
- カード全体で 1 つのアクションを実行する場合は、コンテナーにクリック ハンドラーを割り当てるのではなく、単一のインタラクティブな要素を使用して、アクションがロールと名前を保持するようにします。

</PlatformBlock>

| [2.4.3 フォーカス順序](https://www.w3.org/WAI/WCAG21/Understanding/focus-order.html) | アクション領域は、`start` スロット、デフォルト スロット、`end` スロットを固定された DOM 順序でレンダリングし、垂直方向でもこの順序は変更されません。 |
| [4.1.2 名前、役割、値](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value.html) | Card は暗黙的なロールを設定しないため、すべてのコントロールの名前、ロール、値は、提供するコンテンツに委ねられます。 |

</PlatformBlock>

ユーザーの責任:

- カードがドキュメントのアウトラインに含まれるように、タイトルには実際の見出し要素を渡し、サブタイトルはプレーン テキストにします。
- 意味のあるメディアには代替テキストを提供し、画像として公開される場合は、メディア領域にアクセシブルな名前を付けます。
- アイコンのみのアクション ボタンには、アクセシブルな名前を付けます。
- CSS で水平カードや分割カードのレイアウトを構築する場合は、DOM の順序と視覚的な順序を一致させます。
- カードの色をオーバーライドする場合は、十分なコントラストを維持します。

## FAQ

<Faq>
  <FaqItem question="スクリーン リーダーを損なわずにカード全体をクリック可能にするにはどうすればよいですか?" indicatorPosition="end">
    Card は単純なコンテナーでありインタラクティブな動作を追加しないため、カード全体をリンクで囲むのは一般的ですが有害な近道です。そのリンクのアクセシブルな名前が、カード内のすべてのテキストになってしまうためです。代わりに、カード タイトルに実際のリンクまたはボタンを配置し、カード ボックス全体を覆う絶対配置の擬似要素でカード全体に広げます。これにより、タイトルがアクセシブルな名前のまま維持され、四角形全体がクリック可能なままで、テキスト選択や中クリックも引き続き機能します。
  </FaqItem>
  <FaqItem question="行またはグリッド内のカードの高さを揃えるにはどうすればよいですか?" indicatorPosition="end">
    Card はコンテンツに応じてサイズが決まり、兄弟要素間で高さを揃えることはありません。各カードが行の高さに伸びるように、カードを CSS グリッドまたは行方向の flex レイアウトに配置し、メディア領域に固定の高さまたは `aspect-ratio` を指定し、`-webkit-line-clamp` でタイトルと本文を指定した行数に制限します。カードの高さが揃わない原因は、ほとんどの場合、各画像と各段落が自身の高さを決めてしまうことです。
  </FaqItem>
  <FaqItem question="カードの画像が切り取られるのはなぜですか? サイズを制御するにはどうすればよいですか?" indicatorPosition="end">
    <PlatformBlock for="WebComponents, React, Blazor">Card のメディア領域は、そのコンテンツを領域の幅と高さいっぱいに引き伸ばし、`object-fit: cover` を適用するため、画像は歪むのではなく切り取られます。メディア領域自体を CSS の `height` または `aspect-ratio` でサイズ設定してください。内部の画像のサイズを変更しても効果はありません。</PlatformBlock><PlatformBlock for="Angular">Card のメディア領域は、含まれるメディアのサイズを制御するため、画像ではなく領域のサイズを設定してください。`igx-card-media` の `height` および `width` 入力を設定し、カードの行が揃うように、カード間で一貫したアスペクト比を使用します。</PlatformBlock>
  </FaqItem>
  <FaqItem question="カード アクションが、配置した場所とは別の領域に表示されるのはなぜですか?" indicatorPosition="end">
    <PlatformBlock for="Angular">カード アクション領域は、記述順ではなくセレクターによってコンテンツを投影します。`igxEnd` のない `igxButton` を持つ要素は先頭の領域に配置され、`igxStart` のない `igxIconButton` を持つ要素または `igx-icon` は末尾の領域に配置されます。どちらのセレクターにも一致しないコンテンツのみが中央に残ります。アクションを目的の場所に配置するには、`igxStart` または `igxEnd` を明示的に設定します。</PlatformBlock><PlatformBlock for="WebComponents, React, Blazor">カード アクションの `end` スロット内のコンテンツには、アクション領域の反対側の端に揃えるために先頭マージンが自動的に適用されるため、末尾のアクションが 1 つだけの場合、他のアクションから離れて見えることがあります。他のアクションと一緒に配置する場合は、その要素を `start` スロットまたはデフォルト スロットに移動します。3 つの領域は、方向に関係なく、常に `start`、デフォルト、`end` の順にレンダリングされます。</PlatformBlock>
  </FaqItem>
  <FaqItem question="Card ではなく Grid や List を使用するのはどのような場合ですか?" indicatorPosition="end">
    データが高密度で表形式であり、読み手が列をまたいでスキャン、ソート、比較する必要がある場合は Grid を使用し、多数の短く均一な行を狭いスペースに収める必要がある場合は List を使用します。各アイテムに独自のメディア、長めのテキスト、独自のアクションが必要な場合は Card を使用します。長くスクロールするほどカードを並べている場合、多くは形を変えた List です。
  </FaqItem>
</Faq>
