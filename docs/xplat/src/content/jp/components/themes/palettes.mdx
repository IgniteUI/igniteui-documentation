# {ProductName} のパレット

{ProductName} のパレットは、シード カラーから生成される `--ig-*` CSS 変数のセットで、すべてのコンポーネント テーマのカラーを提供します。

## 概要

{ProductName} のパレットには、`primary`、`secondary`、`gray`、`surface`、`info`、`success`、`warn`、`error` の 8 つのカラー ファミリがあります。各ファミリは、そのシェードを `--ig-<family>-<variant>` という名前の CSS 変数として公開します (例: `--ig-primary-500`)。

| ファミリ | バリアント |
|---|---|
| `primary`、`secondary`、`info`、`success`、`warn`、`error` | `50`、`100`、`200`、`300`、`400`、`500`、`600`、`700`、`800`、`900`、`A100`、`A200`、`A400`、`A700`、`seed` |
| `gray` | `50`–`900`、`seed` |
| `surface` | `base`、`sunken`、`raised`、`overlay`、`container`、`seed` |

番号付きのシェードは、最も明るい `50` から最も暗い `900` まで続きます。`A100`–`A700` のアクセント シェードは、強調に使用する鮮やかなバリアントです。`surface` ファミリはシェードではなくレイヤーを表します。`base` はページおよびコンポーネントの背景で、`sunken`、`raised`、`overlay` はそれを基準としたレイヤー、`container` は半透明の塗りつぶしです。パレットには互換性のために番号付きの `surface` シェードも含まれますが、非推奨であり、コンポーネント テーマはロールを読み取ります。

すべてのバリアントには、`--ig-primary-500-contrast` のような対応する `-contrast` 変数があり、構成された WCAG レベルでそのシェードに対して読みやすい方の黒または白に解決されます。

<DocsAside type="info" title="情報">
コントラスト カラーは、対応するシェードからブラウザーによって計算される CSS 相対カラーであるため、シェードをオーバーライドすると、そのコントラスト カラーも一緒に更新されます。半透明の `container` は例外で、そのコントラスト カラーは `base` の上に重ねたコンテナーから計算されます (その上のテキストはこれに対して読み取られます)。そのため、どちらの変更にも追従します。
</DocsAside>

以下は、Light Material パレットの `primary` ファミリの抜粋です:

```css
:root {
  --ig-primary-500: #09f;
  --ig-primary-500-contrast: hsla(from color(from var(--ig-primary-500) var(--y-contrast)) h 0 l / 1);
  --ig-primary-600: hsl(from var(--ig-primary-500) h calc(s * 1.26) calc(l * 0.89));
  --ig-primary-600-contrast: hsla(from color(from var(--ig-primary-600) var(--y-contrast)) h 0 l / 1);
  --ig-primary-seed: #09f;
  /* ... */
  --ig-wcag-a: 0.31;
  --ig-wcag-aa: 0.185;
  --ig-wcag-aaa: 0.178;
  --ig-contrast-level: var(--ig-wcag-aa);
  --y: clamp(0, (y / var(--ig-contrast-level) - 1) * -infinity, 1);
  --y-contrast: xyz-d65 var(--y) var(--y) var(--y);
}
```

各ファミリは、パレットの生成元となったカラーを変更せずに保持する `seed` 変数も公開します。ビルド済みのテーマでは、`primary`、`secondary`、およびその他のカラー ファミリの seed は `500` バリアントと一致します。`gray` では一致しません。`--ig-gray-seed` はグレースケールの派生元となったカラー (サーフェス カラーの輝度から選択された黒または白) を記録し、`--ig-gray-500` は生成された中間トーンです。

<DocsAside type="info" title="情報">
しきい値は `--ig-contrast-level` に保持されており、デフォルトは `var(--ig-wcag-aa)` です。任意のスコープでオーバーライドして、`var(--ig-wcag-a)` または `var(--ig-wcag-aaa)` に切り替えることができます。<PlatformBlock for="React, WebComponents, Blazor"> ビルド済みの CSS を使用する代わりに Sass からテーマをコンパイルする場合、`palette` および `adaptive-contrast` ミックスインは `a`、`aa`、または `aaa` を直接受け取ります。[アクセシビリティ](accessibility.mdx)を参照してください。</PlatformBlock>
</DocsAside>

<PlatformBlock for="Angular">

Sass では、`palette()` および `adaptive-contrast()` ミックスインは `'a'`、`'aa'`、または `'aaa'` を直接受け取ります:

```scss
@include palette($palette, $contrast-level: 'aaa');
```

</PlatformBlock>

## パレットの生成方法

ビルド済みの CSS テーマに含まれるものを含め、すべての {ProductName} パレットは、`igniteui-theming` Sass ライブラリの `palette()` 関数によって生成されます。<PlatformBlock for="React, WebComponents, Blazor"> ビルド済みのパレットを使用するのに Sass は必要ありませんが、その作成方法を知ると変数の動作を理解できます。</PlatformBlock>この関数には 2 つのジェネレーターがあり、実行時の動作が異なる CSS 変数を生成します:

| ジェネレーター | シェードの出力形式 | 使用場所 |
|---|---|---|
| `legacy` | `500` の CSS 相対カラー。`--ig-primary-500` をオーバーライドすると、ブラウザーですべてのプライマリ シェードが更新されます。 | すべてのビルド済み CSS テーマと、事前定義された Sass パレット。 |
| `fitted` | コントラスト ターゲットに合わせて解決された固定カラー。1 つの変数をオーバーライドしても、そのシェードのみが変更されます。 | Sass の `palette()` で生成するパレット (デフォルト)。 |

`legacy` ジェネレーターは、`500` シェードの彩度と明度に固定値を乗算するため、シェードの品質は `500` カラーの明るさまたは暗さに依存します。非常に暗い、または非常に淡い `500` では、シェードが近接したり、白に解決されたりします。ブランド カラーが非常に暗い、または非常に淡い場合は、代わりに Sass で `fitted` ジェネレーターを使用してパレットを生成してください。これはコントラスト スケールに合わせて各ファミリを構築するため、そのようなシードでも 10 個の異なるシェードが生成されます。[パレット生成](palette-generation.mdx)では、両方のジェネレーターについて説明し、パレットの生成方法を示します。<PlatformBlock for="Angular"> [Sass によるパレット](sass/palettes.mdx)では、各ワークフローを詳しく説明しています。</PlatformBlock>

このトピックの残りの部分では、実行時のオーバーライドについて説明します。これは、ビルド済みのテーマなど、`legacy` ジェネレーターで構築されたパレットでのみ新しいシェードを派生させます。

## パレットの定義

ファミリのカラーを変更するには、その `500` バリアントをオーバーライドします。そのファミリの他の番号付きシェードとアクセント シェードはすべて `500` の相対カラーであるため、一緒に更新されます:

```css
:root {
  --ig-primary-500: #09f;
}
```

派生したシェードは `500` の色相を保持し、彩度と明度のみを変更するため、各ファミリは単色です:

```css
:root {
  --ig-primary-600: hsl(from var(--ig-primary-500) h calc(s * 1.26) calc(l * 0.89));
}
```

`seed` 変数は `500` から派生しません。パレットの生成元となったカラーを記録します。`seed` ではなく、使用するシェードをオーバーライドしてください。

## スコープ

グローバル パレットを変更するには、アプリケーションのグローバル スタイルシートの `:root` でパレット変数をオーバーライドします。任意の CSS カラー構文を使用できます:

```css
:root {
  --ig-primary-500: #9f349c;
}
```

オーバーライドを他のセレクターにスコープすると、複数のパレットを並行して実行できます。たとえば、青と赤のパレットをクラスで定義します:

```css
/* styles.css */

.blue-theme {
  --ig-primary-500: #0008ff;
}

.red-theme {
  --ig-primary-500: #ff0400;
}
```

<PlatformBlock for="Angular">

```html
<app-component class="blue-theme"></app-component>
```

</PlatformBlock>

クラスを `blue-theme` から `red-theme` に変更すると、要素内のすべてのパレットが切り替わります。

同じ方法で、単一のコンポーネントのパレット カラーを変更できます。たとえば、Material の Avatar は背景を `gray` の `400` シェードから取得するため、Avatar でそのシェードをオーバーライドすると、パレットの残りの部分に影響を与えずに背景を変更できます:

<PlatformBlock for="Angular">

```css
igx-avatar {
  --ig-gray-400: #efefef;
}
```

</PlatformBlock>
<PlatformBlock for="React, WebComponents, Blazor">

```css
igc-avatar {
  --ig-gray-400: #efefef;
}
```

</PlatformBlock>

## サーフェス レイヤー

`surface` ファミリは、番号付きのシェードではなく、名前付きレイヤーのセットです。コンポーネントは、`--ig-surface-base` を先頭とするこれらのレイヤーを読み取ります:

| 変数 | 用途 |
| --- | --- |
| `--ig-surface-base` | ページの背景 |
| `--ig-surface-sunken` | くぼんだ領域 |
| `--ig-surface-raised` | ページの上に置かれるカードとパネル |
| `--ig-surface-overlay` | メニュー、ダイアログ、ポップオーバー |
| `--ig-surface-container` | サーフェスの上の半透明レイヤー: ライト サーフェスでは黒、ダーク サーフェスでは白 |

各レイヤーには、そのレイヤー上の前景色用に、`--ig-surface-base-contrast` のような対応する `-contrast` 変数があります。

動く余地のないレイヤーは `base` に解決されます。たとえば、純白の base では、`raised` と `overlay` も白になるため、ページから区別するには境界線または[エレベーション](elevations.mdx)を使用します。レイヤーの生成方法については、[パレット生成](palette-generation.mdx#surface-roles)を参照してください。

## ダークとライト

`gray` と `surface` ファミリによって、{ProductName} のパレットがライトかダークかが決まります。ライト パレットは、明るいサーフェスと暗い色から構築されたグレーを組み合わせ、ダーク パレットは、暗いサーフェスと白から構築されたグレーを組み合わせます。テキスト、境界線、アイコンはグレーからカラーを取得するため、この 2 つのファミリはグレー スケールの反対側に保つ必要があります。

コンポーネントの背景は `surface` ロールを読み取るため、実行時にサーフェスを変更するにはロールをオーバーライドします。ロールはどちらのジェネレーターでも固定カラーであり、`--ig-surface-500` から派生しません:

**Material Light:**

```css
:root {
  /* the surface roles are light */
  --ig-surface-base: #fff;
  --ig-surface-raised: #fff;
  --ig-surface-overlay: #fff;
  --ig-surface-sunken: #f7f7f7;
  /* grays are built from a dark color to contrast the surface */
  --ig-gray-500: hsl(0, 0%, 62%);
}
```

**Material Dark:**

```css
:root {
  /* the surface roles are dark */
  --ig-surface-base: #222;
  --ig-surface-raised: #282828;
  --ig-surface-overlay: #2f2f2f;
  --ig-surface-sunken: #1c1c1c;
  /* grays are built from white to contrast the surface */
  --ig-gray-500: hsl(0, 0%, 74%);
}
```

<PlatformBlock for="Angular">

コンポーネントは {ProductName} 22.3.0 以降でサーフェス ロールを読み取ります。以前のバージョンでは、代わりに背景として `--ig-surface-500` を読み取るため、それらのバージョンでは `--ig-surface-base` と一緒に `--ig-surface-500` もオーバーライドしてください。

</PlatformBlock>

<PlatformBlock for="WebComponents">

コンポーネントは Ignite UI for Web Components 7.5.0 以降でサーフェス ロールを読み取ります。以前のバージョンでは、代わりに背景として `--ig-surface-500` を読み取るため、それらのバージョンでは `--ig-surface-base` と一緒に `--ig-surface-500` もオーバーライドしてください。

</PlatformBlock>

<PlatformBlock for="React, Blazor">

サーフェス ロールより前のリリースのコンポーネントは、代わりに背景として `--ig-surface-500` を読み取ります。そのようなリリースを使用している場合、またはわからない場合は、`--ig-surface-base` と一緒に `--ig-surface-500` もオーバーライドしてください。コンポーネントがロールを読み取る場合、追加の変数による悪影響はありません。

</PlatformBlock>

`gray` と `surface` は、ほとんどのコンポーネントで使用されており、テーマの外観全体に最も大きな影響を与えるため、その変更には注意が必要です。

## その他のカラー

`info`、`success`、`warn`、`error` ファミリは、<PlatformBlock for="Angular">`igx-input-group`</PlatformBlock><PlatformBlock for="React, WebComponents, Blazor">`igc-input`</PlatformBlock> の検証状態など、状態のカラーを設定します。これらを変更するには `500` バリアントをオーバーライドすると、各ファミリの残りもそれに追従します:

```css
:root {
  --ig-info-500: #1377d5;
  --ig-success-500: #4eb862;
  --ig-warn-500: #faa419;
  --ig-error-500: #ff134a;
}
```
