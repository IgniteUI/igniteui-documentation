# Descripción general del Chat de {Platform}

El componente Chat de {ProductName} ofrece una solución completa para crear interfaces conversacionales en sus aplicaciones. Tanto si crea una herramienta de atención al cliente, un espacio de trabajo colaborativo o un asistente chatbot, el componente Chat le da los bloques básicos que necesita: enviar y recibir mensajes de texto, subir archivos adjuntos, mostrar sugerencias de respuesta rápida y mostrar indicadores de escritura cuando el otro participante está redactando una respuesta.

A diferencia de una lista de mensajes estática, el componente <ApiLink pkg="core" type="Chat" /> es interactivo y está diseñado para la **comunicación en tiempo real**. Gestiona la entrada, la renderización y la interacción del usuario, y le da control total sobre cómo se muestran los mensajes y los adjuntos. También expone una API de renderizado amplia que le permite sustituir cualquier parte de su diseño o de su aspecto visual.

#### Colección bidireccional de mensajes

El <PlatformBlock for="WebComponents,React">`messages`</PlatformBlock><PlatformBlock for="Blazor">`Messages`</PlatformBlock> La colección es bidireccional: la aplicación proporciona los mensajes que se muestran y el Chat actualiza la colección original a medida que avanza la conversación. Después de que el usuario envíe un mensaje, el código que mantiene una referencia a la colección puede acceder al mensaje recién creado.

El <PlatformBlock for="WebComponents">`igcMessageCreated`</PlatformBlock><PlatformBlock for="React">`onMessageCreated`</PlatformBlock><PlatformBlock for="Blazor">`MessageCreated`</PlatformBlock> El evento es una notificación para la persistencia u otros efectos secundarios. No vuelva a añadir el mensaje creado a la colección.

Si la colección original debe permanecer sin cambios, pase al Chat una copia superficial. Los objetos de mensaje existentes siguen compartidos; cree una nueva instancia de cada mensaje al construir la colección copiada si esos objetos también deben permanecer independientes.

### Sugerencias
Las sugerencias de respuesta rápida ofrecen a los usuarios respuestas predefinidas que pueden pulsar para responder al instante. Esta función resulta especialmente útil en chatbots, flujos de atención al cliente o cuando se guía a los usuarios por un proceso estructurado.
Puede proporcionar sugerencias enlazando una matriz de cadenas a la propiedad suggestions. El atributo `suggestions-position` le permite controlar dónde se muestran: debajo del área de entrada o debajo de la lista de mensajes.

<PlatformBlock for="WebComponents">


```ts

  currentUserId: "me",
  suggestions: ['Yes', 'No', 'Maybe later'],
  suggestionsPosition: "below-input"
};
```

```html
<igc-chat
  .options=${options}>
</igc-chat>
```

</PlatformBlock>


<PlatformBlock for="React">

### Renderizadores personalizados
Aunque el componente Chat funciona de inmediato con su interfaz predeterminada, muchas aplicaciones necesitan personalizar el aspecto. Por ejemplo, puede que quiera añadir confirmaciones de lectura, mostrar avatares o sustituir el área de entrada por un botón de grabación de voz.
El componente <ApiLink pkg="core" type="Chat" /> resuelve esta necesidad con un sistema de renderizadores. Un renderizador es simplemente una función que devuelve una plantilla para una parte concreta de la interfaz. Puede sustituir tantos renderizadores como quiera, o tan pocos como necesite.

#### ChatTemplateRenderer
Todos los renderizadores siguen la misma firma de función:

<PlatformBlock for="WebComponents, React">

```ts
export type ChatTemplateRenderer<T> = (ctx: T) => unknown;
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```js
igRegisterScript("MyTemplate", (ctx) => {
}, false);
```

</PlatformBlock>

El parámetro ctx proporciona distintos datos contextuales según lo que se esté renderizando.

#### Contextos de los renderizadores

| Tipo de contexto                | Datos proporcionados                                                                                                          |
| --------------------------- | -----------------------------------------------------------------------------------------------------------------------|
| <ApiLink pkg="core" type="ChatRenderContext" />       | `instance` (la instancia del componente de chat).                                                |
| <ApiLink pkg="core" type="ChatInputRenderContext" />      | Hereda <ApiLink pkg="core" type="ChatRenderContext" /> y añade `attachments` (matriz de <ApiLink pkg="core" type="ChatMessageAttachment" />) y `value` (texto de entrada actual). |
| <ApiLink pkg="core" type="ChatMessageRenderContext" />    | Hereda <ApiLink pkg="core" type="ChatRenderContext" /> y añade <ApiLink pkg="core" type="ChatMessage" /> (el <ApiLink pkg="core" type="ChatMessage" /> que se está renderizando).                                      |
| <ApiLink pkg="core" type="ChatAttachmentRenderContext" /> | Hereda <ApiLink pkg="core" type="ChatMessageRenderContext" /> y añade `attachment` (el <ApiLink pkg="core" type="ChatMessageAttachment" /> que se está renderizando).                      |

#### Renderizadores disponibles

Se pueden personalizar las siguientes partes del chat:
- Nivel de mensaje: message, messageHeader, messageContent, messageAttachments, messageActions
- Nivel de adjunto: attachment, attachmentHeader, attachmentContent
- Nivel de entrada: input, inputActions, inputActionsStart, inputActionsEnd, inputAttachments, fileUploadButton, sendButton
- Sugerencias: suggestionPrefix

Este nivel de detalle permite ajustar solo una parte (por ejemplo, el aspecto de los adjuntos) sin reescribir toda la disposición del chat.

#### Ejemplo: ampliar las acciones de entrada
El componente <ApiLink pkg="core" type="Chat" /> proporciona dos renderizadores que resultan útiles cuando quiere mantener las acciones predeterminadas (subir y enviar) pero ampliarlas con controles adicionales:
- `inputActionsStart`: le permite insertar contenido personalizado después del botón de subida integrado.
- `inputActionsEnd`: le permite insertar contenido personalizado después del botón de envío integrado.

Por ejemplo, puede que quiera añadir un botón de grabación de voz antes de los demás botones, o un menú de opciones adicionales después del botón de enviar.

```ts
import { createMarkdownRenderer } from 'igniteui-webcomponents/extras';

// Create a reusable Markdown renderer instance
const markdownRenderer = await createMarkdownRenderer();

const options = {
  renderers: {
    messageContent: async ({ message }) => markdownRenderer(message),

```

En este ejemplo:
- La propiedad text de cada mensaje se analizará como Markdown usando la biblioteca [marked](https://github.com/markedjs/marked).
- El renderizador sanea la salida usando [DOMPurify](https://github.com/cure53/DOMPurify)
- Los enlaces se abren automáticamente en una pestaña nueva con atributos rel seguros.

#### Resaltado de sintaxis

El renderizador de Markdown también admite el resaltado de sintaxis de los bloques de código mediante [Shiki](https://shiki.matsu.io/). De forma predeterminada, incluye el resaltado de JavaScript, TypeScript, HTML y CSS con el tema github-light. Puede personalizar este comportamiento mediante MarkdownRendererOptions:

```ts
const markdownRenderer = await createMarkdownRenderer({
  theme: { light: 'min-light' },
  languages: ['javascript', 'python']
});
```

Esto habilitará los bloques de código resaltados para JavaScript, Python y Go, con el tema oscuro de GitHub.

#### Opciones de configuración

| Opción          | Descripción                                                                     |
| --------------- | ------------------------------------------------------------------------------- |
| `noHighlighter` | Si `true`, desactiva por completo el resaltado de sintaxis.                               |
| `languages`     | Lista de lenguajes de programación que se admiten en los bloques de código resaltados.            |
| `theme`         | Un objeto que especifica los temas de **Shiki** que se aplican. Admite valores independientes para el modo `light` y el modo `dark` (por ejemplo, `{ light: 'github-light', dark: 'github-dark' }`). |
| `sanitizer`     | Una función personalizada para sanitizar el HTML final. El valor predeterminado es `DOMPurify.sanitize`. |

#### Adopción de estilos raíz (adoptRootStyles)

Las opciones del componente Chat incluyen una marca especial para escenarios de estilo avanzados:

| Opción            | Tipo      | Valor predeterminado | Descripción        |
| ----------------- | --------- | ------- | ------------------ |
| `adoptRootStyles` | `boolean` | false   | Cuando `true`, el componente permite que el contenido renderizado dentro de su Shadow DOM (por ejemplo, el procedente de renderizadores personalizados) herede los estilos del elemento raíz del documento. Esto ofrece una solución rápida para dar estilo, pero **no se recomienda** para producción. |

Esta propiedad puede resultar útil si prefiere no lidiar con el encapsulado de Shadow DOM al aplicar CSS global a plantillas renderizadas de forma personalizada.
Sin embargo, tiene compensaciones:
- ✅ Comodidad: permite que los estilos globales (del documento) afecten a los renderizadores de mensajes personalizados.
- ⚠ Riesgo: rompe el encapsulado y puede provocar fugas de estilos, cuando el CSS global altera sin querer el aspecto interno.
- 🔒 Ajuste de una sola vez: esta opción solo puede establecerse al inicializar. Cambiarla en tiempo de ejecución no tiene efecto.

Recomendamos encarecidamente usar los enfoques estándar de estilo de Web Components antes de recurrir a esta propiedad:
- API de variables CSS y ::part: prefiera la personalización mediante las partes y variables expuestas.
- Elementos `<link>`: para hojas de estilo más grandes, insértelas dentro del Shadow DOM.
- Etiquetas `<style>` en línea: para sobrescrituras de estilo pequeñas y acotadas.

#### Ejemplo

```css
igc-chat::part(header) {
  background-color: var(--ig-gray-800);
  color: var(--ig-warn-400);
}

igc-chat::part(message-container) {
  background: var(--ig-warn-200);
  color: var(--ig-warn-200-contrast);
}

igc-chat::part(message-sent) {
  background: var(--ig-warn-500);
  color: var(--ig-warn-500-contrast);
}

igc-chat::part(message-header) {
  color: var(--ig-warn-A700); 
}
```

Esto le permite dar estilo a <ApiLink pkg="core" type="Chat" /> para que coincida con su marca sin reemplazar su funcionalidad.
