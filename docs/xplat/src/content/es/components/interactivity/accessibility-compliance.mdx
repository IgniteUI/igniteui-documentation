# Cumplimiento de accesibilidad

Esta página recoge las normas de accesibilidad a las que se ajusta {ProductName}, lo que cubre hoy la documentación de cada componente y cómo notificar un problema de accesibilidad.

La compatibilidad con la accesibilidad se ofrece en dos capas: los propios componentes y el motor de temas que los da estilo. Use esta página para consultar el estado de un componente concreto; use [Theming Accessibility](../themes/accessibility.mdx) para el contraste, el escalado de texto y el comportamiento de los colores de los gráficos.

<DocsAside type="note">
**Alcance de esta página.** La información siguiente refleja el **tema predeterminado** y el comportamiento documentado actual de cada componente. Es un resumen de compatibilidad, no una declaración formal de conformidad. Los temas personalizados, los cambios tipográficos y las sustituciones de animaciones o colores pueden alterar el resultado.
</DocsAside>

## Normas que seguimos

| Norma | Región | Qué exige |
|---|---|---|
| <a href="https://www.w3.org/WAI/WCAG21/quickref/" target="_blank" rel="noopener noreferrer">WCAG 2.1 nivel AA</a> | Internacional | Los criterios de éxito que se enumeran a continuación. Es la base a la que se refieren las otras dos. |
| <a href="https://www.section508.gov/" target="_blank" rel="noopener noreferrer">Sección 508 (revisada)</a> | Estados Unidos | Contratación pública federal. Desde las Normas de la Sección 508 revisadas (publicadas en 2017, con fecha de cumplimiento en enero de 2018), incorpora por referencia WCAG 2.0 nivel AA, por lo que se cumple con el mismo trabajo. |
| <a href="https://www.etsi.org/deliver/etsi_en/301500_301599/301549/" target="_blank" rel="noopener noreferrer">EN 301 549</a> | Europa | La norma europea de referencia para la accesibilidad de las TIC, basada en WCAG. La Ley Europea de Accesibilidad, que se apoya en ella, se aplica desde el 28 de junio de 2025. |

<DocsAside type="note">
La Sección 508 definía antes sus propias 16 reglas en el §1194.22. Estas fueron sustituidas por las Normas revisadas, que adoptan WCAG directamente. Por tanto, apuntar a WCAG 2.1 nivel AA cubre las tres normas anteriores.
</DocsAside>

### Criterios de éxito que se aplican a los componentes de la interfaz

La conformidad con WCAG se reclama respecto a **criterios de éxito** concretos, no respecto a las pautas más generales. Estos son los criterios que una biblioteca de componentes de interfaz puede afectar:

| Criterio | Nivel | Qué significa para un componente |
|---|:--:|---|
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/non-text-content.html" target="_blank" rel="noopener noreferrer">1.1.1 Contenido no textual</a> | A | Los iconos y las imágenes tienen una alternativa textual. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html" target="_blank" rel="noopener noreferrer">1.3.1 Información y relaciones</a> | A | La estructura que se transmite visualmente también se transmite en el marcado. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/meaningful-sequence.html" target="_blank" rel="noopener noreferrer">1.3.2 Secuencia significativa</a> | A | El orden de lectura coincide con el orden visual. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html" target="_blank" rel="noopener noreferrer">1.4.3 Contraste (mínimo)</a> | AA | El texto cumple 4,5:1 respecto a su fondo. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/resize-text.html" target="_blank" rel="noopener noreferrer">1.4.4 Cambiar el tamaño del texto</a> | AA | El texto se escala al 200 % sin pérdida de contenido. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast.html" target="_blank" rel="noopener noreferrer">1.4.11 Contraste de elementos no textuales</a> | AA | Los bordes y los estados de los controles cumplen 3:1. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/content-on-hover-or-focus.html" target="_blank" rel="noopener noreferrer">1.4.13 Contenido al pasar el ratón o al recibir el foco</a> | AA | Los tooltips y los popovers se pueden descartar y permanecen visibles. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/keyboard.html" target="_blank" rel="noopener noreferrer">2.1.1 Teclado</a> | A | Se puede acceder a toda la funcionalidad con el teclado. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/no-keyboard-trap.html" target="_blank" rel="noopener noreferrer">2.1.2 Sin bloqueo de teclado</a> | A | El foco siempre puede volver a salir. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/focus-order.html" target="_blank" rel="noopener noreferrer">2.4.3 Orden del foco</a> | A | El orden de tabulación sigue una secuencia significativa. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/focus-visible.html" target="_blank" rel="noopener noreferrer">2.4.7 Foco visible</a> | AA | El control enfocado se indica de forma visible. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/label-in-name.html" target="_blank" rel="noopener noreferrer">2.5.3 Etiqueta en el nombre</a> | A | El nombre accesible contiene la etiqueta visible. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/on-focus.html" target="_blank" rel="noopener noreferrer">3.2.1 Al recibir el foco</a> | A | El foco por sí solo no provoca un cambio de contexto. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/on-input.html" target="_blank" rel="noopener noreferrer">3.2.2 Al introducir datos</a> | A | Cambiar un valor por sí solo no provoca un cambio de contexto. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions.html" target="_blank" rel="noopener noreferrer">3.3.2 Etiquetas o instrucciones</a> | A | Los campos de entrada tienen etiquetas o instrucciones. |
| <a href="https://www.w3.org/WAI/WCAG21/Understanding/name-role-value.html" target="_blank" rel="noopener noreferrer">4.1.2 Nombre, función, valor</a> | A | Cada control expone un nombre, una función y su estado actual. |

| **Motor de temas** (`igniteui-theming`) | Contraste de color, dimensionado del texto, paletas de colores de gráficos, utilidades de estilo para controles personalizados. | [Accesibilidad de los temas](../themes/accessibility.mdx) |

## Configuración requerida

Algunos resultados de accesibilidad dependen de cómo configure la aplicación y no solo del componente.

<PlatformBlock for="Angular">

| Tarea | Criterio | Qué configurar |
|---|---|---|
| Animación y movimiento | <a href="https://www.w3.org/WAI/WCAG21/Understanding/three-flashes-or-below-threshold.html" target="_blank" rel="noopener noreferrer">2.3.1 Tres destellos o menos</a> | Proporcione `NoopAnimationsModule` desde `@angular/platform-browser/animations` en lugar de `BrowserAnimationsModule` para desactivar las animaciones de Angular en toda la aplicación. |

</PlatformBlock>

<PlatformBlock for="React, WebComponents, Blazor">

| Tarea | Criterio | Qué configurar |
|---|---|---|
| Animación y movimiento | <a href="https://www.w3.org/WAI/WCAG21/Understanding/three-flashes-or-below-threshold.html" target="_blank" rel="noopener noreferrer">2.3.1 Tres destellos o menos</a> | No requiere configuración. El reproductor de animaciones lee el ajuste `prefers-reduced-motion: reduce` del sistema operativo y reproduce las animaciones con una duración de `0` cuando está establecido. |

</PlatformBlock>

Los elementos restantes se aplican a todas las plataformas.

| Tarea | Criterio | Qué configurar |
|---|---|---|
| Límites de tiempo en los mensajes transitorios | <a href="https://www.w3.org/WAI/WCAG21/Understanding/timing-adjustable.html" target="_blank" rel="noopener noreferrer">2.2.1 Tiempo ajustable</a> | Los componentes que se cierran automáticamente, como Snackbar y Toast, ofrecen un ajuste de la duración de visualización. Amplíelo o desactive el cierre automático para que el usuario tenga tiempo de leer el mensaje. |
| Contraste de color tras aplicar el tema | <a href="https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html" target="_blank" rel="noopener noreferrer">1.4.3 Contraste (mínimo)</a> | Establezca los colores de primer plano con `contrast-color()` o `adaptive-contrast()` en lugar de valores fijos. Consulte [Theming Accessibility](../themes/accessibility.mdx). |
| Nombres accesibles en los controles solo con icono | <a href="https://www.w3.org/WAI/WCAG21/Understanding/name-role-value.html" target="_blank" rel="noopener noreferrer">4.1.2 Nombre, función, valor</a> | Proporcione un nombre accesible en su propio marcado. Un control que muestra solo un icono no tiene nombre hasta que se lo asigne. |

## Documentación formal de conformidad

Esta página es un índice de documentación, no una declaración de conformidad. Registra lo que cubre nuestra propia documentación; no certifica ningún componente frente a una norma.

Para compras, contratos o auditorías, cuando se requiera una declaración de conformidad trazable por criterio, solicite el informe de conformidad de accesibilidad vigente (VPAT) a través de su gestor de cuenta o del soporte de Infragistics. Indique el producto, la versión y la norma que debe cubrir el informe (WCAG 2.1 nivel AA, Sección 508 o EN 301 549).

<DocsAside type="note">
Las revisiones anteriores de esta página incluían matrices de conformidad por componente. Esas tablas afirmaban un nivel de conformidad que no estaba respaldado por una evaluación trazable por criterio, y se han eliminado en lugar de repetirlas. El informe de conformidad es la fuente autorizada para esa información.
</DocsAside>

## Cómo notificar un problema de accesibilidad

Si encuentra un problema de accesibilidad en un componente, notifíquelo en el <a href="{GithubLink}/issues" target="_blank" rel="noopener noreferrer">gestor de incidencias de {ProductName}</a>.

Incluya el componente, la tecnología de asistencia y el navegador que usó, el comportamiento esperado y el criterio de éxito de WCAG que cree que se ve afectado. Los informes de accesibilidad se clasifican según los criterios enumerados arriba.

## Preguntas frecuentes

<Faq>
  <FaqItem question="¿Cumple {ProductName} con WCAG?" indicatorPosition="end">
    La conformidad es una propiedad de una aplicación terminada, no de una biblioteca de componentes por sí sola. {ProductName} apunta a WCAG 2.1 nivel AA y documenta el comportamiento por componente en el índice anterior, pero el resultado depende del marcado, el contenido y la configuración que añada. Use el índice anterior para revisar los componentes que utiliza e informe de cualquier cosa que no se comporte como se documenta.
  </FaqItem>

  <FaqItem question="¿Por qué algunos componentes indican «Aún sin documentar»?" indicatorPosition="end">
    Ese estado significa que la documentación propia del componente todavía no describe el comportamiento. No es una afirmación de que el componente incumpla un criterio; registra lo que cubre la documentación, para que pueda distinguir un comportamiento documentado de uno que no lo está.
  </FaqItem>

  <FaqItem question="¿La Sección 508 sigue teniendo sus propias reglas separadas?" indicatorPosition="end">
    No. Las Normas revisadas de la Sección 508 (publicadas en 2017, con fecha de cumplimiento en enero de 2018) sustituyeron a las reglas anteriores del §1194.22 y adoptan por referencia WCAG nivel AA, por lo que cumplir WCAG también cubre la Sección 508.
  </FaqItem>

  <FaqItem question="¿La información de conformidad se aplica a los temas personalizados?" indicatorPosition="end">
    En parte. El comportamiento de teclado y ARIA no se ve afectado por el tema. El contraste de color sí: al sustituir colores, el texto puede quedar por debajo de la proporción exigida. Verifique las paletas personalizadas como se describe en Theming Accessibility.
  </FaqItem>

  <FaqItem question="¿Dónde encuentro los atajos de teclado de un componente?" indicatorPosition="end">
    En el tema propio del componente, enlazado desde la columna Reference de arriba. La familia de cuadrículas comparte un tema específico de navegación por teclado.
  </FaqItem>
</Faq>
