# Card

{ProductName} Card organiza contenido multimedia, texto y acciones relacionados en un único contenedor de contenido flexible.

Use la tarjeta para agrupar contenido sobre un único tema, como un producto, un artículo, un contacto, una ubicación o un elemento de panel.

## Primeros pasos

Para usar {Platform} Card, siga el tema <PlatformBlock for="Angular">[{ProductName} Primeros pasos](../general/getting-started.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[{ProductName} Primeros pasos](../general-getting-started.mdx)</PlatformBlock> para la configuración básica del proyecto y, después, registre el componente para su plataforma de destino.

<PlatformBlock for="React,WebComponents">

Para {Platform} usando el paquete **{PackageCommon}**, instale el paquete:

```cmd
npm install {PackageCommon}
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

A continuación, deberá importar <ApiLink pkg="core" type="Card" />, su CSS de tema y registrar el componente, de la siguiente manera:

```ts
import { defineComponents, IgcCardComponent } from 'igniteui-webcomponents';
import 'igniteui-webcomponents/themes/light/bootstrap.css';

defineComponents(IgcCardComponent);
```

Registrar la tarjeta también registra los subcomponentes de encabezado, contenido multimedia, contenido y acciones. Registre cualquier otro componente que use el contenido de su tarjeta, como el avatar, el botón y el botón de icono:

```ts
import {
  defineComponents,
  IgcAvatarComponent,
  IgcButtonComponent,
  IgcCardComponent,
  IgcIconButtonComponent,
} from 'igniteui-webcomponents';

defineComponents(IgcCardComponent, IgcAvatarComponent, IgcButtonComponent, IgcIconButtonComponent);
```

</PlatformBlock>

<PlatformBlock for="React">

A continuación, deberá importar los wrappers de Card y el CSS del tema, de la siguiente manera:

```tsx
import {
  IgrCard,
  IgrCardActions,
  IgrCardContent,
  IgrCardHeader,
  IgrCardMedia,
} from 'igniteui-react';
import 'igniteui-webcomponents/themes/light/bootstrap.css';
```

Importe cualquier otro wrapper que use el contenido de su tarjeta, como `IgrAvatar`, `IgrButton` y `IgrIconButton`.

</PlatformBlock>

<PlatformBlock for="Blazor">

Registre los servicios de {ProductName}:

```csharp
// in Program.cs file

builder.Services.AddIgniteUIBlazor();
```

Registrar <ApiLink pkg="core" type="CardModule" />, el módulo de recursos de cliente de <ApiLink pkg="core" type="Card" />, es **opcional**: el componente carga sus recursos la primera vez que se muestra. Incluirlo en `builder.Services.AddIgniteUIBlazor(typeof(IgbCardModule))` sirve para precargar recursos o para admitir elementos creados solo en el cliente (véase [Módulos de componentes](../general-getting-started.mdx#módulos-de-componentes)).

También necesitará enlazar un archivo CSS adicional para aplicar el estilo al componente <ApiLink pkg="core" type="Card" />. Lo siguiente debe colocarse en la página host de la aplicación (**wwwroot/index.html** en una aplicación Blazor WebAssembly independiente o Blazor Hybrid, **Pages/_Host.cshtml** en una aplicación Blazor Server, **Components/App.razor** en una aplicación Blazor Web App):

```razor
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
```

</PlatformBlock>

<PlatformBlock for="Angular">

Para Angular usando el paquete **igniteui-angular**, instale el paquete:

```cmd
npm install igniteui-angular
```

Después, importe el token `IGX_CARD_DIRECTIVES` de la colección de `imports` del componente. El token incorpora la tarjeta junto con todos sus componentes y directivas de apoyo.

```ts
import { IGX_CARD_DIRECTIVES } from 'igniteui-angular/card';
```

Importe cualquier otra directiva que use el contenido de su tarjeta, como `IgxButtonDirective`, `IgxIconButtonDirective`, `IgxIconComponent` y `IgxRippleDirective`, desde `igniteui-angular`.

</PlatformBlock>

### Slots del encabezado

Use los slots del encabezado para definir la miniatura, el título, el subtítulo y el contenido adicional del encabezado.

<PlatformBlock for="WebComponents">

```html
<igc-card-header>
  <igc-avatar slot="thumbnail" initials="TS"></igc-avatar>
  <h3 slot="title">Title</h3>
  <span slot="subtitle">Subtitle</span>
</igc-card-header>
```

</PlatformBlock>

<PlatformBlock for="Angular">

```html
<igx-card-header>
  <div igxCardThumbnail>
    <igx-icon>place</igx-icon>
  </div>
  <h3 igxCardHeaderTitle>Title</h3>
  <span igxCardHeaderSubtitle>Subtitle</span>
</igx-card-header>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrCardHeader>
  <IgrAvatar slot="thumbnail" initials="TS" />
  <h3 slot="title">Title</h3>
  <span slot="subtitle">Subtitle</span>
</IgrCardHeader>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbCardHeader>
  <IgbAvatar slot="thumbnail" Initials="TS" />
  <h3 slot="title">Title</h3>
  <span slot="subtitle">Subtitle</span>
</IgbCardHeader>
```

</PlatformBlock>

<PlatformBlock for="WebComponents, React, Blazor">

Pase un elemento de encabezado, como `<h3>`, al slot `title` para que la tarjeta ocupe su lugar en el esquema del documento, y use un elemento en línea neutro, como `<span>`, para `subtitle`. El encabezado restablece el margen y la fuente del contenido en slot, así que el encabezado mantiene la tipografía de la tarjeta.

</PlatformBlock>

<PlatformBlock for="Angular">

Aplique `igxCardHeaderTitle` a un elemento de encabezado, como `<h3>`, para que la tarjeta ocupe su lugar en el esquema del documento, y aplique `igxCardHeaderSubtitle` a un elemento en línea neutro, como `<span>`.

</PlatformBlock>

### Disposición

Para una tarjeta horizontal, agrupe el encabezado y el contenido en un mismo wrapper, añada las acciones junto a ese wrapper y aplique una fila flex al contenido de la tarjeta.

## Accesibilidad

La tarjeta es un contenedor. La agrupación y la semántica del contenido multimedia proceden de las regiones de la tarjeta, mientras que la operabilidad por teclado y los nombres accesibles proceden del contenido que coloque dentro de ellas.

### Interacción por teclado

La tarjeta y sus regiones de encabezado, contenido multimedia, contenido y acciones no declaran manejadores de teclas y no están en el orden de tabulación. El foco se mueve por el contenido enfocable que coloque dentro de ellas, en el orden del DOM.

| Clave | Acción |
| -- | -- |
| <kbd>Tabulador</kbd> | Mueve el foco al siguiente elemento enfocable dentro de la tarjeta, como un botón o un enlace del área de contenido o de acciones. |
| <kbd>Shift</kbd> + <kbd>Tab</kbd> | Mueve el foco al elemento enfocable anterior dentro de la tarjeta. |

El área de acciones renderiza siempre su región inicial, después su contenido centrado y, por último, su región final. Cambiar las acciones a un diseño vertical las vuelve a estilizar sin reordenar el DOM, de modo que el orden de teclado y de lector de pantalla se mantiene.

### Lectores de pantalla / ARIA

<PlatformBlock for="Angular">

- El host de la tarjeta renderiza `role="group"` y un `id` generado en la forma `igx-card-1`. Establezca la entrada `role` cuando un rol de agrupación distinto encaje con su arquitectura de información, y haga referencia al título de la tarjeta con `aria-labelledby` para que el grupo tenga un nombre accesible.
- `igx-card-media` renderiza `role="img"`, que expone toda la región multimedia como una única imagen y convierte sus hijos en presentacionales, de modo que un atributo `alt` en la imagen interna no le da nombre. Nombre la propia región con `aria-label` o `aria-labelledby`, o establezca su entrada `role` en `presentation` cuando el contenido multimedia sea decorativo.
- Los miembros de encabezado, título, subtítulo, contenido y acciones solo añaden clases de estilo. No aportan roles ni atributos `aria-*`.
- Dé un nombre accesible a los botones solo con icono del área de acciones; el icono por sí solo no proporciona ninguno.
- Use un único elemento interactivo cuando toda la tarjeta active una sola acción, en lugar de asociar un manejador de clic al contenedor, de modo que la acción conserve un rol y un nombre.

</PlatformBlock>

<PlatformBlock for="WebComponents, React, Blazor">

- La tarjeta y cada región de la tarjeta renderizan slots simples y no establecen atributos `role` ni `aria-*`. Los elementos wrapper dentro del encabezado no tienen nombre accesible y no crean puntos de referencia. Añada usted mismo un rol y un nombre accesible en el host de la tarjeta cuando su arquitectura de información lo requiera.
- Los slots `title` y `subtitle` renderizan el elemento que se les pase y no imponen un nivel de encabezado.
- Añada texto `alt` a las imágenes de la región multimedia.
- Dé un nombre accesible a los botones solo con icono del área de acciones; el icono por sí solo no proporciona ninguno.
- Use un único elemento interactivo cuando toda la tarjeta active una sola acción, en lugar de asociar un manejador de clic al contenedor, de modo que la acción conserve un rol y un nombre.

</PlatformBlock>

## Preguntas frecuentes

<Faq>
  <FaqItem question="¿Cómo hago que una tarjeta completa sea pulsable sin romper los lectores de pantalla?" indicatorPosition="end">
    La tarjeta es un contenedor simple y no añade comportamiento interactivo, así que envolver toda la tarjeta en un enlace es un atajo habitual pero perjudicial: el nombre accesible de ese enlace pasa a ser todo el texto de la tarjeta. En su lugar, coloque un enlace o un botón real en el título de la tarjeta y amplíe su área sobre la tarjeta con un pseudoelemento posicionado de forma absoluta que cubra el recuadro de la tarjeta. El título sigue siendo el nombre accesible, todo el rectángulo sigue siendo pulsable, y la selección de texto y el clic con la rueda siguen funcionando.
  </FaqItem>
  <FaqItem question="¿Cómo hago que las tarjetas de una fila o de una cuadrícula tengan la misma altura?" indicatorPosition="end">
    La tarjeta se dimensiona según su contenido y no iguala las alturas de sus hermanas. Disponga las tarjetas en una cuadrícula CSS o en una fila flex para que cada tarjeta se estire hasta la altura de la fila, dé a la región multimedia una altura fija o `aspect-ratio`, y limite el título y el cuerpo a un número fijo de líneas con `-webkit-line-clamp`. Las alturas desiguales de las tarjetas casi siempre se deben a dejar que cada imagen y cada párrafo decidan su propia altura.
  </FaqItem>
  <FaqItem question="¿Por qué se recorta la imagen de mi tarjeta y cómo controlo su tamaño?" indicatorPosition="end">
    <PlatformBlock for="WebComponents, React, Blazor">La región multimedia de la tarjeta estira su contenido al ancho y alto completos de la región y aplica `object-fit: cover`, así que la imagen se recorta en lugar de deformarse. Dimensione la propia región multimedia con `height` o `aspect-ratio` de CSS; cambiar las dimensiones de la imagen interior no tiene ningún efecto.</PlatformBlock><PlatformBlock for="Angular">La región multimedia de la tarjeta controla las dimensiones del contenido multimedia que contiene, así que dimensione la región en lugar de la imagen. Establezca las entradas `height` y `width` en `igx-card-media`, y use una relación de aspecto coherente en todas las tarjetas para que las filas de tarjetas permanezcan alineadas.</PlatformBlock>
  </FaqItem>
  <FaqItem question="¿Por qué aparecen mis acciones de tarjeta en una región distinta de aquella en la que las coloqué?" indicatorPosition="end">
    <PlatformBlock for="Angular">El área de acciones de la tarjeta proyecta el contenido por selector, no por el orden en que lo escribe el autor. Un elemento con `igxButton` y sin `igxEnd` va a la región inicial, y un elemento con `igxIconButton`, o un `igx-icon`, sin `igxStart` va a la región final; solo el contenido que no coincide con ninguno de los dos selectores permanece centrado. Establezca `igxStart` o `igxEnd` de forma explícita para colocar una acción donde desee.</PlatformBlock><PlatformBlock for="WebComponents, React, Blazor">El contenido del slot `end` de las acciones de la tarjeta recibe un margen inicial automático para alinearse con el borde opuesto del área de acciones, lo que hace que una única acción final parezca separada del resto. Mueva el elemento al slot `start` o al slot predeterminado cuando pertenezca al mismo grupo que las demás acciones. Las tres regiones se renderizan siempre en el orden `start`, predeterminado, `end`, con independencia de la orientación.</PlatformBlock>
  </FaqItem>
  <FaqItem question="¿Cuándo debo usar Grid o List en lugar de Card?" indicatorPosition="end">
    Use Grid cuando los datos sean densos y tabulares y los lectores necesiten recorrer, ordenar o comparar entre columnas; use List cuando muchas filas cortas y uniformes deban caber en un espacio reducido. Use Card cuando cada elemento merezca su propio contenido multimedia, un texto más largo y sus propias acciones. Un desplazamiento largo de tarjetas suele ser una lista disfrazada.
  </FaqItem>
