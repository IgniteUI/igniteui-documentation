# Descripción general de {Platform} Dock Manager

El Dock Manager de Infragistics {Platform} permite gestionar el diseño de su aplicación mediante paneles, y que los usuarios finales lo personalicen aún más anclando, redimensionando, moviendo, maximizando y ocultando paneles.

## Ejemplo de {Platform} Dock Manager

Este ejemplo muestra la mayoría de las funciones y opciones de acoplamiento de <ApiLink type="DockManager" /> que puede usar en su aplicación.

## Uso

Una vez importado Dock Manager, puede añadirlo a la página:

<PlatformBlock for="WebComponents">
```html
<igc-dockmanager id="dockManager">
</igc-dockmanager>
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx

</IgrDockManager>
```

<DocsAside type="info">
Como el componente Dock Manager usa ShadowDOM y slots, no es compatible con navegadores antiguos como Internet Explorer 11 y Edge 18 o anteriores (versiones no basadas en Chromium).
</DocsAside>

Dock Manager tiene una propiedad <ApiLink type="DockManager" member="layout" label="Layout" />, que describe la disposición de los paneles. Para empezar a definir un diseño, debe establecer la propiedad <ApiLink type="DocumentHost" member="rootPane" label="RootPane" /> y añadir paneles hijos. Así se define un diseño con un único panel de contenido:

<PlatformBlock for="WebComponents">
```ts
import { IgcDockManagerPaneType, IgcSplitPaneOrientation, IgcDockManagerComponent } from 'igniteui-dockmanager';

// ...

this.dockManager = document.getElementById("dockManager") as IgcDockManagerComponent;
this.dockManager.layout = {
    rootPane: {
        type: IgcDockManagerPaneType.splitPane,
        orientation: IgcSplitPaneOrientation.horizontal,
        panes: [
            {
                type: IgcDockManagerPaneType.contentPane,
                contentId: 'content1',
                header: 'Pane 1'
            }
        ]
    }
};

```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
import {  IgrDockManager, IgrDockManagerPaneType, IgrSplitPaneOrientation } from 'igniteui-react-dockmanager';

// ...

this.dockManager = document.getElementById("dockManager") as IgrDockManager;
this.dockManager.layout = {
    rootPane: {
        type: IgrDockManagerPaneType.splitPane,
        orientation: IgrSplitPaneOrientation.horizontal,
        panes: [
            {
                type: IgrDockManagerPaneType.contentPane,
                contentId: 'content1',
                header: 'Pane 1'
            }
        ]
    }
};
```

</PlatformBlock>

Para cargar el contenido de los paneles, Dock Manager usa [slots](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/slot). El atributo [slot](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/slot) del elemento de contenido debe coincidir con el <ApiLink type="ContentPane" member="contentId" label="ContentId" /> del panel de contenido en la configuración del diseño. Se recomienda encarecidamente establecer el ancho y el alto de los elementos de contenido en **100%** para obtener un comportamiento predecible cuando el usuario final redimensiona los paneles.

<PlatformBlock for="WebComponents">
```html
<igc-dockmanager id="dockManager">
    <div slot="content1" style="width: 100%; height: 100%;">Content 1</div>
</igc-dockmanager>
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
<IgrDockManager id="dockManager">
    <div slot="content1" style={{ width: '100%', height: '100%' }}>Content 1</div>
</IgrDockManager>
```
</PlatformBlock>

Dock Manager define varios tipos de panel:
- <ApiLink type="ContentPane" />
- <ApiLink type="SplitPane" />
- <ApiLink type="TabGroupPane" />
- <ApiLink type="DocumentHost" />

Cada tipo de panel tiene una propiedad <ApiLink type="DocumentHost" member="size" label="Size" />. Según la orientación del padre, el tamaño puede afectar al ancho o al alto del panel. De forma predeterminada, el tamaño de un panel es relativo a los tamaños de sus paneles hermanos y su valor predeterminado es 100. Si tiene dos paneles hermanos, en los que el primero tiene el tamaño 200 y el segundo el tamaño 100, el primero será el doble de grande que el segundo, y los dos ocuparán todo el espacio disponible. Si el tamaño absoluto de su padre es 900 px, se dimensionarán a 600 px y 300 px respectivamente. Si para determinados paneles quiere especificar sus tamaños en píxeles, en lugar de depender de la distribución relativa de todo el espacio disponible, debe establecer la propiedad `useFixedSize` del panel dividido padre.

<PlatformBlock for="WebComponents">
 Para más información, consulte el tema [Split Panes Fixed Size Mode](./dock-manager-customization.mdx#modo-de-tamaño-fijo-para-paneles-divididos).
 </PlatformBlock>

El usuario final puede realizar las siguientes acciones para personalizar el diseño en tiempo de ejecución:
- Anclar o desanclar un panel
- Redimensionar un panel
- Cerrar un panel
- Arrastrar un panel para que flote
- Mover un panel flotante
- Acoplar un panel flotante
- Maximizar un panel

Todas estas acciones se reflejan en la propiedad <ApiLink type="DockManager" member="layout" label="Layout" /> de Dock Manager.

### Panel de contenido

El <ApiLink type="ContentPane" /> representa un panel con encabezado y contenido. Puede alojarse dentro de un Split Pane o de un Tab Group Pane. Así se define un panel de contenido:

<PlatformBlock for="WebComponents">
```ts
const contentPane: IgcContentPane = {
    type: IgcDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1'
}
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const contentPane: IgrContentPane = {
    type: IgrDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1'
}
```
</PlatformBlock>

La propiedad <ApiLink type="ContentPane" member="header" label="Header" /> se usa para proporcionar un encabezado de texto al panel de contenido. Este texto se muestra en varios lugares: el encabezado superior del panel de contenido, el encabezado de la pestaña si el panel está en un grupo de pestañas, y el encabezado desanclado si el panel está desanclado. Puede proporcionar contenido personalizado en slot para cada uno de estos lugares usando, respectivamente, las propiedades <ApiLink type="ContentPane" member="headerId" label="HeaderId" />, <ApiLink type="ContentPane" member="tabHeaderId" label="TabHeaderId" /> y <ApiLink type="ContentPane" member="unpinnedHeaderId" label="UnpinnedHeaderId" />. Si alguna de estas propiedades no está establecida, se usa el texto de <ApiLink type="ContentPane" member="header" label="Header" />. Así se proporciona contenido en slot para el encabezado de una pestaña:

<PlatformBlock for="WebComponents">
```html
<igc-dockmanager id="dockManager">
    <div slot="content1" style="width: 100%; height: 100%;">Content 1</div>
    <span slot="tabHeader1">Pane 1 Tab</span>
</igc-dockmanager>
```
</PlatformBlock>

<PlatformBlock for="WebComponents">
```ts
const contentPane: IgcContentPane = {
    type: IgcDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1',
    tabHeaderId: 'tabHeader1'
}
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
<IgrDockManager id="dockManager">
    <div slot="content1" style={{ width: '100%', height: '100%' }}>Content 1</div>
    <span slot="tabHeader1">Pane 1 Tab</span>
</IgrDockManager>
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const contentPane: IgrContentPane = {
    type: IgrDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1',
    tabHeaderId: 'tabHeader1'
}
```
</PlatformBlock>

Cuando un panel está desanclado, aparece como un encabezado de pestaña en uno de los bordes de Dock Manager. Si el usuario final lo selecciona, su contenido aparece encima de los paneles anclados acoplados. Para desanclar un panel de contenido, establezca su propiedad <ApiLink type="ContentPane" member="isPinned" label="IsPinned" /> en **false**.

<PlatformBlock for="WebComponents">
```ts
const contentPane = {
    type: IgcDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1',
    isPinned: false
}
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const contentPane = {
    type: IgrDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1',
    isPinned: false
}
```
</PlatformBlock>

La propiedad <ApiLink type="ContentPane" member="isPinned" label="IsPinned" /> solo afecta a los paneles de contenido acoplados fuera de un host de documento. Además, los paneles de contenido alojados en un panel flotante no pueden desanclarse.

De forma predeterminada, el destino de desanclado de un panel de contenido se calcula automáticamente según la ubicación del panel respecto al host de documento. Cuando hay más de un host de documento definido, se usa el más cercano en la jerarquía de padres del panel de contenido desanclado. Si no hay ningún host de documento definido, se usa la ubicación predeterminada: `Left`. También es posible establecer el destino deseado del panel desanclado mediante la propiedad <ApiLink type="ContentPane" member="unpinnedLocation" label="UnpinnedLocation" />.

Puede configurar qué operaciones del usuario final están permitidas para un panel de contenido mediante sus propiedades <ApiLink type="ContentPane" member="allowClose" label="AllowClose" />, <ApiLink type="ContentPane" member="allowPinning" label="AllowPinning" />, <ApiLink type="ContentPane" member="allowDocking" label="AllowDocking" /> y <ApiLink type="ContentPane" member="allowFloating" label="AllowFloating" />.

Al definir un panel de contenido, puede establecer la propiedad <ApiLink type="ContentPane" member="documentOnly" label="DocumentOnly" /> en true para que el panel solo pueda acoplarse dentro de un host de documento.

Para restringir la interacción del usuario con el panel de contenido y con su contenido, puede establecer la propiedad <ApiLink type="ContentPane" member="disabled" label="Disabled" /> en true. Esto impedirá todas las interacciones del usuario con el panel, salvo que se trate de un único panel flotante. Este último podrá moverse, maximizarse o cerrarse (según la configuración del panel para maximizar y cerrar), así que el usuario podrá ver los elementos que hay debajo, pero no podrá interactuar con su contenido.

De forma predeterminada, cuando se cierra un panel, se elimina del objeto <ApiLink type="DockManager" member="layout" label="Layout" />. Sin embargo, en algunos casos querrá ocultar el panel temporalmente y mostrarlo de nuevo más tarde. Para hacerlo sin cambiar el objeto <ApiLink type="DockManager" member="layout" label="Layout" />, puede usar la propiedad <ApiLink type="ContentPane" member="hidden" label="Hidden" /> del panel de contenido. Si establece la propiedad en **true**, el panel se ocultará de la interfaz, pero seguirá en el objeto <ApiLink type="DockManager" member="layout" label="Layout" />. Para sustituir el comportamiento de cierre predeterminado, puede suscribirse al evento `PaneClose` así:

<PlatformBlock for="WebComponents">
```ts
this.dockManager.addEventListener('paneClose', ev => {
    for (const pane of ev.detail.panes) {
        pane.hidden = true;
    }
    ev.preventDefault();
});
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
this.dockManager.addEventListener('paneClose', ev => {
    for (const pane of ev.detail.panes) {
        pane.hidden = true;
    }
    ev.preventDefault();
});
```
</PlatformBlock>

### Split Pane

El <ApiLink type="SplitPane" /> es un panel contenedor que apila todos sus <ApiLink type="SplitPane" member="panes" label="Panes" /> hijos en horizontal o en vertical, según su propiedad <ApiLink type="SplitPane" member="orientation" label="Orientation" />. Así se define un split pane horizontal con dos paneles de contenido hijos:

<PlatformBlock for="WebComponents">
```ts
const splitPane: IgcSplitPane = {
    type: IgcDockManagerPaneType.splitPane,
    orientation: IgcSplitPaneOrientation.horizontal,
    panes: [
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content1',
            header: 'Pane 1'
        },
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content2',
            header: 'Pane 2'
        }
    ]
}
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const splitPane: IgrSplitPane = {
    type: IgrDockManagerPaneType.splitPane,
    orientation: IgrSplitPaneOrientation.horizontal,
    panes: [
        {
            type: IgrDockManagerPaneType.contentPane,
            contentId: 'content1',
            header: 'Pane 1'
        },
        {
            type: IgrDockManagerPaneType.contentPane,
            contentId: 'content2',
            header: 'Pane 2'
        }
    ]
}
```
</PlatformBlock>

El split pane puede contener paneles hijos de todos los tipos, incluidos otros split panes.

De forma predeterminada, si el split pane está vacío, no se muestra. Si quiere cambiar ese comportamiento, puede establecer su propiedad <ApiLink type="SplitPane" member="allowEmpty" label="AllowEmpty" /> en true, y el split pane se mostrará en la interfaz aunque no contenga paneles.

### Tab Group Pane

El <ApiLink type="TabGroupPane" /> muestra sus <ApiLink type="SplitPane" member="panes" label="Panes" /> hijos de contenido como las pestañas de un componente de pestañas. Así se define un tab group pane con un panel de contenido para cada una de sus dos pestañas:

<PlatformBlock for="WebComponents">
```ts

        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content1',
            header: 'Pane 1'
        },
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content2',
            header: 'Pane 2'
        }
    ]
}
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const tabGroupPane: IgrTabGroupPane = {
    type: IgrDockManagerPaneType.tabGroupPane,
    panes: [
        {
            type: IgrDockManagerPaneType.contentPane,

            header: 'Pane 1'
        },
        {
            type: IgrDockManagerPaneType.contentPane,
            contentId: 'content2',
            header: 'Pane 2'
        }
```

Si no hay espacio suficiente para mostrar todos los encabezados de pestaña, el grupo de pestañas muestra un menú **More tabs** con las pestañas no visibles. Si hace clic en un elemento de pestaña de ese menú, la pestaña se selecciona y se mueve a la primera posición.

Las pestañas también pueden reordenarse sin separarse del grupo de pestañas en el que están. Puede hacer clic en la pestaña que quiera y arrastrarla a la izquierda o a la derecha hasta la posición deseada. Si arrastra la pestaña seleccionada fuera de la zona de pestañas, se separará en un panel flotante.

Si quiere que el tab group pane se muestre en la interfaz cuando no tiene pestañas, puede establecer la propiedad <ApiLink type="SplitPane" member="allowEmpty" label="AllowEmpty" /> en true.

### Panel flotante

El panel flotante es un split pane que se muestra por encima de todos los demás, en una ventana flotante. Las definiciones de los paneles flotantes se almacenan en la propiedad <ApiLink type="DockManagerLayout" member="floatingPanes" label="FloatingPanes" /> de <ApiLink type="DockManager" member="layout" label="Layout" />. Así se añade un panel flotante con un único panel de contenido dentro:

<PlatformBlock for="WebComponents">
```ts
const layout: IgcDockManagerLayout = {
    rootPane: {
        // ...
    },
    floatingPanes: [
        {
            type: IgcDockManagerPaneType.splitPane,
            orientation: IgcSplitPaneOrientation.horizontal,
            floatingLocation: { x: 80, y: 80 },
            floatingWidth: 200,
            floatingHeight: 150,
            floatingResizable: true,
            panes: [
                {
                    type: IgcDockManagerPaneType.contentPane,
                    contentId: 'content1',
                    header: 'Floating Pane 1'
                }
            ]
        }
    ]
};
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const layout: IgrDockManagerLayout = {
    rootPane: {
        // ...
    },
    floatingPanes: [
        {
            type: IgrDockManagerPaneType.splitPane,
            orientation: IgrSplitPaneOrientation.horizontal,
            floatingLocation: { x: 80, y: 80 },
            floatingWidth: 200,
            floatingHeight: 150,
            floatingResizable: true,
            panes: [
                {
                    type: IgrDockManagerPaneType.contentPane,
                    contentId: 'content1',
                    header: 'Floating Pane 1'
                }
            ]
        }
    ]
};
```
</PlatformBlock>

Las propiedades <ApiLink type="SplitPane" member="floatingLocation" label="FloatingLocation" />, <ApiLink type="SplitPane" member="floatingWidth" label="FloatingWidth" /> y <ApiLink type="SplitPane" member="floatingHeight" label="FloatingHeight" /> representan dimensiones absolutas en píxeles. Tenga en cuenta que estas propiedades solo se aplican a los split panes del array <ApiLink type="DockManagerLayout" member="floatingPanes" label="FloatingPanes" />.

Con <ApiLink type="SplitPane" member="floatingResizable" label="FloatingResizable" /> y
<ApiLink type="DockManager" member="allowFloatingPanesResize" label="AllowFloatingPanesResize" /> puede establecer si se permite redimensionar los paneles flotantes. `allowFloatingPanesResize` es una propiedad de **IgcDockManagerComponent**, así que si su valor es **false**, ninguno de los paneles flotantes puede redimensionarse. La propiedad `floatingResizable` puede aplicarse por separado a cada split pane del array `floatingPanes`, y si no se establece, toma el valor de la propiedad `allowFloatingPanesResize`. Si la propiedad `floatingResizable` se establece para un panel concreto, su valor tiene prioridad sobre el valor de la propiedad `allowFloatingPanesResize`.

### Panel activo

El componente Dock Manager resalta el panel de contenido que contiene el foco y lo expone en su propiedad <ApiLink type="Spreadsheet" member="activePane" label="ActivePane" />. Puede cambiar el panel activo mediante programación estableciendo la propiedad. También puede escuchar los cambios de la propiedad <ApiLink type="Spreadsheet" member="activePane" label="ActivePane" /> suscribiéndose al evento `ActivePaneChanged`:

<PlatformBlock for="WebComponents">
```ts

```
</PlatformBlock>

<PlatformBlock for="React">

### Redimensionar paneles

Los usuarios finales redimensionan los paneles arrastrando el splitter que hay entre ellos. Mientras se arrastra el splitter, una silueta sigue al puntero, y los paneles se redimensionan cuando se suelta el puntero.

Los usuarios finales también pueden redimensionar paneles en ambas direcciones a la vez. Cuando dos splitters se encuentran, por ejemplo cuando uno termina sobre otro formando una T, al pasar el puntero por el punto de encuentro el cursor cambia a un cursor de movimiento. Si arrastra desde ahí, se mueven ambos splitters a la vez y se redimensionan los paneles a ambos lados de cada splitter.

Al pulsar el punto de encuentro, se resaltan ambos splitters, y permanecen resaltados hasta que el foco se mueve a otro lugar. Mientras están resaltados, las teclas de flecha mueven ambos, como se describe en [Keyboard Navigation](#navegación-por-teclado).

Cuando ambos splitters se arrastran juntos, Dock Manager dispara los eventos `splitterResizeStart` y `splitterResizeEnd` para cada uno de ellos. Cancelar `splitterResizeStart` en cualquiera de los dos splitters cancela el redimensionado de ambos.

### Acoplamiento

Cuando empieza a arrastrar un panel flotante, aparecen distintos indicadores de acoplamiento según la posición del panel arrastrado. Hay cuatro tipos principales de acoplamiento: acoplamiento raíz, acoplamiento de panel, acoplamiento de host de documento y acoplamiento de splitter. El acoplamiento en bordes está disponible como comportamiento adicional cuando el acoplamiento raíz está deshabilitado, y funciona en la dirección de la orientación del split pane raíz.

#### Acoplamiento raíz

En este tipo de acoplamiento, mientras arrastra un panel aparecen cuatro indicadores de flecha cerca de los cuatro bordes de dock manager. Al soltar, el panel arrastrado pasará a ser un hijo directo del <ApiLink type="DocumentHost" member="rootPane" label="RootPane" /> de Dock Manager. Visualmente, el panel recién acoplado se ajusta en su borde correspondiente y ocupa hasta la mitad del ancho o del alto de dock manager, desplazando el resto del contenido a la otra mitad.

<Image src={dockmanagerRootDocking} alt="dockmanager-root-docking" class="responsive-img" />

#### Acoplamiento de panel

Aparecen indicadores de acoplamiento en el centro de un panel de contenido o de un tab group pane cuando arrastra el panel flotante sobre él. Al soltar, el panel arrastrado se ajusta en cualquier lado del panel de destino o se agrupa con él para crear un diseño con pestañas. Según la combinación del diseño inicial y la posición de acoplamiento, la operación puede crear dinámicamente un nuevo split o tab group pane que pasará a ser el padre de ambos paneles, el arrastrado y el de destino.

<Image src={dockmanagerPaneDocking} alt="dockmanager-pane-docking" class="responsive-img" />

#### Acoplamiento en host de documento

Si el panel arrastrado está sobre un host de documento, aparecen indicadores de acoplamiento adicionales que permiten acoplar en relación con el panel de destino o con todo el host de documento.

<Image src={dockmanagerDocumentHostDocking} alt="dockmanager-document-host-docking" class="responsive-img" />

#### Acoplamiento de splitter

El acoplamiento de splitter permite a los usuarios finales colocar paneles con precisión dentro de un diseño dividido existente. Mientras arrastra un panel flotante, si el cursor se acerca a cualquier splitter entre dos paneles, aparecerá un indicador de acoplamiento sobre ese splitter.

Cuando el usuario suelta el panel sobre este indicador, dock manager inserta el panel en el split pane que contiene el splitter de destino, ajustando los paneles vecinos para hacer sitio. Así es fácil refinar diseños complejos insertando nuevas herramientas o vistas exactamente entre dos paneles existentes, sin tener que reestructurar todo el diseño.

Si su escenario requiere una experiencia más sencilla, sin este nivel de precisión, el acoplamiento de splitter puede deshabilitarse estableciendo la propiedad `allowSplitterDock` de Dock Manager en **false**.

<Image src={dockmanagerSplitterDocking} alt="dockmanager-splitter-docking" class="responsive-img" />

#### Acoplamiento en bordes

El acoplamiento en bordes ofrece a los usuarios finales una forma sencilla de añadir paneles importantes al principio o al final de su diseño principal, sin tener que apuntar con cuidado a un splitter o panel concreto. Una vez deshabilitado el acoplamiento raíz estableciendo la propiedad `allowRootDock` en **false**, dock manager activa automáticamente los indicadores de acoplamiento en bordes a lo largo de las posiciones primera y última del split pane raíz. Como el split pane raíz es horizontal o vertical, el acoplamiento en bordes solo está disponible en esa única dirección (izquierda/derecha para una raíz horizontal, o arriba/abajo para una raíz vertical).

Este comportamiento resulta especialmente útil cuando el panel raíz es desplazable (cuando su propiedad `useFixedSize` está establecida en **true** y el contenido se extiende más allá de la zona visible). En estos escenarios, los usuarios pueden:

- En un split pane raíz **horizontal**, arrastrar cualquier panel hacia el borde **izquierdo** para acoplarlo como primer elemento, o hacia el borde **derecho** para acoplarlo como último elemento.
- En un split pane raíz **vertical**, arrastrar cualquier panel hacia el borde **superior** para acoplarlo como primer elemento, o hacia el borde **inferior** para acoplarlo como último elemento.

Cuando el usuario suelta el panel sobre el indicador de acoplamiento en bordes, dock manager inserta el panel en el borde elegido y lo desplaza automáticamente a la vista. Así se garantiza que las ventanas de herramientas o los paneles recién añadidos sean visibles de inmediato, incluso en diseños complejos y desplazables.

## Navegación por teclado

La navegación por teclado mejora la accesibilidad de **Dock Manager** y ofrece al usuario final una gran variedad de interacciones, como recorrer todos los paneles o dividir la vista en varias direcciones acoplando el panel activo.


Los atajos son los siguientes:

### Acoplamiento

- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>↑</kbd> Acopla al borde superior global
- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>↓</kbd> Acopla al borde inferior global
- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>→</kbd> Acopla al borde derecho global
- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>←</kbd> Acopla al borde izquierdo global
- <kbd>SHIFT</kbd> + <kbd>↑</kbd> Con varias pestañas en un grupo de pestañas, divide la vista y acopla la pestaña enfocada arriba
- <kbd>SHIFT</kbd> + <kbd>↓</kbd> Con varias pestañas en un grupo de pestañas, divide la vista y acopla la pestaña enfocada abajo
- <kbd>SHIFT</kbd> + <kbd>→</kbd> Con varias pestañas en un grupo de pestañas, divide la vista y acopla la pestaña enfocada a la derecha
- <kbd>SHIFT</kbd> + <kbd>←</kbd> Con varias pestañas en un grupo de pestañas, divide la vista y acopla la pestaña enfocada a la izquierda

### Navegación
- <kbd>CMD/CTRL</kbd> + <kbd>F6</kbd> o <kbd>CMD/CTRL</kbd> + <kbd>→</kbd> Enfoca la siguiente pestaña del host de documento
- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>F6</kbd> o <kbd>CMD/CTRL</kbd> + <kbd>←</kbd> Enfoca la pestaña anterior del host de documento
- <kbd>ALT</kbd> + <kbd>F6</kbd> Enfoca el siguiente panel de contenido
- <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>F6</kbd> Enfoca el panel de contenido anterior

### Navegador de paneles

Los siguientes atajos de teclado muestran un navegador desde el que puede recorrer paneles y documentos.

- <kbd>CMD/CTRL</kbd> + <kbd>F7</kbd> o <kbd>CMD/CTRL</kbd> + <kbd>F8</kbd>  Empieza por el primer documento y avanza
- <kbd>ALT</kbd> + <kbd>F7</kbd> o <kbd>ALT</kbd> + <kbd>F8</kbd> Empieza por el primer panel y avanza
- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>F7</kbd> o <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>F8</kbd> Empieza por el último documento y retrocede
- <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>F7</kbd> o <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>F8</kbd> Empieza por el último panel y retrocede

### Redimensionamiento
- <kbd>←</kbd> / <kbd>→</kbd> Mueve el splitter vertical enfocado a la izquierda o a la derecha 10 píxeles
- <kbd>↑</kbd> / <kbd>↓</kbd> Mueve el splitter horizontal enfocado hacia arriba o hacia abajo 10 píxeles
- <kbd>←</kbd> / <kbd>→</kbd> y <kbd>↑</kbd> / <kbd>↓</kbd> Tras pulsar el punto donde se encuentran dos splitters, mueve el splitter vertical y el horizontal, respectivamente, 10 píxeles

### Otros
- <kbd>ALT</kbd> + <kbd>F3</kbd> Cierra el panel activo

Practique todas las acciones anteriores en la [demo](./dock-manager.mdx#ejemplo-de-{PlatformLower}-dock-manager) de ejemplo.

## Localización

Dock Manager permite localizar las cadenas que se usan en los menús contextuales, los tooltips y los atributos ARIA. De forma predeterminada, lee el atributo [lang](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/lang) del elemento `<html>` raíz para determinar el idioma que debe usar. Si el atributo [lang](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/lang) falta o tiene un valor no compatible, Dock Manager usa [English (en)]({environment:infragisticsBaseUrl}/products/ignite-ui/dock-manager/docs/typescript/latest/index.html#IgcDockManagerResourceStringsEN).

<PlatformBlock for="WebComponents">
Las cadenas de recursos listas para usar de Dock Manager en español (`es`), japonés (`ja`) y coreano (`ko`) se proporcionan a través de la dependencia de pares `igniteui-i18n-resources`. Para usar uno de estos idiomas, instale `igniteui-i18n-resources` y registre el paquete correspondiente con `igniteui-i18n-core`:

```ts
import { registerI18n } from 'igniteui-i18n-core';
import { DockManagerResourceStringsES } from 'igniteui-i18n-resources';

registerI18n(DockManagerResourceStringsES, 'es');
```

Si necesita admitir otro idioma, use el método [addResourceStrings]({environment:infragisticsBaseUrl}/products/ignite-ui/dock-manager/docs/typescript/latest/index.html#addResourceStrings) para proporcionar sus propias cadenas traducidas:

```ts
import { addResourceStrings } from 'igniteui-dockmanager';

const dockManagerStringsFr: IgcDockManagerResourceStrings = {
  close: 'Fermer',
  // ...
};

addResourceStrings('fr', dockManagerStringsFr);
```

</PlatformBlock>

Dock Manager también expone una propiedad <ApiLink type="DockManager" member="resourceStrings" label="ResourceStrings" /> que puede usar para modificar cadenas concretas directamente. Cuando establece la propiedad <ApiLink type="DockManager" member="resourceStrings" label="ResourceStrings" />, Dock Manager usa las cadenas que usted proporcione, independientemente del atributo [lang](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/lang) de la página.


</PlatformBlock>
