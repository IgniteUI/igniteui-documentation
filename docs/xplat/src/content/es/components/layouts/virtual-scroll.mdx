# Componente Virtual Scroll

{ProductName} Virtual Scroll es un componente que renderiza listas grandes manteniendo en el DOM solo los elementos de su ventana gráfica, más un búfer configurable. La barra de desplazamiento sigue abarcando toda la colección, de modo que una lista virtual de cien mil elementos se desplaza como una lista normal.

<span class="ig-typography__body-2" style="display: block; margin-bottom: 24px;"><strong>1. Host:</strong> el contenedor de desplazamiento. Su altura fija (el ancho cuando es horizontal) determina cuántos elementos son visibles.<br />

<strong>5. Búfer de sobreescaneo:</strong> los elementos <code>overScan</code> (2 de forma predeterminada) renderizados más allá de cada borde de la ventana gráfica.</span>

## Uso

### Plantilla de elemento

La plantilla de elemento de Virtual Scroll recibe el elemento y su posición dentro de toda la colección. Use el índice y el recuento total para el contenido que depende de la posición, como estilos alternos o `aria-posinset` y `aria-setsize`.

<PlatformBlock for="Angular">

Marque un `ng-template` con `igxVirtualItem`, o pase una plantilla definida en otro lugar mediante <ApiLink type="VirtualScroll" member="itemTemplate" label="itemTemplate" />, que tiene prioridad. El contexto de la plantilla proporciona `$implicit` (el elemento), `index`, `count`, `first`, `last`, `even` y `odd`.

```html
<igx-list>
    <igx-virtual-scroll role="presentation" [data]="employees" [estimatedItemSize]="64" style="height: 480px">
        <ng-template igxVirtualItem let-employee let-index="index" let-count="count">
            <igx-list-item [attr.aria-posinset]="index + 1" [attr.aria-setsize]="count">
                <igx-avatar igxListThumbnail shape="circle" [initials]="employee.initials"></igx-avatar>
                <span igxListLineTitle>{{ employee.name }}</span>
                <span igxListLineSubTitle>{{ employee.email }}</span>
            </igx-list-item>
        </ng-template>
    </igx-virtual-scroll>
</igx-list>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

Establezca <ApiLink type="VirtualScroll" member="itemTemplate" label="itemTemplate" /> en una función que devuelva una plantilla de Lit. La función recibe un `VirtualScrollItemContext` con `value` (el elemento), `index`, `count`, `isFirst` y `isLast`. Sin una plantilla de elemento, el componente no renderiza nada.

```ts

    <igc-list-item aria-posinset=${ctx.index + 1} aria-setsize=${ctx.count}>
        <igc-avatar slot="start" shape="circle" initials=${ctx.value.initials}></igc-avatar>
        <span slot="title">${ctx.value.name}</span>
        <span slot="subtitle">${ctx.value.email}</span>
    </igc-list-item>
`;
```

</PlatformBlock>

### Datos

La colección <ApiLink type="VirtualScroll" member="data" label="data" /> de Virtual Scroll se compara por referencia. Asigne un nuevo array para actualizar la lista; modificar in situ el array enlazado, por ejemplo con `push`, no la actualiza.

<PlatformBlock for="Angular">

```ts
this.employees = [...this.employees, newEmployee];
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```ts
virtualScroll.data = [...virtualScroll.data, newEmployee];
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
setEmployees(current => [...current, newEmployee]);
```

</PlatformBlock>

Cuando cambia `data`, el componente conserva los tamaños medidos de los elementos anteriores al primer índice modificado y vuelve a medir el resto cuando se renderizan. Añadir al final conserva todas las mediciones existentes; reemplazar, filtrar u ordenar descarta las mediciones desde el primer elemento modificado en adelante.

<PlatformBlock for="React, WebComponents">

Un elemento conserva su elemento DOM mientras su clave esté en la ventana renderizada. Sin <ApiLink type="VirtualScroll" member="keyFunction" label="keyFunction" />, el índice es la clave, así que tras una ordenación, una inserción o una eliminación, el elemento de un índice permanece y muestra su nuevo elemento. Devuelva un id estable desde `keyFunction` cuando los elementos se muevan dentro de `data`:

```ts
virtualScroll.keyFunction = (employee) => employee.id;
```

</PlatformBlock>

### Tamaño estimado de los elementos

El <ApiLink type="VirtualScroll" member="estimatedItemSize" label="estimatedItemSize" /> de Virtual Scroll es el tamaño en píxeles que tiene un elemento hasta que se renderiza y se mide (`50` de forma predeterminada). Los elementos pueden tener tamaños distintos: cada tamaño medido sustituye a la estimación.

<PlatformBlock for="Angular">

Establezca la estimación cerca del tamaño medio de los elementos para que la barra de desplazamiento y `scrollToIndex` sean precisos antes de medir los elementos.

</PlatformBlock>

Una vez medidos los elementos, su media sustituye a la estimación para los elementos que todavía no se han medido, de modo que la barra de desplazamiento y `scrollToIndex` se corrigen solos aunque la estimación no sea exacta.

</PlatformBlock>

### Desplazarse hasta un índice

El método <ApiLink type="VirtualScroll" member="scrollToIndex" label="scrollToIndex" /> de Virtual Scroll desplaza un elemento a la vista. Sus opciones son las del `scrollIntoView` nativo: `block` (`start`, `center`, `end` o `nearest`), `inline` para una lista horizontal, y `behavior` (`auto` o `smooth`). Los elementos que no se han renderizado solo tienen un tamaño estimado, así que el componente mide los elementos en los que aterriza y corrige la posición; la promesa devuelta se resuelve en la posición final.

    await this.virtualScroll().scrollToIndex(index, { block: 'center' });
}

### Desplazamiento infinito

<PlatformBlock for="Angular">

La salida <ApiLink type="VirtualScroll" member="dataRequest" label="dataRequest" /> de Virtual Scroll admite la carga solo de adición a partir de datos remotos. Se emite cuando la ventana renderizada se acerca al final de `data`, y en el primer renderizado cuando los elementos cargados no llenan la ventana gráfica. Añada los elementos solicitados como un nuevo array:

```html
<igx-virtual-scroll [data]="employees()" [estimatedItemSize]="64" (dataRequest)="loadMore($event)" style="height: 440px">
    <ng-template igxVirtualItem let-employee>...</ng-template>
</igx-virtual-scroll>
```

```ts
public readonly employees = signal<Employee[]>(firstPage);

public loadMore(request: VirtualScrollDataRequest): void {
    this.service.fetch(request.startIndex, request.count).subscribe(page => {
        this.employees.update(current => [...current, ...page]);
    });
}
```

### Datos paginados

La entrada <ApiLink type="VirtualScroll" member="dataWindow" label="dataWindow" /> de Virtual Scroll de Angular enlaza una página de una colección mayor en lugar de `data`. La lista tiene la longitud de `totalCount`, de modo que la barra de desplazamiento abarca toda la colección mientras solo la página está en memoria, y los índices que la página no cubre no renderizan nada.

```ts
interface VirtualDataWindow<T> {
    readonly items: readonly T[]; // the loaded page
    readonly startIndex: number;  // the index of items[0] in the whole collection
    readonly totalCount: number;  // the size of the whole collection
}
```

Cargue la página siguiente del intervalo que informa <ApiLink type="VirtualScroll" member="stateChange" label="stateChange" />. Cancele la solicitud anterior, para que una respuesta lenta no sustituya a una página más reciente:

```html
<igx-virtual-scroll [dataWindow]="page()" [estimatedItemSize]="64" (stateChange)="onStateChange($event)" style="height: 440px">
    <ng-template igxVirtualItem let-employee>...</ng-template>
</igx-virtual-scroll>
```

```ts
public readonly page = signal<VirtualDataWindow<Employee>>({ items: [], startIndex: 0, totalCount: 100_000 });
private pending?: Subscription;

public onStateChange(state: VirtualScrollState): void {
    const page = this.page();
    if (state.startIndex >= page.startIndex && state.endIndex < page.startIndex + page.items.length) {
        return; // The loaded page already covers the range.
    }

    const startIndex = Math.max(0, state.startIndex - 30);
    const count = state.endIndex + 30 - startIndex + 1;

    this.pending?.unsubscribe();
    this.pending = this.service.fetch(startIndex, count).subscribe(result => {
        this.page.set({ items: result.items, startIndex, totalCount: result.total });
    });
}
```

<Sample src="/data-display/virtual-scroll-paged-data" height={560} alt="Virtual Scroll de Angular cargando páginas de una colección remota" />

Los tamaños medidos se conservan por índice mientras `totalCount` no cambie; una página con un `totalCount` distinto, como un resultado filtrado, se vuelve a medir. `dataRequest` no se emite mientras `dataWindow` está enlazado. El componente guarda una entrada de tamaño por índice, así que su memoria crece con `totalCount`: unos 17 MB para un millón de elementos.

</PlatformBlock>

### Qué hacer y qué no

Virtual Scroll suele funcionar como el contenedor de desplazamiento de una lista larga, manteniendo en el DOM solo los elementos de su ventana gráfica, más un pequeño búfer. Evítelo en una lista lo bastante corta para renderizarla de una vez, y al escribir la plantilla del elemento, mantenga el estado de cada elemento en los datos y no en sus elementos del DOM: los elementos se reutilizan, así que el estado del DOM que la plantilla no enlaza aparece en cualquier elemento que ocupe ese DOM.

## Accesibilidad

{Platform} Virtual Scroll mantiene en el DOM solo la ventana renderizada, así que la plantilla del elemento tiene que exponer la posición de cada elemento dentro de toda la colección.

### Interacción por teclado

{Platform} Virtual Scroll no añade manejadores de teclas. El host es un contenedor de desplazamiento nativo, y un contenedor de desplazamiento con el foco se desplaza con las teclas del navegador:

| Clave | Acción |
| --- | --- |
| Flecha arriba / Flecha abajo | Desplaza una lista vertical. |
| Flecha izquierda / Flecha derecha | Desplaza una lista horizontal. |
| Re Pág / Av Pág | Desplaza aproximadamente una ventana gráfica. |
| Home / End | Desplaza hasta el inicio o el final de la colección. |

El host no tiene `tabindex`. Los navegadores difieren en si un contenedor de desplazamiento sin contenido enfocable puede recibir el foco, así que establezca `tabindex="0"` en el host cuando los elementos no contengan nada enfocable. El foco dentro de un elemento no sobrevive a que ese elemento salga de la ventana renderizada, así que mueva el foco de forma deliberada antes de que ocurra.

### Lectores de pantalla / ARIA

<PlatformBlock for="Angular">

- El host tiene `role="list"`; el track, el elemento de contenido y los wrappers de elemento tienen `role="presentation"`. Los elementos que renderizan `role="listitem"`, como `igx-list-item`, se exponen como elementos de esa lista.
- Dentro de un contenedor que ya proporciona semántica de lista, como `igx-list`, establezca `role="presentation"` en el host para que los elementos no queden anidados en una segunda lista.
- Asigne las variables de plantilla `index` y `count` a `aria-posinset` y `aria-setsize`.
- Dé un nombre accesible a un host enfocable con `aria-label` o `aria-labelledby`.

</PlatformBlock>

<PlatformBlock for="React, WebComponents">

- El track, el elemento de contenido y los wrappers de elemento tienen `role="presentation"`. El host no tiene rol: colóquelo dentro de un elemento con un rol de lista, como `igc-list`, o dele `role="list"` cuando los elementos rendericen `role="listitem"`.
- Asigne las propiedades de contexto `index` y `count` a `aria-posinset` y `aria-setsize`.
- Dé a un host enfocable un rol que admita un nombre accesible, como `role="list"`, y nómbrelo con `aria-label` o `aria-labelledby`.

</PlatformBlock>

### Cumplimiento de accesibilidad

Infragistics documenta las normas de accesibilidad a las que apunta {ProductName} en el tema [Accessibility Compliance](../interactivity/accessibility-compliance.mdx). Este tema no hace ninguna declaración de conformidad para Virtual Scroll: la tabla enumera lo que proporciona el componente, y la lista posterior cubre lo que la aplicación debe añadir.

| Criterio | Cómo el componente cumple el requisito |
| --- | --- |
| [1.3.1 Información y relaciones](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships) | Los wrappers son presentacionales, así que la estructura de lista procede del host y de la plantilla del elemento, que puede exponer la posición de cada elemento con `aria-posinset` y `aria-setsize`. |
| [2.1.1 Teclado](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | El host es un contenedor de desplazamiento nativo que se desplaza con el teclado una vez que tiene el foco. Llegar a él con el teclado depende de la aplicación; consulte la lista siguiente. |

Sus responsabilidades:

- Haga el host accesible con el teclado mediante `tabindex="0"` cuando los elementos no contengan nada enfocable, y dé al host un nombre accesible.
- Exponga la posición del elemento con `aria-posinset` y `aria-setsize` desde la plantilla del elemento.
- Proporcione una semántica de lista que encaje con la plantilla del elemento (véase [Screen Readers / ARIA](#lectores-de-pantalla--aria)).
- Mantenga el estado de la aplicación, como una selección, en los datos y no en los elementos renderizados.

## Solución de problemas

### ¿Por qué Virtual Scroll no renderiza ningún elemento?

El host no tiene tamaño en el eje de desplazamiento, falta la plantilla del elemento, o `data` está vacío. Dé al host una altura fija (vertical) o un ancho fijo (horizontal), establezca la plantilla del elemento y compruebe la colección enlazada.

### ¿Por qué la lista no se actualiza cuando añado un elemento?

Virtual Scroll compara `data` por referencia, así que un cambio in situ no se detecta. Asigne un nuevo array, por ejemplo `[...items, newItem]`.

### ¿Por qué cambia de tamaño la barra de desplazamiento mientras me desplazo?

Los elementos que no se han renderizado usan `estimatedItemSize`, y el tamaño total se corrige a medida que se miden los elementos.

<PlatformBlock for="Angular">

Establezca `estimatedItemSize` cerca del tamaño medio de los elementos.

</PlatformBlock>

<PlatformBlock for="React, WebComponents">

El tamaño medio medido sustituye entonces a la estimación para los elementos que todavía no se han medido, de modo que la corrección se estabiliza mientras se desplaza. Establezca `estimatedItemSize` cerca del tamaño medio de los elementos para que el primer renderizado se aproxime al contenido real.

</PlatformBlock>

### ¿Por qué los elementos se desplazan de su posición más abajo en la lista?

Los márgenes no forman parte del tamaño medido de un elemento. Sustituya los márgenes de los elementos por relleno, o por un `gap` dentro del elemento.

<PlatformBlock for="Angular">

### ¿Por qué una lista dentro de un desplegable o de un diálogo muestra sus elementos con un fotograma de retraso?

Un contenedor que permanece oculto hasta que se abre no tiene tamaño en la pasada de detección de cambios que lo muestra, así que el host se mide después de ese renderizado y los elementos se renderizan en el fotograma siguiente. Lea los elementos renderizados después de que se resuelva `layoutComplete`.

### ¿Cómo sustituyo una lista igxForOf por Virtual Scroll?

Virtual Scroll mide los elementos en tiempo de ejecución y crea su propio contenedor de desplazamiento, así que el tamaño del contenedor y las entradas del contenedor de desplazamiento de `igxForOf` no tienen equivalente. La directiva `igxForOf` está obsoleta en favor de Virtual Scroll; las listas existentes siguen funcionando, pero use Virtual Scroll para las listas nuevas que virtualizan un único eje.

| igxForOf | Desplazamiento virtual |
| --- | --- |
| `*igxFor="let item of data"` | `[data]="data"` con un `ng-template igxVirtualItem` |
| `igxForScrollOrientation` | `orientation` |
| `igxForContainerSize` | La altura o el ancho del host, establecidos con CSS |
| `igxForItemSize` | `estimatedItemSize` (una estimación inicial; los elementos se miden) |
| `igxForScrollContainer` | No es necesario: el host es el contenedor de desplazamiento |
| `scrollTo(index)` | `scrollToIndex(index, options)`, que devuelve una promesa |
| `chunkLoad`, `chunkPreload` | `stateChange` |
| `igxForTotalItemCount` para datos remotos | `dataWindow` con `totalCount`, o `data` con `dataRequest` para la carga solo de adición |
| `index`, `count`, `first`, `last`, `even`, `odd` | Las mismas variables de plantilla |

Las cuadrículas mantienen su propia virtualización de filas y columnas; consulte [Grid Virtualization](../grid/virtualization.mdx).

</PlatformBlock>

## Limitaciones conocidas

- {Platform} Virtual Scroll virtualiza un único eje. Las filas y las columnas que se virtualizan a la vez requieren una cuadrícula.
- Los elementos se reutilizan a medida que la ventana se mueve, así que el estado del DOM que la plantilla del elemento no enlaza, como una casilla sin un `checked` enlazado, aparece en el elemento que ocupe ese DOM. Enlace todo el estado del elemento y escriba los cambios del usuario de vuelta en el elemento.

<PlatformBlock for="Angular">

- Con `dataWindow`, una página que conserva `totalCount` pero coloca registros distintos en los mismos índices mantiene los tamaños medidos de los registros anteriores hasta que esas filas se vuelven a renderizar.

</PlatformBlock>
