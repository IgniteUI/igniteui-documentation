## Usar Ignite UI CLI

Para crear una aplicación desde cero y configurarla para usar Ignite UI React, puede usar Ignite UI CLI. El primer paso es instalar el paquete correspondiente de forma global, como se indica a continuación:

```cmd
npm install -g igniteui-cli
```

Si quiere una experiencia guiada por las opciones disponibles, puede iniciar el modo paso a paso, que le ayudará a crear y configurar su nueva aplicación. Para iniciar la guía, basta con ejecutar el comando `ig`:

```cmd
ig
```

A continuación, elija `\React` como framework y `Ignite UI for React TS` como tipo de proyecto. Seleccione **Side Navigation** o **Side Navigation Mini** para empezar con una disposición de navegación. Después de seleccionar cualquiera de las plantillas de navegación, el asistente pregunta si desea añadir autenticación. La plantilla **Empty** no muestra la opción de autenticación. Después puede añadir un componente o vista concretos, o seleccionar `Complete & Run`.

O cree un proyecto directamente con un único comando, por ejemplo:

```cmd
ig new <project-name> --framework=react --type=igr-ts --template=side-nav
```

Para un recorrido paso a paso por el asistente y por el complemento de autenticación, consulte [Guía paso a paso con Ignite UI CLI](./general-step-by-step-guide-using-cli.mdx). Para una referencia completa de todos los comandos de la CLI, los ID de plantilla y el uso directo de plantillas de autenticación, consulte la [información general de la CLI](./general-cli-overview.mdx).

Si añadió un componente Grid durante las preguntas, cuando la aplicación esté en ejecución debería ver algo similar a lo siguiente:

<Image src={igCliGrid} alt="" />

<DocsAside type="info">
Tenga en cuenta que, de forma predeterminada, Ignite UI CLI instala la versión Trial del componente Grid de Ignite UI for React, que está sujeta a una [licencia comercial](./general-open-source-vs-premium.mdx#tabla-comparativa-de-todos-los-componentes).
</DocsAside>

Como alternativa, puede usar frameworks populares como Next.js, Vite o Expo, tal como recomienda el equipo de React. A continuación se indican instrucciones paso a paso para crear aplicaciones React con Ignite UI for React usando uno de estos métodos.

## Usar Vite CLI

### Crear un proyecto React nuevo

Todos los frameworks populares para el desarrollo con React ofrecen potentes herramientas CLI para generar la estructura base de una aplicación React.

1 - Abra **VS Code**, seleccione el menú **Terminal** y después la opción **Nueva terminal**.

2 - Escriba el siguiente comando en la ventana de la terminal:

```cmd
npm create vite@latest
```

A continuación, siga las indicaciones para elegir un nombre para el proyecto, React como framework, si quiere usar TypeScript y otras opciones que ofrece Vite. Consulte este <a href="https://react.dev/learn/creating-a-react-app" target="_blank">tema</a> para más información sobre las distintas formas de generar la plantilla base de una aplicación React.

### Añadir un componente Grid de Ignite UI React

#### Instalación de paquetes
Para añadir el componente [**Grid**](./grids/data-grid.mdx) de Ignite UI React a la aplicación, debe instalar el paquete `igniteui-react-grids`:

```cmd
npm install igniteui-react-grids --save
```

#### Importar los módulos de componentes

A continuación podemos importar los módulos necesarios de los componentes que queremos usar. Hagámoslo para los componentes Grid y Column, que también usaremos en la plantilla. También necesitamos importar uno de los temas.

```ts
import { IgrGrid, IgrColumn } from 'igniteui-react-grids';
import 'igniteui-react-grids/grids/themes/light/bootstrap.css';
```

#### Usar los componentes

Ya estamos listos para usar el componente de cuadrícula {ProductName} en nuestro marcado. Vamos a definirlo:

```tsx
// App.tsx
function App() {
  const data = [
    { name: "John", age: 30 },
    { name: "Jane", age: 25 },
    { name: "Bob", age: 35 }
  ];

  return (
    <div style={{ height: "100%", width: "100%" }}>
      <IgrGrid
        data={data}
        autoGenerate={false}>
        <IgrColumn
          field="name"
          header="Name"
          dataType="string">
        </IgrColumn>
        <IgrColumn
          field="age"
          header="Age"
          dataType="number">
        </IgrColumn>
      </IgrGrid>
    </div>
  );
}
```

### Ejecutar la aplicación

Por último, podemos ejecutar nuestra nueva aplicación:

```cmd
npm run dev
```

Después de ejecutar este comando, el proyecto se compilará y se servirá localmente en su equipo. Se abrirá automáticamente en su navegador predeterminado y podrá usar los componentes {ProductName} en su proyecto. El resultado final debería mostrar una cuadrícula de datos con datos de ejemplo:

## Instalar los polyfills

Ejecute este comando para instalar los polyfills de los web components:

```bash
npm install @webcomponents/custom-elements
```

A continuación, importe los polyfills de los web components en index.js:

```ts
import '@webcomponents/custom-elements/custom-elements.min';
import '@webcomponents/custom-elements/src/native-shim.js';
```

## Instalar Ignite UI for Web Components
Para usar los Web Components de Ignite UI en su aplicación, debe instalar el paquete `igniteui-webcomponents`:

```cmd
npm install igniteui-webcomponents
```

A continuación, debe importar los componentes que quiera usar en su archivo `\index.ts`. Puede importar uno o varios componentes con la función `\defineComponents`, así:

```ts
import { defineComponents, IgcAvatarComponent, IgcBadgeComponent } from 'igniteui-webcomponents';

defineComponents(IgcAvatarComponent, IgcBadgeComponent);
```

También puede importar todos los componentes con la función `\defineAllComponents`:

```ts
import { defineAllComponents } from 'igniteui-webcomponents';

defineAllComponents();
```

<DocsAside type="info">
Importar todos los componentes aumentará el tamaño del paquete de su aplicación. Por eso le recomendamos importar solo los componentes que realmente usa.
</DocsAside>

El último paso es importar el CSS necesario para nuestros componentes, para que tengan el estilo correcto:

```ts
import 'igniteui-webcomponents/themes/light/bootstrap.css';
```

Una vez importados los componentes, puede usarlos en su HTML:

```html
<igc-avatar initials="AZ"></igc-avatar>
<igc-badge></igc-badge>
```

## Instalar los paquetes de gráficos y mapas

### Paso 1: crear el proyecto de Web Component

1 - Abra una línea de comandos y cree un directorio llamado **wc-html**

```cmd
mkdir wc-html
```

2 - Cambie la ruta de la línea de comandos al directorio recién creado

```cmd
cd wc-html
```

3 - Inicialice **npm** en el directorio

```cmd
npm init -y
```

4 - Instale el empaquetador **webpack** y la **webpack cli** como dependencia de desarrollo

```cmd
npm install webpack webpack-cli --save-dev
```

<DocsAside type="info">
Webpack es un empaquetador de módulos. Su función principal es empaquetar archivos JavaScript para usarlos en un navegador, aunque también puede transformar, empaquetar o agrupar casi cualquier recurso o activo.
</DocsAside>

5 - Abra el proyecto en **VS Code**

```cmd
code .
```

6 - Cree un archivo nuevo llamado **index.html** con este código:

```html
<html>
    <head>
        <title>Getting Started with Ignite UI for Web Components</title>
    </head>
    <body>

    </body>
</html>
```

7 - Cree una carpeta nueva llamada **src** y, dentro de ella, un archivo nuevo llamado **index.js**. La estructura del proyecto debe ser como la siguiente:

<Image src={wcProject} alt="wc-project" />

8 - Actualice el archivo **package.json** para incluir un script de compilación que use **webpack**

```json
  "scripts": {
    "build": "webpack ./src/index.js -o ./dist/ --output-filename index.bundle.js"
  },
```

<DocsAside type="info">
Este script usará webpack para empaquetar el archivo **index.js** en otro archivo llamado **index.bundle.js** y lo colocará en una carpeta llamada **dist**.

Si se produce un problema de **JavaScript heap out of memory** durante la compilación, puede aumentar el tamaño del heap usando este comando de compilación en su lugar:
</DocsAside>

```json
"scripts": {
    "build": "node --max_old_space_size=8192 node_modules/webpack/bin/webpack src/index.js -o dist/index.bundle.js"
},
```

### Paso 2: instalar los polyfills

1 - Abra una terminal en **VS Code** (menú **Ver** -> **Terminal**, o pulse las teclas <kbd>CTRL</kbd> + <kbd>`</kbd>)

2 - Escriba este comando para instalar los polyfills de los web components:

```cmd
npm install @webcomponents/custom-elements
```

3 - Importe los polyfills de los web components en **index.js**

```ts
import '@webcomponents/custom-elements/custom-elements.min';
import '@webcomponents/custom-elements/src/native-shim.js';
```

### Paso 3: instalar Ignite UI for Web Components y lit-html

1 - Instale el Web Component de Ignite UI for Web Components con **npm**. En este ejemplo, instalaremos el Web Component de mapa:

```cmd
npm install --save {PackageCore}
npm install --save {PackageCharts}
npm install --save {PackageMaps}
npm install lit-html
```

2 - Importe los módulos del mapa geográfico y **ModuleManager** en el archivo **index.js**:

```ts
import { IgcGeographicMapModule } from 'igniteui-webcomponents-maps';
import { IgcDataChartInteractivityModule } from 'igniteui-webcomponents-charts';
// module manager for registering the modules
import { ModuleManager } from 'igniteui-webcomponents-core';
```

3 - Registre los módulos del mapa geográfico con **ModuleManager**

```ts
ModuleManager.register(
    IgcGeographicMapModule,
    IgcDataChartInteractivityModule
);
```

4 - Añada el Web Component del mapa geográfico en el body del archivo **index.html**

```html
<body>
    <igc-geographic-map id="map" height="500px" width="100%">
    </igc-geographic-map>
</body>
```

### Paso 4: compilar y ejecutar el proyecto de Web Components

1 - Abra una terminal en **VS Code** y ejecute el script **build**

```cmd
npm run build
```

<DocsAside type="info">
Este comando ejecutará el script de compilación que creamos antes. El script de compilación generará un archivo llamado **index.bundle.js** en una carpeta llamada **dist**
</DocsAside>

2 - Añada el script **index.bundle.js** al final del elemento **body** del archivo **index.html**.

```html
<body>
    <igc-geographic-map id="map" height="500px" width="100%">
    </igc-geographic-map>

    <script src="dist/index.bundle.js"></script>
</body>
```

3 - Para ejecutar el proyecto, inicie un servidor de desarrollo local. En este ejemplo usamos Live Server. Haga clic con el botón derecho dentro del editor de **index.html** y seleccione **Open with Live Server**

{/*<Image src={wcLiveServer} alt="wc-live-server" />*/}

Live Server es una extensión de Visual Studio Code que permite iniciar un servidor de desarrollo local con la función de recarga en vivo para páginas estáticas y dinámicas. Esta extensión puede instalarse desde la pestaña Extensiones de Visual Studio Code, o descargándola desde el [Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer).

## Desarrollo asistido por IA

Ignite UI ofrece un conjunto de herramientas de IA en tres partes: **Agent Skills**, el **servidor Ignite UI CLI MCP** y el **servidor Ignite UI Theming MCP**, que fundamentan a los asistentes de programación con IA en las API de componentes, las rutas de importación y los tokens de diseño correctos. Una vez conectado, su asistente de IA puede generar el andamiaje de proyectos, añadir y modificar componentes, responder preguntas de documentación y generar código {ProductName} preciso sin salir de su editor.

Ejecute `ig ai-config` en la raíz de su proyecto para copiar los {ProductName} Agent Skills y escribir la configuración del servidor Ignite UI MCP en `.vscode/mcp.json` en un solo paso.

Para una visión general de las tres capas y las instrucciones de configuración, consulte [Desarrollo asistido por IA con Ignite UI](./ai/ai-assisted-development-overview.mdx). Para la guía completa de configuración del cliente de CLI MCP, consulte [Ignite UI CLI MCP](./ai/cli-mcp.mdx). Para un recorrido completo que usa ambos servidores MCP, consulte [Crear una aplicación de principio a fin con CLI MCP y Theming MCP](./general-how-to-mcp-e2e.mdx).

## Gráficos y diagramas
{ProductName} contiene una biblioteca de [Charts & Graphs](./charts/chart-overview.mdx) que permite visualizar cualquier tipo de datos mediante sus más de 65 tipos de series de gráficos y combinaciones, para crear gráficos y paneles espectaculares e interactivos. Diseñada para ser rápida y atractiva, pensada para funcionar en todos los navegadores modernos y con interactividad y compatibilidad táctil completas, le permite crear visualizaciones adaptables en cualquier dispositivo con rapidez.

## Medidores
{ProductName} incluye los componentes [Radial Gauge](./radial-gauge.mdx), [Linear Gauge](./linear-gauge.mdx) y [Bullet Graph](./bullet-graph.mdx), que sirven para ilustrar datos de forma sencilla e intuitiva. El [Radial Gauge](./radial-gauge.mdx) tiene diversas opciones de personalización para crear una forma y una escala predefinidas. El [Linear Gauge](./linear-gauge.mdx) ofrece una vista sencilla de un valor comparado con una escala y uno o varios rangos. Admite una escala, un conjunto de marcas de graduación y un conjunto de etiquetas. El componente [Bullet Graph](./bullet-graph.mdx) le permite crear visualizaciones de datos que sustituyen a los medidores e indicadores de los paneles por gráficos de barras sencillos.

## Mapas
El componente {ProductName} [Geographic Map](./geo-map.mdx) permite visualizar datos geográficos en su aplicación. Puede representar conjuntos de datos formados por muchas ubicaciones geográficas en forma de marcadores, líneas, polígonos o incluso mapas de bits interactivos. Permite superponer varias capas de mapa con datos geográficos, marcar ubicaciones geográficas concretas y mostrar información mediante marcadores y colores personalizados.

## Cuadrículas y entradas
{ProductName} incluye varios componentes [Grid](./grids/grids-header.mdx) que permiten enlazar y mostrar datos con poca configuración, en forma de [Grid Lite](./grid-lite/overview.mdx), un componente de cuadrícula ligero con licencia MIT; [Data Grid](./grids/data-grid.mdx), un componente de cuadrícula con muchas funciones y licencia comercial; [List](./grids/list.mdx), [Tree](./grids/tree.mdx) e incluso [Spreadsheet](./spreadsheet-overview.mdx).

## Botones, entradas, disposiciones y menús
{ProductName} incluye distintos tipos de [Buttons](./inputs/button.mdx), [Inputs](./inputs/input.mdx), [Menus](./menus/navbar.mdx) y [Layouts](./layouts/tabs.mdx) que le permiten crear aplicaciones web modernas mediante encapsulación y el concepto de componentes reutilizables, con un enfoque sin dependencias. Consulte aquí la [Storybook](https://igniteui.github.io/igniteui-webcomponents). Estos componentes se basan en el [Indigo Design System](https://www.infragistics.com/products/appbuilder/ui-toolkit), cuentan con el soporte completo de [App Builder](https://appbuilder.indigo.design/) y están respaldados por kits de interfaz listos para usar para Figma.

## Instalar Ignite UI for Blazor

Ignite UI for Blazor se distribuye mediante paquetes NuGet. Instale **IgniteUI.Blazor** desde el [feed de NuGet de Infragistics](./general-nuget-feed.mdx) o **IgniteUI.Blazor.Trial** desde [NuGet.org](https://www.nuget.org/packages/IgniteUI.Blazor.Trial).

En una Blazor Web App con el modo de renderizado WebAssembly o Auto, basta con instalarlo en el proyecto cliente, ya que el proyecto de servidor lo obtiene mediante la referencia al proyecto.

Para más información sobre la instalación de Ignite UI for Blazor con NuGet, lea el tema [Instalación de Ignite UI for Blazor](./general-installing-blazor.mdx).

## Registrar Ignite UI for Blazor

1 - Abra el archivo **Program.cs** y registre el servicio de Ignite UI for Blazor llamando a la función **builder.Services.AddIgniteUIBlazor**. En una Blazor Web App con el modo de renderizado WebAssembly o Auto, hágalo en el **Program.cs** tanto del proyecto de servidor como del proyecto cliente:

```csharp
builder.Services.AddIgniteUIBlazor();
```

2 - Añada el espacio de nombres **IgniteUI.Blazor.Controls** en el archivo **_Imports.razor** (en ambos proyectos cuando hay un proyecto cliente):

```razor
@using IgniteUI.Blazor.Controls
```

3 - Añada la hoja de estilos en el elemento **`<head>`** del archivo **Components/App.razor**:

```razor
<head>
    <link rel="stylesheet" href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" />
</head>
```

Para aplicaciones de .NET 9 o posterior, se recomienda usar la propiedad de colección **Assets**:

```razor
<head>
    <link rel="stylesheet" href="@Assets["_content/IgniteUI.Blazor/themes/light/bootstrap.css"]" />
</head>
```

4 - Añada la referencia al script antes del script de Blazor en el archivo **Components/App.razor**. Refiérase a él directamente, no a través de **Assets**:

```razor
<script src="_content/IgniteUI.Blazor/app.bundle.js"></script>
<script src="@Assets["_framework/blazor.web.js"]"></script>
```

### Módulos de componentes

Llamar a `builder.Services.AddIgniteUIBlazor()` es todo lo que necesita la mayoría de las aplicaciones: cada componente carga sus recursos de cliente la primera vez que se renderiza. Registre los módulos explícitamente para:

- tener los recursos de un componente listos cuando la aplicación se inicia, antes de que el componente se renderice por primera vez;
- usar un componente que se crea solo en el cliente, por ejemplo, mediante una plantilla JavaScript, donde ningún componente Razor solicita su módulo;
- habilitar funciones que ningún componente solicita por sí mismo, como la interactividad de los gráficos (<ApiLink raw type="DataChartInteractivityModule" />) o los paquetes `*FullModule`, todo ello en el paquete **{PackageCore}**.

Indique los módulos en `\AddIgniteUIBlazor`, que los carga cuando se inicia el entorno de ejecución de Ignite UI:

```csharp
builder.Services.AddIgniteUIBlazor(
    typeof(IgbBadgeModule),
    typeof(IgbDataChartInteractivityModule)
);
```

O registre un módulo más tarde, con el entorno de ejecución inyectado:

```razor
@inject IIgniteUIBlazor IgniteUIBlazor

@code {
    protected override void OnInitialized()
    {
        IgbBadgeModule.Register(IgniteUIBlazor);
    }
}
```

## Declarar los espacios de nombres

Cada paquete de controles tiene su propio espacio de nombres, y un archivo XAML declara los que usa. WinUI y
Uno Platform usan la forma `using:`:

```xml

<Window
    xmlns:ig="using:Infragistics.Controls"
    xmlns:igCharts="using:Infragistics.Controls.Charts"
    xmlns:igDataGrids="using:Infragistics.Controls.Grids"
    xmlns:igGauges="using:Infragistics.Controls.Gauges"
    xmlns:igMaps="using:Infragistics.Controls.Maps"
```

Solo necesita los que usa realmente un archivo. Todos los fragmentos de código de estos temas se escriben con estos
prefijos, por lo que un fragmento que muestra `igDataGrids:XamDataGrid` necesita la declaración `\igDataGrids` de arriba.
