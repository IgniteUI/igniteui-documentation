## Paquetes npm de {ProductName}: usar el feed npm privado
npm es el gestor de paquetes más popular y también el predeterminado del entorno de ejecución Node.js. Tiene una gran adopción y es una de las formas más rápidas y sencillas de gestionar los paquetes de los que depende su proyecto. Para más información sobre el funcionamiento de npm, lea la [documentación oficial de npm](https://docs.npmjs.com/).

Infragistics {ProductName} está disponible como paquetes npm, y puede añadirlos como dependencias de su proyecto en [unos pocos pasos sencillos](./general-getting-started.mdx). Este enfoque no requiere configurar npm. Si instala un paquete con licencia comercial, empezará a usar la **versión de prueba de {ProductName}** del producto.

<DocsAside type="info">
¿Qué significa empezar a usar una versión de prueba? Significa que usará una versión de nuestro producto con una **marca de agua** en parte de su vista web. No significa que vaya a usar el paquete con licencia durante un tiempo determinado antes de que caduque, por ejemplo, un mes.
</DocsAside>

El feed npm privado que proporciona Infragistics contiene las versiones con licencia de los paquetes con licencia comercial.

### Cómo configurar su entorno para usar el feed npm privado

#### Primero debe configurar el registro privado y asociarlo con el ámbito de Infragistics

Esto le permitirá usar sin problemas una combinación de paquetes del registro npm público y del registro privado de Infragistics. Se le pedirá el nombre de usuario y la contraseña que usa para iniciar sesión en su cuenta de Infragistics. También debe indicar el correo electrónico registrado en su perfil de Infragistics.

> Si su cuenta no tiene licencia (todavía usa una cuenta de prueba), el feed privado de paquetes no le será accesible; por ejemplo, devolverá un error 404 o 403. **Solo las cuentas con licencia pueden acceder al feed privado de packages.infragistics.**

### Ahora, para iniciar sesión en nuestro feed privado con npm

#### npm versión 9 o posterior
Nuestro feed privado no admite actualmente los comandos login/adduser con npm v9, por lo que le recomendamos en su lugar los pasos siguientes para añadir los campos de autenticación necesarios a la configuración:

```cmd
npm config set @infragistics:registry https://packages.infragistics.com/npm/js-licensed/

npm config set //packages.infragistics.com/npm/js-licensed/:username=YOUR_USERNAME

npm config set //packages.infragistics.com/npm/js-licensed/:email=YOUR_IG_EMAIL

npm config set //packages.infragistics.com/npm/js-licensed/:_auth=YOUR_IG_AUTH_TOKEN
```

Puede generar un [token de acceso](#uso-del-token-de-acceso) desde su perfil de Infragistics.

Este enfoque es aplicable a todas las versiones anteriores de `npm`.

#### npm hasta la versión 8
Ejecute el comando `adduser` e indique una cuenta de usuario y una contraseña:

```cmd
npm adduser --registry=https://packages.infragistics.com/npm/js-licensed/ --scope=@infragistics
```

Se le pedirá el nombre de usuario y la contraseña que usa para iniciar sesión en su cuenta de Infragistics. También debe indicar el correo electrónico registrado en su perfil de Infragistics.

> `npm` no permite usar el símbolo `"@"` dentro de su nombre de usuario, porque se considera "no seguro para la red". Como su nombre de usuario es en realidad el correo electrónico que usa para su cuenta de Infragistics, siempre contiene el símbolo `"@"`. Por eso debe salvar esta limitación sustituyendo el símbolo `"@"` por `"!!"` (dos signos de exclamación). Por ejemplo, si su nombre de usuario es `"username@example.com"`, cuando se le pida el nombre de usuario debe indicar lo siguiente: `"username!!example.com"`.

#### Una vez hecho esto, habrá iniciado sesión y podrá instalar las versiones más recientes de los paquetes de Ignite UI en su proyecto

```cmd
npm uninstall {PackageDockManager}
npm install @infragistics/{PackageDockManager}

npm uninstall {PackageDockManager}
npm install @infragistics/{PackageDockManager}
```

Tenga en cuenta que hemos definido el paquete {ProductName} con ámbito, lo que significa que no es necesario cambiar los registros si quiere instalar paquetes de nuestro feed privado y de npmjs.org al mismo tiempo.

### Cambios en el código fuente del proyecto tras actualizar el paquete con licencia

Si pasa de un paquete de prueba a uno con licencia, los nuevos paquetes tendrán ámbito bajo `@infragistics`.
Por tanto, puede hacer una de estas dos cosas:

- Hacer un reemplazo global de todos los paquetes de prueba y cambiarlos por la versión con licencia y ámbito en todos los archivos del proyecto. Por ejemplo, reemplace todas las referencias a `{PackageDockManager}` por `@infragistics/{PackageDockManager}`. El cambio debe afectar a todas las importaciones donde se usan estos paquetes.

  **O bien**

- Añada una asignación **paths** en el archivo **tsconfig.json** del proyecto.

```json
{
  /* ... */
  "compilerOptions": {
    "baseUrl": "./",
    "outDir": "./dist/out-tsc",
    /* ... */
    "paths": {
      "{PackageDockManager}": ["./node_modules/@infragistics/{PackageDockManager}"],
      "{PackageDockManager}/*": ["./node_modules/@infragistics/{PackageDockManager}/*"],
    }
  }
}
```

## Uso del token de acceso

También puede autenticarse en nuestro feed npm privado con un token de acceso, que puede obtener desde su [cuenta de usuario de infragistics.com](https://account.infragistics.com/access-tokens). La autenticación con token de acceso es la alternativa preferida cuando quiere integrar un proceso de CI en un repositorio de acceso público que usa los paquetes con licencia de {ProductName}.

La siguiente información explica cómo configurar la autenticación en nuestro registro npm privado con un token de acceso en la configuración local, en los procedimientos de compilación de Azure Pipelines y en el proceso de compilación de Travis CI:

- Genere un token en https://account.infragistics.com/access-tokens

<Image src={generateToken} alt="Nuevo token generado" class="responsive-img" style="margin-bottom:10px; -webkit-box-shadow: 4px 4px 4px 4px #ccc; -moz-box-shadow: 4px 4px 4px 4px #ccc; box-shadow: 4px 4px 4px 4px #ccc; max-width: 600px" />

> Cada token está codificado en Base64.

- Añada lo siguiente a su archivo [.npmrc](https://docs.npmjs.com/configuring-npm/npmrc.html)

```cmd
@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/
//packages.infragistics.com/npm/js-licensed/:_auth=YOUR_ACCESS_TOKEN
//packages.infragistics.com/npm/js-licensed/:username=YOUR_USERNAME
```

## Configuración de Azure Pipelines
Actualice el archivo azure-pipelines.yml con los siguientes pasos:

```cmd
steps:

- script: npm config set @infragistics:registry $(npmRegistry)
  displayName: 'Npm add registry'
- script: npm config set $(igScope):_auth=$(token)
  displayName: 'Npm config auth'
```

Añada las variables **npm registry** y **token**.

## Configuración de Travis CI
Aquí seguiremos casi el mismo enfoque. La única diferencia es que la configuración se establecerá en [before_install](https://docs.travis-ci.com/user/job-lifecycle/#the-job-lifecycle)

```cmd
before_install:
- echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- echo "//packages.infragistics.com/npm/js-licensed/:_auth=$TOKEN" >> ~/.npmrc
```

La mejor forma de definir una variable de entorno depende del tipo de información que vaya a contener. Por tanto, [tiene dos opciones](https://docs.travis-ci.com/user/environment-variables/):

- cifrarla y añadirla [a su .travis.yml](https://docs.travis-ci.com/user/environment-variables/#defining-encrypted-variables-in-travisyml)
- añadirla a la [configuración del repositorio](https://docs.travis-ci.com/user/environment-variables/#defining-variables-in-repository-settings)

### Configuración de GitHub Actions

Añada los siguientes scripts antes del paso **npm i(ci)** en la [configuración del flujo de trabajo de CI](https://help.github.com/en/actions/language-and-framework-guides/using-nodejs-with-github-actions):

```cmd
- run: echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- run: echo "//packages.infragistics.com/npm/js-licensed/:_auth=${{ secrets.NPM_TOKEN }}" >> ~/.npmrc
```

Defina los [secretos (variables de entorno cifradas)](https://help.github.com/en/actions/configuring-and-managing-workflows/creating-and-storing-encrypted-secrets) y úselos en el flujo de trabajo de acciones de GitHub para la información sensible, como el token de acceso.
