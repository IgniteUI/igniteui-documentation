# Temas en {ProductName}

## Cambio de tema en tiempo de ejecución

<DocsAside type="info">
Cambiar el tema en tiempo de ejecución también requiere sustituir la hoja de estilos global de la tabla anterior.
</DocsAside>

{ProductName} le permite cambiar los temas de los componentes en tiempo de ejecución mediante la función `ConfigureTheme` que exporta la biblioteca.

Recibe el tema como primer argumento (`bootstrap`, `material`, `fluent` o `indigo`) y una variante opcional como segundo, `light` o `dark`. Omítala para mantener la que está activa actualmente.

```ts
import { configureTheme } from "igniteui-webcomponents";

// Sets material as the theme to be used by all components
configureTheme("material");

// Sets material and switches to its dark variant
configureTheme("material", "dark");
```

<DocsAside type="info">
Esto solo indica a los componentes que cambien sus estilos internos al tema deseado; también debe cambiar el archivo de tema global a uno de los archivos enumerados anteriormente.
</DocsAside>

</PlatformBlock>

## Personalizar con Sass

Los archivos de tema anteriores son CSS prediseñado, y los temas de esta sección los personalizan sobrescribiendo variables CSS; consulte [Palettes](palettes.mdx), [Typography](typography.mdx), [Elevations](elevations.mdx) y [Configuration](configuration.mdx). Esa vía no necesita configuración de compilación y cubre la mayor parte de la personalización.

Los temas prediseñados se compilan a partir de `igniteui-theming`, la biblioteca de Sass que hay detrás de cada tema de {ProductName}, y la misma biblioteca está disponible para su aplicación. Algunas capacidades solo son accesibles desde ella, porque se ejecutan en tiempo de compilación en lugar de mediante una variable:

- Generar una paleta a partir de sus propios colores semilla, como se describe en [Palette Generation](palette-generation.mdx).
- Las funciones de contraste y de paleta de gráficos del tema [Accessibility](accessibility.mdx).

Una compilación de Sass con `igniteui-theming` produce CSS sencillo: una hoja de estilos con variables `--ig-*` que carga después del archivo de tema, de la misma forma que carga sus propias sobrescrituras de CSS. Su framework solo necesita una forma de ejecutar el compilador de Sass. Instale ambos paquetes:

```cmd
npm install igniteui-theming sass --save-dev
```

A continuación, importe la biblioteca en un archivo `.scss`:

```scss
@use 'igniteui-theming' as *;

// Required for $material-type-scale, $indigo-type-scale, and similar preset variables
@use 'igniteui-theming/sass/typography/presets' as *;

// Required for $material-elevations and $indigo-elevations
@use 'igniteui-theming/sass/elevations/presets' as *;

:root {
  @include palette(palette($primary: #0099ff, $secondary: #df1b74, $surface: #ffffff));
}
```

### Compilar la hoja de estilos

<PlatformBlock for="React">

Vite y Next.js compilan las importaciones de `.scss` una vez instalado el paquete `sass`. Importe la hoja de estilos después del archivo de tema:

```tsx
import 'igniteui-react-grids/grids/themes/light/bootstrap.css';
import './theme.scss';
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

Vite compila las importaciones de `.scss` una vez instalado el paquete `sass`, y webpack hace lo mismo a través de `sass-loader`. Importe la hoja de estilos después del archivo de tema:

```ts
import 'igniteui-webcomponents/themes/light/bootstrap.css';
import './theme.scss';
```

</PlatformBlock>

<PlatformBlock for="Blazor">

Un proyecto de Blazor no tiene empaquetador de JavaScript, así que compile la hoja de estilos con la línea de comandos de Sass, por ejemplo desde un script de npm o un paso previo a la compilación, y escriba el resultado en `wwwroot`:

```cmd
npx sass --load-path=node_modules Styles/theme.scss wwwroot/css/theme.css
```

Enlace el archivo compilado después del archivo de tema en su página host:

```html
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
<link href="css/theme.css" rel="stylesheet" />
```

</PlatformBlock>

<PlatformBlock for="React, WebComponents">

Cualquier otra herramienta de compilación funciona de la misma forma, y también la línea de comandos de Sass. Cuando nada más compila Sass, ejecútela como un paso aparte y cargue la salida como cualquier archivo CSS:

```cmd
npx sass --load-path=node_modules src/theme.scss public/theme.css
```

</PlatformBlock>

<DocsAside type="note">
Si `@use 'igniteui-theming' as *;` no se resuelve, a su compilador de Sass le falta `node_modules` en sus rutas de carga. Pase `--load-path=node_modules` a la línea de comandos de Sass, establezca `css.preprocessorOptions.scss.loadPaths` en Vite, o establezca `sassOptions.loadPaths` en Next.js.
</DocsAside>

### Sin una cadena de herramientas de Sass

La salida no tiene que recompilarse junto con su aplicación. Compile la hoja de estilos una vez y guarde el CSS en el control de versiones, y vuelva a compilarla solo cuando cambie el Sass. El [servidor MCP de Theming](../ai/theming-mcp.mdx) también puede generar paletas y temas de componente como CSS listo para usar, sin un compilador de Sass local.
