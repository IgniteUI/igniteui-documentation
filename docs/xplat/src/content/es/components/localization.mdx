# Localización (i18n) de {Platform}

La nueva localización introduce más funciones con menos requisitos tanto para las cadenas de localización como para el formato de todos los locales disponibles. El formato se basa en los estándares introducidos por la API de `Intl`.

Actualmente, {ProductName} incluye cadenas de recursos para los siguientes idiomas: `Bulgarian`, `Czech`, `Danish`, `Dutch`, `English`, `French`, `German`, `Hungarian`, `Italian`, `Japanese`, `Korean`, `Norwegian`, `Polish`, `Portuguese`, `Romanian`, `Spanish`, `Swedish`, `Turkish`, `Traditional Chinese (zh-Hant)` y `Simplified Chinese (zh-Hans)`. Están disponibles a través del paquete `igniteui-i18n-resources`, excepto el inglés, que viene como localización predeterminada.

## Configuración regional

El término **locale** se refiere a las cadenas generales que definen los distintos idiomas y regiones. Se basan en la definición de etiquetas [BCP 47](https://developer.mozilla.org/en-US/docs/Glossary/BCP_47_language_tag). La mayoría de las básicas se describen en el [IANA Language Subtag Registry](https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry). Para consultar una lista de idiomas, consulte el estándar de idiomas [ISO 639](https://www.loc.gov/standards/iso639-2/).

Afecta tanto al formato de las fechas y los números como a las cadenas de recursos localizadas que usan los componentes de {ProductName}. El locale predeterminado de {ProductName} es `en-US`.

El locale puede establecerse de varias maneras, de forma global o por componente.

### API global

Todos los tipos y las API pueden importarse desde cualquiera de los dos paquetes. Afecta tanto al formato como a las cadenas de recursos registradas que usan todos los componentes. {ProductName} admite todo el conjunto de locales que admite `Intl`. Si el locale proporcionado no es válido o no está admitido, se usa el locale predeterminado `en-US` hasta que se establezca un locale válido.

En general, los recursos deben registrarse bajo los idiomas, las regiones y los scripts de las etiquetas previstas, para que los componentes se localicen correctamente. Para más información, consulte la sección [Regions and Scripts](#regiones-y-escrituras).

### Atributo `lang`

Este enfoque permite establecer la localización mediante el atributo global `lang` de la etiqueta `HTML`. Este atributo se observa y, si cambia, todos los componentes renderizados actualizan sus cadenas de recursos al idioma establecido actualmente. Se aplican todas las reglas sobre la etiqueta usada descritas anteriormente.

<DocsAside type="info">
Esto funciona solo a nivel raíz y no funcionará para los elementos internos de la página.
</DocsAside>

### Por componente

Cada componente también tiene su propia propiedad `locale`. Cuando se especifica, el componente no se ve afectado por el locale global.

## Cadenas de recursos localizadas

Todos los componentes de {ProductName} se renderizan en inglés de forma predeterminada y pueden renderizarse en cualquiera de los idiomas enumerados. Hay tres formas de lograrlo globalmente, y una forma por componente. Para cualquier idioma que no esté disponible actualmente, puede proporcionarse una traducción personalizada para cada cadena de recursos disponible a través de la API.

Las traducciones de las cadenas de los componentes se guardan en cadenas de recursos y deben registrarse en el sistema de localización antes de que los componentes puedan usarlas.


<PlatformBlock for="WebComponents, React">



Para ello, primero debe instalar el paquete [`igniteui-i18n-resources`](https://www.npmjs.com/package/igniteui-i18n-resources), que contiene las cadenas de recursos localizadas de todos los idiomas:

```
npm install igniteui-i18n-resources --save-dev
```

Después, registre cada idioma que quiera poner a disposición. Por ejemplo, alemán y japonés:

```ts
import { ResourceStringsDE, ResourceStringsJA } from 'igniteui-i18n-resources';

registerI18n(ResourceStringsDE, 'de');
registerI18n(ResourceStringsJA, 'ja');
```


</PlatformBlock>



<PlatformBlock for="Blazor">



Para ello, primero instale el paquete NuGet [`IgniteUI.Blazor.I18n.Resources`], que contiene las cadenas de recursos localizadas de todos los idiomas:

```
nuget install IgnieteUI.Blazor.I18n.Resources
```

```razor
I18nManager.RegisterI18nAsync(new IgbResourceStringsBG(), "bg");
```


</PlatformBlock>


También debe especificar el locale al que se aplicarán las cadenas de recursos. Si se proporciona una etiqueta no válida, los recursos se establecen para el locale predeterminado `en-US`.

### Regiones y escrituras

Se tiene en cuenta la parte `language + region` o `language + script` del locale usado para registrar los recursos, ya que son las combinaciones más habituales. La región y el script se separan con `-` y normalmente se definen en la segunda o tercera posición, por ejemplo, `en-US`, `en-GB` o `en-Latn`.

Si no se especifican ni la región ni el script, los recursos registrados se aplican a todos los locales que usan ese idioma base (por ejemplo, `en`). Sin embargo, si también se definen recursos para regiones o scripts concretos, solo los locales sin recursos propios recurren a los recursos del idioma base.

Al registrar recursos, el script tiene prioridad sobre la región. Se recomienda usar la región o el script, sin mezclar ambos a la vez. Así resulta más fácil gestionar e identificar qué recursos están disponibles para un locale determinado.

Si se usan región y script a la vez, tome como ejemplo el idioma `en` con la región `GB` y el script `Latn`. Si hay recursos definidos tanto para `en-GB` como para `en-Latn`, y el locale se establece después en `en-Latn-GB` (especificando región y script), los recursos del script tienen prioridad. Si no hay recursos del script, se usan los de la región. Si no hay recursos registrados ni de región ni de script, se usan los recursos predeterminados `en`, si están disponibles.

## Personalizar un componente

Si quiere que un componente concreto de su aplicación use los recursos ya registrados globalmente, pero con una localización distinta.

### Configuración regional

Si quiere establecer para un componente un locale distinto del global, puede hacerlo estableciendo la propiedad `locale`. Esto afecta al idioma de las cadenas de recursos usadas y también al formato, ya que ambos van unidos.

Con este enfoque, ya debería tener registradas globalmente las cadenas de recursos disponibles:

```ts
import { ResourceStringsJA } from 'igniteui-i18n-resources';

registerI18n(ResourceStringsJA, 'ja');
```

Al establecer la propiedad `locale` del componente, se sustituirá la configuración regional global que se esté usando:

<PlatformBlock for="WebComponents">
```html
<igc-grid locale="ja">
    <igc-column field="ProductName" header="Product Name" groupable="true"></igc-column>
    <igc-column field="QuantityPerUnit" header="Quantity Per Unit" groupable="true"></igc-column>
</igc-grid>
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
<IgrGrid data={data} locale="ja">
    <IgrColumn field="ProductName" header="Product Name" groupable={true}></IgrColumn>
    <IgrColumn field="QuantityPerUnit" header="Quantity Per Unit" groupable={true}></IgrColumn>
</IgrGrid>
```
</PlatformBlock>

<PlatformBlock for="Blazor">
```razor
<IgbGrid Data="@data" Locale="ja">
    <IgbColumn Field="ProductName" Header="Product Name" Groupable="true"></IgbColumn>
    <IgbColumn Field="QuantityPerUnit" Header="Quantity Per Unit" Groupable="true"></IgbColumn>
</IgbGrid>
```
</PlatformBlock>

#### Solo el idioma

Si quiere cambiar solo el idioma del componente, sin cambiar la configuración regional, incluso puede establecer las cadenas de recursos de cada componente mediante la propiedad `resourceStrings`, que sustituirá las usadas globalmente:

<PlatformBlock for="WebComponents">
```html
<igc-grid>
    <igc-column field="ProductName" header="Product Name" groupable="true"></igc-column>
    <igc-column field="QuantityPerUnit" header="Quantity Per Unit" groupable="true"></igc-column>
</igc-grid>
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
<IgrGrid data={data} resourceStrings={resourcesDE}>
    <IgrColumn field="ProductName" header="Product Name" groupable={true}></IgrColumn>
    <IgrColumn field="QuantityPerUnit" header="Quantity Per Unit" groupable={true}></IgrColumn>
</IgrGrid>
```
</PlatformBlock>

Debe asegurarse de usar el tipo de cadena de recursos correcto para el componente con el que quiera sustituirla. Cada componente tiene su propio conjunto de cadenas de recursos. En este caso, para la cuadrícula en alemán:

```ts
import { GridResourceStringsDE } from 'igniteui-i18n-resources';

// Inside App Component:
public resourcesDE = GridResourceStringsDE;
```

</PlatformBlock>
