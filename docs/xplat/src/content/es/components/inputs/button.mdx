# Componente Button

El componente Button de {Platform} le permite habilitar elementos pulsables que activan acciones en su aplicación {Platform}. Tiene control total sobre las variantes, el estilo y los tamaños de los botones. El componente Button también le permite gestionar los clics, alternar el botón y deshabilitarlo cuando sea necesario.

El Button renderiza su contenido dentro de la parte CSS `base`. Use el slot predeterminado para la etiqueta, y los slots `prefix` y `suffix` para el contenido opcional antes y después de la etiqueta.

```text
<igc-button>
├── ::part(base)
├── prefix slot
├── default slot content
└── suffix slot
</igc-button>
```

## Uso

Use el Button de {Platform} para activar una acción, enviar datos de un formulario o navegar a otra página. Elija el tipo y la variante de botón adecuados para la acción y, si es necesario, añada contenido opcional como iconos.

El contenido del Button se coloca en su slot predeterminado. Añada la etiqueta de la acción como contenido del botón para que la finalidad de la acción sea clara para todos los usuarios.

<PlatformBlock for="Angular">

```html
<button igxButton>Save changes</button>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrButton>Save changes</IgrButton>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-button>Save changes</igc-button>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbButton>Save changes</IgbButton>
```

</PlatformBlock>

Con los slots `prefix` y `suffix` del componente <ApiLink pkg="core" type="Button" />, podemos añadir contenido distinto antes y después del contenido principal del botón.

Recomendamos usar un elemento `<span>` cuando se añada texto simple, símbolos o emojis, y un componente <ApiLink pkg="core" type="Icon" /> cuando se añadan iconos a los slots `prefix` y `suffix`.

<PlatformBlock for="Angular">

```html
<button igxButton="contained">
    <span igxButtonIcon="prefix">download</span>
    Download
    <span igxButtonIcon="suffix">arrow_forward</span>
</button>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrButton type="button" variant="contained">
    <span slot="prefix">Download</span>
    <IgrIcon slot="suffix" name="download"></IgrIcon>
</IgrButton>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-button type="button" variant="contained">
    <span slot="prefix">Download</span>
    <igc-icon slot="suffix" name="download"></igc-icon>
</igc-button>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbButton Variant="@ButtonVariant.Contained">
    <span slot="prefix">Download</span>
    <IgbIcon slot="suffix" IconName="download"></IgbIcon>
</IgbButton>
```

</PlatformBlock>

### Tipo

El componente de botón cambiará su estructura interna de un elemento [`<button>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/button) a un elemento de tipo [`<a>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/a) cuando se establezca el atributo <ApiLink pkg="core" type="Button" member="href" label="Href" />. En ese caso, el botón puede considerarse un enlace normal. Al establecer el atributo <ApiLink pkg="core" type="Button" member="href" label="Href" /> también podrá establecer los atributos <ApiLink pkg="core" type="Button" member="rel" label="Rel" />, <ApiLink pkg="core" type="Button" member="target" label="Target" /> y <ApiLink pkg="core" type="Button" member="download" label="Download" />.
Cuando el componente de botón usa internamente un elemento [`<button>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/button) real, podemos especificar su <ApiLink pkg="core" type="Button" member="type" label="DisplayType" /> estableciendo la propiedad en cualquiera de los siguientes valores:

- `Submit`: cuando queremos enviar los datos del formulario
- `reset`: cuando queremos restablecer los datos del formulario a sus valores iniciales
- `button`: cuando queremos añadir un botón con funcionalidad personalizada en cualquier parte de una página web

### Variantes

Se admiten cinco tipos de botones: botón `contained` para acciones principales destacadas, botón `outlined` para acciones secundarias, botón `flat` para acciones discretas, botón `floating action` (Fab) para acciones principales destacadas, y botón `icon` para acciones representadas por un icono. Los botones de icono también pueden usar cualquiera de las otras cuatro variantes.

### Qué hacer y qué no

**Cuándo usarlo:** use Button para acciones que cambian el estado, envían datos o activan un comando de la aplicación.

**Cuándo no usarlo:** use [Icon Button](./icon-button.mdx) cuando la acción se represente solo con un icono y no necesite una etiqueta de texto.

## Estilos

Personalice el Button con la configuración del tema, las variables CSS o las partes CSS para que coincida con el lenguaje visual de su aplicación.

### Variables CSS

Use las variables CSS generadas en el elemento Button para sobrescribir los valores del tema en una instancia concreta. Las funciones de tema específicas de cada variante derivan los valores de los estados de interacción relacionados a partir de los parámetros primarios del tema.

### Partes de estilo

## Accesibilidad

El Button de {Platform} es un control interactivo para acciones y, cuando se establece `href`, para la navegación.
Use el comportamiento nativo del botón para los comandos y conserve el comportamiento de enlace para la navegación.

### Interacción por teclado

El Button usa el comportamiento de teclado de su control nativo renderizado. Un Button deshabilitado no es
interactivo, y un Button con `href` se renderiza como un enlace en lugar de como un botón de comando.

| Clave | Acción |
| -- | -- |
| Tab / Shift+Tab | Mueve el foco hacia el Button o lo aleja de él cuando puede enfocarse con el teclado. |
| Enter / Space | Activa un Button de comando enfocado. Enter activa un Button usado como enlace. |

### Lectores de pantalla / ARIA

El Button renderiza un `button` nativo para las acciones de comando y un elemento `a` cuando se establece `href`.
El elemento nativo proporciona la función y la semántica de teclado adecuadas.

<PlatformBlock for="WebComponents, React, Blazor">

- El contenido visible del Button se usa como su nombre accesible cuando contiene texto significativo.
- Proporcione un `aria-label` u otro mecanismo de nombrado accesible para un Button solo con icono.
- Un Button deshabilitado expone su estado deshabilitado a través del control nativo renderizado.
- Los controladores de eventos de clic del Button realizan acciones de la aplicación; no sustituyen el
    nombre accesible, el rol ni el estado del Button.

</PlatformBlock>

<PlatformBlock for="Angular">

- El Button usa el elemento nativo `button` o `a`, de modo que la tecnología de asistencia recibe
    el rol nativo correspondiente y la semántica de teclado.
- Proporcione un `aria-label` u otro mecanismo de nombrado accesible para un Button solo con icono.
- Un Button deshabilitado no es interactivo con el teclado.
- Los controladores de eventos de clic realizan acciones de la aplicación; añada un nombre accesible y un estado por separado
    cuando la acción no se transmita mediante el contenido visible o los atributos nativos.

</PlatformBlock>

### Cumplimiento de accesibilidad

Este tema no declara la conformidad a nivel de producto con WCAG, la Sección 508 ni EN 301 549. Verifique el Button renderizado y la aplicación que lo rodea frente a los requisitos de accesibilidad que se apliquen al proyecto de destino.

| Criterio | Cómo el componente cumple el requisito |
| -- | -- |
| [2.1.1 Teclado](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | El botón de comando nativo admite la activación por teclado, y un Button con `href` usa la activación nativa de enlaces. |
| [4.1.2 Nombre, función, valor](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | El elemento nativo renderizado aporta la semántica de rol y de estado. El contenido visible del Button aporta el nombre accesible cuando es significativo. |
| [2.4.4 Propósito del enlace](https://www.w3.org/WAI/WCAG21/Understanding/link-purpose-in-context) | Cuando se establece `href`, el Button se convierte en un enlace de navegación; proporcione un nombre que identifique su destino o su propósito. |

Sus responsabilidades:

- Dé a cada Button un nombre accesible significativo, especialmente a los Button que solo tienen icono.
- Use un Button de comando para las acciones y `href` para la navegación; no emule uno con el otro.
- No se base solo en el color, en el estilo al pasar el cursor o en el estilo de foco para comunicar la acción o el estado.
- Conserve un contraste suficiente y un indicador de foco visible al personalizar el tema del Button.

## Solución de problemas

Use esta sección para revisar los límites y las decisiones habituales antes de tratar el Button como un comando, un enlace de navegación o un control de formulario.

### ¿Por qué el Button se comporta como un enlace?

Cuando se establece `href`, el Button se usa para la navegación en lugar de para una acción de comando. Quite `href` cuando el control deba activar la lógica de la aplicación en lugar de navegar a una URL.

### ¿Por qué el Button no puede enfocarse con el teclado?

Compruebe si el Button está deshabilitado o si la aplicación que lo rodea cambia su comportamiento de foco. Use un Button enfocable para las acciones que deban estar disponibles mediante la navegación por teclado.

### Limitaciones conocidas

El Button tiene los siguientes límites independientes de la plataforma:

- Use una etiqueta de texto u otro mecanismo de nombrado accesible para cada acción; un Button solo con icono y sin etiqueta no comunica su propósito por sí mismo.
- Establecer `href` convierte el Button de un control de acción en un control de navegación. Use [Icon Button](./icon-button.mdx) para las acciones solo con icono y verifique su nombre accesible por separado.
- El aspecto visual del Button no determina si la acción de la aplicación que lo rodea está disponible o es válida; la lógica de la aplicación debe proporcionar ese estado y su retroalimentación.
