# Query Builder de {Platform} - Descripción general

El Query Builder de {ProductName} ofrece una interfaz rica que permite a los desarrolladores crear consultas complejas de filtrado de datos para un conjunto de datos determinado. Con este componente, puede construir un árbol de expresiones y especificar condiciones AND/OR entre expresiones, con editores y listas de condiciones determinados por el tipo de datos de cada campo. El árbol de expresiones puede transformarse fácilmente en una consulta con un formato que admita el backend.

## Uso de Query Builder de {Platform}

Si no hay ningún árbol de expresiones establecido inicialmente, empiece eligiendo una entidad y los campos de esta que debe devolver la consulta. Después pueden añadirse condiciones o subgrupos.

Para añadir una condición, seleccione un campo, un operando según el tipo de datos del campo y un valor si el operando no es unario. Los operandos `In` y `Not In` le permitirán crear una consulta interna con condiciones para una entidad distinta, en lugar de proporcionar simplemente un valor. Una vez confirmada la condición, aparece un chip con la información de la condición. Al hacer clic o pasar el cursor sobre el chip, tiene las opciones de modificarlo o de añadir otra condición o grupo justo después.

Al hacer clic en el botón (AND u OR) colocado encima de cada grupo, se abre un menú con opciones para cambiar el tipo de grupo o desagrupar las condiciones que contiene.

Como cada condición está relacionada con un campo concreto de una entidad determinada, cambiar la entidad restablecerá todas las condiciones y grupos preestablecidos.

Puede empezar a usar el componente estableciendo la propiedad <ApiLink type="QueryBuilder" member="entities" label="Entities" /> con una matriz que describa el nombre de la entidad y una matriz de sus campos, donde cada campo se define por su nombre y su tipo de datos. Una vez seleccionado un campo, se asignan automáticamente los operandos correspondientes según el tipo de datos.
Query Builder tiene la propiedad <ApiLink type="QueryBuilder" member="expressionTree" label="ExpressionTree" />. Puede usarla para establecer un estado inicial del control y acceder a la lógica de filtrado especificada por el usuario.

  this.ordersFields = [
    { field: 'orderId', dataType: 'number' },
    { field: 'customerId', dataType: 'string' },
    { field: 'orderDate', dataType: 'date' }
  ];

  this.entities = [
    { name: 'Orders', fields: this.ordersFields }
  ];

  const tree = new IgcFilteringExpressionsTree();
  tree.operator = FilteringLogic.And;
  tree.entity = 'Orders';

  this.expressionTree = tree;
  this.queryBuilder.entities = this.entities;
  this.queryBuilder.expressionTree = this.expressionTree;
}

## Arrastrar expresiones

Los chips de condición pueden recolocarse fácilmente con arrastrar y soltar con el ratón o con la reordenación mediante el teclado. Con ellos, los usuarios pueden ajustar dinámicamente la lógica de sus consultas.

- Arrastrar un chip no modifica su condición ni su contenido, solo su posición.
- Los chips también pueden arrastrarse entre grupos y subgrupos. Por ejemplo, agrupar y desagrupar expresiones se logra con la función de arrastre de expresiones.
Para agrupar condiciones ya existentes, primero hay que añadir un grupo nuevo con el botón de grupo "add". Después, arrastrando, se pueden mover las expresiones necesarias a ese grupo. Para desagrupar, puede arrastrar todas las condiciones fuera de su grupo actual; cuando se mueva la última condición fuera, el grupo se eliminará.

<DocsAside type="info">
Los chips de un árbol de consulta no pueden arrastrarse a otro, por ejemplo, de la consulta principal a una interna y viceversa.
</DocsAside>

<Image src={queryBuilderDragAndDrop} alt="Ejemplo animado de arrastrar y soltar del Query Builder con el ratón" class="responsive-img" />

## Interacción por teclado

**Combinaciones de teclas**

- <kbd>Tab</kbd> / <kbd>Shift + Tab</kbd>: navega al chip, indicador de arrastre, botón de eliminar o botón de expresión 'add' siguiente o anterior.
- <kbd>Arrow Down</kbd> / <kbd>Arrow Up</kbd>: cuando el indicador de arrastre del chip tiene el foco, el chip puede moverse hacia abajo o hacia arriba.
- <kbd>Space</kbd> / <kbd>Enter</kbd>: la expresión enfocada entra en modo de edición. Si el chip se ha movido, esto confirma su nueva posición.
- <kbd>Esc</kbd>: se cancela la reordenación del chip y vuelve a su posición original.

<DocsAside type="info">
La reordenación con el teclado ofrece la misma funcionalidad que arrastrar y soltar con el ratón. Una vez movido un chip, el usuario debe confirmar la nueva posición o cancelar la reordenación.
</DocsAside>

<DocsAside type="info">
Al usar `SearchValueTemplate`, debe proporcionar plantillas para todos los tipos de campo de su entidad, o el query builder no funcionará correctamente. Es obligatorio implementar una plantilla predeterminada o de respaldo que gestione los campos o las condiciones que no cubren las plantillas personalizadas específicas. </DocsAside>
las condiciones de esos campos.


<PlatformBlock for="WebComponents">


```ts
constructor() {
  this.queryBuilder = document.getElementById('queryBuilder') as IgcQueryBuilderComponent;
  this.queryBuilder.searchValueTemplate = (ctx) => this.buildSearchValueTemplate(ctx);
}

private buildSearchValueTemplate(ctx: IgcQueryBuilderSearchValueContext) {
  const field = ctx.selectedField?.field;
  const condition = ctx.selectedCondition;
  const matchesEqualityCondition = condition === 'equals' || condition === 'doesNotEqual';

  if (!ctx.implicit) {
      ctx.implicit = { value: null };
  }

  // Custom template for Region field
  if (field === 'Region' && matchesEqualityCondition) {
      return this.buildRegionSelect(ctx);
  }

  // Custom template for OrderStatus field
  if (field === 'OrderStatus' && matchesEqualityCondition) {
      return this.buildStatusRadios(ctx);
  }

  // Custom template for date fields
  if (ctx.selectedField?.dataType === 'date') {
      return this.buildDatePicker(ctx);
  }

  // Custom template for time fields
  if (ctx.selectedField?.dataType === 'time') {
      return this.buildTimeInput(ctx);
  }

  // Default template for all other fields (string, number, boolean, etc.)
  // This ensures all fields have a functioning editor
  return this.buildDefaultInput(ctx);
}
```

private buildRegionSelect(ctx: IgcQueryBuilderSearchValueContext) {
  const currentValue = ctx?.implicit?.value?.value ?? '';

  return html`
    <igc-select
      placeholder="Region"
      .value=${currentValue}
      @igcChange=${(event: CustomEvent<{ value: string }>) => {
        const region = this.regionOptions.find(o => o.value === event.detail.value);
        ctx.implicit.value = region ?? null;
      }}>
      ${this.regionOptions.map(option => html`
        <igc-select-item value=${option.value}>${option.text}</igc-select-item>
      `)}
    </igc-select>
  `;
}

// Field definitions for string, number, and boolean types
{ field: 'ShipCountry', dataType: 'string' }
{ field: 'OrderID', dataType: 'number' }
{ field: 'IsRushOrder', dataType: 'boolean' }

// Template that handles all these types
private buildDefaultInput(ctx: IgcQueryBuilderSearchValueContext) {
  const dataType = ctx.selectedField?.dataType;
  const isNumber = dataType === 'number';
  const isBoolean = dataType === 'boolean';
  
  const placeholder = ctx.selectedCondition === 'inQuery' || ctx.selectedCondition === 'notInQuery'
    ? 'Sub-query results'
    : 'Value';

  const inputValue = ctx.implicit?.value ?? '';
  const disabledConditions = ['empty', 'notEmpty', 'null', 'notNull', 'inQuery', 'notInQuery'];
  const isDisabled = isBoolean || !ctx.selectedField || disabledConditions.includes(ctx.selectedCondition ?? '');

  return html`
    <igc-input 
      .value=${inputValue}
      ?disabled=${isDisabled}
      placeholder=${placeholder}
      type=${isNumber ? 'number' : 'text'}
      @input=${(event: Event) => {
        const target = event.target as HTMLInputElement;
        ctx.implicit.value = isNumber
          ? target.value === '' ? null : Number(target.value)
          : target.value;
      }}>
    </igc-input>
  `;
}

    const placeholder = ctx.selectedCondition === 'inQuery' || ctx.selectedCondition === 'notInQuery'
        ? 'Sub-query results'
        : 'Value';

    const currentImplicitValue = ctx && ctx.implicit ? ctx.implicit.value : null;
    const currentValue = typeof currentImplicitValue === 'object' && currentImplicitValue && 'text' in currentImplicitValue
        ? equalityCondition ? currentImplicitValue.text : ''
        : currentImplicitValue;

    const inputValue = currentValue == null ? '' : currentValue;
    const disabledConditions = ['empty', 'notEmpty', 'null', 'notNull', 'inQuery', 'notInQuery'];
    const isDisabled = isBoolean || selectedField == null || disabledConditions.includes(ctx.selectedCondition ?? '');

    return html`
      <igc-input 
        .value=${inputValue}
        ?disabled=${isDisabled}
        placeholder=${placeholder}
        type=${isNumber ? 'number' : 'text'}
        @input=${(event) => {
            const target = event.target;
            ctx.implicit.value = isNumber
                ? target.value === '' ? null : Number(target.value)
                : target.value;
        }}>
      </igc-input>
    `;
}
