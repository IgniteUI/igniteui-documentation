# Componente Selector de color <Badge variant="new" />

El Selector de color de {ProductName} es un componente asociado a formularios que permite a los usuarios elegir y editar un color mediante un desplegable interactivo con un lienzo de degradado, controles deslizantes de tono y alfa, cambio de formato, un cuentagotas y muestras predefinidas.

## Demostración en vivo

La demostración del Selector de color de {Platform} muestra el ancla en modo `input`, que previsualiza el color seleccionado actualmente y abre un desplegable en el que puede editar o seleccionar otro color.

### Modo

La propiedad <ApiLink pkg="core" type="ColorPicker" member="mode" label="mode" /> controla la presentación del ancla. Su valor predeterminado, `default`, renderiza un botón desencadenante que previsualiza el color actual; `input` renderiza un campo de texto editable con un prefijo de muestra de color. Ambas anclas abren el mismo desplegable del selector.

### Formato

### Validación

Marque el control como <ApiLink pkg="core" type="ColorPicker" member="required" label="required" /> para que falle la validación del formulario cuando no se haya seleccionado ningún color. El componente admite la API estándar asociada a formularios: <ApiLink pkg="core" type="ColorPicker" member="checkValidity" label="checkValidity" />, <ApiLink pkg="core" type="ColorPicker" member="reportValidity" label="reportValidity" /> y <ApiLink pkg="core" type="ColorPicker" member="setCustomValidity" label="setCustomValidity" />.

Muestre mensajes de ayuda y de validación debajo del ancla mediante estos slots:

- `helper-text`: muestra una sugerencia o un mensaje instructivo debajo del ancla.
- `value-missing`: renderiza contenido personalizado cuando falla la validación del campo obligatorio.
- `invalid`: renderiza contenido personalizado cuando el componente está en estado no válido.
- `custom-error`: muestra contenido cuando se establece un mensaje de validación personalizado mediante <ApiLink pkg="core" type="ColorPicker" member="setCustomValidity" label="setCustomValidity()" />.

### Qué hacer y qué no

**Cuándo usarlo:** use el Selector de color cuando los usuarios necesiten introducir o editar un color arbitrario mediante un editor visual, y el valor deba formar parte del envío y de la validación del formulario. Proporcione siempre una etiqueta clara, y prefiera el modo `input` cuando el selector esté junto a otros campos del formulario.

**Cuándo no usarlo:** cuando los usuarios solo elijan entre un conjunto pequeño y fijo de colores, muestre ese conjunto como botones normales o como un select.

## Uso del Selector de color en formularios de Angular

Para usar el web component Selector de color en un formulario de Angular y enlazarlo con `formControlName` o `ngModel`, Angular requiere una implementación de su interfaz `ControlValueAccessor`. {ProductName} proporciona una como `IgcFormControlDirective`, que se asocia a los web components admitidos mediante su selector de elemento. Desde la versión 22.2.0, admite `igc-color-picker` además de `igc-rating`.

Importe `IgcFormControlDirective` junto con `ReactiveFormsModule`, o `FormsModule` si enlaza con `ngModel`:

```ts
import { ReactiveFormsModule } from '@angular/forms';
import { IgcFormControlDirective } from 'igniteui-angular/directives';
// import { IgcFormControlDirective } from '@infragistics/igniteui-angular/directives'; for licensed package

@Component({
    imports: [ReactiveFormsModule, IgcFormControlDirective],
    schemas: [CUSTOM_ELEMENTS_SCHEMA]
})

export class LabelFormComponent {...}
```

Después, enlace el Selector de color a un `FormControl` con `formControlName`. El control recibe el color en el `format` activo y se actualiza cuando el foco sale del Selector de color con un color distinto:

```html
<form [formGroup]="labelForm">
  <igc-color-picker formControlName="color" label="Label color" required></igc-color-picker>
</form>
```

La directiva gestiona solo el enlace del valor. Mantenga `CUSTOM_ELEMENTS_SCHEMA` si usa el enlace de propiedades de Angular para otras propiedades del Selector de color, como `[swatches]="swatches"`.

## Accesibilidad

El Selector de color de {Platform} es un control asociado a formularios que puede manejarse con el teclado. El ancla es un botón con etiqueta (modo predeterminado) o un campo editable (modo de entrada), y el selector abierto atrapa el foco.

### Interacción por teclado

Los atajos de teclado siguientes se omiten mientras el componente está `disabled`.

| Clave | Acción |
| -- | -- |
| `Alt` + `ArrowDown` | Alterna el desplegable del selector. |
| `Alt` + `ArrowUp` | Cierra el desplegable del selector y devuelve el foco al ancla. |
| `Escape` | Cierra el desplegable del selector y devuelve el foco al ancla. |
| Teclas `Arrow` | Cuando el marcador del lienzo de degradado tiene el foco, lo mueve un paso en la dirección pulsada. |
| `ArrowUp` / `ArrowDown` | Cuando el campo alfa tiene el foco, aumenta o disminuye la opacidad un 1 %. |
| `Tab` | Mueve el foco entre los elementos interactivos dentro del selector abierto. |

### Lectores de pantalla / ARIA

- El ancla establece `aria-haspopup="dialog"` y `aria-expanded`, y hace referencia al contenedor del texto de ayuda mediante `aria-describedby`, de modo que los mensajes de ayuda y de validación se anuncian.
- El desplegable del selector tiene `role="dialog"` y el nombre accesible `Color picker`.
- El marcador del lienzo de degradado tiene `role="slider"` y anuncia ambos ejes mediante `aria-valuetext` (por ejemplo, `Saturation 50%, brightness 80%`).
- Los controles deslizantes de tono y alfa son elementos `input[type="range"]` nativos etiquetados mediante `aria-label` (`Hue`, `Alpha slider`).
- El selector de formato y la entrada del valor de color tienen etiquetas ocultas visualmente; los botones de copiar y de cuentagotas exponen texto oculto visualmente.
- Cada botón de muestra expone su color mediante `aria-label`.
- Mientras el selector está abierto, el foco queda atrapado dentro de él; el contenido del selector está `inert` cuando está cerrado y se excluye del orden de tabulación.

## Solución de problemas

La guía de resolución de problemas del Selector de color de {Platform} sigue un formato problema → causa → solución para los problemas habituales de integración y de plataforma.

### ¿Por qué mi valor de color se borró o volvió atrás?

Asignar una cadena vacía, solo con espacios o no válida a `value` borra el color en lugar de conservar el valor anterior. Una cadena no válida escrita en la entrada de color vuelve al color actual. Asigne una cadena de color CSS válida y asegúrese de que el entorno admite `OffscreenCanvas` (véase Limitaciones conocidas).

### ¿Por qué el valor emitido tiene un formato distinto del que escribí?

El valor siempre se serializa en el `format` activo, así que una cadena introducida no se devuelve byte a byte igual. Por ejemplo, al escribir `red` con `format="hex"` se obtiene `#ff0000`. Establezca `format` en la notación que espera leer de nuevo.

### ¿Por qué no se emite ningún `igcInput` mientras escribo un color?

La entrada de color confirma un color escrito cuando cambia, no en cada pulsación, y un color escrito no emite ningún `igcInput`. Escuche `igcChange`, que se dispara cuando el foco sale del componente con un color distinto.

### Limitaciones conocidas

- El botón del cuentagotas solo está habilitado en los navegadores que implementan la API [`EyeDropper`](https://developer.mozilla.org/en-US/docs/Web/API/EyeDropper). El soporte se detecta una vez, cuando se crea el componente.
- Copiar al portapapeles depende de `navigator.clipboard` y de un contexto seguro (HTTPS o `localhost`); no hace nada sin avisar cuando la API no está disponible o el permiso se deniega.
- El componente analiza cada cadena de color mediante un contexto 2D de `OffscreenCanvas`. Cuando `OffscreenCanvas` no está disponible, todos los valores se resuelven como vacíos.
- Las etiquetas accesibles integradas, como `Hue`, `Alpha slider`, `Open color picker` y `Copy color value to clipboard`, están solo en inglés y no están localizadas.
