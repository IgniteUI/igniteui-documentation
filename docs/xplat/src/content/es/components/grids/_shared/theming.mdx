# Temas de {Platform} {ComponentTitle}

Un tema de {ComponentTitle} puede construirse solo con un color de **fondo**, **primer plano** y **acento**, y el resto de colores se derivan de ellos: el encabezado, las filas, los bordes, los resúmenes, la barra de herramientas, el paginador y las ventanas emergentes de filtrado. Los colores derivados no necesitan escribirse a mano; genérelos con <PlatformBlock for="WebComponents, React">`grid-theme()`, </PlatformBlock>el [Theming MCP](../../ai/theming-mcp.mdx) o el [playground de temas](#pruébelo).

La derivación reside en el tema generado, no en el componente. De forma predeterminada, cada propiedad `--ig-grid-*` es independiente y cambia solo su propia parte de {ComponentTitle}; consulte [Ajustar finamente las propiedades individuales](#ajustar-finamente-las-propiedades-individuales).

<DocsAside type="info">
No hay un conjunto de tokens separado para cada cuadrícula. Grid, Tree Grid, Hierarchical Grid y Pivot Grid leen todos las mismas propiedades personalizadas `--ig-grid-*`, de modo que el mismo tema se aplica a cualquiera de ellos sin modificaciones.
</DocsAside>

## Crear un tema

Un tema generado es un bloque de propiedades personalizadas `--ig-grid-*` declaradas en una clase. El bloque contiene los tres tokens primarios, además de cada uno de los demás tokens escritos como una expresión CSS sobre ellos:

```css
.my-grid {
  --ig-grid-background: #08002e;
  --ig-grid-accent-color: #ff7d52;
  --ig-grid-foreground: hsla(from color(from var(--ig-grid-background) var(--y-contrast)) h 0 l/1);
  --ig-grid-header-background: color-mix(in srgb, var(--ig-grid-foreground) 6%, var(--ig-grid-background));
  --ig-grid-header-text-color: var(--ig-grid-foreground);
  --ig-grid-row-hover-background: color-mix(in srgb, var(--ig-grid-accent-color) 8%, var(--ig-grid-row-odd-background));
  /* … and the rest of the token set */
}
```

Elija la ruta que se ajuste a su cadena de herramientas: cada una produce este mismo conjunto de tokens.

<PlatformBlock for="WebComponents, React">

### Sass

Si su proyecto compila Sass, el motor de temas puede escribir el conjunto de tokens por usted mediante la función `grid-theme()`. Para usarla, primero instale el paquete de temas:

```bash
npm install igniteui-theming
```

A continuación, importe el paquete, que exporta las funciones de tema y el mixin `tokens()`:

```scss
@use "igniteui-theming" as *;
```

A continuación, declare el tema con <ApiLink type="function-grid-theme" label="grid-theme" kind="sass" module="index.html" /> e inclúyalo en el elemento que quiera afectar:

```scss
.my-grid {
  @include tokens(grid-theme(
    $background: #08002e,
    $accent-color: #ff7d52
  ));
}
```

Cada parámetro se asocia al token del mismo nombre: `$background` a `--ig-grid-background`, `$accent-color` a `--ig-grid-accent-color`, y cada token que omita se emite como una expresión sobre los que haya establecido.

</PlatformBlock>

[Ignite UI Theming MCP](../../ai/theming-mcp.mdx) genera el tema a través de su asistente de IA. Si pide salida CSS, devolverá propiedades personalizadas listas para usar, así que no se necesita una cadena de herramientas Sass local.

## Tokens primarios

En un tema generado, {ComponentTitle} se construye a partir de tres tokens primarios y todos los demás colores los siguen.

| Token | Lo que controla en un tema generado |
| -- | -- |
| `--ig-grid-background` | La superficie sobre la que se construye todo el componente. Todas las demás superficies y el primer plano predeterminado se derivan de ella. |
| `--ig-grid-foreground` | Texto e iconos. Se derivan del fondo por contraste cuando no se establecen. |
| `--ig-grid-accent-color` | Color interactivo: indicadores de ordenación, selección, tintes al pasar el ratón, foco. |

`--ig-grid-foreground` figura como primario, pero rara vez necesita establecerse. Si no se toca, se elige por contraste con el fondo, de modo que un fondo oscuro produce texto claro y uno claro produce texto oscuro sin necesidad de una segunda declaración.

## Cómo funciona la derivación

Los tokens derivados en un tema generado no son colores fijos. Cada uno es una expresión CSS sobre los tokens primarios:

```css
.my-grid {
  --ig-grid-foreground: hsla(from color(from var(--ig-grid-background) var(--y-contrast)) h 0 l/1);
  --ig-grid-header-background: color-mix(in srgb, var(--ig-grid-foreground) 6%, var(--ig-grid-background));
  --ig-grid-row-hover-background: color-mix(in srgb, var(--ig-grid-accent-color) 8%, var(--ig-grid-row-odd-background));
  --ig-grid-sorted-header-icon-color: hsl(from var(--ig-grid-accent-color) h s l/0.7);
}
```

Se derivan dos consecuencias. En primer lugar, cambiar un token primario recalcula todo lo que depende de él, incluso en tiempo de ejecución mediante propiedades personalizadas CSS. En segundo lugar, las relaciones se mantienen con cualquier valor que se proporcione, de modo que un tema no puede desajustarse consigo mismo. Ambas cosas solo se cumplen mientras los tokens generados estén declarados; si los elimina, cada propiedad vuelve a ser independiente.

## Profundizando

En un tema generado, algunos tokens son raíces de derivación por derecho propio. Declarar uno lo desvincula del fondo, y lo que se apoye en él debe derivarse del nuevo valor.

`--ig-grid-header-background` es el ejemplo más claro. Si no se toca, se mezcla a partir de `--ig-grid-background`, y el texto del encabezado sigue a `--ig-grid-foreground`. Si lo declara, el texto del encabezado se vuelve a derivar para tomar contraste respecto al propio fondo del encabezado:

```css
.my-grid {
  --ig-grid-header-background: #ff7d52;
  --ig-grid-header-text-color: hsla(from color(from var(--ig-grid-header-background) var(--y-contrast)) h 0 l/1);
}
```

<DocsAside type="note">
Recurra a estos tokens solo cuando quiera que una superficie deje de seguir el fondo. La mayoría de los tokens derivados es mejor dejarlos como están: sustituir uno fija un valor que, de otro modo, se mantendría en sintonía con el resto del tema.
</DocsAside>

## Estructura

El color es solo la mitad de un tema. La densidad y el redondeo los controlan los tokens globales del sistema de diseño, no los tokens de cuadrícula, así que se establecen junto con los tokens de cuadrícula:

```css
.my-grid {
  --ig-size: var(--ig-size-small);   /* small | medium | large */
  --ig-radius-factor: 0;             /* 0 to 1 */
}
```

Las líneas de la cuadrícula también son tokens de tema. Para ocultar una, tíñala con el color de la superficie que hay detrás en lugar de eliminarla, de modo que las métricas de las filas no cambien entre temas:

```css
.my-grid {
  /* horizontal dividers, blended away */
  --ig-grid-row-border-color: var(--ig-grid-background);
  /* vertical dividers, drawn in the same color the theme derives for rows */
  --ig-grid-body-column-border-color-odd: hsl(from color-mix(in srgb, var(--ig-grid-foreground) 16%, var(--ig-grid-background)) h s l/0.38);
  --ig-grid-body-column-border-color-even: hsl(from color-mix(in srgb, var(--ig-grid-foreground) 16%, var(--ig-grid-background)) h s l/0.38);
}
```

## Ajustar finamente las propiedades individuales

De forma predeterminada, cada propiedad `--ig-grid-*` es independiente. Cada una se resuelve con la paleta base; en el tema Material, por ejemplo, el encabezado toma `var(--ig-grid-header-background, var(--ig-gray-100))`, de modo que un único cambio altera solo esa parte de {ComponentTitle} y deja el resto del diseño intacto. Esto hace que los ajustes puntuales sean seguros y predecibles:

```css
.my-grid {
  --ig-grid-header-background: #120b3d;
  --ig-grid-header-text-color: #ffffff;
}
```

La misma independencia se aplica a los tokens primarios. Sin un tema generado, `--ig-grid-background` y `--ig-grid-accent-color` son propiedades normales y **no** se propagan al resto de {ComponentTitle}:

```css
/* The background changes, the header stays gray. */
.my-grid {
  --ig-grid-background: #08002e;
  --ig-grid-accent-color: #ff7d52;
}
```

Para rediseñar toda la {ComponentTitle} a partir de unos pocos colores, [cree un tema](#crear-un-tema).
