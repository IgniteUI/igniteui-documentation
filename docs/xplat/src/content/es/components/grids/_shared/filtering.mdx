# Filtrado de {Platform} {ComponentTitle}

El filtrado de {ProductName} en {Platform} {ComponentTitle} es una función que permite mostrar u ocultar selectivamente datos según criterios o condiciones específicos. Hay un contenedor de datos enlazado a través del cual el componente <ApiLink type="{ComponentName}" /> proporciona una API de filtrado completa y todas las capacidades de filtrado. Los tipos de filtrado disponibles aquí son tres:

- Filtrado rápido
- [Filtrado al estilo de Excel](excel-style-filtering.mdx)
- [Filtrado avanzado](advanced-filtering.mdx)

## Configuración

Para especificar si el filtrado está habilitado y qué modo de filtrado debe usarse, <ApiLink type="{ComponentName}" /> expone las propiedades siguientes: <ApiLink type="{ComponentName}" member="allowFiltering" />, <ApiLink type="{ComponentName}" member="allowAdvancedFiltering" />, <ApiLink type="{ComponentName}" member="filterMode" /> y <ApiLink type="Column" member="filterable" />.

La propiedad <ApiLink type="{ComponentName}" member="allowFiltering" /> le permite especificar las siguientes opciones:
- **false**: el filtrado de la cuadrícula correspondiente quedará deshabilitado. Este es el valor predeterminado.
- **true**: el filtrado de la cuadrícula correspondiente quedará habilitado.

La propiedad <ApiLink type="{ComponentName}" member="allowAdvancedFiltering" /> le permite especificar las siguientes opciones:
- **false**: el filtrado avanzado de la cuadrícula correspondiente quedará deshabilitado. Este es el valor predeterminado.
- **true**: el filtrado avanzado de la cuadrícula correspondiente quedará habilitado.

La propiedad <ApiLink type="{ComponentName}" member="filterMode" /> le permite especificar las siguientes opciones:
- **QuickFilter**: una interfaz de filtrado simple. Este es el valor predeterminado.
- **ExcelStyleFilter**: una interfaz de filtrado similar a la de Excel.

La propiedad <ApiLink type="Column" member="filterable" /> le permite especificar las siguientes opciones:
- **true**: el filtrado de la columna correspondiente quedará habilitado. Este es el valor predeterminado.
- **false**: el filtrado de la columna correspondiente quedará deshabilitado.

## Interacción

Para abrir la fila de filtro de una columna concreta, haga clic en el chip 'Filter' situado debajo de su encabezado. Para añadir condiciones, elija el operando de filtro en el desplegable situado a la izquierda del campo de entrada e introduzca un valor. En las columnas **number** y **date**, 'Equals' se selecciona de forma predeterminada; en las columnas **string**, 'Contains'; y en las columnas **boolean**, 'All'. Al pulsar 'Enter' se confirma la condición y ya puede añadir otra. Entre los chips de condición hay un desplegable que determina el operador lógico entre ellos; 'AND' está seleccionado de forma predeterminada. Para quitar una condición, haga clic en el botón 'X' del chip; para editarla, seleccione el chip y el campo de entrada se llenará con los datos del chip. Mientras la fila de filtro está abierta, puede hacer clic en el encabezado de cualquier columna filtrable para seleccionarla y añadir condiciones de filtro para ella.

Cuando se han aplicado algunas condiciones de filtro a una columna y la fila de filtro está cerrada, puede eliminar las condiciones pulsando el botón de cierre del chip, o abrir la fila de filtro seleccionando cualquiera de los chips. Cuando no hay espacio suficiente para mostrar todas las condiciones, aparece un icono de filtro con un distintivo que indica cuántas condiciones más hay. También puede hacer clic en él para abrir la fila de filtro.

## Uso

Hay una estrategia de filtrado predeterminada incluida, así como todas las condiciones de filtrado estándar, que el desarrollador puede sustituir por su propia implementación. Además, hemos proporcionado una forma sencilla de incorporar sus propias condiciones de filtrado personalizadas. El <ApiLink type="{ComponentName}" /> ofrece actualmente no solo una interfaz de filtrado simple, sino también opciones de filtrado más complejas. Según el <ApiLink type="Column" member="dataType" /> establecido para la columna, el conjunto correcto de **operaciones de filtrado** se carga dentro del desplegable de la interfaz de filtrado. Además, puede establecer <ApiLink type="FilteringExpression" member="ignoreCase" label="IgnoreCase" /> y las propiedades iniciales <ApiLink type="BooleanFilteringOperand" member="condition" label="Condition" />.

La función de filtrado está habilitada para el componente <ApiLink type="{ComponentName}" /> al establecer la entrada <ApiLink type="{ComponentName}" member="allowFiltering" /> en **true**. El <ApiLink type="{ComponentName}" member="filterMode" /> predeterminado es `QuickFilter` y **no puede** cambiarse en tiempo de ejecución. Para deshabilitar esta función en una columna determinada, establezca la entrada <ApiLink type="Column" member="filterable" /> en **false**.

Puede filtrar cualquier columna o una combinación de columnas mediante la API de <ApiLink type="{ComponentName}" />. <ApiLink type="{ComponentName}" /> expone varios métodos para esta tarea: <ApiLink type="Filter" />, `FilterGlobal` y `ClearFilter`.

- <ApiLink type="Filter" />: filtra una única columna o una combinación de columnas.

Se exponen cinco clases de operandos de filtrado:

- <ApiLink type="FilteringOperand" />: es un operando de filtrado base, que puede heredarse al definir condiciones de filtrado personalizadas.
- <ApiLink type="BooleanFilteringOperand" /> define todas las condiciones de filtrado predeterminadas para el tipo **boolean**.
- <ApiLink type="NumberFilteringOperand" /> define todas las condiciones de filtrado predeterminadas para el tipo **numeric**.
- <ApiLink type="StringFilteringOperand" /> define todas las condiciones de filtrado predeterminadas para el tipo **string**.
- <ApiLink type="DateFilteringOperand" /> define todas las condiciones de filtrado predeterminadas para el tipo **date**.

```typescript
// Single column filtering

// Filter the `ProductName` column for values which `contains` the `myproduct` substring, ignoring case
this.grid.filter('ProductName', 'myproduct', IgcStringFilteringOperand.instance().condition('contains'), true);
```

Los únicos parámetros obligatorios son la clave del campo de la columna y el término de filtrado. Tanto la condición como la distinción entre mayúsculas y minúsculas se deducirán de las propiedades de la columna si no se proporcionan. En el caso de filtrado múltiple, el método acepta un array de expresiones de filtrado.

## Operandos de filtrado personalizados

Puede personalizar el menú de filtrado añadiendo, eliminando o modificando los operandos de filtrado. De forma predeterminada, el menú de filtrado contiene ciertos operandos según el tipo de datos de la columna (<ApiLink type="BooleanFilteringOperand" />, <ApiLink type="DateFilteringOperand" />, <ApiLink type="NumberFilteringOperand" /> y <ApiLink type="StringFilteringOperand" />). Puede extender estas clases, o su clase base <ApiLink type="FilteringOperand" />, para cambiar el comportamiento de los elementos del menú de filtrado.

En el ejemplo siguiente, revise los menús de filtro de las columnas “Product Name” y “Discontinued”. Para el filtro de la columna “Discontinued”, hemos limitado los operandos a All, True y False. Para el filtro de la columna “Product Name”, hemos modificado la lógica de los operandos Contains y Does Not Contain para realizar búsquedas sensibles a mayúsculas y minúsculas, y hemos añadido también los operandos Empty y Not Empty.

Para hacerlo, extienda <ApiLink type="StringFilteringOperand" /> y <ApiLink type="BooleanFilteringOperand" />, modifique las operaciones y su lógica, y establezca la entrada `filters` de la columna en los nuevos operandos.

<PlatformBlock for="Angular">
```typescript
// grid-custom-filtering.component.ts

export class GridCustomFilteringComponent {
    public caseSensitiveFilteringOperand = CaseSensitiveFilteringOperand.instance();
    public booleanFilteringOperand = BooleanFilteringOperand.instance();
}

export class CaseSensitiveFilteringOperand extends IgxStringFilteringOperand {
    private constructor() {
        super();
        const customOperations = [
            {
                iconName: 'contains',
                isUnary: false,
                logic: (target: string, searchVal: string, ignoreCase?: boolean) => {
                    ignoreCase = false;
                    const search = IgxStringFilteringOperand.applyIgnoreCase(searchVal, ignoreCase);
                    target = IgxStringFilteringOperand.applyIgnoreCase(target, ignoreCase);
                    return target.indexOf(search) !== -1;
                },
                name: 'Contains (case sensitive)'
            },
            {
                iconName: 'does_not_contain',
                isUnary: false,
                logic: (target: string, searchVal: string, ignoreCase?: boolean) => {
                    ignoreCase = false;
                    const search = IgxStringFilteringOperand.applyIgnoreCase(searchVal, ignoreCase);
                    target = IgxStringFilteringOperand.applyIgnoreCase(target, ignoreCase);
                    return target.indexOf(search) === -1;
                },
                name: 'Does Not Contain (case sensitive)'
            }
        ];

        const emptyOperators = [
            // 'Empty'
            this.operations[6],
            // 'Not Empty'
            this.operations[7]
        ];

        this.operations = customOperations.concat(emptyOperators);
    }
}

export class BooleanFilteringOperand extends IgxBooleanFilteringOperand {
    private constructor() {
        super();
        this.operations = [
            // 'All'
            this.operations[0],
            // 'TRUE'
            this.operations[1],
            // 'FALSE'
            this.operations[2]
        ];
    }
}
```

```typescript
                logic: (target: string, searchVal: string, ignoreCase?: boolean) => {
                    ignoreCase = false;
                    const search = IgcStringFilteringOperand.applyIgnoreCase(searchVal, ignoreCase);
                    target = IgcStringFilteringOperand.applyIgnoreCase(target, ignoreCase);
                    return target.indexOf(search) === -1;
                },
                name: 'Does Not Contain (case sensitive)'
            }
        ];

        const emptyOperators = [
            // 'Empty'
            this.operations[6],
            // 'Not Empty'
            this.operations[7]
        ];

        this.operations = customOperations.concat(emptyOperators);
    }
}

export class BooleanFilteringOperand extends IgcBooleanFilteringOperand {
    private constructor() {
        super();
        this.operations = [
            // 'All'
            this.operations[0],
            // 'TRUE'
            this.operations[1],
            // 'FALSE'
            this.operations[2]
        ];
    }
}
```

## Estilos

Para empezar a dar estilo a la fila de filtro, debemos importar el archivo `index`, donde viven todas las funciones de tema y los mixins de componentes:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Siguiendo el enfoque más sencillo, creamos un tema nuevo que extiende `grid-theme` y acepta los parámetros `$filtering-row-text-color`, `$filtering-row-background`, `$filtering-header-text-color` y `$filtering-header-background`.

```scss
$custom-grid: grid-theme(
    $filtering-row-text-color: #292826,
    $filtering-row-background: #FFCD0F,
    $filtering-header-text-color: #292826,
    $filtering-header-background: #FFCD0F
);
```

Como se ve, `grid-theme` solo controla los colores de la fila de filtro y del encabezado de la columna que se está filtrando. Evidentemente, hay muchos más componentes dentro de la fila de filtro, como un grupo de entrada, chips, botones y otros. Para darles estilo, debemos crear un tema independiente para cada uno, así que creemos un nuevo tema de grupo de entrada y un nuevo tema de botón:

```scss
$dark-input-group: input-group-theme(
    $box-background: #FFCD0F,
    $idle-text-color: #292826,
    $focused-text-color: #292826,
    $filled-text-color: #292826
);

$dark-button: flat-button-theme(
    $background: #FFCD0F,
    $foreground: #292826,
    $hover-background: #292826,
    $hover-foreground: #FFCD0F
);
```

En este ejemplo solo hemos cambiado algunos parámetros del grupo de entrada y del botón, pero `input-group-theme` y `flat-button-theme` ofrecen muchos más parámetros para controlar su estilo respectivo.

El último paso es **incluir** los mixins de componentes, cada uno con su tema correspondiente. También estableceremos la propiedad color para el marcador de posición de la entrada.

```scss
@include grid($custom-grid);
.igx-grid__filtering-row {
    @include button($dark-button);
    @include input-group($dark-input-group);

    .igx-input-group__input::placeholder {
        color: #FFCD0F;
    }
}
```

<DocsAside type="info">
Limitamos los mixins de **igx-button** e **igx-input-group** dentro de `.igx-grid__filtering-row`, de modo que solo se den estilo a los botones de la fila de filtro y a su grupo de entrada. De lo contrario, otros botones y grupos de entrada de la cuadrícula también se verían afectados.
</DocsAside>

 <DocsAside type="info">
 Si el componente usa una encapsulación de vista `Emulated`, es necesario `penetrate` esta encapsulación usando `::ng-deep`:
 </DocsAside>

```scss
:host {
     ::ng-deep {
        @include grid($custom-grid);
        .igx-grid__filtering-row {
            @include button($dark-button);
            @include input-group($dark-input-group);

                color: #FFCD0F;

}
```

### Definición de una paleta de colores

En lugar de codificar los valores de color como acabamos de hacer, podemos conseguir más flexibilidad en cuanto a colores usando las funciones `igx-palette` y `igx-color`.

`igx-palette` genera una paleta de colores basada en los colores primario y secundario que se le pasan:

```scss
$yellow-color: #FFCD0F;
$black-color: #292826;

$dark-palette: palette($primary: $black-color, $secondary: $yellow-color);
```

Y después, con `igx-color`, podemos obtener fácilmente un color de la paleta.

```scss
$custom-grid: grid-theme(
    $filtering-row-text-color: color($dark-palette, "primary", 400),
    $filtering-row-background: color($dark-palette, "secondary", 400),
    $filtering-header-text-color: color($dark-palette, "primary", 400),
    $filtering-header-background: color($dark-palette, "secondary", 400)
);

$dark-input-group: input-group-theme(
    $box-background: color($dark-palette, "secondary", 400),
    $idle-text-color: color($dark-palette, "primary", 400),
    $focused-text-color: color($dark-palette, "primary", 400),
    $filled-text-color: color($dark-palette, "primary", 400)
);

$dark-button: flat-button-theme(
    $background: color($dark-palette, "secondary", 400),
    $foreground: color($dark-palette, "primary", 400),
    $hover-background: color($dark-palette, "primary", 400),
    $hover-foreground: color($dark-palette, "secondary", 400)
);
```

<DocsAside type="info">
`igx-color` y `igx-palette` son funciones potentes para generar y obtener colores. Consulte el tema [Paletas](../themes/sass/palettes.mdx) para una guía detallada sobre cómo usarlas.
</DocsAside>

### Usar esquemas

Avanzando con el motor de temas, puede construir una estructura sólida y flexible que se beneficia de los [Esquemas](../themes/sass/schemas.mdx). Un **esquema** es una receta de un tema.

Extienda uno de los dos esquemas predefinidos que se proporcionan para cada componente; en este caso, los esquemas `light-grid`, `light-input-group` y `light-button`:

```scss
// Extending the light grid schema
$custom-grid-schema: extend($_light-grid,
    (
        filtering-row-text-color:(
           color: ("primary", 400)
        ),
        filtering-row-background:(
           color: ("secondary", 400)
        ),
        filtering-header-text-color:(
           color: ("primary", 400)
        ),
        filtering-header-background:(
           color: ("secondary", 400)
        )
    )
);

// Extending the light input group schema
$custom-input-group-schema: extend($_light-input-group,
    (
        box-background:(
           color: ("secondary", 400)
        ),
        idle-text-color:(
           color: ("primary", 400)
        ),
        focused-text-color:(
           color: ("primary", 400)
        ),
        filled-text-color:(
           color: ("primary", 400)
        )
    )
);

// Extending the light button schema
$custom-button-schema: extend($_light-button,
    (
        flat-background:(
           color: ("secondary", 400)
        ),
        flat-text-color:(
           color: ("primary", 400)
        ),
        flat-hover-background:(
           color: ("primary", 400)
        ),
        flat-hover-text-color:(
           color: ("secondary", 400)
        )
    )
);
```

Para aplicar nuestros esquemas personalizados, debemos **extender** uno de los globales (`light` o `dark`), lo que básicamente señala los componentes con un esquema personalizado, y después añadirlo a los temas de cada componente:

```scss
// Extending the global light-schema
$custom-light-schema: extend($light-schema,(
    igx-grid: $custom-grid-schema,
    igx-input-group: $custom-input-group-schema,
    igx-button: $custom-button-schema
));

// Defining grid-theme with the global light schema
$custom-grid: grid-theme(
  $schema: $custom-light-schema
);

// Defining flat-button-theme with the global light schema
$custom-button: flat-button-theme(
  $schema: $custom-light-schema
);

// Defining input-group-theme with the global light schema
$custom-input-group: input-group-theme(
  $schema: $custom-light-schema
);
```

No olvide incluir los temas de la misma forma que se ha mostrado anteriormente.

## Limitaciones conocidas

<DocsAside type="info">
Algunos navegadores, como Firefox, no logran interpretar los separadores decimales específicos de cada región y los consideran separadores de agrupación, por lo que resultan no válidos. Al introducir valores de este tipo en el filtro de una columna numérica, solo se aplicará a la expresión de filtrado la parte válida del número. Para más información, consulte el [problema](https://bugzilla.mozilla.org/show_bug.cgi?id=1199665) de Firefox.
</DocsAside>

### Cambios incompatibles en la versión 6.1.0
- La propiedad <ApiLink type="{ComponentName}" /> `filteringExpressions` se ha eliminado. Use <ApiLink type="FilteringExpressionsTree" /> en su lugar.
- El método `filter_multiple` se ha eliminado. Use el método <ApiLink type="Filter" /> y la propiedad <ApiLink type="FilteringExpressionsTree" /> en su lugar.
- El método <ApiLink type="Filter" /> tiene una nueva firma. Ahora acepta los siguientes parámetros:
  - <ApiLink type="Column" member="name" label="Name" />: el nombre de la columna que se va a filtrar.
  - `Value`: el valor que se usará para filtrar.
  - `ConditionOrExpressionTree` (opcional): este parámetro acepta un objeto de tipo <ApiLink type="FilteringOperation" /> o <ApiLink type="FilteringExpressionsTree" />. Si solo se necesita un filtrado simple, puede pasarse una operación de filtrado como argumento. En el caso de filtrado avanzado, puede pasarse como argumento un árbol de expresiones que contenga una lógica de filtrado compleja.
  - <ApiLink type="FilteringExpression" member="ignoreCase" label="IgnoreCase" /> (opcional): indica si el filtrado distingue o no mayúsculas y minúsculas.
- El evento `FilteringDone` tiene ahora un único parámetro de tipo <ApiLink type="FilteringExpressionsTree" /> que contiene el estado de filtrado de la columna filtrada.
- Operandos de filtrado: la propiedad <ApiLink type="FilteringExpression" /> de la condición ya no es una referencia directa a un método de condición de filtrado, sino una referencia a un <ApiLink type="FilteringOperation" />.
- <ApiLink type="ColumnComponent" /> expone ahora una propiedad <ApiLink type="Column" member="filters" label="Filters" />, que acepta una referencia a una clase <ApiLink type="FilteringOperand" />.
- Pueden proporcionarse filtros personalizados a las columnas {ComponentTitle} rellenando la propiedad <ApiLink type="BooleanFilteringOperand" member="operations" label="Operations" /> de <ApiLink type="FilteringOperand" /> con operaciones de tipo <ApiLink type="FilteringOperation" />.
