# Ordenación de {Platform} {ComponentTitle}

La función de ordenación de datos de {ProductName} en {Platform} {ComponentTitle} se habilita por columna, lo que significa que <ApiLink type="{ComponentName}" /> puede tener una combinación de columnas ordenables y no ordenables. Realizar acciones de ordenación {Platform} le permite cambiar el orden de visualización de los registros según los criterios especificados.

<PlatformBlock for="Angular">
<DocsAside type="info">
Hasta ahora, la agrupación y la ordenación funcionaban conjuntamente. En la versión 13.2 se introduce un nuevo comportamiento que desacopla la agrupación de la ordenación. Por ejemplo, borrar la agrupación no borrará las expresiones de ordenación de la cuadrícula, o viceversa. Aun así, si una columna está ordenada y agrupada a la vez, las expresiones de agrupación tienen prioridad.
</DocsAside>

</PlatformBlock>

## Ordenar mediante la API

Puede ordenar cualquier columna o una combinación de columnas mediante la API de <ApiLink type="{ComponentName}" />, usando el método <ApiLink type="{ComponentName}" member="sort" label="Sort" />:

<PlatformBlock for="Angular">
```typescript

```
</PlatformBlock>

<PlatformBlock for="WebComponents">
```typescript

```
</PlatformBlock>

<PlatformBlock for="React">

<ComponentBlock for="Grid">
<PlatformBlock for="Angular">
```typescript

// Perform a case insensitive ascending sort on the ProductName column.
this.grid.sort({ fieldName: 'ProductName', dir: SortingDirection.Asc, ignoreCase: true });

// Perform sorting on both the ProductName and Price columns.
this.grid.sort([
    { fieldName: 'ProductName', dir: SortingDirection.Asc, ignoreCase: true },
    { fieldName: 'Price', dir: SortingDirection.Desc }
]);

```

## Estilos

Para empezar a dar estilo al comportamiento de ordenación, debemos importar el archivo `index`, donde viven todas las funciones de tema y los mixins de componentes:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Siguiendo el enfoque más sencillo, creamos un tema nuevo que extiende <ApiLink type="function-grid-theme" label="grid-theme" kind="sass" module="index.html" /> y acepta los parámetros `$sorted-header-icon-color` y `sortable-header-icon-hover-color`.

```scss
$custom-theme: grid-theme(
    $sorted-header-icon-color: #ffb06a,
    $sortable-header-icon-hover-color: black
);
```

El último paso es **incluir** los mixins de componentes:

```scss
 @include grid($custom-theme);
```

<DocsAside type="info">
Si el componente usa un ViewEncapsulation [Emulated](../themes/styles.mdx#view-encapsulation), es necesario `penetrate` esa encapsulación usando `::ng-deep`:
</DocsAside>

 ```scss
:host {
    ::ng-deep {
        @include grid($custom-theme);
    }
}
```

### Definir una paleta de colores

En lugar de codificar los valores de color como acabamos de hacer, podemos conseguir más flexibilidad en cuanto a colores usando las funciones <ApiLink type="function-igx-palette" label="igx-palette" kind="sass" module="index.html" /> y <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" />.

`igx-palette` genera una paleta de colores basada en los colores primario y secundario que se le pasan:

```scss
$black-color: black;
$orange-color: #ffb06a;

$custom-palette: palette($primary: $black-color, $secondary: $orange-color);
```

Y después, con <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" />, podemos obtener fácilmente un color de la paleta.

```scss
$custom-theme: grid-theme(
    $sorted-header-icon-color: color($custom-palette, "secondary", 500),
    $sortable-header-icon-hover-color: color($custom-palette, "primary", 500)
);
```

<DocsAside type="info">
`igx-color` y `igx-palette` son funciones potentes para generar y obtener colores. Consulte el tema [Paletas](../themes/sass/palettes.mdx) para una guía detallada sobre cómo usarlas.
</DocsAside>

### Usar esquemas

Para avanzar con el motor de temas, puede crear una estructura sólida y flexible que se beneficie de [**esquemas**](../themes/sass/schemas.mdx). Un **esquema** es una receta de un tema.

Extienda uno de los dos esquemas predefinidos que se proporcionan para cada componente; en este caso, <ApiLink type="variable-_light-grid" label="_light-grid" kind="sass" module="index.html" />:

```scss
// Extending the light grid schema
$custom-grid-schema: extend($_light-grid,
    (
        sorted-header-icon-color: (igx-color:('secondary', 500)),
        sortable-header-icon-hover-color: (igx-color:('primary', 500))
    )
);
```

Para aplicar nuestro esquema personalizado, tenemos que **extender** uno de los globales (<ApiLink type="variable-light-schema" label="light" kind="sass" module="index.html" /> o <ApiLink type="variable-dark-schema" label="dark" kind="sass" module="index.html" />), lo que básicamente señala los componentes con un esquema personalizado, y después añadirlo a los temas de los componentes correspondientes:

```scss
// Extending the global light-schema
$my-custom-schema: extend($light-schema,
    (
        igx-grid: $custom-grid-schema
    )
);

// Defining our custom theme with the custom schema
$custom-theme: grid-theme(
  $palette: $custom-palette,
  $schema: $my-custom-schema
);
```

No olvide incluir los temas de la misma forma que se ha mostrado anteriormente.
