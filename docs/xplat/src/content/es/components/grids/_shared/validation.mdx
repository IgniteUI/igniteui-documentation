# Edición y validación de {Platform} {ComponentTitle}

{Platform} {ComponentName} proporciona edición con un mecanismo de validación integrado de la entrada del usuario al editar celdas o filas. Amplía la funcionalidad de validación de formularios para facilitar la integración con una funcionalidad muy conocida. Cuando cambia el estado del editor, se aplican indicadores visuales a la celda editada en `{ComponentName}`.

## Configuración

### Configurar mediante configuración basada en plantillas

Ampliamos algunos de los validadores de formularios de {Platform} para que funcionen directamente con <ApiLink type="Column" />. Los mismos validadores están disponibles como atributos que se pueden establecer de forma declarativa en <ApiLink type="Column" />. Los siguientes validadores se admiten de forma inmediata:

- Required
- Mínimo
- Máximo
- Email
- MinLength
- MaxLength
- Pattern

## API del servicio de validación

La cuadrícula expone un servicio de validación mediante la propiedad <ApiLink type="{ComponentName}" member="validation" />.

Ese servicio tiene las siguientes API públicas:

- `Valid`: devuelve si el estado de validación del grid es válido.
- `GetInvalid`: devuelve los registros con estados no válidos.
- `Clear`: borra el estado de un registro por id, o borra todo el estado si no se proporciona ningún id.
- <ApiLink type="{ComponentName}" member="markAsTouched" />: marca el registro/campo correspondiente como tocado.

Los estados no válidos persistirán hasta que se corrijan los errores de validación según la regla de validación o hasta que se borren.

## Desencadenadores de validación

La validación se disparará en los siguientes escenarios:

- Mientras se edita mediante el editor de celdas, según el <ApiLink type="GridValidationTrigger" /> de la cuadrícula. Ya sea en `Change` mientras se escribe en el editor, o en `Blur` cuando el editor pierde el foco o se cierra.
- Al actualizar celdas o filas mediante la API: <ApiLink type="{ComponentName}" member="updateRow" />, <ApiLink type="{ComponentName}" member="updateCell" />, etc.
- Al usar la edición por lotes y la API `Undo`/`Redo` del servicio de transacciones.

<DocsAside type="info">
La validación no se disparará para los registros que no se han editado mediante la entrada del usuario o mediante la API de edición. Los indicadores visuales de la celda solo se mostrarán si el campo correspondiente se considera tocado, ya sea por la interacción del usuario o mediante la API <ApiLink type="{ComponentName}" member="markAsTouched" /> del servicio de validación.
</DocsAside>

## Opciones de personalización de validación de {Platform} {ComponentTitle}

### Establecer un validador personalizado

Puede definir su propia directiva de validación para usarla en una <ApiLink type="Column" /> de la plantilla.

```ts
@Directive({
    selector: '[phoneFormat]',
    providers: [{ provide: NG_VALIDATORS, useExisting: PhoneFormatDirective, multi: true }]
})
export class PhoneFormatDirective extends Validators {
    @Input('phoneFormat')
    public phoneFormatString = '';

    public validate(control: AbstractControl): ValidationErrors | null {
        return this.phoneFormatString ? phoneFormatValidator(new RegExp(this.phoneFormatString, 'i'))(control)
            : null;
    }
}
```

Una vez definida y añadida en el módulo de su aplicación, puede asignarla de forma declarativa a una columna concreta de la cuadrícula:

```html
<igx-column phoneFormat="\+\d{1}\-(?!0)(\d{3})\-(\d{3})\-(\d{4})\b"></igx-column>
```

### Cambiar la plantilla de error predeterminada

Puede definir su propia plantilla de error personalizada que se mostrará en la información emergente de error cuando la celda entre en estado no válido. Es útil en escenarios en los que desea añadir su propio mensaje de error personalizado o cambiar de otro modo el aspecto o el contenido del mensaje.

```html

      <ng-container *ngTemplateOutlet="defaultErr">
```

### Validación entre campos

En algunos escenarios, la validación de un campo puede depender del valor de otro campo del registro.

En ese caso puede usarse un validador personalizado para comparar los valores del registro mediante su <PlatformBlock for="Angular"><ApiLink type="IGridFormGroupCreatedEventArgs" member="formGroup" label="FormGroup" /></PlatformBlock><PlatformBlock for="WebComponents,Blazor"><ApiLink type="FormGroup" /></PlatformBlock>.

<ComponentBlock for="Grid">
El ejemplo siguiente muestra una validación entre campos de distintos campos del mismo registro. Comprueba la validez de las fechas respecto a la fecha actual y entre la fecha de activación y la de creación del registro, así como la proporción de acuerdos ganados/perdidos de cada empleado. Todos los errores se recogen en una columna anclada aparte que indica que el registro no es válido y muestra los errores correspondientes.

Las siguientes líneas de código muestran la función validadora entre campos, que contiene las comparaciones y establece los errores correspondientes.

<PlatformBlock for="Blazor">
```razor
private rowValidator(): ValidatorFn {
    return (formGroup: FormGroup): ValidationErrors | null => {
        let returnObject = {};
        const createdOnRecord = formGroup.get('created_on');
        const lastActiveRecord = formGroup.get('last_activity');
        const winControl = formGroup.get('deals_won');
        const loseControl = formGroup.get('deals_lost');
        const actualSalesControl = formGroup.get('actual_sales');

        // Validate dates
        const curDate = new Date();
        if (new Date(createdOnRecord.value) > curDate) {
            // The created on date should not be greater than current date.
            returnObject['createdInvalid'] =  true;
        }
        if (new Date(lastActiveRecord.value) > curDate) {
            // The last active date should not be greater than current date.
            returnObject['lastActiveInvalid'] = true;
        }
        if (new Date(createdOnRecord.value) > new Date(lastActiveRecord.value)) {
            // The created on date should not be greater than last active date.
            returnObject['createdLastActiveInvalid'] = true;
        }

        // Validate deals
        const dealsRatio = this.calculateDealsRatio(winControl.value, loseControl.value);
        if (actualSalesControl.value === 0 && dealsRatio > 0) {
            // If the actual sales value is 0 but there are deals made.
            returnObject['salesZero'] = true;
        }
        if (actualSalesControl.value > 0 && dealsRatio === 0) {
            // If the deals ratio based on deals won is 0 but the actual sales is bigger than 0.
            returnObject['salesNotZero'] = true;
        }

        return returnObject;
    };
}

public calculateDealsRatio(dealsWon, dealsLost) {
    if (dealsLost === 0) return dealsWon + 1;
    return Math.round(dealsWon / dealsLost * 100) / 100;
}

```

Los validadores entre campos pueden añadirse al formGroup en el evento `FormGroupCreated`. En ellos pueden compararse varios campos para comprobar su validez.

```ts
  public formCreateCustomerHandler(event: IGridFormGroupCreatedEventArgs) {
        const formGroup = event.formGroup;
        formGroup.addValidators(this.addressValidator());
    }

    public formCreateOrderHandler(event: IGridFormGroupCreatedEventArgs) {
        const formGroup = event.formGroup;
        formGroup.addValidators(this.dateValidator());

    public addressValidator(): ValidatorFn {
        return (control: AbstractControl): ValidationErrors | null => {
            const formGroup = control;
            let returnObject = {};
            const city = formGroup.get('City');
            const country = formGroup.get('Country');
            const validCities = this.countryData.get(country.value);
            if (!validCities || !validCities[city.value]) {
                returnObject['invalidAddress'] = true;
            }
            return returnObject;
        }
    }

    public dateValidator(): ValidatorFn {
        return (control: AbstractControl): ValidationErrors | null => {
            const formGroup = control;
            let returnObject = {};
            const orderDate = formGroup.get('OrderDate').value;
            const shippedDate = formGroup.get('ShippedDate').value;
            if (new Date(shippedDate) < new Date(orderDate)) {
                returnObject['invalidRange'] = true;
            }
            return returnObject;
        }
    }
```

```ts
    public isRowValid(cell: IgxGridCell) {
        const hasErrors = !!cell.row.validation.errors || cell.row.cells.some(x => !!x.validation.errors);
        return !hasErrors;
    }

    public stateMessage(cell: IgxGridCell) {
        const messages = [];
        const row = cell.row;
        if  (row.validation.errors?.invalidAddress) {
            messages.push('The address information is invalid. City does not match the Country.');
        }
        if  (row.validation.errors?.invalidRange) {
            messages.push('The ShippedDate cannot be before the OrderDate.');
        }
        const cellValidationErrors = row.cells.filter(x => !!x.validation.errors);
        if (cellValidationErrors && cellValidationErrors.length > 0) {
            const fields = cellValidationErrors.map(x => x.column.field).join(',');
            messages.push('The following fields are required: ' + fields);
        }

        if (messages.length === 0) {
            // no errors
            return ['Valid'];
        }
        return messages;
    }
```
