# Edición de celdas de {Platform} {ComponentTitle}

La edición de celdas de {ProductName} en {Platform} {ComponentTitle} ofrece una gran capacidad de manipulación de datos del contenido de celdas individuales dentro del componente {Platform} {ComponentTitle}, y dispone de una API potente para las operaciones CRUD de React. Es una característica fundamental en aplicaciones como hojas de cálculo, tablas de datos y cuadrículas de datos, que permite a los usuarios añadir, editar o actualizar datos en celdas concretas.
De forma predeterminada, la cuadrícula de {ProductName} se usa en la edición de celdas. Y, gracias a la **plantilla de edición de celdas predeterminada**, habrá distintos editores según el tipo de datos de la columna Top of Form.

Además, puede definir sus propias plantillas personalizadas para las acciones de actualizar datos y para sustituir el comportamiento predeterminado de confirmación y descarte de cualquier cambio.

## Edición de celdas

### Edición a través de la interfaz

Puede entrar en el modo de edición de una celda específica cuando una celda editable tiene el foco, de una de las siguientes formas:
- con doble clic;
- con un clic simple: el clic simple solo entrará en el modo de edición si la celda seleccionada anteriormente estaba en modo de edición y la celda seleccionada actualmente es editable. Si la celda seleccionada anteriormente no estaba en modo de edición, el clic simple solo selecciona la celda sin entrar en el modo de edición;
- al pulsar la tecla <kbd>ENTER</kbd>;
- al pulsar la tecla <kbd>F2</kbd>;

Puede salir del modo de edición **sin confirmar** los cambios de una de las siguientes formas:
- al pulsar la tecla <kbd>Escape</kbd>;
- al realizar operaciones de **ordenación**, **filtrado**, **búsqueda** y **ocultación**;

Puede salir del modo de edición y **confirmar** los cambios de una de las siguientes formas:
- al pulsar la tecla <kbd>ENTER</kbd>;
- al pulsar la tecla <kbd>F2</kbd>;
- al pulsar la tecla <kbd>TAB</kbd>;
- con un clic simple en otra celda: cuando hace clic en otra celda de <ApiLink type="{ComponentName}" />, sus cambios se enviarán.
- las operaciones como la paginación, el redimensionamiento, el anclaje o el movimiento salen del modo de edición y los cambios se envían.


<DocsAside type="info">
La celda permanece en modo de edición cuando se desplaza vertical u horizontalmente, o cuando se hace clic fuera de <ApiLink type="{ComponentName}" />. Esto es válido tanto para la edición de celdas como para la edición de filas.
</DocsAside>

### Edición al estilo de Excel de {ComponentTitle}


Con la edición al estilo de Excel, el usuario puede desplazarse por las celdas como lo haría en Excel, y editarlas muy rápidamente.

Para implementar esta funcionalidad personalizada, puede usar los eventos de <ApiLink type="{ComponentName}" />. Primero nos conectamos a los eventos keydown de la cuadrícula, y desde ahí podemos implementar dos funcionalidades:

<PlatformBlock for="React">
```tsx
const gridRef = useRef<IgrGrid>();
useEffect(() => {
    gridRef.current.addEventListener("keydown", handleKeyDown);
    return () => {
        gridRef.current.removeEventListener("keydown", handleKeyDown);
    };
}, []);
<IgrGrid ref={gridRef} autoGenerate={false} data={nwindData} primaryKey="ProductID">
</IgrGrid>
```

<DocsAside type="info">
Usamos el evento keydown nativo del navegador en lugar del evento sintético onKeyDown de React. Cuando una celda entra en modo de edición y se pulsa la tecla ENTER para pasar a la fila siguiente, la función de edición de la cuadrícula actualiza el valor de la celda y cierra el modo de edición. Como resultado, el elemento input usado para editar se elimina del DOM. Debido a las optimizaciones del sistema de eventos de React, el evento sintético onKeyDown no se propaga hasta la cuadrícula, porque en ese momento el elemento ya no existe en el árbol de React. Por tanto, es necesario usar el listener de evento nativo para garantizar el comportamiento esperado.
</DocsAside>

</PlatformBlock>

```typescript
public keydownHandler(event) {
  const key = event.keyCode;
  const grid = this.grid;
  const activeElem = grid.navigation.activeNode;

  if ((key >= 48 && key <= 57) ||
      (key >= 65 && key <= 90) ||
      (key >= 97 && key <= 122)) {
        // Number or Alphabet upper case or Alphabet lower case
        const columnName = grid.getColumnByVisibleIndex(activeElem.column).field;
        const cell = grid.getCellByColumn(activeElem.row, columnName);
        if (cell && !grid.crudService.cellInEditMode) {
            grid.crudService.enterEditMode(cell);
            cell.editValue = event.key;
        }
    }
}
```

```typescript
function handleKeyDown(event: KeyBoardEvent) {
    const code = event.code;
    const grid = event.currentTarget as IgrGrid;
    const activeElem = grid.selectedCells[0];

    if ((event.code >= "Digit0" && event.code <= "Digit9") || (event.code >= "KeyA" && event.code <= "KeyZ")
        || (event.code >= "Numpad0" && event.code <= "Numpad9" && event.code !== "Enter" && event.code !== "NumpadEnter")) {
        if (activeElem && !activeElem.editMode) {
            activeElem.editMode = true;
            activeElem.editValue = event.key;
        } else if (activeElem && activeElem.editMode) {
            event.preventDefault();
            activeElem.editValue = activeElem.editValue + event.key;
        }
    }
}
```

- Modo de edición constante: al escribir mientras una celda está seleccionada, se entra de inmediato en el modo de edición con el valor escrito, reemplazando el existente
- Las filas que no son de datos se omiten al navegar con <kbd>ENTER</kbd>/<kbd>SHIFT</kbd> + <kbd>ENTER</kbd>. Así, los usuarios pueden recorrer rápidamente sus valores.

</ComponentBlock>

<PlatformBlock for="Angular">
<ApiLink type="{ComponentName}" /> permite dar estilo a sus celdas mediante la [{ProductName} Theme Library](../themes/styles.mdx). La propiedad <ApiLink type="function-grid-theme" label="theme" kind="sass" module="index.html" /> de la cuadrícula expone una amplia gama de propiedades, que permiten dar estilo a muchos aspectos distintos de la cuadrícula.

En los pasos siguientes veremos cómo dar estilo a la celda de la cuadrícula en modo de edición y cómo limitar el alcance de esos estilos.

Para usar la [Ignite UI Theming Library](../themes/styles.mdx), primero debemos importar el archivo `index` del tema en nuestros estilos globales:


### Importar la biblioteca de estilos

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to {ProductName} version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Ahora podemos usar todas las funciones que expone el motor de temas {ProductName}.

### Definir una paleta

Una vez importado correctamente el archivo index, creamos una paleta personalizada que podemos usar. Definamos dos colores que nos gusten y usémoslos para crear una paleta con [igx-palette](../themes/palettes.mdx):

```scss
$white: #fff;
$blue: #4567bb;

$color-palette: palette($primary: $white, $secondary: $blue);
```

### Definir temas

Ahora podemos definir el tema usando nuestra paleta. Las celdas se estilan mediante <ApiLink type="function-grid-theme" label="grid-theme" kind="sass" module="index.html" />, así que podemos usarlo para generar un tema para nuestro <ApiLink type="{ComponentName}" />:

```scss
$custom-grid-theme: grid-theme(
    $cell-editing-background: $blue,
    $cell-edited-value-color: $white,
    $cell-active-border-color: $white,
    $edit-mode-color: color($color-palette, "secondary", 200)
);
```

### Aplicar el tema

La forma más sencilla de aplicar nuestro tema es con una instrucción `sass` `@include` en el archivo de estilos globales:

```scss
@include grid($custom-grid-theme);
```

De este modo, el tema se aplicará a **todas** las cuadrículas de nuestra aplicación. Si queremos aplicar este estilo personalizado solo a un componente concreto, debemos acotar el tema.

### Tema acotado al componente

Para que el tema personalizado afecte solo a nuestro componente concreto, podemos mover todos los estilos que acabamos de definir del archivo de estilos globales al archivo de estilos de nuestro componente personalizado (incluida la [importación](#importing-style-library) del archivo `index`).

Así, gracias a la [ViewEncapsulation](https://angular.io/api/core/Component#encapsulation) de {Platform}, nuestros estilos se aplicarán solo a nuestro componente personalizado.

 <DocsAside type="info">
 Si el componente usa un ViewEncapsulation [Emulated](../themes/styles.mdx#view-encapsulation), es necesario atravesar esa encapsulación con `::ng-deep` para dar estilo a la cuadrícula.
 </DocsAside>

 <DocsAside type="info">
 Envolvemos la instrucción dentro de un selector `:host` para evitar que nuestros estilos afecten a elementos fuera de nuestro componente:
 </DocsAside>

```scss
:host {
    ::ng-deep {
            @include grid($custom-grid-theme);
        }
    }
}
```
