# Adición de filas de {Platform} {ComponentTitle}

<ComponentBlock for="Grid, HierarchicalGrid">
La función de adición de filas de {ProductName} en {Platform} {ComponentTitle} permite a los usuarios introducir y enviar nuevos registros de datos sin navegar a un formulario o una página aparte. Con <ApiLink type="{ComponentName}" />, los usuarios pueden manipular los datos mediante la adición de filas en línea y una potente API para operaciones CRUD.
Añada un componente <ApiLink type="ActionStrip" /> con las acciones de edición habilitadas en la plantilla de la cuadrícula. Después, pase el cursor sobre una fila y use el botón proporcionado. Por último, pulse <kbd>ALT</kbd> + <kbd>+</kbd> para mostrar la interfaz de adición de filas.

</ComponentBlock>

<ComponentBlock for="TreeGrid">

> **Nota**:
> Establecer una clave principal es obligatorio para las operaciones de adición de filas.

> **Nota**:
> De forma predeterminada, todas las columnas, excepto la de clave principal, son editables en la interfaz de adición de filas. Si desea deshabilitar la edición de una columna concreta, debe establecer la entrada <ApiLink type="Column" member="editable" /> de esa columna en `false`.

<ComponentBlock for="Grid, HierarchicalGrid">
> **Nota**:
> La entrada <ApiLink type="GridEditingActions" /> que controla la visibilidad del botón de añadir fila puede usar el contexto de la tira de acciones (de tipo <ApiLink type="RowType" />) para ajustar los registros para los que se muestra el botón.

</ComponentBlock>

<ComponentBlock for="TreeGrid">
> **Nota**:
> Las entradas <ApiLink type="GridEditingActions" /> que controlan la visibilidad de los botones de añadir fila y añadir hijo pueden usar el contexto de la tira de acciones (de tipo <ApiLink type="RowType" />) para ajustar los registros para los que se muestran los botones.

</ComponentBlock>

El `BaseTransactionService` interno se proporciona automáticamente para <ApiLink type="{ComponentName}" />. Guarda los cambios pendientes de celdas hasta que el estado de la fila se envía o se cancela.

## Iniciar la adición de filas mediante programación

<ApiLink type="{ComponentName}" /> permite mostrar mediante programación la interfaz de añadir fila usando dos métodos públicos distintos. Uno acepta un ID de fila para especificar la fila debajo de la que debe mostrarse la interfaz, y otro funciona por índice. Puede usar estos métodos para mostrar la interfaz en cualquier punto de la vista de datos actual. No se admite cambiar de página ni especificar una fila que, por ejemplo, esté filtrada.

<ComponentBlock for="Grid, HierarchicalGrid">
Al usar <ApiLink type="{ComponentName}" member="beginAddRowById" /> debe especificar la fila que se usará como contexto de la operación mediante su `RowID` (PK). El método funciona como si el usuario final hubiera hecho clic en el botón de acción de añadir fila de la fila indicada, mostrando la interfaz debajo de ella. También puede hacer que la interfaz aparezca como la primera fila de la cuadrícula pasando `null` como primer parámetro.

<PlatformBlock for="WebComponents">
```typescript
this.grid.beginAddRowById('ALFKI');  // Spawns the add row UI under the row with PK 'ALFKI'
this.grid.beginAddRowById(null);     // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="React">
```typescript
gridRef.current.beginAddRowById('ALFKI');  // Spawns the add row UI under the row with PK 'ALFKI'
gridRef.current.beginAddRowById(null);     // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="Blazor">
```razor
@code {
    await this.grid.BeginAddRowByIdAsync('ALFKI', false);  // Spawns the add row UI under the row with PK 'ALFKI'
    await this.grid.BeginAddRowByIdAsync(null, false);     // Spawns the add row UI as the first record
}
```
</PlatformBlock>

El método <ApiLink type="{ComponentName}" member="beginAddRowByIndex" /> funciona de forma parecida, pero requiere especificar el índice en el que debe aparecer la interfaz. Los valores permitidos van de 0 al tamaño de la vista de datos menos 1.

<PlatformBlock for="WebComponents">
```typescript
this.grid.beginAddRowByIndex(10);   // Spawns the add row UI at index 10
this.grid.beginAddRowByIndex(0);    // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="React">
```typescript
gridRef.current.beginAddRowByIndex(10);   // Spawns the add row UI at index 10
gridRef.current.beginAddRowByIndex(0);    // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="Blazor">
```razor
@code {
    await this.grid.BeginAddRowByIndexAsync(10);   // Spawns the add row UI at index 10
    await this.grid.BeginAddRowByIndexAsync(0);    // Spawns the add row UI as the first record
}
```
</PlatformBlock>

</ComponentBlock>

<ComponentBlock for="TreeGrid">
Al usar <ApiLink type="{ComponentName}" member="beginAddRowById" /> debe especificar la fila que se usará como contexto de la operación mediante su `RowID` (PK). El método funciona como si el usuario final hubiera hecho clic en el botón de acción de añadir fila de la fila indicada, mostrando la interfaz debajo de ella. El segundo parámetro controla si la fila se añade como hija de la fila de contexto o como hermana. También puede hacer que la interfaz aparezca como la primera fila de la cuadrícula pasando `null` como primer parámetro.

<PlatformBlock for="WebComponents">
```typescript
this.treeGrid.beginAddRowById('ALFKI', true);   // Spawns the add row UI to add a child for the row with PK 'ALFKI'
this.treeGrid.beginAddRowById(null);            // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="Blazor">
```razor
@code {
    await this.treeGrid.BeginAddRowByIdAsync('ALFKI', true);  // Spawns the add row UI to add a child for the row with PK 'ALFKI'
    await this.treeGrid.BeginAddRowByIdAsync(null, false);     // Spawns the add row UI as the first record
}
```
</PlatformBlock>

El método <ApiLink type="{ComponentName}" member="beginAddRowByIndex" /> funciona de forma similar, pero la fila que se usará como contexto se especifica por índice.

## Posicionamiento

- La posición predeterminada de la interfaz de adición de filas es debajo de la fila en la que el usuario final hizo clic en el botón de añadir fila.

- <ApiLink type="{ComponentName}" /> se desplaza automáticamente para mostrar por completo la interfaz de añadir fila.

- La superposición de la interfaz de añadir fila mantiene su posición durante el desplazamiento.

## Comportamiento

La interfaz de añadir fila tiene el mismo comportamiento que la de edición de filas, ya que están diseñadas para ofrecer una experiencia de edición coherente a los usuarios finales. Consulte el tema [{ComponentTitle} Row Editing](row-editing.mdx) para más información.

Después de añadir una nueva fila a través de la interfaz de adición de filas, su posición o visibilidad se determina según el estado de ordenación, filtrado y agrupación de <ApiLink type="{ComponentName}" />. En un <ApiLink type="{ComponentName}" /> que no tiene ninguno de estos estados aplicados, aparece como el último registro. Se muestra brevemente un snackbar con un botón que el usuario final puede usar para desplazar <ApiLink type="{ComponentName}" /> hasta su posición si no está a la vista.

## Navegación por teclado

- <kbd>ALT</kbd> + <kbd>+</kbd>: entra en el modo de edición para añadir una fila

<ComponentBlock for="TreeGrid">
- <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>+</kbd>: entra en el modo de edición para añadir un hijo

</ComponentBlock>
- <kbd>ESC</kbd> sale del modo de adición de filas sin enviar ningún cambio

- <kbd>TAB</kbd> mueve el foco de una celda editable de la fila a la siguiente, y desde la celda editable más a la derecha a los botones CANCEL y DONE. La navegación desde el botón DONE va a la celda editable más a la izquierda de la fila que se está editando.

## Integración de funciones

- Cualquier operación de adición de filas se detendrá si cambia la vista de datos de <ApiLink type="{ComponentName}" />. Los cambios realizados por el usuario final se envían. Las operaciones que cambian la vista de datos incluyen, entre otras, la ordenación, la agrupación, el filtrado, la paginación, etc.

- Los resúmenes se actualizan después de terminar la operación de añadir fila. Lo mismo ocurre con las demás funciones que dependen de la vista de datos, como la ordenación, el filtrado, etc.

<ComponentBlock for="HierarchicalGrid">
- Al mostrar la interfaz de <ApiLink type="{ComponentName}" />, cualquier diseño hijo que esté expandido para una fila en la que el usuario final haga clic en el botón de añadir fila se contrae.

## Escenarios remotos

En la mayoría de los escenarios de datos remotos, la asignación de la clave primaria se produce en la solicitud de creación al servidor. En este caso, los registros añadidos en el cliente no tendrán el valor final de la clave primaria hasta que se guarden en la base de datos del servidor. En ese caso, la forma recomendada de gestionar esta actualización en <ApiLink type="{ComponentName}" /> es la siguiente:

- Si <ApiLink type="{ComponentName}" /> no usa transacciones.

    Cuando la solicitud de creación se completa correctamente y devuelve los datos del registro añadido, puede reemplazar el id de ese registro en la instancia de registro de datos local.

- Si <ApiLink type="{ComponentName}" /> usa transacciones.

    Cuando la solicitud de creación o de actualización por lotes se completa correctamente y devuelve las instancias de registro añadidas (con sus ids generados por la base de datos), las transacciones ADD relacionadas deben borrarse del registro de transacciones usando el método de la API `Clear`. Esto es necesario porque la transacción local tendrá un campo id generado, que puede ser distinto del creado en la base de datos, así que deben borrarse. Después puede añadir el registro o registros incluidos en la respuesta a la instancia de datos local.

Así se garantiza que los ids generados de forma remota siempre se reflejen en los datos locales, y que las operaciones posteriores de actualización o eliminación apunten a los ids de registro correctos.
</PlatformBlock>
