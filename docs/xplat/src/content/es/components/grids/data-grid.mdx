## Uso

Ahora que hemos importado los paquetes de la cuadrícula, empecemos con la configuración básica y enlacemos datos locales:

<PlatformBlock for="Blazor">

```razor

```

</PlatformBlock>

<PlatformBlock for="Angular">

```html

```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html

```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```typescript
constructor() {
    let grid1 = document.getElementById("grid1") as IgcGridComponent;
    grid1.data = data;

```

</PlatformBlock>

<PlatformBlock for="React">


</PlatformBlock>

La propiedad <ApiLink type="Grid" member="id" label="Id" /> es un valor de cadena y es el identificador único de la cuadrícula, que se generará automáticamente si no se proporciona, mientras que <ApiLink type="Grid" member="data" label="data" /> enlaza la cuadrícula, en este caso, a datos locales.

La propiedad <ApiLink type="GridBaseDirective" member="autoGenerate" label="AutoGenerate" /> indica a la cuadrícula que genere automáticamente los componentes <ApiLink type="Column" /> de la cuadrícula a partir de los campos del origen de datos. También intentará deducir el tipo de datos adecuado para la columna, si es posible. En caso contrario, el desarrollador debe definir explícitamente las columnas y la correspondencia con los campos del origen de datos.

## Definición de cuadrícula Bootstrap

{ProductName} incluye un potente sistema de disposición basado en flex, similar a una cuadrícula Bootstrap. Se espera que cualquier aplicación moderna siga un enfoque de diseño web adaptable, lo que significa que puede ajustar con elegancia la disposición de los elementos HTML según el tamaño del dispositivo o simplemente al redimensionar el navegador. En el pasado, la disposición de cuadrícula Bootstrap era el enfoque más utilizado, pero un sistema de disposición basado en flex, como CSS grid, se ha vuelto más popular, ya que funciona en cualquier navegador. La directiva de disposición {ProductName} permite el flujo vertical y horizontal, incluido el ajuste de contenido y texto, la justificación y la alineación. La cuadrícula de {ProductName} admite una disposición adaptable mediante CSS, lo que le proporciona la máxima flexibilidad en cuanto al comportamiento de la cuadrícula al redimensionarla.


</PlatformBlock>


## Cuadrícula editable de {Platform}

Cada operación de edición de la cuadrícula incluye operaciones por lotes, lo que significa que la API le permite agrupar las ediciones en una única llamada al servidor, o bien realizar las operaciones de edición o actualización de la cuadrícula a medida que se producen las interacciones con ella. Junto con una gran experiencia de desarrollo como cuadrícula editable con operaciones CRUD, la cuadrícula incluye navegación por teclado al estilo de Excel. Se incluye la navegación habitual de la cuadrícula, además de la opción de sustituir cualquier opción de navegación para satisfacer las necesidades de sus clientes. Una cuadrícula editable con un buen esquema de navegación es fundamental para cualquier aplicación empresarial moderna; con la cuadrícula de Ignite UI, lo hacemos sencillo.

En este tema aprenderá más sobre la [plantilla de celda](./data-grid.mdx#plantilla-de-celda) y la [plantilla de edición de celdas](./data-grid.mdx#plantilla-de-edición-de-celdas), y sobre la edición.

### Plantilla de celda

Cuando se establece una plantilla de celda, cambia todas las celdas de la columna. El objeto de contexto proporcionado en la plantilla consta del valor de la celda proporcionado implícitamente y del propio objeto de celda. Puede usarse para definir una plantilla en la que el texto de las celdas se dé formato, por ejemplo, con mayúscula inicial en cada palabra.

```typescript
public nameCellTemplate = (ctx: IgcCellTemplateContext) => {
    return html`
```

<PlatformBlock for="Angular">



Cuando se cambian datos a través de la **plantilla de celda** usando `ngModel`, hay que llamar a los métodos de la API adecuados para asegurarse de que el valor se actualiza correctamente en la colección de datos subyacente de la cuadrícula de Angular. En el fragmento anterior, la llamada `ngModelChange` pasa por la [API de edición](./_shared/cell-editing.mdx#editing-through-api) de la cuadrícula y por su cadena de edición, desencadenando correctamente las [transacciones](./_shared/batch-editing.mdx) (si procede) y gestionando los [resúmenes](./_shared/summaries.mdx), la [selección](./_shared/selection.mdx), etc. Sin embargo, este `ngModelChange` se disparará cada vez que cambie el valor de la celda, no solo cuando el usuario termine de editar, lo que genera muchas más llamadas a la API.


</PlatformBlock>


> **Nota**:
> La cuadrícula expone un tratamiento predeterminado para los tipos de columna number, string, date y boolean. Por ejemplo, para el tipo de columna boolean, la columna mostrará de forma predeterminada el icono `check` o `close`, en lugar de true/false.


<PlatformBlock for="Angular">



Si los datos de una celda están enlazados con `[(ngModel)]` y no se gestiona el cambio de valor, el nuevo valor **no** se actualizará correctamente en el origen de datos subyacente de la cuadrícula de Angular. ### Formato de visualización personalizado

Hay parámetros opcionales para el formato:

- <ApiLink type="ColumnPipeArgs" member="format" label="Format" />: determina qué partes de fecha/hora se muestran; por defecto es `'mediumDate'`, equivalente a **'MMM d, y'**

Una buena práctica es separar toda la lógica relacionada con la obtención de datos en un servicio de datos independiente, así que vamos a crear un servicio que se encargue de obtener los datos del servidor.

Implementemos nuestro servicio en un archivo aparte

```typescript
// northwind.service.ts

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs/Observable';
import { of } from 'rxjs/observable/of';
import { catchError, map } from 'rxjs/operators';
```

Estamos importando el decorador `Injectable`, que es un [ingrediente esencial](https://angular.io/guide/dependency-injection) en cada definición de servicio {Platform}. El `HttpClient` nos proporcionará la funcionalidad para comunicarnos con los servicios de backend. Devuelve un `Observable` de algún resultado al que nos suscribiremos en nuestro componente de cuadrícula.

**Nota**: antes de Angular 5, `HttpClient` se encontraba en `@angular/http` y se llamaba `Http`.

Como vamos a recibir una respuesta JSON que contiene un array de registros, podemos ayudarnos especificando qué tipo de datos esperamos recibir en el observable, definiendo una interfaz con la forma correcta. La comprobación de tipos siempre es recomendable y puede ahorrarle dolores de cabeza más adelante.

```typescript
// northwind.service.ts

export interface NorthwindRecord {
    ProductID: number;
    ProductName: string;
    SupplierID: number;
    CategoryID: number;
    QuantityPerUnit: string;
    UnitPrice: number;
    UnitsInStock: number;
    UnitsOnOrder: number;
    ReorderLevel: number;
    Discontinued: boolean;
    CategoryName: string;
}
```

El servicio en sí es bastante sencillo y consta de un método: `FetchData`, que devolverá un `Observable<NorthwindRecord[]>`. Si la petición falla por cualquier motivo (servidor no disponible, error de red, etc.), el `HttpClient` devolverá un error. Aprovecharemos el operador `CatchError`, que intercepta un Observable que ha fallado y pasa el error a un controlador de errores. Nuestro controlador de errores registrará el error y devolverá un valor seguro.

```typescript
// northwind.service.ts

@Injectable()
export class NorthwindService {
    private url = 'http://services.odata.org/V4/Northwind/Northwind.svc/Alphabetical_list_of_products';

    constructor(private http: HttpClient) {}

    public fetchData(): Observable<NorthwindRecord[]> {
        return this.http
            .get(this.url)
            .pipe(
                map(response => response['value']),
                catchError(
                    this.errorHandler('Error loading Northwind data', [])
                )
            );
    }

    private errorHandler<T>(message: string, result: T) {
        return (error: any): Observable<any> => {
            console.error(`${message}: ${error.message}`);
            return of(result as T);
        };
    }
}
```

Asegúrese de importar tanto `HttpClientModule` como nuestro servicio en el módulo de la aplicación y de registrar el servicio como proveedor.

```typescript
// app.module.ts

import { HttpClientModule } from '@angular/common/http';
import { NorthwindService } from './northwind.service';

@NgModule({
    imports: [
        HttpClientModule
    ],
    providers: [
        NorthwindService
    ]
})
export class AppModule {}
```

Después de implementar el servicio, lo inyectaremos en el constructor de nuestro componente y lo usaremos para recuperar los datos. El hook de ciclo de vida `ngOnInit` es un buen lugar para lanzar la solicitud inicial.

**Nota**: en el código siguiente puede preguntarse por qué establecemos la propiedad _records_ en un array vacío antes de suscribirnos al servicio. La solicitud Http es asíncrona, y hasta que se completa, la propiedad _records_ será _undefined_, lo que provocará un error cuando el grid intente enlazarse a ella. Debe inicializarla con un valor predeterminado o usar un `BehaviorSubject`.

```typescript
// my.component.ts

@Component({

})
export class MyComponent implements OnInit {

    public records: NorthwindRecord[];

    constructor(private northwindService: NorthwindService) {}

    ngOnInit() {
        this.records = [];
        this.northwindService.fetchData().subscribe((records) => this.records = records);
    }
}
```

y en la plantilla del componente:

```html
    <igx-grid [data]="records">
        <igx-column field="ProductId"></igx-column>
        <!-- rest of the column definitions -->
    </igx-grid>
```

</PlatformBlock>

Supone que los datos están disponibles para inspeccionarlos y generar las columnas adecuadas. Normalmente esto no ocurre hasta que responde el servicio remoto, y el grid lanzará un error. Hacer que <ApiLink type="GridBaseDirective" member="autoGenerate" label="AutoGenerate" /> esté disponible al enlazar con un servicio remoto está previsto para versiones futuras.

## Rendimiento (experimental)

El diseño de <ApiLink type="GridToolbar" member="grid" label="Grid" /> le permite aprovechar la función de fusión de eventos (Event Coalescing) que introdujo Angular. Esta función mejora el rendimiento, con una mejora de aproximadamente **20 %** en interacciones y capacidad de respuesta. Esta función puede habilitarse a nivel de aplicación simplemente estableciendo las propiedades `ngZoneEventCoalescing` y `ngZoneRunCoalescing` en **true** en el método `bootstrapModule`:

```typescript
platformBrowserDynamic()
  .bootstrapModule(AppModule, { ngZoneEventCoalescing: true, ngZoneRunCoalescing: true })
  .catch(err => console.error(err));
```

<DocsAside type="info">
Esta función sigue siendo experimental para `IgxGridComponent`. Esto significa que podrían producirse comportamientos inesperados en el Grid. Si encuentra alguno de esos comportamientos, póngase en contacto con nosotros en nuestra página de [GitHub]({GithubLink}/discussions).
</DocsAside>

<DocsAside type="info">
Habilitarla puede afectar a otras partes de una aplicación Angular que no están relacionadas con `IgxGridComponent`.
</DocsAside>

En [**Angular**](https://angular.io/) la mayoría de los estilos reciben prefijos de forma implícita gracias al plugin [Autoprefixer](https://www.npmjs.com/package/autoprefixer).

Sin embargo, para añadir prefijos a las **disposiciones de grid** debe activar la [propiedad grid](https://www.npmjs.com/package/autoprefixer) de **Autoprefixer** con el comentario ```autoprefixer grid:on```.

Para facilitarle el trabajo, aplique el comentario en el archivo `src/styles.scss`.

```scss
// src/styles.scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
@include core();
/* autoprefixer grid:on */
@include theme($default-palette);
```

## Limitaciones conocidas

|Limitación|Descripción|
|--- |--- |
|Anchos de columna establecidos en `percentage` y `px`|Actualmente no admitimos mezclar anchos de columna con `%` y `px`.|
|Al intentar filtrar una columna de tipo `number`|Si en el campo de filtrado se introduce un valor distinto de `number`, se devuelve `NaN` debido a una conversión incorrecta.|
|El `width` del grid no depende de los anchos de columna | El `width` de todas las columnas no determina la extensión del propio grid. Esta viene determinada por las dimensiones del contenedor padre o por el `width` definido para el grid.|
|Grid anidado en un contenedor padre | Cuando no se establece el `width` del grid y se coloca en un contenedor padre con dimensiones definidas, el grid se extiende a ese contenedor.|
| Las columnas tienen un ancho mínimo permitido. Según la variable CSS `--ig-size`, son los siguientes: <br/>"small": 56px <br/> "medium": 64px <br/> "large ": 80px | Si se establece un ancho inferior al mínimo permitido, no afectará a los elementos renderizados. Se renderizarán con el ancho mínimo permitido para el `--ig-size` correspondiente. Esto puede provocar un comportamiento inesperado con la virtualización horizontal, por lo que no se admite.
| La altura de la fila no se ve afectada por la altura de las celdas que no están renderizadas actualmente en la vista. | Debido a la virtualización, una columna con plantilla personalizada (que cambia la altura de la celda) que no está en la vista no afectará a la altura de la fila. La altura de la fila solo se verá afectada mientras la columna correspondiente esté desplazada a la vista.
