# Paginación de cuadrícula/tabla {Platform}

Las interfaces de tabla tabulares se usan habitualmente en muchos productos web. Crear una interfaz de tabla desde cero no es fácil; sin embargo, con la cuadrícula {ProductName}, crear una interfaz de tabla es sencillo, y enlazar grandes cantidades de datos locales o remotos a la cuadrícula {Platform} es fácil. Como la cuadrícula está virtualizada de forma predeterminada, no es necesario incluir paginación de tabla para mostrar grandes conjuntos de datos. Se utiliza principalmente porque es la forma más eficiente de organizar datos complejos en la interfaz. Con la paginación de tabla, los datos pueden mostrarse en un número fijo de filas, permitiendo que los usuarios "se desplacen" por sus datos, sin necesidad de una barra de desplazamiento. La interfaz de paginación de tabla suele incluir elementos como la página actual, el total de páginas y las flechas o botones Anterior y Siguiente en los que se puede hacer clic para pasar de página, como se muestra aquí:

La paginación de filas se habilita en la tabla / cuadrícula de datos {ProductName} estableciendo la propiedad `IsPagerVisible`. Además, puede limitar el número máximo de filas visibles estableciendo `PageSize`.

## Descripción general

Desde el punto de vista de la experiencia de usuario, la paginación de tabla tiene ventajas e inconvenientes. Según un [artículo reciente](https://www.uxmatters.com/mt/archives/2018/11/paging-scrolling-and-infinite-scroll.php) de UX Matters, este es un desglose de los aspectos buenos y malos de la paginación de tabla.

Ventajas de la paginación de tabla:

- Limita la elección del usuario
- Los clics son medibles

Inconvenientes de la paginación de tabla:

- Los usuarios aún tienen que desplazarse
- Los paginadores funcionan y se comportan de forma diferente de un sitio a otro
- Demasiados controles de interfaz pueden resultar confusos
- Los usuarios perciben la paginación como lenta y engorrosa
- Es posible que los usuarios no vean los controles de paginación
- La carga de páginas puede ser lenta
- Los usuarios no saben si las acciones se aplican a la página o a todo el conjunto de datos

Con la cuadrícula de datos {ProductName} puede añadir paginación. Sin embargo, como la cuadrícula de datos tiene desplazamiento infinito integrado de forma predeterminada, recomendamos el desplazamiento infinito (o virtual) en lugar de añadir un paginador. Con la experiencia de usuario predeterminada de desplazamiento infinito virtualizado, obtiene:

- El mejor rendimiento, manteniendo el control sobre cuántos datos se "paginan" mediante la interacción de desplazamiento
- Un enfoque natural para desplazarse por todo el contenido
- Todas las interacciones son claras para el usuario final
- Se corresponde con las interacciones naturales de la experiencia de usuario móvil

## Sincronización de cuadrícula/página de {Platform}

Cuando los usuarios interactúan con la cuadrícula, por ejemplo, ordenando o agrupando, y ha habilitado el paginador {Platform} en la cuadrícula, debe usar las siguientes funciones para asegurarse de que los datos de la paginación {Platform} estén sincronizados con la visualización de la tabla {Platform}.

- applySorts
- applyGroups
- applyFilters
