# Treemap de {Platform}

El gráfico Treemap de {ProductName} muestra datos jerárquicos (con estructura de árbol) como un conjunto de nodos anidados. A cada rama del árbol se le asigna un nodo de treemap, que a su vez se divide en nodos más pequeños que representan las subramas. El rectángulo de cada nodo tiene un área proporcional a una dimensión especificada de los datos. A menudo, los nodos se colorean para mostrar una dimensión distinta de los datos.

## Recomendaciones para el Treemap

### ¿Son los Treemaps de {Platform} adecuados para su proyecto?

Cuando las dimensiones de color y de tamaño están correlacionadas de algún modo con la estructura del árbol, a menudo se pueden ver patrones que serían difíciles de detectar de otra forma. Una segunda ventaja de los treemaps es que, por construcción, aprovechan el espacio de forma eficiente. Como resultado, pueden mostrar legiblemente miles de elementos en pantalla al mismo tiempo.

- Los treemaps son más eficaces que los gráficos circulares y otros tipos de gráficos de áreas, que a menudo clasifican mal los puntos de datos y comunican mal las diferencias relativas entre sus valores.
- Los treemaps están diseñados para escenarios de exploración detallada (drill-down). Puede profundizar continuamente en el conjunto de datos representado por rectángulos más pequeños para realizar un análisis de datos más eficiente.
- Los treemaps no están diseñados para transmitir cantidades numéricas; su objetivo es mostrar clasificaciones relativas.

Como cualquier otra visualización de datos, un gráfico Treemap debe usarse en escenarios concretos. No resuelve el mismo problema que una visualización como un Bar Chart o un Line Chart. Está pensado para una visualización de datos más compleja y rica.

### Casos de uso del Treemap

Hay varios casos de uso habituales para elegir un Treemap. Cuando:

- Tiene datos jerárquicos para explorar en detalle (datos organizados como un árbol, con ramas y subramas).
- Quiere ilustrar jerarquías de peso relativo y valores comparativos entre categorías (ramas) y subcategorías (subramas).
- Quiere mostrar grandes conjuntos de datos que necesitan una visualización compacta y eficiente en cuanto al espacio.
- Quiere ofrecer un análisis de datos rápido de un vistazo, sin valores precisos. El tamaño relativo de los rectángulos ayuda a identificar patrones o valores atípicos muy rápidamente.
- Quiere aprovechar el espacio de forma eficiente. Los treemaps pueden mostrar legiblemente miles de elementos en pantalla al mismo tiempo.

### Cuándo no usar un Treemap

- Está contando una historia con datos que requiere valores precisos
- Tiene valores de datos negativos
- Tiene datos planos, no jerárquicos
- Sus datos son de tamaño similar

### Estructura de datos del Treemap

- El origen de datos debe ser un array o una lista de elementos de datos
- El origen de datos debe contener al menos un elemento de datos; de lo contrario, el mapa no representará ningún nodo.
- Todos los elementos de datos deben contener al menos una columna de datos (por ejemplo, de cadena) que debe asignarse a la propiedad `labelMemberPath`.
- Todos los elementos de datos deben contener al menos una columna de datos numérica que debe asignarse mediante la propiedad `valueMemberPath`.
- Para clasificar los datos en mosaicos organizados, puede usar opcionalmente `parentIdMemberPath` y `idMemberPath`.

### Tipos de disposición

El gráfico Treemap muestra el peso relativo de los datos. Usa diversos algoritmos para determinar cómo debe producirse la disposición de sus elementos de datos:

- `SliceAndDice`: el algoritmo de disposición busca conservar el orden inicial a costa de la relación de aspecto.
- `Squarified`: el algoritmo de mosaico tiene una mejor relación de aspecto que `SliceAndDice` y conserva mejor el orden que Squarified.
- `Stripped`: el tipo de disposición obtiene la mejor relación de aspecto, pero los objetos se ordenan por tamaño.

El Treemap le permite elegir el algoritmo que mejor se adapte a sus requisitos, y usa de forma predeterminada el método Squarified. También incluye la posibilidad de colorear los nodos mediante dos mecanismos:

- Un mecanismo basado en grupos que colorea los elementos con valores similares
- Un mecanismo basado en escalas, similar a un coropleta de mapa, que asigna colores a los nodos según su valor.

### Orientación de la disposición

La propiedad `layoutOrientation` permite al usuario establecer la dirección en la que se expanden los nodos de la jerarquía.

Tenga en cuenta que la propiedad `layoutOrientation` funciona con los tipos de disposición SliceAndDice y Strip.

- `Horizontal`: los nodos hijos se apilan horizontalmente (SliceAndDice).
- `Vertical`: los nodos hijos se apilan verticalmente (SliceAndDice).

## Resaltado basado en porcentajes del Treemap de {Platform}

- `highlightedDataSource`: especifica el origen de datos del que se leen los valores resaltados. Si es null, los valores resaltados se leen de la propiedad ItemsSource.
- `highlightedValueMemberPath`: especifica el nombre de la propiedad del origen de datos donde se leen los valores resaltados.
- `highlightedValueOpacity`: controla la opacidad del valor normal situado detrás del valor resaltado.
- `highlightedValuesDisplayMode`: habilita o deshabilita los valores resaltados.
  - Auto: el treemap decide qué modo usar.
  - Overlay: el treemap muestra los valores resaltados sobre el valor normal, aplicando al valor normal una ligera opacidad.
  - Hidden: el treemap no muestra los valores resaltados.
