# Rendimiento de gráficos de {Platform}

Los gráficos {Platform} están optimizados para un renderizado de alto rendimiento de millones de puntos de datos y para actualizarlos cada pocos milisegundos. Sin embargo, hay varias características del gráfico que afectan al rendimiento del gráfico y deben tenerse en cuenta al optimizar el rendimiento de su aplicación. Este tema le guiará para que los gráficos {Platform} funcionen lo más rápido posible en su aplicación.

## Ejemplos de rendimiento de gráficos de {Platform}

Los siguientes ejemplos muestran dos escenarios de alto rendimiento de los gráficos {Platform}.

## Gráfico {Platform} con alta frecuencia

En el escenario de alta frecuencia, los gráficos {Platform} pueden representar elementos de datos que se actualizan en tiempo real o en intervalos de milisegundos especificados. No notará retrasos, parpadeos de pantalla ni demoras visuales, incluso al interactuar con el gráfico en un dispositivo táctil. El siguiente ejemplo muestra el `CategoryChart` en el escenario de alta frecuencia.

En el escenario de gran volumen, los gráficos {Platform} pueden representar 1 millón de puntos de datos mientras el gráfico mantiene un rendimiento fluido cuando el usuario final amplía, reduce o navega por el contenido del gráfico. ## Directrices generales de rendimiento

Esta sección enumera directrices y características de los gráficos que aumentan la sobrecarga y el procesamiento de las actualizaciones en los gráficos {Platform}.

### Tamaño de los datos

Si necesita representar orígenes de datos con un gran número de puntos de datos (por ejemplo, más de 10 000), le recomendamos usar {Platform} `DataChart` con uno de los siguientes tipos de serie, que están diseñados específicamente para ese fin.
<PlatformBlock for="Web">
- [Scatter HD Chart](../types/scatter-chart.mdx#scatter-high-density-chart-de-{PlatformLower}) en lugar de [Category Point Chart](../types/point-chart.mdx) o [Scatter Marker Chart](../types/scatter-chart.mdx#gráfico-de-dispersión-con-marcadores-de-{PlatformLower})</PlatformBlock>
- [Scatter Polyline Chart](../types/shape-chart.mdx#scatter-polyline-chart-de-{PlatformLower}) en lugar de [Category Line Chart](../types/line-chart.mdx#ejemplo-de-gráfico-de-líneas-de-{PlatformLower}) o [Scatter Line Chart](../types/scatter-chart.mdx#scatter-line-chart-de-{PlatformLower})
- [Scatter Polygon Chart](../types/shape-chart.mdx#gráfico-de-dispersión-de-polígonos-de-{PlatformLower}) en lugar de [Category Area Chart](../types/area-chart.mdx#ejemplo-de-gráfico-de-áreas-de-{PlatformLower}) o [Column Chart](../types/column-chart.mdx#ejemplo-de-gráfico-de-columnas-de-{PlatformLower})

### Estructura de los datos

Aunque los gráficos {Platform} admiten la representación de varios orígenes de datos enlazando un array de arrays de puntos de datos a la propiedad `DataSource`, es mucho más rápido en los gráficos aplanar varios orígenes de datos en un único origen de datos en el que cada elemento de datos contenga varias columnas de datos en lugar de solo una. Por ejemplo:

<PlatformBlock for="Xaml">

```csharp
this.CategoryChart.ItemsSource = FlattenDataSource.Create();

public static class FlattenDataSource
{
    public static List<FlattenDataItem> Create() {
        var data = new List<FlattenDataItem>() {
            new FlattenDataItem { Year = "1996", USA = 148, CHN = 110 },
            new FlattenDataItem { Year = "2000", USA = 142, CHN = 115 },
        };
        return data;
    }
    public class FlattenDataItem
    {
        public int USA { get; set; }
        public int CHN { get; set; }
        public string Year { get; set; }
    }
}
// instead of this data structure:
public static class MultiDataSources
{
    public static List<List<MultiDataItem>> Create() {
        var dataSource1 = new List<MultiDataItem>() {
            new MultiDataItem { Year = "1996", Value = 148 },
            new MultiDataItem { Year = "2000", Value = 142 },
        };
        var dataSource2 = new List<MultiDataItem>() {
            new MultiDataItem { Year = "1996", Value = 110 },
            new MultiDataItem { Year = "2000", Value = 115 },
        };
        var multipleSources = new List<List<MultiDataItem>>();
        multipleSources.Add(dataSource1);
        multipleSources.Add(dataSource2);
        return multipleSources;
    }
    public class MultiDataItem
    {
        public int Value { get; set; }
        public string Year { get; set; }
    }
}
```

### Filtrado de datos

{Platform} `CategoryChart`<PlatformBlock for="Web"> y los controles `FinancialChart` tienen</PlatformBlock><PlatformBlock for="WinUI, Uno"> el control tiene</PlatformBlock> un adaptador de datos integrado que analiza sus datos y genera series de gráfico por usted. Sin embargo, funciona más rápido si usa `includedProperties` y `excludedProperties` para filtrar solo las columnas de datos que realmente quiere representar. Por ejemplo,


```json-snippet channel="code"
{
    "$styleOptions": { "qualifyCodeBehindFields": true },
    "skipAlterDataCasing": true,
    "descriptions": {
        "content": {
            "type": "CategoryChart",
            "name": "Chart",
            "includedProperties": [
                "Year",
                "USA",
                "RUS"
            ],
            "$includedProperties": "+perf:code",
            "excludedProperties": [
                "CHN",
                "FRN",
                "GER"
            ],
            "$excludedProperties": "+perf:code"
        }
    }
}
```

### Tipos de gráfico

Los tipos de gráfico más sencillos, como [Line Chart](../types/line-chart.mdx), tienen un rendimiento mayor que [Spline Chart](../types/spline-chart.mdx), debido a la compleja interpolación de las líneas spline entre los puntos de datos. Como alternativa, puede cambiar el tipo de una serie por otra más rápida en el control {Platform} `DataChart`.

### Animaciones del gráfico

Habilitar [Chart Animations](chart-animations.mdx) retrasará ligeramente la representación final de las series en los gráficos {Platform} mientras reproducen las animaciones de entrada.

### Anotaciones del gráfico

Habilitar [Chart Annotations](chart-annotations.mdx), como las anotaciones de llamada, las anotaciones de línea de mira o las anotaciones de valor final, reducirá ligeramente el rendimiento del gráfico {Platform}.

### Resaltado del gráfico

Habilitar [Chart Highlighting](chart-highlighting.mdx) reducirá ligeramente el rendimiento del gráfico {Platform}.

### Leyenda del gráfico

Añadir una leyenda a los gráficos {Platform} puede reducir el rendimiento si los títulos de las series o de los elementos de datos asignados a la leyenda cambian con frecuencia durante la ejecución.

### Marcadores del gráfico

En los gráficos {Platform}, los [Markers](chart-markers.mdx) son especialmente costosos en cuanto al rendimiento del gráfico, porque aumentan la complejidad de la disposición del gráfico y realizan enlace de datos para obtener cierta información. Además, los marcadores reducen el rendimiento cuando hay muchos puntos de datos o cuando hay muchos orígenes de datos enlazados. Por tanto, si no se necesitan marcadores, deben eliminarse del gráfico.

Este fragmento de código muestra cómo eliminar los marcadores de los gráficos {Platform}.

```json-snippet channel="code"
{
    "$styleOptions": { "qualifyCodeBehindFields": true },
    "type": "CategoryChart",
    "name": "Chart",
    "$comments": { "markerTypes": "on CategoryChart or FinancialChart" },
    "markerTypes": [ "None" ],
    "$markerTypes": "+perf:code"
}
```

```json-snippet channel="code"
{
    "$styleOptions": { "qualifyCodeBehindFields": true },
    "type": "DataChart",
    "name": "Chart",
    "series": [
        {
            "type": "LineSeries",
            "name": "LineSeries",
            "$comments": { "markerType": "on LineSeries of DataChart" },
            "markerType": "None",
            "$markerType": "+perf:code"
        }
    ]
}
```


### Resolución del gráfico

Establecer la propiedad `DomainChart.resolution` en un valor más alto mejorará el rendimiento, pero reducirá la fidelidad gráfica de las líneas de las series representadas. Por tanto, puede aumentarse hasta el punto en que la fidelidad resulte inaceptable.

Este fragmento de código muestra cómo reducir la resolución en los gráficos {Platform}.

```json-snippet channel="code"
{
    "$styleOptions": { "qualifyCodeBehindFields": true },
    "type": "CategoryChart",
    "name": "Chart",
    "$comments": { "resolution": "on CategoryChart" },
    "resolution": 10,
    "$resolution": "+perf:code"
}
```

```json-snippet channel="code"
{
    "$styleOptions": { "qualifyCodeBehindFields": true },
    "type": "DataChart",
    "name": "Chart",
    "series": [
        {
            "type": "LineSeries",
            "name": "LineSeries",
            "$comments": { "resolution": "on LineSeries of DataChart" },
            "resolution": 10,
            "$resolution": "+perf:code"
        }
    ]
}
```

### Tipos de ejes

No se recomienda usar un eje X con compatibilidad con fecha y hora si el espacio entre los puntos de datos, basado en el intervalo de tiempo que hay entre ellos, no es importante. En su lugar, debe usarse un eje ordinal o de categoría, porque es más eficiente a la hora de agrupar los datos. Además, el eje ordinal o de categoría no realiza ninguna ordenación de los datos, a diferencia del eje X basado en el tiempo.

<DocsAside type="info">
`CategoryChart` ya usa un eje ordinal o de categoría, por lo que no es necesario cambiar sus propiedades.
</DocsAside>

### Intervalos de los ejes

De forma predeterminada, los gráficos {Platform} calcularán automáticamente `yAxisInterval` según el rango de sus datos. Por tanto, debe evitar establecer el intervalo del eje, sobre todo con un valor pequeño, para no representar demasiadas líneas de cuadrícula y etiquetas del eje. Además, puede que quiera aumentar la propiedad `yAxisInterval` a un valor mayor que el intervalo del eje calculado automáticamente si no necesita muchas líneas de cuadrícula ni etiquetas del eje.

<DocsAside type="info">
No recomendamos establecer el intervalo secundario del eje, ya que reduce el rendimiento del gráfico.

### Escala del eje

Se recomienda establecer la propiedad `yAxisIsLogarithmic` en false para obtener un mayor rendimiento, ya que se necesitan menos operaciones que para calcular el rango del eje y los valores de las etiquetas del eje en escala logarítmica.

## Rendimiento en Financial Chart

Además de las directrices de rendimiento anteriores, el control {Platform} `FinancialChart` tiene las siguientes características únicas que afectan al rendimiento.

### Modo del eje Y

Se recomienda establecer la opción `yAxisMode` en `Numeric` para obtener un mayor rendimiento, ya que se necesitan menos operaciones que con el modo `LineSeries.percentChange`.

### Paneles del gráfico

Establecer muchos paneles con las opciones `indicatorTypes` y `overlayTypes` puede reducir el rendimiento; se recomienda usar algunos indicadores financieros y una superposición financiera.

### Zoom Slider

Establecer la opción `zoomSliderType` en `None` mejorará el rendimiento del gráfico y dejará más espacio vertical para otros indicadores y para el panel de volumen.

### Tipo de volumen

Establecer la propiedad `volumeType` puede tener el siguiente impacto en el rendimiento del gráfico:

- `None`: es el menos costoso, ya que no muestra el panel de volumen.
- `Line`: es un tipo de volumen más costoso de representar, y se recomienda cuando se representan muchos puntos de datos o muchos orígenes de datos.
- `Area`: es más costoso de representar que el tipo de volumen `Line`.
- `Column`: es más costoso de representar que el tipo de volumen `Area`, y se recomienda cuando se representan datos de volumen de 1 a 3 acciones.
</PlatformBlock>
## Rendimiento en Data Chart

Además de las directrices generales de rendimiento, el control {Platform} `DataChart` tiene las siguientes características únicas que afectan al rendimiento.

### Colección de ejes

Añadir demasiados ejes a la colección `Axes` del control `DataChart` reducirá el rendimiento del gráfico, y recomendamos [compartir ejes](chart-axis-layouts.mdx#ejemplo-de-uso-compartido-de-ejes) entre series.

### Colección de series

Además, añadir muchas series a la colección `Series` del control {Platform} `DataChart` añadirá sobrecarga al renderizado, porque cada serie tiene su propio lienzo de representación. Esto es especialmente importante si tiene más de 10 series en Data Chart. Recomendamos combinar varios orígenes de datos en un origen de datos aplanado (véase la sección [Estructura de los datos](#estructura-de-los-datos)) y, después, usar la característica de estilo condicional de las siguientes series:

| Escenario de rendimiento más lento | Escenario más rápido con estilo condicional |
| ----------------------------|---------------------------------------- |
| Más de 10 de `LineSeries`         | `ScatterLineSeries` único |
| Más de 20 de `LineSeries`         | `ScatterPolylineSeries` único |
| Más de 10 de `ScatterLineSeries`  | `ScatterPolylineSeries` único |
| Más de 10 de `PointSeries`        | `ScatterSeries` único |<PlatformBlock for="Web">
| Más de 20 de `PointSeries`        | `HighDensityScatterSeries` único |
| Más de 20 de `ScatterSeries`      | `HighDensityScatterSeries` único |</PlatformBlock>
| Más de 10 de `AreaSeries`         | `ScatterPolygonSeries` único |
| Más de 10 de `ColumnSeries`       | `ScatterPolygonSeries` único |
