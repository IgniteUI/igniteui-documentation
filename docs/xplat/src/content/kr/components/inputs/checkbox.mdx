# {Platform} 체크박스 컴포넌트

{Platform} 체크박스는 {Platform} 앱에 체크박스를 추가할 수 있게 해 주는 컴포넌트입니다. 표준 HTML 체크박스처럼 동작하여, 사용자가 기본적인 선택 및 해제 상태 또는 추가로 불확정 상태를 선택할 수 있습니다. 또한 {Platform} 체크박스 컴포넌트의 스타일을 완전히 제어할 수 있으며 폼과 함께 사용할 수 있습니다.

## 시작하기

{Platform} 체크박스를 사용하려면  <PlatformBlock for="Angular">[{ProductName} 시작하기](../general/getting-started.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[{ProductName} 시작하기](../general-getting-started.mdx)</PlatformBlock> 기본 프로젝트 설정 항목을 참조한 다음, 대상 플랫폼에 맞게 컴포넌트를 설치하거나 등록하십시오.

<PlatformBlock for="WebComponents">

**{PackageWebComponents}** 패키지를 사용하여, 체크박스를 import하고 등록하기 전에 패키지를 설치하십시오:

```cmd
npm install {PackageWebComponents}
```

그다음 <ApiLink pkg="core" type="Checkbox" />, 테마 CSS를 import하고 컴포넌트 모듈을 등록하십시오:

```ts
import { defineComponents, IgcCheckboxComponent } from "igniteui-webcomponents";
import 'igniteui-webcomponents/themes/light/bootstrap.css';

defineComponents(IgcCheckboxComponent);
```

</PlatformBlock>

<PlatformBlock for="React">

**{PackageReact}** 패키지를 사용하여, 체크박스 래퍼를 import하기 전에 패키지를 설치하십시오:

```cmd
npm install igniteui-react
```

그다음 React 체크박스 래퍼와 테마 CSS를 import하십시오:

```tsx
import { IgrCheckbox } from 'igniteui-react';
import 'igniteui-webcomponents/themes/light/bootstrap.css';
```

</PlatformBlock>

<PlatformBlock for="Blazor">

{ProductName} 서비스를 등록합니다:

```csharp
// in Program.cs file

builder.Services.AddIgniteUIBlazor();
```

체크박스의 클라이언트 리소스 모듈인 <ApiLink pkg="core" type="CheckboxModule" />를 등록하는 것은 **선택 사항**입니다. 컴포넌트는 처음 렌더링될 때 자체 리소스를 로드합니다. `builder.Services.AddIgniteUIBlazor(typeof(IgbCheckboxModule))`에 나열하면 리소스를 미리 로드하거나, 클라이언트에서만 생성되는 요소를 지원하는 데 사용할 수 있습니다([컴포넌트 모듈](../general-getting-started.mdx#컴포넌트-모듈) 참조).

그다음 애플리케이션의 호스트 페이지(독립 실행형 Blazor WebAssembly 또는 Blazor Hybrid 앱에서는 **wwwroot/index.html**, Blazor Server 앱에서는 **Pages/_Host.cshtml**, Blazor Web App에서는 **Components/App.razor**)에 테마 CSS 파일을 연결하십시오:

```razor
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
```

</PlatformBlock>

## 사용법

<ApiLink pkg="core" type="Checkbox" />는 기본적으로 사용자가 선택됨과 선택 안 됨 상태 중에서 고를 수 있게 하며, 옵션이 부분 선택을 나타낼 때는 불확정 상태도 지원합니다.

체크박스의 <ApiLink pkg="core" type="Checkbox" member="labelPosition" label="LabelPosition" /> 어트리뷰트를 설정하면 레이블을 체크박스 토글의 앞 또는 뒤 중 어디에 배치할지 지정할 수 있습니다. 허용되는 값은 `before`와 `after`(기본값)입니다:

<PlatformBlock for="React">

```tsx
<IgrCheckbox labelPosition="before"></IgrCheckbox>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-checkbox label-position="before">Label</igc-checkbox>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbCheckbox LabelPosition="@ToggleLabelPosition.Before">Label</IgbCheckbox>
```

</PlatformBlock>

<PlatformBlock for="Angular">

```html
<igx-checkbox labelPosition="before">Label</igx-checkbox>
```

</PlatformBlock>

체크박스는 체크박스 바깥의 요소로도 레이블을 붙일 수 있습니다. 이 경우 사용자는 필요에 따라 레이블의 위치와 스타일을 완전히 제어할 수 있습니다.

<PlatformBlock for="React">

</PlatformBlock>


</PlatformBlock>

### Sass 테마 지정

{ProductName} 테마 시스템을 사용하여 애플리케이션의 나머지 부분과 일관되게 체크박스의 스타일을 지정하십시오. 사용자 지정 테마를 추가하기 전에 API 문서에서 사용 가능한 Sass 테마 매개변수를 확인하십시오.

<PlatformBlock for="Angular">

<ApiLink kind="sass" module="themes" type="function-checkbox-theme" label="checkbox-theme" code={true} />은 다음 매개변수를 노출합니다:

| 기본 매개변수 | 관련 매개변수 | 설명 |
| --- | --- | --- |
| `$empty-color` | `$empty-color-hover`, `$focus-outline-color` | 선택되지 않은 테두리 색상과 관련 포커스 또는 마우스 오버 상태. |

## 접근성

{Platform} 체크박스는 레이블과 상태를 가진 선택 가능한 컨트롤을 제공하며, 상태는 키보드 사용자와 보조 기술 사용자가 계속 이해할 수 있어야 합니다.

### 키보드 상호 작용

체크박스는 렌더링된 컨트롤이 제공하는 키보드 동작을 사용합니다. 비활성화된 체크박스는 키보드로 상호 작용할 수 없으며, 스페이스 키로 선택 상태를 바꿀 수 있습니다.

체크박스가 제공하는 키보드 상호 작용을 사용하고, 대상 플랫폼에서 포커스와 상태 변경 동작을 확인하십시오.

| 키 / 상호 작용 | 동작 |
| --- | --- |
| Tab / Shift+Tab | 체크박스가 활성화되고 포커스할 수 있을 때 체크박스로 포커스를 옮기거나 체크박스에서 포커스를 옮깁니다. |
| Space | 포커스된 체크박스의 선택 상태를 토글합니다. |
| 불확정 상태 | 불확정 상태가 활성화되면 체크박스는 현재 상태를 노출합니다. |

### 화면 읽기 프로그램 / ARIA

체크박스는 렌더링된 컨트롤의 의미 체계를 통해 선택 상태, 비활성화 상태, 그리고 설정된 경우 필수, 유효하지 않음, 불확정 상태를 노출합니다.

<PlatformBlock for="WebComponents, React, Blazor">

- 보조 기술 사용자가 목적을 식별할 수 있도록, 모든 체크박스에 의미 있는 레이블 콘텐츠를 제공하십시오.
- 레이블이 컴포넌트 바깥에 있다면, 지원되는 레이블 지정 방식으로 연결하고 대상 플랫폼에서 읽히는 내용을 확인하십시오.
- 컨트롤을 사용자 지정하거나 감쌀 때도 체크박스의 상태 의미 체계를 유지하십시오.
- change 이벤트 핸들러는 상태 변경을 보고할 뿐이며, 접근 가능한 이름이나 상태를 대체하지 않습니다.

</PlatformBlock>

<PlatformBlock for="Angular">

- 보조 기술 사용자가 목적을 식별할 수 있도록, 모든 체크박스에 의미 있는 레이블 콘텐츠를 제공하십시오.
- 레이블이 컴포넌트 바깥에 있다면, 지원되는 Angular 레이블 지정 방식으로 연결하고 대상 플랫폼에서 읽히는 내용을 확인하십시오.
- 컨트롤을 사용자 지정하거나 감쌀 때도 체크박스의 상태 의미 체계를 유지하십시오.
- change 이벤트 핸들러는 상태 변경을 보고합니다. 필요할 때는 접근 가능한 이름을 따로 추가하십시오.

</PlatformBlock>

선택됨, 선택 안 됨, 필수, 유효하지 않음, 비활성화, 불확정 상태는 컴포넌트가 지원하는 의미 체계를 통해 보조 기술에 계속 전달되어야 합니다. 렌더링된 읽기 내용을 플랫폼 API 문서와 대조하여 확인하십시오.

### 접근성 준수

렌더링된 {Platform} 체크박스를 애플리케이션의 접근성 요구 사항에 맞춰 확인하십시오.

| 기준 | 컴포넌트가 요구 사항을 지원하는 방식 |
| --- | --- |
| [2.1.1 키보드](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | 활성화된 체크박스는 키보드 포커스를 받을 수 있으며, 스페이스 키로 선택 상태를 바꿀 수 있습니다. |
| [4.1.2 이름, 역할, 값](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | 체크박스는 렌더링된 컨트롤과 지원되는 상태 의미 체계를 통해 접근 가능한 이름과 현재 선택 상태를 노출합니다. |
| [3.3.1 오류 식별](https://www.w3.org/WAI/WCAG21/Understanding/error-identification) | 체크박스가 유효하지 않으면 유효성 검사 상태를 노출하고, 주변 폼에 적절한 메시지를 제공하십시오. |

사용자의 책임:

- 모든 체크박스에 의미 있는 접근 가능한 이름을 부여하십시오.
- 체크박스 테마를 사용자 지정할 때도 포커스가 보이도록 유지하고 충분한 대비를 보존하십시오.
- 시각적 스타일만으로 부족한 경우에도 필수, 유효하지 않음, 비활성화, 불확정 상태가 전달되도록 하십시오.
- 렌더링된 체크박스를 키보드 탐색과 지원되는 보조 기술로 테스트하십시오.
