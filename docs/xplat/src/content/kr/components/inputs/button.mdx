# 버튼 컴포넌트

{Platform} 버튼 컴포넌트를 사용하면 {Platform} 앱에서 동작을 실행하는 클릭 가능한 요소를 만들 수 있습니다. 버튼 변형, 스타일, 크기를 완전히 제어할 수 있습니다. 버튼 컴포넌트는 클릭을 처리하고, 버튼을 토글하며, 필요할 때 비활성화하는 기능도 제공합니다.

버튼은 콘텐츠를 `base` CSS 파트 안에 렌더링합니다. 레이블에는 기본 슬롯을 사용하고, 레이블 앞뒤의 선택적 콘텐츠에는 `prefix` 및 `suffix` 슬롯을 사용하십시오.

```text
<igc-button>
├── ::part(base)
├── prefix slot
├── default slot content
└── suffix slot
</igc-button>
```

## 시작하기

{Platform} 버튼을 사용하려면  <PlatformBlock for="Angular">[{ProductName} 시작하기](../general/getting-started.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[{ProductName} 시작하기](../general-getting-started.mdx)</PlatformBlock> 기본 프로젝트 설정 항목을 참조한 다음, 대상 플랫폼에 맞게 컴포넌트를 등록하십시오.

<PlatformBlock for="Angular">

**igniteui-angular** 패키지를 사용하는 Angular의 경우, 패키지를 설치하십시오:

```cmd
npm install igniteui-angular
```

그다음 `IgxButtonDirective`를 import하고 컴포넌트의 `imports` 컬렉션에 추가하십시오.

```ts
import { Component } from '@angular/core';
import { IgxButtonDirective } from 'igniteui-angular/directives';

@Component({
    selector: 'app-button',
    imports: [IgxButtonDirective],
    template: '<button igxButton>Save changes</button>'
})
export class ButtonComponent {}
```

</PlatformBlock>

<PlatformBlock for="React,WebComponents">

**{PackageCommon}** 패키지를 사용하는 {Platform}의 경우, 패키지를 설치하십시오:

```cmd
npm install {PackageCommon}
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

그다음 다음과 같이 <ApiLink pkg="core" type="Button" />, 필요한 CSS를 import하고 모듈을 등록해야 합니다:

```ts
import { defineComponents, IgcButtonComponent } from "igniteui-webcomponents";
import 'igniteui-webcomponents/themes/light/bootstrap.css';

defineComponents(IgcButtonComponent);
```

</PlatformBlock>

<PlatformBlock for="React">

그다음 다음과 같이 <ApiLink pkg="core" type="Button" />와 필요한 CSS를 import해야 합니다:

```tsx
import { IgrButton } from 'igniteui-react';

```

</PlatformBlock>

<PlatformBlock for="Blazor">

{ProductName} 서비스를 등록합니다:

## 사용법

{Platform} 버튼을 사용하여 동작을 실행하거나, 폼 데이터를 제출하거나, 다른 페이지로 이동하십시오. 동작에 맞는 버튼 유형과 변형을 선택한 다음, 필요할 때 아이콘 같은 선택적 콘텐츠를 추가하십시오.

버튼 콘텐츠는 기본 슬롯에 배치됩니다. 모든 사용자가 동작의 목적을 알 수 있도록, 동작 레이블을 버튼 콘텐츠로 추가하십시오.

<PlatformBlock for="Angular">

```html
<button igxButton>Save changes</button>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrButton>Save changes</IgrButton>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-button>Save changes</igc-button>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbButton>Save changes</IgbButton>
```

</PlatformBlock>

<ApiLink pkg="core" type="Button" /> 컴포넌트의 `prefix` 및 `suffix` 슬롯을 사용하면 버튼의 주 콘텐츠 앞뒤에 서로 다른 콘텐츠를 추가할 수 있습니다.

간단한 텍스트, 기호 또는 이모지를 추가할 때는 `<span>` 요소를, `prefix` 및 `suffix` 슬롯에 아이콘을 추가할 때는 <ApiLink pkg="core" type="Icon" /> 컴포넌트를 사용하는 것을 권장합니다.

<PlatformBlock for="Angular">

```html
<button igxButton="contained">
    <span igxButtonIcon="prefix">download</span>
    Download
    <span igxButtonIcon="suffix">arrow_forward</span>
</button>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrButton type="button" variant="contained">
    <span slot="prefix">Download</span>
    <IgrIcon slot="suffix" name="download"></IgrIcon>
</IgrButton>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-button type="button" variant="contained">
    <span slot="prefix">Download</span>
    <igc-icon slot="suffix" name="download"></igc-icon>
</igc-button>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbButton Variant="@ButtonVariant.Contained">
    <span slot="prefix">Download</span>
    <IgbIcon slot="suffix" IconName="download"></IgbIcon>
</IgbButton>
```

</PlatformBlock>

### 타입

<ApiLink pkg="core" type="Button" member="href" label="Href" /> 어트리뷰트가 설정되면 버튼 컴포넌트는 내부 구조를 [`<button>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/button)에서 [`<a>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/a) 유형의 요소로 바꿉니다. 이 경우 버튼은 일반 링크처럼 생각할 수 있습니다. <ApiLink pkg="core" type="Button" member="href" label="Href" /> 어트리뷰트를 설정하면 <ApiLink pkg="core" type="Button" member="rel" label="Rel" />, <ApiLink pkg="core" type="Button" member="target" label="Target" />, <ApiLink pkg="core" type="Button" member="download" label="Download" /> 어트리뷰트도 설정할 수 있습니다.
버튼 컴포넌트가 내부적으로 실제 [`<button>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/button) 요소를 사용하는 경우, 속성을 다음 값 중 하나로 설정하여 <ApiLink pkg="core" type="Button" member="type" label="DisplayType" />를 지정할 수 있습니다:

- `Submit` - 폼 데이터를 제출하고 싶을 때
- `reset` - 폼 데이터를 초기 값으로 재설정하고 싶을 때
- `button` - 웹 페이지의 어디에서든 사용자 지정 기능을 가진 버튼을 추가하고 싶을 때

### 변형

버튼은 다섯 가지 유형을 지원합니다: 강조되는 주요 동작용 `contained` 버튼, 보조 동작용 `outlined` 버튼, 은은한 동작용 `flat` 버튼, 강조되는 주요 메인 동작용 `floating action`(Fab) 버튼, 아이콘으로 표현되는 동작용 `icon` 버튼입니다. 아이콘 버튼은 다른 네 가지 변형 중 어떤 것도 사용할 수 있습니다.

## 스타일링

애플리케이션의 시각적 언어에 맞도록 테마 설정, CSS 변수 또는 CSS 파트로 버튼을 사용자 지정하십시오.

### Sass 테마 지정

표준 {ProductName} 테마 작업 흐름을 사용하여 애플리케이션의 나머지 부분과 일관되게 버튼을 사용자 지정하십시오.

### CSS 변수

특정 인스턴스의 테마 값을 재정의하려면 버튼 요소에 생성된 CSS 변수를 사용하십시오. 변형별 테마 함수는 기본 테마 매개변수로부터 관련 상호 작용 상태 값을 도출합니다.

| 기본 속성 | 종속 속성 | 설명 |
| --- | --- | --- |
| `$background` | `$hover-background`, `$focus-background`, `$active-background` | 상호 작용 상태별 버튼 배경색. |
| `$foreground` | `$hover-foreground`, `$focus-foreground`, `$active-foreground` | 상호 작용 상태별 버튼 텍스트 색상. |
| `$border-color` | `$hover-border-color`, `$focus-border-color`, `$active-border-color` | 상호 작용 상태별 버튼 테두리 색상. |
| `$shadow-color` | `$resting-shadow`, `$hover-shadow`, `$focus-shadow`, `$active-shadow` | 버튼 그림자 색상과 고도(elevation). |
| `$disabled-background` | `$disabled-foreground`, `$disabled-icon-color`, `$disabled-border-color` | 비활성화되었을 때의 버튼 색상. |

### 스타일 파트

<ApiLink pkg="core" type="Button" />은 스타일 지정에 사용할 수 있는 세 개의 CSS 파트를 노출합니다:

|이름|설명|

## 접근성

{Platform} 버튼은 동작을 위한 상호 작용 컨트롤이며, `href`가 설정되면 탐색 컨트롤이 됩니다.
명령에는 기본 button 동작을 사용하고, 탐색에는 링크 동작을 유지하십시오.

### 키보드 상호 작용

버튼은 렌더링된 기본 컨트롤의 키보드 동작을 사용합니다. 비활성화된 버튼은 상호 작용할 수 없으며, `href`가 있는 버튼은 명령 버튼이 아니라 링크로 렌더링됩니다.

| 키 | 동작 |
| -- | -- |
| Tab / Shift+Tab | 키보드로 포커스할 수 있을 때 버튼에 포커스를 옮기거나 버튼에서 포커스를 옮깁니다. |
| Enter / Space | 포커스된 명령 버튼을 활성화합니다. 링크로 사용되는 버튼은 Enter로 활성화합니다. |

### 화면 읽기 프로그램 / ARIA

버튼은 명령 동작을 위해 기본 `button` 요소를, `href`가 설정되면 `a` 요소를 렌더링합니다.
기본 요소가 적절한 역할과 키보드 의미 체계를 제공합니다.

<PlatformBlock for="WebComponents, React, Blazor">

- 버튼의 보이는 콘텐츠에 의미 있는 텍스트가 있으면, 그것이 접근 가능한 이름으로 사용됩니다.
- 아이콘만 있는 버튼에는 `aria-label` 또는 다른 접근 가능한 이름 지정 방법을 제공하십시오.
- 비활성화된 버튼은 렌더링된 기본 컨트롤을 통해 비활성화 상태를 노출합니다.
- 버튼의 클릭 이벤트 핸들러는 애플리케이션 동작을 수행하며, 버튼의 접근 가능한 이름, 역할, 상태를 대체하지 않습니다.

</PlatformBlock>

<PlatformBlock for="Angular">

- 버튼은 기본 `button` 또는 `a` 요소를 사용하므로, 보조 기술은 그에 맞는 기본 역할과 키보드 의미 체계를 받습니다.
- 아이콘만 있는 버튼에는 `aria-label` 또는 다른 접근 가능한 이름 지정 방법을 제공하십시오.
- 비활성화된 버튼은 키보드로 상호 작용할 수 없습니다.
- 클릭 이벤트 핸들러는 애플리케이션 동작을 수행합니다. 동작이 보이는 콘텐츠나 기본 어트리뷰트로 전달되지 않는 경우에는 접근 가능한 이름과 상태를 따로 추가하십시오.

</PlatformBlock>

### 접근성 준수

이 항목은 제품 수준의 WCAG, Section 508 또는 EN 301 549 적합성을 주장하지 않습니다. 렌더링된 버튼과 그 주변 애플리케이션을 대상 프로젝트에 적용되는 접근성 요구 사항에 따라 검증하십시오.

| 기준 | 컴포넌트가 요구 사항을 지원하는 방식 |
| -- | -- |
| [2.1.1 키보드](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | 기본 명령 버튼은 키보드 활성화를 지원하며, `href`가 있는 버튼은 기본 링크 활성화를 사용합니다. |
| [4.1.2 이름, 역할, 값](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | 렌더링된 기본 요소가 역할과 상태 의미 체계를 제공합니다. 보이는 버튼 콘텐츠가 의미 있을 때 접근 가능한 이름을 제공합니다. |
| [2.4.4 링크 목적](https://www.w3.org/WAI/WCAG21/Understanding/link-purpose-in-context) | `href`이 설정되면 버튼은 탐색 링크가 됩니다. 대상이나 목적을 식별하는 이름을 제공하십시오. |

사용자의 책임:

- 모든 버튼, 특히 아이콘만 있는 버튼에 의미 있는 접근 가능한 이름을 제공하십시오.
- 동작에는 명령 버튼을, 탐색에는 `href`를 사용하십시오. 한 가지를 다른 것으로 흉내 내지 마십시오.
- 동작이나 상태를 전달하기 위해 색상, 마우스 오버, 포커스 스타일에만 의존하지 마십시오.
- 버튼 테마를 사용자 지정할 때는 충분한 대비와 보이는 포커스 표시기를 유지하십시오.

## 문제 해결

버튼을 명령, 탐색 링크 또는 폼 컨트롤로 다루기 전에, 이 섹션에서 경계와 일반적인 결정을 확인하십시오.

### 버튼이 링크처럼 동작하는 이유는 무엇입니까?

`href`이 설정되면 버튼은 명령 동작이 아니라 탐색에 사용됩니다. 컨트롤이 URL로 이동하는 대신 애플리케이션 로직을 실행해야 한다면 `href`를 제거하십시오.

### 버튼이 키보드로 포커스되지 않는 이유는 무엇입니까?

버튼이 비활성화되어 있는지, 아니면 주변 애플리케이션이 포커스 동작을 바꾸고 있는지 확인하십시오. 키보드 탐색으로 사용할 수 있어야 하는 동작에는 포커스 가능한 버튼을 사용하십시오.

### 알려진 제한 사항

버튼에는 다음과 같은 플랫폼에 독립적인 경계가 있습니다:

- 모든 동작에 텍스트 레이블 또는 다른 접근 가능한 이름 지정 방법을 사용하십시오. 레이블이 없는 아이콘 전용 버튼은 그 자체로 목적을 전달하지 못합니다.
- `href`을 설정하면 버튼은 동작 컨트롤에서 탐색 컨트롤로 바뀝니다. 아이콘 전용 동작에는 [아이콘 버튼](./icon-button.mdx)을 사용하고, 접근 가능한 이름은 따로 확인하십시오.
- 버튼의 시각적 모양은 주변 애플리케이션 동작이 사용 가능한지 또는 유효한지를 결정하지 않습니다. 이러한 상태와 피드백은 애플리케이션 로직이 제공해야 합니다.
