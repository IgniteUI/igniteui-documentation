# {Platform}용 Ignite UI CLI

[Ignite UI CLI](https://github.com/IgniteUI/igniteui-cli)(`igniteui-cli`)는 {ProductName}로 {Platform} 애플리케이션을 만들고 스캐폴딩하는 독립형 전역 명령줄 도구입니다. {ProductName}용으로 미리 구성된 프로젝트 템플릿, 처음 설정하는 사용자를 위한 단계별 안내 마법사, 스크립트 작업 흐름을 위한 비대화형 `new` 및 `add` 명령, 개발 서버, 그리고 AI 코딩 어시스턴트를 실시간 {ProductName} 문서에 연결하는 내장 MCP 서버를 제공합니다.

Ignite UI CLI는 프레임워크의 빌드 도구를 대체하지 않습니다. CLI가 만든 프로젝트는 표준 {Platform} 애플리케이션이며, 스캐폴딩 후에도 네이티브 빌드 명령과 구성과 완전히 호환됩니다.

<PlatformBlock for="React">
Ignite UI CLI는 Vite나 다른 React 도구를 대체하지 않습니다. CLI로 만든 프로젝트는 표준 Vite 기반 React 애플리케이션이며, 스캐폴딩 후에도 npm 스크립트 및 Vite 명령과 완전히 호환됩니다.
</PlatformBlock>

## Ignite UI CLI 설치하기

npm을 사용하여 Ignite UI CLI를 전역으로 설치하십시오:

```bash
npm install -g igniteui-cli
```

또는 yarn을 사용하십시오:

```cmd
yarn global add igniteui-cli
```

설치를 확인하십시오:

```cmd
ig version
```

## 새 프로젝트 만들기

Ignite UI CLI는 프로젝트 생성을 위해 두 가지 모드를 제공합니다. 하나는 안내형 대화식 마법사이고, 다른 하나는 인수를 사용하는 직접 명령입니다.

### 안내형 마법사 사용하기

단계별 마법사는 새 프로젝트를 시작하기에 권장되는 방법입니다. 프레임워크, 프로젝트 유형, 템플릿, 테마를 선택하라는 안내가 나온 후, 프로젝트를 스캐폴딩하고 자동으로 커밋합니다.

마법사를 실행하려면 다음을 실행하십시오:

```cmd
ig
```

또는:

```cmd
ig new
```

마법사 옵션을 단계별로 살펴보려면 [Ignite UI CLI를 사용한 단계별 가이드](./general-step-by-step-guide-using-cli.mdx)를 참조하십시오.

### 프로젝트 직접 만들기

<PlatformBlock for="React">
React 프로젝트를 비대화형으로 만들려면 프레임워크로 `react`를, 프로젝트 유형으로 `igr-ts`를 지정하십시오:

```cmd
ig new <project-name> --framework=react --template=side-nav
```

React에 사용할 수 있는 기본 프로젝트 템플릿은 다음과 같습니다:

| 템플릿 ID   | 설명                                                                 |
| :------------ | :-------------------------------------------------------------------------- |
| empty         | 미리 정의된 뷰가 없는 최소 프로젝트 구조입니다. 이 템플릿에서는 인증을 사용할 수 없습니다. |
| side-nav      | 사이드 내비게이션 드로어가 있는 프로젝트 구조입니다. 추가 옵션으로 인증을 지원합니다(아래 참조). |
| side-nav-mini | 간결한 사이드 내비게이션 드로어가 있는 프로젝트 구조입니다. 추가 옵션으로 인증을 지원합니다(아래 참조). |

대화형 마법사에서 `side-nav` 또는 `side-nav-mini`를 선택하면 인증을 추가할지 묻는 추가 프롬프트가 나타납니다. `empty`를 선택하면 인증 프롬프트를 건너뜁니다. 다음 템플릿 ID는 생성되며 `ig new`와 함께 비대화형 생성에도 직접 사용할 수 있습니다. 이들은 마법사의 템플릿 목록에는 표시되지 않습니다:

| 템플릿 ID        | 설명                                      |
| :----------------- | :----------------------------------------------- |
| side-nav-auth      | 인증이 추가된 확장 사이드 탐색입니다.    |
| side-nav-mini-auth | 인증이 추가된 확장 미니 사이드 탐색입니다. |

</PlatformBlock>

<PlatformBlock for="Blazor">

Blazor 프로젝트는 **.NET CLI**로 스캐폴딩되므로 **.NET SDK 10.0 이상**이 필요합니다. 처음 사용할 때 CLI는 아직 없다면 [`IgniteUI.Blazor.Templates`](https://www.nuget.org/packages/IgniteUI.Blazor.Templates) 패키지를 자동으로 설치합니다.

Blazor 프로젝트를 비대화형으로 만들려면 프레임워크로 `blazor`를 지정하고 호스팅 모델을 선택하십시오:

```cmd
ig new <project-name> --framework blazor --hosting Server
```

테마, 테마 변형을 설정하고 패키지 복원을 건너뛰는 더 완전한 예제입니다:

```cmd
ig new MyApp --framework blazor --hosting Auto --theme material --variant dark --skip-install
```

### Blazor 옵션

| 옵션            | 별칭 | 값                                          | 기본값     | 설명                                                        |
| :---------------- | :---- | :---------------------------------------------- | :---------- | :----------------------------------------------------------------- |
| `--hosting`       |       | `Server`, `Wasm`, `Auto`                        | `Server`    | Blazor 호스팅 모델(Blazor 전용).                                |
| `--theme`         | `-th` | `bootstrap`, `material`, `fluent`, `indigo`     | `bootstrap` | 프로젝트에 적용되는 Ignite UI 테마입니다.                            |
| `--variant`       |       | `light`, `dark`                                 | `light`     | 테마 색상 변형(Blazor 전용)입니다.                                |
| `--skip-install`  | `-si` | —                                               | `false`     | 스캐폴딩 후 패키지 복원을 건너뜁니다.                       |
| `--skip-git`      | `-sg` | —                                               | `false`     | 프로젝트에 대해 git 저장소를 초기화하지 않습니다.               |

> [!NOTE]
`--hosting` 및 `--variant`는 Blazor 프레임워크에서만 유효하며 다른 프레임워크에서는 무시됩니다.

### 기본 프로젝트 템플릿

| 템플릿 ID | 설명                                                                      |
| :---------- | :------------------------------------------------------------------------------- |
| empty       | `IgniteUI.Blazor.Templates` 패키지로 스캐폴딩되는 최소 Blazor Web App입니다.   |

프로젝트를 만들었으면 표준 .NET 도구로 실행하십시오:

```cmd
cd <project-name>
dotnet run
```

프로젝트를 만들 때 다음 인수를 사용할 수 있습니다:

| 인수         | 별칭  | 설명                                                                                                           |
| :--------------- | :----- | :-------------------------------------------------------------------------------------------------------------------- |
| `name`           | `-n`   | 애플리케이션의 이름입니다. 애플리케이션은 같은 이름의 디렉터리 안에 생성됩니다.                        |
| `--framework`    | `-f`   | 생성되는 프로젝트의 프레임워크입니다. 기본값: `jquery`. 지원: `jquery`, `angular`, `react`, `webcomponents`. |
| `--type`         | `-t`   | 선택한 프레임워크의 프로젝트 유형입니다. React에는 `igr-ts`를, Web Components에는 `igc-ts`를 사용하십시오.                   |
| `--template`     |        | 사용할 프로젝트 템플릿입니다. 프레임워크별 사용 가능 옵션은 위의 템플릿 표를 참조하십시오.                       |

| `--skip-install` | `--si` | 프로젝트를 만들 때 npm 패키지 설치를 건너뜁니다.                                                                   |
| `--assistants`   |        | 지정한 AI 코딩 어시스턴트용 MCP 서버를 구성합니다. 값: `generic`, `vscode`, `cursor`, `gemini`, `junie`, `none`. |
| `--agents`       |        | 지정한 에이전트의 스킬 디렉터리에 Agent Skill 파일을 복사합니다. 값: `generic`, `claude`, `copilot`, `cursor`, `codex`, `windsurf`, `gemini`, `junie`, `none`. |

### 프로젝트 생성 중 AI 구성

`--agents`와 `--assistants` 플래그를 제공하지 않으면, `ig new`는 프로젝트 생성 흐름의 일부로 AI 도구 구성을 요청합니다. 프로젝트를 스캐폴딩한 후 마법사는 다음 프롬프트를 표시합니다:

```bash
? Which AI coding assistants do you want to configure MCP servers for? (Press <space> to select)
❯◉ VS Code (GitHub Copilot)
 ◉ Cursor
 ◯ Generic (.mcp.json)
 ◯ Gemini CLI
 ◯ JetBrains (AI Assistant)
 ◯ None
```

```bash
? Which AI agents should receive skill files? (Press <space> to select)
❯◉ GitHub Copilot (.agents/skills/)
 ◉ Claude (.claude/skills/)
 ◉ Cursor (.cursor/rules/)
 ◯ Codex (.codex/)
 ◯ Windsurf (.windsurfrules)
 ◯ Gemini CLI (.gemini/)
 ◯ JetBrains Junie (.junie/guidelines/)
 ◯ None
```

화살표 키로 옵션을 이동하고, SPACE로 선택을 전환하며, ENTER로 확인하십시오.

프로젝트 생성 중 AI 구성 프롬프트를 완전히 건너뛰려면 `--assistants none --agents none`를 전달하십시오:

```cmd
ig new my-app --framework=react --template=side-nav --assistants none --agents none
```

프롬프트 없이 AI 도구를 자동으로 구성하려면 원하는 값을 지정하십시오:

```cmd
ig new my-app --framework=react --template=side-nav --assistants vscode --agents copilot claude
```

</PlatformBlock>

## 컴포넌트 템플릿 추가하기

프로젝트를 만든 후에는 언제든지 추가 컴포넌트 뷰를 추가할 수 있습니다. 인수 없이 `ig add`를 실행하면 대화형 템플릿 탐색기가 시작됩니다:

```cmd
ig add
```

특정 컴포넌트 템플릿을 직접 추가하려면 템플릿 ID와 새 컴포넌트의 이름을 제공하십시오:

```cmd
ig add [component-template] [component-name]
```

예를 들어 `MyGrid`라는 이름의 데이터 그리드 컴포넌트를 추가하려면:

```cmd
ig add grid MyGrid
```

현재 프로젝트에서 사용 가능한 모든 템플릿을 나열하려면:

```cmd
ig list
```

이 목록은 프로젝트를 인식하며 프로젝트의 프레임워크와 유형을 반영합니다.

컴포넌트 추가 마법사의 안내 설명은 [Ignite UI CLI 사용 단계별 가이드](./general-step-by-step-guide-using-cli.mdx#뷰-추가)를 참조하십시오.

<DocsAside type="info">
라우팅 파일에는 새로 생성된 페이지의 경로가 업데이트됩니다. 예를 들어 `MyGrid`라는 컴포넌트는 `/my-grid`에서 이동할 수 있습니다.
</DocsAside>

## 애플리케이션 실행하기

`start` 명령은 애플리케이션을 빌드하고, 로컬 웹 서버를 시작하며, 기본 브라우저에서 엽니다:

```cmd
ig start
```

<PlatformBlock for="React">
### Vite 사용하기

Ignite UI CLI로 생성된 React 애플리케이션은 빌드 도구로 [Vite](https://vitejs.dev/)를 사용하며, 빠른 개발 빌드와 핫 모듈 교체(HMR)를 지원합니다. CLI 래퍼 없이 Vite 개발 서버를 직접 시작하려면:

```cmd
npm run dev
```

Vite 개발 서버는 기본적으로 `http://localhost:5173`에서 시작합니다. CLI가 빌드와 실행을 한 명령으로 처리하도록 하려면 `ig start`를 사용하십시오.
</PlatformBlock>

## AI 어시스턴트 통합(MCP)

Ignite UI CLI에는 AI 코딩 어시스턴트(GitHub Copilot, Claude, Cursor 등)를 {ProductName} 컴포넌트 문서와 API 참조에 직접 연결하는 내장 **MCP(Model Context Protocol) 서버**가 포함되어 있습니다. 구성하면 AI 어시스턴트가 편집기를 떠나지 않고도 프로젝트를 스캐폴딩하고, 컴포넌트를 추가 및 수정하며, 문서를 검색하고, API 세부 정보를 찾아보고, 정확한 {ProductName} 코드를 생성할 수 있습니다.

CLI MCP 서버는 전역 설치 없이 `npx`를 통해 시작됩니다:

```cmd
npx -y igniteui-cli mcp
```

또는 Ignite UI CLI를 전역으로 설치한 경우:

```cmd
ig mcp
```

<PlatformBlock for="React, WebComponents, Blazor">

### `ig ai-config`를 이용한 빠른 설정

`ai-config` 명령은 MCP 서버를 구성하고, 프레임워크별 스킬 파일을 각 에이전트의 스킬 디렉터리에 복사하며, 지침 파일을 설정합니다. 이 모든 작업이 한 단계에서 이루어집니다. 프로젝트 루트에서 실행하십시오:

```cmd
npx igniteui-cli ai-config
```

CLI를 전역으로 설치한 경우:

```cmd
ig ai-config
```

<DocsAside type="info">
버전을 고정하지 않으면 `npx`이(가) `ai-config` 하위 명령을 인식하지 못하는 이전 CLI 버전을 가져올 수 있으며, 그 경우 대신 대화형 프로젝트 생성 프롬프트가 실행되어 기존 프로젝트 안에 새 프로젝트가 만들어집니다. CLI 버전 16.x가 설치되어 있는지 확인하십시오.
</DocsAside>

#### 대화형 모드

매개변수를 제공하지 않으면 명령이 대화형 모드로 들어갑니다. 먼저 MCP 서버 구성을 받을 AI 코딩 어시스턴트를 선택하라는 안내가 나옵니다:

```bash
? Which AI coding assistants do you want to configure MCP servers for? (Press <space> to select)
❯◉ VS Code (GitHub Copilot)       - writes .vscode/mcp.json
 ◉ Cursor                          - writes .cursor/mcp.json
 ◯ Generic (.mcp.json)             - writes .mcp.json
 ◯ Gemini CLI                      - writes .gemini/settings.json
 ◯ JetBrains (AI Assistant)        - writes .junie/mcp.json
 ◯ None
```

다음으로 스킬 파일을 받을 AI 에이전트를 선택하라는 안내가 나옵니다:

```bash
? Which AI agents should receive skill files? (Press <space> to select)
❯◉ GitHub Copilot (.agents/skills/) - copies skills to .agents/skills/
 ◉ Claude (.claude/skills/)          - copies skills to .claude/skills/
 ◉ Cursor (.cursor/rules/)           - copies skills to .cursor/rules/
 ◯ Codex (.codex/)                   - copies skills to .codex/
 ◯ Windsurf (.windsurfrules)         - copies skills to .windsurfrules/
 ◯ Gemini CLI (.gemini/)             - copies skills to .gemini/
 ◯ JetBrains Junie (.junie/)         - copies skills to .junie/guidelines/
 ◯ None
```

화살표 키로 옵션을 이동하고, SPACE로 선택을 전환하며, ENTER로 확인하십시오.

#### 비대화형 모드

`--assistants`를 사용하여 MCP 구성을 받을 코딩 어시스턴트를 선택하고, `--agents`를 사용하여 스킬 파일을 받을 에이전트를 선택하십시오:

```cmd
ig ai-config --assistants vscode --agents copilot
```

한 번의 실행으로 여러 어시스턴트와 에이전트를 대상으로 지정하십시오:

```cmd
ig ai-config --assistants generic vscode --agents claude copilot cursor
```

| 플래그 | 값 | 기본값 |
|:-----|:-------|:--------|
| `--assistants` | `generic`, `vscode`, `cursor`, `gemini`, `junie`, `none` | 대화형으로 입력 요청 |
| `--agents` | `generic`, `claude`, `copilot`, `cursor`, `codex`, `windsurf`, `gemini`, `junie`, `none` | 대화형으로 입력 요청 |

#### 서버 시작하기

명령이 끝난 후 AI 클라이언트에서 MCP 서버를 시작하십시오. 서버는 구성되었지만 아직 실행 중이 아닙니다. 에이전트가 도구를 사용하려면 클라이언트가 각 서버를 먼저 실행해야 합니다.

**GitHub Copilot이 있는 VS Code:** `.vscode/mcp.json`를 여십시오. VS Code는 각 서버 항목 위에 인라인 **Start** 버튼을 표시합니다. `igniteui`와 `igniteui-theming` 모두에 대해 **Start**를 클릭하십시오. 시작되면 VS Code는 각 서버 옆에 사용 가능한 도구 개수를 표시합니다(예: _"13 tools | 1 prompt"_). 또는 명령 팔레트(`Ctrl+Shift+P` / `Cmd+Shift+P`)에서 **MCP: List Servers**를 실행하고, 각 서버를 선택한 후 **Start**를 선택하십시오.

모든 AI 클라이언트에 대한 전체 설정 안내와 Agent Skills 연결은 [Agent Skills](./ai/skills.mdx) 및 [Ignite UI CLI MCP](./ai/cli-mcp.mdx)를 참조하십시오.

</PlatformBlock>

AI 클라이언트가 CLI MCP 서버를 사용하도록 수동으로 구성하십시오. 대부분의 팀은 CLI MCP와 Theming MCP를 함께 연결합니다. CLI MCP는 프로젝트와 컴포넌트 작업 흐름을 처리하고, Theming MCP는 팔레트, 테마, 디자인 토큰을 처리합니다.

**VS Code** - 프로젝트 루트에서 `.vscode/mcp.json`를 만들거나 편집하십시오:

```json
{
  "servers": {
    "igniteui-cli": {
      "command": "npx",
      "args": ["-y", "igniteui-cli", "mcp"]
    },
    "igniteui-theming": {
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
    }
  }
}
```

**Cursor, Claude Desktop, Claude Code, JetBrains 및 기타 MCP 클라이언트:**

```json
{
  "mcpServers": {
    "igniteui-cli": {
      "command": "npx",
      "args": ["-y", "igniteui-cli", "mcp"]
    },
    "igniteui-theming": {
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
    }
  }
}
```

클라이언트별 설정 안내(VS Code, GitHub, Cursor, Claude Desktop, Claude Code, JetBrains)와 사용 가능한 도구의 전체 설명은 [Ignite UI CLI MCP](./ai/cli-mcp.mdx)를 참조하십시오.

<PlatformBlock for="React, WebComponents">

두 MCP 서버를 모두 사용하는 종단 간 안내는 [CLI MCP와 Theming MCP로 앱 종단 간 빌드하기](./general-how-to-mcp-e2e.mdx)를 참조하십시오.

</PlatformBlock>
