# {Platform} {ComponentTitle} 행 추가

<ComponentBlock for="Grid, HierarchicalGrid">
{Platform} {ComponentTitle}의 {ProductName} 행 추가 기능을 사용하면 사용자가 별도의 양식이나 페이지로 이동하지 않고도 새 데이터 레코드를 입력하고 제출할 수 있습니다. <ApiLink type="{ComponentName}" />를 사용하면 사용자는 인라인 행 추가와 CRUD 작업을 위한 강력한 API를 통해 데이터를 조작할 수 있습니다.
그리드 템플릿에 편집 작업이 활성화된 <ApiLink type="ActionStrip" /> 컴포넌트를 추가하십시오. 그다음 행 위에 마우스를 올리고 제공된 버튼을 사용하십시오. 마지막으로 <kbd>ALT</kbd> + <kbd>+</kbd>를 누르면 행 추가 UI가 나타납니다.

</ComponentBlock>

## 프로그래밍 방식으로 행 추가 시작하기

<ApiLink type="{ComponentName}" />은(는) 두 가지 서로 다른 공개 메서드를 사용하여 프로그래밍 방식으로 행 추가 UI를 나타나게 할 수 있습니다. 하나는 UI가 나타날 아래의 행을 지정하기 위한 행 ID를 받고, 다른 하나는 인덱스로 작동합니다. 이 메서드들을 사용하여 현재 데이터 뷰 안 어디에서든 UI를 나타나게 할 수 있습니다. 페이지를 바꾸거나 예를 들어 필터링으로 숨겨진 행을 지정하는 것은 지원되지 않습니다.

<ApiLink type="{ComponentName}" member="beginAddRowById" />을(를) 사용하려면 작업의 컨텍스트로 사용할 행을 `RowID`(PK)로 지정해야 합니다. 그러면 이 메서드는 최종 사용자가 지정된 행의 행 추가 액션 스트립 버튼을 클릭한 것처럼 동작하여, 그 아래에 UI를 나타냅니다. 첫 번째 매개변수에 `null`을(를) 전달하면 UI를 그리드의 가장 첫 번째 행으로 나타나게 할 수도 있습니다.

<PlatformBlock for="WebComponents">
```typescript

this.grid.beginAddRowById(null);     // Spawns the add row UI as the first record
```
</PlatformBlock>

```razor
    await this.grid.BeginAddRowByIdAsync(null, false);     // Spawns the add row UI as the first record
}
```
</PlatformBlock>

## 위치 지정

- 행 추가 UI의 기본 위치는 최종 사용자가 행 추가 버튼을 클릭한 행의 아래입니다.

- <ApiLink type="{ComponentName}" />은(는) 행 추가 UI가 완전히 보이도록 자동으로 스크롤합니다.

- 행 추가 UI의 오버레이는 스크롤하는 동안 위치를 유지합니다.

## 동작

행 추가 UI는 행 편집 UI와 같은 동작을 가집니다. 최종 사용자에게 일관된 편집 경험을 제공하도록 설계되었기 때문입니다. 자세한 내용은 [{ComponentTitle} 행 편집](row-editing.mdx) 주제를 참조하십시오.

행 추가 UI를 통해 새 행을 추가한 후, 그 위치 및/또는 가시성은 <ApiLink type="{ComponentName}" />의 정렬, 필터링, 그룹화 상태에 따라 결정됩니다. 이러한 상태가 하나도 적용되지 않은 <ApiLink type="{ComponentName}" />에서는 마지막 레코드로 나타납니다. 최종 사용자가 보이지 않는 위치에 있는 <ApiLink type="{ComponentName}" />을(를) 그 위치로 스크롤할 수 있는 버튼이 들어 있는 스낵바가 잠깐 표시됩니다.

## 키보드 탐색

- <kbd>ALT</kbd> + <kbd>+</kbd> - 행 추가를 위해 편집 모드로 들어갑니다

<ComponentBlock for="TreeGrid">
- <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>+</kbd> - 하위 항목 추가를 위해 편집 모드로 들어갑니다

</ComponentBlock>
- <kbd>ESC</kbd>는 어떤 변경 사항도 제출하지 않고 행 추가 모드를 벗어납니다

- <kbd>TAB</kbd>은 포커스를 행의 편집 가능한 한 셀에서 다음 셀로 옮기고, 가장 오른쪽 편집 가능한 셀에서는 CANCEL 및 DONE 버튼으로 옮깁니다. DONE 버튼에서의 탐색은 현재 편집 중인 행의 가장 왼쪽 편집 가능한 셀로 이동합니다.

## 기능 통합

- <ApiLink type="{ComponentName}" />의 데이터 뷰가 수정되면 모든 행 추가 작업이 중지됩니다. 최종 사용자가 한 변경 사항은 제출됩니다. 데이터 뷰를 바꾸는 작업에는 정렬, 그룹화, 필터링, 페이징 등이 포함되며, 이에 국한되지 않습니다.

- 요약은 행 추가 작업이 끝난 후 업데이트됩니다. 정렬, 필터링 등 다른 데이터 뷰 의존 기능도 마찬가지입니다.

<ComponentBlock for="HierarchicalGrid">
- <ApiLink type="{ComponentName}" />의 UI를 나타낼 때, 최종 사용자가 행 추가 버튼을 클릭한 행에 대해 현재 펼쳐져 있는 하위 레이아웃은 접힙니다.

</ComponentBlock>

### 버튼 사용자 지정하기

`RowEditActionsDirective`을(를) 사용하면 행 편집 오버레이의 버튼을 사용자 지정할 수 있습니다.

버튼이 키보드 탐색의 일부가 되기를 원한다면, 각 버튼에 `RowEditTabStopDirective`가 있어야 합니다.

```html
<ng-template igxRowEditActions let-endRowEdit>

</ng-template>
```

> **참고**:
> `RowEditActions` 디렉티브를 사용하면 편집 및 추가 오버레이 버튼의 편집 작업이 모두 변경됩니다.

## 원격 시나리오

대부분의 원격 데이터 시나리오에서는 기본 키 할당이 생성 서버 요청에서 이루어집니다. 이 경우 클라이언트에서 추가된 레코드는 서버 데이터베이스에 저장되기 전까지 최종 기본 키 값을 가지지 않습니다. 이때 <ApiLink type="{ComponentName}" />에서 이 업데이트를 처리하는 권장 방법은 다음과 같습니다:

- <ApiLink type="{ComponentName}" />이(가) 트랜잭션을 사용하지 않는 경우.

    생성 요청이 성공적으로 완료되어 추가된 레코드 데이터를 반환하면, 로컬 데이터 레코드 인스턴스에서 그 레코드의 id를 교체할 수 있습니다.

- <ApiLink type="{ComponentName}" />이(가) 트랜잭션을 사용하는 경우.

    생성 요청 또는 일괄 업데이트 요청이 성공적으로 완료되어 추가된 레코드 인스턴스(DB가 생성한 id 포함)를 반환하면, 관련된 ADD 트랜잭션을 `Clear` API 메서드를 사용하여 트랜잭션 로그에서 지워야 합니다. 로컬 트랜잭션에는 생성된 id 필드가 있으며, 이는 데이터베이스에서 만든 것과 다를 수 있으므로 지워야 하기 때문입니다. 그다음 응답으로 전달된 레코드를 로컬 데이터 인스턴스에 추가할 수 있습니다.

이렇게 하면 원격에서 생성된 id가 항상 로컬 데이터에 반영되고, 이후의 업데이트/삭제 작업이 올바른 레코드 id를 대상으로 하게 됩니다.
</PlatformBlock>
