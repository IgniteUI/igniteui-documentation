# {Platform} {ComponentTitle} 요약

{Platform} {ComponentTitle}의 {ProductName} 요약 기능은 열 단위로 그룹 바닥글 역할을 합니다. {Platform} {ComponentName} 요약은 강력한 기능으로, 열 안 데이터의 유형에 따라 미리 정의된 기본 요약 항목 세트를 제공하거나 <ApiLink type="{ComponentName}" />에 사용자 지정 템플릿을 구현하여, 별도의 컨테이너에서 열 정보를 볼 수 있게 합니다.

## {Platform} {ComponentTitle} 요약 개요 예제

<Sample src="/{ComponentSample}/data-summary-options" height={650} alt="{Platform} {ComponentTitle} 데이터 요약 옵션" />


<DocsAside type="info">
열의 요약은 **모든 열 값의 함수**입니다. 단, 필터링이 적용되어 있으면 열의 요약은 **필터링된 결과 값의 함수**가 됩니다
</DocsAside>

<ApiLink type="{ComponentName}" /> 요약은 {ProductName}에서 열 단위로도 활성화할 수 있으므로, 필요한 열에만 활성화할 수 있습니다. <ApiLink type="{ComponentName}" /> 요약은 열 안 데이터의 유형에 따라 미리 정의된 기본 요약 세트를 제공하므로 시간을 절약할 수 있습니다:


`string` 및 `boolean` <ApiLink type="Column" member="dataType" />의 경우 다음 함수를 사용할 수 있습니다:
- 개수

`number`, `currency` 및 `percent` 데이터 유형의 경우 다음 함수를 사용할 수 있습니다:

- 개수
- 최솟값
- 최댓값
- 평균
- 합계

`date` 데이터 유형의 경우 다음 함수를 사용할 수 있습니다:
- 개수
- 가장 이른 날짜
- 가장 늦은 날짜

사용 가능한 모든 열 데이터 타입은 공식 [열 타입 항목](column-types.mdx#기본-템플릿)에서 찾을 수 있습니다.

<ApiLink type="{ComponentName}" /> 요약은 <ApiLink type="ColumnState" member="hasSummary" /> 속성을 **true**로 설정하여 열 단위로 활성화합니다. 또한 각 열의 요약은 열 데이터 유형에 따라 결정된다는 점을 기억해야 합니다. <ApiLink type="{ComponentName}" />에서 기본 열 데이터 유형은 `string`이므로, `number`나 `date` 전용 요약을 원한다면 <ApiLink type="Column" member="dataType" /> 속성을 `number` 또는 `date`으로 지정해야 합니다. 요약 값은 그리드의 <ApiLink type="GridBaseDirective" member="locale" label="Locale" /> 및 열의 <ApiLink type="Column" member="pipeArgs" />에 따라 지역화되어 표시된다는 점에 유의하십시오.

## 사용자 지정 {ComponentTitle} 요약

이러한 함수가 요구 사항을 충족하지 못한다면, 특정 열에 대해 사용자 지정 요약을 제공할 수 있습니다.


<PlatformBlock for="WebComponents">
이를 위해서는 열 데이터 유형과 필요에 따라 기본 클래스 <ApiLink type="SummaryOperand" />, <ApiLink type="NumberSummaryOperand" /> 또는 <ApiLink type="DateSummaryOperand" /> 중 하나를 재정의해야 합니다. 이렇게 하면 기존 함수를 다시 정의하거나 새 함수를 추가할 수 있습니다. <ApiLink type="SummaryOperand" /> 클래스는 <ApiLink type="SummaryOperand" member="count" label="Count" /> 메서드에 대해서만 기본 구현을 제공합니다. <ApiLink type="NumberSummaryOperand" />는 <ApiLink type="SummaryOperand" />을(를) 확장하며 <ApiLink type="NumberSummaryOperand" member="min" label="Min" />, <ApiLink type="NumberSummaryOperand" member="max" label="Max" />, <ApiLink type="NumberSummaryOperand" member="sum" label="Sum" /> 및 <ApiLink type="NumberSummaryOperand" member="average" label="Average" />에 대한 구현을 제공합니다. <ApiLink type="DateSummaryOperand" />는 <ApiLink type="SummaryOperand" />을(를) 확장하며, 추가로 <ApiLink type="DateSummaryOperand" member="earliest" label="Earliest" />와 <ApiLink type="DateSummaryOperand" member="latest" label="Latest" />를 제공합니다.

</PlatformBlock>

```typescript
import { IgxSummaryResult, IgxSummaryOperand, IgxNumberSummaryOperand, IgxDateSummaryOperand } from 'igniteui-angular';

class MySummary extends IgxNumberSummaryOperand {
    constructor() {
        super();
    }

    operate(data?: any[]): IgxSummaryResult[] {
        const result = super.operate(data);
        result.push({
            key: 'test',
            label: 'Test',
            summaryResult: data.filter(rec => rec > 10 && rec < 30).length
        });
        return result;
    }
}
```

## 요약 서식 지정
기본적으로 내장 요약 피연산자가 만든 요약 결과는 그리드 <ApiLink type="GridBaseDirective" member="locale" label="Locale" />과 열 <ApiLink type="Column" member="pipeArgs" />에 따라 지역화되고 서식이 지정됩니다. 사용자 지정 피연산자를 사용할 때는 <ApiLink type="GridBaseDirective" member="locale" label="Locale" />과 <ApiLink type="Column" member="pipeArgs" />가 적용되지 않습니다. 요약 결과의 기본 모양을 바꾸고 싶다면 <ApiLink type="Column" member="summaryFormatter" label="SummaryFormatter" /> 속성을 사용하여 서식을 지정할 수 있습니다.

```typescript
public dateSummaryFormat(summary: IgxSummaryResult, summaryOperand: IgxSummaryOperand): string {
    const result = summary.summaryResult;
    if (summaryOperand instanceof IgxDateSummaryOperand && summary.key !== 'count'
        && result !== null && result !== undefined) {
        const pipe = new DatePipe('en-US');
        return pipe.transform(result,'MMM YYYY');
    }
    return result;
}
```

```typescript
    public dateSummaryFormat(summary: IgcSummaryResult, summaryOperand: IgcSummaryOperand): string {
```

## Group By와 함께하는 요약

열 기준으로 그룹화했다면 <ApiLink type="{ComponentName}" />은(는) <ApiLink type="{ComponentName}" member="summaryCalculationMode" label="SummaryCalculationMode" />과 <ApiLink type="{ComponentName}" member="summaryPosition" label="SummaryPosition" /> 속성을 사용하여 요약 위치와 계산 모드를 바꿀 수 있게 합니다. 이 두 속성과 함께 <ApiLink type="{ComponentName}" />은(는) <ApiLink type="{ComponentName}" member="showSummaryOnCollapse" label="ShowSummaryOnCollapse" /> 속성을 노출하며, 이는 해당 그룹 행이 접혔을 때 요약 행이 계속 보일지를 결정할 수 있게 합니다.

<ApiLink type="{ComponentName}" member="summaryCalculationMode" label="SummaryCalculationMode" /> 속성의 사용 가능한 값은 다음과 같습니다:

- <ApiLink type="GridSummaryCalculationMode" label="RootLevelOnly" /> - 요약은 루트 수준에 대해서만 계산됩니다.
- <ApiLink type="GridSummaryCalculationMode" label="ChildLevelsOnly" /> - 요약은 하위 수준에 대해서만 계산됩니다.
- <ApiLink type="GridSummaryCalculationMode" label="RootAndChildLevels" /> - 요약은 루트 수준과 하위 수준 모두에 대해 계산됩니다. 이것이 기본값입니다.

<ApiLink type="{ComponentName}" member="summaryPosition" label="SummaryPosition" /> 속성의 사용 가능한 값은 다음과 같습니다:

- <ApiLink type="GridSummaryPosition" label="Top" /> - 요약 행이 그룹화 행의 하위 항목 앞에 나타납니다.
- <ApiLink type="GridSummaryPosition" label="Bottom" /> - 요약 행이 그룹화 행의 하위 항목 뒤에 나타납니다. 이것이 기본값입니다.

<ApiLink type="{ComponentName}" member="showSummaryOnCollapse" label="ShowSummaryOnCollapse" /> 속성은 불리언입니다. 기본값은 **false**로 설정되어 있으며, 이는 그룹 행이 접히면 요약 행이 숨겨진다는 뜻입니다. 속성을 **true**로 설정하면 그룹 행이 접혀도 요약 행이 계속 보입니다.


<DocsAside type="info">
<ApiLink type="{ComponentName}" member="summaryPosition" label="SummaryPosition" /> 속성은 자식 수준 요약에만 적용됩니다. 루트 수준 요약은 항상 <ApiLink type="{ComponentName}" />의 아래쪽에 고정되어 나타납니다.
</DocsAside>

## 키보드 탐색

요약 행은 다음 키보드 상호 작용으로 탐색할 수 있습니다:

- <kbd>UP</kbd> - 한 셀 위로 이동합니다.
- <kbd>DOWN</kbd> - 한 셀 아래로 이동합니다.
- <kbd>LEFT</kbd> - 한 셀 왼쪽으로 이동합니다.
- <kbd>RIGHT</kbd> - 한 셀 오른쪽으로 이동합니다.
- <kbd>CTRL</kbd> + <kbd>LEFT</kbd> 또는 <kbd>HOME</kbd> - 가장 왼쪽 셀로 이동합니다.
- <kbd>CTRL</kbd> + <kbd>RIGHT</kbd> 또는 <kbd>END</kbd> - 가장 오른쪽 셀로 이동합니다.

가장 간단한 방법으로, <ApiLink type="function-grid-summary-theme" label="grid-summary-theme" kind="sass" module="index.html" />을(를) 확장하고 `$background-color`, `$focus-background-color`, `$label-color`, `$result-color`, `$pinned-border-width`, `$pinned-border-style` 및 `$pinned-border-color` 매개변수를 받는 새 테마를 만듭니다.

```scss
$custom-theme: grid-summary-theme(
    $background-color: #e0f3ff,
    $focus-background-color: rgba( #94d1f7, .3 ),
    $label-color: #e41c77,
    $result-color: black,
    $pinned-border-width: 2px,
    $pinned-border-style: dotted,
    $pinned-border-color: #e41c77
);
```

마지막 단계는 컴포넌트 믹스인을 **include**하는 것입니다:

```scss
@include grid-summary($custom-theme);
```

<DocsAside type="info">
컴포넌트가 [Emulated](../themes/styles.mdx#view-encapsulation) ViewEncapsulation을 사용한다면, `::ng-deep`를 사용하여 이 캡슐화를 `penetrate`해야 합니다:
</DocsAside>

 ```scss
:host {
    ::ng-deep {
        @include grid-summary($custom-theme);
    }
}
```

### 색상 팔레트 정의하기

방금 한 것처럼 색상 값을 하드코딩하는 대신, <ApiLink type="function-igx-palette" label="igx-palette" kind="sass" module="index.html" />와 <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" /> 함수를 사용하면 색상에 대해 더 큰 유연성을 얻을 수 있습니다.

`igx-palette`는 전달된 기본 색상과 보조 색상을 기준으로 색상 팔레트를 생성합니다:

```scss
$blue-color: #7793b1;
$green-color: #00ff2d;

$my-custom-palette: palette($primary: $blue-color, $secondary: $green-color);
```

그다음 <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" />로 팔레트에서 색상을 쉽게 가져올 수 있습니다.

```scss
$custom-theme: grid-summary-theme(
    $background-color: color($my-custom-palette, "primary", 700),
    $focus-background-color: color($my-custom-palette, "primary", 800),
    $label-color: color($my-custom-palette, "secondary", 500),
    $result-color: color($my-custom-palette, "grays", 900),
    $pinned-border-width: 2px,
    $pinned-border-style: dotted,
    $pinned-border-color: color($my-custom-palette, "secondary", 500)
);
```

<DocsAside type="info">
`igx-color`와 `igx-palette`는 색상을 생성하고 가져오는 강력한 함수입니다. 사용 방법에 대한 자세한 안내는 [팔레트](../themes/palettes.mdx) 항목을 참조하십시오.
</DocsAside>

### 스키마 사용하기

테마 엔진을 더 활용하여 [**스키마**](../themes/sass/schemas.mdx)의 이점을 얻는 견고하고 유연한 구조를 만들 수 있습니다. **스키마**는 테마의 레시피입니다.

모든 컴포넌트에 제공되는 사전 정의된 스키마 두 가지 중 하나를 확장하십시오. 이 경우에는 <ApiLink type="variable-_light-grid-summary" label="_light-grid-summary" kind="sass" module="index.html" />입니다:

```scss
// Extending the light grid summary schema
$my-summary-schema: extend($_light-grid-summary,
    (
        background-color: (igx-color: ('primary', 700)),
        focus-background-color: (igx-color: ('primary', 800)),
        label-color: (igx-color: ('secondary', 500)),
        result-color: (igx-color: ('grays', 900)),
        pinned-border-width: 2px,
        pinned-border-style: dotted,
        pinned-border-color: (igx-color: ('secondary', 500))
    )
);
```

사용자 지정 스키마를 적용하려면 전역(<ApiLink type="variable-light-schema" label="light" kind="sass" module="index.html" /> 또는 <ApiLink type="variable-dark-schema" label="dark" kind="sass" module="index.html" />) 중 하나를 **확장**해야 합니다. 이는 기본적으로 사용자 지정 스키마를 가진 컴포넌트를 지정하는 것이며, 그다음 해당 컴포넌트 테마에 추가합니다:

```scss
// Extending the global light-schema
$my-custom-schema: extend($light-schema,
    (
        igx-grid-summary: $my-summary-schema
    )
);

// Defining our custom theme with the custom schema
$custom-theme: grid-summary-theme(
    $palette: $my-custom-palette,
    $schema: $my-custom-schema
);
```

위에서 보여 드린 것과 같은 방식으로 테마를 포함하는 것을 잊지 마십시오.
