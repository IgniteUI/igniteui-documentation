# {Platform} {ComponentTitle} 필터링

{Platform} {ComponentTitle}의 {ProductName} 필터링은 특정 기준이나 조건에 따라 데이터를 선택적으로 표시하거나 숨길 수 있게 하는 기능입니다. <ApiLink type="{ComponentName}" /> 컴포넌트가 풍부한 필터링 API와 모든 필터링 기능을 제공하는 바인딩된 데이터 컨테이너가 있습니다. 여기서 사용할 수 있는 필터링 유형은 세 가지입니다:

- 빠른 필터링
- [Excel 스타일 필터링](excel-style-filtering.mdx)
- [고급 필터링](advanced-filtering.mdx)

## 설정

필터링을 활성화할지와 어떤 필터링 모드를 사용할지 지정하기 위해, <ApiLink type="{ComponentName}" />는 다음 속성을 노출합니다 - <ApiLink type="{ComponentName}" member="allowFiltering" />, <ApiLink type="{ComponentName}" member="allowAdvancedFiltering" />, <ApiLink type="{ComponentName}" member="filterMode" /> 및 <ApiLink type="Column" member="filterable" />.

<ApiLink type="{ComponentName}" member="allowFiltering" /> 속성을 사용하면 다음 옵션을 지정할 수 있습니다:
- **false** - 해당 그리드의 필터링이 비활성화됩니다. 이것이 기본값입니다.
- **true** - 해당 그리드의 필터링이 활성화됩니다.

<ApiLink type="{ComponentName}" member="allowAdvancedFiltering" /> 속성을 사용하면 다음 옵션을 지정할 수 있습니다:
- **false** - 해당 그리드의 고급 필터링이 비활성화됩니다. 이것이 기본값입니다.
- **true** - 해당 그리드의 고급 필터링이 활성화됩니다.

<ApiLink type="{ComponentName}" member="filterMode" /> 속성을 사용하면 다음 옵션을 지정할 수 있습니다:
- **QuickFilter** - 단순한 필터링 UI입니다. 이것이 기본값입니다.
- **ExcelStyleFilter** - Excel 같은 필터링 UI입니다.

<ApiLink type="Column" member="filterable" /> 속성을 사용하면 다음 옵션을 지정할 수 있습니다:
- **true** - 해당 열의 필터링이 활성화됩니다. 이것이 기본값입니다.
- **false** - 해당 열의 필터링이 비활성화됩니다.

## 상호 작용

특정 열의 필터 행을 열려면, 머리글 아래에 있는 'Filter' 칩을 클릭해야 합니다. 조건을 추가하려면 입력란 왼쪽의 드롭다운을 사용해 필터 피연산자를 선택하고 값을 입력하십시오. **숫자** 및 **날짜** 열에서는 기본적으로 'Equals'가 선택되고, **문자열** 열에서는 'Contains', **부울** 열에서는 'All'이 선택됩니다. 'Enter'를 누르면 조건이 확정되고 다른 조건을 추가할 수 있습니다. '조건' 칩 사이에는 칩 사이의 논리 연산자를 결정하는 드롭다운이 있으며, 기본값은 'AND'입니다. 조건을 제거하려면 칩의 'X' 버튼을 클릭하고, 수정하려면 칩을 선택하면 입력란에 칩의 데이터가 채워집니다. 필터 행이 열려 있는 동안에는 필터링 가능한 열의 머리글을 아무거나 클릭하여 선택하고 해당 열의 필터 조건을 추가할 수 있습니다.

열에 필터 조건이 적용되어 있고 필터 행이 닫혀 있을 때는, 칩의 닫기 버튼을 클릭하여 조건을 제거하거나, 칩 중 하나를 선택하여 필터 행을 열 수 있습니다. 모든 조건을 표시할 공간이 부족하면, 몇 개의 조건이 더 있는지 나타내는 배지가 붙은 필터 아이콘이 표시됩니다. 이 아이콘을 클릭해도 필터 행이 열립니다.

## 사용법

기본 필터링 전략과 모든 표준 필터링 조건이 기본으로 제공되며, 개발자는 이를 자신만의 구현으로 바꿀 수 있습니다. 또한 사용자 지정 필터링 조건을 쉽게 연결하는 방법도 제공합니다. <ApiLink type="{ComponentName}" />는 현재 단순한 필터링 UI뿐만 아니라 더 복잡한 필터링 옵션도 제공합니다. 열의 설정된 <ApiLink type="Column" member="dataType" />에 따라 올바른 **필터링 작업** 세트가 필터 UI 드롭다운에 로드됩니다. 또한 <ApiLink type="FilteringExpression" member="ignoreCase" label="IgnoreCase" /> 및 초기 <ApiLink type="BooleanFilteringOperand" member="condition" label="Condition" /> 속성을 설정할 수 있습니다.

<ApiLink type="{ComponentName}" /> 컴포넌트는 <ApiLink type="{ComponentName}" member="allowFiltering" /> 입력을 **true**로 설정하여 필터링 기능이 활성화됩니다. 기본 <ApiLink type="{ComponentName}" member="filterMode" />은 `QuickFilter`이며 실행 중에는 **변경할 수 없습니다**. 특정 열에 대해 이 기능을 비활성화하려면 <ApiLink type="Column" member="filterable" /> 입력을 **false**로 설정하십시오.

<PlatformBlock for="Angular, WebComponents">
<ApiLink type="{ComponentName}" /> API를 통해 어떤 열이든 또는 여러 열의 조합이든 필터링할 수 있습니다. <ApiLink type="{ComponentName}" />은(는) 이 작업을 위한 여러 메서드를 노출합니다 - <ApiLink type="Filter" />, `FilterGlobal` 및 `ClearFilter`.

- <ApiLink type="Filter" /> - 단일 열 또는 여러 열의 조합을 필터링합니다.

노출된 필터링 피연산자 클래스는 다섯 가지입니다:

- <ApiLink type="FilteringOperand" />: 사용자 지정 필터링 조건을 정의할 때 상속할 수 있는 기본 필터링 피연산자입니다.
- <ApiLink type="BooleanFilteringOperand" />는 **부울** 형식의 모든 기본 필터링 조건을 정의합니다.
- <ApiLink type="NumberFilteringOperand" />는 **숫자** 형식의 모든 기본 필터링 조건을 정의합니다.
- <ApiLink type="StringFilteringOperand" />는 **문자열** 형식의 모든 기본 필터링 조건을 정의합니다.
- <ApiLink type="DateFilteringOperand" />는 **날짜** 형식의 모든 기본 필터링 조건을 정의합니다.

```typescript
// Single column filtering

// Filter the `ProductName` column for values which `contains` the `myproduct` substring, ignoring case
this.grid.filter('ProductName', 'myproduct', IgcStringFilteringOperand.instance().condition('contains'), true);
```

필수 매개변수는 열 필드 키와 필터링 용어뿐입니다. 조건과 대소문자 구분은 제공되지 않으면 열 속성에서 추론됩니다. 여러 필터링의 경우, 이 메서드는 필터 식의 배열을 받습니다.


<DocsAside type="info">

</DocsAside>

## 초기 필터링 상태

<ApiLink type="{ComponentName}" />의 초기 필터링 상태를 설정하려면, 필터링할 각 열에 대해 <ApiLink type="{ComponentName}" /> <ApiLink type="FilteringExpressionsTree" /> 속성을 <ApiLink type="FilteringExpressionsTree" />의 배열로 설정하십시오.

constructor(private cdr: ChangeDetectorRef) { }

public ngAfterViewInit() {
    const gridFilteringExpressionsTree = new FilteringExpressionsTree(FilteringLogic.And);
    const productFilteringExpressionsTree = new FilteringExpressionsTree(FilteringLogic.And, 'ProductName');
    const productExpression = {
        condition: IgxStringFilteringOperand.instance().condition('contains'),
        fieldName: 'ProductName',
        ignoreCase: true,
        searchVal: 'c'

    gridFilteringExpressionsTree.filteringOperands.push(productFilteringExpressionsTree);

    this.@@igObjectRef.filteringExpressionsTree = gridFilteringExpressionsTree;
    this.cdr.detectChanges();
}

## 사용자 지정 필터링 피연산자

필터링 피연산자를 추가, 제거 또는 수정하여 필터링 메뉴를 사용자 지정할 수 있습니다. 기본적으로 필터링 메뉴에는 열의 데이터 유형(<ApiLink type="BooleanFilteringOperand" />, <ApiLink type="DateFilteringOperand" />, <ApiLink type="NumberFilteringOperand" /> 및 <ApiLink type="StringFilteringOperand" />)에 따른 특정 피연산자가 포함됩니다. 이 클래스들이나 그 기본 클래스인 <ApiLink type="FilteringOperand" />을(를) 확장하여 필터링 메뉴 항목의 동작을 바꿀 수 있습니다.

아래 샘플에서 “Product Name”과 “Discontinued” 열의 필터 메뉴를 살펴보십시오. “Discontinued” 열 필터는 피연산자를 All, True, False로 제한했습니다. “Product Name” 열 필터는 Contains 및 Does Not Contain 피연산자의 로직을 대소문자를 구분하는 검색으로 수정했고, Empty 및 Not Empty 피연산자도 추가했습니다.

이를 하려면 <ApiLink type="StringFilteringOperand" />과(와) <ApiLink type="BooleanFilteringOperand" />을(를) 확장하고, 작업과 그 논리를 수정한 다음, 열의 `filters` 입력을 새 피연산자로 설정하십시오.

export class GridCustomFilteringComponent {
    public caseSensitiveFilteringOperand = CaseSensitiveFilteringOperand.instance();
    public booleanFilteringOperand = BooleanFilteringOperand.instance();
}

export class CaseSensitiveFilteringOperand extends IgxStringFilteringOperand {
    private constructor() {
        super();
        const customOperations = [
            {
                iconName: 'contains',
                isUnary: false,
                logic: (target: string, searchVal: string, ignoreCase?: boolean) => {
                    ignoreCase = false;
                    const search = IgxStringFilteringOperand.applyIgnoreCase(searchVal, ignoreCase);
                    target = IgxStringFilteringOperand.applyIgnoreCase(target, ignoreCase);
                    return target.indexOf(search) !== -1;
                },
                name: 'Contains (case sensitive)'
            },
            {
                iconName: 'does_not_contain',
                isUnary: false,
                logic: (target: string, searchVal: string, ignoreCase?: boolean) => {
                    ignoreCase = false;
                    const search = IgxStringFilteringOperand.applyIgnoreCase(searchVal, ignoreCase);
                    target = IgxStringFilteringOperand.applyIgnoreCase(target, ignoreCase);
                    return target.indexOf(search) === -1;
                },
                name: 'Does Not Contain (case sensitive)'
            }
        ];

        const emptyOperators = [
            // 'Empty'
            this.operations[6],
            // 'Not Empty'
            this.operations[7]
        ];

        this.operations = customOperations.concat(emptyOperators);
    }
}

export class BooleanFilteringOperand extends IgxBooleanFilteringOperand {
    private constructor() {
        super();
        this.operations = [
            // 'All'
            this.operations[0],
            // 'TRUE'
            this.operations[1],
            // 'FALSE'
            this.operations[2]
        ];
    }
}

## 스타일링

필터링 행의 스타일 지정을 시작하려면, 모든 테마 함수와 컴포넌트 믹스인이 있는 `index` 파일을 import해야 합니다:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

가장 간단한 방법으로, `grid-theme`을(를) 확장하고 `$filtering-row-text-color`, `$filtering-row-background`, `$filtering-header-text-color` 및 `$filtering-header-background` 매개변수를 받는 새 테마를 만듭니다.

```scss
$custom-grid: grid-theme(
    $filtering-row-text-color: #292826,
    $filtering-row-background: #FFCD0F,
    $filtering-header-text-color: #292826,
    $filtering-header-background: #FFCD0F
);
```

보시다시피 `grid-theme`는 필터링 행과 필터링되고 있는 해당 열 머리글의 색상만 제어합니다. 필터링 행에는 입력 그룹, 칩, 버튼 등 훨씬 더 많은 컴포넌트가 있습니다. 이들의 스타일을 지정하려면 각각에 대해 별도의 테마를 만들어야 하므로, 새 입력 그룹 테마와 새 버튼 테마를 만들어 봅시다:

```scss
$dark-input-group: input-group-theme(
    $box-background: #FFCD0F,
    $idle-text-color: #292826,
    $focused-text-color: #292826,
    $filled-text-color: #292826
);

$dark-button: flat-button-theme(
    $background: #FFCD0F,
    $foreground: #292826,
    $hover-background: #292826,
    $hover-foreground: #FFCD0F
);
```

이 예제에서는 입력 그룹과 버튼의 일부 매개변수만 바꾸었지만, `input-group-theme`과 `flat-button-theme`은(는) 각 스타일을 제어하는 훨씬 더 많은 매개변수를 제공합니다.

마지막 단계는 각 컴포넌트 믹스인을 해당 테마와 함께 **include**하는 것입니다. 또한 입력란의 플레이스홀더 색상 속성도 설정합니다.

```scss
@include grid($custom-grid);
.igx-grid__filtering-row {
    @include button($dark-button);
    @include input-group($dark-input-group);

    .igx-input-group__input::placeholder {
        color: #FFCD0F;
    }
}
```

<DocsAside type="info">
**igx-button**과 **igx-input-group** 믹스인은 `.igx-grid__filtering-row` 안에 범위를 지정하여, 필터링 행의 버튼과 입력 그룹에만 스타일이 적용되도록 합니다. 그렇지 않으면 그리드의 다른 버튼과 입력 그룹도 영향을 받습니다.
</DocsAside>

 <DocsAside type="info">
 컴포넌트가 `Emulated` ViewEncapsulation을 사용한다면, `::ng-deep`를 사용하여 이 캡슐화를 `penetrate`해야 합니다:
 </DocsAside>

```scss
:host {
     ::ng-deep {
        @include grid($custom-grid);
        .igx-grid__filtering-row {
            @include button($dark-button);
            @include input-group($dark-input-group);

            .igx-input-group__input::placeholder {
                color: #FFCD0F;
            }
        }
    }
}
```

### 스키마 사용하기

테마 엔진을 더 활용하여 [스키마](../themes/sass/schemas.mdx)의 이점을 얻는 견고하고 유연한 구조를 만들 수 있습니다. **스키마**는 테마의 레시피입니다.

모든 컴포넌트에 제공되는 사전 정의된 스키마 두 가지 중 하나를 확장하십시오. 이 경우에는 `light-grid`, `light-input-group`, `light-button` 스키마입니다:

```scss
// Extending the light grid schema
$custom-grid-schema: extend($_light-grid,
    (
        filtering-row-text-color:(
           color: ("primary", 400)
        ),
        filtering-row-background:(
           color: ("secondary", 400)
        ),
        filtering-header-text-color:(
           color: ("primary", 400)
        ),
        filtering-header-background:(
           color: ("secondary", 400)
        )
    )
);

// Extending the light input group schema
$custom-input-group-schema: extend($_light-input-group,
    (
        box-background:(
           color: ("secondary", 400)
        ),
        idle-text-color:(
           color: ("primary", 400)
        ),
        focused-text-color:(
           color: ("primary", 400)
        ),
        filled-text-color:(
           color: ("primary", 400)
        )
    )
);

// Extending the light button schema
$custom-button-schema: extend($_light-button,
    (
        flat-background:(
           color: ("secondary", 400)
        ),
        flat-text-color:(
           color: ("primary", 400)
        ),
        flat-hover-background:(
           color: ("primary", 400)
        ),
        flat-hover-text-color:(
           color: ("secondary", 400)
        )
    )
);
```

사용자 지정 스키마를 적용하려면 전역(`light` 또는 `dark`) 중 하나를 **확장**해야 합니다. 이는 기본적으로 사용자 지정 스키마를 가진 컴포넌트를 지정하는 것이며, 그다음 해당 컴포넌트 테마에 추가합니다:

```scss
// Extending the global light-schema
$custom-light-schema: extend($light-schema,(
    igx-grid: $custom-grid-schema,
    igx-input-group: $custom-input-group-schema,
    igx-button: $custom-button-schema
));

// Defining grid-theme with the global light schema
$custom-grid: grid-theme(
  $schema: $custom-light-schema
);

// Defining flat-button-theme with the global light schema
$custom-button: flat-button-theme(
  $schema: $custom-light-schema
);

// Defining input-group-theme with the global light schema
$custom-input-group: input-group-theme(
  $schema: $custom-light-schema
);
```

위에서 보여 드린 것과 같은 방식으로 테마를 포함하는 것을 잊지 마십시오.

### 6.1.0의 호환성이 깨지는 변경 사항
- <ApiLink type="{ComponentName}" /> `filteringExpressions` 속성이 제거되었습니다. 대신 <ApiLink type="FilteringExpressionsTree" />을(를) 사용하십시오.
- `filter_multiple` 메서드가 제거되었습니다. 대신 <ApiLink type="Filter" /> 메서드와 <ApiLink type="FilteringExpressionsTree" /> 속성을 사용하십시오.
- <ApiLink type="Filter" /> 메서드는 새 시그니처를 가집니다. 이제 다음 매개변수를 받습니다:
  - <ApiLink type="Column" member="name" label="Name" /> - 필터링할 열의 이름입니다.
  - `Value` - 필터링에 사용할 값입니다.
  - `ConditionOrExpressionTree`(선택 사항) - 이 매개변수는 <ApiLink type="FilteringOperation" /> 또는 <ApiLink type="FilteringExpressionsTree" /> 유형의 객체를 받습니다. 단순 필터링만 필요하면 필터링 작업을 인수로 전달할 수 있습니다. 고급 필터링의 경우, 복잡한 필터링 로직을 담은 식 트리를 인수로 전달할 수 있습니다.
  - <ApiLink type="FilteringExpression" member="ignoreCase" label="IgnoreCase" />(선택 사항) - 필터링이 대소문자를 구분하는지 여부입니다.
- `FilteringDone` 이벤트는 이제 필터링된 열의 필터링 상태를 담은 <ApiLink type="FilteringExpressionsTree" /> 유형의 매개변수 하나만 가집니다.
- 필터링 피연산자: <ApiLink type="FilteringExpression" /> condition 속성은 더 이상 필터링 조건 메서드에 대한 직접 참조가 아니라, <ApiLink type="FilteringOperation" />에 대한 참조입니다.
- <ApiLink type="ColumnComponent" />은(는) 이제 <ApiLink type="FilteringOperand" /> 클래스 참조를 받는 <ApiLink type="Column" member="filters" label="Filters" /> 속성을 노출합니다.
- <ApiLink type="FilteringOperand" />의 <ApiLink type="BooleanFilteringOperand" member="operations" label="Operations" /> 속성을 <ApiLink type="FilteringOperation" /> 유형의 작업으로 채우면, {ComponentTitle} 열에 사용자 지정 필터를 제공할 수 있습니다.
