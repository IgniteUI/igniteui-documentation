## 부트스트랩 그리드 정의

{ProductName}에는 강력한 부트스트랩 그리드 같은 flex 기반 레이아웃 시스템이 포함되어 있습니다. 오늘날의 최신 애플리케이션은 반응형 웹 디자인 방식을 따라야 하며, 이는 기기 크기나 브라우저 크기 조정에 따라 HTML 요소의 레이아웃을 자연스럽게 조정할 수 있다는 뜻입니다. 과거에는 부트스트랩 그리드 레이아웃이 가장 많이 쓰였지만, 이제는 어떤 브라우저에서도 작동하는 CSS 그리드 같은 flex 기반 레이아웃 시스템이 더 널리 쓰이고 있습니다. {ProductName} 레이아웃 디렉티브는 콘텐츠/텍스트 줄바꿈, 정렬, 맞춤을 포함하여 세로 및 가로 흐름을 허용합니다. {ProductName} 그리드는 CSS를 사용하여 반응형 레이아웃을 지원하므로, 크기 조정 시 그리드의 동작을 가장 자유롭게 설정할 수 있습니다.

## 편집 가능한 {Platform} 그리드

그리드 편집의 각 작업에는 일괄 작업이 포함되어 있습니다. 즉 API를 사용하면 편집 내용을 하나의 서버 호출로 묶을 수 있으며, 그리드 상호 작용이 일어날 때마다 편집/업데이트 작업을 수행할 수도 있습니다. CRUD 작업이 가능한 편집 그리드로서의 훌륭한 개발자 경험과 함께, 그리드에는 Excel과 비슷한 키보드 탐색도 포함되어 있습니다. 일반적인 기본 그리드 탐색이 포함되어 있으며, 고객의 요구에 맞게 어떤 탐색 옵션이든 재정의할 수 있습니다. 훌륭한 탐색 방식을 갖춘 편집 가능한 그리드는 현대적인 업무용 애플리케이션에 필수적이며, Ignite UI 그리드를 사용하면 이것을 쉽게 구현할 수 있습니다.

이 항목을 따라가면 [셀 템플릿](./data-grid.mdx#셀-템플릿)과 [셀 편집 템플릿](./data-grid.mdx#셀-편집-템플릿), 그리고 편집에 대해 더 알아볼 수 있습니다.

```typescript
constructor() {
    var name = this.name = document.getElementById('name') as IgcColumnComponent;

    this._bind = () => {
        name.headerTemplate = this.nameHeaderTemplate;
    }

    this._bind();
}

public nameHeaderTemplate = (ctx: IgcColumnTemplateContext) => {
    return html`
        ${this.formatUppercase(ctx.column.field)}
    `;
}

public formatUppercase(value: string) {
    return value.toUpperCase();
}
```

```typescript
constructor() {
```

### 사용자 지정 표시 형식

서식 지정을 위한 선택적 매개변수가 있습니다:

- <ApiLink type="ColumnPipeArgs" member="format" label="Format" /> - 표시되는 날짜/시간 부분을 결정하며, 기본값은 `'mediumDate'`이고 **'MMM d, y'**와 같습니다
- <ApiLink type="ColumnPipeArgs" member="timezone" label="Timezone" /> - 날짜의 시간대 오프셋입니다. 기본적으로 최종 사용자의 로컬 시스템 시간대를 사용합니다
- <ApiLink type="ColumnPipeArgs" member="digitsInfo" label="DigitsInfo" /> - 소수 표현 객체입니다. 기본값은 **1.0-3**입니다

이 매개변수로 표시 형식을 사용자 지정할 수 있도록 <ApiLink type="Column" member="pipeArgs" label="PipeArgs" /> 입력이 노출되어 있습니다. <ApiLink type="Column" member="pipeArgs" label="PipeArgs" />가 설정되어 있다면, 열은 자신의 데이터 타입에 해당하는 속성만 따릅니다. 예:

## 그리드 데이터 구조

<ApiLink type="Grid" />은 **평면 데이터**와 중첩된 **POJO(Plain Old Java Objects)**를 처리합니다. 렌더링에 사용되는 데이터 구조는 다음 형태입니다:

```typescript
const OBJECT_ARRAY = [{
        ObjectKey1: value1,
        ObjectKey2: value2,
        // ...
        ObjectKeyN: valueN
    },
    // ...
  }];

const POJO = [{
        ObjectKey1: value1,
        ObjectKey2: value2,
        // ...
        ObjectKeyN: {
          ObjectKeyN1: value1,
          ObjectKeyN2: value2,
          // ...
          ObjectKeyNM: valueNM,
        }
    },
    // ...
  }];
```

>**경고**:
**키 값에는 배열이 포함되면 안 됩니다**.

><ApiLink type="GridBaseDirective" member="autoGenerate" label="AutoGenerate" /> 열을 사용하는 경우 **데이터 키가 동일해야 합니다.**

## 그리드 데이터 바인딩

{Platform} 데이터 그리드는 비교할 수 없이 뛰어난 데이터 바인딩 옵션을 제공하며, 실시간 업데이트와 부드러운 스크롤에 최적화되어 있습니다. 지연 시간이 짧은 렌더링을 통해 그리드는 실시간 스트리밍 데이터, 대용량 데이터 세트 등을 포함하여 모든 UI 변경을 즉시 표시합니다.

{Platform} 데이터 그리드를 더 사용하기 전에, 대규모 애플리케이션에서 흔한 시나리오인 원격 데이터 서비스에 바인딩하도록 그리드를 변경하겠습니다.

```typescript
// northwind.service.ts

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs/Observable';
import { of } from 'rxjs/observable/of';
```

`Injectable` 데코레이터를 가져오고 있으며, 이는 모든 {Platform} 서비스 정의의 [필수 요소](https://angular.io/guide/dependency-injection)입니다. `HttpClient`는 백엔드 서비스와 통신하는 기능을 제공합니다. 이는 그리드 컴포넌트에서 구독할 결과의 `Observable`를 반환합니다.

**참고**: Angular 5 이전에는 `HttpClient`가 `@angular/http`에 있었고 `Http`라는 이름이었습니다.

레코드 배열을 담은 JSON 응답을 받게 되므로, 올바른 형태의 인터페이스를 정의하여 Observable에서 어떤 종류의 데이터가 반환될지 명시하면 도움이 됩니다. 타입 검사는 항상 권장되며, 나중에 많은 문제를 막아 줄 수 있습니다.

```typescript
// northwind.service.ts

export interface NorthwindRecord {
    ProductID: number;
    ProductName: string;
    SupplierID: number;
    CategoryID: number;
    QuantityPerUnit: string;
    UnitPrice: number;
    UnitsInStock: number;
    UnitsOnOrder: number;
    ReorderLevel: number;
    Discontinued: boolean;
    CategoryName: string;
}
```

서비스 자체는 간단하며, `FetchData` 메서드 하나로 구성되어 `Observable<NorthwindRecord[]>`를 반환합니다. 요청이 어떤 이유로든 실패하면(서버 사용 불가, 네트워크 오류 등) `HttpClient`는 오류를 반환합니다. 실패한 Observable을 가로채 오류를 오류 핸들러로 전달하는 `CatchError` 연산자를 활용하겠습니다. 오류 핸들러는 오류를 기록하고 안전한 값을 반환합니다.

```typescript
// northwind.service.ts

@Injectable()
export class NorthwindService {
    private url = 'http://services.odata.org/V4/Northwind/Northwind.svc/Alphabetical_list_of_products';

    constructor(private http: HttpClient) {}

    public fetchData(): Observable<NorthwindRecord[]> {
        return this.http
            .get(this.url)
            .pipe(
                map(response => response['value']),
                catchError(
                    this.errorHandler('Error loading Northwind data', [])
                )
            );
    }

    private errorHandler<T>(message: string, result: T) {
        return (error: any): Observable<any> => {
            console.error(`${message}: ${error.message}`);
            return of(result as T);
        };
    }
}
```

애플리케이션 모듈에서 `HttpClientModule`과 우리의 서비스를 모두 import하고, 서비스를 provider로 등록해야 합니다.

```typescript
// app.module.ts

import { HttpClientModule } from '@angular/common/http';
import { NorthwindService } from './northwind.service';

@NgModule({
    imports: [
        HttpClientModule
    ],
    providers: [
        NorthwindService
    ]
})
export class AppModule {}
```

서비스를 구현한 후에는 컴포넌트의 생성자에 주입하여 데이터를 가져오는 데 사용합니다. `ngOnInit` 수명 주기 훅은 초기 요청을 보내기에 좋은 위치입니다.

**참고**: 아래 코드에서 서비스를 구독하기 전에 _records_ 속성을 빈 배열로 설정하는 이유가 궁금할 수 있습니다. Http 요청은 비동기이며, 완료될 때까지 _records_ 속성은 *undefined*이므로, 그리드가 이에 바인딩하려고 할 때 오류가 발생합니다. 기본값으로 초기화하거나 `BehaviorSubject`를 사용해야 합니다.

```typescript
// my.component.ts

@Component({

})
export class MyComponent implements OnInit {

    public records: NorthwindRecord[];

    constructor(private northwindService: NorthwindService) {}

    ngOnInit() {
        this.records = [];
        this.northwindService.fetchData().subscribe((records) => this.records = records);
    }
}
```

## 성능(실험적)

<ApiLink type="GridToolbar" member="grid" label="Grid" />의 설계는 Angular가 도입한 이벤트 병합(Event Coalescing) 기능을 활용할 수 있도록 되어 있습니다. 이 기능은 상호 작용과 반응성 측면에서 대략 **20%** 정도 성능을 향상시킵니다. 이 기능은 애플리케이션 수준에서 `bootstrapModule` 메서드의 `ngZoneEventCoalescing` 및 `ngZoneRunCoalescing` 속성을 **true**로 설정하여 간단히 활성화할 수 있습니다:

```typescript
platformBrowserDynamic()
  .bootstrapModule(AppModule, { ngZoneEventCoalescing: true, ngZoneRunCoalescing: true })
  .catch(err => console.error(err));
```

<DocsAside type="info">
이는 `IgxGridComponent`에 대해 아직 실험적인 기능입니다. 따라서 그리드에서 예기치 않은 동작이 있을 수 있습니다. 그러한 동작을 만나면 [Github]({GithubLink}/discussions) 페이지를 통해 문의해 주십시오.
</DocsAside>

<DocsAside type="info">
이를 활성화하면 `IgxGridComponent`과 관련 없는 Angular 애플리케이션의 다른 부분에도 영향을 줄 수 있습니다.
</DocsAside>

## 알려진 제한 사항

|제한 사항|설명|
|--- |--- |
|`percentage`과 `px`에서 설정한 열 너비|현재 `%`과 `px`의 열 너비를 섞어 사용하는 것은 지원하지 않습니다.|
|`number` 타입의 열을 필터링하려고 할 때|필터링 입력에 `number`이(가) 아닌 값을 입력하면, 잘못된 캐스트 때문에 `NaN`이(가) 반환됩니다.|
|그리드 `width`은(는) 열 너비에 의존하지 않습니다 | 모든 열의 `width`은(는) 그리드 자체의 범위를 결정하지 않습니다. 그리드의 범위는 상위 컨테이너의 크기 또는 정의된 그리드의 `width`에 의해 결정됩니다.|
|상위 컨테이너에 중첩된 그리드 | 그리드의 `width`이(가) 설정되지 않고 크기가 정의된 상위 컨테이너에 배치되면, 그리드는 이 컨테이너 크기만큼 펼쳐집니다.|
| 열에는 허용되는 최소 열 너비가 있습니다. `--ig-size` CSS 변수에 따라 다음과 같습니다: <br/>"small": 56px <br/> "medium": 64px <br/> "large ": 80px | 허용되는 최소 너비보다 작은 너비를 설정하면 렌더링되는 요소에 영향을 주지 않습니다. 해당 `--ig-size`의 최소 허용 너비로 렌더링됩니다. 이는 가로 가상화에서 예상치 못한 동작을 일으킬 수 있으므로 지원되지 않습니다.
| 행 높이는 현재 보기에 렌더링되지 않은 셀의 높이에 영향을 받지 않습니다. | 가상화 때문에 보기에 없는 열의 사용자 지정 템플릿(셀 높이를 바꾸는 템플릿)은 행 높이에 영향을 주지 않습니다. 행 높이는 관련 열이 보기에서 스크롤될 때만 영향을 받습니다.
