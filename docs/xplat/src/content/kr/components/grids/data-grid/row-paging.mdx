# {Platform} 그리드/테이블 페이지 나누기

표 형식의 테이블 UI는 많은 웹 제품에서 흔히 사용됩니다. 하지만 처음부터 표 UI를 만드는 것은 쉽지 않습니다. 반면 {ProductName} 그리드에서는 테이블 UI를 만드는 것이 간단하고, 많은 양의 로컬 또는 원격 데이터를 {Platform} 그리드에 바인딩하는 것도 쉽습니다. 그리드는 기본적으로 가상화되어 있으므로, 대용량 데이터 세트를 표시하기 위해 테이블 페이지 나누기를 포함할 필요가 없습니다. 테이블 페이지 나누기는 주로 복잡한 데이터를 UI에서 가장 효율적으로 정리하는 방법으로 사용됩니다. 테이블 페이지 나누기를 사용하면 데이터를 정해진 행 수로 표시할 수 있어, 실제 스크롤바 없이도 사용자가 데이터를 "넘겨" 볼 수 있습니다. 테이블 페이지 나누기의 UI에는 보통 현재 페이지, 전체 페이지 수, 그리고 사용자가 페이지를 넘길 수 있는 클릭 가능한 이전/다음 화살표 또는 버튼이 포함되며, 이는 다음과 같습니다:

{ProductName} 데이터 테이블/데이터 그리드에서 행 페이징은 `IsPagerVisible` 속성을 설정하여 활성화합니다. 또한 `PageSize`를 설정하여 보이는 행의 최대 개수를 제한할 수 있습니다.

## 개요

UX 관점에서 테이블 페이지 나누기에는 장단점이 있습니다. UX Matters의 [최근 기사](https://www.uxmatters.com/mt/archives/2018/11/paging-scrolling-and-infinite-scroll.php)에 따르면, 테이블 페이지 나누기의 장단점은 다음과 같습니다.

테이블 페이징의 장점:

- 사용자의 선택을 제한합니다
- 클릭 수를 측정할 수 있습니다

테이블 페이징의 단점:

- 사용자는 여전히 스크롤해야 합니다
- 페이저는 사이트마다 작동 방식과 동작이 다릅니다
- UI 컨트롤이 너무 많으면 혼란스러울 수 있습니다
- 사용자는 페이징을 느리고 번거롭다고 느낍니다
- 사용자가 페이지 나누기 컨트롤을 알아채지 못할 수 있습니다
- 페이지 로딩이 느릴 수 있습니다
- 사용자는 작업이 페이지에 적용되는지 전체 데이터 세트에 적용되는지 헷갈릴 수 있습니다

{ProductName} 데이터 그리드에는 페이징을 추가할 수 있습니다. 하지만 데이터 그리드는 기본적으로 무한 스크롤을 내장하고 있으므로, 페이저를 추가하기보다는 무한(또는 가상) 스크롤을 권장합니다. 가상화된 무한 스크롤을 기본 사용자 경험으로 삼으면 다음과 같은 이점이 있습니다:

- 스크롤 상호 작용을 통해 한 번에 '페이지'로 나뉘는 데이터의 양을 제어하면서도 최고의 성능을 제공합니다
- 모든 콘텐츠를 스크롤하는 자연스러운 방식입니다
- 모든 상호 작용이 최종 사용자에게 명확합니다
- 모바일 UX의 자연스러운 상호 작용과 일치합니다

## {Platform} 그리드/페이지 동기화

사용자가 정렬이나 그룹화와 같이 그리드와 상호 작용하고 그리드에 {Platform} 페이저를 활성화했다면, {Platform} 페이징 데이터가 {Platform} 테이블 표시와 동기화되도록 다음 함수를 사용해야 합니다.

- applySorts
- applyGroups
- applyFilters

## API 참조

- `DataGrid`
- `IsPagerVisible`
- `PageSize`
