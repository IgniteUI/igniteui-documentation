## Ignite UI CLI 사용하기

처음부터 애플리케이션을 만들고 Ignite UI React를 사용하도록 구성하려면 Ignite UI CLI를 사용할 수 있습니다. 첫 단계는 다음과 같이 해당 패키지를 전역으로 설치하는 것입니다:

```cmd
npm install -g igniteui-cli
```

사용 가능한 옵션을 안내받으며 진행하려면 새 애플리케이션을 만들고 설정하는 데 도움이 되는 단계별 모드를 시작할 수 있습니다. 안내를 시작하려면 `ig` 명령을 실행하면 됩니다:

```cmd
ig
```

그다음 프레임워크로 `\React`를, 프로젝트 유형으로 `Ignite UI for React TS`를 선택하십시오. 탐색 레이아웃으로 시작하려면 **Side Navigation** 또는 **Side Navigation Mini**를 선택하십시오. 둘 중 하나의 탐색 템플릿을 선택하면 마법사가 인증을 추가할지 묻습니다. **Empty** 템플릿에서는 인증 옵션이 나타나지 않습니다. 그런 다음 특정 컴포넌트/뷰를 추가하거나 `Complete & Run`를 선택할 수 있습니다.

또는 한 명령으로 프로젝트를 직접 만들 수도 있습니다. 예:

```cmd
ig new <project-name> --framework=react --type=igr-ts --template=side-nav
```

마법사와 인증 추가 기능 흐름에 대한 단계별 안내는 [Ignite UI CLI 사용 단계별 가이드](./general-step-by-step-guide-using-cli.mdx)를 참조하십시오. 모든 CLI 명령, 템플릿 ID, 직접 인증 템플릿 사용법의 전체 참조는 [CLI 개요](./general-cli-overview.mdx)를 참조하십시오.

프롬프트 중에 Grid 컴포넌트를 추가했다면, 애플리케이션이 실행된 후 다음과 비슷한 화면이 보일 것입니다:

## Vite CLI 사용하기

### 새 React 프로젝트 만들기

React 개발을 위한 모든 인기 프레임워크는 React 애플리케이션을 스캐폴딩하는 강력한 CLI 도구를 제공합니다.

1 - **VS Code**를 열고 **터미널** 메뉴에서 **새 터미널** 옵션을 선택하십시오.

2 - 터미널 창에 다음 명령을 입력하십시오:

```cmd
npm create vite@latest
```

그다음 안내에 따라 프로젝트 이름을 정하고, 프레임워크로 React를, TypeScript 사용 여부와 Vite가 제공하는 기타 여러 옵션을 선택하십시오. React 애플리케이션의 기본 구조를 만드는 여러 방법에 대한 자세한 내용은 이 <a href="https://react.dev/learn/creating-a-react-app" target="_blank">항목</a>을 참조하십시오.

### Ignite UI React 그리드 컴포넌트 추가하기

#### 패키지 설치
앱에 Ignite UI React [**Grid**](./grids/data-grid.mdx) 컴포넌트를 추가하려면 `igniteui-react-grids` 패키지를 설치해야 합니다:

```cmd
npm install igniteui-react-grids --save
```

#### 컴포넌트 모듈 가져오기

그다음 사용하려는 컴포넌트의 필요한 모듈을 가져올 수 있습니다. 템플릿에서도 사용할 Grid와 Column 컴포넌트에 대해 이를 수행합시다. 또한 테마 중 하나도 가져와야 합니다.

```ts
import { IgrGrid, IgrColumn } from 'igniteui-react-grids';
import 'igniteui-react-grids/grids/themes/light/bootstrap.css';
```

#### 컴포넌트 사용하기

이제 마크업에서 {ProductName} 그리드 컴포넌트를 사용할 준비가 되었습니다! 그리드를 정의해 보겠습니다:

```tsx
// App.tsx
function App() {
  const data = [
    { name: "John", age: 30 },
    { name: "Jane", age: 25 },
    { name: "Bob", age: 35 }
  ];

  return (
    <div style={{ height: "100%", width: "100%" }}>
      <IgrGrid
        data={data}
        autoGenerate={false}>
        <IgrColumn
          field="name"
          header="Name"
          dataType="string">
        </IgrColumn>
        <IgrColumn
          field="age"
          header="Age"
          dataType="number">
        </IgrColumn>
      </IgrGrid>
    </div>
  );
}
```

## 폴리필 설치

## Ignite UI for Web Components 설치
애플리케이션에서 Ignite UI Web Components를 사용하려면 `igniteui-webcomponents` 패키지를 설치해야 합니다:

```cmd
npm install igniteui-webcomponents
```

다음으로 `\index.ts` 파일에서 사용하려는 컴포넌트를 가져와야 합니다. `\defineComponents` 함수를 사용하여 다음과 같이 하나 이상의 컴포넌트를 가져올 수 있습니다:

```ts
import { defineComponents, IgcAvatarComponent, IgcBadgeComponent } from 'igniteui-webcomponents';

defineComponents(IgcAvatarComponent, IgcBadgeComponent);
```

`\defineAllComponents` 함수를 사용하여 모든 컴포넌트를 가져올 수도 있습니다:

```ts
import { defineAllComponents } from 'igniteui-webcomponents';

defineAllComponents();
```

<DocsAside type="info">
모든 컴포넌트를 가져오면 애플리케이션의 번들 크기가 늘어납니다. 그래서 실제로 사용하는 컴포넌트만 가져오는 것을 권장합니다.
</DocsAside>

마지막 단계는 컴포넌트의 스타일이 올바르게 적용되도록 필요한 CSS를 가져오는 것입니다:

```ts
import 'igniteui-webcomponents/themes/light/bootstrap.css';
```

컴포넌트를 가져온 후에는 HTML에서 사용할 수 있습니다:

```html
<igc-avatar initials="AZ"></igc-avatar>
<igc-badge></igc-badge>
```

## 차트 및 지도 패키지 설치

### 1단계 - Web Component 프로젝트 만들기

1 - 명령줄을 열고 **wc-html**이라는 디렉터리를 만드십시오

```cmd
mkdir wc-html
```

2 - 명령줄 경로를 새로 만든 디렉터리로 변경하십시오

```cmd
cd wc-html
```

3 - 디렉터리에서 **npm**을 초기화하십시오

```cmd
npm init -y
```

4 - **webpack** 번들러와 **webpack cli**를 개발 종속성으로 설치하십시오

```cmd
npm install webpack webpack-cli --save-dev
```

<DocsAside type="info">
Webpack은 모듈 번들러입니다. 주된 목적은 브라우저에서 사용할 JavaScript 파일을 번들링하는 것이지만, 거의 모든 리소스나 자산을 변환, 번들링, 패키징할 수도 있습니다.
</DocsAside>

5 - **VS Code**에서 프로젝트를 여십시오

```cmd
code .
```

6 - 다음 코드로 **index.html**이라는 새 파일을 만드십시오:

```html
<html>
    <head>
        <title>Getting Started with Ignite UI for Web Components</title>
    </head>
    <body>

    </body>
</html>
```

7 - **src**라는 새 폴더를 만들고, 그 안에 **index.js**라는 새 파일을 만드십시오. 프로젝트 구조는 다음과 같아야 합니다:

<Image src={wcProject} alt="wc-project" />

8 - **webpack**을 사용하는 빌드 스크립트를 포함하도록 **package.json** 파일을 업데이트하십시오

```json
  "scripts": {
    "build": "webpack ./src/index.js -o ./dist/ --output-filename index.bundle.js"
  },
```

<DocsAside type="info">
이 스크립트는 webpack을 사용하여 **index.js** 파일을 **index.bundle.js**라는 다른 파일로 번들링하고, 이를 **dist**라는 폴더에 넣습니다.

빌드 중 **JavaScript heap out of memory** 문제가 발생하면, 대신 다음 빌드 명령을 사용하여 힙 크기를 늘릴 수 있습니다:
</DocsAside>

```json
"scripts": {
    "build": "node --max_old_space_size=8192 node_modules/webpack/bin/webpack src/index.js -o dist/index.bundle.js"
},
```

### 3단계 - Ignite UI for Web Components와 lit-html 설치

1 - **npm**을 사용하여 Ignite UI for Web Component를 설치하십시오. 이 예제에서는 Map Web Component를 설치합니다:

```cmd
npm install --save {PackageCore}
npm install --save {PackageCharts}
npm install --save {PackageMaps}
npm install lit-html
```

2 - **index.js** 파일에서 지리 맵 모듈과 **ModuleManager**를 가져오십시오:

```ts
import { IgcGeographicMapModule } from 'igniteui-webcomponents-maps';
import { IgcDataChartInteractivityModule } from 'igniteui-webcomponents-charts';
// module manager for registering the modules
import { ModuleManager } from 'igniteui-webcomponents-core';
```

3 - **ModuleManager**를 사용하여 지리 맵 모듈을 등록하십시오

```ts
ModuleManager.register(
    IgcGeographicMapModule,
    IgcDataChartInteractivityModule
);
```

4 - **index.html** 파일의 body에 지리 맵 웹 컴포넌트를 추가하십시오

```html
<body>
    <igc-geographic-map id="map" height="500px" width="100%">
    </igc-geographic-map>
</body>
```

### 4단계 - Web Component 프로젝트 빌드 및 실행

1 - **VS Code**에서 터미널을 열고 **build** 스크립트를 실행하십시오

```cmd
npm run build
```

<DocsAside type="info">
이 명령은 앞서 만든 빌드 스크립트를 실행합니다. 빌드 스크립트는 **dist**라는 폴더에 **index.bundle.js**이라는 파일을 생성합니다
</DocsAside>

2 - **index.html** 파일의 **body** 요소 끝에 **index.bundle.js** 스크립트를 추가하십시오.

```html
<body>
    <igc-geographic-map id="map" height="500px" width="100%">
    </igc-geographic-map>

    <script src="dist/index.bundle.js"></script>
</body>
```

3 - 프로젝트를 실행하려면 로컬 개발 서버를 시작하십시오. 이 예제에서는 Live Server를 사용합니다. **index.html** 편집기 안에서 마우스 오른쪽 버튼을 클릭하고 **Live Server로 열기**를 선택하십시오

## Ignite UI for Blazor 설치

Ignite UI for Blazor는 NuGet 패키지로 제공됩니다. [Infragistics NuGet 피드](./general-nuget-feed.mdx)에서 **IgniteUI.Blazor**를, 또는 [NuGet.org](https://www.nuget.org/packages/IgniteUI.Blazor.Trial)에서 **IgniteUI.Blazor.Trial**을 설치하십시오.

WebAssembly 또는 Auto 렌더 모드의 Blazor Web App에서는 클라이언트 프로젝트에 설치하면 충분하며, 서버 프로젝트는 프로젝트 참조를 통해 이를 가져옵니다.

NuGet을 사용하여 Ignite UI for Blazor를 설치하는 자세한 방법은 [Ignite UI for Blazor 설치](./general-installing-blazor.mdx) 항목을 읽어 보십시오.

## Ignite UI for Blazor 등록

1 - **Program.cs** 파일을 열고 **builder.Services.AddIgniteUIBlazor** 함수를 호출하여 Ignite UI for Blazor 서비스를 등록하십시오. WebAssembly 또는 Auto 렌더 모드의 Blazor Web App에서는 서버 프로젝트와 클라이언트 프로젝트 모두의 **Program.cs**에서 이 작업을 수행하십시오:

```csharp
builder.Services.AddIgniteUIBlazor();
```

2 - **_Imports.razor** 파일에 **IgniteUI.Blazor.Controls** 네임스페이스를 추가하십시오(클라이언트 프로젝트가 있으면 두 프로젝트 모두에서):

```razor
@using IgniteUI.Blazor.Controls
```

3 - **Components/App.razor** 파일의 **`<head>`** 요소에 스타일시트를 추가하십시오:

```razor
<head>
    <link rel="stylesheet" href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" />
</head>
```

.NET 9 이상 애플리케이션에서는 **Assets** 컬렉션 속성을 사용하는 것을 권장합니다:

```razor
<head>
    <link rel="stylesheet" href="@Assets["_content/IgniteUI.Blazor/themes/light/bootstrap.css"]" />
</head>
```

4 - **Components/App.razor** 파일에서 Blazor 스크립트 앞에 스크립트 참조를 추가하십시오. **Assets**를 통하지 않고 직접 참조하십시오:

```razor
<script src="_content/IgniteUI.Blazor/app.bundle.js"></script>
<script src="@Assets["_framework/blazor.web.js"]"></script>
```

### 컴포넌트 모듈

대부분의 앱에는 `builder.Services.AddIgniteUIBlazor()`를 호출하는 것으로 충분합니다. 각 컴포넌트는 처음 렌더링될 때 클라이언트 리소스를 로드합니다. 다음을 위해서는 모듈을 명시적으로 등록하십시오:

- 컴포넌트가 처음 렌더링되기 전, 앱이 시작될 때 컴포넌트의 리소스를 준비해 두기;
- JavaScript 템플릿 등으로 클라이언트에서만 생성되는 컴포넌트를 사용하기(이 경우 Razor 컴포넌트가 해당 모듈을 요청하지 않습니다);
- 어떤 컴포넌트도 단독으로 요청하지 않는 기능(예: 차트 상호 작용(<ApiLink raw type="DataChartInteractivityModule" />) 또는 `*FullModule` 번들)을 활성화하기. 이 모두는 **{PackageCore}** 패키지에 있습니다.

`\AddIgniteUIBlazor`에 모듈을 나열하면 Ignite UI 런타임이 시작될 때 모듈을 로드합니다:

```csharp
builder.Services.AddIgniteUIBlazor(
    typeof(IgbBadgeModule),
    typeof(IgbDataChartInteractivityModule)
);
```

또는 주입된 런타임을 통해 나중에 모듈을 등록하십시오:

```razor
@inject IIgniteUIBlazor IgniteUIBlazor

@code {
    protected override void OnInitialized()
    {
        IgbBadgeModule.Register(IgniteUIBlazor);
    }
}
```

## 네임스페이스 선언하기

각 컨트롤 패키지는 자체 네임스페이스에 있으며, XAML 파일은 사용하는 네임스페이스를 선언합니다. WinUI와
Uno Platform은 `using:` 형식을 사용합니다:

```xml

<Window
    xmlns:ig="using:Infragistics.Controls"
    xmlns:igCharts="using:Infragistics.Controls.Charts"
    xmlns:igDataGrids="using:Infragistics.Controls.Grids"
    xmlns:igGauges="using:Infragistics.Controls.Gauges"
    xmlns:igMaps="using:Infragistics.Controls.Maps"
    xmlns:igDashboards="using:Infragistics.Controls.Dashboards"
    xmlns:igInputs="using:Infragistics.Controls.Inputs"
    xmlns:igLayouts="using:Infragistics.Controls.Layouts">
</Window>

```

파일이 실제로 사용하는 네임스페이스만 필요합니다. 이 항목들의 모든 코드 조각은 이 접두사로 작성되므로, `igDataGrids:XamDataGrid`를 보여 주는 조각에는 위의 `\igDataGrids` 선언이 필요합니다.

## 첫 번째 컴포넌트 추가하기

패키지가 설치되고 네임스페이스가 선언되면, 컨트롤은 다른 마크업과 같은 마크업입니다. 위에서 선언한 `\igGauges` 접두사를 사용하여 창에 방사형 게이지를 추가하는 예입니다:

```json-snippet source="/gauges/radial-gauge/needle"
{
    "type": "RadialGauge",
    "name": "gauge",
    "value": 50,
    "minimumValue": 0,
    "maximumValue": 80,
    "interval": 10
}
```

프로젝트를 실행하면 게이지가 50 값에서 척도, 눈금 표시, 바늘을 그립니다. 각 컨트롤의 항목은 이와 같은 블록에서 시작하여 해당 항목이 다루는 속성을 추가합니다.

# {ProductName} 시작하기

{ProductName}는 자체 패키지 세트를 통해 Uno Platform에서 실행됩니다. 컨트롤, 속성, XAML은 WinUI 항목에서 보여 주는 것과 같습니다. 차이점은 프로젝트를 만드는 방법과 존재하는 패키지입니다.

## 사전 요구 사항

Uno Platform은 단일 Visual Studio 워크로드가 아니라 자체 솔루션 템플릿과 자체 필수 구성 요소 검사를 가지고 있으며, 둘 다 이 항목이 다룰 수 있는 것보다 빠르게 변합니다. Uno Platform
[시작하기](https://platform.uno/docs/articles/get-started.html) 안내를 따라 프로젝트를 만들고 `uno-check`를 실행한 다음, 여기로 돌아와 {ProductName}를 추가하십시오.

WebAssembly 헤드는 대신 `Infragistics.Uno.Wasm.*` 패키지를 사용합니다: **Infragistics.Uno.Wasm.Core**,

라이선스 사용자는 Infragistics 비공개 NuGet 피드에서 이 패키지를 가져옵니다. Visual Studio에서 **도구** → **NuGet 패키지 관리자** → **패키지 관리자 설정**에서 패키지 원본으로 추가하고, 원본을 `https://packages.infragistics.com/nuget/licensed/v3/index.json`로 설정하십시오.

## 독립형 Blazor WebAssembly 앱

**Blazor WebAssembly Standalone App** 템플릿(`dotnet new blazorwasm`)으로 만든 앱에서는 모든 컴포넌트가 대화형이므로 렌더 모드가 필요하지 않습니다. 다음 차이점을 제외하고 위 단계를 따르십시오:

- **wwwroot/index.html** 파일의 **`<head>`** 요소에 스타일시트를 추가하십시오.
- 4단계의 스크립트 참조는 건너뛰십시오.

## 기존 Blazor Server 앱

.NET 8 이전에 **Blazor Server App** 템플릿으로 만든 앱은 여전히 지원되지만, Microsoft는 Blazor Web App을 권장합니다([Blazor Server 앱을 Blazor Web App으로 변환하기](https://learn.microsoft.com/aspnet/core/migration/70-to-80#convert-a-blazor-server-app-into-a-blazor-web-app) 참조). 변환하기 전까지는 렌더 모드가 필요하지 않습니다. 다음 차이점을 제외하고 위 단계를 따르십시오:

- **Pages/_Host.cshtml** 파일(.NET 6에서는 **Pages/_Layout.cshtml**)의 **`<head>`** 요소에 스타일시트를 추가하십시오.
- 4단계의 스크립트 참조는 건너뛰십시오.
