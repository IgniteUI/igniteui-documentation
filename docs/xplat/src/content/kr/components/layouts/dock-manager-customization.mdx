## {Platform} Dock Manager 사용자 지정

Infragistics {Platform} Dock Manager 컴포넌트는 특정 애플리케이션 요구 사항에 맞게 레이아웃을 더 사용자 지정하는 데 필요한 속성을 제공합니다.
{Platform} DockManager로 탁월한 사용자 인터페이스를 만들고 애플리케이션의 생산성을 높이는 방법을 살펴보겠습니다!

## 근접 도킹

이 모드에서는 조이스틱 표시기가 숨겨지며, 패널을 다른 패널의 가장자리에 가까이 끌어서 도킹할 수 있습니다. 패널을 끄는 동안 마우스 커서가 도킹 위치에 해당하는 영역에 도달하면 도킹 미리 보기가 표시됩니다. 마우스 버튼을 놓으면 끌던 패널이 미리 보기된 위치에 도킹됩니다. 근접 도킹을 사용하려면 `proximityDock` 속성을 **true**로 설정하기만 하면 됩니다.

```ts
this.dockManager.proximityDock = true;
```

### 내부 도킹

끌고 있는 패널 1을 패널 2의 오른쪽에 도킹하려면 커서가 패널 2의 오른쪽 테두리와 왼쪽으로 이동한 오른쪽 테두리 오프셋으로 정의된 영역 안에 있어야 합니다. 오프셋 거리는 근접 도킹 임계값으로 지정되며 50px로 설정되어 있습니다. 스플리터가 있는 경우에는 스플리터의 양쪽에서 도킹할 수 있습니다.

### 외부 도킹
외부 도킹을 수행하려면 먼저 특정 조건을 충족해야 합니다. Dock Manager에서 외부 도킹은 문서 호스트 안에서만 허용되므로, 대상 패널을 문서 호스트의 외곽 영역에 도킹하게 됩니다.

예를 들어 위쪽 외부 도킹을 수행하려면 끌고 있는 패널이 문서 호스트의 위쪽 테두리와 위쪽 테두리 오프셋 안에 정의된 영역 안에 있어야 합니다. 오프셋 거리는 근접 도킹 외부 임계값으로 지정되며 25px로 명시적으로 설정되어 있습니다. 근접 도킹 임계값인 50px은 변경되지 않으므로, 이 시나리오에서는 내부 도킹에 25px 영역만 사용할 수 있습니다. 문서 호스트 안에 스플리터가 있는 경우에는 스플리터의 양쪽에서 외부 도킹을 수행할 수 있습니다.

> 참고: 근접 도킹이 활성화되면 사용자는 하나의 패널에서 왼쪽과 오른쪽, 위쪽과 아래쪽 위치에 대한 외부 도킹을 모두 수행할 수 없습니다. 예를 들어 두 개의 분할 패널이 스플리터로 나뉘어 있는 경우, 끌고 있는 패널이 왼쪽 분할 패널 위에 있을 때는 외부 왼쪽 도킹만 수행할 수 있으며, 그 반대도 마찬가지입니다.

## 프로그래밍 방식으로 패널에 포커스 주기

`focusPane` 메서드를 사용하면 원하는 패널의 `contentId`을(를) 제공하여 레이아웃 안의 특정 패널에 동적으로 프로그래밍 방식으로 포커스를 줄 수 있습니다.

```ts
this.dockManager.focusPane('content1');
```

`focusPane` 메서드를 사용하면 대상 패널의 상태에 따라 동작이 달라집니다. 동작 방식은 다음과 같습니다:

1. **부동 패널**: 패널이 부동 상태이면 `focusPane`을(를) 호출할 때 패널에 포커스가 주어지고, activePane으로 설정되며, 다른 부동 패널 위에 표시됩니다.

2. **고정 해제된 패널**: 대상 패널이 고정 해제되어 있으면 `focusPane`이(가) 패널을 열린 상태로 플라이아웃합니다.

3. **일반 고정 패널**: 일반 고정 패널의 경우 `focusPane`이(가) 패널을 `activePane`(으)로 설정합니다.


이 메서드를 사용하면 개발자는 사용자 상호 작용이나 애플리케이션 이벤트에 따라 패널의 표시 여부와 위치를 손쉽게 제어할 수 있습니다.

## 자동 숨김 패널 헤더

DockManager의 `showPaneHeaders` 속성을 사용하면 `layout` 안에서 패널 헤더의 표시 여부를 제어할 수 있습니다. 기본적으로 `showPaneHeaders`은(는) `always`(으)로 설정되어 있어 패널 헤더가 항상 표시됩니다. `onHoverOnly`(으)로 설정하면 콘텐츠 패널의 위쪽 가장자리에 마우스를 올릴 때까지 모든 패널 헤더가 숨겨집니다. 그러면 해당 패널 헤더가 나타나며, 마우스가 벗어나면 부드럽게 다시 숨겨집니다. 아래 예제를 확인하십시오:

## 내부 도킹 제어
기본적으로 Dock Manager에서는 사용자가 패널을 서로 안으로 쉽게 끌어 도킹하여 탭을 만들 수 있습니다. 이 기능을 더 세밀하게 제어할 수 있도록 `allowInnerDock` 및 `acceptsInnerDock` 두 가지 속성을 도입했습니다.

<ApiLink type="IgcContentPane" />의 `acceptsInnerDock` 속성을 설정하면 개발자는 특정 콘텐츠 패널 안의 도킹을 제어할 수 있습니다. 이 속성을 false로 설정하면 지정한 패널에서 내부 도킹을 수행할 수 없습니다.


<PlatformBlock for="WebComponents">

```ts
{
    type: IgcDockManagerPaneType.contentPane,
    header: 'Floating 1',
    contentId: 'content3',
    acceptsInnerDock: false
}
```

</PlatformBlock>

DockManager 전체에서 내부 도킹을 비활성화하려면 `allowInnerDock`을(를) **false**로 설정하십시오. 이 속성은 최종 사용자가 패널을 내부 도킹할 수 있는지 여부 자체를 결정합니다.


```ts
this.dockManager.allowInnerDock = false;
```

## 크기 조정 중인 패널 강조

사용자가 스플리터를 끌어 패널 크기를 조정할 때, 특히 더 복잡한 레이아웃에서는 어떤 패널이 영향을 받는지 항상 분명하지 않습니다. 이 상호 작용을 더 명확하게 하기 위해 Dock Manager는 현재 크기가 조정되고 있는 패널 주위에 테두리를 그릴 수 있습니다. 이 시각적 단서는 사용자가 스플리터를 움직일 때 레이아웃의 어떤 부분이 커지거나 작아지는지 즉시 이해하도록 돕습니다.

Dock Manager 호스트 요소(또는 상위 요소)에서 다음 사용자 지정 CSS 속성을 구성하여 이 동작을 활성화하고 스타일을 지정할 수 있습니다:

- `--igc-resize-target-border-color` – 크기 조정 대상 테두리의 색을 제어합니다.
- `--igc-resize-target-border-width` – 테두리 두께를 제어합니다(예: `2px`).
- `--igc-resize-target-border-style` – 테두리 스타일을 제어합니다(예: `solid`, `dashed`).

```css
igc-dockmanager {
    --igc-resize-target-border-color: #0078d4;
    --igc-resize-target-border-width: 2px;
    --igc-resize-target-border-style: solid;
}
```

이 변수를 설정하면 스플리터 끌기의 영향을 받는 모든 패널이 크기 조정 작업 동안 구성된 테두리로 감싸져, 사용자가 어떤 패널이 조정되고 있는지 명확하고 즉각적으로 알 수 있습니다.

## 분할 패널 고정 크기 모드

기본적으로 분할 레이아웃의 각 패널은 형제 패널과 비교한 상대 크기를 받으며, 그 크기의 기본값은 100입니다. 예를 들어 형제 패널 두 개가 있고 첫 번째 패널의 크기는 400, 두 번째 패널의 크기는 200으로 설정되어 있다면, 첫 번째 패널은 두 번째 패널의 두 배 크기가 되며 둘이 합쳐 사용 가능한 공간을 모두 채웁니다.

일부 패널에서 상대 크기 대신 명시적인 픽셀 기반 크기가 필요하다면, 상위 분할 패널의 `useFixedSize` 속성을 **true**로 설정하여 고정 크기 모드를 켤 수 있습니다. 이 속성을 활성화하면 모든 자식 패널이 `size` 속성을 기준으로 픽셀 단위로 크기가 정해집니다. 앞의 예제에서 첫 번째 패널은 400픽셀, 두 번째 패널은 200픽셀을 차지합니다. 스플리터로 크기를 조정하면 상호 작용 중인 패널의 크기만 바뀌며, 형제 패널 사이에서 공간을 다시 나누지 않습니다.

자식 패널 크기의 합이 상위 요소의 사용 가능한 크기를 넘는 즉시 분할 패널은 스크롤 가능해집니다. Dock Manager는 사용자가 콘텐츠에 계속 집중할 수 있도록 내장 자동 스크롤 기능도 제공합니다:

- 사용자가 고정 크기 루트 패널의 가장자리 쪽으로 **패널을 끌면** 컨테이너가 끄는 방향으로 스크롤되어 화면 밖 영역에 쉽게 도달할 수 있습니다.
- 사용자가 스플리터로 **패널 크기를 조정하면** 새로 확장된 콘텐츠가 보이도록 컨테이너가 필요에 따라 스크롤됩니다.

**가로** 분할 패널에서는 **왼쪽** 또는 **오른쪽**으로 자동 스크롤되며, **세로** 분할 패널에서는 끄는 방향이나 크기 조정 방향에 따라 **위쪽** 또는 **아래쪽**으로 자동 스크롤됩니다.


<PlatformBlock for="WebComponents">

```ts
const splitPaneRelativeSize: IgcSplitPane = {
    type: IgcDockManagerPaneType.splitPane,
    orientation: IgcSplitPaneOrientation.horizontal,
    panes: [
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content1',
            header: 'Pane 1',
            size: 400 // Size will be relative to siblings
        },
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content2',
            header: 'Pane 2',
            size: 200 // Size will be relative to siblings
        }
    ]
}

const splitPaneFixedSize: IgcSplitPane = {
    type: IgcDockManagerPaneType.splitPane,
    orientation: IgcSplitPaneOrientation.horizontal,
    useFixedSize: true,
    panes: [
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content3',
            header: 'Pane 3',
            size: 400 // Size will be applied in pixels
        },
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content4',
            header: 'Pane 4',
            size: 200 // Size will be applied in pixels
        }
    ]
}
```

</PlatformBlock>

`useFixedSize`이(가) **true**로 설정된 분할 패널 안에 패널을 도킹하면, 도킹된 패널은 부동 패널과 같은 너비/높이(분할 패널의 방향에 따라 다름)를 갖게 됩니다.
