# {Platform} Dock Manager 개요

Infragistics {Platform} Dock Manager는 패널을 통해 애플리케이션의 레이아웃을 관리하는 수단을 제공하며, 최종 사용자가 패널을 고정, 크기 조정, 이동, 최대화, 숨기기로 더 사용자 지정할 수 있게 합니다.

## {Platform} Dock Manager 예제

<DocsAside type="info">
Dock Manager 컴포넌트는 ShadowDOM과 슬롯을 사용하므로 Internet Explorer 11, Edge 18 이하(Chromium이 아닌 버전) 같은 오래된 브라우저에서는 지원되지 않습니다.

Dock Manager에는 패널의 배치를 설명하는 <ApiLink type="DockManager" member="layout" label="Layout" /> 속성이 있습니다. 레이아웃 정의를 시작하려면 <ApiLink type="DocumentHost" member="rootPane" label="RootPane" /> 속성을 설정하고 자식 패널을 추가하십시오. 다음은 단일 콘텐츠 패널로 레이아웃을 정의하는 방법입니다:

<PlatformBlock for="WebComponents">
```ts
import { IgcDockManagerPaneType, IgcSplitPaneOrientation, IgcDockManagerComponent } from 'igniteui-dockmanager';

// ...

this.dockManager = document.getElementById("dockManager") as IgcDockManagerComponent;
this.dockManager.layout = {
    rootPane: {
        type: IgcDockManagerPaneType.splitPane,
        orientation: IgcSplitPaneOrientation.horizontal,
        panes: [
            {
                type: IgcDockManagerPaneType.contentPane,
                contentId: 'content1',
                header: 'Pane 1'
            }
        ]
    }
};

```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
import {  IgrDockManager, IgrDockManagerPaneType, IgrSplitPaneOrientation } from 'igniteui-react-dockmanager';

// ...

this.dockManager = document.getElementById("dockManager") as IgrDockManager;
this.dockManager.layout = {
    rootPane: {
        type: IgrDockManagerPaneType.splitPane,
        orientation: IgrSplitPaneOrientation.horizontal,
        panes: [
            {
                type: IgrDockManagerPaneType.contentPane,
                contentId: 'content1',
                header: 'Pane 1'
            }
        ]
    }
};
```

</PlatformBlock>

패널의 콘텐츠를 로드하기 위해 Dock Manager는 [슬롯](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/slot)을 사용합니다. 콘텐츠 요소의 [slot](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/slot) 속성은 레이아웃 구성에서 콘텐츠 패널의 <ApiLink type="ContentPane" member="contentId" label="ContentId" />와 일치해야 합니다. 최종 사용자가 패널 크기를 조정할 때 예측 가능한 반응을 위해 콘텐츠 요소의 너비와 높이를 **100%**로 설정하는 것이 좋습니다.

<PlatformBlock for="WebComponents">
```html
<igc-dockmanager id="dockManager">
    <div slot="content1" style="width: 100%; height: 100%;">Content 1</div>
</igc-dockmanager>
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
<IgrDockManager id="dockManager">
    <div slot="content1" style={{ width: '100%', height: '100%' }}>Content 1</div>
</IgrDockManager>
```
</PlatformBlock>

Dock Manager는 여러 패널 유형을 정의합니다:
- <ApiLink type="ContentPane" />
- <ApiLink type="SplitPane" />
- <ApiLink type="TabGroupPane" />
- <ApiLink type="DocumentHost" />

각 패널 유형에는 <ApiLink type="DocumentHost" member="size" label="Size" /> 속성이 있습니다. 상위 방향에 따라 이 크기는 패널의 너비 또는 높이에 영향을 줄 수 있습니다. 기본적으로 패널의 크기는 형제 패널의 크기에 상대적이며 기본값은 100입니다. 형제 패널이 두 개 있고 첫 번째 패널의 크기는 200, 두 번째 패널의 크기는 100으로 설정되어 있다면, 첫 번째 패널은 두 번째 패널의 두 배 크기가 되며 두 패널이 사용 가능한 공간을 모두 채웁니다. 상위 요소의 절대 크기가 900px이면 각각 600px과 300px로 크기가 정해집니다. 사용 가능한 공간을 상대적으로 나누는 대신 특정 패널의 크기를 픽셀 단위로 지정하려면 상위 분할 패널의 `useFixedSize`을(를) 설정해야 합니다.

<PlatformBlock for="WebComponents">
 이에 대한 자세한 내용은 [분할 패널 고정 크기 모드](./dock-manager-customization.mdx#분할-패널-고정-크기-모드) 항목을 참조하십시오.
 </PlatformBlock>

최종 사용자는 런타임에 레이아웃을 사용자 지정하기 위해 다음 작업을 수행할 수 있습니다:
- 패널 고정/고정 해제
- 패널 크기 조정
- 패널 닫기
- 패널을 끌어 부동 상태로 만들기
- 부동 패널 이동
- 부동 패널 도킹
- 패널 최대화

이 모든 작업은 Dock Manager의 <ApiLink type="DockManager" member="layout" label="Layout" /> 속성에 반영됩니다.

### 콘텐츠 패널

<ApiLink type="ContentPane" />은(는) 헤더와 콘텐츠가 있는 패널을 나타냅니다. 분할 패널 또는 탭 그룹 패널 안에 호스팅할 수 있습니다. 콘텐츠 패널은 다음과 같이 정의합니다:

<PlatformBlock for="WebComponents">
```ts
const contentPane: IgcContentPane = {
    type: IgcDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1'
}
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const contentPane: IgrContentPane = {
    type: IgrDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1'
}
```
</PlatformBlock>

<ApiLink type="ContentPane" member="header" label="Header" /> 속성은 콘텐츠 패널의 텍스트 헤더를 제공하는 데 사용됩니다. 이 텍스트는 여러 위치에 렌더링됩니다. 맨 위 콘텐츠 패널 헤더, 패널이 탭 그룹에 있을 때의 탭 헤더, 그리고 패널이 고정 해제되었을 때의 고정 해제 헤더입니다. 각 위치에는 <ApiLink type="ContentPane" member="headerId" label="HeaderId" />, <ApiLink type="ContentPane" member="tabHeaderId" label="TabHeaderId" />, <ApiLink type="ContentPane" member="unpinnedHeaderId" label="UnpinnedHeaderId" /> 속성을 사용해 사용자 지정 슬롯 콘텐츠를 제공할 수 있습니다. 이들 속성 중 하나라도 설정되지 않으면 <ApiLink type="ContentPane" member="header" label="Header" /> 텍스트가 사용됩니다. 탭 헤더 슬롯 콘텐츠를 제공하는 방법은 다음과 같습니다:

<PlatformBlock for="WebComponents">
```html
<igc-dockmanager id="dockManager">
    <div slot="content1" style="width: 100%; height: 100%;">Content 1</div>
    <span slot="tabHeader1">Pane 1 Tab</span>
</igc-dockmanager>
```
</PlatformBlock>

<PlatformBlock for="WebComponents">
```ts
const contentPane: IgcContentPane = {
    type: IgcDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1',
    tabHeaderId: 'tabHeader1'
}
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
<IgrDockManager id="dockManager">
    <div slot="content1" style={{ width: '100%', height: '100%' }}>Content 1</div>
    <span slot="tabHeader1">Pane 1 Tab</span>
</IgrDockManager>
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const contentPane: IgrContentPane = {
    type: IgrDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1',
    tabHeaderId: 'tabHeader1'
}
```
</PlatformBlock>

패널이 고정 해제되면 Dock Manager의 가장자리 중 하나에 탭 헤더로 나타납니다. 최종 사용자가 이를 선택하면 콘텐츠가 도킹된 고정 패널 위에 표시됩니다. 콘텐츠 패널을 고정 해제하려면 <ApiLink type="ContentPane" member="isPinned" label="IsPinned" /> 속성을 **false**로 설정하십시오.

<PlatformBlock for="WebComponents">
```ts
const contentPane = {
    type: IgcDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1',
    isPinned: false
}
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const contentPane = {
    type: IgrDockManagerPaneType.contentPane,
    contentId: 'content1',
    header: 'Pane 1',
    isPinned: false
}
```
</PlatformBlock>

<ApiLink type="ContentPane" member="isPinned" label="IsPinned" /> 속성은 문서 호스트 바깥에 도킹된 콘텐츠 패널에만 영향을 줍니다. 또한 부동 패널 안에 호스팅된 콘텐츠 패널은 고정 해제할 수 없습니다.

기본적으로 콘텐츠 패널의 고정 해제 대상은 문서 호스트를 기준으로 한 패널의 위치에 따라 자동으로 계산됩니다. 문서 호스트가 두 개 이상 정의된 경우, 고정 해제된 콘텐츠 패널의 상위 계층에서 가장 가까운 문서 호스트가 사용됩니다. 정의된 문서 호스트가 없으면 기본 위치인 `Left`이(가) 사용됩니다. <ApiLink type="ContentPane" member="unpinnedLocation" label="UnpinnedLocation" /> 속성을 사용하여 고정 해제된 패널의 원하는 대상을 설정할 수도 있습니다.

콘텐츠 패널의 <ApiLink type="ContentPane" member="allowClose" label="AllowClose" />, <ApiLink type="ContentPane" member="allowPinning" label="AllowPinning" />, <ApiLink type="ContentPane" member="allowDocking" label="AllowDocking" /> 및 <ApiLink type="ContentPane" member="allowFloating" label="AllowFloating" /> 속성을 사용하여 콘텐츠 패널에 허용할 최종 사용자 작업을 구성할 수 있습니다.

콘텐츠 패널을 정의할 때 <ApiLink type="ContentPane" member="documentOnly" label="DocumentOnly" /> 속성을 true로 설정하면 패널을 문서 호스트 안에서만 도킹할 수 있습니다.

콘텐츠 패널과 그 콘텐츠에 대한 사용자 상호 작용을 제한하려면 <ApiLink type="ContentPane" member="disabled" label="Disabled" /> 속성을 true로 설정하십시오. 그러면 단일 부동 패널이 아닌 한 패널과의 모든 사용자 상호 작용이 차단됩니다. 단일 부동 패널은 이동, 최대화 또는 닫기(패널의 최대화 및 닫기 설정에 따라)가 가능하므로, 사용자는 그 아래 요소를 볼 수는 있지만 패널의 콘텐츠와 상호 작용할 수는 없습니다.

기본적으로 패널을 닫으면 <ApiLink type="DockManager" member="layout" label="Layout" /> 객체에서 제거됩니다. 하지만 경우에 따라 패널을 일시적으로 숨겼다가 나중에 다시 표시하고 싶을 수 있습니다. <ApiLink type="DockManager" member="layout" label="Layout" /> 객체를 변경하지 않고 이를 수행하려면 콘텐츠 패널의 <ApiLink type="ContentPane" member="hidden" label="Hidden" /> 속성을 사용할 수 있습니다. 이 속성을 **true**로 설정하면 UI에서 숨겨지지만 패널은 <ApiLink type="DockManager" member="layout" label="Layout" /> 객체에 그대로 남아 있습니다. 기본 닫기 동작을 재정의하려면 다음과 같이 `PaneClose` 이벤트를 구독하십시오:

<PlatformBlock for="WebComponents">
```ts
this.dockManager.addEventListener('paneClose', ev => {
    for (const pane of ev.detail.panes) {
        pane.hidden = true;
    }
    ev.preventDefault();
});
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
this.dockManager.addEventListener('paneClose', ev => {
    for (const pane of ev.detail.panes) {
        pane.hidden = true;
    }
    ev.preventDefault();
});
```
</PlatformBlock>

### 분할 패널

<ApiLink type="SplitPane" />은(는) 자식 <ApiLink type="SplitPane" member="panes" label="Panes" />을(를) <ApiLink type="SplitPane" member="orientation" label="Orientation" /> 속성에 따라 가로 또는 세로로 쌓는 컨테이너 패널입니다. 자식 콘텐츠 패널 두 개를 가진 가로 분할 패널은 다음과 같이 정의합니다:

<PlatformBlock for="WebComponents">
```ts
const splitPane: IgcSplitPane = {
    type: IgcDockManagerPaneType.splitPane,
    orientation: IgcSplitPaneOrientation.horizontal,
    panes: [
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content1',
            header: 'Pane 1'
        },
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content2',
            header: 'Pane 2'
        }
    ]
}
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const splitPane: IgrSplitPane = {
    type: IgrDockManagerPaneType.splitPane,
    orientation: IgrSplitPaneOrientation.horizontal,
    panes: [
        {
            type: IgrDockManagerPaneType.contentPane,
            contentId: 'content1',
            header: 'Pane 1'
        },
        {
            type: IgrDockManagerPaneType.contentPane,
            contentId: 'content2',
            header: 'Pane 2'
        }
    ]
}
```
</PlatformBlock>

분할 패널에는 다른 분할 패널을 포함한 모든 패널 유형의 자식 패널이 포함될 수 있습니다.

기본적으로 분할 패널이 비어 있으면 표시되지 않습니다. 하지만 이 동작을 변경하려면 <ApiLink type="SplitPane" member="allowEmpty" label="AllowEmpty" /> 속성을 true로 설정하면 안에 패널이 없어도 분할 패널이 UI에 표시됩니다.

### 탭 그룹 패널

<ApiLink type="TabGroupPane" />은(는) 자식 <ApiLink type="SplitPane" member="panes" label="Panes" />을(를) 탭 컴포넌트의 탭으로 표시합니다. 두 개의 탭 각각에 콘텐츠 패널이 있는 탭 그룹 패널은 다음과 같이 정의합니다:

<PlatformBlock for="WebComponents">
```ts
const tabGroupPane: IgcTabGroupPane = {
    type: IgcDockManagerPaneType.tabGroupPane,
    panes: [
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content1',
            header: 'Pane 1'
        },
        {
            type: IgcDockManagerPaneType.contentPane,
            contentId: 'content2',
            header: 'Pane 2'
        }
    ]
}
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
const tabGroupPane: IgrTabGroupPane = {
    type: IgrDockManagerPaneType.tabGroupPane,
    panes: [
        {
            type: IgrDockManagerPaneType.contentPane,
            contentId: 'content1',
            header: 'Pane 1'
        },
        {
            type: IgrDockManagerPaneType.contentPane,
            contentId: 'content2',
            header: 'Pane 2'
        }
    ]
}
```
</PlatformBlock>

모든 탭 헤더를 표시할 공간이 충분하지 않으면 탭 그룹에는 보이지 않는 탭을 담은 **추가 탭** 메뉴가 표시됩니다. 그 메뉴에서 탭 항목을 클릭하면 해당 탭이 선택되어 첫 번째 위치로 이동합니다.

탭은 있던 탭 그룹에서 분리되지 않고도 순서를 바꿀 수 있습니다. 원하는 탭을 클릭한 다음 원하는 위치로 왼쪽 또는 오른쪽으로 끌면 됩니다. 선택한 탭을 탭 영역 밖으로 끌면 부동 패널로 분리됩니다.

탭이 없을 때도 탭 그룹 패널이 UI에 표시되도록 하려면 <ApiLink type="SplitPane" member="allowEmpty" label="AllowEmpty" /> 속성을 true로 설정하십시오.

### 부동 패널

부동 패널은 부동 창 안의 다른 모든 패널 위에 렌더링되는 분할 패널입니다. 부동 패널 정의는 <ApiLink type="DockManager" member="layout" label="Layout" />의 <ApiLink type="DockManagerLayout" member="floatingPanes" label="FloatingPanes" /> 속성에 저장됩니다. 콘텐츠 패널 하나가 들어 있는 부동 패널을 추가하는 방법은 다음과 같습니다:

```ts
        }
    ]
};
```
</PlatformBlock>

<ApiLink type="SplitPane" member="floatingResizable" label="FloatingResizable" /> 및

### 패널 크기 조정

최종 사용자는 패널 사이의 스플리터를 끌어 패널 크기를 조정합니다. 스플리터를 끄는 동안 고스트가 포인터를 따라가며, 포인터를 놓으면 패널 크기가 조정됩니다.

최종 사용자는 두 방향으로 동시에 패널 크기를 조정할 수도 있습니다. 예를 들어 한 스플리터가 다른 스플리터에서 끝나 T자 모양을 이루는 등 두 스플리터가 만나는 곳에서 그 교차점에 마우스를 올리면 포인터가 이동 커서로 바뀝니다. 그곳에서 끌면 두 스플리터가 함께 움직이고, 각 스플리터의 양쪽 패널 크기가 조정됩니다.

교차점을 누르면 두 스플리터가 모두 강조 표시되며, 포커스가 다른 곳으로 옮겨 갈 때까지 강조 표시 상태가 유지됩니다. 강조 표시되는 동안 화살표 키를 사용하면 [키보드 탐색](#키보드-탐색)에 설명된 대로 두 스플리터가 모두 움직입니다.

두 스플리터를 함께 끌면 Dock Manager는 각각에 대해 `splitterResizeStart` 및 `splitterResizeEnd` 이벤트를 발생시킵니다. 어느 한 스플리터의 `splitterResizeStart`을(를) 취소하면 두 스플리터의 크기 조정이 모두 취소됩니다.

### 도킹

부동 패널을 끌기 시작하면 끌고 있는 패널의 위치에 따라 서로 다른 도킹 표시기가 나타납니다. 주요 도킹 유형은 네 가지이며, 루트 도킹, 패널 도킹, 문서 호스트 도킹 및 스플리터 도킹입니다. 가장자리 도킹은 루트 도킹이 비활성화되었을 때 추가 동작으로 사용할 수 있으며, 루트 분할 패널의 방향을 따라 작동합니다.

#### 루트 도킹

이 도킹 유형에서는 패널을 끄는 동안 Dock Manager의 네 가장자리 근처에 네 개의 화살표 도킹 표시기가 나타납니다. 놓으면 끌던 패널이 Dock Manager의 <ApiLink type="DocumentHost" member="rootPane" label="RootPane" />의 직접 자식이 됩니다. 시각적으로는 새로 도킹된 패널이 해당 가장자리에 맞춰 자리를 잡고 Dock Manager 너비 또는 높이의 최대 절반을 차지하며, 나머지 콘텐츠는 다른 절반으로 밀려납니다.

<Image src={dockmanagerRootDocking} alt="dockmanager-root-docking" class="responsive-img" />

#### 패널 도킹

부동 패널을 콘텐츠 패널이나 탭 그룹 패널 위로 끌면 그 중앙에 도킹 표시기가 나타납니다. 놓으면 끌던 패널이 대상 패널의 어느 쪽에든 맞춰 자리를 잡거나, 대상 패널과 묶여 탭 레이아웃을 만듭니다. 초기 레이아웃과 도킹 위치의 조합에 따라, 도킹 작업으로 끌던 패널과 대상 패널의 새 상위 요소가 되는 새 분할 패널이나 탭 그룹 패널이 동적으로 만들어질 수 있습니다.

<Image src={dockmanagerPaneDocking} alt="dockmanager-pane-docking" class="responsive-img" />

#### 문서 호스트 도킹

끌고 있는 패널이 문서 호스트 위에 있으면 대상 패널 또는 문서 호스트 전체를 기준으로 도킹할 수 있는 추가 도킹 표시기가 나타납니다.

<Image src={dockmanagerDocumentHostDocking} alt="dockmanager-document-host-docking" class="responsive-img" />

#### 스플리터 도킹

스플리터 도킹을 사용하면 최종 사용자가 기존 분할 레이아웃 안에 패널을 정밀하게 배치할 수 있습니다. 부동 패널을 끄는 동안 커서가 두 패널 사이의 스플리터에 가까워지면 그 스플리터 위에 도킹 표시기가 나타납니다.

사용자가 이 표시기 위에 패널을 놓으면 Dock Manager는 대상 스플리터를 소유한 분할 패널에 패널을 삽입하고, 인접한 패널을 조정하여 공간을 만듭니다. 이를 통해 전체 레이아웃을 다시 구성하지 않고도 기존 두 패널 사이에 새 도구나 뷰를 정확히 넣어 복잡한 레이아웃을 쉽게 다듬을 수 있습니다.

이 수준의 정밀도가 필요하지 않은 더 단순한 경험이 필요하다면, Dock Manager의 `allowSplitterDock` 속성을 **false**로 설정하여 스플리터 도킹을 비활성화할 수 있습니다.

<Image src={dockmanagerSplitterDocking} alt="dockmanager-splitter-docking" class="responsive-img" />

#### 가장자리 도킹

가장자리 도킹을 사용하면 최종 사용자가 특정 스플리터나 패널을 신중하게 겨냥하지 않고도 주요 레이아웃의 맨 앞이나 맨 끝에 중요한 패널을 쉽게 추가할 수 있습니다. `allowRootDock` 속성을 **false**로 설정하여 루트 도킹을 비활성화하면, Dock Manager가 루트 분할 패널의 첫 번째 및 마지막 위치를 따라 가장자리 도킹 표시기를 자동으로 활성화합니다. 루트 분할 패널은 가로 또는 세로이므로, 가장자리 도킹은 그 한 방향에서만 사용할 수 있습니다(가로 루트는 왼쪽/오른쪽, 세로 루트는 위쪽/아래쪽).

이 동작은 루트 패널이 스크롤 가능할 때(`useFixedSize` 속성이 **true**로 설정되고 콘텐츠가 보이는 영역을 넘어설 때) 특히 유용합니다. 이러한 상황에서 사용자는 다음을 할 수 있습니다:

- **가로** 루트 분할 패널에서는 아무 패널이나 **왼쪽** 가장자리 쪽으로 끌면 첫 번째 항목으로 도킹되고, **오른쪽** 가장자리 쪽으로 끌면 마지막 항목으로 도킹됩니다.
- **세로** 루트 분할 패널에서는 아무 패널이나 **위쪽** 가장자리 쪽으로 끌면 첫 번째 항목으로 도킹되고, **아래쪽** 가장자리 쪽으로 끌면 마지막 항목으로 도킹됩니다.

사용자가 가장자리 도킹 표시기 위에 패널을 놓으면 Dock Manager는 선택한 가장자리에 패널을 삽입하고 자동으로 보이는 위치로 스크롤합니다. 이를 통해 복잡하고 스크롤 가능한 레이아웃에서도 새로 추가된 도구 창이나 대시보드가 즉시 보이도록 합니다.

<Image src={dockmanagerEdgeDocking} alt="dockmanager-edge-docking" class="responsive-img" />

## 키보드 탐색

키보드 탐색은 **Dock Manager**의 접근성을 높이며, 모든 패널 사이를 이동하거나 활성 패널을 도킹하여 여러 방향으로 뷰를 분할하는 등 최종 사용자에게 다양한 상호 작용을 제공합니다.


단축키는 다음과 같습니다:

### 도킹

- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>↑</kbd> 전역 위쪽에 도킹
- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>↓</kbd> 전역 아래쪽에 도킹
- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>→</kbd> 전역 오른쪽에 도킹
- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>←</kbd> 전역 왼쪽에 도킹
- <kbd>SHIFT</kbd> + <kbd>↑</kbd> 탭 그룹에 여러 탭이 있을 때 뷰를 분할하고 포커스된 탭을 위쪽에 도킹
- <kbd>SHIFT</kbd> + <kbd>↓</kbd> 탭 그룹에 여러 탭이 있을 때 뷰를 분할하고 포커스된 탭을 아래쪽에 도킹
- <kbd>SHIFT</kbd> + <kbd>→</kbd> 탭 그룹에 여러 탭이 있을 때 뷰를 분할하고 포커스된 탭을 오른쪽에 도킹
- <kbd>SHIFT</kbd> + <kbd>←</kbd> 탭 그룹에 여러 탭이 있을 때 뷰를 분할하고 포커스된 탭을 왼쪽에 도킹

### 탐색
- <kbd>CMD/CTRL</kbd> + <kbd>F6</kbd> 또는 <kbd>CMD/CTRL</kbd> + <kbd>→</kbd> 문서 호스트의 다음 탭에 포커스
- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>F6</kbd> 또는 <kbd>CMD/CTRL</kbd> + <kbd>←</kbd> 문서 호스트의 이전 탭에 포커스
- <kbd>ALT</kbd> + <kbd>F6</kbd> 다음 콘텐츠 패널에 포커스
- <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>F6</kbd> 이전 콘텐츠 패널에 포커스

### 패널 탐색기

다음 키보드 단축키는 패널과 문서를 순회할 수 있는 탐색기를 표시합니다.

- <kbd>CMD/CTRL</kbd> + <kbd>F7</kbd> 또는 <kbd>CMD/CTRL</kbd> + <kbd>F8</kbd>  첫 번째 문서부터 앞으로 시작
- <kbd>ALT</kbd> + <kbd>F7</kbd> 또는 <kbd>ALT</kbd> + <kbd>F8</kbd> 첫 번째 패널부터 앞으로 시작
- <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>F7</kbd> 또는 <kbd>CMD/CTRL</kbd> + <kbd>SHIFT</kbd> + <kbd>F8</kbd> 마지막 문서부터 뒤로 시작
- <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>F7</kbd> 또는 <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>F8</kbd> 마지막 패널부터 뒤로 시작

### 크기 조정
- <kbd>←</kbd> / <kbd>→</kbd> 포커스가 있는 세로 스플리터를 왼쪽 또는 오른쪽으로 10픽셀 이동
- <kbd>↑</kbd> / <kbd>↓</kbd> 포커스가 있는 가로 스플리터를 위 또는 아래로 10픽셀 이동
- <kbd>←</kbd> / <kbd>→</kbd> 및 <kbd>↑</kbd> / <kbd>↓</kbd> 두 스플리터가 만나는 지점을 누른 후, 각각 세로 스플리터와 가로 스플리터를 10픽셀씩 이동

### 기타
- <kbd>ALT</kbd> + <kbd>F3</kbd> 활성 패널 닫기

위에 설명한 모든 작업은 샘플 [데모](./dock-manager.mdx#{PlatformLower}-dock-manager-예제)에서 직접 연습해 보십시오.

## 스타일링

Dock Manager는 스타일과 동작을 캡슐화하기 위해 shadow DOM을 사용합니다. 따라서 일반적인 CSS 선택기로 내부 요소를 직접 대상으로 지정할 수 없습니다. 이 때문에 **::part** CSS 선택기로 대상을 지정할 수 있는 컴포넌트 **파트**를 노출합니다.

```css
igc-dockmanager::part(content-pane) {
  border-radius: 10px;
}
```

### 테마

Dock Manager에는 밝은 테마와 어두운 테마가 있습니다. 기본값은 밝은 테마입니다. 어두운 테마로 바꾸려면 CSS에서 **igc.themes.css** 파일을 가져오고, Dock Manager 또는 그 상위 요소 중 하나에 **dark-theme** 클래스를 추가하기만 하면 됩니다:

## 현지화

Dock Manager는 컨텍스트 메뉴, 툴팁 및 ARIA 속성에 사용되는 문자열을 지역화할 수 있습니다. 기본적으로 루트 `<html>` 요소의 [lang](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/lang) 속성을 읽어 사용할 언어를 결정합니다. [lang](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/lang) 속성이 없거나 지원되지 않는 값으로 설정되어 있으면 Dock Manager는 [영어(en)]({environment:infragisticsBaseUrl}/products/ignite-ui/dock-manager/docs/typescript/latest/index.html#IgcDockManagerResourceStringsEN)를 사용합니다.

<PlatformBlock for="WebComponents">
스페인어(`es`), 일본어(`ja`), 한국어(`ko`)용 즉시 사용 가능한 Dock Manager 리소스 문자열은 `igniteui-i18n-resources` 피어 종속성을 통해 제공됩니다. 이 언어 중 하나를 사용하려면 `igniteui-i18n-resources`을(를) 설치하고 해당 번들을 `igniteui-i18n-core`으로 등록하십시오:

```ts
import { registerI18n } from 'igniteui-i18n-core';
import { DockManagerResourceStringsES } from 'igniteui-i18n-resources';

registerI18n(DockManagerResourceStringsES, 'es');
```

다른 언어를 지원해야 한다면 [addResourceStrings]({environment:infragisticsBaseUrl}/products/ignite-ui/dock-manager/docs/typescript/latest/index.html#addResourceStrings) 메서드를 사용하여 번역된 자체 문자열을 제공하십시오:

```ts
import { addResourceStrings } from 'igniteui-dockmanager';

const dockManagerStringsFr: IgcDockManagerResourceStrings = {
  close: 'Fermer',
  // ...
};

addResourceStrings('fr', dockManagerStringsFr);
```

</PlatformBlock>

Dock Manager에는 개별 문자열을 직접 수정할 수 있는 <ApiLink type="DockManager" member="resourceStrings" label="ResourceStrings" /> 속성도 있습니다. <ApiLink type="DockManager" member="resourceStrings" label="ResourceStrings" /> 속성을 설정하면 페이지의 [lang](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/lang) 속성과 관계없이 Dock Manager가 제공한 문자열을 사용합니다.


</PlatformBlock>
