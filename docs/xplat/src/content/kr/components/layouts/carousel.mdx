# Carousel 컴포넌트

{ProductName} Carousel은 탐색 컨트롤과 표시기를 갖춘 이미지, 카드 또는 기타 콘텐츠를 보여 주는 슬라이드 기반 레이아웃 컴포넌트입니다.

사용자가 선택적 애니메이션, 사용자 지정 탐색 및 자동 전환과 함께 관련된 소규모 슬라이드 모음을 한 번에 하나씩 살펴봐야 할 때 Carousel을 사용하십시오.

## 시작하기

슬라이드를 선언하기 전에 {Platform}에는 carousel 컴포넌트, slide 컴포넌트 및 테마 스타일시트가 필요합니다.

애플리케이션에 Carousel을 추가하기 전에 [시작하기](../general/getting-started.mdx) 항목에 따라 {ProductName}을(를) 설치하고 테마를 구성하십시오.

</PlatformBlock>

```ts
import 'igniteui-webcomponents/themes/light/bootstrap.css';

defineComponents(IgcCarouselComponent);
```

<PlatformBlock for="React">

```tsx
import 'igniteui-webcomponents/themes/light/bootstrap.css';
```

<PlatformBlock for="Blazor">

{ProductName} 서비스를 등록합니다:

```csharp
// in Program.cs file

builder.Services.AddIgniteUIBlazor();
```

Carousel의 클라이언트 리소스 모듈인 <ApiLink pkg="core" type="CarouselModule" />을(를) 등록하는 것은 **선택 사항**입니다. 컴포넌트는 처음 렌더링될 때 리소스를 로드합니다. `builder.Services.AddIgniteUIBlazor(typeof(IgbCarouselModule))`에 나열하면 리소스를 미리 로드하거나 클라이언트에서만 만들어지는 요소를 지원할 수 있습니다([컴포넌트 모듈](../general-getting-started.mdx#컴포넌트-모듈) 참조).

애플리케이션 호스트 페이지에 테마 스타일시트를 추가하십시오.

```razor
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
```

</PlatformBlock>

<DocsAside type="info">
활성 슬라이드가 설정되지 않으면 첫 번째 슬라이드가 기본적으로 활성화됩니다. 초기 렌더링이나 이후 업데이트 중에 여러 슬라이드가 활성화되면 마지막으로 활성화된 슬라이드가 사용됩니다.
</DocsAside>

## 접근성

{Platform} Carousel은 키보드 사용자와 보조 기술 사용자를 위해 캐러셀, 슬라이드 및 표시기 시맨틱을 노출합니다.

### 키보드 상호 작용

| 키 | 동작 |
| --- | --- |
| <kbd>Space</kbd> 또는 <kbd>Enter</kbd> | 포커스가 있는 탐색 버튼을 활성화합니다. |
| <kbd>왼쪽 화살표</kbd> | 표시기 포커스를 이전 슬라이드 표시기로 이동합니다. 오른쪽에서 왼쪽으로 쓰는 모드에서는 다음 표시기로 이동합니다. |
| <kbd>오른쪽 화살표</kbd> | 표시기 포커스를 다음 슬라이드 표시기로 이동합니다. 오른쪽에서 왼쪽으로 쓰는 모드에서는 이전 표시기로 이동합니다. |
| <kbd>Home</kbd> | 표시기 포커스를 첫 번째 슬라이드 표시기로 이동합니다. 오른쪽에서 왼쪽으로 쓰는 모드에서는 마지막 표시기로 이동합니다. |
| <kbd>End</kbd> | 표시기 포커스를 마지막 슬라이드 표시기로 이동합니다. 오른쪽에서 왼쪽으로 쓰는 모드에서는 첫 번째 표시기로 이동합니다. |

### 화면 읽기 프로그램 / ARIA

Carousel은 호스트, 슬라이드, 표시기 및 탐색 컨트롤에 대해 ARIA 역할과 상태를 제공합니다.

| 요소 | 역할 또는 속성 | 목적 |
| --- | --- | --- |
| Carousel 호스트 | `role="region"` 및 `aria-roledescription="carousel"` | Carousel을 탐색 가능한 콘텐츠 영역으로 식별합니다. |
| 슬라이드 컨테이너 | `aria-live="polite"` 또는 `aria-live="off"` | 자동 재생이 활성화되지 않은 경우 슬라이드 변경을 알립니다. |
| 슬라이드 | `role="tabpanel"`, `aria-roledescription="slide"`, `aria-label` | 각 슬라이드와 세트 안에서의 위치를 식별합니다. |
| 표시기 컨테이너 | `role="tablist"` | 슬라이드 표시기를 그룹화합니다. |
| 표시기 | `role="tab"`, `aria-label`, `aria-selected` | 표시기가 나타내는 슬라이드와 선택 여부를 식별합니다. |
| 탐색 버튼 | `aria-label` | 이전 및 다음 슬라이드 작업의 이름을 지정합니다. |

### 접근성 준수

Infragistics는 [접근성 준수](../interactivity/accessibility-compliance.mdx) 항목에서 Section 508 및 WCAG 2.1 지침 영역에 대한 {ProductName} 접근성 지원을 문서화합니다.

| --- | --- |

| [2.1.2 키보드 트랩 없음](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html) | Carousel의 키보드 상호 작용은 포커스가 컴포넌트 안에 계속 머물러 있을 필요가 없습니다. |

<Faq>
  <FaqItem question="캐러셀은 자동 재생되어야 합니까?" indicatorPosition="end">
    가능하면 수동 탐색을 우선하십시오. 캐러셀이 자동으로 회전한다면 사용자가 각 슬라이드를 읽고 상호 작용할 충분한 시간을 가질 수 있도록 일시 중지와 재개 방법을 분명하게 제공하십시오.
  </FaqItem>
  <FaqItem question="사용자가 캐러셀에 마우스를 올리거나 포커스를 두면 어떻게 되어야 합니까?" indicatorPosition="end">
    사용자가 캐러셀의 콘텐츠를 읽거나 상호 작용하는 동안에는 자동 회전을 일시 중지하십시오. 사용자가 명시적으로 계속하기를 선택하기 전까지 재개하지 마십시오.
  </FaqItem>
  <FaqItem question="캐러셀에는 슬라이드가 몇 개나 있어야 합니까?" indicatorPosition="end">
    묶음을 작고 집중적으로 유지하십시오. 관련 슬라이드의 짧은 묶음은 숨겨진 콘텐츠가 있는 긴 순서보다 찾고 훑어보기 쉽습니다.
  </FaqItem>
  <FaqItem question="슬라이드에 양식, 버튼 또는 여러 작업을 넣을 수 있습니까?" indicatorPosition="end">
    대화형 콘텐츠의 포커스 순서가 예측 가능하고, 사용자가 상호 작용하는 동안 슬라이드가 바뀌지 않는다면 가능합니다. 작업은 슬라이드의 주요 작업에 집중하십시오.
  </FaqItem>
  <FaqItem question="표시기 점은 대화형이어야 합니까?" indicatorPosition="end">
    표시기가 개별 슬라이드로의 직접 탐색을 나타낸다면 대화형으로 만드십시오. 그러면 이전 또는 다음을 반복해서 선택하지 않고도 사용자가 특정 콘텐츠에 바로 갈 수 있습니다.
  </FaqItem>
  <FaqItem question="캐러셀 대신 정적 레이아웃을 언제 사용해야 합니까?" indicatorPosition="end">
    사용자가 항목을 비교하거나, 모든 항목을 읽거나, 특정 항목을 바로 찾아야 할 때는 정적 목록, 그리드, 탭 또는 Stepper를 사용하십시오. 캐러셀은 관련 콘텐츠의 간결한 순서에 가장 적합합니다.
  </FaqItem>
</Faq>
