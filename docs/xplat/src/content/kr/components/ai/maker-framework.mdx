# MAKER Framework

MAKER Framework(`@igniteui/maker-mcp`)는 Infragistics의 다중 에이전트 AI 오케스트레이션 MCP 서버로, 여러 AI 에이전트에 걸쳐 합의 기반 투표 알고리즘을 사용하여 복잡한 작업을 검증되고 실행 가능한 단계 계획으로 분해합니다. MAKER는 Maximal Agentic decomposition, first-to-ahead-by-K Error correction, Red-flagging의 약자입니다. 이 프레임워크는 Cognizant AI Lab의 연구 논문 _Solving a million-step LLM task with zero errors_를 기반으로 합니다. `npx`를 통해 `@igniteui` GitHub Packages 레지스트리에서 MCP 서버로 실행되며, STDIO 전송을 통해 MCP 호환 AI 클라이언트에 연결됩니다. 연결되면 AI 어시스턴트는 `plan`, `execute`, `plan_and_execute` 세 가지 도구를 호출하여 자동 오류 감지 및 수정과 함께 장기 작업을 실행할 수 있습니다.

MAKER Framework는 Ignite UI 컴포넌트 스캐폴딩 도구가 아닙니다. Ignite UI 프로젝트 생성, 컴포넌트 생성 및 문서 조회에는 [CLI MCP 서버](cli-mcp.mdx)를 사용하십시오. MAKER는 프레임워크에 종속되지 않으며, Angular, React, Blazor 또는 Web Components를 특별히 대상으로 하지 않고, 스스로 프로젝트 소스 파일을 읽거나 수정하지도 않습니다. 최소 한 개의 AI 제공자 API 키(OpenAI, Anthropic 또는 Google AI)와 `@igniteui` 레지스트리에 대한 `read:packages` 범위를 가진 GitHub 개인 액세스 토큰이 필요합니다.

## MAKER의 작동 방식

MAKER Framework는 계획과 실행이라는 두 개의 순차적 단계로 작동합니다. 각 단계는 전용 내부 AI 클라이언트 집합을 사용하며, 다음 단계로 넘어가기 전에 같은 합의 기반 투표 메커니즘으로 결과를 검증합니다.

**계획 단계**에서는 계획 클라이언트가 단계 묶음(구성 가능한 묶음 크기, 기본값 3)을 제안합니다. 이후 별도의 계획 투표 클라이언트가 "first-to-ahead-by-K" 투표를 실행합니다. 여러 AI 에이전트가 제안된 단계에 대해 "Yes", "No" 또는 "End"로 투표합니다. 한 결과가 다른 결과보다 K표 앞서면 제안이 승인됩니다. 거부된 제안은 다음 재시도에 거부 사유를 포함하며, 계획이 완성되거나 재시도 한도에 도달할 때까지 지속적인 개선을 이끕니다.

**실행 단계**에서는 프레임워크가 검증된 단계 계획을 구성 가능한 묶음 단위로 처리합니다. 실행 클라이언트가 각 묶음을 실행하고 갱신된 상태를 생성합니다. 실행 투표 클라이언트는 같은 K표 차이 투표 알고리즘을 사용하여 새 상태를 이전 상태 및 원래 작업과 비교 검증합니다. 거부된 실행은 피드백과 함께 다시 시도됩니다. 최종적으로 누적된 상태가 작업 결과가 됩니다.

빨간 깃발(red-flag) 검증 계층은 두 단계 전체에서 작동합니다. 모든 AI 클라이언트 요청은 응답이 투표 시스템에 들어가기 전에 구성 가능한 검증기를 실행하는 보호된 호출로 감싸집니다. 형식이 잘못되었거나 너무 짧은 응답은 실패 메시지를 프롬프트에 덧붙여 다시 시도합니다. 사용자 지정 검증기는 `IAIRedFlagValidator`을 구현하여 추가할 수 있습니다.

## MAKER MCP 서버 설치하기

MAKER는 `@igniteui` 범위로 GitHub Packages에 게시되며, 레지스트리를 한 번 설정해야 합니다. 컴퓨터에서 다음 명령을 한 번 실행하십시오:

```bash
npm config set @igniteui:registry https://npm.pkg.github.com
```

그런 다음 `~/.npmrc`(Windows: `%USERPROFILE%\.npmrc`)을 열고 `read:packages` 범위를 가진 GitHub 개인 액세스 토큰을 추가하십시오:

```ini
//npm.pkg.github.com/:_authToken=YOUR_GITHUB_PAT
```

레지스트리를 구성한 후에는 별도의 전역 설치 없이 `npx`을 통해 MCP 서버가 실행됩니다. 네이티브 바이너리(약 50MB)는 처음 실행할 때 내려받아 캐시됩니다. 이후 시작은 즉시 이루어집니다.

## AI 클라이언트에 연결하기

AI 클라이언트의 MCP 구성 파일에 `maker` 서버 항목을 추가하십시오. `env` 블록은 AI 제공자 키를 전달하므로, 사용하는 제공자의 키만 설정하십시오.

### VS Code (GitHub Copilot)

워크스페이스의 `.vscode/mcp.json`에 추가하십시오:

```json
{
  "servers": {
    "maker": {
      "command": "npx",
      "args": ["-y", "@igniteui/maker-mcp", "--stdio"],
      "env": {
        "Executor__AIProviderKeys__OpenAI": "<your-openai-key>"
      }
    }
  }
}
```

Copilot Chat을 Agent 모드로 전환하고 도구 목록에 `plan`, `execute`, `plan_and_execute`이(가) 나타나는지 확인하십시오.

### Claude Desktop

1. Claude Desktop 구성 파일을 여십시오:
    - macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
    - Windows: `%APPDATA%\Claude\claude_desktop_config.json`
2. `mcpServers` 블록에 `maker` 항목을 추가하십시오:

    ```json
    {
      "mcpServers": {
        "maker": {
          "command": "npx",
          "args": ["-y", "@igniteui/maker-mcp", "--stdio"],
          "env": {
            "Executor__AIProviderKeys__Anthropic": "<your-anthropic-key>"
          }
        }
      }
    }
    ```

3. Claude Desktop을 다시 시작하십시오. 처음 시작할 때 네이티브 바이너리를 내려받습니다(일반적인 연결에서 약 30초).

### Cursor, Claude Code, JetBrains 및 기타 MCP 클라이언트

STDIO 전송을 지원하는 MCP 클라이언트는 모두 같은 `mcpServers` 블록을 사용합니다:

```json
{
  "mcpServers": {
    "maker": {
      "command": "npx",
      "args": ["-y", "@igniteui/maker-mcp", "--stdio"],
      "env": {
        "Executor__AIProviderKeys__OpenAI": "<your-openai-key>"
      }
    }
  }
}
```

## MAKER MCP 서버 구성하기

MAKER의 모든 구성은 환경 변수로 제공됩니다. 명명 규칙은 섹션 구분자로 이중 밑줄(`__`)을 사용합니다. MCP 클라이언트 구성의 `env` 블록에 변수를 전달하십시오.

### AI 제공자 키

최소한 하나의 제공자 키를 설정하십시오. 여러 제공자의 키를 동시에 설정하고, 내부 클라이언트마다 서로 다른 제공자를 지정할 수 있습니다.

| 환경 변수                  | 설명       |
| ------------------------------------- | ----------------- |
| `Executor__AIProviderKeys__OpenAI`    | OpenAI API 키    |
| `Executor__AIProviderKeys__Anthropic` | Anthropic API 키 |
| `Executor__AIProviderKeys__Google`    | Google AI API 키 |

### 내부 클라이언트별 모델 선택

MAKER는 네 개의 내부 AI 클라이언트, 즉 `Planning`, `PlanVoting`, `Execution`, `ExecutionVoting`를 사용합니다. 각 클라이언트는 서로 다른 제공자와 모델을 대상으로 할 수 있습니다. 기본값은 네 클라이언트 모두 OpenAI의 `gpt-5.1`를 사용합니다.

비용과 품질의 균형을 위해 제공자를 섞어 사용하려면 클라이언트마다 `Provider` 및 `Model` 변수를 설정하십시오:

```json
"env": {
  "Executor__AIProviderKeys__OpenAI":             "<openai-key>",
  "Executor__AIProviderKeys__Anthropic":          "<anthropic-key>",
  "Executor__Clients__Planning__Provider":        "Anthropic",
  "Executor__Clients__Planning__Model":           "claude-opus-4-5",
  "Executor__Clients__PlanVoting__Provider":      "OpenAI",
  "Executor__Clients__PlanVoting__Model":         "gpt-4.1-mini",
  "Executor__Clients__Execution__Provider":       "Anthropic",
  "Executor__Clients__Execution__Model":          "claude-opus-4-5",
  "Executor__Clients__ExecutionVoting__Provider": "OpenAI",
  "Executor__Clients__ExecutionVoting__Model":    "gpt-4.1-mini"
}
```

올바른 `Provider` 값: `OpenAI`, `Anthropic`, `Google`.

### 외부 MCP 서버 연결하기

MAKER는 외부 MCP 서버를 도구 제공자로 연결하여, 해당 도구를 실행 클라이언트가 사용할 수 있게 할 수 있습니다. 인덱스가 있는 환경 변수를 사용하여 각 서버의 이름, 설명, URL 및 선택적 API 키를 구성하십시오:

```json
"env": {
  "Executor__McpServers__0__Name":        "igniteui-cli",
  "Executor__McpServers__0__Description": "Ignite UI CLI scaffolding and documentation tools",
  "Executor__McpServers__0__Url":         "https://mcp.example.com/igniteui-cli"
}
```

추가 서버를 등록하려면 인덱스(`0`, `1`, `2`, ...)를 늘리십시오.

### 배치 크기와 투표 임계값 조정하기

각 MCP 도구 호출은 자연어로 `batchSize` 및 `k` 매개변수를 받습니다. 도구를 호출할 때 프롬프트에서 이 값을 설정하십시오.

| 매개변수   | 기본값 | 설명                                                                                                            |
| ----------- | ------- | ---------------------------------------------------------------------------------------------------------------------- |
| `batchSize` | `3`     | 투표 라운드당 제안되거나 실행되는 단계 수입니다. 값이 낮을수록 더 많은 제어가 가능하고, 값이 높을수록 처리량이 향상됩니다.         |
| `k`         | `10`    | 합의 차이 임계값입니다. 값이 높을수록 결과가 수락되기 전에 투표 에이전트 간에 더 강한 합의가 필요합니다. |

빠르고 탐색적인 작업에는 `k`을(를) 낮추십시오(3-5). 토큰 비용보다 정확성이 중요한 중요한 작업에는 `k`을(를) 높이십시오(15-20).

## 사용 가능한 도구

MAKER MCP 서버는 연결된 AI 에이전트에 세 가지 도구를 제공합니다.

| 도구               | 설명                                                               |
| ------------------ | ------------------------------------------------------------------------- |
| `plan`             | 작업을 실행하지 않고 검증된 순서가 있는 단계 목록으로 분해합니다 |
| `execute`          | `plan`이(가) 생성한 단계 목록을 실행하며, 묶음마다 합의 투표를 수행합니다   |
| `plan_and_execute` | 한 번의 호출로 계획하고 실행하며, 단계 사이에 실시간 진행 이벤트를 제공합니다     |

실행 전에 단계 계획을 검토하고 검증하려면 `plan`을 실행한 다음 `execute`를 사용하십시오. 검토가 필요 없는 무인 실행에는 `plan_and_execute`을 사용하십시오.

## 일반적인 작업 흐름

### 단일 작업

기본 설정으로 `plan_and_execute`을 직접 호출하십시오:

> 기술 블로그 게시물을 위해 REST와 GraphQL을 비교하는 자세한 글을 작성하도록 plan_and_execute를 사용하십시오.

### 실행 전에 계획 검토하기

`plan`을 사용하여 단계를 검토한 다음, 이를 `execute`에 전달하십시오:

> 1. PostgreSQL 스키마를 다중 테넌트 설계로 마이그레이션하는 계획을 만들도록 plan을 사용하십시오.
> 2. 단계를 보여 주십시오.
> 3. 그 단계들로 마이그레이션 스크립트를 수행하도록 execute를 사용하십시오.

### 중요한 작업을 위한 고신뢰 실행

더 강한 합의를 요구하려면 `k`을(를) 높이십시오:

> 이 스마트 컨트랙트에서 보안 취약점을 검토하도록 batchSize=3, k=15로 plan_and_execute를 사용하십시오.

### 저비용 탐색 작업

토큰 사용량을 최소화하려면 두 매개변수를 모두 낮추십시오:

> Node.js CLI 도구의 프로젝트 README 초안을 작성하도록 batchSize=3, k=3으로 plan_and_execute를 사용하십시오.

## 지원되는 플랫폼

네이티브 바이너리는 네 가지 플랫폼용으로 배포됩니다. 올바른 바이너리는 처음 실행할 때 자동으로 선택되어 캐시됩니다.

| 플랫폼 | 아키텍처          | RID         |
| -------- | --------------------- | ----------- |
| Windows  | x64                   | `win-x64`   |
| macOS    | x64(Intel)           | `osx-x64`   |
| macOS    | arm64(Apple Silicon) | `osx-arm64` |
| Linux    | x64                   | `linux-x64` |

ARM Linux는 현재 패키지로 제공되지 않습니다. 플랫폼 지원을 추가로 요청하려면 [github.com/IgniteUI/MAKER](https://github.com/IgniteUI/MAKER)에 이슈를 등록하십시오.

바이너리 캐시 위치는 `MAKER_MCP_CACHE` 환경 변수로 재정의할 수 있습니다. 기본 캐시 경로는 Windows에서는 `%LOCALAPPDATA%\maker-mcp\{version}\{rid}\`, macOS와 Linux에서는 `~/.cache/maker-mcp/{version}/{rid}/`입니다.
