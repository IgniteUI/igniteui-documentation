# 라이선스 FAQ 및 설치

## {ProductName} npm 패키지 - 비공개 npm 피드 사용하기
npm은 가장 인기 있는 패키지 관리자이며, Node.js 런타임 환경의 기본 패키지 관리자이기도 합니다. 널리 채택되어 있으며, 프로젝트가 의존하는 패키지를 관리하는 가장 빠르고 쉬운 방법 중 하나입니다. npm의 작동 방식에 대한 자세한 정보는 공식 [npm 문서](https://docs.npmjs.com/)를 읽어 보십시오.

Infragistics {ProductName}는 npm 패키지로 제공되며, [몇 가지 간단한 단계](./general-getting-started.mdx)로 프로젝트에 종속성으로 추가할 수 있습니다. 이 방법을 선택하면 npm을 구성할 필요가 없습니다. 상업용 라이선스 패키지를 설치하면 제품의 **{ProductName} 체험판 버전**을 사용하기 시작하게 됩니다.

<DocsAside type="info">
체험판 버전을 사용하기 시작한다는 것은 웹 뷰의 일부에 **워터마크**가 표시되는 제품 버전을 사용한다는 뜻입니다. 특정 기간(예: 한 달) 동안 라이선스 패키지를 사용한 뒤 만료된다는 의미는 아닙니다.

Infragistics가 제공하는 비공개 npm 피드에는 상업용 라이선스 패키지의 라이선스 버전이 포함되어 있습니다.

### 비공개 npm 피드를 사용하도록 환경을 설정하는 방법

#### 먼저 비공개 레지스트리를 설정하고, 이 레지스트리를 Infragistics 범위와 연결해야 합니다

이렇게 하면 공개 npm 레지스트리와 Infragistics 비공개 레지스트리의 패키지를 자연스럽게 함께 사용할 수 있습니다. Infragistics 계정에 로그인할 때 사용하는 사용자 이름과 비밀번호를 입력하라는 메시지가 표시됩니다. 또한 Infragistics 프로필에 등록된 이메일도 입력해야 합니다.

> 계정이 라이선스가 없는 상태(여전히 체험판 계정 사용 중)라면 비공개 패키지 피드에 접근할 수 없습니다. 예를 들어 404 또는 403 오류 메시지가 반환됩니다. **라이선스가 있는 계정만 packages.infragistics 비공개 피드에 접근할 수 있습니다.**

### 이제 npm을 사용하여 비공개 피드에 로그인하십시오

#### npm 9 이상
비공개 피드는 현재 npm v9에서 login/adduser 명령을 지원하지 않으므로, 대신 다음 단계를 따라 구성에 필요한 인증 필드를 추가하는 것을 권장합니다:

```cmd
npm config set @infragistics:registry https://packages.infragistics.com/npm/js-licensed/

npm config set //packages.infragistics.com/npm/js-licensed/:username=YOUR_USERNAME

npm config set //packages.infragistics.com/npm/js-licensed/:email=YOUR_IG_EMAIL

npm config set //packages.infragistics.com/npm/js-licensed/:_auth=YOUR_IG_AUTH_TOKEN
```

Infragistics 프로필을 통해 [액세스 토큰](#액세스-토큰-사용)을 생성할 수 있습니다.

이 방식은 `npm`의 모든 이전 버전에 적용됩니다.

#### npm v8 이하 버전
`adduser` 명령을 실행하고 사용자 계정과 비밀번호를 지정하십시오:

```cmd
npm adduser --registry=https://packages.infragistics.com/npm/js-licensed/ --scope=@infragistics
```

Infragistics 계정에 로그인할 때 사용하는 사용자 이름과 비밀번호를 입력하라는 메시지가 표시됩니다. Infragistics 프로필에 등록된 이메일도 제공해야 합니다.

> `npm`은(는) 사용자 이름에 `"@"` 기호를 사용하는 것을 "인터넷에 안전하지 않은" 것으로 간주하여 허용하지 않습니다. 사용자 이름은 실제로 Infragistics 계정에 사용하는 이메일이므로 항상 `"@"` 기호를 포함합니다. 그래서 `"@"` 기호를 `"!!"`(느낌표 두 개)로 바꾸어 이 제한을 우회해야 합니다. 예를 들어 사용자 이름이 `"username@example.com"`인 경우, 사용자 이름을 묻을 때 다음과 같이 입력해야 합니다: `"username!!example.com"`.

#### 이 과정이 끝나면 로그인되어 프로젝트에 최신 버전의 Ignite UI 패키지를 설치할 수 있습니다

```cmd
npm uninstall {PackageDockManager}
npm install @infragistics/{PackageDockManager}

npm uninstall {PackageDockManager}
npm install @infragistics/{PackageDockManager}
```

{ProductName} 패키지는 범위가 지정(scoped)되어 있으므로, 비공개 피드와 npmjs.org의 패키지를 동시에 설치하려면 레지스트리를 변경할 필요가 없다는 점을 기억하십시오.

### 라이선스 패키지 업데이트 후 프로젝트 소스의 변경 사항

Trial에서 라이선스 패키지로 업그레이드하면 새 패키지는 `@infragistics` 아래 범위가 지정됩니다.
따라서 다음 중 하나를 선택할 수 있습니다:

- 모든 체험판 패키지에 대해 전역 바꾸기를 수행하여 프로젝트의 모든 파일에서 라이선스 범위 버전으로 변경하십시오. 예를 들어 모든 `{PackageDockManager}` 참조를 `@infragistics/{PackageDockManager}`로 바꾸십시오. 이 변경은 해당 패키지가 사용되는 모든 import에 영향을 주어야 합니다.

  **또는**

- 프로젝트 **tsconfig.json**에 **paths** 매핑을 추가하십시오.

```json
{
  /* ... */
  "compilerOptions": {
    "baseUrl": "./",
    "outDir": "./dist/out-tsc",
    /* ... */
    "paths": {
      "{PackageDockManager}": ["./node_modules/@infragistics/{PackageDockManager}"],
      "{PackageDockManager}/*": ["./node_modules/@infragistics/{PackageDockManager}/*"],
    }
  }
}
```

## 액세스 토큰 사용

[infragistics.com 사용자 계정](https://account.infragistics.com/access-tokens)을 통해 얻을 수 있는 액세스 토큰을 사용하여 비공개 npm 피드에 인증할 수도 있습니다. 공개적으로 접근 가능한 저장소에서 {ProductName} 라이선스 패키지를 사용하는 CI 프로세스를 통합하려는 경우, 액세스 토큰 인증이 선호되는 대안입니다.

다음 정보는 로컬 구성, Azure Pipelines 빌드 절차, Travis CI 빌드 프로세스에서 액세스 토큰을 사용하여 비공개 npm 레지스트리 인증을 설정하는 방법입니다:

- https://account.infragistics.com/access-tokens 주소에서 토큰을 생성하십시오.

## Travis CI 구성
여기서도 거의 같은 방식을 따릅니다. 다른 점은 구성이 [before_install](https://docs.travis-ci.com/user/job-lifecycle/#the-job-lifecycle)에서 설정된다는 것입니다

```cmd
before_install:
- echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- echo "//packages.infragistics.com/npm/js-licensed/:_auth=$TOKEN" >> ~/.npmrc
```

환경 변수를 정의하는 가장 좋은 방법은 그 안에 담길 정보의 유형에 따라 달라집니다. 따라서 [두 가지 옵션이 있습니다](https://docs.travis-ci.com/user/environment-variables/):

- 암호화하여 [.travis.yml에](https://docs.travis-ci.com/user/environment-variables/#defining-encrypted-variables-in-travisyml) 추가하기
- [저장소 설정](https://docs.travis-ci.com/user/environment-variables/#defining-variables-in-repository-settings)에 추가하기

### GitHub Actions 구성

[CI 워크플로 구성](https://help.github.com/en/actions/language-and-framework-guides/using-nodejs-with-github-actions)의 **npm i(ci)** 단계 앞에 다음 스크립트를 추가하십시오:

```cmd
- run: echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- run: echo "//packages.infragistics.com/npm/js-licensed/:_auth=${{ secrets.NPM_TOKEN }}" >> ~/.npmrc
```

[시크릿(암호화된 환경 변수)](https://help.github.com/en/actions/configuring-and-managing-workflows/creating-and-storing-encrypted-secrets)을 정의하고, 액세스 토큰 같은 민감한 정보에는 GitHub 액션 워크플로에서 이를 사용하십시오.
