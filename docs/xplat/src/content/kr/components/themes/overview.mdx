## 실행 중 테마 전환

<DocsAside type="info">
실행 중에 테마를 바꾸려면 위 표의 전역 스타일시트도 교체해야 합니다.
</DocsAside>

{ProductName}에서는 라이브러리가 내보내는 `ConfigureTheme` 함수로 실행 중에 컴포넌트 테마를 전환할 수 있습니다.

첫 번째 인수로 테마를 받습니다. `bootstrap`, `material`, `fluent`, `indigo` 중 하나입니다. 두 번째 인수로는 선택적 변형을 받으며, `light` 또는 `dark`입니다. 현재 활성화된 변형을 유지하려면 변형을 생략하십시오.

```ts
import { configureTheme } from "igniteui-webcomponents";

// Sets material as the theme to be used by all components
configureTheme("material");

// Sets material and switches to its dark variant
configureTheme("material", "dark");
```

<DocsAside type="info">
이는 컴포넌트에 내부 스타일을 원하는 테마로 전환하라고만 알려 주므로, 전역 테마 파일도 위에 나열된 파일 중 하나로 전환해야 합니다.
</DocsAside>

</PlatformBlock>

## Sass로 사용자 지정하기

위의 테마 파일은 미리 빌드된 CSS이며, 이 섹션의 항목들은 CSS 변수를 덮어써서 이를 사용자 지정합니다. [팔레트](palettes.mdx), [타이포그래피](typography.mdx), [높이감](elevations.mdx), [구성](configuration.mdx)을 참조하십시오. 이 방식은 빌드 구성이 필요 없으며 대부분의 사용자 지정을 다룹니다.

미리 빌드된 테마는 모든 {ProductName} 테마의 바탕이 되는 Sass 라이브러리인 `igniteui-theming`에서 컴파일되며, 같은 라이브러리를 애플리케이션에서도 사용할 수 있습니다. 일부 기능은 변수가 아니라 컴파일 시점에 실행되므로 이 라이브러리에서만 접근할 수 있습니다:

- [팔레트 생성](palette-generation.mdx)에 설명된 대로 직접 시드 색으로 팔레트를 생성하기.
- [접근성](accessibility.mdx) 항목의 명암 대비 및 차트 팔레트 함수.

`igniteui-theming`을(를) 사용한 Sass 빌드는 일반 CSS를 생성합니다. 이는 `--ig-*` 변수의 스타일시트이며, 자체 CSS 재정의를 로드하는 것과 같은 방식으로 테마 파일 다음에 로드합니다. 프레임워크에는 Sass 컴파일러를 실행하는 방법만 있으면 됩니다. 두 패키지를 설치하십시오:

```cmd
npm install igniteui-theming sass --save-dev
```

그다음 `.scss` 파일에서 라이브러리를 가져오십시오:

```scss
@use 'igniteui-theming' as *;

// Required for $material-type-scale, $indigo-type-scale, and similar preset variables
@use 'igniteui-theming/sass/typography/presets' as *;

// Required for $material-elevations and $indigo-elevations
@use 'igniteui-theming/sass/elevations/presets' as *;

:root {
  @include palette(palette($primary: #0099ff, $secondary: #df1b74, $surface: #ffffff));
}
```

### 스타일시트 컴파일하기

<PlatformBlock for="React">

`sass` 패키지가 설치되면 Vite와 Next.js는 `.scss` 가져오기를 컴파일합니다. 테마 파일 다음에 스타일시트를 가져오십시오:

```tsx
import 'igniteui-react-grids/grids/themes/light/bootstrap.css';
import './theme.scss';
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

`sass` 패키지가 설치되면 Vite는 `.scss` 가져오기를 컴파일하며, webpack은 `sass-loader`을(를) 통해 같은 작업을 합니다. 테마 파일 다음에 스타일시트를 가져오십시오:

```ts
import 'igniteui-webcomponents/themes/light/bootstrap.css';
import './theme.scss';
```

</PlatformBlock>

<PlatformBlock for="Blazor">

Blazor 프로젝트에는 JavaScript 번들러가 없으므로, 예를 들어 npm 스크립트나 빌드 전 단계에서 Sass 명령줄로 스타일시트를 컴파일하고 그 결과를 `wwwroot`에 쓰십시오:

```cmd
npx sass --load-path=node_modules Styles/theme.scss wwwroot/css/theme.css
```

호스트 페이지에서 테마 파일 다음에 컴파일된 파일을 연결하십시오:

```html
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
<link href="css/theme.css" rel="stylesheet" />
```

</PlatformBlock>

<PlatformBlock for="React, WebComponents">

다른 빌드 도구도 같은 방식으로 작동하며, Sass 명령줄도 마찬가지입니다. 다른 어떤 도구도 Sass를 컴파일하지 않는다면, 별도의 단계로 실행하고 결과를 다른 CSS 파일처럼 로드하십시오:

```cmd
npx sass --load-path=node_modules src/theme.scss public/theme.css
```

</PlatformBlock>

<DocsAside type="note">
`@use 'igniteui-theming' as *;`이(가) 해석되지 않으면 Sass 컴파일러의 로드 경로에 `node_modules`이(가) 없는 것입니다. Sass 명령줄에 `--load-path=node_modules`을(를) 전달하거나, Vite에서 `css.preprocessorOptions.scss.loadPaths`을(를) 설정하거나, Next.js에서 `sassOptions.loadPaths`을(를) 설정하십시오.
</DocsAside>

### Sass 도구 체인 없이

출력물을 애플리케이션과 함께 다시 빌드할 필요는 없습니다. 스타일시트를 한 번 컴파일하고 CSS를 커밋한 다음, Sass를 바꿀 때만 다시 컴파일하십시오. [Theming MCP 서버](../ai/theming-mcp.mdx)도 로컬 Sass 컴파일러 없이 바로 사용할 수 있는 CSS로 팔레트와 컴포넌트 테마를 생성할 수 있습니다.
