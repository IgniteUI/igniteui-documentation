# {ProductName}의 접근성

{ProductName} 테마 엔진은 접근성을 스타일 계층에 포함합니다. 실행 시 어떤 배경색에 대해서도 텍스트 색을 계산하고 이를 WCAG 명암 대비 기준과 비교하며, 모든 타입 스케일을 상대 단위로 표현하여 텍스트가 사용자 설정에 따라 크기가 조정되도록 합니다. 또한 색각 이상이 있는 사용자를 위해 선택형 색상 팔레트를 제공합니다.

## 시작하기 전에

이 페이지에서 신뢰할 수 있는 범위는 세 가지 경계로 정해집니다.

**테마 엔진은 스타일을 지정하며, 시맨틱을 추가하지 않습니다.** ARIA 역할, 키보드 처리 및 포커스 관리는 테마가 아니라 컴포넌트 라이브러리에서 옵니다. 테마를 적용한다고 해서 사용자 지정 컨트롤이 그 자체로 접근 가능해지지는 않습니다.

**명암 대비 계산은 생성된 팔레트 색에 적용됩니다.** 엔진은 `palette()` 생성기가 만든 팔레트의 전경색을 계산합니다. 개별 컴포넌트 테마는 특정 전경 토큰을 특정 배경 토큰과 직접 짝지을 수도 있으며, 그 짝은 테마별로 설정되고 아래에 설명된 명암 대비 계산으로 만들어지지 않습니다. 컴포넌트 토큰을 직접 재정의할 때는 [`contrast()`](#명암-대비-비율-직접-확인하기)로 결과를 확인하십시오.

**완성된 제품의 준수 여부는 사용자가 확인해야 합니다.** 엔진이 제어하는 것은 팔레트, 계산된 조합, 타입 스케일 같은 입력이며, 애플리케이션이 이를 어떻게 사용하는지는 제어하지 않습니다. 브랜드 색으로 만든 팔레트도 완전한 준수에 도달할 수 있지만, 엔진이 그 결과를 대신 주장할 수는 없습니다. 준수를 말하기 전에 렌더링된 결과를 확인하십시오.

이 페이지의 기능은 테마 엔진의 동작을 설명합니다. {ProductName} 제품 자체에 대한 준수 진술이 아닙니다. 컴포넌트별 준수 정보는 [접근성 준수](../interactivity/accessibility-compliance.mdx)를 참조하십시오.

## 일반적인 작업 흐름

### 브랜드 색 위에서도 텍스트를 읽기 쉽게 유지하기

팔레트에서 가져온 모든 배경은 하드코딩된 `black` 또는 `white` 대신 `contrast-color()`와(과) 짝지으십시오:

```scss
.my-component {
    background: color($color: 'primary', $variant: 500);
    color: contrast-color($color: 'primary', $variant: 500);
}
```

테마가 이미 내보내는 변수를 사용하여 일반 CSS로 같은 짝짓기를 하면 다음과 같습니다:

```css
.my-component {
  background: var(--ig-primary-500);
  color: var(--ig-primary-500-contrast);
}
```

팔레트에서 오지 않은 색(테넌트 색, 사용자 설정, 실행 시 설정된 값)에는 `adaptive-contrast()`을(를) 사용하십시오:

```scss
.my-component {
    --bg: #09f;

    background: var(--bg);
    color: adaptive-contrast(var(--bg));
}
```

`adaptive-contrast()`은(는) 상대 색 표현식을 감싼 얇은 래퍼이므로, Sass 없이도 같은 결과를 얻을 수 있습니다. `--y-contrast`은(는) 테마가 정의합니다:

```css
.my-component {
  --bg: #09f;

  background: var(--bg);
  color: hsla(from color(from var(--bg) var(--y-contrast)) h 0 l / 1);
}
```

계산은 빌드 시점이 아니라 브라우저에서 이루어집니다. 스타일시트가 컴파일된 후 배경색이 바뀌면 전경색도 다시 계산되어 맞춰지므로, 실행 중 테마 전환과 테넌트별 브랜딩에도 짝짓기가 유지됩니다.

<DocsAside type="note">
`adaptive-contrast()`은(는) 검정과 흰색 중에서 선택합니다. 이 두 가지가 가능한 결과이므로, 이 방식이 중간 톤 배경에 대해 달성할 수 있는 비율은 약 4.6:1로 제한됩니다. 이는 일반 텍스트에 대한 WCAG AA 기준인 4.5:1을 충족하며, 엔진의 기본 설정이 바로 이 기준입니다. 7:1 AAA 기준에 도달하려고 이 방식에만 의존하지 마십시오. AAA에 도달하려면 그것이 가능할 만큼 밝거나 어두운 배경색을 선택해야 합니다.
</DocsAside>

### 명암 대비 수준 설정하기

계산된 전경색은 `--ig-contrast-level` CSS 변수에 담긴 WCAG 기준과 비교되며, 이 변수의 기본값은 `var(--ig-wcag-aa)`입니다. 세 가지 수준이 미리 정의되어 있습니다: `a`, `aa`, `aaa`.

팔레트를 생성할 때 애플리케이션 전체의 수준을 설정하십시오:

```scss
@include palette($palette, $contrast-level: 'aaa');
```

페이지의 한 부분에만 수준을 높이려면 해당 범위에서 변수를 재정의하십시오:

```css
.high-contrast-panel {
  --ig-contrast-level: var(--ig-wcag-aaa);
}
```

명암 대비 수준은 계산된 전경색이 검정과 흰색 사이에서 바뀌는 휘도 임계값을 옮기며, 선택할 수 있는 두 색 자체를 바꾸지는 않습니다. `aaa`을(를) 설정한다고 해서 그 자체로 조합이 준수되는 것은 아니며, 이는 선택한 배경색에 달려 있습니다. [`contrast()`](#명암-대비-비율-직접-확인하기)로 확인하십시오. 생성된 명암 대비 변수는 [팔레트](palettes.mdx)를 참조하십시오.

### 사용자의 브라우저 설정에 맞춰 텍스트 크기 조정하기

별도의 구성은 필요하지 않습니다. 제공되는 네 가지 테마의 모든 타입 스케일은 `font-size`, `line-height`, `letter-spacing` 및 여백을 `rem()` 함수로 표현하므로, 출력되는 모든 값은 루트 글꼴 크기에 상대적입니다.

라이브러리는 기본 크기를 읽을 수 있는 값으로 기록합니다:

```css
--ig-base-font-size: 16px;
```

라이브러리는 `html { font-size: … }` 규칙을 출력하지 않습니다. 이것이 중요한 이유는, 그 규칙을 쓰는 것이 기본 텍스트를 키운 사용자를 테마 시스템이 재정의하는 가장 흔한 방식이기 때문입니다. 라이브러리는 기본 크기를 읽기만 하므로, 브라우저에서 기본값을 더 크게 설정한 사용자는 더 큰 {ProductName} 텍스트를 보게 됩니다.

이는 스타일 지정 계층에서 WCAG 2.1 <a href="https://www.w3.org/WAI/WCAG21/Understanding/resize-text.html" target="_blank" rel="noopener noreferrer">1.4.4 텍스트 크기 조정</a>(레벨 AA)을 다룹니다.

### 명암 대비 기준 높이거나 낮추기

계산된 전경색이 검정에서 흰색으로 바뀌는 수준은 CSS 변수에 담겨 있으므로 Sass 없이도 바꿀 수 있습니다. 기본값은 AA입니다:

```css
:root {
  --ig-contrast-level: var(--ig-wcag-aaa);
}
```

Sass에서는 `palette()` 및 `adaptive-contrast()` 믹스인이 `a`, `aa`, `aaa`를 직접 받습니다.

### 색각 이상 차트 팔레트 켜기

차트는 흔히 색상(hue)만으로 계열을 구분하는데, 이는 색각 이상이 있는 사용자에게는 통하지 않습니다. 테마 엔진은 그 상태의 일반적인 형태에서도 색이 구별되도록 유지되는 두 번째 차트 팔레트를 제공합니다.

팔레트는 **기본적으로 꺼져 있습니다**. `configure-colors()`로 켜십시오:

```scss
// Include at the top level, before your theme includes.
@include configure-colors($enhanced-accessibility: true);
```

그러면 모든 차트 테마가 접근 가능한 세트에서 색을 가져옵니다. 차트 브러시는 테마를 생성할 때 설정되므로 이 설정에는 Sass가 필요합니다. 미리 빌드된 테마 CSS는 이를 위한 변수를 제공하지 않습니다.

{ProductName}에서는 설정할 때 같은 스위치를 사용할 수 있습니다:

```scss
@include core($enhanced-accessibility: true);
```

색만으로 차트의 의미를 전달해서는 안 됩니다. 이 팔레트를 직접 레이블, 뚜렷한 표식 또는 점선 패턴과 함께 사용하면 차트가 회색조에서도 작동합니다.
</DocsAside>

### 명암 대비 비율 직접 확인하기

엔진은 WCAG 상대 휘도 공식을 구현하여 노출하므로, 라이브러리가 사용하는 것과 같은 구현으로 직접 고른 색을 확인할 수 있습니다:

```scss
$ratio: contrast(#09f, #000);   // 7
$lum: luminance(#09f);          // 0.3
```

컴포넌트 토큰을 직접 재정의하거나, 팔레트 생성기가 만들지 않은 색 조합을 도입할 때마다 이를 사용하십시오. 이 두 기능은 컴파일 시점에 실행되며 CSS 대응 기능이 없습니다. 스타일시트는 비율을 계산할 수 없기 때문입니다.

### 스크린 리더에서 숨기지 않고 입력 숨기기

사용자 지정 스타일의 체크박스, 라디오, 스위치는 보통 시맨틱과 키보드 동작을 위해 그 아래에 기본 입력을 유지합니다. 이를 `hide-default()`(으)로 숨기십시오:

```scss
.my-checkbox input {
    @include hide-default();
}
```

이 믹스인은 고정된 선언 세트로 확장되므로, CSS에 직접 작성할 수도 있습니다:

```css
.my-checkbox input {
  position: absolute;
  width: 1px;
  height: 1px;
  margin: -1px;
  border: none;
  clip: rect(0, 0, 0, 0);
  outline: 0;
  pointer-events: none;
  overflow: hidden;
  appearance: none;
}
```

이 믹스인은 입력을 화면 밖으로 옮기면서도 접근성 트리에는 남겨 두므로, 역할, 키보드 동작, 스크린 리더 알림이 유지됩니다. 대신 `display: none` 또는 `visibility: hidden`를 사용하면 컨트롤이 보조 기술에서 완전히 제거되어, 눈으로 보지 않는 모든 사용자에게 컴포넌트가 작동하지 않게 됩니다.

### 어두운 테마 사용하기

제공되는 네 가지 테마인 Material, Bootstrap, Fluent, Indigo는 각각 밝은 팔레트와 함께 완전한 어두운 팔레트를 제공합니다. 어두운 표시는 빛에 민감한 사용자를 포함한 일부 사용자에게 접근성 요구이므로, 단순한 외관 선호가 아니라 지원되는 구성으로 다루십시오. 하나를 선택하는 방법은 [팔레트](palettes.mdx)를 참조하십시오.

## 문제 해결

**직접 스타일을 바꾼 컴포넌트의 텍스트를 읽기 어렵습니다.** 배경 토큰을 바꾸면서 짝이 되는 전경 토큰은 바꾸지 않았을 가능성이 큽니다. 고정 값 대신 `contrast-color()` 또는 `adaptive-contrast()`로 전경색을 설정한 다음, `contrast()`로 결과를 확인하십시오.

**제가 `$contrast-level: 'aaa'`을(를) 설정했는데 색이 많이 바뀌지 않습니다.** 명암 대비 수준은 계산된 전경색이 검정과 흰색 사이에서 바뀌는 휘도 임계값을 옮깁니다. 전경색에 색조를 입히지는 않으므로, 위에서 설명한 한계를 넘어 달성 가능한 비율을 높일 수는 없습니다. AAA에 도달하려면 배경색 자체를 바꾸십시오.

**접근 가능한 팔레트를 켠 후에도 차트 색이 바뀌지 않습니다.** 차트 테마를 생성하기 전에 `configure-colors()`을(를) 포함해야 합니다. 이 포함 코드를 테마 포함 코드 위로 옮기십시오.

**브라우저 글꼴 크기를 키워도 텍스트가 커지지 않습니다.** 애플리케이션 자체 스타일에서 `html { font-size: … }` 규칙이나 `px`의 `font-size` 값이 있는지 확인하십시오. 테마 엔진은 둘 중 어느 것도 출력하지 않습니다.

## FAQ

<Faq>
  <FaqItem question="Ignite UI 테마를 적용하면 애플리케이션이 접근 가능해지나요?" indicatorPosition="end">
    아니요. 테마 엔진은 색 명암 대비, 텍스트 크기 조정, 차트 팔레트를 처리합니다. 키보드 조작 가능성, ARIA 시맨틱, 스크린 리더 지원은 컴포넌트 라이브러리와 직접 작성한 마크업에서 나옵니다.
  </FaqItem>

  <FaqItem question="직접 브랜드 색을 제공해도 텍스트를 읽을 수 있습니까?" indicatorPosition="end">
    예. 팔레트를 통해 사용하는 색은 구성된 수준(기본값 AA)에 따라 측정됩니다. 배경이 바뀔 때마다, 실행 중인 경우에도 전경색은 브라우저에서 다시 계산됩니다. 직접 설정한 짝은 이 계산 범위 밖에 있으므로 <code>contrast()</code>로 확인하십시오.
  </FaqItem>

  <FaqItem question="명암 대비 수준 설정은 실제로 무엇을 바꿉니까?" indicatorPosition="end">
    계산된 전경색이 검정에서 흰색으로 바뀌는 휘도 임계값을 옮깁니다. 선택할 수 있는 두 색은 바뀌지 않으므로, 이 메커니즘이 도달할 수 있는 최대 비율은 높아지지 않습니다.
  </FaqItem>

  <FaqItem question="색각 이상 차트 팔레트는 기본적으로 켜져 있습니까?" indicatorPosition="end">
    아니요. <code>configure-colors($enhanced-accessibility: true)</code>로 켤 수 있습니다<PlatformBlock for="Angular">, 또는 설정할 때 <code>core($enhanced-accessibility: true)</code>로 켤 수 있습니다</PlatformBlock>.
  </FaqItem>

  <FaqItem question="텍스트 크기 조정을 위해 무언가를 구성해야 합니까?" indicatorPosition="end">
    아니요. 모든 타입 스케일은 이미 상대적이며, 라이브러리는 페이지 글꼴 크기를 설정하지 않습니다. 텍스트 크기가 조정되지 않으면 애플리케이션 자체 스타일을 확인하십시오.
  </FaqItem>
</Faq>
