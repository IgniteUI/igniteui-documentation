# Card

The {ProductName} Card organizes related media, text, and actions in one flexible content container.

Use the card to group content about a single subject, such as a product, article, contact, location, or dashboard item.

## Getting Started

To use the {Platform} Card, follow the <PlatformBlock for="Angular">[{ProductName} Getting Started](../general/getting-started.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[{ProductName} Getting Started](../general-getting-started.mdx)</PlatformBlock> topic for the basic project setup, then register the component for your target platform.

<PlatformBlock for="React,WebComponents">

For {Platform} using the **{PackageCommon}** package, install the package:

```cmd
npm install {PackageCommon}
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

You will then need to import the <ApiLink pkg="core" type="Card" />, its theme CSS, and register the component, like so:

```ts
import { defineComponents, IgcCardComponent } from 'igniteui-webcomponents';
import 'igniteui-webcomponents/themes/light/bootstrap.css';

defineComponents(IgcCardComponent);
```

Registering the card also registers the card header, media, content, and actions sub-components. Register any other components your card content uses, such as the avatar, button, and icon button:

```ts
import {
  defineComponents,
  IgcAvatarComponent,
  IgcButtonComponent,
  IgcCardComponent,
  IgcIconButtonComponent,
} from 'igniteui-webcomponents';

defineComponents(IgcCardComponent, IgcAvatarComponent, IgcButtonComponent, IgcIconButtonComponent);
```

</PlatformBlock>

<PlatformBlock for="React">

You will then need to import the Card wrappers and the theme CSS, like so:

```tsx
import {
  IgrCard,
  IgrCardActions,
  IgrCardContent,
  IgrCardHeader,
  IgrCardMedia,
} from 'igniteui-react';
import 'igniteui-webcomponents/themes/light/bootstrap.css';
```

Import any other wrappers your card content uses, such as `IgrAvatar`, `IgrButton`, and `IgrIconButton`.

</PlatformBlock>

<PlatformBlock for="Blazor">

For Blazor using the **IgniteUI.Blazor** package, register the Card module as follows:

```csharp
// in Program.cs file

builder.Services.AddIgniteUIBlazor(typeof(IgbCardModule));
```

Register a module for each other component your card content uses:

```csharp
builder.Services.AddIgniteUIBlazor(typeof(IgbAvatarModule));
builder.Services.AddIgniteUIBlazor(typeof(IgbButtonModule));
builder.Services.AddIgniteUIBlazor(typeof(IgbIconButtonModule));
```

You will also need to link an additional CSS file to apply the styling to the <ApiLink pkg="core" type="Card" /> component. The following needs to be placed in the **wwwroot/index.html** file in a **Blazor Web Assembly** project or the **Pages/_Host.cshtml** file in a **Blazor Server** project:

```razor
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
```

</PlatformBlock>

<PlatformBlock for="Angular">

For Angular using the **igniteui-angular** package, install the package:

```cmd
npm install igniteui-angular
```

Then import the `IGX_CARD_DIRECTIVES` token in the component `imports` collection. The token brings in the card together with all of its supporting components and directives.

```ts
import { IGX_CARD_DIRECTIVES } from 'igniteui-angular/card';
```

Import any other directives your card content uses, such as `IgxButtonDirective`, `IgxIconButtonDirective`, `IgxIconComponent`, and `IgxRippleDirective`, from `igniteui-angular`.

</PlatformBlock>

The simplest way to start using the <ApiLink pkg="core" type="Card" /> is as follows:

```html
  </igx-card-content>
</igx-card>
```

</PlatformBlock>

### Layout

Use layout wrappers when card sections need to be arranged horizontally or split between media and content areas.

For a horizontal card, group the header and content in one wrapper, add the actions beside that wrapper, and apply a flex row to the card content.

<PlatformBlock for="WebComponents">

```html
<igc-card>
  <div class="card-horizontal">
    <div>
      <igc-card-header>
        <img src="https://dl.infragistics.com/x/img/music/rozes.jpg" slot="thumbnail" alt="Rozes album cover" />
        <span slot="title">Rozes</span>
        <span slot="subtitle">Under the Grave (2016)</span>
      </igc-card-header>
      <igc-card-content>
        <p>As I have always said: I write what's real and what's true, even if it means throwing myself under the bus.</p>
      </igc-card-content>
    </div>
    <div class="divider"></div>
    <igc-card-actions>
      <span class="material-icons">skip_previous</span>
      <span class="material-icons">play_arrow</span>
      <span class="material-icons">skip_next</span>
    </igc-card-actions>
  </div>
</igc-card>
```

</PlatformBlock>

## Accessibility

The card is a container. Grouping and media semantics come from the card regions, while keyboard operability and accessible names come from the content you place inside them.

### Keyboard Interaction

The card and its header, media, content, and actions regions declare no key handlers and are not in the tab order. Focus moves through the focusable content you place inside them, in DOM order.

| Key | Action |
| -- | -- |
| <kbd>Tab</kbd> | Moves focus to the next focusable element inside the card, such as a button or link in the content or actions area. |
| <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves focus to the previous focusable element inside the card. |

The actions area always renders its leading region, then its centered content, then its trailing region. Switching the actions to a vertical layout restyles them without reordering the DOM, so keyboard and screen reader order stay the same.

### Screen Readers / ARIA

<PlatformBlock for="Angular">

- The card host renders `role="group"` and a generated `id` in the form `igx-card-1`. Set the `role` input when a different grouping role fits your information architecture, and reference the card title with `aria-labelledby` so the group has an accessible name.
- `igxCardMedia` renders `role="img"`, which exposes the whole media region as a single image. Give that container an accessible name, or move the description to the `alt` attribute of the image inside it.
- The header, title, subtitle, content, and actions members add styling classes only. They contribute no roles and no `aria-*` attributes.
- Give icon-only buttons in the actions area an accessible name; the icon alone provides none.
- Use a single interactive element when the whole card triggers one action, rather than attaching a click handler to the container, so the action keeps a role and a name.

</PlatformBlock>

<PlatformBlock for="WebComponents, React, Blazor">

- The card and every card region render plain slots and set no `role` or `aria-*` attributes. The wrapper elements inside the header have no accessible name and create no landmarks. Add a role and an accessible name on the card host yourself when your information architecture needs one.
- The `title` and `subtitle` slots render whatever element you pass and do not impose a heading level.
- Add `alt` text to images in the media region.
- Give icon-only buttons in the actions area an accessible name; the icon alone provides none.
- Use a single interactive element when the whole card triggers one action, rather than attaching a click handler to the container, so the action keeps a role and a name.

</PlatformBlock>

## FAQ

<Faq>
  <FaqItem question="How do I make an entire card clickable without breaking screen readers?" indicatorPosition="end">
    The card is a plain container and adds no interactive behavior, so wrapping the whole card in a link is a common but harmful shortcut: the accessible name of that link becomes every piece of text in the card. Put a real link or button on the card title instead, then stretch it over the card with an absolutely positioned pseudo-element that covers the card box. The title stays the accessible name, the whole rectangle stays clickable, and text selection and middle-click keep working.
  </FaqItem>
  <FaqItem question="How do I make cards in a row or grid the same height?" indicatorPosition="end">
    The card sizes itself from its content and does not equalize heights across siblings. Lay the cards out in a CSS grid or a flex row so each card stretches to the row height, give the media region a fixed height or `aspect-ratio`, and clamp the title and body to a set number of lines with `-webkit-line-clamp`. Unequal card heights almost always come from letting each image and each paragraph decide its own height.
  </FaqItem>
  <FaqItem question="Why is my card image cropped, and how do I control its size?" indicatorPosition="end">
    <PlatformBlock for="WebComponents, React, Blazor">The card media region stretches its content to the full width and height of the region and applies `object-fit: cover`, so the image is cropped rather than distorted. Size the media region itself with CSS `height` or `aspect-ratio`; changing the dimensions of the image inside has no effect.</PlatformBlock><PlatformBlock for="Angular">The card media region controls the dimensions of the media it contains, so size the region rather than the image. Set the `height` and `width` inputs on `igx-card-media`, and use a consistent aspect ratio across cards so rows of cards stay aligned.</PlatformBlock>
  </FaqItem>
  <FaqItem question="Why do my card actions appear in a different region than the one I placed them in?" indicatorPosition="end">
    <PlatformBlock for="Angular">The card actions area projects content by selector, not by author order. An element with `igxButton` and without `igxEnd` goes to the leading region, and an element with `igxIconButton`, or an `igx-icon`, without `igxStart` goes to the trailing region; only content matching neither selector stays centered. Set `igxStart` or `igxEnd` explicitly to place an action where you want it.</PlatformBlock><PlatformBlock for="WebComponents, React, Blazor">Content in the `end` slot of the card actions takes an automatic leading margin so it aligns with the opposite edge of the actions area, which makes a single trailing action look detached from the rest. Move the element to the `start` slot or to the default slot when it belongs with the other actions. The three regions always render in `start`, default, `end` order regardless of the orientation.</PlatformBlock>
  </FaqItem>
  <FaqItem question="When should I use Grid or List instead of Card?" indicatorPosition="end">
    Use Grid when the data is dense and tabular and readers need to scan, sort, or compare across columns, and use List when many short, uniform rows must fit in a small space. Use Card when each item deserves its own media, longer text, and its own actions. A long scroll of cards is usually a list in disguise.
  </FaqItem>
</Faq>
