# Tabs

The {ProductName} Tabs is a component that organizes related content at the same level of hierarchy into tabs and shows the content of the selected tab.

<PlatformBlock for="Angular">

The Angular Tabs is the `igx-tabs` component. Each `igx-tab-item` in it holds a tab header and the content that the Tabs shows when the tab is selected.

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

Each tab holds its header and its content in one element. The Tabs supports keyboard navigation, and it shows scroll buttons when the tab headers don't fit.

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

The `igc-tabs` element renders the header strip and the scroll buttons. Each `igc-tab` renders its own header and content, and the Tabs places the content of all tabs below the header strip:

```text
igc-tabs[role="tablist"]
└─ #shadow-root
   └─ div[part="tabs"]                                 // the scrollable header strip
      └─ div[part="inner"]
         ├─ igc-icon-button[part="start-scroll-button"] // rendered when the headers overflow
         ├─ slot                                       // the igc-tab elements
         │  └─ igc-tab
         │     └─ #shadow-root
         │        ├─ div[part="tab-header"][role="tab"]
         │        │  └─ div[part="base"]
         │        │     ├─ slot[name="prefix"][part="prefix"]
         │        │     ├─ div[part="content"]
         │        │     │  └─ slot[name="label"]        // falls back to the label property
         │        │     └─ slot[name="suffix"][part="suffix"]
         │        └─ div[part="tab-body"][role="tabpanel"] // visible only for the selected tab
         │           └─ slot                           // the content of the tab
         ├─ igc-icon-button[part="end-scroll-button"]   // rendered when the headers overflow
         └─ div[part="selected-indicator"]
            └─ span                                    // moves under the selected tab header
```

</PlatformBlock>

<PlatformBlock for="Angular">

The `igx-tabs` element renders the header strip from the `igx-tab-header` of each tab item and the content area from the `igx-tab-content` of each tab item:

```text
igx-tabs.igx-tabs
├─ div.igx-tabs-header
│  ├─ button.igx-tabs-header-button                 // start scroll button, hidden when the headers fit
│  ├─ div.igx-tabs-header__content
│  │  └─ div.igx-tabs-header__wrapper[role="tablist"]
│  │     ├─ div.igx-tabs-header-scroll
│  │     │  └─ igx-tab-header[role="tab"]          // one for each igx-tab-item
│  │     │     ├─ [igxPrefix]
│  │     │     ├─ div.igx-tab-header__inner        // [igxTabHeaderIcon] above [igxTabHeaderLabel]
│  │     │     └─ [igxSuffix]
│  │     └─ div.igx-tabs-header__active-indicator
│  └─ button.igx-tabs-header-button                 // end scroll button, hidden when the headers fit
└─ div.igx-tabs-content
   └─ igx-tab-content[role="tabpanel"]             // one for each igx-tab-item; renders its content only when selected
```

</PlatformBlock>

## Usage

Use the {Platform} Tabs to organize different views of the same information or switch between similar or related data sets.

### Type

The Tabs are available in two types - Short, showing only text by default, with the option to have prefix and suffix icons, and Tall, which also has an additional third icon on top of the text.

### Responsiveness

The Tabs can be Content Fit to fill up the available horizontal space by adapting their width, or Fixed with scrolling buttons to navigate a large number of tab items. This allows fitting more content than what is normally possible with the other mode in the same total space.

The <PlatformBlock for="Angular"><ApiLink pkg="core" type="Tabs" member="tabAlignment" label="tabAlignment" /></PlatformBlock><PlatformBlock for="React,WebComponents,Blazor"><ApiLink pkg="core" type="Tabs" member="alignment" label="alignment" /></PlatformBlock> property sets how the {Platform} Tabs arranges the tab headers:

- `start` (default): each tab header is as wide as its content, and the headers start at the start edge of the Tabs.
- `center`: each tab header is as wide as its content, and the headers are centered.
- `end`: each tab header is as wide as its content, and the headers end at the end edge of the Tabs.
- `justify`: the tab headers stretch to fill the width of the Tabs. Use it for the Content Fit mode.

<PlatformBlock for="WebComponents">

```html
<igc-tabs alignment="justify">
  <igc-tab label="Podcasts"></igc-tab>
  <igc-tab label="Playlists"></igc-tab>
  <igc-tab label="Genres"></igc-tab>
</igc-tabs>
```

</PlatformBlock>

```tsx
  <IgrTab label="Playlists" />
```

### Selection

<PlatformBlock for="WebComponents">

The {Platform} Tabs emits `igcChange` with the newly selected tab when the user selects a tab with a click or a key. To select a tab in code, call <ApiLink pkg="core" type="Tabs" member="select" label="select" /> with the tab, or with its `id` or `label`. Read the selected tab from <ApiLink pkg="core" type="Tabs" member="selectedTab" label="selectedTab" />:

```html
<igc-tabs>
  <igc-tab id="overview" label="Overview"></igc-tab>
  <igc-tab id="details" label="Details"></igc-tab>
</igc-tabs>
```

```ts
const tabs = document.querySelector('igc-tabs')!;

tabs.addEventListener('igcChange', (event) => {
  console.log(`Selected: ${event.detail.label}`);
});

tabs.select('details');
console.log(tabs.selectedTab?.label); // "Details"
```

</PlatformBlock>

<PlatformBlock for="React">

The {Platform} Tabs calls `onChange` with the newly selected tab when the user selects a tab with a click or a key. To select a tab in code, call <ApiLink pkg="core" type="Tabs" member="select" label="select" /> with the tab, or with its `id` or `label`:

```tsx
import { useRef } from 'react';
import { IgrTab, IgrTabs } from 'igniteui-react';

export default function ProfileTabs() {
  const tabsRef = useRef<IgrTabs>(null);

  return (
    <>
      <IgrTabs ref={tabsRef} onChange={(e: CustomEvent<IgrTab>) => console.log(e.detail.label)}>
        <IgrTab label="Overview" />
        <IgrTab label="Details" />
      </IgrTabs>
      <button onClick={() => tabsRef.current?.select('Details')}>Show details</button>
    </>
  );
}
```

</PlatformBlock>

<PlatformBlock for="Blazor">

The {Platform} Tabs raises `Change` with the newly selected tab when the user selects a tab with a click or a key. To select a tab in code, call <ApiLink pkg="core" type="Tabs" member="SelectAsync" label="SelectAsync" /> with the `id` or the `Label` of the tab:

```razor
<IgbTabs @ref="Tabs" Change="OnTabChange">
    <IgbTab Label="Overview" />
    <IgbTab Label="Details" />
</IgbTabs>

<button @onclick="ShowDetails">Show details</button>

@code {
    private IgbTabs Tabs { get; set; }

    private async Task ShowDetails()
    {
        await Tabs.SelectAsync("Details");
    }

    private void OnTabChange(IgbTabComponentEventArgs e)
    {
        Console.WriteLine(e.Detail.Label);
    }
}
```

### Do/Don't

## Accessibility

The {Platform} Tabs uses the roles of the WAI-ARIA tabs pattern: users reach the tab headers with the Tab key, move between them with the arrow keys, and select a tab to show its content.

### Keyboard Interaction

<PlatformBlock for="React,WebComponents,Blazor">

The header strip of the {Platform} Tabs is a single tab stop: only the selected tab header is in the tab order, or the first enabled tab header when no tab is selected. The content of the selected tab is the next tab stop. The following keys work while a tab header has the focus:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves the focus out of the header strip, to the content of the selected tab or to the previous focusable element. The Tabs doesn't handle these keys. |
| <kbd>Arrow Right</kbd> | Moves the focus to the next enabled tab header, and from the last one to the first. In a right-to-left layout, moves it to the previous one. With the `auto` activation, also selects the tab. |
| <kbd>Arrow Left</kbd> | Moves the focus to the previous enabled tab header, and from the first one to the last. In a right-to-left layout, moves it to the next one. With the `auto` activation, also selects the tab. |
| <kbd>Home</kbd> | Moves the focus to the first enabled tab header. With the `auto` activation, also selects the tab. |
| <kbd>End</kbd> | Moves the focus to the last enabled tab header. With the `auto` activation, also selects the tab. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Selects the focused tab. |

The {Platform} Tabs handles these keys on `keydown`:

- It prevents their default action, so the arrow keys, Home, End, and Space don't scroll the page.
- A key that you hold doesn't repeat its action.
- A key that you press together with Shift, Ctrl, Alt, or Meta does nothing.
- The Tabs scrolls the header that receives the focus into view.

With a pointer, a click on a tab header focuses and selects the tab. A disabled tab ignores clicks. The scroll buttons aren't in the tab order.

</PlatformBlock>

<PlatformBlock for="Angular">

Only the selected tab header of the Angular Tabs is in the tab order, so the header strip is a single tab stop. When no tab item is selected, no tab header is in the tab order. The content of the selected tab is the next tab stop. The following keys work while a tab header has the focus:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves the focus out of the header strip, to the content of the selected tab or to the previous focusable element. The Tabs doesn't handle these keys. |
| <kbd>Arrow Right</kbd> | Moves the focus to the next enabled tab header, and from the last one to the first. In a right-to-left layout, moves it to the previous one. With the `auto` activation, also selects the tab. |
| <kbd>Arrow Left</kbd> | Moves the focus to the previous enabled tab header, and from the first one to the last. In a right-to-left layout, moves it to the next one. With the `auto` activation, also selects the tab. |
| <kbd>Home</kbd> | Moves the focus to the first enabled tab header. With the `auto` activation, also selects the tab. |
| <kbd>End</kbd> | Moves the focus to the last enabled tab header. With the `auto` activation, also selects the tab. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | With the `manual` activation, selects the focused tab by clicking its header. |

With a pointer, a click on a tab header selects the tab when the tab item has content. A disabled tab header ignores clicks. The scroll buttons aren't in the tab order.

### Screen Readers / ARIA

<PlatformBlock for="React,WebComponents,Blazor">

The {Platform} Tabs renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| `igc-tabs` | `tablist` | `aria-orientation="horizontal"`, set through element internals |
| The `tab-header` part of each tab | `tab` | `aria-selected`, `aria-disabled`, `aria-controls` that points to the content of the tab, `aria-posinset`, and `aria-setsize` |
| The `tab-body` part of each tab | `tabpanel` | `aria-labelledby` that points to the header of the tab |

The {Platform} Tabs also behaves as follows for assistive technology:

- A tab takes its accessible name from its header content: the `label` property or the `label` slot, and the content of the `prefix` and `suffix` slots.
- The content of the tabs that aren't selected is hidden and `inert`, so assistive technology and the keyboard skip it.
- The `aria-posinset` and `aria-setsize` attributes of each tab header give screen readers the position of the tab in the set, such as "2 of 3".
- The Tabs doesn't use a live region. A changed selection reaches assistive technology through the `aria-selected` state and the focus.

</PlatformBlock>

<PlatformBlock for="Angular">

The Angular Tabs renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| The `div.igx-tabs-header__wrapper` element in the header | `tablist` | — |
| `igx-tab-header` | `tab` | `aria-selected`, `aria-disabled`, and, when the tab item has content, an `id` and `aria-controls` that points to the content |
| `igx-tab-content` | `tabpanel` | `aria-labelledby` that points to the header of the tab item |

The Angular Tabs also behaves as follows for assistive technology:

- A tab takes its accessible name from the content of its `igx-tab-header`.
- The Tabs renders the content of the selected tab item only, so the content of the other tab items isn't in the DOM.
- Tab items without `igx-tab-content`, such as the tabs that drive the router, get no `id` and `aria-controls`.
- The Tabs doesn't use a live region. A changed selection reaches assistive technology through the `aria-selected` state and the focus.

</PlatformBlock>

### Accessibility Compliance

Infragistics documents {ProductName} accessibility support for Section 508 and WCAG 2.1 guideline areas in the [Accessibility Compliance](../interactivity/accessibility-compliance.mdx) topic.

| Criterion | How the component complies |
| --- | --- |
| [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships) | The `tablist`, `tab`, and `tabpanel` roles expose the structure, and each tab panel is labeled by its tab header through `aria-labelledby`. |
| [1.4.1 Use of Color](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color) | In the Material, Fluent, and Indigo themes, the selected tab header shows an indicator line under it, so the selection doesn't depend on color alone. |
| [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | The arrow keys, Home, and End move between the tab headers, and Enter and Space select the focused tab<PlatformBlock for="Angular"> with the `manual` activation</PlatformBlock>. |
| [2.1.2 No Keyboard Trap](https://www.w3.org/WAI/WCAG21/Understanding/no-keyboard-trap) | The Tabs doesn't handle the Tab key, so Tab and Shift + Tab move the focus out of the header strip. |
| [2.4.3 Focus Order](https://www.w3.org/WAI/WCAG21/Understanding/focus-order) | The header strip is a single tab stop, followed by the content of the selected tab. |
| [2.4.7 Focus Visible](https://www.w3.org/WAI/WCAG21/Understanding/focus-visible) | The focused tab header takes the hover colors of the theme, so it stands out from the other tab headers. |
| [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | Each tab header exposes the `tab` role, a name from its content, and its selected and disabled states through `aria-selected` and `aria-disabled`. |

Your responsibilities:

- Give every tab a text label that names its content. A tab takes its accessible name from its header content, so a header with an icon only needs a text alternative. See [Type](#type).
- When you override the theme colors, keep a contrast ratio of at least 3:1 between the selected indicator and the background, as [1.4.11 Non-text Contrast](https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast) requires, and keep the focused tab header distinct from the other headers.
- Don't use the Tabs for the steps of a sequential process. Use a Stepper, which communicates the order of the steps.
<PlatformBlock for="Angular">- Keep a tab item selected, so that keyboard users can reach the header strip, and set the `manual` activation for tabs that drive the router.</PlatformBlock>

## Dependencies

The {Platform} Tabs requires a theme to apply its colors and sizes. See the framework-specific setup in <PlatformBlock for="Angular">[**Getting Started**](../general/getting-started.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[**Getting Started**](../general-getting-started.mdx)</PlatformBlock>.

<PlatformBlock for="Angular">

The scroll buttons of the Angular Tabs use the Icon Button and the Icon, and the `theme()` mixin includes their styles together with the Tabs styles.

</PlatformBlock>

<PlatformBlock for="WebComponents">

The registration of the `IgcTabsComponent` also registers the `igc-tab` element and the `igc-icon-button` element of the scroll buttons. Register the components that you place in the tabs, such as the Icon, separately.

</PlatformBlock>

<PlatformBlock for="Blazor">

Register the modules of the components that you place in the tabs, such as the `IgbIconModule`, separately.

</PlatformBlock>

## FAQ

These questions cover common {Platform} Tabs setup, accessibility, and usage scenarios.

<Faq>
  <FaqItem question="How do I select a tab in code?" indicatorPosition="end">
    <PlatformBlock for="Angular">Set the `selectedIndex` property of the Angular Tabs, or set the `selected` input of a tab item to `true`. The Angular Tabs emits `selectedIndexChanging` and `selectedItemChange` for these changes too.</PlatformBlock><PlatformBlock for="React,WebComponents">Call the `select` method of the {Platform} Tabs with a tab, or with the `id` or the `label` of a tab, or set `selected` on the tab. The {Platform} Tabs doesn't emit the change event for a selection that you make in code.</PlatformBlock><PlatformBlock for="Blazor">Call the `SelectAsync` method of the Blazor Tabs with the `id` or the `Label` of a tab, or set `Selected` on the tab. The Blazor Tabs doesn't raise `Change` for a selection that you make in code.</PlatformBlock>
  </FaqItem>
  <FaqItem question="Can I prevent users from switching to another tab?" indicatorPosition="end">
    <PlatformBlock for="Angular">Yes. Handle the `selectedIndexChanging` event of the Angular Tabs and set `cancel` to `true` to keep the current tab, for example while a form in it has unsaved changes. To make a tab unavailable at all times, set `disabled` on the tab item.</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">The change event of the {Platform} Tabs isn't cancelable, because the {Platform} Tabs emits it after the selection changes. Set `disabled` on the tabs that users must not open, and enable them when they become available.</PlatformBlock>
  </FaqItem>
  <FaqItem question="Does the Tabs keep the content of hidden tabs in the DOM?" indicatorPosition="end">
    <PlatformBlock for="Angular">No. The Angular Tabs adds the content of the selected tab item to the DOM and removes the content of the other tab items from it. Code that queries the DOM, such as `document.querySelector`, finds only the content of the selected tab item.</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">Yes. The {Platform} Tabs keeps the content of every tab in the DOM, hides the content of the tabs that aren't selected, and makes it `inert`, so users and assistive technology can't reach it until its tab is selected.</PlatformBlock>
  </FaqItem>
  <FaqItem question="Should I use the Tabs for a checkout or another step-by-step process?" indicatorPosition="end">
    No. The {Platform} Tabs organizes related information that users can open in any order, and it doesn't communicate an order of steps. Use the {Platform} Stepper for a sequential process, such as a checkout or a configuration wizard.
  </FaqItem>
</Faq>
