# {ProductName} Changelog



All notable changes for each version of {ProductName} are documented on this page.

## **{PackageVerLatest}**

### {PackageGrids} (Grids)

- <ApiLink type="Grid" />, <ApiLink type="TreeGrid" />, <ApiLink type="HierarchicalGrid" />, <ApiLink type="PivotGrid" />
  - The Excel style filtering search list is now virtualized by the new [Virtual Scroll](./layouts/virtual-scroll.mdx) component. A row is measured in the DOM once it renders and the measured size replaces the estimate it started from. The list markup changed accordingly: the internal display container and vertical scrollbar helper elements are replaced by the virtual scroll host and its item wrappers. Applications and tests that reach into those elements directly need updating.
  - **Accessibility** - Removed the nested list role from the internal virtual scroll container of the Excel style filtering, preserving its existing listbox and options.
  - The `rowStyles`, `headerStyles` and `headerGroupStyles` properties are now typed `GridStyleCSSProperty | null` instead of `any`.
  - Scrollbars are now styled with the standard `scrollbar-color` and `scrollbar-width` properties instead of the `::-webkit-scrollbar-*` pseudo-elements. Scrollbars rendered inside the grids, the Column Actions and the Excel style filtering menus follow that host's own background and foreground colors. Scrollbar arrow buttons cannot be styled or enabled through the standard properties, and `scrollbar-width: thin` removes them where the platform draws them. Firefox versions prior to 64 render the scrollbars with the platform default colors and size.
- **PDF export**
  - Summary rows are now shaded like the header row of the exported table. A summary closes the rows above it the way the header opens them, so it no longer reads as one more record. As with the header background, the shading follows the `showTableBorders` option.
  - The row dimension cells of a <ApiLink type="PivotGrid" /> export are shaded the same way. A row dimension value that repeats down consecutive records is now drawn once, in a single cell over all of them, the way the grid merges its own row headers. A value merges only under the same parent dimension, so the same date under two different cities still gets a cell each, and a cell that would reach past the bottom of a page is cut off there and opened again under the headers of the next one.

**Breaking Changes**

- **Theming**
  - The `--ig-grid-summary-border-width` and `--ig-grid-summary-pinned-border-width` CSS custom properties were removed. A summary cell takes its border width from the grid itself, the header border width for the cell separator and the pinned border width for the pinned border, so a summary border can no longer be thicker or thinner than the column border it continues. The border styles and colors stay themable through the `--ig-grid-summary-border-style`, `--ig-grid-summary-pinned-border-style`, `--ig-grid-summary-border-color` and `--ig-grid-summary-pinned-border-color` properties.
  - The standard scrollbar properties expose only two colors and three width keywords, so most of the scrollbar theme variables no longer have any effect. `--sb-thumb-bg-color` and `--sb-track-bg-color` continue to work, while the hover, border, corner and minimum height variables are ignored. `--sb-size` no longer sets the scrollbar thickness, because `scrollbar-width` accepts only `auto`, `thin` or `none`. Set `--sb-width: thin` on the scope that declares the scrollbar variables, or `scrollbar-width: thin` directly on the scrolling element, where a thinner scrollbar is required.

#### New Components

The following components from `igniteui-webcomponents` 7.3.0 and 7.4.0 are now available in {ProductName}:

- [Breadcrumbs](./layouts/breadcrumbs.mdx) (<ApiLink type="Breadcrumbs" /> and <ApiLink type="Breadcrumb" />) - Show a navigation trail.
- [Color Picker](./inputs/color-picker.mdx) (<ApiLink type="ColorPicker" />) - Provides a user interface for selecting colors, supporting various color formats and a customizable palette.
- [QR Code](./inputs/qr-code.mdx) (<ApiLink type="QrCode" />) - Renders a scannable QR code as an SVG from the `value` property, encoding the data in numeric, alphanumeric or byte mode.
- [Virtual Scroll](./layouts/virtual-scroll.mdx) (<ApiLink type="VirtualScroll" />) - Renders large or unbounded lists efficiently, because it renders only the items in the viewport plus a configurable `overScan`.
  - Supports `vertical` and `horizontal` orientation, and RTL layouts.
  - Item sizes can be fixed, estimated with `estimatedItemSize`, or fully variable. The component measures each rendered item and corrects its estimate automatically. The average measured item size replaces `estimatedItemSize` for the items that are not measured yet, so the scrollbar follows the real content.
  - Item elements are recycled: an item that stays in the rendered window keeps its element, and the elements of the items that leave show the items that enter. The `keyFunction` property returns the key of an item, so an item keeps its element also when it moves in `data`. Without it, the index is the key. DOM state that the item template does not bind, for example the state of a checkbox without a `checked` binding, stays with the element, so bind such state in the item template.
  - The component operates correctly above the maximum scroll coordinate of the browser, so lists that are much larger than the DOM permits continue to scroll and render correctly.

#### New Features

- #### Button Group
  - The single selection modes (`single` and `single-required`) now use the radio group keyboard pattern. The group is one tab stop, and the arrow keys move the focus and the selection together, skipping disabled buttons and wrapping at the two ends. `alignment="horizontal"` uses ArrowLeft and ArrowRight and follows the text direction, `alignment="vertical"` uses ArrowUp and ArrowDown. The `multiple` mode does not change and each button stays a tab stop.
  - Improved accessibility: the single selection modes expose a `radiogroup` with `radio` buttons, instead of toggle buttons with `aria-pressed`. The `radiogroup` or `group` role and the disabled state are now on the <ApiLink type="ButtonGroup" /> host, so an `aria-label` or `aria-labelledby` on the host names the group, and `alignment` sets the `aria-orientation` of the radio group. The `focused` CSS part of <ApiLink type="ToggleButton" /> is now documented.
- #### Calendar, Date Picker, Date Range Picker
  - <ApiLink type="Calendar" /> now exports the `label-inner`, `months-row` and `years-row` CSS parts. The pickers export them as `calendar-label-inner`, `months-row` and `years-row`.
  - When `weekStart` is not set, the week starts on the first day of the week of the `locale`, as reported by `Intl.Locale.prototype.getWeekInfo()`. For example, `bg` starts on Monday and `en` stays on Sunday. An explicit `weekStart` has priority. Set it to `undefined` to return to the locale value. Browsers without `getWeekInfo()` keep the Sunday default.
  - The header date and the month/year navigation follow the field order of the `locale`. For `ja`, the year button precedes the month button. The years view keeps plain numbers.
- #### Chip
  - `outlined` property. When set to `true`, the chip shows an outlined style.
  - The `start` and `end` slots, and the new `action` and `remove` CSS parts, are now documented.
- #### Combo, Color Picker, Date Picker, Date Range Picker, Dropdown, Select, Tooltip
  - `scrollStrategy` property. It sets what the popup does when a container scrolls: `hide` (default) hides the popup while its anchor is fully out of view, `scroll` keeps the popup visible and on its anchor, and `close` closes the component on each scroll (a `sticky` tooltip also closes). The date pickers ignore the property in `dialog` mode.
- #### Dropdown
  - Improved accessibility: the target element declares `aria-haspopup="listbox"`. While the list is open, the target holds `aria-activedescendant` that points at the item that keyboard navigation is on, so screen readers announce the highlight.
- #### Icon
  - `registerIcon` and `registerIconFromText` now accept a `RegisterIconOptions` object as their third argument, in addition to the plain collection string. `stripMeta: true` removes the `<title>` and `<desc>` elements from the stored SVG, which prevents the native browser tooltip on hover. The title text stays available as the `aria-label` of the host <ApiLink type="Icon" /> element.
- #### Mask Input, Date Time Input, Date Range Picker
  - The masked editors now support the standard undo and redo shortcuts: `Ctrl + Z` / `Cmd + Z` to undo, and `Ctrl + Y`, `Ctrl + Shift + Z` / `Cmd + Shift + Z` to redo. A sequence of typed characters, or a sequence of deletions, becomes one undo step. A caret movement, a paste, a drop, a cut, a spin of a date part, and an IME composition each start a new step. A restored step emits `onInput`, so two-way bindings follow the undo. The history stays through focus changes and is discarded when you set the value programmatically, when the form resets the control, or when the `mask`, `prompt` or `inputFormat` pattern changes.
- #### Splitter
  - `startCollapsed` and `endCollapsed` properties. Use them to read and to set the collapsed state of each pane.
  - `onLayoutChanged` event. The component emits it after a user resize or a change of the expansion state. The payload holds the current layout (`startSize`, `endSize`, `startCollapsed`, `endCollapsed`).
- #### Tabs
  - `selectedTab` property. It returns the selected <ApiLink type="Tab" /> element, or `null`.
  - `select()` now also matches the `label` of a tab, in addition to its IDREF, so you can pass the value that `selected` reports back into it.
  - Improved accessibility: the tab headers expose `aria-posinset` and `aria-setsize`, the strip declares its `aria-orientation`, and the selected panel is focusable, so keyboard users can reach panel content that holds no focusable elements of its own. The strip also keeps a tab stop when no tab is selected.
  - The component now finds <ApiLink type="Tab" /> elements that come through an intermediate slot, so another component can wrap <ApiLink type="Tabs" />.
- #### Tooltip
  - Improved accessibility: the anchor points at the tooltip with `aria-describedby`, so screen readers announce the content as the description of the anchor. In `sticky` mode the default close action is a labelled `<button>` that you can reach and operate from the keyboard. The new `close-button` CSS part exposes it.
- #### Popover
  - Popover-based components now use native CSS anchor positioning in browsers that support it (Chrome/Edge 133+, Firefox 147+, Safari 26+). Other browsers use `@floating-ui/dom` as before, and load it only when necessary.
- #### Themes
  - All components now carry `forced-colors: active` styles in the Material, Bootstrap, Fluent and Indigo themes. In Windows High Contrast mode they draw from the system palette (`CanvasText`, `Highlight`, `GrayText`, `LinkText`), and the disabled, hover, focus and selected states stay distinguishable.

#### Breaking Changes

- #### Combo, Color Picker, Date Picker, Date Range Picker, Dropdown, Select, Tooltip
  - **Behavior change:** The popup now hides while its anchor is fully scrolled out of view. Before, it stayed visible. Set `scrollStrategy="scroll"` to keep the previous behavior.
- #### Dropdown, Select, Tooltip
  - The popup no longer moves along the viewport edge to stay in view. It only flips to the opposite side.
- #### Button Group
  - A disabled group no longer sets `disabled` on its buttons. The buttons inherit the state, so a button that is disabled on its own stays disabled when you enable the group again, and the buttons that you add to a disabled group are also disabled.
  - In the single selection modes each button is no longer a separate tab stop. See the keyboard pattern in the New Features section above.
- #### Date Time Input, Date Picker, Date Range Picker
  - The components no longer change the `value` property while the user types. `value` now holds only a committed value and changes together with the `onChange` event, which the components still emit on blur. Before, `value` changed on each keystroke and no event announced the change. This makes the components usable in templates that bind `value` externally, such as an edit template in <ApiLink type="Grid" />.
  - The value that the user types, and the result of a spin of a date part or of `Ctrl + ;`, is available in the `detail` of the `onInput` event. A spin of a date part in a focused editor also defers to the commit on blur. A programmatic `stepUp()` or `stepDown()` on an unfocused component changes `value` immediately, as do `clear()`, `setRangeText()` and direct assignments. In the pickers the calendar continues to follow the typed date during editing.
- #### Dropdown
  - The component no longer emits `onChange` when you select the item that is already selected. The list still closes, as before.
- #### Tabs
  - The scroll buttons now scroll to the nearest tab that is not fully visible, instead of a fixed step of 180px. A tab below a scroll button counts as not visible, so one click brings exactly one tab into view.
- #### Tooltip
  - A tooltip that closes from a hide trigger now waits exactly `hideDelay`. Before, it waited through an additional, undocumented stage of 180ms.
  - In `sticky` mode the default close button hides the tooltip immediately and does not wait for `hideDelay`.
  - `focusin` and `focusout` are now part of the default `showTriggers` and `hideTriggers`, so a tooltip opens when its anchor gets keyboard focus, and closes when the focus leaves the anchor.
- #### Chip
  - **Breaking for custom styles:** `part="base"` is now a plain wrapper. The selection control moved to the new `action` part, and the remove control to the new `remove` part. Move rules that target `::part(base)` for the interactive surface to `::part(action)`.
  - The `focus-outline-color` and `focus-selected-outline-color` CSS variables are replaced by `focus-shadow-color` and `focus-selected-shadow-color`.
  - The `onRemove` event no longer declares a boolean detail that it never carried.
- #### Avatar
  - The component now exposes `role="img"`. Before, it declared `image`, which is an ARIA 1.3 token that current tools do not know.
  - The accessible name now comes from `alt`, and then from `initials`. The role description is the static string `avatar`. Before, the name was always the literal "avatar", and `alt` or `initials` became the role description.
- #### Badge
  - The role description is the static string `badge`. The visual `variant` no longer reaches assistive technology. The `icon` CSS part now applies only when an <ApiLink type="Icon" /> is the only content of the badge, as the documentation already stated.
- #### Carousel
  - The component now delegates focus to its indicator container, its navigation buttons, or the first focusable element in the active slide, in this sequence.
- #### Tile Manager
  - <ApiLink type="Tile" /> renders its resize handles directly. The `trigger-side`, `trigger` and `trigger-bottom` parts keep their names, and the new `tile-container` part wraps the tile content together with the handles.
- #### AI-Assisted Development - Skills
  - Renamed the `grid-lite-to-igr-grid-migration` skill to `igniteui-react-migrate-grid-lite-to-premium` to follow the `igniteui-react-` prefix used by the other skills. Reinstall it under the new folder name and remove the old one.
  - Renamed each skill's `reference/` folder to `references/`. Reinstall the affected skills (`igniteui-react-components`, `igniteui-react-customize-theme`, `igniteui-react-generate-from-image-design`) so their links resolve.

        It can be enabled on the individual columns:

<PlatformBlock for="React">

```tsx
        <IgrColumn field="field" merge={true}></IgrColumn>
```

</PlatformBlock>
        The merging can be configured on the grid level to apply either:
  - `onSort` - only when the column is sorted.
  - `always` - always, regardless of data operations.

<PlatformBlock for="React">

```tsx
        <IgrGrid cellMergeMode="always">
        </IgrGrid>
```

</PlatformBlock>

        The default `cellMergeMode` is `onSort`.

        The functionality can be modified by setting a custom `mergeStrategy` on the grid, in case some other merge conditions or logic is needed for a custom scenario.

        It's possible also to set a `mergeComparer` on the individual columns, in case some custom handling is needed for a particular data field.

<PlatformBlock for="React">

```tsx
        <IgrColumn field="Col1" pinned={true} pinningPosition="pinningPosition">
        </IgrColumn>
```

</PlatformBlock>

        ```ts
        pinningPosition = ColumnPinningPosition.End;
        ```

        Or with the API, via optional parameter:

        ```ts
        grid.pinColumn('Col1', 0, ColumnPinningPosition.End);
        grid.pinColumn('Col2', 0, ColumnPinningPosition.Start);
        ```

        If property `pinningPosition` is not set on a column, the column will default to the position specified on the grid's `pinning` options for `columns`.

  - Improved sorting algorithm efficiency using Schwartzian transformation. This is a technique, also known as decorate-sort-undecorate, which avoids recomputing the sort keys by temporarily associating them with the original data records.
