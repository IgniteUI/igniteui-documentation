# Dialog

The {ProductName} Dialog is a component that shows a message, a confirmation, or a form in a modal window that users complete or close before they continue.

<PlatformBlock for="Angular">

The Angular Dialog is the `igx-dialog` component. It shows a title, a message, and up to two built-in buttons, or the title, content, and actions that you project into it.

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

The Dialog is built on the native `dialog` element. It shows a title, a message, your content, and the action buttons in its footer, and it closes when the user presses Escape.

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

The `igc-dialog` element renders a backdrop and a native `dialog` element with a header, a content section, and a footer:

```text
igc-dialog
└─ #shadow-root
   ├─ div[part="backdrop"]                       // the backdrop behind the open dialog
   └─ dialog[part="base"][role="dialog"]         // opened as a modal dialog
      ├─ header[part="title"]                    // hidden when the dialog has no title
      │  └─ slot[name="title"]                   // falls back to the title property
      ├─ section[part="content"]
      │  ├─ slot[name="message"]                 // hidden when empty
      │  └─ slot                                 // the content of the dialog
      └─ footer[part="footer"]
         └─ slot[name="footer"]                  // falls back to the default OK button
```

</PlatformBlock>

<PlatformBlock for="Angular">

While the Angular Dialog is open, the overlay renders it inside the `igx-dialog` element, in the top layer of the page:

```text
igx-dialog
└─ div.igx-overlay__wrapper--modal[popover="manual"]  // the backdrop of a modal dialog
   └─ div.igx-overlay__content--modal
      └─ div.igx-dialog[tabindex="0"]                 // keeps the focus inside the dialog
         └─ div.igx-dialog__window[role]
            ├─ div.igx-dialog__window-title           // the title, or the projected igx-dialog-title
            ├─ div.igx-dialog__window-content
            │  └─ span.igx-dialog__window-message      // the message, or the projected content
            └─ div.igx-dialog__window-actions          // the built-in buttons, or the projected igx-dialog-actions
```

## Getting Started

To use the {Platform} Dialog, follow the <PlatformBlock for="Angular">[{ProductName} Getting Started](../general/getting-started.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[{ProductName} Getting Started](../general-getting-started.mdx)</PlatformBlock> topic for the basic project setup, then add the component for your target platform.

<PlatformBlock for="WebComponents">

Install the **{PackageCommon}** package:

```cmd
npm install {PackageCommon}
```

Then import the <ApiLink pkg="core" type="Dialog" />, its theme CSS, and register the component. The registration also registers the `igc-button` element of the default OK button:

```ts
import { defineComponents, IgcDialogComponent } from 'igniteui-webcomponents';
import 'igniteui-webcomponents/themes/light/bootstrap.css';

defineComponents(IgcDialogComponent);
```

</PlatformBlock>


```tsx
import { IgrButton, IgrDialog } from 'igniteui-react';
import 'igniteui-webcomponents/themes/light/bootstrap.css';
```

</PlatformBlock>

<PlatformBlock for="Blazor">

Register the Dialog module and the Button module of the action buttons in **Program.cs**:

```razor
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
```

<PlatformBlock for="Angular">

If your project doesn't use {ProductName} yet, run `ng add igniteui-angular`. Then import the `IGX_DIALOG_DIRECTIVES` token and add it to the `imports` of your component. The token holds the <ApiLink pkg="core" type="Dialog" /> and the `igx-dialog-title` and `igx-dialog-actions` directives. The built-in buttons of the dialog don't need extra imports, and the example below imports the `IgxButtonDirective` for the button that opens the dialog:

```ts
import { Component } from '@angular/core';
import { IGX_DIALOG_DIRECTIVES } from 'igniteui-angular/dialog';
import { IgxButtonDirective } from 'igniteui-angular/directives';
// import { IGX_DIALOG_DIRECTIVES } from '@infragistics/igniteui-angular/dialog'; for licensed package

@Component({
    selector: 'app-home',
    template: `
        <button igxButton="contained" (click)="dialog.open()">Delete file</button>

        <igx-dialog #dialog
            title="Delete File"
            message="Are you sure you want to delete this file?"
            leftButtonLabel="Cancel"
            (leftButtonSelect)="dialog.close()"
            rightButtonLabel="Delete"
            (rightButtonSelect)="dialog.close()">
        </igx-dialog>
    `,
    imports: [IGX_DIALOG_DIRECTIVES, IgxButtonDirective]
})
export class HomeComponent {}
```

The built-in buttons don't close the Angular Dialog by themselves. Call `close()` in the handlers of their `leftButtonSelect` and `rightButtonSelect` events.

</PlatformBlock>

## Usage

Use the {Platform} Dialog to show a message or alert to the user, allowing him to take action accordingly or to present a form that requires immediate action before proceeding, such as a login. The Dialog is displayed modally, meaning that the user has to complete or close it before moving on.

### Types

The Dialog can be used to show an alert with only a confirming button, a message with cancellation and confirmation, or as a container for action that needs immediate attention, such as a user logging into his account. Its Button area is templatable, allowing you, for example, to adjust the buttons.

<PlatformBlock for="React,WebComponents,Blazor">

For an alert, leave the `footer` slot empty, and the {Platform} Dialog shows its default OK button, which closes the dialog. For a confirmation, place the cancel and the confirm buttons in the `footer` slot. For a custom dialog, place the controls in the content of the dialog:

</PlatformBlock>

### Title and Content

<PlatformBlock for="React,WebComponents,Blazor">

The <ApiLink pkg="core" type="Dialog" member="title" label="title" /> property sets the text of the dialog header. To show other content in the header, such as an icon, place it in the `title` slot, which takes precedence over the property. Place a short message in the `message` slot, which the {Platform} Dialog shows above the rest of the content and limits to a width of 40 characters. Everything else that you place in the dialog becomes its content:

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-dialog>
  <span slot="title">Delete File</span>
  <span slot="message">Are you sure you want to delete this file?</span>

</igc-dialog>
```

</PlatformBlock>


</PlatformBlock>

<PlatformBlock for="Angular">

The <ApiLink pkg="core" type="Dialog" member="title" label="title" /> and <ApiLink pkg="core" type="Dialog" member="message" label="message" /> properties set the text of the dialog header and the dialog body. To show other content in the header, such as an icon, project an `igx-dialog-title` element or an element with the `igxDialogTitle` directive. Everything else that you place in the dialog becomes its content. The Angular Dialog ignores the projected title when you set `title`, and the projected content when you set `message`:

```html

</igx-dialog>
```

### Action Buttons

<PlatformBlock for="React,WebComponents,Blazor">

Place the action buttons of the {Platform} Dialog in the `footer` slot. When the slot is empty, the dialog shows a default OK button, which closes the dialog and emits the closing events. Set <ApiLink pkg="core" type="Dialog" member="hideDefaultAction" label="hideDefaultAction" /> to hide the default button, for example when the content of the dialog has its own buttons. The property has no effect when the `footer` slot has content:

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-dialog title="Processing" hide-default-action>
  <p>Exporting the report. This can take a few seconds.</p>
</igc-dialog>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrDialog title="Processing" hideDefaultAction={true}>
  <p>Exporting the report. This can take a few seconds.</p>
</IgrDialog>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbDialog Title="Processing" HideDefaultAction="true">
    <p>Exporting the report. This can take a few seconds.</p>
</IgbDialog>
```

</PlatformBlock>

<PlatformBlock for="Angular">

The <ApiLink pkg="core" type="Dialog" member="leftButtonLabel" label="leftButtonLabel" /> and <ApiLink pkg="core" type="Dialog" member="rightButtonLabel" label="rightButtonLabel" /> properties add the built-in buttons, and each button renders only when its label is set. The `leftButtonType` and `rightButtonType` properties set the button variant, `flat` by default, and the `leftButtonRipple` and `rightButtonRipple` properties set the ripple color. A click on a built-in button emits <ApiLink pkg="core" type="Dialog" member="leftButtonSelect" label="leftButtonSelect" /> or <ApiLink pkg="core" type="Dialog" member="rightButtonSelect" label="rightButtonSelect" />, and the dialog stays open until you call `close()`:

```html
<igx-dialog #dialog
    title="Delete File"
    message="Are you sure you want to delete this file?"
    leftButtonLabel="Cancel"
    (leftButtonSelect)="dialog.close()"
    rightButtonLabel="Delete"
    rightButtonType="contained"
    (rightButtonSelect)="deleteFile(); dialog.close()">
</igx-dialog>
```

For other buttons, project them into the dialog with an `igx-dialog-actions` element or an element with the `igxDialogActions` directive. The Angular Dialog ignores the projected actions when you set a button label.

</PlatformBlock>

### Opening and Closing

<PlatformBlock for="React,WebComponents,Blazor">

Open and close the {Platform} Dialog with the following methods, which play the open and the close animations:

</PlatformBlock>

<PlatformBlock for="React,WebComponents">

- <ApiLink pkg="core" type="Dialog" member="show" label="show" /> opens the dialog.
- <ApiLink pkg="core" type="Dialog" member="hide" label="hide" /> closes the dialog.
- <ApiLink pkg="core" type="Dialog" member="toggle" label="toggle" /> opens the dialog when it's closed and closes it when it's open.

Each method returns a promise that resolves to `false` when the dialog is already in the requested state. The <ApiLink pkg="core" type="Dialog" member="open" label="open" /> property also opens and closes the dialog, but without the animations.

</PlatformBlock>

<PlatformBlock for="Blazor">

- <ApiLink pkg="core" type="Dialog" member="ShowAsync" label="ShowAsync" /> opens the dialog.
- <ApiLink pkg="core" type="Dialog" member="HideAsync" label="HideAsync" /> closes the dialog.
- <ApiLink pkg="core" type="Dialog" member="ToggleAsync" label="ToggleAsync" /> opens the dialog when it's closed and closes it when it's open.

Each method returns `false` when the dialog is already in the requested state. The <ApiLink pkg="core" type="Dialog" member="Open" label="Open" /> parameter also opens and closes the dialog, but without the animations, and it doesn't change when the user closes the dialog. Use the methods to keep the state in sync.

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

These methods and the `open` property don't emit the closing events. To open or close the dialog without code, add the `command` and `commandfor` attributes to a button, in browsers that support the [Invoker Commands API](https://developer.mozilla.org/en-US/docs/Web/API/Invoker_Commands_API). Set `command` to `--show`, `--hide`, or `--toggle`, and set `commandfor` to the `id` of the dialog:

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-button command="--show" commandfor="delete-dialog">Delete file</igc-button>

<igc-dialog id="delete-dialog" title="Delete File">
  <p>Are you sure you want to delete this file?</p>
  <igc-button slot="footer" variant="flat" command="--hide" commandfor="delete-dialog">Cancel</igc-button>
</igc-dialog>
```

</PlatformBlock>

</PlatformBlock>

<PlatformBlock for="Blazor">

<PlatformBlock for="Angular">

Open and close the Angular Dialog with the following methods, which play the open and the close animations:

- <ApiLink pkg="core" type="Dialog" member="open" label="open" /> opens the dialog. It accepts optional overlay settings, as described in [Position and Animation](#position-and-animation).
- <ApiLink pkg="core" type="Dialog" member="close" label="close" /> closes the dialog.
- <ApiLink pkg="core" type="Dialog" member="toggle" label="toggle" /> opens the dialog when it's closed and closes it when it's open.

To control the dialog from a property of your component, bind <ApiLink pkg="core" type="Dialog" member="isOpen" label="isOpen" /> two-way. The property changes to `false` when the user closes the dialog:

```html
<button igxButton="contained" (click)="showDialog = true">Delete file</button>

<igx-dialog [(isOpen)]="showDialog"
    title="Delete File"
    message="Are you sure you want to delete this file?"
    leftButtonLabel="Cancel"
    (leftButtonSelect)="showDialog = false">
</igx-dialog>
```

The Angular Dialog emits <ApiLink pkg="core" type="Dialog" member="opening" label="opening" /> and <ApiLink pkg="core" type="Dialog" member="closing" label="closing" /> before it opens and closes, and <ApiLink pkg="core" type="Dialog" member="opened" label="opened" /> and <ApiLink pkg="core" type="Dialog" member="closed" label="closed" /> after the animation ends. These events also fire when you open and close the dialog in code. Set `cancel` to `true` in the handler of `opening` or `closing` to keep the dialog in its current state.

</PlatformBlock>

```ts
const dialog = document.querySelector('igc-dialog')!;

dialog.addEventListener('igcClosing', (event) => {
  if (event.target === dialog && hasUnsavedChanges) {
    event.preventDefault();
  }
});
```

</PlatformBlock>

```tsx

  onClosing={(event: CustomEvent<void>) => {
    if (event.target === event.currentTarget && hasUnsavedChanges) {
      event.preventDefault();

  ...
</IgrDialog>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

The <ApiLink pkg="core" type="Dialog" member="Closing" label="Closing" /> callback can't cancel the closing, because it runs after the browser handles the event. To cancel it, set <ApiLink pkg="core" type="Dialog" member="ClosingScript" label="ClosingScript" /> to the name of a JavaScript function that you register with `igRegisterScript`:

```razor
<IgbDialog Title="Edit Profile" ClosingScript="onDialogClosing">
    ...
</IgbDialog>
```

```javascript
// In JavaScript
function onDialogClosing(event) {
    if (event.target === event.currentTarget && window.hasUnsavedChanges) {
        event.preventDefault();
    }
}

igRegisterScript("onDialogClosing", onDialogClosing, false);
```

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

Components in the dialog that open and close, such as the Select, emit their own `igcClosing` and `igcClosed` events, which bubble to the dialog. Check that the target of the event is the dialog before you handle it, as the examples above do.

</PlatformBlock>

<PlatformBlock for="Angular">

The Angular Dialog closes when the user presses Escape. Set <ApiLink pkg="core" type="Dialog" member="closeOnEscape" label="closeOnEscape" /> to `false` to keep it open, for example while it guards unsaved work. Set <ApiLink pkg="core" type="Dialog" member="closeOnOutsideSelect" label="closeOnOutsideSelect" /> to `true` to close the dialog when the user clicks outside it. The dialog reads these properties when it opens, so a change while the dialog is open takes effect the next time it opens:

```html
<igx-dialog title="Edit Profile" [closeOnEscape]="false">
  ...
</igx-dialog>

<igx-dialog title="Shortcuts" [closeOnOutsideSelect]="true">
  ...
</igx-dialog>
```

To keep the dialog open in other cases, cancel the `closing` event. Its `event` argument holds the keyboard or the pointer event that closes the dialog, and it's `undefined` when you call `close()`:

```html
<igx-dialog title="Edit Profile" (closing)="onClosing($event)">
  ...
</igx-dialog>
```

```ts
import { IDialogCancellableEventArgs } from 'igniteui-angular/dialog';

public hasUnsavedChanges = false;

public onClosing(args: IDialogCancellableEventArgs) {
    if (args.event && this.hasUnsavedChanges) {
        args.cancel = true;
    }
}
```

</PlatformBlock>

### Forms

<PlatformBlock for="React,WebComponents,Blazor">

Place a `form` element with `method="dialog"` in the content of the {Platform} Dialog to close the dialog when the user submits the form. The dialog emits the closing events, so you can cancel the closing, and it doesn't send the form to a server. To keep the submit button in the footer, as the design guidance recommends, associate it with the form:

</PlatformBlock>

### Position and Animation

By default, the Angular Dialog opens in the center of the page with a fade animation. Set <ApiLink pkg="core" type="Dialog" member="positionSettings" label="positionSettings" /> to change the position and the animations. The dialog uses a global position strategy, so only `horizontalDirection` and `verticalDirection` change its position, and the settings that you leave out keep their default values:

```ts
import { slideInTop, slideOutTop } from 'igniteui-angular/animations';
import { HorizontalAlignment, PositionSettings, VerticalAlignment } from 'igniteui-angular/core';

public positionSettings: PositionSettings = {
    horizontalDirection: HorizontalAlignment.Center,
    verticalDirection: VerticalAlignment.Top,
    openAnimation: slideInTop,
    closeAnimation: slideOutTop
};
```

```html
<igx-dialog title="Notification" [positionSettings]="positionSettings">
  ...
</igx-dialog>
```

The dialog is modal by default: it shows a backdrop, and the backdrop blocks clicks on the page. Set <ApiLink pkg="core" type="Dialog" member="isModal" label="isModal" /> to `false` to show the dialog without a backdrop and keep the page interactive. To change the overlay settings for a single opening, pass them to `open()`. The settings that you pass override the defaults of the dialog for that opening only and don't change its properties:

```ts
this.dialog.open({ modal: false, closeOnOutsideClick: true });
```

</PlatformBlock>

## Accessibility

The {Platform} Dialog shows its content in a modal window that users reach and leave with the keyboard. This section lists what the dialog renders and handles, as its template and event handlers define it.

### Keyboard Interaction

<PlatformBlock for="React,WebComponents,Blazor">

The {Platform} Dialog opens its native `dialog` element with `showModal()` and closes it with `close()`, so the browser manages the focus:

- When the dialog opens, the focus moves to the first focusable element in the dialog, in DOM order: a control in the content, a button in the `footer` slot, or the default OK button. When the dialog has no focusable elements, the focus moves to the dialog itself.
- While the dialog is open, the rest of the page is inert, so the keyboard and the pointer can't reach it.
- When the dialog closes, the focus returns to the element that had it before the dialog opened.

The following keys work while the dialog is open:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves the focus to the next or the previous focusable element in the dialog. The dialog doesn't handle these keys: the inert page makes the browser move the focus from the last element in the dialog to the browser controls and then back to the first element. |
| <kbd>Escape</kbd> | The browser sends a `cancel` event to the native `dialog`. The {Platform} Dialog prevents the native close, emits the closing event, and closes when you don't cancel that event. With `keepOpenOnEscape`, the dialog stays open, and when the browser closes the native `dialog` anyway, for example on a repeated Escape, the dialog opens it again. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Activates the focused button. The default OK button closes the dialog and emits the closing events. |

The {Platform} Dialog also handles these pointer and form actions:

- A click on the native `dialog` outside its box, which is a click on the backdrop, closes the dialog when `closeOnOutsideClick` is set. The dialog checks the pointer position, so a press inside the dialog followed by a release on the backdrop also closes it.
- A `submit` event from a form with `method="dialog"` in the default slot closes the dialog, unless you prevent the `submit` event or cancel the closing event.

</PlatformBlock>

<PlatformBlock for="Angular">

The Angular Dialog manages the focus as follows:

- When the dialog opens with built-in buttons, each button gets the `igxFocus` directive bound to `isOpen`, so the right button gets the focus, or the left button when it's the only one.
- When the dialog opens without built-in buttons, the focus doesn't move into the dialog. Move it yourself, for example with `[igxFocus]="dialog.isOpen"` on the first control in the content.
- While the dialog is open, the `igxFocusTrap` directive on the `div.igx-dialog` container handles Tab and Shift + Tab.
- When the dialog closes, the focus doesn't return to the element that opened it.

The following keys work while the dialog is open:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> | Moves the focus to the next focusable element in the dialog, and from the last one to the first. |
| <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves the focus to the previous focusable element in the dialog, and from the first one to the last. |
| <kbd>Escape</kbd> | Closes the dialog and emits `closing` and `closed` when `closeOnEscape` is `true`. The overlay service listens for Escape on the whole document, so the key works wherever the focus is, and it closes only the topmost open overlay. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Activates the focused button. A built-in button emits `leftButtonSelect` or `rightButtonSelect` and doesn't close the dialog. |

The focus trap works only when `focusTrap` is `true`, and it handles Tab and Shift + Tab as follows:

- It finds the focusable elements in the dialog with the `a[href], button, input, textarea, select, details, [tabindex]:not([tabindex="-1"])` selector. It skips disabled elements and the content of elements with `aria-hidden="true"`, and it doesn't look into the shadow roots of web components.
- It moves the focus in DOM order, so it ignores positive `tabindex` values, and it wraps from the last element to the first and back.
- When the dialog has no focusable elements, it keeps the focus on the `div.igx-dialog` container.

The Angular Dialog also handles these pointer actions:

- In a modal dialog, a click on the backdrop closes the dialog when `closeOnOutsideSelect` is `true`. A press inside the dialog followed by a release on the backdrop also counts as a click on the backdrop.
- In a dialog with `isModal` set to `false`, a click anywhere outside the dialog closes it when `closeOnOutsideSelect` is `true`.
- The dialog stops the propagation of the clicks inside it, so click handlers on the document don't receive them.

</PlatformBlock>

### Screen Readers / ARIA

<PlatformBlock for="React,WebComponents,Blazor">

The {Platform} Dialog renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| `div[part="backdrop"]` | — | `aria-hidden="true"` while the dialog is closed. The element is empty and decorative. |
| `dialog[part="base"]` | `dialog` | `aria-labelledby` that points to the `title` part, and `aria-label` when you set `aria-label` on the `igc-dialog` element. |
| `header[part="title"]` | — | The `id` that `aria-labelledby` points to. Hidden when the dialog has no title. |
| The default OK button | `button` | The name "OK". |

The {Platform} Dialog exposes the following information to assistive technology:

- While the dialog is open, it's a modal `dialog`, and the content of the page outside it isn't in the accessibility tree. While the dialog is closed, the dialog isn't in the accessibility tree.
- The dialog takes its accessible name from the `title` property or the `title` slot. An `aria-label` on the `igc-dialog` element takes precedence over the title, and a dialog without a title or an `aria-label` has no accessible name.
- The dialog doesn't set `aria-describedby`, so the message and the content aren't its accessible description.
- The dialog doesn't use a live region. Assistive technology finds the open dialog through the focus, which moves into it.

</PlatformBlock>

<PlatformBlock for="Angular">

The Angular Dialog renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| `igx-dialog` | — | `id`, `igx-dialog-0` and up by default, and `tabindex="-1"`. |
| `div.igx-overlay__wrapper--modal` | — | `popover="manual"`, which renders the open dialog in the top layer of the page. |
| `div.igx-dialog` | — | `tabindex="0"`, and `aria-hidden="true"` while the dialog is closed. |
| `div.igx-dialog__window` | `dialog` with two built-in buttons, `alertdialog` with one, `alert` without built-in buttons | `aria-labelledby` that points to the `titleId`. |
| `div.igx-dialog__window-title` | — | The `id` that `aria-labelledby` points to, set to the `titleId`. Rendered when you set `title`. |
| The built-in buttons | `button` | `type="button"` and the name from `leftButtonLabel` or `rightButtonLabel`. |

The Angular Dialog exposes the following information to assistive technology:

- The role of the dialog depends on the built-in buttons, and the `role` property is read-only. A custom dialog without built-in buttons, such as a sign-in form, has the `alert` role.
- The dialog takes its accessible name from the `title` property. A projected `igx-dialog-title` doesn't get the `titleId`, so a dialog with a projected title has no accessible name unless you bind `[id]="dialog.titleId"` on the title.
- The dialog doesn't set `aria-modal`, and the top layer doesn't make the rest of the page inert, so assistive technology can still reach the page behind a modal dialog.
- The dialog doesn't set `aria-describedby`, so the message and the content aren't its accessible description.
- While the dialog is closed, its container has `aria-hidden="true"` and is hidden.

</PlatformBlock>

## Troubleshooting

These are the {Platform} Dialog problems that come up most often, with their causes and fixes.

<PlatformBlock for="React,WebComponents">

### Why is returnValue empty after the user submits the form?

The {Platform} Dialog sets `returnValue` from the submitter of the form, and only a native `button` or `input` element is a submitter. An Ignite UI Button submits the form without a submitter, so `returnValue` keeps its previous value. Use a native submit button, or set `returnValue` in the click handler of the Ignite UI Button before the form is submitted.

</PlatformBlock>

<PlatformBlock for="Blazor">

### Why does Show() throw an error?

The `Show`, `Hide`, and `Toggle` methods are the synchronous versions of `ShowAsync`, `HideAsync`, and `ToggleAsync`. The dialog methods in the browser return a promise, so on Blazor WebAssembly the synchronous calls throw an exception although the dialog opens or closes, and on Blazor Server they fail ([igniteui-blazor#512](https://github.com/IgniteUI/igniteui-blazor/issues/512)). Use the `Async` methods instead.

</PlatformBlock>

<PlatformBlock for="Angular">

### Why does a screen reader read my custom dialog as an alert?

The Angular Dialog sets its role from the built-in buttons, and a dialog without `leftButtonLabel` and `rightButtonLabel` gets the `alert` role. The `role` property is read-only. When the dialog only confirms or cancels an action, use the built-in buttons, which give it the `dialog` or the `alertdialog` role.

### Why doesn't a change to closeOnEscape take effect?

The Angular Dialog passes `closeOnEscape`, `closeOnOutsideSelect`, and `isModal` to the overlay when it opens, so a change while the dialog is open applies the next time it opens ([igniteui-angular#12537](https://github.com/IgniteUI/igniteui-angular/issues/12537)). To change the behavior of an open dialog, cancel the `closing` event instead.

</PlatformBlock>

### Known Limitations

<PlatformBlock for="React,WebComponents,Blazor">

- The `command` and `commandfor` attributes work only in browsers that support the [Invoker Commands API](https://developer.mozilla.org/en-US/docs/Web/API/Invoker_Commands_API).
- The `message` slot limits its content to a width of 40 characters.

</PlatformBlock>

<PlatformBlock for="Blazor">

- The `Open` parameter doesn't change when the user closes the dialog, and the Blazor Dialog has no `OpenChanged` callback.
- The `Closing` callback can't cancel the closing. Use `ClosingScript`, as described in [Closing on Escape and Outside Click](#closing-on-escape-and-outside-click).
- The `ReturnValue` parameter doesn't reach the dialog in the browser, and it doesn't change when a form sets the return value ([igniteui-blazor#300](https://github.com/IgniteUI/igniteui-blazor/issues/300)).

</PlatformBlock>

<PlatformBlock for="Angular">

- A dialog without built-in buttons doesn't move the focus into itself when it opens, and the dialog doesn't return the focus to the element that opened it.
- The modal dialog doesn't make the rest of the page inert for assistive technology.
- The focus trap moves the focus in DOM order and ignores positive `tabindex` values ([igniteui-angular#13299](https://github.com/IgniteUI/igniteui-angular/issues/13299)).
- The dialog stops the propagation of the clicks inside it, so a third-party menu in the dialog that closes on document clicks stays open ([igniteui-angular#13849](https://github.com/IgniteUI/igniteui-angular/issues/13849)).
- The `minSize` of the position settings has no effect, because the dialog uses a global position strategy.

</PlatformBlock>
