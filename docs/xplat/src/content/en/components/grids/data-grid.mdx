# Data Grid

The {ProductName} Data Grid (<PlatformBlock for="React,Blazor"><ApiLink type="Grid" /></PlatformBlock><PlatformBlock for="WebComponents"><ApiLink type="Grid" label="IgcGridComponent" /></PlatformBlock><PlatformBlock for="Angular"><ApiLink type="Grid" label="IgxGridComponent" /></PlatformBlock>) displays and edits flat tabular data: an array of records, one row per record. It is the grid to start with for lists of orders, customers and transactions. You enable features such as sorting, filtering, grouping, editing, paging and Excel export per column or per grid, and the Data Grid virtualizes its rows and columns by default.

For hierarchical data, use the [Tree Grid](./tree-grid/overview.mdx) or the [Hierarchical Grid](./hierarchical-grid/overview.mdx), which offer most of the same features. To summarize data in a cross-tabular layout, use the [Pivot Grid](./pivot-grid/overview.mdx).

<PlatformBlock for="Angular">

The selector of the Angular Data Grid is `igx-grid`, and each `igx-column` in it defines one column.

</PlatformBlock>

## Anatomy

The {Platform} Data Grid consists of a header row and a virtualized body of rows and cells, with an optional toolbar above them and optional summary cells and a paginator below them.

<span class="ig-typography__body-2" style="display: block; margin-bottom: 24px;"><strong>1. Grid Toolbar (optional):</strong> bar above the grid for a title and grid-level actions such as column hiding, column pinning, exporting and advanced filtering<br />
<strong>2. Grid Body:</strong> the scrollable, virtualized area that renders the data rows<br />
<strong>3. Header Row:</strong> the row that holds one header cell for each visible column and stays in view while the body scrolls<br />
<strong>4. Header Cell:</strong> shows the title of a column and hosts its sorting, filtering, moving and resizing interactions<br />
<strong>5. Grid Column:</strong> a vertical set of cells bound to one data field; it defines the data type, the width, the templates and the features enabled for that field<br />
<strong>6. Grid Row:</strong> one data record, displayed as a horizontal set of cells<br />
<strong>7. Grid Cell:</strong> the intersection of a row and a column, which shows a single value and, when the column is editable, edits it<br />
<strong>8. Summary Cell (optional):</strong> a cell below a column that shows aggregated values such as count, sum, min, max or average<br />
<strong>9. Paginator (optional):</strong> the bar below the grid that splits the data into pages and provides page navigation and page size selection</span>

The `igc-grid` element has no shadow root. It renders the header row, the body and the summary row as `igx-` elements, between the `igc-grid-toolbar` and `igc-paginator` elements that you place in it:

```text
├─ igc-grid-toolbar.igx-grid-toolbar                   // optional
├─ igx-grid-group-by-area                              // when a column is groupable or grouped
├─ igx-grid-header-row.igx-grid-thead[role="rowgroup"]
│  └─ div.igx-grid-thead__wrapper
│     └─ div.igx-grid__tr[role="row"]
│        └─ igx-display-container                      // renders the headers of the columns in view
│           └─ igx-grid-header-group                   // one for each column in view
│              └─ igx-grid-header[role="columnheader"]
├─ div.igx-grid__tbody
│  └─ div.igx-grid__tbody-content[role="rowgroup"]
│     └─ igx-display-container                         // renders the rows in view
│        └─ div[data-index]                            // one for each row in view
│           └─ igx-grid-row.igx-grid__tr[role="row"]   // igx-grid-groupby-row for a group row
```

<PlatformBlock for="WebComponents">

Install the `{PackageGrids}` package:

```cmd
npm install {PackageGrids}
```

Import the grid; the import registers the `igc-grid` element and the elements that you place in it, such as `igc-column`, `igc-grid-toolbar` and `igc-paginator`:

```typescript
import 'igniteui-webcomponents-grids/grids/combined.js';
```

Reference the grid styles as well. Choose the light or the dark variant of one of the [themes](../themes/overview.mdx) and import it:

```typescript
import 'igniteui-webcomponents-grids/grids/themes/light/bootstrap.css';
```

Or to link it:

```html
<link rel='stylesheet' href='node_modules/igniteui-webcomponents-grids/grids/themes/light/bootstrap.css'>
```

Cell and header templates use Lit's `html` tag; `{PackageGrids}` installs `lit`, which includes `lit-html`, and you add `lit-html` to your own dependencies when you import from it directly.

</PlatformBlock>

## Usage

Use the {Platform} Data Grid to display, edit and analyze records that share the same fields.

### Basic Configuration

Add the grid to your markup and bind it to local data:

<PlatformBlock for="Blazor">

```razor
<IgbGrid Id="grid1" Data="data" AutoGenerate="true"></IgbGrid>
```

</PlatformBlock>

<PlatformBlock for="Angular">

```html
<igx-grid #grid1 id="grid1" [data]="localData" [autoGenerate]="true"></igx-grid>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-grid id="grid1" auto-generate="true"></igc-grid>
```

```typescript
import { IgcGridComponent } from 'igniteui-webcomponents-grids/grids';

constructor() {
    let grid1 = document.getElementById("grid1") as IgcGridComponent;
    grid1.data = data;
}
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrGrid id="grid1" autoGenerate={true} data={localData}></IgrGrid>
```

</PlatformBlock>

The <ApiLink type="Grid" member="id" /> property is the unique identifier of the grid, generated automatically when you don't set it, and <ApiLink type="Grid" member="data" /> binds the grid, here to local data.

With <ApiLink type="Grid" member="autoGenerate" />, the grid creates a <ApiLink type="Column" /> for each field of the first record and infers its data type<PlatformBlock for="Angular,React,WebComponents">: a number, a Boolean, a `Date` object and a string that ends with an image file extension, such as `.png`, give number, boolean, date and image columns, and any other value gives a string column</PlatformBlock>. To set the columns and their mapping to the data fields yourself, [define the columns](#column-configuration).

### Column Configuration

Each <ApiLink type="Column" /> in the columns collection of the grid defines one column and the features enabled for it, such as **sorting** and **filtering**, and can have cell, header and footer templates.

#### Header Template

A header template replaces the content of the column header. The snippet below formats the header text in upper case:

<PlatformBlock for="Angular">

```html
<igx-column field="Name">
    <ng-template igxHeader let-column>
        {{ column.field | uppercase }}
    </ng-template>
</igx-column>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-column id="name" field="Name"></igc-column>
```

```typescript
import { html } from 'lit-html';
import { IgcColumnComponent, IgcColumnTemplateContext } from 'igniteui-webcomponents-grids/grids';

constructor() {
    var name = this.name = document.getElementById('name') as IgcColumnComponent;
    name.headerTemplate = this.nameHeaderTemplate;
}

public nameHeaderTemplate = (ctx: IgcColumnTemplateContext) => {
    return html`
        ${this.formatUppercase(ctx.column.field)}
    `;
}

public formatUppercase(value: string) {
    return value.toUpperCase();
}
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```javascript
    return value.toUpperCase();
}
```

</PlatformBlock>

#### Cell Template

A cell template applies to all cells of the column. Its context is the cell value, provided implicitly (<PlatformBlock for="Angular">`$implicit`</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">`implicit`</PlatformBlock>), and the cell object (`cell`). The snippet below formats the cell text in title case:

<PlatformBlock for="Angular">

```html
<igx-column field="Name">
    <ng-template igxCell let-value>
        {{ value | titlecase }}
    </ng-template>
</igx-column>
```

The `uppercase` and `titlecase` pipes come from `@angular/common`. Add `UpperCasePipe` and `TitleCasePipe` to the `imports` of your component.

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-column id="name" field="Name"></igc-column>
```

```typescript
import { html } from 'lit-html';
import { IgcCellTemplateContext, IgcColumnComponent } from 'igniteui-webcomponents-grids/grids';

constructor() {

}

        ${this.formatTitleCase(ctx.implicit)}
    `;
}

public formatTitleCase(value: string) {
    return value.toLowerCase().replace(/\b\w/g, c => c.toUpperCase());
}
```

The implicit value is enough to format or style what the cell shows. To read other fields of the record or to call the API of the grid, take the <ApiLink type="CellTemplateContext" member="cell" /> instance instead:

<PlatformBlock for="Angular">

```html
<igx-grid #grid [data]="data">
    <igx-column dataType="string" field="Name">
        <ng-template igxCell let-cell="cell">
            <!-- Implement row deleting inside the cell template itself -->
            <span tabindex="0" (keydown.delete)="grid.deleteRow(cell.row.key)">{{ cell.value | titlecase }}</span>
        </ng-template>
    </igx-column>
    <igx-column dataType="boolean" field="Subscription">
        <ng-template igxCell let-cell="cell">
            <!-- Bind the cell value through the ngModel directive and update the data source when the value is changed in the template -->
            <input type="checkbox" [ngModel]="cell.value" (ngModelChange)="cell.update($event)" />
        </ng-template>
    </igx-column>
</igx-grid>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-grid id="grid" auto-generate="false">
    <igc-column id="name" field="Name" data-type="string"></igc-column>
```

```typescript
constructor() {
    var grid = this.grid = document.getElementById('grid') as IgcGridComponent;
    var name = this.name = document.getElementById('name') as IgcColumnComponent;
    var subscription = this.subscription = document.getElementById('subscription') as IgcColumnComponent;
    grid.data = this.data;
    name.bodyTemplate = this.nameCellTemplate;
    subscription.bodyTemplate = this.subscriptionCellTemplate;
}

public nameCellTemplate = (ctx: IgcCellTemplateContext) => {
    return html`
        <span tabindex="0" @keydown="${(e: KeyboardEvent) => this.deleteRow(e, ctx.cell.id.rowID)}">${this.formatTitleCase(ctx.cell.value)}</span>
    `;
}

public subscriptionCellTemplate = (ctx: IgcCellTemplateContext) => {
    if (ctx.cell.value) {
            return html` <input type="checkbox" checked /> `;
    } else {
            return html` <input type="checkbox"/> `;
    }
}

public deleteRow(e: KeyboardEvent, rowID: any) {
    if (e.code === "Delete") {
        this.grid.deleteRow(rowID);
    }
}

public formatTitleCase(value: string) {
    return value.toLowerCase().replace(/\b\w/g, c => c.toUpperCase());
}
```

```javascript
            return html` <input type="checkbox" checked /> `;

});

    if (e.code === "Delete") {
        cell.grid.deleteRow(cell.id.rowID);
    }
}

    return value.toLowerCase().replace(/\b\w/g, c => c.toUpperCase());
```

<PlatformBlock for="Angular">

When a cell template changes the value with `ngModel`, update it through the grid's [editing API](./_shared/cell-editing.mdx#editing-through-api), as the `ngModelChange` handler above does. </PlatformBlock>

#### Custom Display Format

<PlatformBlock for="Angular">

The grid formats the values of date, number, currency and percent columns with the Angular [`DatePipe`](https://angular.dev/api/common/DatePipe), [`DecimalPipe`](https://angular.dev/api/common/DecimalPipe), [`CurrencyPipe`](https://angular.dev/api/common/CurrencyPipe) and [`PercentPipe`](https://angular.dev/api/common/PercentPipe). Formatting changes only what the column displays; data operations use the values in your data source. The format follows the <ApiLink type="Grid" member="locale" /> of the grid, which falls back to the application locale (`'en-US'` by default); see [Setting up the locale of your app](https://angular.dev/guide/i18n/locale-id).

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

The {Platform} Data Grid formats the values of date, number, currency and percent columns for display, following the <ApiLink type="Grid" member="locale" /> of the grid. Formatting changes only what the column displays; sorting, filtering and the other data operations use the values in your data. The [Column Types](./_shared/column-types.mdx#default-template) topic describes the format options of each column type.

</PlatformBlock>

The optional formatting parameters are:

- <ApiLink type="ColumnPipeArgs" member="format" /> - determines what date/time parts are displayed, defaults to `'mediumDate'`, equivalent to `'MMM d, y'`
- <ApiLink type="ColumnPipeArgs" member="timezone" /> - the timezone offset for dates. By default uses the end-user's local system timezone
- <ApiLink type="ColumnPipeArgs" member="digitsInfo" /> - decimal representation objects. Default to `'1.0-3'`

Set them through the <ApiLink type="Column" member="pipeArgs" /> property of the column. A column uses only the parameters that apply to its data type:

### Performance (Experimental)

The <ApiLink type="Grid" /> works with the event coalescing of Angular, which improves the responsiveness of interactions by roughly **20%**. Enable it for the application by setting the `eventCoalescing` and `runCoalescing` options of `provideZoneChangeDetection` to `true`:

```typescript
// main.ts

bootstrapApplication(AppComponent, {
    providers: [provideZoneChangeDetection({ eventCoalescing: true, runCoalescing: true })]
}).catch(err => console.error(err));
```

Event coalescing is an option of the zone.js-based change detection, while Angular 21 and later use zoneless change detection by default. In an NgModule-based application, pass the same provider in the `applicationProviders` option of `bootstrapModule()`.

<DocsAside type="info">
Event coalescing is experimental for the `IgxGridComponent` and can cause unexpected behavior in the grid; if it does, report it on [GitHub]({GithubLink}/discussions). It applies to the whole application, so it can also affect parts that don't use the grid.
</DocsAside>

### Do/Don't

Align the content of the header cells and the body cells by data type: text to the left and numbers to the right, which is the default for number, currency and percent columns. Keep cell content on one line, so that all rows have the same height, and show only the columns that the task needs; users can show the rest from the [Column Hiding](./_shared/column-hiding.mdx) menu.

## Styling

The {Platform} Data Grid takes its colors from the theme of the application. Change them with the following CSS variables, which the grid theme reads on the grid element. Each one falls back to a global variable with the `--ig-grid-` prefix, such as `--ig-grid-header-background`, which you can set on any ancestor of the Data Grid:

| Variable | What it changes |
| --- | --- |
| `--header-background` | The background of the header row. |
| `--header-text-color` | The text color of the column headers. |
| `--header-border-color` | The color of the header borders. |
| `--content-background` | The background of the body. |
| `--content-text-color` | The text color of the cells. |
| `--row-odd-background` | The background of the odd rows. |
| `--row-even-background` | The background of the even rows. |
| `--row-hover-background` | The background of the row under the pointer. |
| `--row-selected-background` | The background of a selected row. |
| `--cell-selected-background` | The background of a selected cell. |
| `--row-border-color` | The color of the border below each row. |
| `--grid-border-color` | The color of the border around the Data Grid. |

## Accessibility

The {Platform} Data Grid can be operated with the keyboard and exposes its structure and state to assistive technology through ARIA roles and attributes.

### Keyboard Interaction

Keyboard navigation covers every element of the grid: cells, rows, column headers, the toolbar and the footer. The header row and the body are separate tab stops, and inside each of them the arrow keys move the active cell. The following keys work while the header row or the body has the focus:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Outside edit mode, the Data Grid doesn't handle these keys, so they move the focus to the next or the previous tab stop. While a cell or a row is in edit mode, they move to the next or the previous editable cell. |
| <kbd>Arrow Up</kbd> / <kbd>Arrow Down</kbd> | Move the active cell one row up or down. |
| <kbd>Arrow Left</kbd> / <kbd>Arrow Right</kbd> | Move the active cell, or the active column header, one column to the left or to the right. |
| <kbd>Home</kbd> / <kbd>End</kbd> | Move to the first or the last cell of the row. |
| <kbd>Ctrl</kbd> + <kbd>Home</kbd> / <kbd>Ctrl</kbd> + <kbd>End</kbd> | Move to the first cell of the first data row, or to the last cell of the last data row. |
| <kbd>Ctrl</kbd> + <kbd>Arrow Up</kbd> / <kbd>Ctrl</kbd> + <kbd>Arrow Down</kbd> | In the body, move to the first or the last data row in the column. On the header of a sortable column, sort the column in ascending or descending order, or clear the sorting when the column is already sorted in that order. |
| <kbd>Page Up</kbd> / <kbd>Page Down</kbd> | Scroll the body one page up or down. |
| <kbd>Enter</kbd> / <kbd>F2</kbd> | Enter edit mode in an editable cell. |
| <kbd>Esc</kbd> | Exit edit mode and discard the change. |
| <kbd>Space</kbd> | Select or deselect the row when row selection is on. |
| <kbd>Alt</kbd> + <kbd>Arrow Left</kbd> / <kbd>Alt</kbd> + <kbd>Arrow Up</kbd> | Collapse the group row. |
| <kbd>Alt</kbd> + <kbd>Arrow Right</kbd> / <kbd>Alt</kbd> + <kbd>Arrow Down</kbd> | Expand the group row. |

### Screen Readers / ARIA

The {Platform} Data Grid renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| <PlatformBlock for="Angular">`igx-grid`</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">`igc-grid`</PlatformBlock> | `grid` | `aria-rowcount` and `aria-colcount` |
| `igx-grid-header-row` | `rowgroup` | `aria-activedescendant` that points to the active column header |
| `div.igx-grid__tr` in the header row | `row` | `aria-rowindex="1"` |
| `igx-grid-header` | `columnheader` | `aria-sort` (`ascending` or `descending`) when the column is sorted, `aria-selected`, `aria-colindex` and `aria-rowindex` |
| `div.igx-grid__tbody-content` | `rowgroup` | `aria-activedescendant` that points to the active cell |
| `igx-grid-row` | `row` | `aria-selected` and `aria-disabled` |
| `igx-grid-cell` | `gridcell` | `aria-rowindex`, `aria-colindex`, `aria-selected`, `aria-readonly` when the cell can't be edited, and `aria-invalid` and `aria-describedby` when the value fails validation |

- The focus stays on the header row or on the body while the active cell moves, and `aria-activedescendant` points to the active column header or cell.
- Only the rows and the columns in view are in the DOM. `aria-rowindex` and `aria-colindex` give each rendered cell its position in the data.

### Accessibility Compliance

The [Accessibility Compliance](../interactivity/accessibility-compliance.mdx) topic lists the standards that {ProductName} targets, WCAG 2.1 Level AA among them, and records what the Data Grid documentation covers. It is a support summary, not a formal conformance statement.

| Criterion | How the component complies |
| --- | --- |
| [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships) | The `grid`, `rowgroup`, `row`, `columnheader` and `gridcell` roles expose the structure, and `aria-rowindex` and `aria-colindex` give the position of each cell in the data. |
| [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | The arrow keys, Home, End, Page Up and Page Down move through the cells, Enter and F2 start editing, Space selects rows, and Ctrl + Arrow Up and Ctrl + Arrow Down sort from a column header. |
| [2.1.2 No Keyboard Trap](https://www.w3.org/WAI/WCAG21/Understanding/no-keyboard-trap) | Outside edit mode, the Data Grid doesn't handle the Tab key, so Tab and Shift + Tab move the focus out of the header row and the body. |
| [2.4.3 Focus Order](https://www.w3.org/WAI/WCAG21/Understanding/focus-order) | The header row and the body are separate tab stops, in their visual order. |
| [2.4.7 Focus Visible](https://www.w3.org/WAI/WCAG21/Understanding/focus-visible) | The active cell and the active column header show a border in the `--cell-active-border-color` color. |
| [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | Cells expose the `gridcell` role and their selected and read-only states through `aria-selected` and `aria-readonly`. Column headers expose the sort direction through `aria-sort`, and group rows expose their expanded state through `aria-expanded`. |

Your responsibilities:

- Give the Data Grid an accessible name, for example with `aria-label` or `aria-labelledby` on the grid element. The Data Grid doesn't set one.
- Give icons and icon-only buttons that you place in cell and header templates an accessible name.
- Test the focusable elements that you place in cell templates with the keyboard. The Data Grid handles the arrow keys, Enter, F2, Esc and Space on the body, so these elements may need to handle the keys that they use.
- When you override the theme colors, keep a contrast ratio of at least 4.5:1 for the text of the headers and the cells, as [1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum) requires, and keep the border of the active cell visible. See [Styling](#styling).

## Troubleshooting

These questions cover common problems when you set up the {Platform} Data Grid.

### Why can't I click the elements in my column header template?

When column moving is on or the column is groupable, the header of the {Platform} Data Grid is draggable, so pressing the pointer on the header starts a drag instead of reaching the elements in your header template. Set `draggable="false"` on the element that the user clicks:

<PlatformBlock for="Angular">

```html
<igx-column field="ProductName" header="Product name" [groupable]="true">
    <ng-template igxHeader let-column>
        <span>{{ column.header }}</span>
        <button type="button" draggable="false" (click)="column.hasSummary = !column.hasSummary">Summary</button>
    </ng-template>
</igx-column>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-column id="product" field="ProductName" header="Product name" groupable="true"></igc-column>
```

```ts
const productHeaderTemplate = (ctx: IgcColumnTemplateContext) => html`
    <span>${ctx.column.header}</span>
    <button type="button" draggable="false" @click=${() => (ctx.column.hasSummary = !ctx.column.hasSummary)}>Summary</button>
`;

const product = document.getElementById('product') as IgcColumnComponent;
product.headerTemplate = productHeaderTemplate;
```

</PlatformBlock>

<PlatformBlock for="React">


### How do I import the Data Grid in an NgModule-based application?

The `IGX_GRID_DIRECTIVES` token in [Getting Started](#getting-started) is for standalone components, which the Data Grid supports as of version `16.0.0`. // app.module.ts

```typescript
import { NgModule } from '@angular/core';
```

## Known Limitations

The {Platform} Data Grid has the following limitations.

| Limitation | Description |
| --- | --- |
| Column widths in `%` and `px` | Mixing percentage and pixel column widths is not supported. |
| Filtering a number column | A value that is not a number in the filter input returns `NaN`. |
| Data Grid width and column widths | Unless the `width` of the Data Grid is `null`, the column widths do not determine the width of the Data Grid; the width of the Data Grid or of its parent container does. |
| Minimum column width | Resizing or auto-sizing doesn't make a column narrower than 56 px (small), 64 px (medium) or 80 px (large), depending on `--ig-size`, unless the column has a minimum width of its own. A narrower width that you set yourself applies. |
<PlatformBlock for="Angular">| `OnPush` change detection | The Data Grid uses `ChangeDetectionStrategy.OnPush`. When a customization changes what the Data Grid shows, make sure that the Data Grid is notified about the change. |
</PlatformBlock>| Row height and virtualization | A custom cell template that is outside the viewport does not affect the row height until it scrolls into view. |

<PlatformBlock for="Angular">

<DocsAside type="info">
The grid uses the `igxForOf` directive internally, so the [`igxForOf` known limitations](../for-of.mdx#known-limitations) apply to it too.
</DocsAside>

## FAQ

These questions cover the license of the {Platform} Data Grid,<PlatformBlock for="Angular"> page layout,</PlatformBlock> custom cell editors and column widths.

<Faq>
  <FaqItem question="Is the {Platform} Data Grid free?" indicatorPosition="end">
    <PlatformBlock for="Angular">No. The Angular Data Grid is a Premium component: `igniteui-angular` is dual-licensed, and the grids are under the Infragistics commercial license, which customer-facing deployments require. The free, open-source grid is [Grid Lite](../grid-lite/overview.mdx), released under the MIT license. [Open-Source vs Premium](../general/open-source-vs-premium.mdx) lists the open-source and the Premium components.</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">No. The {Platform} Data Grid is a Premium component under the Infragistics Ultimate license, and customer-facing deployments require a commercial license. The free, open-source grid is [Grid Lite](../grid-lite/overview.mdx), released under the MIT license. [Open-Source vs Premium](../general-open-source-vs-premium.mdx) lists the open-source and the Premium components.</PlatformBlock>
  </FaqItem><PlatformBlock for="Angular"><FaqItem question="Is the Angular Data Grid a page layout grid?" indicatorPosition="end">
    No. The Angular Data Grid is a data component that displays records in rows and columns; it doesn't arrange the content of a page. For a responsive, Bootstrap-like page layout, {ProductName} has the flex-based [Layout Manager](../layout.mdx) directives. The size of the Angular Data Grid itself follows its container and its `width` and `height`; see [Grid Sizing](./_shared/sizing.mdx).
  </FaqItem></PlatformBlock>
  <FaqItem question="Why doesn't my custom cell editor save its value?" indicatorPosition="end">
    The {Platform} Data Grid saves the `editValue` of the cell when editing ends, not the value of the input in your editing template. <PlatformBlock for="Angular">Bind the editor to it, for example with `[(ngModel)]="cell.editValue"`, as the [cell editing template](#cell-editing-template) shows.</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">Set `editValue` from the input event of the editor, as the [cell editing template](#cell-editing-template) shows.</PlatformBlock> With a custom editor, the {Platform} Data Grid doesn't convert the value to a number, so a number column needs a number in `editValue`. Pressing Escape ends editing without saving `editValue`.
  </FaqItem>
  <FaqItem question="Why is a column of the {Platform} Data Grid wider or narrower than expected?" indicatorPosition="end">
    When a column has a minimum or a maximum width, the {Platform} Data Grid keeps the width of the column within that range. A column without a width shares the free width of the grid, down to 136 px, and the grid scrolls horizontally when the columns don't fit. A width in percent is a share of the width of the grid, so when the width of the {Platform} Data Grid is `null`, a percent column gets the minimum width instead; percent and pixel widths can't be mixed in one grid. See [Grid Sizing](./_shared/sizing.mdx).
  </FaqItem>
</Faq>
