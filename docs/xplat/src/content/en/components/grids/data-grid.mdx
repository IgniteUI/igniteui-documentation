# Data Grid Component

The {ProductName} Data Grid is a virtualized table component that displays local or remote data in rows and columns, with sorting, filtering, editing, selection, and paging. It's also known as a data table.

## Anatomy

The {Platform} Data Grid consists of an optional toolbar, an optional group-by area, a header row with a header for each column, a body with the data rows and their cells, an optional summary row, and an optional paginator.

## Getting Started

To use the {Platform} Data Grid, follow the <PlatformBlock for="Angular">[{ProductName} Getting Started](../general/getting-started.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[{ProductName} Getting Started](../general-getting-started.mdx)</PlatformBlock> topic for the basic project setup, then add the Data Grid for your target platform.

<PlatformBlock for="Angular">

If your project doesn't use {ProductName} yet, run `ng add igniteui-angular`. Then import `IGX_GRID_DIRECTIVES`, which holds the `IgxGridComponent` and its supporting components and directives, from `igniteui-angular/grids/grid`:

```ts
import { Component } from '@angular/core';
import { IGX_GRID_DIRECTIVES } from 'igniteui-angular/grids/grid';

@Component({
    selector: 'app-products-grid',
    templateUrl: './products-grid.component.html',
    imports: [IGX_GRID_DIRECTIVES]
})
export class ProductsGridComponent {
    public products: Product[] = PRODUCTS;
}
```

The {ProductName} theme styles the Data Grid, so the grid follows the theme that you include with the `theme()` mixin.

## Usage

Use the {Platform} Data Grid to show flat records in rows and columns, and let users sort, filter, select, and edit them.

### Columns

### Header Template

A header template replaces the content of a column header. Its context holds the column, so the following template shows the field name in uppercase:

<PlatformBlock for="Angular">

```html
<igx-column field="Name">
    <ng-template igxHeader let-column>
        {{ column.field | uppercase }}
    </ng-template>
</igx-column>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

Column templates are functions that return a lit `html` template, so import `html` from the `lit-html` package:

```html
<igc-column id="name" field="Name"></igc-column>
```

```ts
import { html } from 'lit-html';

const name = document.getElementById('name') as IgcColumnComponent;
name.headerTemplate = (ctx: IgcColumnTemplateContext) => html`${ctx.column.field.toUpperCase()}`;
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx

<IgrColumn field="Name" headerTemplate={nameHeaderTemplate}></IgrColumn>
```

</PlatformBlock>

### Cell Template

A cell template replaces the content of every cell in a column. The template context holds the cell value and the cell itself, so the following template shows the value in title case:

<PlatformBlock for="Angular">

```html
<igx-column field="Name">
    <ng-template igxCell let-value>
        {{ value | titlecase }}
    </ng-template>
</igx-column>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-column id="name" field="Name"></igc-column>
```

```ts
const name = document.getElementById('name') as IgcColumnComponent;
name.bodyTemplate = (ctx: IgcCellTemplateContext) => html`${formatTitleCase(ctx.implicit)}`;

function formatTitleCase(value: string) {
    return value.toLowerCase().replace(/\b\w/g, c => c.toUpperCase());
}
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx

<IgrColumn field="Name" bodyTemplate={nameCellTemplate}></IgrColumn>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

Use the cell from the context when the template needs more than the value. The following templates delete the row when the user presses <kbd>Delete</kbd> on the name, and update the `Subscription` value from a checkbox:

<PlatformBlock for="Angular">

```html
<igx-grid [data]="users" [autoGenerate]="false">
    <igx-column field="Name" dataType="string">
        <ng-template igxCell let-cell="cell">
            <span tabindex="0" (keydown.delete)="cell.row.delete()">{{ cell.value | titlecase }}</span>
        </ng-template>
    </igx-column>
    <igx-column field="Subscription" dataType="boolean">
        <ng-template igxCell let-cell="cell">
            <input type="checkbox" [checked]="cell.value" (change)="cell.update($any($event.target).checked)" />
        </ng-template>
    </igx-column>
</igx-grid>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-grid id="grid" auto-generate="false">
    <igc-column id="name" field="Name" data-type="string"></igc-column>
    <igc-column id="subscription" field="Subscription" data-type="boolean"></igc-column>
</igc-grid>
```

```ts

name.bodyTemplate = (ctx: IgcCellTemplateContext) => html`

    </span>
`;

    <input type="checkbox" .checked=${ctx.cell.value}
        @change=${(e: Event) => ctx.cell.update((e.target as HTMLInputElement).checked)} />
`;
```

</PlatformBlock>


The row's `delete` method works without a primary key. The Data Grid's <ApiLink type="Grid" member="deleteRow" label="deleteRow" /> method also deletes a row, but it takes the primary key of the row and needs the <ApiLink type="Grid" member="primaryKey" label="primaryKey" /> property.

A cell template that changes the value must call the cell's `update` method, so the change goes through the grid editing pipeline: <PlatformBlock for="Angular">[transactions](../grid/batch-editing.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[transactions](./_shared/batch-editing.mdx)</PlatformBlock>, <PlatformBlock for="Angular">[summaries](../grid/summaries.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[summaries](./_shared/summaries.mdx)</PlatformBlock>, and <PlatformBlock for="Angular">[selection](../grid/selection.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[selection](./_shared/selection.mdx)</PlatformBlock> stay in sync. The `update` call runs on every change of the input, not only when the user finishes editing, so prefer a [cell editing template](#cell-editing-template) for edit UI.

<PlatformBlock for="Angular">

A two-way `[(ngModel)]` binding to `cell.value` doesn't update the grid data. Call `cell.update` from the change handler instead, as in the snippet above.

To pass custom data to a cell template, set the column's `additionalTemplateContext` input and read it from the template context:

```html
<igx-column field="Name" [additionalTemplateContext]="contextObject">
    <ng-template igxCell let-cell="cell" let-props="additionalTemplateContext">
        {{ props.firstProperty }}
    </ng-template>
</igx-column>
```

```ts
public contextObject = { firstProperty: 'testValue', secondProperty: 'testValue1' };
```

</PlatformBlock>

Without a cell template, the Data Grid renders number, string, date, and boolean columns with default templates. For example, a boolean column shows a check or a close icon instead of `true` or `false`. See <PlatformBlock for="Angular">[Column Types](../grid/column-types.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[Column Types](./_shared/column-types.mdx)</PlatformBlock>.

### Cell Editing Template

A cell editing template replaces the content of a cell in edit mode. Set the column's <ApiLink type="Column" member="editable" label="editable" /> property to `true`, and write the new value to the cell's <ApiLink type="CellType" member="editValue" label="editValue" />. When the cell leaves edit mode, the Data Grid commits the edit value and emits its <PlatformBlock for="Angular">[editing events](../grid/editing.mdx#event-arguments-and-sequence)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[editing events](./_shared/editing.mdx#event-arguments-and-sequence)</PlatformBlock>:

<PlatformBlock for="Angular">

```html
<igx-column field="Price" dataType="number" [editable]="true">
    <ng-template igxCellEditor let-cell="cell">
        <label for="price">Enter the new price tag</label>
        <input id="price" name="price" type="number" [(ngModel)]="cell.editValue" />
    </ng-template>
</igx-column>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-column id="price" field="Price" data-type="number" editable="true"></igc-column>
```

```ts
const price = document.getElementById('price') as IgcColumnComponent;
price.inlineEditorTemplate = (ctx: IgcCellTemplateContext) => html`
    <label for="price">Enter the new price tag</label>
    <input id="price" name="price" type="number" .value=${ctx.cell.editValue}
        @input=${(e: InputEvent) => ctx.cell.editValue = (e.target as HTMLInputElement).value} />
`;
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx

        </>
    );
}

<IgrColumn field="Price" dataType="number" editable={true} inlineEditorTemplate={priceEditTemplate}></IgrColumn>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

### Column Template API

Each column template is also a property of the <ApiLink type="Column" />, so you can switch templates in code at any time. The following code declares two templates for a `User` column and applies one of them based on a condition, such as a saved user setting or the viewport size:

<PlatformBlock for="Angular">

```html
<igx-grid #grid [data]="users">
    <igx-column field="User"></igx-column>
</igx-grid>

<ng-template #normalView let-value>
    <div class="user-details">{{ value }}</div>
```

### Display Format

The Data Grid formats the values of date, number, currency, and percent columns for display only. Sorting, filtering, and the other data operations use the values in your data. The format follows the grid <ApiLink type="Grid" member="locale" label="locale" />, which defaults to the browser language.

<PlatformBlock for="Angular">

By default, the Angular Data Grid formats values with the Angular formatting functions, such as `formatDate` and `formatNumber`, so register the locale data of the locales that you use (see [Angular locale ID](https://angular.dev/guide/i18n/locale-id)). To format values with the browser's `Intl` API instead, add `provideIgniteIntl()` from `igniteui-angular/core` to the application providers.

</PlatformBlock>

To change the format of a column, set its <ApiLink type="Column" member="pipeArgs" label="pipeArgs" /> property to a <PlatformBlock for="Angular"><ApiLink type="IColumnPipeArgs" /></PlatformBlock><PlatformBlock for="React,WebComponents,Blazor"><ApiLink type="ColumnPipeArgs" /></PlatformBlock> object. A column applies only the options that match its data type:

- `format`: the date and time parts to show. The default is `'mediumDate'` for date columns, `'mediumTime'` for time columns, and `'medium'` for date-time columns.
- `timezone`: the time zone offset of dates, such as `'+0430'`. The default is the local time zone of the user.
- `digitsInfo`: the number of digits, as `{minIntegerDigits}.{minFractionDigits}-{maxFractionDigits}`. The default is `'1.0-3'`.
- `currencyCode`: the ISO 4217 code of the currency in currency columns.
- `display`: how currency columns show the currency, such as `'symbol'` (the default) or `'code'`.

<PlatformBlock for="Angular">

```ts

    format: 'longDate',
    timezone: 'UTC',
    digitsInfo: '1.1-2'
};
```

### Remote Data

To show data from a remote service, request the data and assign the result to the <ApiLink type="Grid" member="data" label="data" /> property:

<PlatformBlock for="Angular">

Request the data in a service:

```ts
// northwind.service.ts
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable, catchError, map, of } from 'rxjs';

export interface Product {
    ProductID: number;
    ProductName: string;
    UnitPrice: number;
    UnitsInStock: number;
}

@Injectable({ providedIn: 'root' })
export class NorthwindService {
    private http = inject(HttpClient);
    private url = 'https://services.odata.org/V4/Northwind/Northwind.svc/Products';

    public getProducts(): Observable<Product[]> {
        return this.http.get<{ value: Product[] }>(this.url).pipe(
            map(response => response.value),
            catchError(() => of([]))
        );
    }
}
```

Provide the `HttpClient` in the application configuration:

```ts
// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideHttpClient } from '@angular/common/http';

export const appConfig: ApplicationConfig = {
    providers: [provideHttpClient()]
};
```

Then bind the Data Grid to the result. `toSignal` starts with an empty array, so the grid renders before the response arrives:

```ts
// products-grid.component.ts

    selector: 'app-products-grid',
    template: '<igx-grid [data]="products()" [autoGenerate]="true"></igx-grid>',
    imports: [IGX_GRID_DIRECTIVES]
})
export class ProductsGridComponent {
    public products = toSignal(inject(NorthwindService).getProducts(), { initialValue: [] });
}
```

</PlatformBlock>


</PlatformBlock>

## Accessibility

The {Platform} Data Grid follows the WAI-ARIA grid pattern: it exposes the table structure to assistive technology and supports full keyboard navigation.

### Keyboard Interaction

The header row, the body, and the summary row of the Data Grid are tab stops. Outside edit mode, the Data Grid doesn't handle <kbd>Tab</kbd>, so the browser moves the focus between these parts and out of the grid. Inside a part, the arrow keys move the active cell. The following keys work in the body:

| Key | Action |
| --- | --- |
| <kbd>Arrow</kbd> keys | Move the active cell one cell in the direction of the arrow. |
| <kbd>Ctrl</kbd> + <kbd>Arrow Left</kbd> / <kbd>Arrow Right</kbd> | Move to the first / last cell of the row. |
| <kbd>Ctrl</kbd> + <kbd>Arrow Up</kbd> / <kbd>Arrow Down</kbd> | Move to the first / last row of the column. |
| <kbd>Home</kbd> / <kbd>End</kbd> | Move to the first / last cell of the row. |
| <kbd>Ctrl</kbd> + <kbd>Home</kbd> / <kbd>Ctrl</kbd> + <kbd>End</kbd> | Move to the first cell of the first row / the last cell of the last row. |
| <kbd>Page Up</kbd> / <kbd>Page Down</kbd> | Scroll one page up / down without moving the active cell. |
| <kbd>Enter</kbd> / <kbd>F2</kbd> | Start editing the active cell when its column is editable. In edit mode, commit the edit. |
| <kbd>Esc</kbd> | Cancel the edit and leave edit mode. |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | In edit mode, move to the next / previous editable cell. |
| <kbd>Space</kbd> | Select or deselect the row when row selection is on. |
| <kbd>Alt</kbd> + <kbd>Arrow Right</kbd> / <kbd>Arrow Down</kbd> | Expand the group row or the master-detail row. |
| <kbd>Alt</kbd> + <kbd>Arrow Left</kbd> / <kbd>Arrow Up</kbd> | Collapse the group row or the master-detail row. |

The following keys work in the header row:

| Key | Action |
| --- | --- |
| <kbd>Ctrl</kbd> + <kbd>Arrow Up</kbd> / <kbd>Arrow Down</kbd> | Sort the column in ascending / descending order. |
| <kbd>Shift</kbd> + <kbd>Alt</kbd> + <kbd>Arrow Right</kbd> / <kbd>Arrow Left</kbd> | Group / ungroup the data by the column. |
| <kbd>Space</kbd> | Select the column when column selection is on. |
| <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>L</kbd> | Open the filter row or the Excel-style filter menu of the column. |
| <kbd>Alt</kbd> + <kbd>L</kbd> | Open the advanced filtering dialog. |

For all keys, including the summary row and custom navigation, see <PlatformBlock for="Angular">[Keyboard Navigation](../grid/keyboard-navigation.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[Keyboard Navigation](./_shared/keyboard-navigation.mdx)</PlatformBlock>.

### Screen Readers / ARIA

The Data Grid renders only the rows and columns in view, so it gives each rendered header and cell its position in the whole data set:

| Element | Role | Attributes |
| --- | --- | --- |
| Grid | `grid` | `aria-rowcount`: the number of data rows plus the header row. `aria-colcount`: the number of visible columns. |
| Header row container | `rowgroup` | `aria-activedescendant`: the active header. |
| Header row | `row` | `aria-rowindex="1"` |
| Column header | `columnheader` | `aria-sort` while the column is sorted, `aria-selected`, `aria-colindex`, `aria-rowindex` |
| Body | `rowgroup` | `aria-activedescendant`: the active cell. |
| Data row | `row` | `aria-selected`, `aria-disabled` |
| Data cell | `gridcell` | `aria-rowindex`, `aria-colindex`, `aria-selected`, `aria-readonly` when the column isn't editable, `aria-invalid`, and `aria-describedby` with the validation error when the value is invalid |
| Summary cell | `cell` | — |

The Data Grid has no accessible name of its own. Add `aria-label` or `aria-labelledby` to the grid element, and label the controls that you render in cell, header, and editing templates.

### Accessibility Compliance

{ProductName} targets WCAG 2.1 Level AA, which also addresses Section 508 and EN 301 549. See [Accessibility Compliance](../interactivity/accessibility-compliance.mdx) for the product statement. The Data Grid supports the following criteria:

| Criterion | How the component complies |
| --- | --- |
| [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships) | The `grid`, `rowgroup`, `row`, `columnheader`, and `gridcell` roles expose the table structure, and `aria-rowindex` and `aria-colindex` give each rendered cell its position in the data set. |
| [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | The arrow keys and their <kbd>Ctrl</kbd> combinations move between cells, <kbd>Enter</kbd> and <kbd>F2</kbd> start editing, <kbd>Space</kbd> selects rows, and header shortcuts sort, group, and filter the columns. |
| [2.1.2 No Keyboard Trap](https://www.w3.org/WAI/WCAG21/Understanding/no-keyboard-trap) | Outside edit mode, the Data Grid doesn't handle <kbd>Tab</kbd>, so <kbd>Tab</kbd> and <kbd>Shift</kbd> + <kbd>Tab</kbd> move the focus out of the grid. In edit mode, <kbd>Esc</kbd> leaves edit mode. |
| [3.3.1 Error Identification](https://www.w3.org/WAI/WCAG21/Understanding/error-identification) | A cell with an invalid value sets `aria-invalid` and points `aria-describedby` to its validation error. |
| [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | Headers expose the sort direction through `aria-sort`, rows and cells expose their selection through `aria-selected`, and cells expose their read-only state through `aria-readonly`. |

To keep a page with the Data Grid conformant:

- Give the Data Grid an accessible name with `aria-label` or `aria-labelledby`.
- Label the inputs and buttons that you render in templates.
- Keep enough contrast when you override the theme colors. See [Styling](#styling).
- Keep a logical focus order around the grid in the page layout.

## Troubleshooting

### Why doesn't deleteRow remove the row?

The <ApiLink type="Grid" member="deleteRow" label="deleteRow" /> method takes the primary key of the row, and it does nothing when the <ApiLink type="Grid" member="primaryKey" label="primaryKey" /> property isn't set. Set `primaryKey` to the field that identifies each record and pass that field's value, or call `delete()` on the row, for example `cell.row.delete()` in a cell template.

### Why doesn't a value that my cell template changes reach the data?

A cell template only renders the cell. When the template changes the value, call `cell.update(value)`, which sends the change through the grid editing pipeline. For edit UI, use a cell editing template that writes `cell.editValue` instead. See [Cell Template](#cell-template) and [Cell Editing Template](#cell-editing-template).

### Why doesn't the Data Grid show a change that I made to a record?

The Data Grid doesn't watch the records for changes. When you change a record in place, call <ApiLink type="Grid" member="markForCheck" label="markForCheck" /> to refresh the grid, or assign a new array to <ApiLink type="Grid" member="data" label="data" />.

<PlatformBlock for="Angular">

The Angular Data Grid uses the `OnPush` change detection strategy, so this also applies to changes that your templates make to their own state.

### How do I import the Data Grid in an NgModule-based app?

Standalone imports with `IGX_GRID_DIRECTIVES` are the current approach (see [Getting Started](#getting-started)). For an app that still uses NgModules, `igniteui-angular/grids/grid` exports the `IgxGridModule` for backward compatibility:

```ts
import { NgModule } from '@angular/core';
import { IgxGridModule } from 'igniteui-angular/grids/grid';

@NgModule({
    imports: [IgxGridModule]
})
export class AppModule {}
```

### How do I reduce change detection in an app that uses Zone.js?

Turn on event and run coalescing, so that Zone.js runs one change detection for several events in the same task:

```ts
import { bootstrapApplication } from '@angular/platform-browser';
import { provideZoneChangeDetection } from '@angular/core';

bootstrapApplication(AppComponent, {
    providers: [provideZoneChangeDetection({ eventCoalescing: true, runCoalescing: true })]
});
```

Coalescing changes the timing of change detection in the whole app, not only in the Data Grid, so test the rest of the app after you turn it on.

## Known Limitations

| Limitation | Description |
| --- | --- |
| Mixed column width units | Columns with widths in percentages and columns with widths in pixels can't be mixed in one Data Grid. |
| Grid width | The column widths don't set the width of the Data Grid. The grid takes its <ApiLink type="Grid" member="width" label="width" />, or the width of its parent container when you don't set one. |
| Minimum column width | A column can't be narrower than the minimum width of the current size: 56px for small, 64px for medium, and 80px for large. A narrower width doesn't apply, and it can break horizontal virtualization. |
| Row height and virtualization | Only the columns in view affect the row height. A cell template that makes a row taller changes the row height only while its column is in view. |

<PlatformBlock for="Angular">

The Data Grid renders its rows and columns with the `igxForOf` directive, so the [igxForOf known limitations](../for-of.mdx#known-limitations) also apply to the Data Grid.

</PlatformBlock>

## FAQ

<Faq>
  <FaqItem question="How do I bind the Data Grid to data from a server?" indicatorPosition="end">

  Request the data and assign the result to the `data` property of the {Platform} Data Grid. With `autoGenerate` on, the Data Grid creates its columns when the first records arrive. To page, sort, and filter on the server instead of in the browser, see [Remote Data](#remote-data) and the remote data operations topic.

  </FaqItem>
  <FaqItem question="Can the Data Grid display nested objects?" indicatorPosition="end">

  Yes. A {Platform} Data Grid column binds to a nested property through a path in its `field`, such as `weight.molecular`. To combine several values, or to render a collection, use a cell template. See [Complex Data](#complex-data).

  </FaqItem>
  <FaqItem question="How do I make Data Grid cells editable?" indicatorPosition="end">

  Set the `editable` property of a {Platform} Data Grid column to `true`. Users then edit its cells with a default editor for the column data type, or with your cell editing template. To edit whole rows, set `rowEditable` on the Data Grid. See [Cell Editing Template](#cell-editing-template) and [Editing](#editing).

  </FaqItem>
  <FaqItem question="How does the Data Grid handle large data sets?" indicatorPosition="end">

  The {Platform} Data Grid virtualizes its rows and columns, so it renders only the rows and columns in view while the user scrolls. To load less data into the browser, add paging or run the data operations on the server. See the virtualization and remote data operations topics in [Additional Resources](#additional-resources).

  </FaqItem>
  <FaqItem question="Is the Data Grid free?" indicatorPosition="end">

  No. The {Platform} Data Grid is a commercial component, so production use needs a commercial license. For a free grid with a smaller feature set, use the open-source Grid Lite, which is available under the MIT license. See [Related Components](#related-components).

  </FaqItem>
</Faq>
