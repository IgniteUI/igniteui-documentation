# Data Grid

The {ProductName} Data Grid (<ApiLink type="Grid" />) displays and edits flat tabular data: an array of records, one row per record. It is the grid to start with for lists of orders, customers, transactions and any other data that has one row per record. You enable features such as sorting, filtering, grouping, editing, paging and Excel export per column or per grid, and the Data Grid virtualizes its rows and columns by default.

For hierarchical data, use the [Tree Grid](./tree-grid/overview.mdx) or the [Hierarchical Grid](./hierarchical-grid/overview.mdx), which offer most of the same features. To summarize data in a cross-tabular layout, use the [Pivot Grid](./pivot-grid/overview.mdx).

The selector of the Angular Data Grid is `igx-grid`, and each `igx-column` in it defines one column.

## Anatomy

The {Platform} Data Grid consists of a header row and a virtualized body of rows and cells, with an optional toolbar above them and optional summary cells and a paginator below them.

<span class="ig-typography__body-2" style="display: block; margin-bottom: 24px;"><strong>1. Grid Toolbar (optional):</strong> bar above the grid for a title and grid-level actions such as column hiding, column pinning, exporting and advanced filtering<br />
<strong>2. Grid Body:</strong> the scrollable, virtualized area that renders the data rows<br />
<strong>3. Header Row:</strong> the row that holds one header cell for each visible column and stays in view while the body scrolls<br />
<strong>4. Header Cell:</strong> shows the title of a column and hosts its sorting, filtering, moving and resizing interactions<br />
<strong>5. Grid Column:</strong> a vertical set of cells bound to one data field; it defines the data type, the width, the templates and the features enabled for that field<br />
<strong>6. Grid Row:</strong> one data record, displayed as a horizontal set of cells<br />
<strong>7. Grid Cell:</strong> the intersection of a row and a column, which shows a single value and, when the column is editable, edits it<br />
<strong>8. Summary Cell (optional):</strong> a cell below a column that shows aggregated values such as count, sum, min, max or average<br />
<strong>9. Paginator (optional):</strong> the bar below the grid that splits the data into pages and provides page navigation and page size selection</span>

## Usage

Use the {Platform} Data Grid to display, edit and analyze records that share the same fields.

### Basic Configuration

Now that we have the grid packages imported, let's get started with the basic configuration and bind to local data:

The <ApiLink type="Grid" member="id" /> property is a string value and is the unique identifier of the grid which will be auto-generated if not provided, while <ApiLink type="Grid" member="data" /> binds the grid, in this case to local data.

The <ApiLink type="Grid" member="autoGenerate" /> property tells the grid to auto generate the grid's <ApiLink type="Column" /> components based on the data source fields. It will also try to deduce the appropriate data type for the column if possible. Otherwise, the developer needs to explicitly define the columns and the mapping to the data source fields.

<PlatformBlock for="Angular,React,WebComponents">

The grid reads the fields and their values from the first record. A number, a Boolean, a `Date` object and a string that ends with an image file extension, such as `.png`, give number, boolean, date and image columns; any other value gives a string column.

</PlatformBlock>

<PlatformBlock for="Angular">

{ProductName} includes a powerful bootstrap grid like flex-based layout system. Any modern application today is expected to follow a responsive web design approach, meaning it can gracefully adjust layout of HTML elements based on the device size, or from simply resizing the browser. A bootstrap grid layout was the most used approach in the past, but a flex-based layout system like CSS grid has become more popular, as it works in any browser. The {ProductName} Layout Directive allows vertical and horizontal flow, including content / text wrapping, justification, and alignment. The {ProductName} grid supports a responsive layout using CSS, giving you the ultimate flexibility in how the grid behaves on resize.

</PlatformBlock>

Each operation for grid editing includes batch operations, meaning the API gives you the option to group edits into a single server call, or you can perform grid edit / update operations as they occur with grid interactions. Along with a great developer experience as an editable grid with CRUD operations, the grid includes Excel-like keyboard navigation. Common default grid navigation is included, plus the option to override any navigation option to meet the needs of your customers. An editable grid with a great navigation scheme is critical to any modern line of business application, with the {ProductName} grid we make it easy.

Following this topic you will learn more about [cell template](#cell-template) and [cell editing template](#cell-editing-template) and editing.

#### Header Template

The header template can be set to modify the column headers. The snippets below show you how to format the header text to upper case.

<PlatformBlock for="Angular">

```html
<igx-column field="Name">

    </ng-template>
</igx-column>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-column id="name" field="Name"></igc-column>
```

```typescript
import { html } from 'lit-html';
import { IgcColumnComponent, IgcColumnTemplateContext } from 'igniteui-webcomponents-grids/grids';

constructor() {
    var name = this.name = document.getElementById('name') as IgcColumnComponent;
    name.headerTemplate = this.nameHeaderTemplate;
}

public nameHeaderTemplate = (ctx: IgcColumnTemplateContext) => {
    return html`
        ${this.formatUppercase(ctx.column.field)}
    `;
}

public formatUppercase(value: string) {
    return value.toUpperCase();
}
```

#### Cell Template

When cell template is set it changes all the cells in the column. The context object provided in the template consists of the cell value provided implicitly (<PlatformBlock for="Angular">`$implicit`</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">`implicit`</PlatformBlock>) and the cell object itself (`cell`). It can be used to define a template where the cells' text could be formatted e.g. as title case.

<PlatformBlock for="Angular">

```html
<igx-column field="Name">
    <ng-template igxCell let-value>
        {{ value | titlecase }}
    </ng-template>
</igx-column>
```

The `uppercase` and `titlecase` pipes come from `@angular/common`. Add `UpperCasePipe` and `TitleCasePipe` to the `imports` of your component.

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-column id="name" field="Name"></igc-column>
```

```typescript
import { html } from 'lit-html';
import { IgcCellTemplateContext, IgcColumnComponent } from 'igniteui-webcomponents-grids/grids';

constructor() {
    var name = this.name = document.getElementById('name') as IgcColumnComponent;
    name.bodyTemplate = this.nameCellTemplate;
}

public nameCellTemplate = (ctx: IgcCellTemplateContext) => {
    return html`
        ${this.formatTitleCase(ctx.implicit)}
    `;
}

public formatTitleCase(value: string) {
    return value.toLowerCase().replace(/\b\w/g, c => c.toUpperCase());
}
```

</PlatformBlock>

#### Custom Display Format

A good practice is to separate all data fetching related logic in a separate data service, so we are going to create a service which will handle the fetching of data from the server.

Let's implement our service in a separate file

```typescript
// northwind.service.ts

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable, of } from 'rxjs';
import { catchError, map } from 'rxjs/operators';
```

We're importing the `Injectable` decorator which is an [essential ingredient](https://angular.dev/guide/di) in every {Platform} service definition. The `HttpClient` will provide us with the functionality to communicate with backend services. It returns an `Observable` of some result to which we will subscribe in our grid component.

Since we will receive a JSON response containing an array of records, we may as well help ourselves by specifying what kind of data we're expecting to be returned in the observable by defining an interface with the correct shape. Type checking is always recommended and can save you some headaches down the road.

```typescript
// northwind.service.ts

export interface NorthwindRecord {
    ProductID: number;
    ProductName: string;
    SupplierID: number;
    CategoryID: number;
    QuantityPerUnit: string;
    UnitPrice: number;
    UnitsInStock: number;
    UnitsOnOrder: number;
    ReorderLevel: number;
    Discontinued: boolean;
    CategoryName: string;
}
```

The service itself is pretty simple consisting of one method: `fetchData` that will return an `Observable<NorthwindRecord[]>`. In cases when the request fails for any reason (server unavailable, network error, etc), the `HttpClient` will return an error. We'll leverage the `catchError` operator which intercepts an Observable that failed and passes the error to an error handler. Our error handler will log the error and return a safe value.

```typescript
// northwind.service.ts

@Injectable()
export class NorthwindService {
    private url = 'https://services.odata.org/V4/Northwind/Northwind.svc/Alphabetical_list_of_products';

    constructor(private http: HttpClient) {}

    public fetchData(): Observable<NorthwindRecord[]> {
        return this.http
            .get<{ value: NorthwindRecord[] }>(this.url)
            .pipe(
                map(response => response.value),
                catchError(
                    this.errorHandler('Error loading Northwind data', [])
                )
            );
    }

    private errorHandler<T>(message: string, result: T) {
        return (error: any): Observable<any> => {
            console.error(`${message}: ${error.message}`);
            return of(result as T);
        };
    }
}
```

Make sure to provide the `HttpClient` with `provideHttpClient()` and to register our service as a provider in the application configuration.

```typescript
// app.config.ts

import { ApplicationConfig } from '@angular/core';
import { provideHttpClient } from '@angular/common/http';
import { NorthwindService } from './northwind.service';

export const appConfig: ApplicationConfig = {
    providers: [
        provideHttpClient(),
        NorthwindService
    ]
};
```

After implementing the service we will inject it in our component's constructor and use it to retrieve the data. The `ngOnInit` lifecycle hook is a good place to dispatch the initial request.

**Note**: In the code below, you may wonder why are we setting the _records_ property to an empty array before subscribing to the service. The Http request is asynchronous, and until it completes, the _records_ property would otherwise be _undefined_. You should either initialize it with a default value or use a `BehaviorSubject`.

```typescript
// my.component.ts

@Component({
    // ...
})
export class MyComponent implements OnInit {

    public records: NorthwindRecord[] = [];

    constructor(private northwindService: NorthwindService) {}

    ngOnInit() {
        this.northwindService.fetchData().subscribe((records) => this.records = records);
    }
}
```

and in the template of the component:


### Performance (Experimental)

Design of the <ApiLink type="Grid" /> allows it to take advantage of the Event Coalescing feature that has Angular introduced. This feature allows for improved performance with roughly around **20%** in terms of interactions and responsiveness. This feature can be enabled on application level by setting the `eventCoalescing` and `runCoalescing` options of `provideZoneChangeDetection` to **true** in the providers of the application:

```typescript
// main.ts

bootstrapApplication(AppComponent, {
    providers: [provideZoneChangeDetection({ eventCoalescing: true, runCoalescing: true })]
}).catch(err => console.error(err));
```

Event coalescing is an option of the zone.js-based change detection, while Angular 21 and later use zoneless change detection by default. In an NgModule-based application, pass the same provider in the `applicationProviders` option of `bootstrapModule()`.

<DocsAside type="info">
This is still in experimental feature for the `IgxGridComponent`. This means that there might be some unexpected behaviors in the Grid. In case of encountering any such behavior, please contact us on our [GitHub]({GithubLink}/discussions) page.
</DocsAside>

<DocsAside type="info">
Enabling it can affect other parts of an Angular application that the `IgxGridComponent` is not related to.
</DocsAside>

### Do/Don't

Align the content of the header cells and the body cells by data type: text to the left and numbers to the right. The Data Grid aligns number, currency and percent columns to the right by default; keep that alignment when you template their cells.

<DoDont
  doSrc={gridDoAlignment}
  doAlt="Data Grid with a left-aligned Name column and a right-aligned Age column"
  dontSrc={gridDoNotAlignment}
  dontAlt="Data Grid with an Age column whose numbers are aligned to the left"
>
<Fragment slot="do">

Align text to the left and numbers to the right in the header cells and the body cells.

</Fragment>
<Fragment slot="dont">

Avoid aligning numbers to the left: values of different lengths become hard to compare.

</Fragment>
</DoDont>

Keep the content of every cell on one line. A cell template with content that wraps makes its row taller than the other rows, and the Data Grid measures such a row only when it scrolls into view, as [Known Limitations](#known-limitations) describes.

<DoDont
  doSrc={gridDoRowHeight}
  doAlt="Data Grid with three rows of the same height, in which long descriptions end with an ellipsis"
  dontSrc={gridDoNotRowHeight}
  dontAlt="Data Grid in which a description wraps to three lines and makes its row taller than the other rows"
>
<Fragment slot="do">

Keep cell content on one line; the Data Grid ends long text with an ellipsis.

</Fragment>
<Fragment slot="dont">

Avoid cell templates that let the content wrap: the rows get different heights and the text touches the row borders.

</Fragment>
</DoDont>

Show the columns that the task needs. Hide the remaining ones and let the reader show them from the [Column Hiding](./_shared/column-hiding.mdx) menu, instead of narrowing every column until its content no longer fits.

<DoDont
  doSrc={gridDoColumns}
  doAlt="Data Grid with three columns, Product, Category and Price, that show their headers and values in full"
  dontSrc={gridDoNotColumns}
  dontAlt="Data Grid with six narrow columns whose headers and values are truncated to one or two letters"
>
<Fragment slot="do">

Show a few columns that are wide enough for their headers and values.

</Fragment>
<Fragment slot="dont">

Avoid squeezing every field into the visible width: the headers and the values are truncated.

</Fragment>
</DoDont>

### Sass Theming

The easiest and recommended way to style the `igxGrid` is to use the <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} /> and provide just the three main colors: `background`, `foreground`, and `accent-color`.

These are the core theme properties. When you set them, all grid parts and internal components derive their colors from those values, resulting in a consistent appearance throughout the entire grid. Nested components such as buttons, icons, inputs, dropdowns, checkboxes, scrollbars, chips, and other helper components also derive their styling tokens from the main <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} /> for a unified look.

```scss
@use "igniteui-angular/theming" as *;

$custom-grid: grid-theme(
  $background: #292826,
  $foreground: #eeece1,
  $accent-color: #ffcd0f
);

igx-grid {
  @include tokens($custom-grid);
}
```

There are also additional parameters in the <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} />, such as `$header-background` and `$row-hover-background`, that you can use if you want more specific customizations.

## Accessibility

The {Platform} Data Grid can be operated with the keyboard and exposes its structure and state to assistive technology through ARIA roles and attributes.

### Keyboard Interaction

Keyboard navigation of the <ApiLink type="Grid" /> provides a rich variety of keyboard interactions for the user. It enhances accessibility and allows intuitive navigation through any type of elements inside (cell, row, column header, toolbar, footer, etc.).

The header row and the body of the {Platform} Data Grid are separate tab stops, and inside each of them the arrow keys move the active cell. The following keys work while the header row or the body has the focus:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Outside edit mode, the Data Grid doesn't handle these keys, so they move the focus to the next or the previous tab stop. While a cell or a row is in edit mode, they move to the next or the previous editable cell. |
| <kbd>Arrow Up</kbd> / <kbd>Arrow Down</kbd> | Move the active cell one row up or down. |
| <kbd>Arrow Left</kbd> / <kbd>Arrow Right</kbd> | Move the active cell, or the active column header, one column to the left or to the right. |
| <kbd>Home</kbd> / <kbd>End</kbd> | Move to the first or the last cell of the row. |

### Screen Readers / ARIA

The {Platform} Data Grid renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| <PlatformBlock for="Angular">`igx-grid`</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">`igc-grid`</PlatformBlock> | `grid` | `aria-rowcount` and `aria-colcount` |
| `igx-grid-header-row` | `rowgroup` | `aria-activedescendant` that points to the active column header |
| `div.igx-grid__tr` in the header row | `row` | `aria-rowindex="1"` |
| `igx-grid-header` | `columnheader` | `aria-sort` (`ascending` or `descending`) when the column is sorted, `aria-selected`, `aria-colindex` and `aria-rowindex` |
| `div.igx-grid__tbody-content` | `rowgroup` | `aria-activedescendant` that points to the active cell |
| `igx-grid-row` | `row` | `aria-selected` and `aria-disabled` |
| `igx-grid-cell` | `gridcell` | `aria-rowindex`, `aria-colindex`, `aria-selected`, `aria-readonly` when the cell can't be edited, and `aria-invalid` and `aria-describedby` when the value fails validation |
| `igx-grid-groupby-row` | `row` | The expand indicator of the group row is a `gridcell` with `aria-expanded`. |
| `igx-grid-summary-row` | `row` | The summary cells have the `cell` role. |
| `igx-page-nav` in the paginator | `navigation` | The page buttons have accessible names, such as "Next page". |

The {Platform} Data Grid also behaves as follows for assistive technology:

- The focus stays on the header row or on the body while the active cell moves, and `aria-activedescendant` points to the active column header or cell.
- Only the rows and the columns in view are in the DOM. `aria-rowindex` and `aria-colindex` give each rendered cell its position in the data.

You supply the accessible name of the Data Grid, for example with `aria-label` on the grid element, and accessible names for icon-only content in your cell and header templates.

### Accessibility Compliance

The [Accessibility Compliance](../interactivity/accessibility-compliance.mdx) topic lists the standards that {ProductName} targets, WCAG 2.1 Level AA among them, and records what the Data Grid documentation covers. It is a support summary, not a formal conformance statement.

| Criterion | How the component complies |
| --- | --- |
| [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships) | The `grid`, `rowgroup`, `row`, `columnheader` and `gridcell` roles expose the structure, and `aria-rowindex` and `aria-colindex` give the position of each cell in the data. |
| [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | The arrow keys, Home, End, Page Up and Page Down move through the cells, Enter and F2 start editing, Space selects rows, and Ctrl + Arrow Up and Ctrl + Arrow Down sort from a column header. |
| [2.1.2 No Keyboard Trap](https://www.w3.org/WAI/WCAG21/Understanding/no-keyboard-trap) | Outside edit mode, the Data Grid doesn't handle the Tab key, so Tab and Shift + Tab move the focus out of the header row and the body. |
| [2.4.3 Focus Order](https://www.w3.org/WAI/WCAG21/Understanding/focus-order) | The header row and the body are separate tab stops, in their visual order. |
| [2.4.7 Focus Visible](https://www.w3.org/WAI/WCAG21/Understanding/focus-visible) | The active cell and the active column header show a border in the `--cell-active-border-color` color. |
| [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | Cells expose the `gridcell` role and their selected and read-only states through `aria-selected` and `aria-readonly`. Column headers expose the sort direction through `aria-sort`, and group rows expose their expanded state through `aria-expanded`. |

Your responsibilities:

- Give the Data Grid an accessible name, for example with `aria-label` or `aria-labelledby` on the grid element. The Data Grid doesn't set one.
- Give icons and icon-only buttons that you place in cell and header templates an accessible name.
- Test the focusable elements that you place in cell templates with the keyboard. The Data Grid handles the arrow keys, Enter, F2, Esc and Space on the body, so these elements may need to handle the keys that they use.
- When you override the theme colors, keep a contrast ratio of at least 4.5:1 for the text of the headers and the cells, as [1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum) requires, and keep the border of the active cell visible. See [Styling](#styling).

## Troubleshooting

These questions cover common problems when you set up the {Platform} Data Grid.

### Why can't I click the elements in my column header template?

When column moving is on or the column is groupable, the header of the {Platform} Data Grid is draggable, so pressing the pointer on the header starts a drag instead of reaching the elements in your header template. Set `draggable="false"` on the element that the user clicks:

<PlatformBlock for="Angular">

```html
<igx-column field="ProductName" header="Product name" [groupable]="true">
    <ng-template igxHeader let-column>
        <span>{{ column.header }}</span>
        <button type="button" draggable="false" (click)="column.hasSummary = !column.hasSummary">Summary</button>
    </ng-template>
</igx-column>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-column id="product" field="ProductName" header="Product name" groupable="true"></igc-column>
```

```ts
const productHeaderTemplate = (ctx: IgcColumnTemplateContext) => html`
    <span>${ctx.column.header}</span>
    <button type="button" draggable="false" @click=${() => (ctx.column.hasSummary = !ctx.column.hasSummary)}>Summary</button>
`;

const product = document.getElementById('product') as IgcColumnComponent;
product.headerTemplate = productHeaderTemplate;
```

</PlatformBlock>

### How do I import the Data Grid in an NgModule-based application?

The `IGX_GRID_DIRECTIVES` token in [Getting Started](#getting-started) is for standalone components, which the Data Grid supports as of version `16.0.0`. An application that still declares its components in NgModules can import the `IgxGridModule` from the same entry point instead, which the package keeps for backward compatibility:

```typescript
// app.module.ts

import { NgModule } from '@angular/core';
import { IgxGridModule } from 'igniteui-angular/grids/grid';
// import { IgxGridModule } from '@infragistics/igniteui-angular/grids/grid'; for licensed package

@NgModule({
    imports: [IgxGridModule]
})
export class AppModule {}
```

## Known Limitations

The {Platform} Data Grid has the following limitations.

| Limitation | Description |
| --- | --- |
| Column widths set in `percentage` and `px` | Currently we do not support mixing of column widths with `%` and `px`. |
| When trying to filter a column of type `number` | If a value different than `number` is entered into the filtering input, `NaN` is returned due to an incorrect cast. |
| Grid `width` does not depend on the column widths | Unless the grid's `width` is `null`, the `width` of all columns does not determine the spanning of the grid itself. It is determined by the parent container dimensions or the defined grid's `width`. |
| Grid nested in parent container | When grid's `width` is not set and it is placed in a parent container with defined dimensions, the grid spans to this container. |
| Columns have a minimum allowed column width. Depending on the `--ig-size` CSS variable, they are as follows: <br/>"small": 56px <br/> "medium": 64px <br/> "large": 80px | Resizing or auto-sizing doesn't make a column narrower than the minimum allowed width for the corresponding `--ig-size`, unless the column has a minimum width of its own. A narrower width that you set yourself applies. |
<PlatformBlock for="Angular">| Grid `OnPush` ChangeDetectionStrategy | The grid operates with `ChangeDetectionStrategy.OnPush` so whenever some customization appears make sure that the grid is notified about the changes that happens. |
</PlatformBlock>| Row height is not affected by the height of cells that are not currently rendered in view. | Because of virtualization a column with a custom template (that changes the cell height) that is not in the view will not affect the row height. The row height will be affected only while the related column is scrolled in the view. |

<PlatformBlock for="Angular">

<DocsAside type="info">
`igxGrid` uses `igxForOf` directive internally hence all `igxForOf` limitations are valid for `igxGrid`. For more details see [igxForOf Known Issues](../for-of.mdx#known-limitations) section.
</DocsAside>

</PlatformBlock>

## FAQ

These questions cover common {Platform} Data Grid data binding, editing and performance scenarios.

<Faq>
  <FaqItem question="How do I bind the {Platform} Data Grid to remote data?" indicatorPosition="end">
    Fetch the data and assign the array to the data property of the {Platform} Data Grid. The [Remote Data Binding](#remote-data-binding) section shows the complete example and links to the topics about live data and server-side data operations.
  </FaqItem>
  <FaqItem question="When should I use the Tree Grid or the Hierarchical Grid instead of the Data Grid?" indicatorPosition="end">
    Use the Tree Grid or the Hierarchical Grid for records that form a hierarchy; the [Related Components](#related-components) section explains when each one fits.
  </FaqItem>
  <FaqItem question="How do I change what a cell of the Data Grid displays?" indicatorPosition="end">
    Set the data type of a column of the {Platform} Data Grid to format numbers, dates, currencies and Booleans, and its pipe arguments to change the format, as [Custom Display Format](#custom-display-format) shows. To render your own content, give the column a [cell template](#cell-template).
  </FaqItem>
  <FaqItem question="How do I make the Data Grid editable?" indicatorPosition="end">
    Set a column of the {Platform} Data Grid as editable to edit single cells, or turn on row editing to edit a row and confirm it as a whole. Editing rows through the API or with row editing requires a primary key. To replace the default editor of a column, give it a [cell editing template](#cell-editing-template).
  </FaqItem>
  <FaqItem question="Does the Data Grid handle large data sets?" indicatorPosition="end">
    The {Platform} Data Grid virtualizes rows and columns: it renders only the cells in the viewport and reuses them while the reader scrolls. For data that does not fit in memory, load it on demand as the [Remote Data Operations](./_shared/remote-data-operations.mdx) topic shows.
  </FaqItem>
</Faq>
