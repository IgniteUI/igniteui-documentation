# {Platform} Vertical Charts

The {ProductName} vertical category series draw the familiar line, spline, point, step, area and waterfall charts turned on their side. The categories run down the chart on a `CategoryYAxis` and the values run across it on a `NumericXAxis`, the same arrangement as a [Bar Chart](bar-chart.mdx). Each series is the vertical counterpart of a horizontal series you may already use, and shares its options: `VerticalLineSeries` mirrors the `LineSeries`, `VerticalAreaSeries` the `AreaSeries`, and so on.

## Vertical Chart Recommendations

### Are {Platform} Vertical Charts right for your project?

Turn a chart on its side when the categories read better from top to bottom than from left to right:

- The categories are a physical vertical dimension, such as depth, altitude or the floors of a building.
- The category labels are long, such as survey questions, product features or account names. Running down the chart, each label gets the full width of the axis instead of being rotated or cut off.
- There are many categories, such as the hours of a day, and the chart has more room vertically than horizontally.
- The chart sits beside a bar chart or a table whose rows it should line up with.

### Vertical Chart Use Cases

- Ocean, soil or atmosphere profiles, where the value changes with depth or altitude.
- Survey and ranking results with long category names.
- Timelines that read from top to bottom, such as the hours of a day or the months of a year.
- Profit bridges and other waterfall charts with long step names.
- Bar charts with a target or an average drawn over the bars.

### When not to Use a Vertical Chart

- The categories are a time series that readers expect to run from left to right, such as stock prices. Use the horizontal [Line Chart](line-chart.mdx) or [Area Chart](area-chart.mdx).
- You need to compare the magnitudes of separate categories. A [Bar Chart](bar-chart.mdx) shows each value as the length of a bar, which is easier to compare than the position of a point.

### Vertical Chart Data Structure

- The data source must be an array or a list of data items.
- Each item must have a category, such as a string or a date, which labels its row on the `CategoryYAxis`.
- Each series reads one numeric field through its `valueMemberPath`.

## {Platform} Vertical Chart Axes

A vertical series takes a `CategoryYAxis` for its categories and a `NumericXAxis` for its values. Bind the category axis to the same data as the series and name the category field with `label`. Set `isInverted` on the category axis to run the categories from top to bottom; without it the first item is at the bottom, which suits altitude but not depth.

```json-snippet source="/charts/data-chart/vertical-line-chart"
{
    "descriptions": {
        "content": {
            "type": "DataChart",
            "name": "chart",
            "axes": [
                {
                    "type": "CategoryYAxis",
                    "name": "yAxis",
                    "label": "Depth",
                    "dataSourceRef": "OceanTemperatureByDepth",
                    "interval": 1,
                    "isInverted": true
                },
                {
                    "type": "NumericXAxis",
                    "name": "xAxis",
                    "title": "Temperature (°C)"
                }
            ],
            "series": [
                {
                    "type": "VerticalLineSeries",
                    "name": "VerticalLineSeries1",
                    "title": "Summer",
                    "xAxisRef": "xAxis",
                    "yAxisRef": "yAxis",
                    "dataSourceRef": "OceanTemperatureByDepth",
                    "valueMemberPath": "Summer",
                    "markerType": "Circle",
                    "thickness": 2
                }
            ]
        }
    }
}
```

## {Platform} Vertical Line Chart

The `VerticalLineSeries` joins the values of neighboring categories with straight lines, as in the [example above](#{PlatformLower}-vertical-chart-example). It takes the same marker, thickness and brush options as the `LineSeries`.

## {Platform} Vertical Spline Chart

The `VerticalSplineSeries` joins the values with smooth curves. The example below plots air temperature against altitude, with the ground at the bottom, so the category axis is not inverted.

<Sample src="/charts/data-chart/vertical-spline-chart" height={600} alt="{Platform} Vertical Spline Chart" />

```json-snippet source="/charts/data-chart/vertical-spline-chart"
{
    "type": "DataChart",
    "series": [
        {
            "type": "VerticalSplineSeries",
            "$type": "+doc:markup",
            "title": "Standard Atmosphere",
            "valueMemberPath": "Standard",
            "markerType": "Circle",
            "$markerType": "+doc:markup"
        }
    ]
}
```

## {Platform} Vertical Point Chart

The `VerticalPointSeries` draws a marker for each value without joining them, which suits categories that have no order, such as the features in the survey below. Two point series side by side compare two sets of results, row by row.

## {Platform} Vertical Step Line Chart

The `VerticalStepLineSeries` holds each value until the next category and then steps to the next value, which suits values that change at set times and stay put in between, such as interest rates.

<Sample src="/charts/data-chart/vertical-step-line-chart" height={600} alt="{Platform} Vertical Step Line Chart" />

## {Platform} Vertical Area Chart

The `VerticalAreaSeries` fills the space between the line and the value axis. Lower `areaFillOpacity` when areas overlap, so the series behind stays visible.

<Sample src="/charts/data-chart/vertical-area-chart" height={600} alt="{Platform} Vertical Area Chart" />

```json-snippet source="/charts/data-chart/vertical-area-chart"
{
    "type": "DataChart",
    "series": [
        {
            "type": "VerticalAreaSeries",
            "$type": "+doc:markup",
            "title": "1990",
            "valueMemberPath": "Year1990",
            "areaFillOpacity": 0.5,
            "$areaFillOpacity": "+doc:markup"
        }
    ]
}
```

## {Platform} Vertical Waterfall Chart

The `VerticalWaterfallSeries` draws each category as a bar from the previous value to its own, so a running total reads as a series of gains and losses. Each value is the running total after that step, not the change. Bars that fall from the previous value use `negativeBrush` and `negativeOutline`.

<Sample src="/charts/data-chart/vertical-waterfall-chart" height={600} alt="{Platform} Vertical Waterfall Chart" />

```json-snippet source="/charts/data-chart/vertical-waterfall-chart"
{
    "type": "DataChart",
    "series": [
        {
            "type": "VerticalWaterfallSeries",
            "$type": "+doc:markup",
            "valueMemberPath": "Total",
            "brush": "#2E7D32",
            "$brush": "+doc:markup",
            "outline": "#2E7D32",
            "$outline": "+doc:markup",
            "negativeBrush": "#C62828",
            "$negativeBrush": "+doc:markup",
            "negativeOutline": "#C62828",
            "$negativeOutline": "+doc:markup"
        }
    ]
}
```

## {Platform} Combining Vertical Series with Bar Series

The vertical series share their axes with the `BarSeries`, so they can be drawn over bars in the same chart. The example below draws each region's sales target as a `VerticalLineSeries` over a `BarSeries` of the actual sales.

<Sample src="/charts/data-chart/vertical-chart-combined" height={600} alt="{Platform} Vertical Line Series over a Bar Series" />

```json-snippet source="/charts/data-chart/vertical-chart-combined"
{
    "type": "DataChart",
    "series": [
        {
            "type": "BarSeries",
            "$type": "+doc:markup",
            "title": "Actual",
            "valueMemberPath": "Actual"
        },
        {
            "type": "VerticalLineSeries",
            "$type": "+doc:markup",
            "title": "Target",
            "valueMemberPath": "Target",
            "markerType": "Diamond"
        }
    ]
}
```

## {Platform} Vertical Chart Tooltips

Add a `DataToolTipLayer` to describe the category under the cursor. By default the tooltip ends with a total of the series' values, which is useful when the series add up, such as desktop and mobile visits, but not when they are separate measurements, such as summer and winter temperatures. Set `summaryType` to `None` to leave it out.

```json-snippet source="/charts/data-chart/vertical-line-chart"
{
    "type": "DataChart",
    "series": [
        {
            "type": "DataToolTipLayer",
            "$type": "+doc:markup",
            "summaryType": "None",
            "$summaryType": "+doc:markup"
        }
    ]
}
```
