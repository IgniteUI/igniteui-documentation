# {Platform} Rating Component

The {ProductName} Rating is a form-associated component that lets users view and select a score on a scale of stars or custom symbols.

<PlatformBlock for="Angular">

In Angular, the Rating is the `igc-rating` web component from `igniteui-webcomponents`. Bind it to Angular forms with the `IgcFormControlDirective`.

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

The Rating supports half-star and other fractional values, a hover preview, single selection of distinct symbols, and full keyboard input.

</PlatformBlock>

## Anatomy

The Rating is built from Label and Value, where the Value is the number of the rating scale. The Label can be switched on/off using a boolean property. The number of icons in the rating scale is predefined to 5 stars in total, but if you need to design a Rating with more rating icons, the easiest way to do so is by inserting the component into your workspace.

The `igc-rating` element renders the label and a slider that holds the symbols. Without projected symbols, it renders one star for each point of `max`:

```text
igc-rating
└─ #shadow-root
   ├─ label[part="label"]                    // hidden when label isn't set
   └─ div[part="base"][role="slider"]
      ├─ div[part="symbols"]                 // aria-hidden="true"
      │  └─ slot[name="symbol"]              // projected igc-rating-symbol elements
      │     └─ igc-rating-symbol × max       // default stars when nothing is projected
      │        └─ #shadow-root
      │           ├─ div[part="symbol full"]   // star_filled icon, clipped to the value
      │           └─ div[part="symbol empty"]  // star_outlined icon, clipped to the rest
      └─ label[part="value-label"]
         └─ slot[name="value-label"]         // hidden when the slot is empty
```

Each `igc-rating-symbol` renders its default slot in the `full` part and its `empty` slot in the `empty` part.

## Usage

Use the {Platform} Rating to collect a score for a product, a service, or an experience, or to show an average score that users can't change.

Set `hoverPreview` to fill the symbols up to the value under the pointer before the user clicks. When the pointer leaves the symbols, the {Platform} Rating shows its value again. A read-only or disabled Rating shows no preview.

<PlatformBlock for="WebComponents">

While the preview is on, the Rating emits `igcHover` with the value under the pointer:

```html
<igc-rating hover-preview label="Rate this article"></igc-rating>
<span id="hint"></span>
```

```ts
const rating = document.querySelector('igc-rating')!;
const hint = document.getElementById('hint')!;

rating.addEventListener('igcHover', (event) => {
  hint.textContent = `${event.detail} stars`;
});
```

</PlatformBlock>

<PlatformBlock for="React">

While the preview is on, the Rating calls `onHover` with the value under the pointer:

```tsx
<IgrRating
  hoverPreview={true}
  label="Rate this article"
  onHover={(e: CustomEvent<number>) => setHint(`${e.detail} stars`)}
/>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

While the preview is on, the Rating raises `Hover` with the value under the pointer:

```razor
<IgbRating HoverPreview="true" Label="Rate this article" Hover="OnHover" />

@code {
    private string Hint { get; set; }

    private void OnHover(IgbNumberEventArgs e)
    {
        Hint = $"{e.Detail} stars";
    }
}
```

</PlatformBlock>

<PlatformBlock for="Angular">

While the preview is on, the Rating emits `igcHover` with the value under the pointer:

```html
<igc-rating hover-preview label="Rate this article" (igcHover)="onHover($event)"></igc-rating>
```

```ts
public hint = '';

public onHover(event: Event) {
    this.hint = `${(event as CustomEvent<number>).detail} stars`;
}
```

</PlatformBlock>

By default, a click on the current value keeps the value. Set `allowReset` to reset the {Platform} Rating to 0 when the user clicks the current value again.

<PlatformBlock for="WebComponents">

```html

```

</PlatformBlock>

<PlatformBlock for="React">

```tsx

```

</PlatformBlock>

<PlatformBlock for="Blazor">

```

</PlatformBlock>

<PlatformBlock for="Angular">

```

</PlatformBlock>

### Layout

The `label` property renders a visible label above the symbols and names the {Platform} Rating for assistive technology. To show custom content next to the symbols, such as the current score, place it in the `value-label` slot:

<PlatformBlock for="WebComponents">

```html
<igc-rating value="4" label="Rate this product">
  <span slot="value-label">4 of 5</span>
</igc-rating>
```

Update the slot content in the `igcChange` handler to keep it in sync with the value.

</PlatformBlock>

<PlatformBlock for="React">

```tsx

  <span slot="value-label">{score} of 5</span>
</IgrRating>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

</PlatformBlock>

```html

</igc-rating>
```

</PlatformBlock>

### Empty/Full State

The `value` of the {Platform} Rating sets how full its symbols are. A value of 0, the default, shows all symbols empty, and a value equal to `max` shows all symbols full.

<PlatformBlock for="WebComponents">

Set the value and the maximum as attributes, and listen for `igcChange` to get the value that the user selects:

```html
<igc-rating value="3" max="10" label="Rate this movie"></igc-rating>
```

```ts
const rating = document.querySelector('igc-rating')!;

rating.addEventListener('igcChange', (event) => {
  console.log(`New rating: ${event.detail}`);
});
```

</PlatformBlock>

<PlatformBlock for="React">

Keep the value in state and update it in the `onChange` handler:

```tsx
import { useState } from 'react';
import { IgrRating } from 'igniteui-react';

export default function MovieRating() {
  const [score, setScore] = useState(3);

  return (
    <IgrRating
      value={score}
      max={10}
      label="Rate this movie"
      onChange={(e: CustomEvent<number>) => setScore(e.detail)}
    />
  );
}
```

</PlatformBlock>

<PlatformBlock for="Blazor">

Bind the value with `@bind-Value`:

```razor
<IgbRating @bind-Value="Score" Max="10" Label="Rate this movie" />

@code {
    private double Score { get; set; } = 3;
}
```

</PlatformBlock>

<PlatformBlock for="Angular">

Bind the value as a property, and update it in the `igcChange` handler:

```html
<igc-rating [value]="score" max="10" label="Rate this movie" (igcChange)="onScoreChange($event)"></igc-rating>
```

```ts
public score = 3;

public onScoreChange(event: Event) {
    this.score = (event as CustomEvent<number>).detail;
}
```

</PlatformBlock>

### Size

.rating-small {

### Forms

The {Platform} Rating is a form-associated element. Inside a `<form>`, it submits its value as text under its `name`.

</PlatformBlock>

<PlatformBlock for="WebComponents">

A form reset restores the value that the `value` attribute sets:

## Accessibility

The {Platform} Rating is a slider: users reach it with the Tab key, change its value with the arrow keys, and hear the value through its ARIA attributes.

### Keyboard Interaction

The {Platform} Rating is a single tab stop, because only the slider element inside it, the `base` part, receives focus. A disabled Rating leaves the tab order. A read-only Rating stays in the tab order but ignores the following keys, so they keep their default browser actions, such as page scrolling.

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moves the focus to the next or the previous focusable element. The Rating doesn't handle these keys, so it never traps the focus. |
| <kbd>Arrow Right</kbd> | Increases the value by one step. In a right-to-left layout, decreases it. |
| <kbd>Arrow Left</kbd> | Decreases the value by one step. In a right-to-left layout, increases it. |
| <kbd>Arrow Up</kbd> | Increases the value by one step. |
| <kbd>Arrow Down</kbd> | Decreases the value by one step. |
| <kbd>Home</kbd> | Sets the value to one step, the lowest value that a click can select. |
| <kbd>End</kbd> | Sets the value to the maximum value. |

The {Platform} Rating handles these keys on `keydown`:

- It prevents their default action, so the arrow keys, Home, and End don't scroll the page while the Rating has focus.
- A key that you hold repeats its action.
- A key that you press together with Shift, Ctrl, Alt, or Meta does nothing.
- The value stays between 0 and the maximum value. A key that would move the value past a bound keeps the value and emits no event.
- Each key that changes the value emits the change event.

With a pointer, a click selects the value under the pointer, rounded up to the next step. A read-only or disabled Rating ignores clicks.

### Screen Readers / ARIA

The {Platform} Rating renders one focusable element with the `slider` role and hides its symbols from assistive technology. The rendered elements carry the following ARIA attributes:

| Element | Attribute | Value |
| --- | --- | --- |
| `base` part | `role` | `slider` |
| `base` part | `tabindex` | `0`, or `-1` when the Rating is disabled |
| `base` part | `aria-valuemin` | `0` |
| `base` part | `aria-valuemax` | The maximum value |
| `base` part | `aria-valuenow` | The value, including fractions such as `4.3` |
| `base` part | `aria-valuetext` | "3 of 5" by default, or the `valueFormat` text, where `{0}` stands for the value and `{1}` for the maximum value |
| `symbols` part | `aria-hidden` | `true` |

<PlatformBlock for="React,WebComponents,Angular">

With `igniteui-webcomponents` 7.4.0 and later, the slider also sets `aria-disabled` and `aria-readonly` to expose the disabled and read-only states. With 7.4.1 and later, the slider takes its accessible name from the first of the following:

1. The `aria-labelledby` attribute of the host.
2. A `<label>` element that is bound through `for`, or that wraps the Rating. A click on the label focuses the slider.
3. The `label` property, which renders a visible label that the slider references through `aria-labelledby`.
4. The `aria-label` attribute of the host. The slider ignores it when the `label` property is set.

</PlatformBlock>

<PlatformBlock for="Blazor">

The `Label` property renders a visible label that the slider references through `aria-labelledby`, which gives the slider its accessible name.

</PlatformBlock>

The {Platform} Rating also behaves as follows for assistive technology:

- The symbols, including projected icons and emoji, are hidden, so they don't need text alternatives. The value reaches assistive technology only through `aria-valuenow` and `aria-valuetext`.
- The `value-label` slot renders inside the slider. Screen readers read the value from `aria-valuetext`, so describe the value with `valueFormat` rather than with the slot content.
- The Rating doesn't use a live region. A changed value reaches assistive technology only through the slider attributes.
- The Rating doesn't set `aria-invalid`, so a custom validation message isn't exposed as an invalid state.

### Accessibility Compliance

Infragistics documents {ProductName} accessibility support for Section 508 and WCAG 2.1 guideline areas in the [Accessibility Compliance](../interactivity/accessibility-compliance.mdx) topic.

| Criterion | How the component complies |
| --- | --- |
| [1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG21/Understanding/non-text-content) | The symbols are hidden from assistive technology, and the slider exposes the value as text through `aria-valuetext`. |
| [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships) | The visible label of the `label` property is associated with the slider through `aria-labelledby`. |
| [1.4.1 Use of Color](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color) | The default symbols show a filled star for the selected part of the scale and an outlined star for the rest, so the value doesn't depend on color alone. |
| [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | The arrow keys, Home, and End change the value, so users can rate without a pointer. |
| [2.1.2 No Keyboard Trap](https://www.w3.org/WAI/WCAG21/Understanding/no-keyboard-trap) | The Rating is a single tab stop and doesn't handle the Tab key, so Tab and Shift + Tab move the focus out of it. |
| [2.4.7 Focus Visible](https://www.w3.org/WAI/WCAG21/Understanding/focus-visible) | The Rating themes don't remove the browser focus indicator from the focused slider. |
| [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | The slider exposes the `slider` role, its value through `aria-valuenow` and `aria-valuetext`, and the name that you provide.<PlatformBlock for="React,WebComponents,Angular"> With `igniteui-webcomponents` 7.4.0 and later, it also exposes the disabled and read-only states.</PlatformBlock> |

Your responsibilities:

- Name every Rating with the `label` property<PlatformBlock for="React,WebComponents,Angular">, an associated `<label>` element, or `aria-label`</PlatformBlock>. See [Layout](#layout).
- Set `valueFormat` when "3 of 5" doesn't describe the scale, or when the page uses another language.
- With custom symbols, make the full and the empty symbols differ in shape or fill, not only in color, and keep a contrast ratio of at least 3:1 against the background, as [1.4.11 Non-text Contrast](https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast) requires.
- When you restyle the `base` part, keep a visible focus indicator.
- Keep the pointer targets large enough. Each value is a target as wide as one symbol, or half a symbol with a step of 0.5. The small size renders 18px symbols, below the 24 by 24 CSS pixels of [2.5.8 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum), so prefer the medium or the large size for pointer and touch input.
- Don't put information only in the hover preview, because keyboard users don't see it.
- When you validate the rating with a custom validation message, also show the message as text next to the Rating, as [3.3.1 Error Identification](https://www.w3.org/WAI/WCAG21/Understanding/error-identification) requires, because the Rating doesn't set `aria-invalid`.

Differences from the [WAI-ARIA slider pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider/):

- <kbd>Home</kbd> sets the value to one step instead of to `aria-valuemin`, which is 0. Use <kbd>Arrow Down</kbd> to reach 0.
- The Rating doesn't support <kbd>Page Up</kbd> and <kbd>Page Down</kbd>, which the pattern lists as optional keys.

## Troubleshooting

Use these answers when a {Platform} Rating doesn't behave as expected.

### Why doesn't the change event fire when I set the value?

The {Platform} Rating emits the change event only for user input: a click or a key. Setting the value in code, or calling the step methods, changes the value without the event, so update your own state where you set the value.

### Why doesn't a click on the current value reset the rating?

The {Platform} Rating keeps the value on a click on the current value, unless you set `allowReset`. Before `igniteui-webcomponents` 4.7.0, a click on the current value always reset the rating; set `allowReset` to keep that behavior after an upgrade.

### Why doesn't the hover event fire?

The {Platform} Rating emits the hover event only while `hoverPreview` is on, and not when the Rating is read-only or disabled. Set `hoverPreview` to receive the event.

### Known Limitations

The {Platform} Rating has the following limitations:

- The scale always starts at 0. The Rating has no property for another minimum.
- The Rating has no `required` validation. To require a score, check that the value is greater than 0 before you submit the data.
- In single selection, the step is always 1.
- The Rating has no invalid styles of its own, and it doesn't set `aria-invalid`.

## FAQ

These questions cover common {Platform} Rating setup, accessibility, and usage scenarios.

<Faq>
  <FaqItem question="Can users select half stars?" indicatorPosition="end">
    Yes. Set the `step` property of the {Platform} Rating to `0.5`, and a click on the left half of a star selects the half value in a left-to-right layout. The arrow keys then change the value of the {Platform} Rating in steps of 0.5.
  </FaqItem>
  <FaqItem question="How do I show an average rating that users can't change?" indicatorPosition="end">
    Set the `readOnly` property of the {Platform} Rating and set its value to the average, such as 4.3. The {Platform} Rating fills the symbols in part for a fractional value, stays focusable, and ignores clicks and keys.
  </FaqItem>
  <FaqItem question="Is the Rating accessible to keyboard and screen reader users?" indicatorPosition="end">
    Yes. The {Platform} Rating is a single tab stop with the `slider` role, the arrow keys, Home, and End change its value, and screen readers read the value through `aria-valuetext`. Give the {Platform} Rating an accessible name with the `label` property or `aria-label`, and set `valueFormat` to describe the value in words.
  </FaqItem>
  <FaqItem question="Does the Rating work with forms?" indicatorPosition="end">
    <PlatformBlock for="Angular">Yes. Import the `IgcFormControlDirective` from `igniteui-angular/directives` to bind the Angular Rating with `ngModel` or `formControlName`. The directive updates the model when the user changes the value and disables the Rating when you disable the form control.</PlatformBlock><PlatformBlock for="React,WebComponents">Yes. The {Platform} Rating is a form-associated element, so a `<form>` submits its value under its `name`. A disabled `<fieldset>` also disables the {Platform} Rating.</PlatformBlock><PlatformBlock for="Blazor">Yes. Place the Blazor Rating in a Blazor `EditForm` and bind its value to a property of your model with `@bind-Value`. The binding updates the model through the `ValueChanged` event when the user changes the value.</PlatformBlock>
  </FaqItem>
</Faq>
