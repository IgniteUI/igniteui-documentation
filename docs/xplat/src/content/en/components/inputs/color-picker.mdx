# Color Picker Component <Badge variant="new" />

The {ProductName} Color Picker is a form-associated component that lets users pick and edit a color through an interactive dropdown with a gradient canvas, hue and alpha sliders, format switching, an eye-dropper, and predefined swatches.

The {Platform} Color Picker is composed of an anchor that opens a popover dropdown containing the picker surface — a gradient canvas, hue and alpha sliders, format-aware color inputs, action buttons, and an optional swatch grid.

## Usage

Use the {Platform} Color Picker to let users pick and edit a color through an interactive dropdown. Assign any valid CSS color string (hex, rgb/rgba, hsl/hsla, or a named color) to the <ApiLink pkg="core" type="ColorPicker" member="value" label="value" /> property to set the initial color. An empty or invalid string clears the value and renders a checkered pattern on the anchor.

```

The <ApiLink pkg="core" type="ColorPicker" member="mode" label="mode" /> property controls the anchor presentation. ### Swatches

Provide a list of predefined colors through the <ApiLink pkg="core" type="ColorPicker" member="swatches" label="swatches" /> property. When set, the picker renders a swatch grid below the color inputs. Clicking a swatch applies it as the current color.

### Eye-Dropper and Copy to Clipboard

The picker dropdown includes two built-in actions which are always available:

- **Copy to clipboard** – copies the current color value to the clipboard.
- **Eye-dropper** – lets users pick a color from anywhere on the screen.

### Validation

Mark the control as <ApiLink pkg="core" type="ColorPicker" member="required" label="required" /> to fail form validation when no color is selected. The component supports the standard form-associated API — <ApiLink pkg="core" type="ColorPicker" member="checkValidity" label="checkValidity" />, <ApiLink pkg="core" type="ColorPicker" member="reportValidity" label="reportValidity" />, and <ApiLink pkg="core" type="ColorPicker" member="setCustomValidity" label="setCustomValidity" />.

You can use also use helper and validation messages under the anchor through the exposed slots:

- `helper-text` – Displays a hint or instructional message below the anchor.
- `value-missing` – Renders custom content when the required field validation fails.
- `invalid` – Renders custom content when the component is in an invalid state.
- `custom-error` – Displays content when a custom validation message is set using <ApiLink pkg="core" type="ColorPicker" member="setCustomValidity" label="setCustomValidity()" />.

```

### Do/Don't

Use the <ApiLink pkg="core" type="ColorPicker" /> when users need to enter or edit an arbitrary color through a visual editor and the value must participate in form submission and validation. Always provide a clear label so the anchor is identifiable, and prefer the Input type when the picker is placed alongside other form fields.

## Troubleshooting

The {Platform} Color Picker troubleshooting guidance follows a problem → cause → fix format for common integration and platform issues.

### Why is the eye-dropper button disabled?

The eye-dropper button is only enabled when the browser implements the [`EyeDropper`](https://developer.mozilla.org/en-US/docs/Web/API/EyeDropper) API. Support is captured once at construction time, so injecting the API after the component is created has no effect. Users on browsers without native support should use the gradient canvas or swatches instead.

### Why does clicking the copy button do nothing?

The copy action depends on the `navigator.clipboard.writeText` API and a secure context (HTTPS or `localhost`). It silently no-ops when the API is unavailable, when the site is loaded over an insecure origin, or when the browser denies the clipboard permission.

### Why did an invalid color string clear my value?

Assigning an empty, whitespace-only, or invalid string to `value` clears the color instead of reverting to the previous value. Non-hex/rgb/hsl strings are resolved through an `OffscreenCanvas` 2D context; environments without canvas support resolve to the empty value rather than a fallback color.

### Why is the emitted value in a different format than what I typed?

The externally observable value is always normalized to the active `format`. Round-tripping an input string is not guaranteed to be byte-for-byte identical — for example, typing `red` with `format="hex"` re-serializes to `#ff0000`.

## Known Limitations

The {Platform} Color Picker has the following platform-independent limitations.

- The eye-dropper button is always rendered but only enabled when the browser implements the `EyeDropper` API; support is captured once at construction time.
- Copying to the clipboard depends on `navigator.clipboard` and a secure context; it silently no-ops where unavailable or denied.
- The externally observable `value` is always normalized to the active `format`; the input string is not guaranteed to round-trip byte-for-byte.
- Static UI labels (`Hue`, `Alpha slider`, `Open color picker`, `Copy color value to clipboard`, `Pick a color from the screen`) are accessibility-only and are not currently localized.

  <FaqItem question="How do I bind the Color Picker to a form?" indicatorPosition="end">

  <FaqItem question="Which color formats does the Color Picker accept?" indicatorPosition="end">
    The `value` property accepts any valid CSS color string, including hex, `rgb`/`rgba`, `hsl`/`hsla`, and named colors. The externally observable serialized value is normalized to the active `format` (`hex`, `rgb`, or `hsl`).

  <FaqItem question="Does the eye-dropper work in every browser?" indicatorPosition="end">
    No. The eye-dropper depends on the browser [`EyeDropper`](https://developer.mozilla.org/en-US/docs/Web/API/EyeDropper) API and is only enabled where that API is available. In other browsers the button renders disabled and users must pick a color through the gradient canvas, sliders, or swatches.
  </FaqItem>

  <FaqItem question="How is `igcInput` different from `igcChange`?" indicatorPosition="end">
    `igcInput` fires on every interim interaction — dragging the canvas or sliders, typing, selecting a swatch, or picking through the eye-dropper. `igcChange` fires once when the committed value has changed and focus leaves the component entirely, matching the semantics of the native `change` event on form controls.
  </FaqItem>

  </FaqItem>
