# Combo

The {ProductName} Combo is a component that combines an input field with a searchable dropdown list, letting users filter the options by typing and select one or more items.

<PlatformBlock for="Angular">

The Angular Combo is the `igx-combo` component. It shows its options in a virtualized dropdown list and supports filtering, grouping, custom values, and two-way binding with Angular forms.

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

The Combo shows its options in a virtualized list, so the list can hold thousands of options. The Combo supports case-sensitive filtering, grouping, and binding to complex data.

</PlatformBlock>

The `igc-combo` element renders its input field and its dropdown list in a popover, and the helper text below them:

```text
igc-combo
└─ #shadow-root
   ├─ igc-popover
   │  ├─ igc-input#target[slot="anchor"]            // the input field, exported as the "input" part
   │  │  ├─ slot[name="prefix"]
   │  │  ├─ span[part="clear-icon"]                  // shown when the Combo has a value
   │  │  ├─ slot[name="suffix"]
   │  │  └─ span[part="toggle-icon"]
   │  └─ div[part="list-wrapper"]                    // the dropdown
   │     ├─ div[part="filter-input"]
   │     │  └─ igc-input[part="search-input"]        // hidden with disable-filtering or single-select
   │     ├─ div[part="header"]
   │     │  └─ slot[name="header"]
   │     ├─ igc-virtual-scroll#dropdown[part="list"][role="listbox"]
   │     │  ├─ igc-combo-header[part="group-header"] // one for each group
   │     │  └─ igc-combo-item[part="item"]           // one for each option
   │     ├─ div[part="empty"]                        // shown when the list has no options
   │     │  └─ slot[name="empty"]
   │     └─ div[part="footer"]
   │        └─ slot[name="footer"]
   └─ igc-validator[part="helper-text"]              // the helper text and the validation messages
```

## Usage

Use the {Platform} Combo when users pick one or more options from a long list and need to search it, such as a list of cities or countries.

### Type (Material Theme)

In the Material theme, the Combo Input provides selection between a border type for a more structured perception on solid color backgrounds, and a boxed type that is most appropriate when placed on top of a vivid image to improve readability. The Bootstrap, Fluent, and Indigo themes draw both types the same way, so the other samples of this topic show the box type only in the Material theme.

<PlatformBlock for="React,WebComponents,Blazor">

The {Platform} Combo uses the box type by default. Set `outlined` for the border type:

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<!-- Border type -->
<igc-combo outlined label="Label" placeholder="Select a value"></igc-combo>

<!-- Box type -->
<igc-combo label="Label" placeholder="Select a value"></igc-combo>
```

</PlatformBlock>

### Validation States

Every experienced designer uses constraints wisely to limit the user input and avoid invalid states, hence the availability of validation styles. The sample styles the success state with a CSS class, and shows the warn state as an invalid Combo that takes the warning color of the theme in place of the error color.

### Data Binding

The {Platform} Combo builds its list of options from the array that you bind to `data`. When the array holds objects, set the keys that the Combo uses:

<PlatformBlock for="React,WebComponents">

- <ApiLink type="Combo" member="valueKey" label="valueKey" /> - the field that identifies an option. The value and the selection API of the Combo use it. When you omit it, the Combo uses references to the objects.
- <ApiLink type="Combo" member="displayKey" label="displayKey" /> - the field that the list and the input field show. When you omit it, the Combo uses the `valueKey`.
- <ApiLink type="Combo" member="groupKey" label="groupKey" /> - the field that groups the options. Each group gets a header, and <ApiLink type="Combo" member="groupSorting" label="groupSorting" /> sorts the groups in ascending or descending order.

</PlatformBlock>

<PlatformBlock for="Blazor">

- <ApiLink pkg="core" type="Combo<T>" member="ValueKey" label="ValueKey" /> - the field that identifies an option. The value and the selection API of the Combo use it. When you omit it, the Combo uses references to the objects.
- <ApiLink pkg="core" type="Combo<T>" member="DisplayKey" label="DisplayKey" /> - the field that the list and the input field show. When you omit it, the Combo uses the `ValueKey`.
- <ApiLink pkg="core" type="Combo<T>" member="GroupKey" label="GroupKey" /> - the field that groups the options. Each group gets a header, and <ApiLink pkg="core" type="Combo<T>" member="GroupSorting" label="GroupSorting" /> sorts the groups in ascending or descending order.

The `T` type parameter of the Blazor Combo is the type of its values. Set it to the type of the `ValueKey` field, or to the type of the options when you don't set a `ValueKey`. When you bind the `Value` with `@bind-Value`, Razor infers `T` from the bound field.

</PlatformBlock>

<PlatformBlock for="Angular">

- <ApiLink type="Combo" member="valueKey" label="valueKey" /> - the field that identifies an option. The value and the selection of the Combo use it. When you omit it, the Combo uses references to the objects.
- <ApiLink type="Combo" member="displayKey" label="displayKey" /> - the field that the list and the input field show. When you omit it, the Combo uses the `valueKey`.
- <ApiLink type="Combo" member="groupKey" label="groupKey" /> - the field that groups the options. Each group gets a header, and <ApiLink type="Combo" member="groupSortingDirection" label="groupSortingDirection" /> sorts the groups.

To bind to data that loads from a remote service, see the [Remote Binding](../../combo-remote.mdx) topic.

</PlatformBlock>

When the array holds primitive values, such as strings or numbers, don't set the `valueKey` and the `displayKey`. The Combo uses the values themselves.

### Value and Selection

The {Platform} Combo exposes its selected items through its value, and methods that select and deselect items in code.

<PlatformBlock for="React,WebComponents,Blazor">

The `value` holds the selected items as their `valueKey` values, or as object references when there is no `valueKey`. Set it to select items when the Combo first renders. The `select` and `deselect` methods take an array of items; with an empty array, they select or deselect all items:

</PlatformBlock>

<PlatformBlock for="WebComponents">

```ts
// select and deselect items by their ids, because the valueKey is 'id'
combo.select(['BG01', 'BG02']);
combo.deselect(['BG01']);

// select and deselect all items
combo.select();
combo.deselect();

console.log(combo.value); // the ids of the selected items
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx

comboRef.current?.select(['BG01', 'BG02']);
comboRef.current?.deselect(['BG01']);

// select and deselect all items
comboRef.current?.select([]);
comboRef.current?.deselect([]);

console.log(comboRef.current?.value); // the ids of the selected items
```

</PlatformBlock>

</PlatformBlock>

### Do/Don't

When using the Combo, its input and dropdown should have the same width and their left and right borders should match. Regarding how the dropdown is shown when the Combo is focused, you should always show it on top of the content that follows the Combo triggering its display. Combos don't push content like expansion panels do.

<DoDont
  doSrc={comboDoAlignment}
  doAlt="An open Country combo whose dropdown has the same width as its input and covers the fields below it"
  dontSrc={comboDoNotAlignment}
  dontAlt="An open Country combo whose dropdown is narrower than its input and shifted to the right"
>
<Fragment slot="do">

Align the dropdown with the input so both have the same width and matching left and right borders.

</Fragment>
<Fragment slot="dont">

Avoid a dropdown that is narrower than the input or shifted out of alignment, as it breaks the visual connection between the two.

</Fragment>
</DoDont>

### Sass Theming

When you modify a primary property, all related dependent properties are automatically updated to reflect the change. The primary parameter of the <PlatformBlock for="Angular"><ApiLink kind="sass" module="themes" type="function-combo-theme" label="combo-theme" code={true} /></PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">`combo-theme`</PlatformBlock> function is `$toggle-button-background`, from which the theme derives the colors of the toggle button in all states. Create the themes of the Combo, its dropdown, and its checkboxes, and include them with the `tokens()` mixin, which emits the matching CSS variables in the scope where you include it.

```scss
$custom-drop-down-theme: drop-down-theme(
  $background-color: #e6f2ff
);

$custom-checkbox-theme: checkbox-theme(
  $fill-color: #005dcc,
  $empty-color: #005dcc
);

:host {
  @include tokens($custom-combo-theme);
  @include tokens($custom-drop-down-theme);
  @include tokens($custom-checkbox-theme);
}
```

## Accessibility

The {Platform} Combo uses the roles of the WAI-ARIA combobox pattern: the input field is a `combobox` that controls a `listbox` of options, and users open the list, move through it, and select options with the keyboard.

### Keyboard Interaction

<PlatformBlock for="React,WebComponents,Blazor">

The input field of the {Platform} Combo is a tab stop. When the dropdown opens, the search input takes the focus, or the list when `autofocusList` is set or the search input is hidden. In the single selection mode, the focus stays in the input field. The following keys work while the Combo has the focus:

| Key | Action |
| --- | --- |
| <kbd>Arrow Down</kbd> | In the input field, opens the dropdown, and in the single selection mode also moves the focus to the list and activates the first option. In the search input, moves the focus to the list and activates the first option. In the list, activates the next option. |
| <kbd>Alt</kbd> + <kbd>Arrow Down</kbd> | In the input field, does the same as <kbd>Arrow Down</kbd>. |
| <kbd>Arrow Up</kbd> | In the input field, closes the dropdown. In the search input, closes the dropdown and moves the focus to the input field. In the list, activates the previous option. From the first option, moves the focus to the search input, or closes the dropdown and moves the focus to the input field when the search input is hidden. |
| <kbd>Home</kbd> / <kbd>End</kbd> | In the list, activates the first or the last option. |
| <kbd>Space</kbd> | In the list, selects or deselects the active option. |
| <kbd>Enter</kbd> | With an active option, closes the dropdown and moves the focus to the input field. In the single selection mode, also selects the active option. |
| <kbd>Escape</kbd> | When the dropdown is open, closes it and moves the focus to the input field. When the dropdown is closed, clears the selection. |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Closes the dropdown and moves the focus to the next or the previous focusable element. In the single selection mode, also selects the active option. |

A disabled Combo ignores these keys.

</PlatformBlock>

<PlatformBlock for="Angular">

The input field of the Angular Combo is a tab stop. The following keys work while the Combo has the focus:

| Key | Action |
| --- | --- |
| <kbd>Arrow Down</kbd> / <kbd>Alt</kbd> + <kbd>Arrow Down</kbd> | In the closed Combo, opens the dropdown and moves the focus to the search input. In the search input, moves the focus to the first option, or to the add item button when the list is empty and custom values are allowed. In the list, moves to the next option, and from the last option to the add item button when it is shown. |
| <kbd>Arrow Up</kbd> / <kbd>Alt</kbd> + <kbd>Arrow Up</kbd> | In the search input, closes the dropdown and moves the focus to the Combo. In the list, moves to the previous option. From the first option, moves the focus back to the search input, or closes the dropdown and moves the focus to the Combo when there is no search input. |
| <kbd>Home</kbd> / <kbd>End</kbd> | In the list, moves to the first or the last option. |
| <kbd>Space</kbd> | In the list, selects or deselects the active option. |
| <kbd>Enter</kbd> | In the list, confirms the selection and closes the dropdown. On the add item button, adds the text of the search input as a new item and selects it. |
| <kbd>Escape</kbd> | When the dropdown is open, closes it and keeps the focus on the Combo. When the dropdown is closed, clears the selection. |
| <kbd>Tab</kbd> | Closes the dropdown and moves the focus to the next focusable element. |

</PlatformBlock>

### Screen Readers / ARIA

<PlatformBlock for="React,WebComponents,Blazor">

The {Platform} Combo renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| The input field | `combobox` | `aria-haspopup="listbox"`, `aria-expanded`, `aria-disabled`, `aria-controls` that points to the list, and, with a helper text, `aria-describedby` that points to it |
| The `list` part | `listbox` | `aria-multiselectable` (`false` in the single selection mode), `aria-labelledby` that points to the input field, and `aria-activedescendant` that points to the active option |
| Each `item` part | `option` | `aria-selected`, `aria-posinset`, and `aria-setsize` |
| The `clear-icon` part | `button` | `aria-label` from the resource strings |

The {Platform} Combo also behaves as follows for assistive technology:

- The input field takes its accessible name from the `label`. Without a label, it gets a name from the resource strings that says whether options are selected.
- The active option is announced through `aria-activedescendant` while the focus stays in the list.
- The content of the closed dropdown is `inert`.

</PlatformBlock>

<PlatformBlock for="Angular">

The Angular Combo renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| The input of the input field | `combobox` | `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls` that points to the list, `aria-labelledby`, and `aria-label` |
| The search input | `searchbox` | `aria-autocomplete="list"` and `aria-label="search"` |
| The dropdown | `listbox` | `aria-labelledby` that points to the `igxLabel` or to the `ariaLabelledBy` element |
| The container of the options | — | `aria-multiselectable="true"` and `aria-activedescendant` that points to the active option |
| Each option | `option` | `aria-selected` |
| Each group header | `group` | — |
| The add item button | `button` | `aria-label` from the resource strings |

The input field takes its accessible name from the `igxLabel` or from the <ApiLink type="Combo" member="ariaLabelledBy" label="ariaLabelledBy" /> input. Without them, it gets a name from the resource strings that says whether options are selected.

</PlatformBlock>

Infragistics documents {ProductName} accessibility support for Section 508 and WCAG 2.1 guideline areas in the [Accessibility Compliance](../../interactivity/accessibility-compliance.mdx) topic.

| --- | --- |

## Known Limitations

- The input field that shows the selected items isn't editable. In Firefox, the cursor is visible in it.
- When the Angular Combo is bound to an array of primitives that contains `undefined`, the list doesn't show `undefined`. When the `valueKey` field of an object is `undefined`, the list shows the item, but users can't select it.
- When the Angular Combo is bound to a remote service and has a predefined selection, the input field stays blank until the data loads.
- The list uses the [Virtual Scroll](../../layouts/virtual-scroll.mdx#known-limitations), so its limitations apply. The list renders only the options in view, and code that queries the DOM finds only those options.

</PlatformBlock>
