# Tooltip

The {ProductName} Tooltip is a component that shows supplementary information about an element in a small popup next to it while the user interacts with that element, for example while hovering over it.

<PlatformBlock for="Angular">

The Angular Tooltip is a pair of directives. The `igxTooltip` directive marks the element that holds the information, and the `igxTooltipTarget` directive marks the element that the tooltip describes and shows the tooltip when the user hovers over that element.

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

The Tooltip attaches to an anchor element through its `anchor` property, shows the text or the content that you place in it, and positions itself next to the anchor.

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

The `igc-tooltip` element renders a popover with a container for the content, the close button, and the arrow:

```text
igc-tooltip                                   // role="tooltip", or role="status" when sticky
└─ #shadow-root
   └─ igc-popover                             // positions the tooltip next to the anchor
      └─ div[part="base"]                     // part="base simple-text" when the message property is shown
         ├─ slot                              // the content of the tooltip, falls back to the message property
         ├─ slot[name="close-button"]         // rendered only when the tooltip is sticky
         └─ div#arrow[part="bottom"]          // rendered only with the arrow, the part follows the placement
```

</PlatformBlock>

<PlatformBlock for="Angular">

While the Angular Tooltip is open, the overlay moves the element with the `igxTooltip` directive into a wrapper at its place in the DOM, in the top layer of the page:

```text
div.igx-overlay__wrapper[popover="manual"]
└─ div.igx-overlay__content
   └─ [igxTooltip].igx-tooltip                // role="tooltip", or role="status" when sticky
      ├─ your content
      ├─ span.igx-tooltip--bottom[data-arrow] // hidden unless hasArrow is set, the class follows the placement
      └─ igx-tooltip-close-button             // rendered only when the tooltip is sticky
```

While the tooltip is closed, the element stays in place with the `igx-tooltip--hidden` class and `aria-hidden="true"`.

</PlatformBlock>



</PlatformBlock>

<PlatformBlock for="Angular">

If your project doesn't use {ProductName} yet, run `ng add igniteui-angular`. Then import the `IGX_TOOLTIP_DIRECTIVES` token and add it to the `imports` of your component. The token holds the <ApiLink type="TooltipDirective" label="igxTooltip" /> and the <ApiLink type="TooltipTargetDirective" label="igxTooltipTarget" /> directives. The example below also imports the `IgxButtonDirective` for the target:

```ts
import { Component } from '@angular/core';
import { IGX_TOOLTIP_DIRECTIVES, IgxButtonDirective } from 'igniteui-angular/directives';
// import { IGX_TOOLTIP_DIRECTIVES, IgxButtonDirective } from '@infragistics/igniteui-angular/directives'; for licensed package

@Component({
    selector: 'app-home',
    template: `
        <button igxButton="outlined" [igxTooltipTarget]="saveTooltip">Save</button>
        <span #saveTooltip="tooltip" igxTooltip>Save the changes to the server</span>
    `,
    imports: [IGX_TOOLTIP_DIRECTIVES, IgxButtonDirective]
})
export class HomeComponent {}
```

The `igxTooltip` directive is exported as `tooltip`, so the `#saveTooltip="tooltip"` template reference variable holds the directive, and the `igxTooltipTarget` directive of the button shows it.

</PlatformBlock>

## Usage

Use the {Platform} Tooltip to show additional information that describes another component or its purpose in the user interface in a transient way. It becomes visible upon user interaction and may disappear after certain time or upon user interaction.

### Variants

Depending on the elements they display the Tooltip can be any of the following types:

- Tooltip with Arrow and no Close Button
- Tooltip with Arrow and Close Button
- Tooltip with no Arrow and no Close Button
- Tooltip with no Arrow and Close Button

<PlatformBlock for="React,WebComponents,Blazor">

Set <ApiLink pkg="core" type="Tooltip" member="withArrow" label="withArrow" /> to show the arrow. Set <ApiLink pkg="core" type="Tooltip" member="sticky" label="sticky" /> to show the close button: a sticky tooltip ignores the hide triggers, such as the pointer leaving the anchor, and stays open until the user clicks the close button or presses Escape:

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-tooltip anchor="arrow-target" with-arrow>Tooltip message</igc-tooltip>
<igc-tooltip anchor="sticky-target" with-arrow sticky>Tooltip message</igc-tooltip>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrTooltip anchor="arrow-target" withArrow={true}>Tooltip message</IgrTooltip>
<IgrTooltip anchor="sticky-target" withArrow={true} sticky={true}>Tooltip message</IgrTooltip>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbTooltip Anchor="arrow-target" WithArrow="true">Tooltip message</IgbTooltip>
<IgbTooltip Anchor="sticky-target" WithArrow="true" Sticky="true">Tooltip message</IgbTooltip>
```

</PlatformBlock>

### Position

Depending on the position according to its target the Tooltip can be any of the following types:

- Top: The Tooltip shows above the target.
- Right: The Tooltip shows to the right of the target.
- Left: The Tooltip shows to the left of the target.
- Bottom: The Tooltip shows below the target.

<PlatformBlock for="React,WebComponents,Blazor">

Set <ApiLink pkg="core" type="Tooltip" member="placement" label="placement" /> to position the tooltip. The default is `bottom`. Each of the `top`, `right`, `bottom`, and `left` values also has a `-start` and an `-end` variant, which aligns the tooltip with the start or the end of the anchor. When the tooltip doesn't fit on the chosen side, it flips to the opposite side. Set <ApiLink pkg="core" type="Tooltip" member="offset" label="offset" /> to change the distance between the tooltip and the anchor, which is `6` pixels by default:

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-tooltip anchor="target" placement="top">Tooltip message Top</igc-tooltip>
<igc-tooltip anchor="target" placement="right-start" offset="12">Tooltip message Right</igc-tooltip>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrTooltip anchor="target" placement="top">Tooltip message Top</IgrTooltip>
<IgrTooltip anchor="target" placement="right-start" offset={12}>Tooltip message Right</IgrTooltip>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbTooltip Anchor="target" Placement="PopoverPlacement.Top">Tooltip message Top</IgbTooltip>
<IgbTooltip Anchor="target" Placement="PopoverPlacement.RightStart" Offset="12">Tooltip message Right</IgbTooltip>
```

</PlatformBlock>

<PlatformBlock for="Angular">

By default, the Angular Tooltip opens below the target, centered, at a distance of `6` pixels. Set <ApiLink type="TooltipTargetDirective" member="positionSettings" label="positionSettings" /> on the target to change the position. The tooltip merges the settings that you pass with its defaults, and it flips to the opposite side when it doesn't fit on the chosen side:

```ts
import { HorizontalAlignment, PositionSettings, VerticalAlignment } from 'igniteui-angular/core';

public topPosition: PositionSettings = {
    horizontalDirection: HorizontalAlignment.Center,
    horizontalStartPoint: HorizontalAlignment.Center,
    verticalDirection: VerticalAlignment.Top,
    verticalStartPoint: VerticalAlignment.Top
};
```

```html
<igx-icon [igxTooltipTarget]="topTooltip" [positionSettings]="topPosition">info</igx-icon>
<span #topTooltip="tooltip" igxTooltip>Tooltip message Top</span>
```

The [Arrow Position](#arrow-position) section lists the settings for each predefined position.

</PlatformBlock>

### Arrow Position

Depending on the position according to its target the Tooltip Arrow can be any of the following types:

<PlatformBlock for="React,WebComponents,Blazor">

The arrow of the {Platform} Tooltip follows the `placement`. For `top`, `right`, `bottom`, and `left`, the arrow points to the center of the anchor. For the `-start` and the `-end` placements, the arrow moves toward the start or the end of the tooltip. When the tooltip flips to the opposite side, the arrow moves with it:

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-tooltip anchor="target" placement="bottom-start" with-arrow>
  This is a tooltip message. This tooltip shows a long message.
</igc-tooltip>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrTooltip anchor="target" placement="bottom-start" withArrow={true}>
  This is a tooltip message. This tooltip shows a long message.
</IgrTooltip>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbTooltip Anchor="target" Placement="PopoverPlacement.BottomStart" WithArrow="true">
    This is a tooltip message. This tooltip shows a long message.
</IgbTooltip>
```

</PlatformBlock>

<PlatformBlock for="Angular">

The Angular Tooltip positions the arrow from the `positionSettings` of the target. The arrow matches one of the following predefined positions, which the table lists with their `horizontalDirection`, `horizontalStartPoint`, `verticalDirection`, and `verticalStartPoint` values. When the settings don't match any of them, the arrow stays at the top center of the tooltip, as for the default `bottom` position:

| Position | Horizontal | Horizontal start | Vertical | Vertical start |
| --- | --- | --- | --- | --- |
| top | `Center` | `Center` | `Top` | `Top` |
| top-start | `Right` | `Left` | `Top` | `Top` |
| top-end | `Left` | `Right` | `Top` | `Top` |
| bottom | `Center` | `Center` | `Bottom` | `Bottom` |
| bottom-start | `Right` | `Left` | `Bottom` | `Bottom` |
| bottom-end | `Left` | `Right` | `Bottom` | `Bottom` |
| right | `Right` | `Right` | `Middle` | `Middle` |
| right-start | `Right` | `Right` | `Bottom` | `Top` |
| right-end | `Right` | `Right` | `Top` | `Bottom` |
| left | `Left` | `Left` | `Middle` | `Middle` |
| left-start | `Left` | `Left` | `Bottom` | `Top` |
| left-end | `Left` | `Left` | `Top` | `Bottom` |

The horizontal values come from `HorizontalAlignment`, and the vertical values come from `VerticalAlignment`. The arrow works only with the <ApiLink type="TooltipPositionStrategy" />, so a `positionStrategy` that you pass in the `overlaySettings` must extend it. To place the arrow yourself, extend the `TooltipPositionStrategy` and override its `positionArrow` method, which receives the arrow element and an `ArrowFit` object with the direction of the arrow and the sizes of the arrow and the tooltip:

```ts
import { ArrowFit, TooltipPositionStrategy } from 'igniteui-angular/directives';
import { HorizontalAlignment, OverlaySettings, PositionSettings, VerticalAlignment } from 'igniteui-angular/core';

export class CustomArrowStrategy extends TooltipPositionStrategy {
    constructor(settings?: PositionSettings) {
        super(settings);
    }

    public override positionArrow(arrow: HTMLElement, arrowFit: ArrowFit): void {
        Object.assign(arrow.style, {
            left: '-0.25rem',
            transform: 'rotate(-45deg)',
            [arrowFit.direction!]: '-0.25rem'
        });
    }
}

public overlaySettings: OverlaySettings = {
    positionStrategy: new CustomArrowStrategy({
        horizontalDirection: HorizontalAlignment.Right,
        horizontalStartPoint: HorizontalAlignment.Right,
        verticalDirection: VerticalAlignment.Bottom,
        verticalStartPoint: VerticalAlignment.Bottom
    })
};
```

```html
<igx-icon [igxTooltipTarget]="customTooltip" [hasArrow]="true" [overlaySettings]="overlaySettings">info</igx-icon>
<span #customTooltip="tooltip" igxTooltip>Tooltip message</span>
```

</PlatformBlock>

### Target

<PlatformBlock for="React,WebComponents,Blazor">

The <ApiLink pkg="core" type="Tooltip" member="anchor" label="anchor" /> property of the {Platform} Tooltip sets the element that the tooltip describes. Set it to the `id` of an element in the same DOM root as the tooltip. The tooltip listens for its triggers on that element and positions itself next to it. The tooltip looks up the `id` when it connects to the page and when `anchor` changes, so for an anchor that renders after the tooltip, set `anchor` again once the anchor is in the page.

</PlatformBlock>

<PlatformBlock for="React,WebComponents">

When the anchor is in another DOM root, such as the shadow root of another component, set `anchor` to the element itself:

</PlatformBlock>

<PlatformBlock for="WebComponents">

```ts
const tooltip = document.querySelector('igc-tooltip') as IgcTooltipComponent;
tooltip.anchor = document.querySelector('#save-button')!;
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
const tooltipRef = useRef<IgrTooltip>(null);
const buttonRef = useRef<IgrButton>(null);

useEffect(() => {
  tooltipRef.current!.anchor = buttonRef.current!;
}, []);

<IgrButton ref={buttonRef}>Save</IgrButton>
<IgrTooltip ref={tooltipRef}>Save the changes to the server</IgrTooltip>
```

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

To show one tooltip for several elements, pass the element to the `show` method, as described in [Showing and Hiding in Code](#showing-and-hiding-in-code). The element stays the anchor until the tooltip hides, and then the tooltip returns to its `anchor`.

</PlatformBlock>

<PlatformBlock for="Angular">

The <ApiLink type="TooltipTargetDirective" label="igxTooltipTarget" /> directive marks the element that the tooltip describes. Bind it to the template reference variable of an element with the `igxTooltip` directive. The target listens for the triggers and positions the tooltip next to itself. Several targets can share one tooltip: when the user moves to another target, the tooltip closes for the previous one and opens for the new one:

```html
<button igxButton="flat" [igxTooltipTarget]="sharedTooltip">Cut</button>
<button igxButton="flat" [igxTooltipTarget]="sharedTooltip">Copy</button>
<span #sharedTooltip="tooltip" igxTooltip>Uses the clipboard of the browser</span>
```

</PlatformBlock>

### Content

<PlatformBlock for="React,WebComponents,Blazor">

The {Platform} Tooltip shows the content that you place in it. For plain text, set <ApiLink pkg="core" type="Tooltip" member="message" label="message" /> instead. The content takes precedence over `message`, so the tooltip shows `message` only when it has no content of its own. The text from `message` wraps at a width of 200 pixels, and other content isn't limited:

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-tooltip anchor="save-button" message="Save the changes"></igc-tooltip>

<igc-tooltip anchor="share-button" message="This text isn't shown">
  Share the file with your team
</igc-tooltip>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrTooltip anchor="save-button" message="Save the changes" />

<IgrTooltip anchor="share-button" message="This text isn't shown">
  Share the file with your team
</IgrTooltip>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbTooltip Anchor="save-button" Message="Save the changes" />

<IgbTooltip Anchor="share-button" Message="This text isn't shown">
    Share the file with your team
```

</PlatformBlock>

<PlatformBlock for="Angular">

For plain text, set the <ApiLink type="TooltipTargetDirective" member="tooltip" label="tooltip" /> input of a target that isn't bound to an `igxTooltip` element. The target creates the tooltip for you, and its text wraps at a width of 200 pixels. For other content, use an element with the `igxTooltip` directive, which isn't limited in width:


### Showing and Hiding in Code

<PlatformBlock for="React,WebComponents">

Show and hide the {Platform} Tooltip with the following methods, which ignore the delays and don't emit the opening and the closing events:

- <ApiLink pkg="core" type="Tooltip" member="toggle" label="toggle" /> shows the tooltip when it's hidden and hides it when it's shown.

### Scroll Strategy

With `igniteui-webcomponents` 7.4.0 and later, the <ApiLink pkg="core" type="Tooltip" member="scrollStrategy" label="scrollStrategy" /> property sets what the {Platform} Tooltip does when a container of the anchor scrolls:

- `hide`, the default, hides the tooltip while the anchor is fully out of view.
- `scroll` keeps the tooltip visible and next to the anchor.
- `close` closes the tooltip on each scroll, also when the tooltip is sticky.

### Overlay Configuration

The Angular Tooltip opens through the [overlay service](../overlay.mdx). Besides the position, the <ApiLink type="TooltipTargetDirective" member="positionSettings" label="positionSettings" /> of the target set the open and the close animations and the `offset`. The <ApiLink type="TooltipTargetDirective" member="overlaySettings" label="overlaySettings" /> of the target change the other overlay settings, such as the scroll strategy or closing on Escape. The settings that you pass override the defaults of the tooltip:

```ts
import { useAnimation } from '@angular/animations';
import { slideInTop, slideOutBottom } from 'igniteui-angular/animations';
import { CloseScrollStrategy, HorizontalAlignment, OverlaySettings, PositionSettings, VerticalAlignment } from 'igniteui-angular/core';

public positionSettings: PositionSettings = {
    horizontalDirection: HorizontalAlignment.Center,
    horizontalStartPoint: HorizontalAlignment.Center,
    verticalDirection: VerticalAlignment.Top,
    verticalStartPoint: VerticalAlignment.Top,
    openAnimation: useAnimation(slideInTop, { params: { duration: '300ms' } }),
    closeAnimation: useAnimation(slideOutBottom, { params: { duration: '300ms' } }),
    offset: 10
};

public overlaySettings: OverlaySettings = {
    scrollStrategy: new CloseScrollStrategy(),
    closeOnEscape: false
};
```

```html
<igx-icon [igxTooltipTarget]="infoTooltip" [positionSettings]="positionSettings" [overlaySettings]="overlaySettings">info</igx-icon>
<span #infoTooltip="tooltip" igxTooltip>Tooltip message</span>
```

By default, the tooltip uses the `AbsoluteScrollStrategy`, which keeps it next to the target while the page scrolls, and closes on Escape.

</PlatformBlock>

### Do/Don't

When displaying a Tooltip for a given element, proper positioning is essential. The Tooltip should appear close to the element it describes, without obstructing the interface or distracting the user. Its position should ensure maximum visibility and remain fully within the screen. By default, the Tooltip appears centered just below the element; however, if this placement would cause any part of it to be cut off, it should be repositioned so that the entire Tooltip stays visible. Tooltips should not be used to convey critical information.

<DoDont
  doSrc={tooltipDoPosition}
  doAlt="A tooltip below a date input that describes the input without covering it"
  dontSrc={tooltipDoNotPosition}
  dontAlt="A tooltip that covers the label of the date input it describes"
>
<Fragment slot="do">

Keep the tooltip close to the element it describes, and reposition it when needed so the full message stays visible within the screen.

</Fragment>
<Fragment slot="dont">

Avoid placing the tooltip where it gets cut off-screen, blocks key UI, or covers the item it explains

</Fragment>
</DoDont>

## Accessibility

The {Platform} Tooltip describes its anchor and doesn't take the focus itself. This section lists what the tooltip renders and handles, as its template and event handlers define it.

### Keyboard Interaction

<PlatformBlock for="React,WebComponents">

The {Platform} Tooltip listens for its show and hide triggers on the anchor. With `igniteui-webcomponents` 7.3.0 and later, the default triggers include `focusin` and `focusout`, so the following keys work when the anchor is focusable, such as a button or an input:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Moving the focus into the anchor shows the tooltip after `showDelay`. Moving the focus out of the anchor hides it after `hideDelay`, unless the tooltip is sticky. |
| <kbd>Escape</kbd> | While a tooltip is shown, a `keydown` listener on the window hides the tooltip that opened last, wherever the focus is, also when the tooltip is sticky. The tooltip emits only the closed event, so you can't cancel this closing. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | On the anchor, the `click` that the anchor fires hides the tooltip, because `click` is a default hide trigger. On the default close button of a sticky tooltip, it hides the tooltip without a delay. |

The default close button of a sticky tooltip is a native `button` in the shadow root of the `igc-tooltip` element, so it's in the tab order at the position of that element in the DOM, for example right after the anchor when the tooltip follows it.

</PlatformBlock>

<PlatformBlock for="Blazor">

The Blazor Tooltip listens for the show and hide triggers that you set on the anchor. The following keys work:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Shows and hides the tooltip when the triggers include `focusin` and `focusout`, as described in [Triggers](#triggers). |
| <kbd>Escape</kbd> | While a tooltip is shown, a `keydown` listener on the window hides the tooltip that opened last, wherever the focus is, also when the tooltip is sticky. The tooltip raises only the closed event, so you can't cancel this closing. |

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

The {Platform} Tooltip also handles these pointer actions:

- While the tooltip is shown, it listens for `pointerenter` and `pointerleave` on itself. The pointer over the tooltip keeps it open, and the pointer leaving the tooltip hides it after `hideDelay`, unless the tooltip is sticky.
- A click on the anchor before the show delay ends cancels the showing, unless `click` is a show trigger.
- A click anywhere in the `close-button` slot hides a sticky tooltip.

</PlatformBlock>

<PlatformBlock for="Angular">

The Angular Tooltip listens for its show and hide triggers on the target. The default triggers are `pointerenter`, `pointerleave`, and `click`, so the tooltip doesn't show on keyboard focus until you add `focusin` and `focusout`, as described in [Triggers](#triggers). The following keys work:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | With the `focusin` and `focusout` triggers, moving the focus into the target shows the tooltip after `showDelay`, and moving the focus out hides it after 180 milliseconds plus `hideDelay`, unless the tooltip is sticky. |
| <kbd>Escape</kbd> | Closes the tooltip and emits `tooltipHide`, which you can cancel. The overlay service listens for Escape on the whole document, so the key works wherever the focus is, and it closes only the topmost open overlay. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | On a target that fires `click`, such as a button, the click hides the tooltip, because `click` is a default hide trigger. |

The close button of a sticky tooltip, `igx-tooltip-close-button`, handles only clicks. It has no `tabindex` and no role, so keyboard users close a sticky tooltip with Escape.

The Angular Tooltip also handles these pointer actions:

- The tooltip listens for `pointerenter` and `pointerleave` on itself. The pointer over the tooltip keeps it open, and the pointer leaving the tooltip hides it after the delays, unless the tooltip is sticky.
- When the pointer leaves the target before the show delay ends, the tooltip doesn't show.
- A click on the target before the show delay ends cancels the showing, unless `click` is a show trigger.
- A click on the close button hides a sticky tooltip after `hideDelay`.

</PlatformBlock>

### Screen Readers / ARIA

<PlatformBlock for="React,WebComponents,Blazor">

The {Platform} Tooltip renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| `igc-tooltip` | `tooltip`, or `status` while sticky | `aria-live="polite"` and `aria-atomic="true"`, set through `ElementInternals`. `inert` while the show or the hide animation plays. |
| `igc-popover` | — | `inert` while the tooltip is hidden. Its container opens as a `popover="manual"` element in the top layer of the page. |
| The default close icon | — | `aria-hidden="true"`. |<PlatformBlock for="React,WebComponents">
| The anchor | — | `aria-describedby` with the `id` of the tooltip, in `igniteui-webcomponents` 7.3.0 and later. The tooltip generates an `id`, such as `igc-tooltip-1`, when it has none, adds it to the references that the anchor already has, and removes it when it stops describing the anchor. |
| `button[part="close-button"]` | `button` | `type="button"` and `aria-label="Close"`, in `igniteui-webcomponents` 7.3.0 and later. |</PlatformBlock>

</PlatformBlock>

<PlatformBlock for="React,WebComponents">

The {Platform} Tooltip exposes the following information to assistive technology:

- The `aria-describedby` of the anchor makes the content of the tooltip the accessible description of the anchor. The tooltip renders its content only while it's shown, so the description includes the content only while the tooltip is open.
- The description of the anchor of a sticky tooltip also includes "Close", the name of the default close button.
- While the tooltip is hidden, the `igc-tooltip` element stays in the accessibility tree with its role, and its content isn't rendered.
- A sticky tooltip has the `status` role, which is a live region. With `aria-live="polite"` and `aria-atomic="true"`, assistive technology presents the whole content when the content changes.

</PlatformBlock>

<PlatformBlock for="Blazor">

The Blazor Tooltip exposes the following information to assistive technology:

- The tooltip has the `tooltip` role, or the `status` role while it's sticky, which is a live region with `aria-live="polite"` and `aria-atomic="true"`.
- While the tooltip is hidden, the `igc-tooltip` element stays in the accessibility tree with its role, and its content isn't rendered.
- To make the tooltip the description of its anchor, give the tooltip an `id` and set `aria-describedby` on the anchor to that `id`.

</PlatformBlock>

<PlatformBlock for="Angular">

The Angular Tooltip renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| `[igxTooltip]` | `tooltip`, or `status` while sticky | `id`, `igx-tooltip-0` and up when you don't set one. `aria-hidden="true"` and the `igx-tooltip--hidden` class while the tooltip is closed. |
| `igx-tooltip-close-button` | — | No role and no `tabindex`. The default `igx-icon` has `aria-hidden="true"`. |
| `[igxTooltipTarget]` | — | No ARIA attributes. |

The plain-text tooltip that the `tooltip` input of the target creates renders a `span[igxTooltip]` with the same attributes.

The Angular Tooltip exposes the following information to assistive technology:

- The tooltip has the `tooltip` role. While it's sticky, the target sets the `status` role, which is a live region.
- While the tooltip is closed, `aria-hidden="true"` and the `igx-tooltip--hidden` class remove it from the accessibility tree.
- The close button has no role and no accessible name, so assistive technology doesn't expose it as a button.
- The target doesn't refer to the tooltip. Set `aria-describedby` on the target to the `id` of the tooltip, so that the tooltip becomes the accessible description of the target:

```html
<button igxButton="outlined" [igxTooltipTarget]="saveTooltip" aria-describedby="save-tooltip">Save</button>
<span #saveTooltip="tooltip" igxTooltip id="save-tooltip">Save the changes to the server</span>
```

</PlatformBlock>
