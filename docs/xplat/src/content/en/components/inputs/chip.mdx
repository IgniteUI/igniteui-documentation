# Chip Component

The {ProductName} Chip is a compact element that represents a tag, filter, or person and that users can select or remove.

A chip can be selectable, removable, or both, and can show icons or other content before and after its label.

### Prerequisites and Version Compatibility

Some {Platform} Chip features depend on the package version that your application uses.

<PlatformBlock for="WebComponents">

- The `outlined` property is available in {PackageWebComponents} 7.3.0 and later.
- The `action` and `remove` parts are available in 7.4.0 and later. In earlier versions, the `base` part is the selection button and the remove icon renders inside it.
- The `start` and `end` slots are documented slots in 7.4.0 and later. Earlier versions mark them as deprecated in favor of `prefix` and `suffix`.

</PlatformBlock>

<PlatformBlock for="React">

Use the `igniteui-react` package together with the theme stylesheet from `igniteui-webcomponents`. The React Chip wraps the `igc-chip` web component, so the available properties, slots, and parts follow the `igniteui-webcomponents` version that `igniteui-react` uses.

</PlatformBlock>

<PlatformBlock for="Blazor">

Use the `IgniteUI.Blazor` package. In `IgniteUI.Blazor` 26.1, `IgbChip` doesn't expose the `Outlined`, `Locale`, or `ResourceStrings` properties.

</PlatformBlock>

<PlatformBlock for="Angular">

Use the `igniteui-angular` package. The `outlined` input is available in 22.2.0 and later.

</PlatformBlock>

### Size

The {Platform} Chip comes in three sizes:

- Large: suitable for interactive scenarios, such as action triggers.
- Medium: suitable for short areas, such as the recipient field of an email composer.
- Small: suitable for data-dense scenarios, such as the values in a grid cell.

### State

When users interact with the {Platform} Chip, it changes from its default idle state to hover, focused, and selected.

<PlatformBlock for="WebComponents, React, Blazor">

<Sample src="/inputs/chip/state" showThemePicker height={245} alt="{Platform} Chip state example" />

</PlatformBlock>

<PlatformBlock for="Angular">

<Sample src="/data-display/chip-state" showThemePicker height={245} alt="{Platform} Chip state example" />

</PlatformBlock>

The selected state needs selection to be enabled. Set <ApiLink pkg="core" type="Chip" member="selectable" label="Selectable" /> to let users toggle the chip by clicking it or pressing <kbd>Space</kbd><PlatformBlock for="WebComponents, React, Blazor"> or <kbd>Enter</kbd></PlatformBlock>. Each toggle updates <ApiLink pkg="core" type="Chip" member="selected" label="Selected" /> and emits a selection event with the new state. Set `selected` to define the initial state.

<PlatformBlock for="WebComponents, React, Blazor">

The select icon and the pressed state appear only when `selectable` is set.

</PlatformBlock>

</PlatformBlock>

### Remove Chip

When a chip can be removed, a cancel icon appears at its end.

<PlatformBlock for="WebComponents, React, Blazor">

<Sample src="/inputs/chip/remove" showThemePicker height={245} alt="{Platform} Chip remove example" />

<PlatformBlock for="Angular">

Set <ApiLink pkg="core" type="Chip" member="removable" label="Removable" /> to show the icon. Activating the icon emits a remove event, but the chip stays on the page. Remove the chip, or the item it represents, in the event handler.

<PlatformBlock for="WebComponents">

```html
<igc-chip removable>Angular</igc-chip>
```

```ts
document.querySelectorAll('igc-chip[removable]').forEach((chip) => {
  chip.addEventListener('igcRemove', () => chip.remove());
});
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
const [tags, setTags] = useState(['Angular', 'React', 'Blazor']);

{tags.map((tag) => (
  <IgrChip key={tag} removable onRemove={() => setTags((current) => current.filter((item) => item !== tag))}>
    {tag}
  </IgrChip>
))}
```

</PlatformBlock>

<PlatformBlock for="Blazor">

Assign a JavaScript handler through `RemoveScript`, and register it with `igRegisterScript` in a script file that your host page loads.

```razor
<IgbChip Removable="true" RemoveScript="handleChipRemove">Angular</IgbChip>
```

```js
function handleChipRemove(event) {
    event.target.remove();
}

igRegisterScript("handleChipRemove", handleChipRemove, false);
```

</PlatformBlock>

<PlatformBlock for="Angular">

```html
@for (chip of chips; track chip.id) {
  <igx-chip [id]="chip.id" removable (remove)="onRemove($event)">{{ chip.text }}</igx-chip>
}
```

```ts
import { IBaseChipEventArgs } from 'igniteui-angular/chips';

public chips = [
  { id: 'angular', text: 'Angular' },
  { id: 'react', text: 'React' },
  { id: 'blazor', text: 'Blazor' },
];

public onRemove(event: IBaseChipEventArgs) {
  this.chips = this.chips.filter((chip) => chip.id !== event.owner.id);
}
```

</PlatformBlock>

### Chips Area

<PlatformBlock for="Angular">

Use the <ApiLink pkg="core" type="ChipsArea" /> component to organize a collection of chips.

<Sample src="/data-display/chip-area" showThemePicker height={165} alt="{Platform} Chips Area example" />

Inside the chips area, the arrow keys move focus between chips. When users drag a `draggable` chip over another chip, or press <kbd>Shift</kbd> and an arrow key, the chips area emits `reorder` with the new order. It also emits `selectionChange` with the selected chips. The chips area doesn't reorder the chips itself, so apply the new order to your data in the `reorder` handler.

```html
<igx-chips-area (reorder)="onReorder($event)">
  @for (chip of chips; track chip.id) {
    <igx-chip [id]="chip.id" [draggable]="true">{{ chip.text }}</igx-chip>
  }
</igx-chips-area>
```

```ts
import { IChipsAreaReorderEventArgs } from 'igniteui-angular/chips';

public onReorder(event: IChipsAreaReorderEventArgs) {
  this.chips = event.chipsArray.map((chip) => this.chips.find((item) => item.id === chip.id)!);
}
```

</PlatformBlock>

<PlatformBlock for="WebComponents, React, Blazor">

To organize a collection of chips, place them in a container that lays them out with a gap, such as a wrapping flex container.

<Sample src="/inputs/chip/area" showThemePicker height={165} alt="{Platform} Chips Area example" />

## Accessibility

The {Platform} Chip supports keyboard operation and exposes its state to assistive technology.

### Keyboard Interaction

Keyboard users reach each chip with <kbd>Tab</kbd>, followed by its remove control when the chip is removable. Disabled chips are skipped.

<PlatformBlock for="WebComponents, React, Blazor">

| Key | Action |
| -- | -- |
| <kbd>Space</kbd> / <kbd>Enter</kbd> | On the selection button, toggles `selected` when `selectable` is set and emits the select event. On the remove control, emits the remove event. |

</PlatformBlock>

<PlatformBlock for="Angular">

| Key | Action |
| -- | -- |
| <kbd>Space</kbd> | On the chip, toggles `selected` when `selectable` is set. |
| <kbd>Space</kbd> / <kbd>Enter</kbd> | On the remove control, emits `remove`. |
| <kbd>Delete</kbd> | On a removable chip, emits `remove`. |
| <kbd>Arrow Left</kbd> / <kbd>Arrow Right</kbd> | Inside an `igx-chips-area`, moves focus to the previous or next chip. |
| <kbd>Shift</kbd> + <kbd>Arrow Left</kbd> / <kbd>Arrow Right</kbd> | Inside an `igx-chips-area`, emits `reorder` with the focused chip moved one position. |

</PlatformBlock>

### Screen Readers / ARIA

The {Platform} Chip exposes its state through native semantics and ARIA attributes, and takes its accessible name from its content.

<PlatformBlock for="WebComponents, React, Blazor">

- The selection control is a native `button`. When `selectable` is set, `aria-pressed` reflects the `selected` state.
- The default select icon is hidden from assistive technology, because `aria-pressed` already conveys the selected state.
- The default remove icon is a separate control with `role="button"`, `tabindex="0"`, and an `aria-label` that defaults to "remove chip".
- A disabled chip disables its native button, so assistive technology reports the chip as unavailable.

</PlatformBlock>

<PlatformBlock for="Angular">

- The chip host has `role="option"`, and `aria-selected` reflects the `selected` state.
- The `igx-chips-area` element has `role="listbox"` and the `aria-label` "chip area".
- The default select and remove icons have accessible labels.
- A disabled chip is removed from the tab order, but no ARIA attribute exposes its disabled state.

</PlatformBlock>

<PlatformBlock for="WebComponents, React, Angular">

You can change the labels of the default icons, as shown in [Localization](#localization).

</PlatformBlock>

Your responsibilities:

- Give every chip a text label that identifies the item it represents.
- Move focus to a logical place, such as the next chip, after you remove a chip in the remove event handler.
- Keep sufficient contrast between the chip background and its text and icons when you override the theme colors.
- Keep a visible focus indicator when you restyle the chip.
- Keep chips and their remove controls large enough to tap when you use the small size or a custom `--ig-chip-size`.

<PlatformBlock for="WebComponents, React, Blazor">

- Keep custom `remove` slot content focusable and labeled, as described in [Layout](#layout).

</PlatformBlock>

<PlatformBlock for="Angular">

</PlatformBlock>

<PlatformBlock for="Angular">

- The remove control is focusable and contains a labeled icon, but it doesn't expose a `button` role.
- The disabled state isn't exposed through ARIA, so screen readers don't announce a disabled chip as disabled. Describe the state in nearby text when users need to know it.

</PlatformBlock>

## Troubleshooting

Use this section when a chip doesn't behave or look as expected after a change or an upgrade.

### Why does the chip stay on the page after I click the remove icon?

The remove event only notifies your application. Remove the chip in the event handler, as shown in [Remove Chip](#remove-chip).

<PlatformBlock for="WebComponents, React, Blazor">

### Why did my `::part(base)` styles change after an upgrade?

Starting with `igniteui-webcomponents` 7.4.0, the `base` part is the chip wrapper, the selection button is the `action` part, and the remove control is in the `remove` part. Move styles that targeted the button to `::part(action)`.

</PlatformBlock>

### Why doesn't my focus outline variable apply anymore?

<PlatformBlock for="WebComponents, React, Blazor">

The `--ig-chip-focus-outline-color` and `--ig-chip-focus-selected-outline-color` variables were replaced by `--ig-chip-focus-shadow-color` and `--ig-chip-focus-selected-shadow-color` in `igniteui-webcomponents` 7.3.0. Rename the variables in your styles.

</PlatformBlock>

<PlatformBlock for="Angular">

In `igniteui-angular` 22.2.0, the `$focus-outline-color` and `$focus-selected-outline-color` parameters of `chip-theme` were replaced by `$focus-shadow-color` and `$focus-selected-shadow-color`. Rename the parameters, and the matching `--ig-chip-*` variables, in your styles.

</PlatformBlock>
