# Radio Group

The {Platform} Radio and Radio Group are components that let users select exactly one option from a set of mutually exclusive options. Each radio button represents one option, and the Radio Group arranges the radio buttons in a vertical or horizontal layout.

## Getting Started

To use the {Platform} Radio and Radio Group, follow the <PlatformBlock for="Angular">[{ProductName} Getting Started](../general/getting-started.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[{ProductName} Getting Started](../general-getting-started.mdx)</PlatformBlock> topic for the basic project setup, then import or register the components for your target platform.

<PlatformBlock for="WebComponents">

Import the <ApiLink pkg="core" type="Radio" /> and <ApiLink pkg="core" type="RadioGroup" />, a theme, and register the components:

```ts
import { defineComponents, IgcRadioComponent, IgcRadioGroupComponent } from 'igniteui-webcomponents';
import 'igniteui-webcomponents/themes/light/bootstrap.css';

defineComponents(IgcRadioComponent, IgcRadioGroupComponent);
```

</PlatformBlock>

<PlatformBlock for="React">

Import the <ApiLink pkg="core" type="Radio" /> and <ApiLink pkg="core" type="RadioGroup" /> wrappers and a theme:

```tsx
import { IgrRadio, IgrRadioGroup } from 'igniteui-react';
import 'igniteui-webcomponents/themes/light/bootstrap.css';
```

</PlatformBlock>

<PlatformBlock for="Blazor">

Register the <ApiLink pkg="core" type="Radio" /> and <ApiLink pkg="core" type="RadioGroup" /> modules in the **Program.cs** file:

```csharp
builder.Services.AddIgniteUIBlazor(
    typeof(IgbRadioModule),
    typeof(IgbRadioGroupModule)
);
```

Then link the theme CSS file in **wwwroot/index.html** for a **Blazor WebAssembly** project or in **Pages/_Host.cshtml** for a **Blazor Server** project:

```razor
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
```

</PlatformBlock>

<PlatformBlock for="Angular">

Import the <ApiLink type="Radio" /> component and the <ApiLink type="RadioGroupDirective" /> directive:

```ts
import { IgxRadioComponent, IgxRadioGroupDirective } from 'igniteui-angular/radio';
```

Add both to the `imports` collection of your component, or add the `IGX_RADIO_GROUP_DIRECTIVES` collection, which contains them, and then use the `igx-radio-group` and `igx-radio` elements in your template.

</PlatformBlock>

After registration, place the {Platform} Radio components inside a Radio Group and give the group a `name`, so that users can select only one of the options. Set `value` on each radio button to identify the selected option.

<PlatformBlock for="WebComponents">

```html
<igc-radio-group name="fruit">
  <igc-radio value="apple" checked>Apple</igc-radio>
  <igc-radio value="banana">Banana</igc-radio>
  <igc-radio value="mango">Mango</igc-radio>
</igc-radio-group>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrRadioGroup name="fruit">
  <IgrRadio value="apple" checked={true}>Apple</IgrRadio>
  <IgrRadio value="banana">Banana</IgrRadio>
  <IgrRadio value="mango">Mango</IgrRadio>
</IgrRadioGroup>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbRadioGroup name="fruit">
    <IgbRadio Value="apple" Checked="true">Apple</IgbRadio>
    <IgbRadio Value="banana">Banana</IgbRadio>
    <IgbRadio Value="mango">Mango</IgbRadio>
</IgbRadioGroup>
```

</PlatformBlock>

<PlatformBlock for="Angular">

```html
<igx-radio-group name="fruit" alignment="vertical" value="apple">
  <igx-radio value="apple">Apple</igx-radio>
  <igx-radio value="banana">Banana</igx-radio>
  <igx-radio value="mango">Mango</igx-radio>
</igx-radio-group>
```

</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

<DocsAside type="info">
The {Platform} Radio components are mutually exclusive only when they share a `name`. The Radio Group applies its `name` to every radio button it contains; radio buttons without a `name` act independently of each other.
</DocsAside>

</PlatformBlock>

## Usage

### Layout

The {Platform} Radio places its label after the radio control by default. Set the <ApiLink pkg="core" type="Radio" member="labelPosition" label="labelPosition" /> property to `before` to place the label before the control. In a vertical Radio Group, radio buttons with the label before the control align to the end of the group.

<PlatformBlock for="WebComponents">

```html
<igc-radio-group name="color">
  <igc-radio value="yellow" label-position="before" checked>Yellow</igc-radio>
  <igc-radio value="orange" label-position="before">Orange</igc-radio>
</igc-radio-group>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrRadioGroup name="color">
  <IgrRadio value="yellow" labelPosition="before" checked={true}>Yellow</IgrRadio>
  <IgrRadio value="orange" labelPosition="before">Orange</IgrRadio>
</IgrRadioGroup>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor

    <IgbRadio Value="yellow" LabelPosition="ToggleLabelPosition.Before" Checked="true">Yellow</IgbRadio>
    <IgbRadio Value="orange" LabelPosition="ToggleLabelPosition.Before">Orange</IgbRadio>
</IgbRadioGroup>
```

</PlatformBlock>

<PlatformBlock for="Angular">

### Forms

The {Platform} Radio submits the `value` of the selected radio button under the group's `name`. Set the <ApiLink pkg="core" type="Radio" member="required" label="required" /> property on a radio button of the group to require a selection before the form is submitted.

<PlatformBlock for="WebComponents">

```html
<form>
  <igc-radio-group name="fruit">
    <igc-radio value="apple" required>Apple</igc-radio>
    <igc-radio value="banana">Banana</igc-radio>
    <igc-radio value="orange">Orange</igc-radio>
  </igc-radio-group>
</form>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<form>
  <IgrRadioGroup name="fruit">
    <IgrRadio value="apple" required={true}>Apple</IgrRadio>
    <IgrRadio value="banana">Banana</IgrRadio>
    <IgrRadio value="orange">Orange</IgrRadio>
  </IgrRadioGroup>
</form>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbRadioGroup name="fruit">
    <IgbRadio Value="apple" Required="true">Apple</IgbRadio>
```

</PlatformBlock>

### Do/Don't

When extending a Radio Group with additional items, make sure that they are aligned consistently and form a single column. Avoid layout in multiple columns, as well as situations with more than one Radio element with on state at a time.

## Accessibility

The {Platform} Radio renders a native radio input, so assistive technologies announce each radio button with its role, label, and checked state.

### Keyboard Interaction

The {Platform} Radio Group moves focus and selection between its enabled radio buttons with the arrow keys. Disabled radio buttons are skipped.

| Key | Action |
| --- | --- |
| Tab / Shift+Tab | Moves focus into or out of the Radio Group. |
| Arrow Down / Arrow Right | Moves focus to the next enabled radio button and turns it on. From the last radio button, moves to the first one. In right-to-left layouts, Arrow Right moves to the previous radio button. |
| Arrow Up / Arrow Left | Moves focus to the previous enabled radio button and turns it on. From the first radio button, moves to the last one. In right-to-left layouts, Arrow Left moves to the next radio button. |
| Space | Turns on the focused radio button. |
<PlatformBlock for="React,WebComponents,Blazor">| Enter | Submits the form that contains the radio button. |</PlatformBlock>

<PlatformBlock for="React,WebComponents,Blazor">

When a radio button in the group is on, it is the only tab stop of the group. When none of the radio buttons is on, each of them is a tab stop.

</PlatformBlock>

### Screen Readers / ARIA

- Each {Platform} Radio renders a native `<input type="radio">`, which exposes the radio role, the checked state, and the disabled and required states.<PlatformBlock for="Angular"> The input also sets `aria-invalid` from the `invalid` property.</PlatformBlock>
- The label content of the radio button is its accessible name. When the label is outside the component, connect it with `aria-labelledby`.

<PlatformBlock for="React,WebComponents,Blazor">

- The Radio Group renders the `radiogroup` role and sets `aria-orientation` from its `alignment`.
- Give the Radio Group an accessible name, for example with `aria-labelledby` pointing to the question it answers.

</PlatformBlock>

<PlatformBlock for="Angular">

- The `igx-radio-group` element doesn't render a `radiogroup` role. Add `role="radiogroup"` and an accessible name, for example with `aria-labelledby`, when the group needs to be announced as one question.

</PlatformBlock>

### Accessibility Compliance

Verify the rendered {Platform} Radio and Radio Group against the accessibility requirements of your application.

| Criterion | How the component supports the requirement |
| --- | --- |
| [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | Users move between the enabled radio buttons and turn them on with the arrow keys and Space. |
| [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | Each radio button exposes its label as the accessible name, the radio role, and its checked state through the native radio input. |

Your responsibilities:

- Give every radio button meaningful label content, and give the Radio Group an accessible name.
- Keep the focus ring visible and preserve sufficient contrast when you customize the Radio colors.
- Show a validation message in the surrounding form when the Radio is invalid, so the error isn't conveyed by color alone.
- Test the rendered Radio Group with keyboard navigation and the assistive technologies your users rely on.
