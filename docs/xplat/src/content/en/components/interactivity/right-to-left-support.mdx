# Right-to-Left (RTL) Support

{ProductName} components support right-to-left (RTL) layouts: set `dir="rtl"` on the page and the components mirror their layout and most of their keyboard interaction, with no separate RTL theme.

## Overview

{ProductName} takes the direction from the standard HTML `dir` attribute. No component has a direction property, and there is no RTL version of a theme: the theme you already load serves both directions.

| Layer | How it follows the direction |
|---|---|
| **Styles** | Component styles use CSS logical properties, such as `margin-inline-start`, and direction selectors, so the layout mirrors as soon as the direction changes. |
| **Interaction** | Components with horizontal keyboard or pointer interaction, such as Carousel, Slider, Stepper and Tabs, read the direction when the user interacts with them. In RTL, the <kbd>Arrow Left</kbd> and <kbd>Arrow Right</kbd> keys follow the reading direction. |

A few components follow the direction only in part. [Known Limitations](#known-limitations) lists them for {Platform}.

## Before You Start

**RTL mirrors the layout; it does not translate text.** The `dir` attribute changes the reading direction only. <PlatformBlock for="Angular">To show the component strings in another language, see [Localization](../general/localization.mdx).</PlatformBlock><PlatformBlock for="React,WebComponents">To show the component strings in another language, see [Localization](../localization.mdx).</PlatformBlock>

**Set the direction in one place.** For a whole application, set `dir="rtl"` on the `body` element. To mirror only part of a page, set it on a container instead, as described in [Apply RTL to Part of a Page](#apply-rtl-to-part-of-a-page).

**Your own content needs logical properties too.** The components mirror themselves, but styles you write with physical properties, such as `margin-left`, stay where you put them. See [Style Your Own Content for RTL](#style-your-own-content-for-rtl).

## Available Tools

| Tool | Where | What it does |
|---|---|---|
| `dir` attribute | Any HTML element, usually `body` | Sets the direction of the element and of everything inside it. Accepts `rtl`, `ltr` and `auto`. |
| CSS logical properties | Your stylesheets | Place content relative to the reading direction, such as `padding-inline-start` in place of `padding-left`. |
| `:dir(rtl)` pseudo-class | Your stylesheets | Matches an element whose direction is right-to-left, whether the `dir` attribute is on the element or on an ancestor. |

For directional icons, the Icon and the Icon Button also have a <ApiLink pkg="core" type="Icon" member="mirrored" label="mirrored" /> property. See [Mirror a Directional Icon](#mirror-a-directional-icon).

## Common Workflows

### Enable RTL for the Whole Application

Set `dir="rtl"` on the `body` element of the host page. Every {ProductName} component on the page renders right-to-left.

<PlatformBlock for="Angular">

Set the attribute in `src/index.html`:

```html
<!doctype html>
<html lang="ar">
  <head>
    <meta charset="utf-8" />
    <title>My App</title>
  </head>
  <body dir="rtl">
    <app-root></app-root>
  </body>
</html>
```

</PlatformBlock>

<PlatformBlock for="React,WebComponents">

Set the attribute in the `index.html` of your application:

```html
<!doctype html>
<html lang="ar">
  <head>
    <meta charset="utf-8" />
    <title>My App</title>
  </head>
  <body dir="rtl">
    <!-- application content -->
  </body>
</html>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

Set the attribute on the `body` element of the host page: `Components/App.razor` in a Blazor Web App, `wwwroot/index.html` in a Blazor WebAssembly app, or `Pages/_Host.cshtml` in a Blazor Server app. In a Blazor Web App:

```razor
<!DOCTYPE html>
<html lang="ar">
<head>
    <meta charset="utf-8" />
    <base href="/" />
    <HeadOutlet />
</head>
<body dir="rtl">
    <Routes />
    <script src="_content/IgniteUI.Blazor/app.bundle.js"></script>
    <script src="_framework/blazor.web.js"></script>
</body>
</html>
```

</PlatformBlock>

### Switch the Direction at Runtime

To change the direction while the application runs, for example when the user picks another language, set the `dir` attribute of the `body` element. The component styles update at once, and the components read the new direction the next time the user interacts with them.

<PlatformBlock for="Angular">

```ts
import { Component, DOCUMENT, inject } from '@angular/core';

@Component({
    selector: 'app-root',
    templateUrl: './app.component.html'
})
export class AppComponent {
    private readonly document = inject(DOCUMENT);

    public setDirection(dir: 'ltr' | 'rtl') {
        this.document.body.dir = dir;
    }
}
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
function setDirection(dir: 'ltr' | 'rtl') {
  document.body.dir = dir;
}
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```ts
function setDirection(dir: 'ltr' | 'rtl') {
  document.body.dir = dir;
}
```

</PlatformBlock>

<PlatformBlock for="Blazor">

Set the attribute through JavaScript interop:

```razor
@inject IJSRuntime JS

<button @onclick='() => SetDirection("rtl")'>Right to left</button>
<button @onclick='() => SetDirection("ltr")'>Left to right</button>

@code {
    private async Task SetDirection(string dir)
    {
        await JS.InvokeVoidAsync("document.body.setAttribute", "dir", dir);
    }
}
```

</PlatformBlock>

### Apply RTL to Part of a Page

To mirror only part of a page, such as a panel with Arabic or Hebrew content, set `dir="rtl"` on the element that contains it and leave the `body` left-to-right. The components inside the element follow its direction.

### Mirror a Directional Icon

Icons are not mirrored automatically, because most icons look the same in both directions. For an icon that points in the reading direction, such as an arrow, set <ApiLink pkg="core" type="Icon" member="mirrored" label="mirrored" /> to flip it in a right-to-left layout. The [Icon](../layouts/icon.mdx#mirrored) and the [Icon Button](../inputs/icon-button.mdx#mirrored) support it.

</PlatformBlock>

<PlatformBlock for="Angular">

### Mirror a Directional Icon

Icons are not mirrored automatically, and the Angular Icon has no option to mirror an icon. For a directional icon in a right-to-left layout, use an icon that points in the reading direction, such as `arrow_back` in place of `arrow_forward`.

</PlatformBlock>

### Style Your Own Content for RTL

Write the styles of your own content with CSS logical properties, so they mirror together with the components. Use the `:dir(rtl)` pseudo-class for a rule that applies in one direction only:

```css
.toolbar {
  padding-inline-start: 16px; /* left in LTR, right in RTL */
}

.next-icon:dir(rtl) {
  transform: scaleX(-1);
}
```

## Known Limitations

The following components follow the direction only in part in {ProductName}.

<PlatformBlock for="Angular">

| Component | What does not follow the direction |
|---|---|
| [Grid](../grid/grid.mdx), [Tree Grid](../treegrid/tree-grid.mdx), [Hierarchical Grid](../hierarchicalgrid/hierarchical-grid.mdx), [Pivot Grid](../pivotGrid/pivot-grid.mdx) | The layout and the horizontal scrolling follow the direction, but the keyboard navigation does not. <kbd>Arrow Left</kbd> moves the focus to the previous column and <kbd>Arrow Right</kbd> to the next one, so in RTL, <kbd>Arrow Left</kbd> moves the focus to the right. |

| [Icon](../layouts/icon.mdx) | Has no option to mirror an icon. See [Mirror a Directional Icon](#mirror-a-directional-icon). |

</PlatformBlock>

## Troubleshooting

<PlatformBlock for="React,WebComponents,Blazor">

### Why do the Carousel arrows point the wrong way?

The Carousel and the Navigation Drawer combine the direction of the `body` element with their own `dir` attribute. When `dir="rtl"` is on the `html` element only, they render left-to-right; when it is on both the `body` element and the component, the two cancel out. Set `dir="rtl"` in one place: on the `body` element for the whole page, or on the component for a component inside a right-to-left container.

</PlatformBlock>

<PlatformBlock for="Angular">

### Why does `$direction: rtl` fail to compile?

The `core()` mixin, called `igx-core()` before version 13.1.0, no longer has a `$direction` parameter. Version 13.2.0 removed it, together with the RTL-specific `*-rtl.css` theme files, because the regular themes support both directions. Replace `@include igx-core($direction: rtl)` or `@include core($direction: rtl)` with `@include core()`, use the regular theme files, and set the `dir` attribute as described in [Enable RTL for the Whole Application](#enable-rtl-for-the-whole-application). Running `ng update` to 13.2.0 or later makes both changes to your Sass for you.

### Why don't the components follow a direction change at runtime?

Versions earlier than 22.0.0 read the direction once, from the `body` or the `html` element, when the application starts. In those versions, set the `dir` attribute before the application bootstraps, or update to 22.0.0 or later, where the components read the direction each time the user interacts with them.

</PlatformBlock>

### Why does my own content stay on the left in RTL?

Styles that use physical properties, such as `margin-left` or `float: left`, do not mirror. Replace them with logical properties, such as `margin-inline-start` or `float: inline-start`, as shown in [Style Your Own Content for RTL](#style-your-own-content-for-rtl).
