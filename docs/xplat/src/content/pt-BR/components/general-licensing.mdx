# FAQ de licença e instalação

O {ProductName} reúne pacotes disponíveis sob a licença MIT ou sob uma licença comercial. Este modelo de licenciamento oferece suporte tanto ao uso comercial quanto ao uso permissivo de código aberto, dependendo dos componentes, módulos e serviços específicos que você incorporar ao seu projeto.

É fundamental entender qual licença se aplica a cada parte do pacote. O tópico [Código aberto vs Premium](./general-open-source-vs-premium.mdx) traz detalhes sobre qual tipo de licença se aplica a cada componente e, portanto, se você precisa comprar uma licença comercial com base nos componentes que usa nos seus projetos.

## Pacotes npm do {ProductName} - usando o feed npm privado
O npm é o gerenciador de pacotes mais popular e também o padrão do ambiente de execução Node.js. Ele é muito adotado e é uma das formas mais rápidas e fáceis de gerenciar os pacotes dos quais o seu projeto depende. Para mais informações sobre como o npm funciona, leia a [documentação oficial do npm](https://docs.npmjs.com/).

O {ProductName} da Infragistics está disponível como pacotes npm, e você pode adicioná-los como dependências do seu projeto em [poucos passos simples](./general-getting-started.mdx). Essa abordagem não exige configurar o npm. Se você instalar um pacote sob licença comercial, começará a usar a **{ProductName} versão Trial** do produto.

<DocsAside type="info">
O que significa começar a usar uma versão de avaliação? Significa que você vai usar uma versão do nosso produto com uma **marca d'água** na sua visualização web. Não significa que você vai usar o pacote licenciado por um período determinado antes de ele expirar, por exemplo, um mês.
</DocsAside>

O feed npm privado fornecido pela Infragistics contém as versões licenciadas dos pacotes sob licença comercial.

### Como configurar o seu ambiente para usar o feed npm privado

#### Primeiro, você precisa configurar o registro privado e associar esse registro ao escopo da Infragistics

Isso permitirá usar, sem costuras, uma combinação de pacotes do registro npm público e do registro privado da Infragistics. Você será solicitado a informar o nome de usuário e a senha que usa para entrar na sua conta da Infragistics. Também deverá informar o e-mail registrado no seu perfil da Infragistics.

> Se a sua conta não for licenciada (se você ainda estiver usando uma conta de avaliação), o feed privado de pacotes não ficará acessível para você, por exemplo, retornará uma mensagem de erro 404 ou 403. **Somente contas licenciadas podem acessar o feed privado packages.infragistics.**

### Agora, para fazer login no nosso feed privado usando o npm

#### npm versão 9+
O nosso feed privado atualmente não oferece suporte aos comandos login/adduser com o npm v9; por isso, recomendamos os passos a seguir para adicionar os campos de autenticação necessários à configuração:

```cmd
npm config set @infragistics:registry https://packages.infragistics.com/npm/js-licensed/

npm config set //packages.infragistics.com/npm/js-licensed/:username=YOUR_USERNAME

npm config set //packages.infragistics.com/npm/js-licensed/:email=YOUR_IG_EMAIL

npm config set //packages.infragistics.com/npm/js-licensed/:_auth=YOUR_IG_AUTH_TOKEN
```

Você pode gerar um [Access Token](#uso-do-access-token) pelo seu perfil na Infragistics.

Esta abordagem é aplicável a todas as versões anteriores de `npm`.

#### npm até a versão v8
Execute o comando `adduser` e informe uma conta de usuário e uma senha:

```cmd
npm adduser --registry=https://packages.infragistics.com/npm/js-licensed/ --scope=@infragistics
```

Você será solicitado a informar o nome de usuário e a senha que usa para entrar na sua conta da Infragistics. Você também deve informar o e-mail cadastrado no seu perfil da Infragistics.

> `npm` não permite o uso do símbolo `"@"` dentro do seu nome de usuário, pois ele é considerado "não seguro para a rede". Como o seu nome de usuário é, na verdade, o e-mail que você usa na conta da Infragistics, ele sempre contém o símbolo `"@"`. Por isso, você precisa contornar essa limitação substituindo o símbolo `"@"` por `"!!"` (dois pontos de exclamação). Por exemplo, se o seu nome de usuário for `"username@example.com"`, quando for solicitado o nome de usuário, você deve informar: `"username!!example.com"`.

#### Depois disso, você estará conectado e poderá instalar as versões mais recentes dos pacotes do Ignite UI no seu projeto

```cmd
npm uninstall {PackageDockManager}
npm install @infragistics/{PackageDockManager}

npm uninstall {PackageDockManager}
npm install @infragistics/{PackageDockManager}
```

Tenha em mente que definimos o pacote {ProductName} como escopado; assim, não é preciso alterar os registros se você quiser instalar pacotes do nosso feed privado e do npmjs.org ao mesmo tempo.

### Alterações no código-fonte do projeto após a atualização do pacote de licença

Se você estiver atualizando de um pacote trial para um pacote licenciado, os novos pacotes serão escopados sob `@infragistics`.
Por isso, você pode:

- Fazer uma substituição global de todos os pacotes trial e trocá-los pela versão licenciada escopada em todos os arquivos do projeto. Por exemplo, substitua todas as referências a `{PackageDockManager}` por `@infragistics/{PackageDockManager}`. A mudança deve afetar todas as importações em que esses pacotes são usados.

  **Ou**

- Adicione um mapeamento **paths** no **tsconfig.json** do projeto.

```json
{
  /* ... */
  "compilerOptions": {
    "baseUrl": "./",
    "outDir": "./dist/out-tsc",
    /* ... */
    "paths": {
      "{PackageDockManager}": ["./node_modules/@infragistics/{PackageDockManager}"],
      "{PackageDockManager}/*": ["./node_modules/@infragistics/{PackageDockManager}/*"],
    }
  }
}
```

## Uso do access token

Você também pode se autenticar no nosso feed npm privado usando um token de acesso, que pode ser obtido pela sua [conta de usuário da infragistics.com](https://account.infragistics.com/access-tokens). A autenticação por token de acesso é a alternativa preferida quando você quer integrar um processo de CI em um repositório publicamente acessível, que usa os pacotes licenciados do {ProductName}.

As informações a seguir mostram como configurar a autenticação no nosso registro npm privado usando um access token na configuração local, nos procedimentos de build do Azure Pipelines e no processo de build do Travis CI:

- Gere um token em https://account.infragistics.com/access-tokens

<Image src={generateToken} alt="Novo token gerado" class="responsive-img" style="margin-bottom:10px; -webkit-box-shadow: 4px 4px 4px 4px #ccc; -moz-box-shadow: 4px 4px 4px 4px #ccc; box-shadow: 4px 4px 4px 4px #ccc; max-width: 600px" />

> Cada token está codificado em Base64.

- Adicione o seguinte ao seu arquivo [.npmrc](https://docs.npmjs.com/configuring-npm/npmrc.html)

```cmd
@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/
//packages.infragistics.com/npm/js-licensed/:_auth=YOUR_ACCESS_TOKEN
//packages.infragistics.com/npm/js-licensed/:username=YOUR_USERNAME
```

## Configuração do Azure Pipelines
Atualize o azure-pipelines.yml com as seguintes etapas:

```cmd
steps:

- script: npm config set @infragistics:registry $(npmRegistry)
  displayName: 'Npm add registry'
- script: npm config set $(igScope):_auth=$(token)
  displayName: 'Npm config auth'
```

## Configuração do Travis CI
Vamos seguir quase a mesma abordagem aqui. A única diferença é que a configuração será definida em [before_install](https://docs.travis-ci.com/user/job-lifecycle/#the-job-lifecycle)

```cmd
before_install:
- echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- echo "//packages.infragistics.com/npm/js-licensed/:_auth=$TOKEN" >> ~/.npmrc
```

A melhor forma de definir uma variável de ambiente depende do tipo de informação que ela vai conter. Por isso, [você tem duas opções](https://docs.travis-ci.com/user/environment-variables/):

- criptografá-la e adicioná-la [ao seu .travis.yml](https://docs.travis-ci.com/user/environment-variables/#defining-encrypted-variables-in-travisyml)
- adicioná-la às [configurações do repositório](https://docs.travis-ci.com/user/environment-variables/#defining-variables-in-repository-settings)

### Configuração do GitHub Actions

Adicione os scripts a seguir antes da etapa **npm i(ci)** na sua [configuração do fluxo de trabalho de CI](https://help.github.com/en/actions/language-and-framework-guides/using-nodejs-with-github-actions):

```cmd
- run: echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- run: echo "//packages.infragistics.com/npm/js-licensed/:_auth=${{ secrets.NPM_TOKEN }}" >> ~/.npmrc
```

Defina [secrets (variáveis de ambiente criptografadas)](https://help.github.com/en/actions/configuring-and-managing-workflows/creating-and-storing-encrypted-secrets) e use-as no fluxo de trabalho de ações do GitHub para informações sensíveis, como o token de acesso.
