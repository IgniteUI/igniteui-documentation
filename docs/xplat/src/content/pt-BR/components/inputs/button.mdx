# Componente Button

O componente Button {Platform} permite habilitar elementos clicáveis que disparam ações na sua aplicação {Platform}. Você tem controle total sobre as variantes, a estilização e os tamanhos do botão. O componente Button também permite tratar cliques, alternar o botão e desabilitá-lo quando necessário.

O Button renderiza o seu conteúdo dentro da parte CSS `base`. Use o slot padrão para o rótulo e os slots `prefix` e `suffix` para conteúdo opcional antes e depois do rótulo.

```text
<igc-button>
├── ::part(base)
├── prefix slot
├── default slot content
└── suffix slot
</igc-button>
```

## Uso

Use o Button {Platform} para disparar uma ação, enviar dados de formulário ou navegar para outra página. Escolha o tipo e a variante de botão adequados à ação e, quando necessário, adicione conteúdo opcional, como ícones.

O conteúdo do Button é colocado no seu slot padrão. Use o rótulo da ação como conteúdo do botão, para que a finalidade da ação fique clara para todos os usuários.

<PlatformBlock for="Angular">

```html
<button igxButton>Save changes</button>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrButton>Save changes</IgrButton>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-button>Save changes</igc-button>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbButton>Save changes</IgbButton>
```

</PlatformBlock>

Com os slots `prefix` e `suffix` do componente <ApiLink pkg="core" type="Button" />, podemos adicionar conteúdos diferentes antes e depois do conteúdo principal do botão.

Recomendamos usar um elemento `<span>` ao adicionar texto simples, símbolos ou emojis, e um componente <ApiLink pkg="core" type="Icon" /> ao adicionar ícones nos slots `prefix` e `suffix`.

<PlatformBlock for="Angular">

```html
<button igxButton="contained">
    <span igxButtonIcon="prefix">download</span>
    Download
    <span igxButtonIcon="suffix">arrow_forward</span>
</button>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrButton type="button" variant="contained">
    <span slot="prefix">Download</span>
    <IgrIcon slot="suffix" name="download"></IgrIcon>
</IgrButton>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-button type="button" variant="contained">
    <span slot="prefix">Download</span>
    <igc-icon slot="suffix" name="download"></igc-icon>
</igc-button>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbButton Variant="@ButtonVariant.Contained">
    <span slot="prefix">Download</span>
    <IgbIcon slot="suffix" IconName="download"></IgbIcon>
</IgbButton>
```

</PlatformBlock>

### Tipo

O componente de botão mudará sua estrutura interna de um elemento [`<button>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/button) para um elemento do tipo [`<a>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/a) quando o atributo <ApiLink pkg="core" type="Button" member="href" label="Href" /> for definido. Nesse caso, o botão pode ser considerado um link comum. Definir o atributo <ApiLink pkg="core" type="Button" member="href" label="Href" /> também permitirá definir os atributos <ApiLink pkg="core" type="Button" member="rel" label="Rel" />, <ApiLink pkg="core" type="Button" member="target" label="Target" /> e <ApiLink pkg="core" type="Button" member="download" label="Download" />.
Quando o componente de botão usa internamente um elemento [`<button>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/button) real, podemos especificar o seu <ApiLink pkg="core" type="Button" member="type" label="DisplayType" /> definindo a propriedade com qualquer um dos valores a seguir:

- `Submit` - quando quisermos enviar os dados do formulário
- `reset` - quando quisermos redefinir os dados do formulário para os seus valores iniciais
- `button` - quando quisermos adicionar um botão com funcionalidade personalizada em qualquer lugar de uma página web

### Variantes

Cinco tipos de Button são suportados: botão `contained` para ações primárias de destaque, botão `outlined` para ações secundárias, botão `flat` para ações discretas, botão `floating action` (Fab) para ações principais de destaque e botão `icon` para ações representadas por um ícone. Os Icon Buttons também podem usar qualquer uma das outras quatro variantes.

## Estilização

Personalize o Button com configurações de tema, variáveis CSS ou partes CSS para combinar com a linguagem visual da sua aplicação.

### Temas em Sass

Use o fluxo padrão de temas do {ProductName} para personalizar o Button de forma consistente com o restante da aplicação.

### Variáveis CSS

Use as variáveis CSS geradas no elemento Button para sobrescrever os valores do tema em uma instância específica. As funções de tema específicas de cada variante derivam os valores dos estados de interação relacionados a partir dos parâmetros primários do tema.

| Propriedade primária | Propriedade dependente | Descrição |
| --- | --- | --- |
| `$background` | `$hover-background`, `$focus-background`, `$active-background` | Cores de fundo do Button para os estados de interação. |
| `$foreground` | `$hover-foreground`, `$focus-foreground`, `$active-foreground` | Cores do texto do Button para os estados de interação. |
| `$border-color` | `$hover-border-color`, `$focus-border-color`, `$active-border-color` | Cores da borda do Button para os estados de interação. |
| `$shadow-color` | `$resting-shadow`, `$hover-shadow`, `$focus-shadow`, `$active-shadow` | Cores e elevações da sombra do Button. |
| `$disabled-background` | `$disabled-foreground`, `$disabled-icon-color`, `$disabled-border-color` | Cores do Button quando ele está desabilitado. |

### Partes de estilo

O <ApiLink pkg="core" type="Button" /> expõe três partes CSS que podemos usar para estilização:

|Nome|Descrição|
|--|--|
| `base` | O elemento de botão nativo do componente igc-button. |
| `prefix` | O contêiner de prefixo do componente igc-button. |
| `suffix` | O contêiner de sufixo do componente igc-button. |

A parte CSS `base` permite estilizar o elemento envolvido (`<button>` ou `<a>`).

```css
igc-button::part(base) {
  background-color: var(--ig-primary-500);
  color: var(--ig-primary-500-contrast);
  padding: 18px;
}
```

## Acessibilidade

O Button {Platform} é um controle interativo para ações e, quando `href` é definido, para navegação.
Use o comportamento nativo de botão para comandos e preserve o comportamento de link para navegação.

### Interação por teclado

O Button usa o comportamento de teclado do controle nativo renderizado. Um Button desabilitado não é
interativo, e um Button com `href` é renderizado como um link, em vez de um botão de comando.

| Tecla | Ação |
| -- | -- |
| Tab / Shift+Tab | Move o foco para o Button ou para longe dele, quando ele pode receber foco pelo teclado. |
| Enter / Space | Ativa um Button de comando com foco. Enter ativa um Button usado como link. |

### Leitores de tela / ARIA

O Button renderiza um `button` nativo para ações de comando e um elemento `a` quando `href` é definido.
O elemento nativo fornece a função e a semântica de teclado apropriadas.

<PlatformBlock for="WebComponents, React, Blazor">

- O conteúdo visível do Button é usado como o seu nome acessível quando contém texto significativo.
- Forneça um `aria-label` ou outro mecanismo de nomeação acessível para um Button somente com ícone.
- Um Button desabilitado expõe o seu estado desabilitado por meio do controle nativo renderizado.
- Os manipuladores de evento de clique do Button executam ações da aplicação; eles não substituem o nome acessível, a função ou o estado do Button.

</PlatformBlock>

<PlatformBlock for="Angular">

- O Button usa o elemento nativo `button` ou `a`, então a tecnologia assistiva recebe a função e a semântica de teclado nativas correspondentes.
- Forneça um `aria-label` ou outro mecanismo de nomeação acessível para um Button somente com ícone.
- Um Button desabilitado não é interativo por teclado.
- Os manipuladores de evento de clique executam ações da aplicação; adicione um nome acessível e um estado separadamente quando a ação não for transmitida pelo conteúdo visível ou pelos atributos nativos.

</PlatformBlock>

### Conformidade de acessibilidade

Este tópico não faz uma declaração de conformidade no nível do produto com WCAG, Seção 508 ou EN 301 549. Verifique o Button renderizado e a aplicação ao redor em relação aos requisitos de acessibilidade aplicáveis ao projeto de destino.

| Critério | Como o componente atende ao requisito |
| -- | -- |
| [2.1.1 Teclado](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | O botão de comando nativo oferece suporte à ativação por teclado, e um Button com `href` usa a ativação nativa de link. |
| [4.1.2 Nome, função, valor](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | O elemento nativo renderizado fornece a semântica de função e de estado. O conteúdo visível do Button fornece o nome acessível quando ele é significativo. |
| [2.4.4 Finalidade do link](https://www.w3.org/WAI/WCAG21/Understanding/link-purpose-in-context) | Quando `href` é definido, o Button se torna um link de navegação; forneça um nome que identifique o seu destino ou finalidade. |

Suas responsabilidades:

- Dê a cada Button um nome acessível significativo, especialmente os Buttons somente com ícone.
- Use um Button de comando para ações e `href` para navegação; não emule um com o outro.
- Não dependa apenas de cor, de estilo ao passar o mouse ou de estilo de foco para comunicar a ação ou o estado.
- Preserve contraste suficiente e um indicador de foco visível ao personalizar o tema do Button.

## Solução de problemas

Use esta seção para conferir os limites e as decisões comuns antes de tratar o Button como um comando, um link de navegação ou um controle de formulário.

### Por que o Button se comporta como um link?

Quando `href` é definido, o Button é usado para navegação, e não para uma ação de comando. Remova `href` quando o controle deve disparar a lógica da aplicação em vez de navegar para uma URL.

### Por que o Button não pode receber foco pelo teclado?

Verifique se o Button está desabilitado ou se a aplicação ao redor altera o comportamento de foco. Use um Button focável para ações que precisam estar disponíveis pela navegação por teclado.

### Limitações conhecidas

O Button tem os seguintes limites independentes de plataforma:

- Use um rótulo de texto ou outro mecanismo de nomeação acessível para cada ação; um Button somente com ícone e sem rótulo não comunica a sua finalidade por si só.
- Definir `href` muda o Button de controle de ação para controle de navegação. Use [Icon Button](./icon-button.mdx) para ações somente com ícone e verifique o seu nome acessível separadamente.
- A aparência visual do Button não determina se a ação da aplicação ao redor está disponível ou válida; a lógica da aplicação deve fornecer esse estado e o feedback correspondente.
