# Visão geral do Query Builder {Platform}

O Query Builder {ProductName} oferece uma interface rica que permite aos desenvolvedores criar consultas complexas de filtragem de dados para um conjunto de dados especificado. Com este componente, você pode montar uma árvore de expressões e especificar condições AND/OR entre as expressões, com editores e listas de condições determinados pelo tipo de dado de cada campo. A árvore de expressões pode então ser facilmente transformada em uma consulta em um formato suportado pelo backend.

## Usando o Query Builder {Platform}

Se nenhuma árvore de expressões for definida inicialmente, você começa escolhendo uma entidade e quais de seus campos a consulta deve retornar. Depois disso, condições ou subgrupos podem ser adicionados.

Para adicionar uma condição, você seleciona um campo, um operando baseado no tipo de dado do campo e um valor, caso o operando não seja unário. Os operandos `In` e `Not In` permitem criar uma consulta interna com condições para outra entidade, em vez de simplesmente informar um valor. Depois que a condição é confirmada, aparece um chip com as informações da condição. Ao clicar ou passar o mouse sobre o chip, você tem opções para modificá-lo ou adicionar outra condição ou grupo logo após ele.

Clicar no botão (AND ou OR) colocado acima de cada grupo abre um menu com opções para alterar o tipo do grupo ou desagrupar as condições dentro dele.

Como cada condição está relacionada a um campo específico de uma entidade determinada, trocar a entidade redefine todas as condições e grupos predefinidos.

Você pode começar a usar o componente definindo a propriedade <ApiLink type="QueryBuilder" member="entities" label="Entities" /> como um array que descreve o nome da entidade e um array dos seus campos, em que cada campo é definido pelo seu nome e tipo de dado. Depois que um campo é selecionado, os operandos correspondentes são atribuídos automaticamente com base no tipo de dado.
O Query Builder tem a propriedade <ApiLink type="QueryBuilder" member="expressionTree" label="ExpressionTree" />. Você pode usá-la para definir um estado inicial do controle e acessar a lógica de filtragem definida pelo usuário.

```ts
public entities: any[] = [];
public ordersFields: any[] = [];
public expressionTree!: IgcExpressionTree;

  this.queryBuilder = document.getElementById('queryBuilder') as IgcQueryBuilderComponent;
  this.initFields();
}

private initFields(): void {
  this.ordersFields = [
    { field: 'orderId', dataType: 'number' },
    { field: 'customerId', dataType: 'string' },
    { field: 'orderDate', dataType: 'date' }
  ];

  this.entities = [
    { name: 'Orders', fields: this.ordersFields }
  ];

  const tree = new IgcFilteringExpressionsTree();
  tree.operator = FilteringLogic.And;
  tree.entity = 'Orders';

  this.expressionTree = tree;
  this.queryBuilder.entities = this.entities;
  this.queryBuilder.expressionTree = this.expressionTree;
}
```

```ts

  this.expressionTree = e.detail;
  this.onExpressionTreeChange();
});
```

## Arrastar expressões

Os chips de condição podem ser facilmente reposicionados por arrastar e soltar com o mouse ou por reordenação pelo teclado. Com isso, os usuários ajustam dinamicamente a lógica da consulta.

- Arrastar um chip não altera a sua condição ou o seu conteúdo, apenas a sua posição.
- O chip também pode ser arrastado ao longo de grupos e subgrupos. Por exemplo, agrupar ou desagrupar expressões é feito pela funcionalidade de arrastar expressões.
Para agrupar condições já existentes, primeiro é preciso adicionar um novo grupo pelo botão de grupo 'add'. Depois, arrastando, as expressões necessárias podem ser movidas para esse grupo. Para desagrupar, você pode arrastar todas as condições para fora do grupo atual; quando a última condição for movida para fora, o grupo será excluído.

<DocsAside type="info">
Chips de uma árvore de consulta não podem ser arrastados para outra, por exemplo, do pai para o interno e vice-versa.
</DocsAside>

<Image src={queryBuilderDragAndDrop} alt="Exemplo animado de arrastar e soltar do Query Builder com o mouse" class="responsive-img" />

## Interação pelo teclado

**Combinações de teclas**

- <kbd>Tab</kbd> / <kbd>Shift + Tab</kbd> - navega para o próximo/anterior chip, indicador de arrastar, botão de remover ou botão de expressão 'add'.
- <kbd>Arrow Down</kbd>/<kbd>Arrow Up</kbd> - quando o indicador de arrastar do chip está com foco, o chip pode ser movido para cima/baixo.
- <kbd>Space</kbd> / <kbd>Enter</kbd> - a expressão com foco entra no modo de edição. Se o chip tiver sido movido, isso confirma a sua nova posição.
- <kbd>Esc</kbd> - a reordenação do chip é cancelada e ele volta à sua posição original.

<DocsAside type="info">
A reordenação pelo teclado oferece a mesma funcionalidade do arrastar e soltar com o mouse. Depois que um chip é movido, o usuário precisa confirmar a nova posição ou cancelar a reordenação.
</DocsAside>

<PlatformBlock for="React, WebComponents">

</PlatformBlock>

<PlatformBlock for="Blazor">

</PlatformBlock>

<DocsAside type="info">
Ao usar `SearchValueTemplate`, você deve fornecer templates para todos os tipos de campo da sua entidade, ou o query builder não funcionará corretamente. É obrigatório implementar um template padrão/de fallback que trate quaisquer campos ou condições não cobertos pelos templates personalizados específicos. Sem isso, os usuários não poderão editar
</DocsAside>
condições desses campos.


<PlatformBlock for="WebComponents">


```ts
constructor() {
  this.queryBuilder = document.getElementById('queryBuilder') as IgcQueryBuilderComponent;
  this.queryBuilder.searchValueTemplate = (ctx) => this.buildSearchValueTemplate(ctx);
}

private buildSearchValueTemplate(ctx: IgcQueryBuilderSearchValueContext) {
  const field = ctx.selectedField?.field;
  const condition = ctx.selectedCondition;
  const matchesEqualityCondition = condition === 'equals' || condition === 'doesNotEqual';

  if (!ctx.implicit) {
      ctx.implicit = { value: null };
  }

  // Custom template for Region field
  if (field === 'Region' && matchesEqualityCondition) {
      return this.buildRegionSelect(ctx);
  }

  // Custom template for OrderStatus field
  if (field === 'OrderStatus' && matchesEqualityCondition) {
      return this.buildStatusRadios(ctx);
  }

  // Custom template for date fields
  if (ctx.selectedField?.dataType === 'date') {
      return this.buildDatePicker(ctx);
  }

  // Custom template for time fields
  if (ctx.selectedField?.dataType === 'time') {
      return this.buildTimeInput(ctx);
  }

  // Default template for all other fields (string, number, boolean, etc.)
  // This ensures all fields have a functioning editor
  return this.buildDefaultInput(ctx);
}
```

```ts
{ field: 'ShipCountry', dataType: 'string' }
{ field: 'OrderID', dataType: 'number' }
{ field: 'IsRushOrder', dataType: 'boolean' }

// Template that handles all these types
private buildDefaultInput(ctx: IgcQueryBuilderSearchValueContext) {
  const dataType = ctx.selectedField?.dataType;
  const isNumber = dataType === 'number';
  const isBoolean = dataType === 'boolean';
  
  const placeholder = ctx.selectedCondition === 'inQuery' || ctx.selectedCondition === 'notInQuery'
    ? 'Sub-query results'
    : 'Value';

  const inputValue = ctx.implicit?.value ?? '';
  const disabledConditions = ['empty', 'notEmpty', 'null', 'notNull', 'inQuery', 'notInQuery'];
  const isDisabled = isBoolean || !ctx.selectedField || disabledConditions.includes(ctx.selectedCondition ?? '');

  return html`
    <igc-input 
      .value=${inputValue}
      ?disabled=${isDisabled}
      placeholder=${placeholder}
      type=${isNumber ? 'number' : 'text'}
      @input=${(event: Event) => {
        const target = event.target as HTMLInputElement;
        ctx.implicit.value = isNumber
          ? target.value === '' ? null : Number(target.value)
          : target.value;
      }}>
    </igc-input>
  `;
}
```

```javascript
        ? 'Sub-query results'
        : 'Value';

    const currentImplicitValue = ctx && ctx.implicit ? ctx.implicit.value : null;
    const currentValue = typeof currentImplicitValue === 'object' && currentImplicitValue && 'text' in currentImplicitValue
        ? equalityCondition ? currentImplicitValue.text : ''
        : currentImplicitValue;

    const inputValue = currentValue == null ? '' : currentValue;
    const disabledConditions = ['empty', 'notEmpty', 'null', 'notNull', 'inQuery', 'notInQuery'];
    const isDisabled = isBoolean || selectedField == null || disabledConditions.includes(ctx.selectedCondition ?? '');

    return html`
      <igc-input 
        .value=${inputValue}
        ?disabled=${isDisabled}
        placeholder=${placeholder}
        type=${isNumber ? 'number' : 'text'}
        @input=${(event) => {
            const target = event.target;
            ctx.implicit.value = isNumber
                ? target.value === '' ? null : Number(target.value)
                : target.value;
        }}>
      </igc-input>
    `;
}
```
