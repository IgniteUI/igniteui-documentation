# Componente Virtual Scroll

O {ProductName} Virtual Scroll é um componente que renderiza listas grandes mantendo no DOM apenas os itens em sua viewport, mais um buffer configurável. A barra de rolagem ainda abrange a coleção inteira; por isso, uma lista virtual de cem mil itens rola como uma lista comum.

O host do Virtual Scroll precisa de uma altura fixa para a rolagem vertical ou de uma largura fixa para a rolagem horizontal. Um host que cresce com o seu conteúdo renderiza todos os itens; assim, a lista não é virtualizada.

## Uso

### Template de item

O template de item do Virtual Scroll recebe o item e a sua posição na coleção inteira. Use o índice e a contagem total para conteúdo que depende da posição, como estilos alternados ou `aria-posinset` e `aria-setsize`.

<PlatformBlock for="Angular">

Marque um `ng-template` com `igxVirtualItem`, ou passe um template definido em outro lugar por meio de <ApiLink type="VirtualScroll" member="itemTemplate" label="itemTemplate" />, que tem precedência. O contexto do template fornece `$implicit` (o item), `index`, `count`, `first`, `last`, `even` e `odd`.

```html
<igx-list>
    <igx-virtual-scroll role="presentation" [data]="employees" [estimatedItemSize]="64" style="height: 480px">
        <ng-template igxVirtualItem let-employee let-index="index" let-count="count">
            <igx-list-item [attr.aria-posinset]="index + 1" [attr.aria-setsize]="count">
                <igx-avatar igxListThumbnail shape="circle" [initials]="employee.initials"></igx-avatar>
                <span igxListLineTitle>{{ employee.name }}</span>
                <span igxListLineSubTitle>{{ employee.email }}</span>
            </igx-list-item>
        </ng-template>
    </igx-virtual-scroll>
</igx-list>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

Defina <ApiLink type="VirtualScroll" member="itemTemplate" label="itemTemplate" /> como uma função que retorna um template Lit. A função recebe um `VirtualScrollItemContext` com `value` (o item), `index`, `count`, `isFirst` e `isLast`. Sem um template de item, o componente não renderiza nada.

```ts
virtualScroll.itemTemplate = (ctx: VirtualScrollItemContext<Employee>) => html`
    <igc-list-item aria-posinset=${ctx.index + 1} aria-setsize=${ctx.count}>
        <igc-avatar slot="start" shape="circle" initials=${ctx.value.initials}></igc-avatar>
        <span slot="title">${ctx.value.name}</span>
        <span slot="subtitle">${ctx.value.email}</span>
    </igc-list-item>
`;
```

</PlatformBlock>

<PlatformBlock for="React">

### Dados

A coleção <ApiLink type="VirtualScroll" member="data" label="data" /> do Virtual Scroll é comparada por referência. Atribua um novo array para atualizar a lista; alterar o array vinculado no próprio lugar, por exemplo com `push`, não a atualiza.

<PlatformBlock for="Angular">

```ts
this.employees = [...this.employees, newEmployee];
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```ts
virtualScroll.data = [...virtualScroll.data, newEmployee];
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
setEmployees(current => [...current, newEmployee]);
```

</PlatformBlock>

Quando `data` muda, o componente mantém os tamanhos medidos dos itens anteriores ao primeiro índice alterado e mede novamente os demais quando forem renderizados. Acrescentar mantém todas as medições existentes; substituir, filtrar ou ordenar descarta as medições a partir do primeiro item alterado.

<PlatformBlock for="React, WebComponents">

Um item mantém o seu elemento enquanto a sua chave estiver na janela renderizada. Sem <ApiLink type="VirtualScroll" member="keyFunction" label="keyFunction" />, o índice é a chave; assim, depois de uma ordenação, uma inserção ou uma remoção, o elemento de um índice permanece no lugar e mostra o seu novo item. Retorne um id estável de `keyFunction` quando os itens se moverem dentro de `data`:

```ts
virtualScroll.keyFunction = (employee) => employee.id;
```

</PlatformBlock>

### Tamanho estimado do item

O <ApiLink type="VirtualScroll" member="estimatedItemSize" label="estimatedItemSize" /> estimado do Virtual Scroll é o tamanho em pixels que um item tem até ser renderizado e medido (`50` por padrão). Os itens podem ter tamanhos diferentes: cada tamanho medido substitui a estimativa.

<PlatformBlock for="Angular">

Defina a estimativa próxima do tamanho médio dos itens para manter a barra de rolagem e o `scrollToIndex` precisos antes de os itens serem medidos.

</PlatformBlock>

<PlatformBlock for="React, WebComponents">

Defina a estimativa próxima do tamanho médio dos itens para que a primeira renderização fique perto do conteúdo real. Depois que os itens são medidos, a média deles substitui a estimativa para os itens que ainda não foram medidos; assim, a barra de rolagem e o `scrollToIndex` se corrigem sozinhos, mesmo quando a estimativa está errada.

</PlatformBlock>

### Rolar até o índice

O método <ApiLink type="VirtualScroll" member="scrollToIndex" label="scrollToIndex" /> do Virtual Scroll rola um item para a área visível. Suas opções são as do `scrollIntoView` nativo: `block` (`start`, `center`, `end` ou `nearest`), `inline` para uma lista horizontal, e `behavior` (`auto` ou `smooth`). Os itens que ainda não foram renderizados têm apenas um tamanho estimado; por isso, o componente mede os itens onde a rolagem cai e corrige a posição. A promise retornada é resolvida na posição final.

<PlatformBlock for="Angular">

```ts
private readonly virtualScroll = viewChild.required(IgxVirtualScrollComponent);

public async goTo(index: number): Promise<void> {
    await this.virtualScroll().scrollToIndex(index, { block: 'center' });
}
```

### Rolagem infinita

<PlatformBlock for="Angular">

A saída <ApiLink type="VirtualScroll" member="dataRequest" label="dataRequest" /> do Virtual Scroll oferece suporte ao carregamento apenas por acréscimo a partir de dados remotos. Ela é emitida quando a janela renderizada se aproxima do fim de `data`, e na primeira renderização, quando os itens carregados não preenchem a viewport. Acrescente os itens solicitados como um novo array:

```html
<igx-virtual-scroll [data]="employees()" [estimatedItemSize]="64" (dataRequest)="loadMore($event)" style="height: 440px">
    <ng-template igxVirtualItem let-employee>...</ng-template>
</igx-virtual-scroll>
```

```ts
public readonly employees = signal<Employee[]>(firstPage);

public loadMore(request: VirtualScrollDataRequest): void {
    this.service.fetch(request.startIndex, request.count).subscribe(page => {
        this.employees.update(current => [...current, ...page]);
    });
}
```

Quando a fonte não tiver mais itens, pare de acrescentar: o componente não solicita novamente o mesmo índice inicial.

### Dados paginados

A entrada <ApiLink type="VirtualScroll" member="dataWindow" label="dataWindow" /> do Virtual Scroll do Angular vincula uma página de uma coleção maior, em vez de `data`. A lista tem o tamanho de `totalCount`; assim, a barra de rolagem abrange a coleção inteira enquanto somente a página fica na memória, e os índices que a página não cobre não renderizam nada.

```ts
interface VirtualDataWindow<T> {
    readonly items: readonly T[]; // the loaded page
    readonly startIndex: number;  // the index of items[0] in the whole collection
    readonly totalCount: number;  // the size of the whole collection
}
```

Carregue a próxima página do intervalo que <ApiLink type="VirtualScroll" member="stateChange" label="stateChange" /> informa. Cancele a requisição anterior, para que uma resposta lenta não substitua uma página mais recente:

```html
<igx-virtual-scroll [dataWindow]="page()" [estimatedItemSize]="64" (stateChange)="onStateChange($event)" style="height: 440px">
    <ng-template igxVirtualItem let-employee>...</ng-template>
</igx-virtual-scroll>
```

```ts
public readonly page = signal<VirtualDataWindow<Employee>>({ items: [], startIndex: 0, totalCount: 100_000 });
private pending?: Subscription;

public onStateChange(state: VirtualScrollState): void {
    const page = this.page();
    if (state.startIndex >= page.startIndex && state.endIndex < page.startIndex + page.items.length) {
        return; // The loaded page already covers the range.
    }

    const startIndex = Math.max(0, state.startIndex - 30);
    const count = state.endIndex + 30 - startIndex + 1;

    this.pending?.unsubscribe();
    this.pending = this.service.fetch(startIndex, count).subscribe(result => {
        this.page.set({ items: result.items, startIndex, totalCount: result.total });
    });
}
```

<Sample src="/data-display/virtual-scroll-paged-data" height={560} alt="Virtual Scroll do Angular carregando páginas de uma coleção remota" />

Os tamanhos medidos são mantidos por índice enquanto `totalCount` permanece o mesmo; uma página com um `totalCount` diferente, como um resultado filtrado, é medida novamente. `dataRequest` não é emitido enquanto `dataWindow` estiver vinculado. O componente armazena uma entrada de tamanho por índice; por isso, sua memória cresce com `totalCount`: cerca de 17 MB para um milhão de itens.

</PlatformBlock>

### Faça/Não faça

O Virtual Scroll normalmente funciona como o contêiner de rolagem de uma lista longa, mantendo no DOM somente os itens da viewport, mais um pequeno buffer. Evite-o para uma lista curta o bastante para ser renderizada de uma vez. Ao escrever o template do item, mantenha o estado de cada item nos dados, e não nos seus elementos: os elementos dos itens são reaproveitados, então um estado no DOM que o template não vincula aparece no item que ocupar o elemento.

## Estilização

O {Platform} Virtual Scroll não tem tema próprio: ele organiza a viewport, e os itens renderizados obtêm os seus estilos dos elementos e componentes do template do item.

.employees igx-virtual-scroll {

</PlatformBlock>

<PlatformBlock for="React, WebComponents">

## Acessibilidade

O {Platform} Virtual Scroll mantém no DOM apenas a janela renderizada; por isso, o template do item precisa expor a posição de cada item em toda a coleção.

### Interação por teclado

O {Platform} Virtual Scroll não adiciona manipuladores de teclas. O host é um contêiner de rolagem nativo, e um contêiner de rolagem com foco rola com as teclas do navegador:

| Tecla | Ação |
| --- | --- |
| Seta para cima / Seta para baixo | Rola uma lista vertical. |
| Seta para a esquerda / Seta para a direita | Rola uma lista horizontal. |
| Page Up / Page Down | Rola aproximadamente uma viewport. |
| Home / End | Rola até o início ou o fim da coleção. |

O host não tem `tabindex`. Os navegadores diferem quanto a um contêiner de rolagem sem conteúdo focável poder receber o foco; por isso, defina `tabindex="0"` no host quando os itens não contiverem nada focável. O foco dentro de um item não sobrevive quando esse item sai da janela renderizada; mova o foco deliberadamente antes que isso aconteça.

### Leitores de tela / ARIA

<PlatformBlock for="Angular">

- O host tem `role="list"`; a trilha, o elemento de conteúdo e os wrappers de item têm `role="presentation"`. Os itens que renderizam `role="listitem"`, como `igx-list-item`, são expostos como itens dessa lista.
- Dentro de um contêiner que já fornece semântica de lista, como `igx-list`, defina `role="presentation"` no host para que os itens não fiquem aninhados em uma segunda lista.
- Mapeie as variáveis de template `index` e `count` para `aria-posinset` e `aria-setsize`.
- Dê um nome acessível a um host focável com `aria-label` ou `aria-labelledby`.

</PlatformBlock>

<PlatformBlock for="React, WebComponents">

- A trilha, o elemento de conteúdo e os wrappers de item têm `role="presentation"`. O host não tem papel: coloque-o dentro de um elemento com um papel de lista, como `igc-list`, ou dê a ele `role="list"` quando os itens renderizarem `role="listitem"`.
- Mapeie as propriedades de contexto `index` e `count` para `aria-posinset` e `aria-setsize`.
- Dê a um host focável um papel que aceite um nome acessível, como `role="list"`, e nomeie-o com `aria-label` ou `aria-labelledby`.

</PlatformBlock>

### Conformidade de acessibilidade

A Infragistics documenta os padrões de acessibilidade que {ProductName} atende no tópico [Conformidade de acessibilidade](../interactivity/accessibility-compliance.mdx). Este tópico não faz nenhuma declaração de conformidade para o Virtual Scroll: a tabela lista o que o componente oferece, e a lista depois dela cobre o que a aplicação precisa acrescentar.

| Critério | Como o componente atende ao requisito |
| --- | --- |
| [1.3.1 Informações e relações](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships) | Os wrappers são apenas apresentacionais; por isso, a estrutura da lista vem do host e do template do item, que pode expor a posição de cada item com `aria-posinset` e `aria-setsize`. |
| [2.1.1 Teclado](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | O host é um contêiner de rolagem nativo que rola com o teclado depois de receber o foco. Alcançá-lo pelo teclado depende da aplicação; veja a lista abaixo. |

Suas responsabilidades:

- Torne o host alcançável pelo teclado com `tabindex="0"` quando os itens não contiverem nada focável, e dê a ele um nome acessível.
- Exponha a posição do item com `aria-posinset` e `aria-setsize` a partir do template do item.
- Forneça semântica de lista compatível com o template do item (consulte [Leitores de tela / ARIA](#leitores-de-tela--aria)).
- Mantenha o estado da aplicação, como uma seleção, nos dados, e não nos elementos dos itens renderizados.

## Solução de problemas

### Por que o Virtual Scroll não renderiza nenhum item?

O host não tem tamanho no eixo de rolagem, o template do item está faltando, ou `data` está vazio. Dê ao host uma altura fixa (vertical) ou uma largura fixa (horizontal), defina o template do item e verifique a coleção vinculada.

### Por que a lista não é atualizada quando adiciono um item?

O Virtual Scroll compara `data` por referência; por isso, uma alteração no próprio lugar não é detectada. Atribua um novo array, por exemplo `[...items, newItem]`.

### Por que a barra de rolagem muda de tamanho enquanto eu rolo?

Os itens que ainda não foram renderizados usam `estimatedItemSize`, e o tamanho total é corrigido à medida que os itens são medidos.

<PlatformBlock for="Angular">

Defina `estimatedItemSize` próximo do tamanho médio dos itens.

</PlatformBlock>

<PlatformBlock for="React, WebComponents">

O tamanho médio medido então substitui a estimativa para os itens que ainda não foram medidos; assim, a correção se estabiliza conforme você rola. Defina `estimatedItemSize` próximo do tamanho médio dos itens para que a primeira renderização fique perto do conteúdo real.

</PlatformBlock>

### Por que os itens saem do lugar mais para o fim da lista?

As margens não fazem parte do tamanho medido de um item. Substitua as margens dos itens por padding, ou por um `gap` dentro do item.

<PlatformBlock for="Angular">

### Por que uma lista dentro de um drop-down ou de um diálogo mostra os seus itens com um quadro de atraso?

Um contêiner que fica oculto até ser aberto não tem tamanho na passagem de detecção de mudanças que o revela; por isso, o host é medido depois dessa renderização, e os itens são renderizados no quadro seguinte. Leia os itens renderizados depois que `layoutComplete` for resolvida.

### Como substituo uma lista igxForOf pelo Virtual Scroll?

O Virtual Scroll mede os itens em tempo de execução e cria o seu próprio contêiner de rolagem; por isso, as entradas de tamanho do contêiner e de contêiner de rolagem de `igxForOf` não têm equivalente. A diretiva `igxForOf` está descontinuada em favor do Virtual Scroll; as listas existentes continuam funcionando, mas use o Virtual Scroll em novas listas que virtualizam um único eixo.

| igxForOf | Virtual Scroll |
| --- | --- |
| `*igxFor="let item of data"` | `[data]="data"` com um `ng-template igxVirtualItem` |
| `igxForScrollOrientation` | `orientation` |
| `igxForContainerSize` | A altura ou a largura do host, definidas com CSS |
| `igxForItemSize` | `estimatedItemSize` (uma estimativa inicial; os itens são medidos) |
| `igxForScrollContainer` | Não é necessário: o host é o contêiner de rolagem |
| `scrollTo(index)` | `scrollToIndex(index, options)`, que retorna uma promise |
| `chunkLoad`, `chunkPreload` | `stateChange` |
| `igxForTotalItemCount` para dados remotos | `dataWindow` com `totalCount`, ou `data` com `dataRequest`, para carregamento apenas por acréscimo |
| `index`, `count`, `first`, `last`, `even`, `odd` | As mesmas variáveis de template |

Os grids mantêm a sua própria virtualização de linhas e colunas; consulte [Virtualização de grid](../grid/virtualization.mdx).

</PlatformBlock>

## Limitações conhecidas

- O {Platform} Virtual Scroll virtualiza um eixo. Linhas e colunas que são ambas virtualizadas exigem um grid.
- Os elementos dos itens são reaproveitados conforme a janela se move; por isso, um estado no DOM que o template do item não vincula, como uma caixa de seleção sem um `checked` vinculado, aparece no item que ocupar o elemento. Vincule todo o estado do item e grave as alterações do usuário de volta no item.

<PlatformBlock for="Angular">

- Com `dataWindow`, uma página que mantém `totalCount`, mas coloca registros diferentes nos mesmos índices, mantém os tamanhos medidos dos registros anteriores até que essas linhas sejam renderizadas novamente.

</PlatformBlock>
