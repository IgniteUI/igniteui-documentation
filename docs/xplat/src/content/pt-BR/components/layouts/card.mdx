# Card

O {ProductName} Card organiza mídia, texto e ações relacionados em um único contêiner de conteúdo flexível.

Use o card para agrupar conteúdo sobre um único assunto, como um produto, um artigo, um contato, um local ou um item de painel.

## Primeiros passos

Para usar o {Platform} Card, siga o <PlatformBlock for="Angular">[{ProductName} Primeiros passos](../general/getting-started.mdx)</PlatformBlock><PlatformBlock for="React,WebComponents,Blazor">[{ProductName} Primeiros passos](../general-getting-started.mdx)</PlatformBlock> tópico para a configuração básica do projeto e, em seguida, registre o componente para a sua plataforma de destino.

<PlatformBlock for="React,WebComponents">

Para {Platform} usando o pacote **{PackageCommon}**, instale o pacote:

```cmd
npm install {PackageCommon}
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

Em seguida, você precisará importar o <ApiLink pkg="core" type="Card" />, o CSS do seu tema e registrar o componente, assim:

```ts
import { defineComponents, IgcCardComponent } from 'igniteui-webcomponents';
import 'igniteui-webcomponents/themes/light/bootstrap.css';

defineComponents(IgcCardComponent);
```

Registrar o card também registra os subcomponentes de cabeçalho, mídia, conteúdo e ações. Registre quaisquer outros componentes usados no conteúdo do card, como avatar, botão e botão de ícone:

```ts
import {
  defineComponents,
  IgcAvatarComponent,
  IgcButtonComponent,
  IgcCardComponent,
  IgcIconButtonComponent,
} from 'igniteui-webcomponents';

defineComponents(IgcCardComponent, IgcAvatarComponent, IgcButtonComponent, IgcIconButtonComponent);
```

</PlatformBlock>

<PlatformBlock for="React">

Em seguida, você precisará importar os wrappers do Card e a folha de estilo CSS do tema, assim:

```tsx
import {
  IgrCard,
  IgrCardActions,
  IgrCardContent,
  IgrCardHeader,
  IgrCardMedia,
} from 'igniteui-react';
import 'igniteui-webcomponents/themes/light/bootstrap.css';
```

Importe quaisquer outros wrappers usados no conteúdo do card, como `IgrAvatar`, `IgrButton` e `IgrIconButton`.

</PlatformBlock>

<PlatformBlock for="Blazor">

Registre os serviços de {ProductName}:

```csharp
// in Program.cs file

builder.Services.AddIgniteUIBlazor();
```

O registro de <ApiLink pkg="core" type="CardModule" />, o módulo de recurso do cliente de <ApiLink pkg="core" type="Card" />, é **opcional**: o componente carrega seus recursos na primeira vez em que é renderizado. Listá-lo em `builder.Services.AddIgniteUIBlazor(typeof(IgbCardModule))` pode ser usado para pré-carregar recursos ou para dar suporte a elementos criados somente no cliente (veja [Módulos do componente](../general-getting-started.mdx#módulos-do-componente)).

Você também precisará vincular um arquivo CSS adicional para aplicar o estilo ao componente <ApiLink pkg="core" type="Card" />. O seguinte deve ser colocado na página host da aplicação (**wwwroot/index.html** em uma aplicação Blazor WebAssembly independente ou Blazor Hybrid, **Pages/_Host.cshtml** em uma aplicação Blazor Server, **Components/App.razor** em uma aplicação Blazor Web App):

```razor
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
```

</PlatformBlock>

<PlatformBlock for="Angular">

Para Angular usando o pacote **igniteui-angular**, instale o pacote:

```cmd
npm install igniteui-angular
```

Depois, importe o token `IGX_CARD_DIRECTIVES` da coleção `imports` do componente. O token traz o card junto com todos os seus componentes e diretivas de apoio.

```ts
import { IGX_CARD_DIRECTIVES } from 'igniteui-angular/card';
```

Importe quaisquer outras diretivas usadas no conteúdo do card, como `IgxButtonDirective`, `IgxIconButtonDirective`, `IgxIconComponent` e `IgxRippleDirective`, a partir de `igniteui-angular`.

</PlatformBlock>

### Slots do cabeçalho

Use os slots do cabeçalho para definir miniatura, título, subtítulo e conteúdo adicional do cabeçalho.

<PlatformBlock for="WebComponents">

```html
<igc-card-header>
  <igc-avatar slot="thumbnail" initials="TS"></igc-avatar>
  <h3 slot="title">Title</h3>
  <span slot="subtitle">Subtitle</span>
</igc-card-header>
```

</PlatformBlock>

<PlatformBlock for="Angular">

```html
<igx-card-header>
  <div igxCardThumbnail>
    <igx-icon>place</igx-icon>
  </div>
  <h3 igxCardHeaderTitle>Title</h3>
  <span igxCardHeaderSubtitle>Subtitle</span>
</igx-card-header>
```

</PlatformBlock>

<PlatformBlock for="React">

```tsx
<IgrCardHeader>
  <IgrAvatar slot="thumbnail" initials="TS" />
  <h3 slot="title">Title</h3>
  <span slot="subtitle">Subtitle</span>
</IgrCardHeader>
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```razor
<IgbCardHeader>
  <IgbAvatar slot="thumbnail" Initials="TS" />
  <h3 slot="title">Title</h3>
  <span slot="subtitle">Subtitle</span>
</IgbCardHeader>
```

</PlatformBlock>

<PlatformBlock for="WebComponents, React, Blazor">

Passe um elemento de título, como `<h3>`, para o slot `title`, para que o card ocupe seu lugar no esboço do documento, e use um elemento inline neutro, como `<span>`, para o `subtitle`. O cabeçalho redefine a margem e a fonte do conteúdo inserido em slot, então o título mantém a tipografia do card.

</PlatformBlock>

<PlatformBlock for="Angular">

Aplique `igxCardHeaderTitle` a um elemento de título, como `<h3>`, para que o card ocupe seu lugar no esboço do documento, e aplique `igxCardHeaderSubtitle` a um elemento inline neutro, como `<span>`.

</PlatformBlock>

### Layout

Use wrappers de layout quando as seções do card precisarem ser organizadas na horizontal ou divididas entre as áreas de mídia e de conteúdo.

Para um card horizontal, agrupe o cabeçalho e o conteúdo em um único wrapper, coloque as ações ao lado desse wrapper e aplique uma linha flex ao conteúdo do card.

<PlatformBlock for="WebComponents">

```html

  <div class="card-horizontal">
    <div>
      <igc-card-header>
        <img src="https://dl.infragistics.com/x/img/music/rozes.jpg" slot="thumbnail" alt="Rozes album cover" />

        <span slot="subtitle">Under the Grave (2016)</span>
      </igc-card-header>
      <igc-card-content>

      </igc-card-content>
```

## Acessibilidade

O card é um contêiner. A semântica de agrupamento e de mídia vem das regiões do card, enquanto a operabilidade pelo teclado e os nomes acessíveis vêm do conteúdo que você coloca dentro delas.

### Interação por teclado

O card e suas regiões de cabeçalho, mídia, conteúdo e ações não declaram manipuladores de teclado e não estão na ordem de tabulação. O foco passa pelo conteúdo focável que você coloca dentro delas, na ordem do DOM.

| Tecla | Ação |
| -- | -- |
| <kbd>Tab</kbd> | Move o foco para o próximo elemento focável dentro do card, como um botão ou link na área de conteúdo ou de ações. |
| <kbd>Shift</kbd> + <kbd>Tab</kbd> | Move o foco para o elemento focável anterior dentro do card. |

A área de ações sempre renderiza sua região inicial, depois seu conteúdo centralizado e, por fim, sua região final. Mudar as ações para um layout vertical altera o estilo sem reordenar o DOM, então a ordem para o teclado e para leitores de tela permanece a mesma.

### Leitores de tela / ARIA

<PlatformBlock for="Angular">

- O host do card renderiza `role="group"` e um `id` gerado na forma `igx-card-1`. Defina a entrada `role` quando outro papel de agrupamento se adequar à sua arquitetura de informação, e referencie o título do card com `aria-labelledby` para que o grupo tenha um nome acessível.
- `igx-card-media` renderiza `role="img"`, que expõe a região de mídia inteira como uma única imagem e torna seus filhos apresentacionais; assim, um atributo `alt` na imagem interna não a nomeia. Dê nome à própria região com `aria-label` ou `aria-labelledby`, ou defina a sua entrada `role` como `presentation` quando a mídia for decorativa.
- Os membros de cabeçalho, título, subtítulo, conteúdo e ações adicionam apenas classes de estilo. Eles não contribuem com papéis nem com atributos `aria-*`.
- Dê um nome acessível aos botões somente com ícone na área de ações; o ícone sozinho não fornece nenhum.
- Use um único elemento interativo quando o card inteiro disparar uma ação, em vez de anexar um manipulador de clique ao contêiner, para que a ação mantenha um papel e um nome.

</PlatformBlock>

<PlatformBlock for="WebComponents, React, Blazor">

- O card e cada região do card renderizam slots simples e não definem atributos `role` ou `aria-*`. Os elementos wrapper dentro do cabeçalho não têm nome acessível e não criam marcos. Adicione você mesmo um papel e um nome acessível no host do card quando a sua arquitetura de informação precisar disso.
- Os slots `title` e `subtitle` renderizam o elemento que você passar e não impõem um nível de título.
- Adicione texto `alt` às imagens da região de mídia.
- Dê um nome acessível aos botões somente com ícone na área de ações; o ícone sozinho não fornece nenhum.
- Use um único elemento interativo quando o card inteiro disparar uma ação, em vez de anexar um manipulador de clique ao contêiner, para que a ação mantenha um papel e um nome.

</PlatformBlock>

## Perguntas frequentes

<Faq>
  <FaqItem question="Como torno um card inteiro clicável sem prejudicar os leitores de tela?" indicatorPosition="end">
    O card é um contêiner simples e não adiciona comportamento interativo; por isso, envolver o card inteiro em um link é um atalho comum, mas prejudicial: o nome acessível desse link passa a ser todo o texto do card. Em vez disso, coloque um link ou botão real no título do card e depois estique-o sobre o card com um pseudoelemento posicionado de forma absoluta que cubra a caixa do card. O título continua sendo o nome acessível, todo o retângulo continua clicável, e a seleção de texto e o clique com o botão do meio continuam funcionando.
  </FaqItem>
  <FaqItem question="Como faço para que os cards em uma linha ou grade tenham a mesma altura?" indicatorPosition="end">
    O card se dimensiona pelo seu conteúdo e não iguala as alturas dos irmãos. Organize os cards em uma grade CSS ou em uma linha flex, para que cada card se estique até a altura da linha; dê à região de mídia uma altura fixa ou `aspect-ratio`, e limite o título e o corpo a um número definido de linhas com `-webkit-line-clamp`. Alturas desiguais de card quase sempre vêm de deixar cada imagem e cada parágrafo definir a própria altura.
  </FaqItem>
  <FaqItem question="Por que a imagem do meu card está cortada, e como controlo o seu tamanho?" indicatorPosition="end">
    <PlatformBlock for="WebComponents, React, Blazor">A região de mídia do card estica o conteúdo para a largura e a altura totais da região e aplica `object-fit: cover`, de modo que a imagem é cortada em vez de distorcida. Dimensione a própria região de mídia com `height` ou `aspect-ratio` em CSS; alterar as dimensões da imagem interna não tem efeito.</PlatformBlock><PlatformBlock for="Angular">A região de mídia do card controla as dimensões da mídia que contém; por isso, dimensione a região, não a imagem. Defina as entradas `height` e `width` em `igx-card-media`, e use uma proporção consistente entre os cards para que as linhas de cards permaneçam alinhadas.</PlatformBlock>
  </FaqItem>
  <FaqItem question="Por que as ações do meu card aparecem em uma região diferente daquela em que as coloquei?" indicatorPosition="end">
    <PlatformBlock for="Angular">A área de ações do card projeta o conteúdo por seletor, não pela ordem em que o autor o escreveu. Um elemento com `igxButton` e sem `igxEnd` vai para a região inicial, e um elemento com `igxIconButton`, ou um `igx-icon`, sem `igxStart` vai para a região final; somente o conteúdo que não corresponde a nenhum dos seletores permanece centralizado. Defina `igxStart` ou `igxEnd` explicitamente para posicionar uma ação onde você quiser.</PlatformBlock><PlatformBlock for="WebComponents, React, Blazor">O conteúdo no slot `end` das ações do card recebe uma margem inicial automática para se alinhar à borda oposta da área de ações, o que faz uma única ação final parecer separada das demais. Mova o elemento para o slot `start` ou para o slot padrão quando ele pertencer ao grupo das outras ações. As três regiões sempre são renderizadas na ordem `start`, padrão, `end`, independentemente da orientação.</PlatformBlock>
  </FaqItem>
  <FaqItem question="Quando devo usar Grid ou List em vez de Card?" indicatorPosition="end">
    Use Grid quando os dados forem densos e tabulares, e os leitores precisarem examinar, ordenar ou comparar entre colunas; use List quando muitas linhas curtas e uniformes precisarem caber em um espaço pequeno. Use Card quando cada item merecer mídia própria, texto mais longo e ações próprias. Uma longa rolagem de cards geralmente é uma lista disfarçada.
  </FaqItem>
