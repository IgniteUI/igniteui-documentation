# Temas no {ProductName}

O {ProductName} vem com quatro temas distintos: Bootstrap, Material, Fluent e Indigo. Todos os temas de componentes estão incorporados aos componentes; no entanto, é necessária uma folha de estilo global para que as paletas, a tipografia e outras configurações globais funcionem.

## Carregando um tema

Para habilitar um tema, um arquivo de tema deve ser carregado. Dependendo da configuração do seu projeto, você pode `import` ou `link`.

## Troca de tema em tempo de execução

<DocsAside type="info">
Alterar o tema em tempo de execução também exige substituir a folha de estilo global da tabela acima.
</DocsAside>

O {ProductName} permite trocar os temas dos componentes em tempo de execução usando a função `ConfigureTheme` exportada pela biblioteca.

Ela recebe o tema como primeiro argumento — `bootstrap`, `material`, `fluent` ou `indigo` — e uma variante opcional como segundo, `light` ou `dark`. Omita a variante para manter a que estiver ativa no momento.

```ts
import { configureTheme } from "igniteui-webcomponents";

// Sets material as the theme to be used by all components
configureTheme("material");

// Sets material and switches to its dark variant
configureTheme("material", "dark");
```

<DocsAside type="info">
Isso apenas informa aos componentes para trocar os seus estilos internos para o tema desejado; você também deve trocar o arquivo de tema global para um dos arquivos listados acima.
</DocsAside>

</PlatformBlock>

## Personalizando com Sass

Os arquivos de tema acima são CSS pré-compilado, e os tópicos desta seção os personalizam sobrescrevendo variáveis CSS — consulte [Paletas](palettes.mdx), [Tipografia](typography.mdx), [Elevações](elevations.mdx) e [Configuração](configuration.mdx). Esse caminho não exige nenhuma configuração de build e cobre a maioria das personalizações.

Os temas pré-compilados são gerados a partir do `igniteui-theming`, a biblioteca Sass por trás de cada tema {ProductName}, e a mesma biblioteca está disponível para a sua aplicação. Alguns recursos só são acessíveis por ela, porque são executados em tempo de compilação, e não por meio de uma variável:

- Gerar uma paleta a partir das suas próprias cores-semente, conforme descrito em [Geração de paleta](palette-generation.mdx).
- As funções de contraste e de paleta de gráficos do tópico [Acessibilidade](accessibility.mdx).

Um build Sass com `igniteui-theming` produz CSS simples: uma folha de estilo com variáveis `--ig-*`, que você carrega depois do arquivo de tema, da mesma forma que carrega as suas próprias sobrescritas CSS. O seu framework só precisa de uma forma de executar o compilador Sass. Instale os dois pacotes:

```cmd
npm install igniteui-theming sass --save-dev
```

Em seguida, importe a biblioteca em um arquivo `.scss`:

```scss
@use 'igniteui-theming' as *;

// Required for $material-type-scale, $indigo-type-scale, and similar preset variables
@use 'igniteui-theming/sass/typography/presets' as *;

// Required for $material-elevations and $indigo-elevations
@use 'igniteui-theming/sass/elevations/presets' as *;

:root {
  @include palette(palette($primary: #0099ff, $secondary: #df1b74, $surface: #ffffff));
}
```

### Compilando a folha de estilo

<PlatformBlock for="React">

Vite e Next.js compilam imports `.scss` assim que o pacote `sass` estiver instalado. Importe a folha de estilo depois do arquivo de tema:

```tsx
import 'igniteui-react-grids/grids/themes/light/bootstrap.css';
import './theme.scss';
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

O Vite compila imports `.scss` assim que o pacote `sass` estiver instalado, e o webpack faz o mesmo por meio de `sass-loader`. Importe a folha de estilo depois do arquivo de tema:

```ts
import 'igniteui-webcomponents/themes/light/bootstrap.css';
import './theme.scss';
```

</PlatformBlock>

<PlatformBlock for="Blazor">

Um projeto Blazor não tem um bundler JavaScript; por isso, compile a folha de estilo com a linha de comando do Sass, por exemplo a partir de um script npm ou de uma etapa de pré-build, e grave o resultado em `wwwroot`:

```cmd
npx sass --load-path=node_modules Styles/theme.scss wwwroot/css/theme.css
```

Vincule o arquivo compilado depois do arquivo de tema na sua página hospedeira:

```html
<link href="_content/IgniteUI.Blazor/themes/light/bootstrap.css" rel="stylesheet" />
<link href="css/theme.css" rel="stylesheet" />
```

</PlatformBlock>

<PlatformBlock for="React, WebComponents">

Qualquer outra ferramenta de build funciona da mesma forma, e a linha de comando do Sass também. Quando nada mais compila Sass, execute-o como uma etapa separada e carregue a saída como qualquer arquivo CSS:

```cmd
npx sass --load-path=node_modules src/theme.scss public/theme.css
```

</PlatformBlock>

<DocsAside type="note">
Se `@use 'igniteui-theming' as *;` não for resolvido, o seu compilador Sass não tem `node_modules` nos seus load paths. Passe `--load-path=node_modules` para a linha de comando do Sass, defina `css.preprocessorOptions.scss.loadPaths` no Vite ou defina `sassOptions.loadPaths` no Next.js.
</DocsAside>

### Sem um toolchain Sass

A saída não precisa ser recompilada junto com a sua aplicação. Compile a folha de estilo uma vez e faça commit do CSS; depois, recompile-a somente quando alterar o Sass. O [servidor MCP de temas](../ai/theming-mcp.mdx) também pode gerar paletas e temas de componentes como CSS pronto para uso, sem um compilador Sass local.
