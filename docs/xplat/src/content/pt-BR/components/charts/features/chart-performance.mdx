# Desempenho de gráfico de {Platform}

Os gráficos {Platform} são otimizados para alto desempenho na renderização de milhões de pontos de dados e na atualização deles a cada poucos milissegundos. No entanto, há vários recursos de gráfico que afetam o desempenho do gráfico e devem ser considerados ao otimizar o desempenho da sua aplicação. Este tópico vai orientar você a fazer os gráficos {Platform} funcionarem o mais rápido possível na sua aplicação.

## Exemplos de desempenho de gráfico de {Platform}

Os exemplos a seguir demonstram dois cenários de alto desempenho dos gráficos {Platform}.

## Gráfico de {Platform} com alta frequência

No cenário de alta frequência, os gráficos {Platform} podem renderizar itens de dados que são atualizados em tempo real ou em intervalos de milissegundos especificados. Você não vai sentir atrasos, cintilação de tela nem demoras visuais, mesmo ao interagir com o gráfico em um dispositivo de toque. O exemplo a seguir demonstra o `CategoryChart` no cenário de alta frequência.

<Sample src="/charts/category-chart/high-frequency" height={400} alt="Gráfico de {Platform} com alta frequência" />




## Gráfico de {Platform} com grande volume

No cenário de grande volume, os gráficos {Platform} podem renderizar 1 milhão de pontos de dados, mantendo o desempenho suave quando o usuário final faz zoom in/out ou navega pelo conteúdo do gráfico. O exemplo a seguir demonstra o `CategoryChart` no cenário de grande volume.

## Diretrizes gerais de desempenho

Esta seção lista diretrizes e recursos de gráfico que aumentam a sobrecarga e o processamento das atualizações nos gráficos {Platform}.

### Tamanho dos dados

Se você precisar plotar fontes de dados com grande número de pontos de dados (por exemplo, mais de 10.000), recomendamos usar {Platform} `DataChart` com um dos seguintes tipos de série, projetados especialmente para essa finalidade.
<PlatformBlock for="Web">
- [Gráfico Scatter HD](../types/scatter-chart.mdx#gráfico-de-alta-densidade-de-dispersão-de-{PlatformLower}) em vez de [Gráfico de pontos de categoria](../types/point-chart.mdx) ou [Gráfico de marcadores de dispersão](../types/scatter-chart.mdx#gráfico-de-dispersão-com-marcadores-de-{PlatformLower})</PlatformBlock>
- [Gráfico de polilinha de dispersão](../types/shape-chart.mdx#gráfico-de-polilinha-de-dispersão-de-{PlatformLower}) em vez de [Gráfico de linhas de categoria](../types/line-chart.mdx#exemplo-de-gráfico-de-linhas-de-{PlatformLower}) ou [Gráfico de linhas de dispersão](../types/scatter-chart.mdx#gráfico-de-linhas-de-dispersão-de-{PlatformLower})
- [Gráfico de polígonos de dispersão](../types/shape-chart.mdx#gráfico-de-polígonos-de-dispersão-de-{PlatformLower}) em vez de [Gráfico de áreas de categoria](../types/area-chart.mdx#exemplo-de-gráfico-de-área-de-{PlatformLower}) ou [Gráfico de colunas](../types/column-chart.mdx#exemplo-de-gráfico-de-colunas-de-{PlatformLower})

### Estrutura dos dados

Embora os gráficos {Platform} ofereçam suporte à renderização de várias fontes de dados, vinculando um array de arrays de pontos de dados à propriedade `DataSource`, os gráficos são muito mais rápidos se várias fontes de dados forem achatadas em uma única fonte de dados, em que cada item de dados contém várias colunas de dados em vez de apenas uma. Por exemplo:

<PlatformBlock for="Xaml">

```csharp
this.CategoryChart.ItemsSource = FlattenDataSource.Create();

public static class FlattenDataSource
{
    public static List<FlattenDataItem> Create() {
        var data = new List<FlattenDataItem>() {
            new FlattenDataItem { Year = "1996", USA = 148, CHN = 110 },
            new FlattenDataItem { Year = "2000", USA = 142, CHN = 115 },
        };
        return data;
    }
    public class FlattenDataItem
    {
        public int USA { get; set; }
        public int CHN { get; set; }
        public string Year { get; set; }
    }
}
// instead of this data structure:
public static class MultiDataSources
{
    public static List<List<MultiDataItem>> Create() {
        var dataSource1 = new List<MultiDataItem>() {
            new MultiDataItem { Year = "1996", Value = 148 },
            new MultiDataItem { Year = "2000", Value = 142 },
        };
        var dataSource2 = new List<MultiDataItem>() {
            new MultiDataItem { Year = "1996", Value = 110 },
            new MultiDataItem { Year = "2000", Value = 115 },
        };
        var multipleSources = new List<List<MultiDataItem>>();
        multipleSources.Add(dataSource1);
        multipleSources.Add(dataSource2);
        return multipleSources;
    }
    public class MultiDataItem
    {
        public int Value { get; set; }
        public string Year { get; set; }
    }
}
```

### Filtragem de dados

{Platform} `CategoryChart`<PlatformBlock for="Web"> e os controles `FinancialChart` têm</PlatformBlock><PlatformBlock for="WinUI, Uno"> o controle tem</PlatformBlock> um adaptador de dados integrado que analisa os seus dados e gera séries de gráfico para você. No entanto, ele funciona mais rápido se você usar `includedProperties` e `excludedProperties` para filtrar apenas as colunas de dados que você realmente quer renderizar. Por exemplo,


```json-snippet channel="code"
{
    "$styleOptions": { "qualifyCodeBehindFields": true },
    "skipAlterDataCasing": true,
    "descriptions": {
        "content": {
            "type": "CategoryChart",
            "name": "Chart",
            "includedProperties": [
                "Year",
                "USA",
                "RUS"
            ],
            "$includedProperties": "+perf:code",
            "excludedProperties": [
                "CHN",
                "FRN",
                "GER"
            ],
            "$excludedProperties": "+perf:code"
        }
    }
}
```

### Animações do gráfico

Habilitar as [Animações de gráfico](chart-animations.mdx) vai atrasar um pouco a renderização final das séries nos gráficos {Platform} enquanto elas executam as animações de transição de entrada.

### Anotações do gráfico

Habilitar as [Anotações de gráfico](chart-annotations.mdx), como as Anotações de callout, as Anotações de linha de mira ou as Anotações de valor final, vai reduzir um pouco o desempenho do gráfico {Platform}.

### Destaque do gráfico

Habilitar o [Destaque de gráfico](chart-highlighting.mdx) vai reduzir um pouco o desempenho do gráfico {Platform}.

### Legenda do gráfico

Adicionar uma legenda aos gráficos {Platform} pode reduzir o desempenho se os títulos das séries ou dos itens de dados vinculados à legenda mudarem com frequência em tempo de execução.

### Marcadores do gráfico

Nos gráficos {Platform}, os [Marcadores](chart-markers.mdx) são especialmente custosos para o desempenho do gráfico, porque aumentam a complexidade do layout do gráfico e realizam a vinculação de dados para obter certas informações. Além disso, os marcadores reduzem o desempenho quando há muitos pontos de dados ou muitas fontes de dados vinculadas. Portanto, se os marcadores não forem necessários, devem ser removidos do gráfico.

Este trecho de código mostra como remover marcadores dos gráficos {Platform}.

```json-snippet channel="code"
{
    "$styleOptions": { "qualifyCodeBehindFields": true },
    "type": "CategoryChart",
    "name": "Chart",
    "$comments": { "markerTypes": "on CategoryChart or FinancialChart" },
    "markerTypes": [ "None" ],
    "$markerTypes": "+perf:code"
}
```

```json-snippet channel="code"
{
    "$styleOptions": { "qualifyCodeBehindFields": true },
    "type": "DataChart",
    "name": "Chart",
    "series": [
        {
            "type": "LineSeries",
            "name": "LineSeries",
            "$comments": { "markerType": "on LineSeries of DataChart" },
            "markerType": "None",
            "$markerType": "+perf:code"
        }
    ]
}
```


### Resolução do gráfico

Definir a propriedade `DomainChart.resolution` com um valor mais alto vai melhorar o desempenho, mas vai reduzir a fidelidade gráfica das linhas das séries plotadas. Por isso, ela pode ser aumentada até o ponto em que a fidelidade se torne inaceitável.

Este trecho de código mostra como reduzir a resolução nos gráficos {Platform}.

```json-snippet channel="code"
{
    "$styleOptions": { "qualifyCodeBehindFields": true },
    "type": "CategoryChart",
    "name": "Chart",
    "$comments": { "resolution": "on CategoryChart" },
    "resolution": 10,
    "$resolution": "+perf:code"
}
```

```json-snippet channel="code"
{
    "$styleOptions": { "qualifyCodeBehindFields": true },
    "type": "DataChart",
    "name": "Chart",
    "series": [
        {
            "type": "LineSeries",
            "name": "LineSeries",
            "$comments": { "resolution": "on LineSeries of DataChart" },
            "resolution": 10,
            "$resolution": "+perf:code"
        }
    ]
}
```

### Tipos de eixo

Não se recomenda usar um eixo X com suporte a DateTime se os espaços entre os pontos de dados, com base no intervalo de tempo entre eles, não forem importantes. Em vez disso, deve-se usar um eixo ordinal/de categoria, porque ele é mais eficiente na forma como agrupa os dados. Além disso, o eixo ordinal/de categoria não faz nenhuma ordenação dos dados, como faz o eixo X baseado em tempo.

<DocsAside type="info">
O `CategoryChart` já usa um eixo ordinal/de categoria, por isso não há necessidade de alterar as propriedades dele.
</DocsAside>
<PlatformBlock for="Web">
Este trecho de código mostra como definir o eixo X ordinal/de categoria nos controles `FinancialChart` e `DataChart`.

```json-snippet
{
    "skipAlterDataCasing": true,
    "descriptions": {
        "financialChart": {
            "type": "FinancialChart",
            "xAxisMode": "Ordinal"
        },
        "dataChart": {
            "type": "DataChart",
            "axes": [
                { "type": "CategoryXAxis", "label": "Time" }
            ]
        }
    }
}
```

</PlatformBlock><PlatformBlock for="WinUI, Uno">
Este trecho de código mostra como definir o eixo X ordinal/de categoria no controle `DataChart`.

```json-snippet

            "type": "DataChart",

        }
    }
}
```

</PlatformBlock>


### Intervalos do eixo

Por padrão, os gráficos {Platform} calculam automaticamente o `yAxisInterval` com base no intervalo dos seus dados. Por isso, evite definir o intervalo do eixo, especialmente com um valor pequeno, para não renderizar linhas de grade e rótulos de eixo em excesso. Além disso, você pode considerar aumentar a propriedade `yAxisInterval` para um valor maior que o intervalo de eixo calculado automaticamente, se não precisar de muitas linhas de grade ou rótulos de eixo.

<DocsAside type="info">
Não recomendamos definir o intervalo secundário do eixo, pois isso reduz o desempenho do gráfico.
</DocsAside>

Este trecho de código mostra como definir o intervalo principal do eixo nos gráficos {Platform}.

```json-snippet
        "yAxisInterval": 50

    {

        "yAxisInterval": 50
    },
    {
        "type": "DataChart",
        "axes": [
            {
                "type": "CategoryXAxis",
                "name": "xAxis",
                "interval": 5
            },
            {
                "type": "NumericYAxis",
                "name": "yAxis",
                "interval": 50
            }
        ]
    }
]
```

### Escala do eixo

Recomenda-se definir a propriedade `yAxisIsLogarithmic` como false para obter maior desempenho, pois são necessárias menos operações do que para calcular o intervalo do eixo e os valores dos rótulos do eixo em escala logarítmica.

### Visibilidade dos rótulos do eixo

## Desempenho no Financial Chart

Além das diretrizes de desempenho acima, o controle {Platform} `FinancialChart` tem os seguintes recursos exclusivos que afetam o desempenho.

### Modo do eixo Y

Recomenda-se definir a opção `yAxisMode` como `Numeric` para obter maior desempenho, pois são necessárias menos operações do que com o modo `LineSeries.percentChange`.

### Painéis do gráfico

Definir muitos painéis usando as opções `indicatorTypes` e `overlayTypes` pode reduzir o desempenho; recomenda-se usar alguns indicadores financeiros e uma sobreposição financeira.

### Zoom Slider

Definir a opção `zoomSliderType` como `None` vai melhorar o desempenho do gráfico e liberar mais espaço vertical para outros indicadores e para o painel de volume.

### Tipo de volume

Definir a propriedade `volumeType` pode ter o seguinte impacto no desempenho do gráfico:

- `None` - é o mais econômico, porque não exibe o painel de volume.
- `Line` - é um tipo de volume mais custoso para renderizar, e é recomendado ao renderizar muitos pontos de dados ou ao plotar muitas fontes de dados.
- `Area` - é mais custoso para renderizar do que o tipo de volume `Line`.
- `Column` - é mais custoso para renderizar do que o tipo de volume `Area` e é recomendado ao renderizar dados de volume de 1 a 3 ações.
</PlatformBlock>
## Desempenho no Data Chart

Além das diretrizes gerais de desempenho, o controle {Platform} `DataChart` tem os seguintes recursos exclusivos que afetam o desempenho.

### Coleção de eixos

Adicionar eixos demais à coleção `Axes` do controle `DataChart` reduzirá o desempenho do gráfico, por isso recomendamos [Compartilhar eixos](chart-axis-layouts.mdx#exemplo-de-compartilhamento-de-eixo) entre as séries.

### Coleção de séries

Além disso, adicionar muitas séries à coleção `Series` do controle {Platform} `DataChart` aumenta a sobrecarga de renderização, porque cada série tem sua própria tela de renderização. Isso é especialmente importante se houver mais de 10 séries no Data Chart. Recomendamos combinar várias fontes de dados em uma fonte de dados achatada (veja a seção [Estrutura dos dados](#estrutura-dos-dados)) e, em seguida, usar o recurso de estilização condicional das séries a seguir:

| Cenário de desempenho mais lento | Cenário mais rápido com estilização condicional |
| ----------------------------|---------------------------------------- |
| 10+ de `LineSeries`         | `ScatterLineSeries` única |
| 20+ de `LineSeries`         | `ScatterPolylineSeries` única |
| 10+ de `ScatterLineSeries`  | `ScatterPolylineSeries` única |
| 10+ de `PointSeries`        | `ScatterSeries` única |<PlatformBlock for="Web">
| 20+ de `PointSeries`        | `HighDensityScatterSeries` única |
| 20+ de `ScatterSeries`      | `HighDensityScatterSeries` única |</PlatformBlock>
| 10+ de `AreaSeries`         | `ScatterPolygonSeries` única |
| 10+ de `ColumnSeries`       | `ScatterPolygonSeries` única |
