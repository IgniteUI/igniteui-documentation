# Treemap de {Platform}

O gráfico Treemap {ProductName} exibe dados hierárquicos (com estrutura de árvore) como um conjunto de nós aninhados. Cada ramo da árvore recebe um nó de treemap, que é então preenchido com nós menores que representam os subramos. O retângulo de cada nó tem uma área proporcional a uma dimensão específica dos dados. Com frequência, os nós são coloridos para mostrar uma dimensão separada dos dados.

## Recomendações para o Treemap

### Os Treemaps {Platform} são adequados para o seu projeto?

Quando as dimensões de cor e tamanho se correlacionam de alguma forma com a estrutura da árvore, é possível perceber padrões com facilidade, que seriam difíceis de notar de outras maneiras. Vantagem adicional dos treemaps: por construção, eles usam o espaço de forma eficiente. Assim, podem exibir de modo legível milhares de itens na tela ao mesmo tempo.

- Treemaps são mais eficazes do que gráficos de pizza e outras formas de gráfico de área, que muitas vezes classificam mal os pontos de dados e comunicam mal as diferenças relativas entre os valores.
- Treemaps são projetados para cenários de detalhamento (drill-down). Você pode detalhar continuamente o conjunto de dados representado por retângulos menores, para uma análise de dados mais eficiente.
- Treemaps não foram projetados para transmitir quantidades numéricas; a intenção é mostrar classificações relativas.

Como qualquer outra visualização de dados, a visualização em Treemap deve ser usada em cenários específicos. Ela não resolve o mesmo problema que uma visualização como um Gráfico de barras ou um Gráfico de linhas. Ela se destina a uma exibição de dados mais complexa e rica.

### Casos de uso do Treemap

Há vários casos de uso comuns para escolher um Treemap. Quando você:

- Tem dados hierárquicos de detalhamento (dados organizados como uma árvore, com ramos e subramos).
- Quer ilustrar hierarquias de peso relativo e valores comparativos entre categorias (ramos) e subcategorias (subramos).
- Quer exibir grandes conjuntos de dados que precisam de uma visualização compacta e econômica em espaço.
- Quer oferecer uma análise de dados rápida, de relance, sem valores precisos. O tamanho relativo dos retângulos ajuda a identificar padrões e/ou valores atípicos muito rapidamente.
- Quer usar o espaço de forma eficiente. Os treemaps podem exibir de modo legível milhares de itens na tela ao mesmo tempo.

### Quando não usar um Treemap

- Você está contando uma história com dados que exige valores precisos
- Você tem valores de dados negativos
- Você tem dados planos, não hierárquicos
- Seus dados têm tamanhos semelhantes

### Estrutura de dados do Treemap

- A fonte de dados deve ser um array ou uma lista de itens de dados
- A fonte de dados deve conter pelo menos um item de dados; caso contrário, o mapa não renderizará nenhum nó.
- Todos os itens de dados devem conter pelo menos uma coluna de dados (por exemplo, texto), que deve ser mapeada para a propriedade `labelMemberPath`.
- Todos os itens de dados devem conter pelo menos uma coluna de dados numérica, que deve ser mapeada usando a propriedade `valueMemberPath`.
- Para categorizar os dados em blocos organizados, você pode usar opcionalmente `parentIdMemberPath` e `idMemberPath`.

### Tipos de layout

O gráfico Treemap exibe o peso relativo dos dados. Ele usa vários algoritmos para determinar como o layout dos seus itens de dados deve ocorrer:

- `SliceAndDice` - o algoritmo de layout busca preservar a ordem inicial em detrimento da proporção de aspecto.
- `Squarified` - o algoritmo de layout em mosaico tem uma proporção de aspecto melhor do que o `SliceAndDice` e mantém uma ordem melhor do que o Squarified.
- `Stripped` - o tipo de layout obtém a melhor proporção de aspecto, mas os objetos são organizados por tamanho.

O Treemap permite escolher o algoritmo mais adequado às suas necessidades, usando por padrão o método Squarified. Ele também permite colorir os nós por dois mecanismos:

- Um mecanismo baseado em grupos, que colore os itens com valores semelhantes
- Um mecanismo baseado em escala, semelhante a um coroplético de mapa, que mapeia as cores dos nós com base no valor deles.

### Orientação do layout

A propriedade `layoutOrientation` permite ao usuário definir a direção em que os nós da hierarquia serão expandidos.

Observe que a propriedade `layoutOrientation` funciona com os tipos de layout SliceAndDice e Strip.

- `Horizontal` – os nós filhos serão empilhados horizontalmente (SliceAndDice).
- `Vertical` – os nós filhos serão empilhados verticalmente (SliceAndDice).

## Destaque percentual do Treemap de {Platform}

- `highlightedDataSource`: especifica a fonte de dados da qual os valores destacados são lidos. Se for nulo, os valores destacados são lidos da propriedade ItemsSource.
- `highlightedValueMemberPath`: especifica o nome da propriedade na fonte de dados em que os valores destacados são lidos.
- `highlightedValueOpacity`: controla a opacidade do valor normal por trás do valor destacado.
- `highlightedValuesDisplayMode`: habilita ou desabilita os valores destacados.
  - Auto: o treemap decide qual modo usar.
  - Overlay: o treemap exibe os valores destacados sobre o valor normal, com uma leve opacidade aplicada ao valor normal.
  - Hidden: o treemap não exibe os valores destacados.
