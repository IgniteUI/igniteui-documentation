# Localização (i18n) do {Platform}

A nova localização traz mais recursos com menos exigências, tanto para as strings de localização quanto para a formatação de todos os locales disponíveis. A formatação é baseada nos padrões introduzidos pela API `Intl`.

Atualmente, o {ProductName} inclui strings de recursos para os seguintes idiomas: `Bulgarian`, `Czech`, `Danish`, `Dutch`, `English`, `French`, `German`, `Hungarian`, `Italian`, `Japanese`, `Korean`, `Norwegian`, `Polish`, `Portuguese`, `Romanian`, `Spanish`, `Swedish`, `Turkish`, `Traditional Chinese (zh-Hant)` e `Simplified Chinese (zh-Hans)`. Elas estão disponíveis pelo pacote `igniteui-i18n-resources`, exceto o inglês, que vem como localização padrão.

## Localidade

O termo **locale** refere-se às strings gerais que definem os diferentes idiomas e regiões. Elas são baseadas na definição de tag [BCP 47](https://developer.mozilla.org/en-US/docs/Glossary/BCP_47_language_tag). A maioria das básicas está descrita no [IANA Language Subtag Registry](https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry). Para uma lista de idiomas, consulte o padrão de idiomas [ISO 639](https://www.loc.gov/standards/iso639-2/).

Ele afeta tanto a formatação de datas e números quanto as strings de recursos localizadas que os componentes {ProductName} usam. O locale padrão do {ProductName} é `en-US`.

O locale pode ser definido de várias formas, globalmente ou por componente.

O {ProductName} oferece suporte à gama completa de locales compatíveis com o `Intl`. Se um locale informado não for válido nem compatível, o locale padrão do `en-US` é usado até que um locale válido seja definido.

Em geral, os recursos devem ser registrados sob os idiomas, regiões e scripts das tags que se pretende usar, para que os componentes sejam localizados corretamente. Para mais informações, consulte a seção [Regiões e scripts](#regiões-e-scripts).

### Atributo `lang`

Essa abordagem permite definir a localização pelo atributo global `lang` da tag `HTML`. Esse atributo é observado e, se mudar, todos os componentes renderizados atualizam suas strings de recursos para o idioma atualmente definido. Todas as regras sobre a tag usada se aplicam conforme descrito acima.

<DocsAside type="info">
Isso funciona apenas no nível raiz e não funcionará para elementos internos da página.
</DocsAside>

</html>

## Strings de recursos localizadas

Todos os componentes {ProductName} são renderizados em inglês por padrão e podem ser renderizados em qualquer um dos idiomas listados. Há três formas de fazer isso globalmente e uma forma por componente. Para qualquer idioma que não esteja disponível no momento, pode ser fornecida uma tradução personalizada para cada string de recurso disponível pela API.

As traduções das strings dos componentes são armazenadas em strings de recursos e precisam ser registradas no sistema de localização antes que os componentes possam usá-las.


<PlatformBlock for="WebComponents, React">



Para isso, primeiro você precisa instalar o pacote [`igniteui-i18n-resources`](https://www.npmjs.com/package/igniteui-i18n-resources), que contém as strings de recursos localizadas de todos os idiomas:

```
npm install igniteui-i18n-resources --save-dev
```

Depois disso, registre cada idioma que deve ficar disponível. Por exemplo, alemão e japonês:

```ts
import { ResourceStringsDE, ResourceStringsJA } from 'igniteui-i18n-resources';

registerI18n(ResourceStringsDE, 'de');
registerI18n(ResourceStringsJA, 'ja');
```


</PlatformBlock>



<PlatformBlock for="Blazor">



Para isso, primeiro instale o pacote NuGet [`IgniteUI.Blazor.I18n.Resources`], que contém as strings de recursos localizadas de todos os idiomas:

```
nuget install IgnieteUI.Blazor.I18n.Resources
```

```razor
I18nManager.RegisterI18nAsync(new IgbResourceStringsBG(), "bg");
```


</PlatformBlock>


Você também precisa especificar o locale ao qual as strings de recursos se aplicarão. Se uma tag inválida for informada, os recursos são definidos para o locale padrão `en-US`.

### Regiões e scripts

A parte `language + region` ou `language + script` do locale usado para registrar os recursos é considerada, porque são as combinações mais comuns. Região e script são separados por `-` e normalmente ficam na segunda ou terceira posição, por exemplo `en-US`, `en-GB` ou `en-Latn`.

Se não forem especificados nem região nem script, os recursos registrados se aplicam a todos os locales que usam aquele idioma base (por exemplo, `en`). No entanto, se também houver recursos definidos para regiões ou scripts específicos, somente os locales sem recursos próprios definidos recorrem aos recursos do idioma base.

Ao registrar recursos, o script tem prioridade maior que a região. Recomenda-se usar região ou script, sem misturar os dois ao mesmo tempo. Isso facilita gerenciar e identificar quais recursos estão disponíveis para um determinado locale.

Se região e script forem usados juntos, considere o idioma `en` com a região `GB` e o script `Latn` como exemplo. Se houver recursos definidos para `en-GB` e `en-Latn`, e o locale for depois definido como `en-Latn-GB` (especificando região e script), os recursos do script têm prioridade. Se os recursos do script não estiverem disponíveis, são usados os recursos da região. Se nem os recursos de script nem os de região estiverem registrados, são usados os recursos padrão `en`, caso existam.

## Personalizar um componente

Se você quiser que um componente específico da sua aplicação use os recursos já registrados globalmente, mas com uma localização diferente.

### Localidade

Se quiser definir para um componente uma localização diferente da global, você pode fazer isso definindo a propriedade `locale`. Isso afetará o idioma das strings de recursos usadas, bem como a formatação, já que ambos estão ligados.

Com esta abordagem, você já deve ter os recursos de string disponíveis registrados globalmente:

```ts
import { ResourceStringsJA } from 'igniteui-i18n-resources';

registerI18n(ResourceStringsJA, 'ja');
```

Ao definir a propriedade `locale` do componente, a localidade global em uso será substituída:

<PlatformBlock for="WebComponents">
```html
<igc-grid locale="ja">
    <igc-column field="ProductName" header="Product Name" groupable="true"></igc-column>
    <igc-column field="QuantityPerUnit" header="Quantity Per Unit" groupable="true"></igc-column>
</igc-grid>
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
<IgrGrid data={data} locale="ja">
    <IgrColumn field="ProductName" header="Product Name" groupable={true}></IgrColumn>
    <IgrColumn field="QuantityPerUnit" header="Quantity Per Unit" groupable={true}></IgrColumn>
</IgrGrid>
```
</PlatformBlock>

<PlatformBlock for="Blazor">
```razor
<IgbGrid Data="@data" Locale="ja">
    <IgbColumn Field="ProductName" Header="Product Name" Groupable="true"></IgbColumn>
    <IgbColumn Field="QuantityPerUnit" Header="Quantity Per Unit" Groupable="true"></IgbColumn>
</IgbGrid>
```
</PlatformBlock>

#### Somente o idioma

Se você quiser alterar apenas o idioma do componente, sem alterar a localidade, pode até definir as strings de recursos de cada componente usando a propriedade `resourceStrings`, que substituirá as que são usadas globalmente:

<PlatformBlock for="WebComponents">
```html
<igc-grid>
    <igc-column field="ProductName" header="Product Name" groupable="true"></igc-column>
    <igc-column field="QuantityPerUnit" header="Quantity Per Unit" groupable="true"></igc-column>
</igc-grid>
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
<IgrGrid data={data} resourceStrings={resourcesDE}>
    <IgrColumn field="ProductName" header="Product Name" groupable={true}></IgrColumn>
    <IgrColumn field="QuantityPerUnit" header="Quantity Per Unit" groupable={true}></IgrColumn>
</IgrGrid>
```
</PlatformBlock>

É preciso garantir que você use o tipo correto de string de recurso para o componente que quer substituir. Cada componente tem o seu próprio conjunto de strings de recursos. Neste caso, para a grade em alemão:

```ts
import { GridResourceStringsDE } from 'igniteui-i18n-resources';

// Inside App Component:
public resourcesDE = GridResourceStringsDE;
```

</PlatformBlock>
