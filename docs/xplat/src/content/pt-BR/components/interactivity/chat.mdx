# Visão geral do {Platform} Chat

O componente {ProductName} Chat oferece uma solução completa para criar interfaces conversacionais nas suas aplicações. Seja para criar uma ferramenta de suporte ao cliente, um espaço de trabalho colaborativo ou um assistente chatbot, o componente Chat oferece os blocos de construção de que você precisa: envio e recebimento de mensagens de texto, upload de anexos, exibição de sugestões de resposta rápida e indicadores de digitação quando o outro participante está escrevendo uma resposta.

Diferentemente de uma lista de mensagens estática, o componente <ApiLink pkg="core" type="Chat" /> é interativo e projetado para **comunicação em tempo real**. Ele gerencia a entrada, a renderização e a interação do usuário, dando a você controle total sobre a forma como mensagens e anexos são exibidos. Ele também expõe uma API de renderização extensa, que permite sobrescrever qualquer parte do seu layout ou da sua aparência visual.

#### Coleção bidirecional de mensagens

O <PlatformBlock for="WebComponents,React">`messages`</PlatformBlock><PlatformBlock for="Blazor">`Messages`</PlatformBlock> A coleção é bidirecional: a aplicação fornece as mensagens a exibir, e o Chat atualiza a coleção original à medida que a conversa continua. Depois que o usuário envia uma mensagem, o código que mantém uma referência à coleção pode acessar a mensagem recém-criada.

O <PlatformBlock for="WebComponents">`igcMessageCreated`</PlatformBlock><PlatformBlock for="React">`onMessageCreated`</PlatformBlock><PlatformBlock for="Blazor">`MessageCreated`</PlatformBlock> O evento é uma notificação para persistência ou outros efeitos colaterais. Não adicione a mensagem criada à coleção novamente.

Se a coleção original precisar permanecer inalterada, passe ao Chat uma cópia rasa. Os objetos de mensagem existentes continuam compartilhados; crie uma nova instância de cada mensagem ao montar a coleção copiada, se esses objetos também precisarem permanecer independentes.

### Sugestões
As sugestões de resposta rápida oferecem aos usuários respostas predefinidas que eles podem tocar para responder instantaneamente. Esse recurso é especialmente útil em chatbots, fluxos de atendimento ao cliente ou quando você está guiando o usuário por um processo estruturado.
Você pode fornecer sugestões vinculando um array de strings à propriedade suggestions. O atributo `suggestions-position` permite controlar onde elas são exibidas: abaixo da área de input ou abaixo da lista de mensagens.

<PlatformBlock for="WebComponents">


```ts

  currentUserId: "me",
  suggestions: ['Yes', 'No', 'Maybe later'],
  suggestionsPosition: "below-input"
};
```

```html
<igc-chat
  .options=${options}>
</igc-chat>
```

</PlatformBlock>

### Renderizadores personalizados
Embora o componente Chat funcione de imediato com a sua interface padrão, muitas aplicações precisam personalizar a aparência. Por exemplo, você pode querer adicionar confirmações de leitura, exibir avatares ou substituir a área de input por um botão de gravação de voz.
O componente <ApiLink pkg="core" type="Chat" /> atende a essa necessidade com um sistema de renderizadores. Um renderizador é simplesmente uma função que retorna um template para uma determinada parte da interface. Você pode sobrescrever quantos renderizadores quiser, ou poucos.

#### ChatTemplateRenderer
Cada renderizador segue a mesma assinatura de função:

<PlatformBlock for="WebComponents, React">

```ts
export type ChatTemplateRenderer<T> = (ctx: T) => unknown;
```

</PlatformBlock>

<PlatformBlock for="Blazor">

```js
igRegisterScript("MyTemplate", (ctx) => {
}, false);
```

</PlatformBlock>

O parâmetro ctx fornece dados contextuais diferentes, dependendo do que está sendo renderizado.

#### Contextos dos renderizadores

| Tipo de contexto                | Dados fornecidos                                                                                                          |
| --------------------------- | -----------------------------------------------------------------------------------------------------------------------|
| <ApiLink pkg="core" type="ChatRenderContext" />       | `instance` (a instância do componente de chat).                                                |
| <ApiLink pkg="core" type="ChatInputRenderContext" />      | Herda <ApiLink pkg="core" type="ChatRenderContext" /> e acrescenta `attachments` (array de <ApiLink pkg="core" type="ChatMessageAttachment" />) e `value` (texto atual do input). |
| <ApiLink pkg="core" type="ChatMessageRenderContext" />    | Herda <ApiLink pkg="core" type="ChatRenderContext" /> e acrescenta <ApiLink pkg="core" type="ChatMessage" /> (o <ApiLink pkg="core" type="ChatMessage" /> sendo renderizado).                                      |
| <ApiLink pkg="core" type="ChatAttachmentRenderContext" /> | Herda <ApiLink pkg="core" type="ChatMessageRenderContext" /> e acrescenta `attachment` (o <ApiLink pkg="core" type="ChatMessageAttachment" /> sendo renderizado).                      |

#### Renderizadores disponíveis

As seguintes partes do Chat podem ser personalizadas:
- Nível da mensagem: message, messageHeader, messageContent, messageAttachments, messageActions
- Nível do anexo: attachment, attachmentHeader, attachmentContent
- Nível da entrada: input, inputActions, inputActionsStart, inputActionsEnd, inputAttachments, fileUploadButton, sendButton
- Sugestões: suggestionPrefix

Esse nível de granularidade permite ajustar apenas uma parte (por exemplo, a aparência dos anexos) sem reescrever todo o layout do chat.

#### Exemplo: estendendo as ações do input
O componente <ApiLink pkg="core" type="Chat" /> oferece dois renderizadores úteis quando você quer manter as ações padrão (upload e envio), mas estendê-las com controles adicionais:
- `inputActionsStart` – permite inserir conteúdo personalizado depois do botão de upload integrado.
- `inputActionsEnd` – permite inserir conteúdo personalizado depois do botão de envio integrado.

Por exemplo, você pode querer adicionar um botão de gravação de voz antes dos outros botões, ou um menu de opções extras depois do botão de envio.
No exemplo a seguir, o botão de upload padrão é mantido, mas adicionamos um botão de microfone ao lado dele. Do outro lado, removemos o botão de envio padrão e o substituímos por um botão personalizado Ask e um menu "more":

### Renderização de Markdown

O componente Chat inclui suporte integrado a conteúdo Markdown por meio do helper `createMarkdownRenderer`, exportado do ponto de entrada `igniteui-webcomponents/extras` do pacote principal. Isso permite exibir mensagens com texto formatado, links, listas e até blocos de código com destaque de sintaxe, garantindo que todo o HTML renderizado seja higienizado por segurança.

</PlatformBlock>

<PlatformBlock for="React">

O componente Chat inclui suporte integrado a conteúdo Markdown por meio do helper `createMarkdownRenderer`, exportado do ponto de entrada `igniteui-react/extras` do pacote principal. Isso permite exibir mensagens com texto formatado, links, listas e até blocos de código com destaque de sintaxe, garantindo que todo o HTML renderizado seja higienizado por segurança.

<DocsAside type="info">

```cmd
npm install marked marked-shiki shiki dompurify
```

Por padrão, as mensagens são renderizadas como texto simples. Se quiser habilitar o suporte a Markdown, você pode sobrescrever o renderizador messageContent e usar o renderizador de Markdown, conforme mostrado abaixo:

<PlatformBlock for="WebComponents">


```ts
import { createMarkdownRenderer } from 'igniteui-webcomponents/extras';

// Create a reusable Markdown renderer instance
const markdownRenderer = await createMarkdownRenderer();

const options = {
  renderers: {
    messageContent: async ({ message }) => markdownRenderer(message),
  }
};
```

</PlatformBlock>


<PlatformBlock for="React">


```tsx

```

</PlatformBlock>

Neste exemplo:
- A propriedade text de cada mensagem será interpretada como Markdown usando a biblioteca [marked](https://github.com/markedjs/marked).
- O renderizador sanitiza a saída usando o [DOMPurify](https://github.com/cure53/DOMPurify)
- Os links abrem automaticamente em uma nova aba, com atributos rel seguros.

#### Realce de sintaxe

O renderizador de Markdown também oferece suporte a destaque de sintaxe em blocos de código usando [Shiki](https://shiki.matsu.io/). Por padrão, inclui destaque para JavaScript, TypeScript, HTML e CSS com o tema github-light. Você pode personalizar esse comportamento por meio de MarkdownRendererOptions:

```ts
const markdownRenderer = await createMarkdownRenderer({
  theme: { light: 'min-light' },
  languages: ['javascript', 'python']
});
```

Isso habilitará blocos de código destacados para JavaScript, Python e Go, estilizados com o tema escuro do GitHub.

#### Opções de configuração

| Opção          | Descrição                                                                     |
| --------------- | ------------------------------------------------------------------------------- |
| `noHighlighter` | Se `true`, desabilita completamente o destaque de sintaxe.                               |
| `languages`     | Lista de linguagens de programação a suportar em blocos de código destacados.            |
| `theme`         | Um objeto que especifica os temas do **Shiki** a aplicar. Oferece suporte a valores separados para o modo `light` e para o modo `dark` (por exemplo, `{ light: 'github-light', dark: 'github-dark' }`). |
| `sanitizer`     | Uma função personalizada para higienizar o HTML final. O padrão é `DOMPurify.sanitize`. |

</PlatformBlock>

#### Adoção de estilos raiz (adoptRootStyles)

As opções do componente Chat incluem um sinalizador especial para cenários avançados de estilização:

| Opção            | Tipo      | Padrão | Descrição        |
| ----------------- | --------- | ------- | ------------------ |
| `adoptRootStyles` | `boolean` | false   | Quando `true`, o componente permite que o conteúdo renderizado dentro do seu Shadow DOM (por exemplo, a partir de renderizadores personalizados) herde estilos da raiz do documento. Isso oferece uma solução rápida para estilização, mas **não é recomendado** para uso em produção. |

Esta propriedade pode ser útil se você preferir não lidar com o encapsulamento do Shadow DOM ao aplicar CSS global a templates renderizados de forma personalizada.
No entanto, ela tem contrapartidas:
- ✅ Conveniência: permite que estilos globais (do documento) afetem os renderizadores de mensagens personalizados.
- ⚠ Arriscado: quebra o encapsulamento e pode causar vazamento de estilos, em que o CSS global altera de forma não intencional a aparência interna.
- 🔒 Configuração única: esta opção só pode ser definida na inicialização. Alterá-la em tempo de execução não tem efeito.

Recomendamos muito usar as abordagens padrão de estilização de Web Components antes de recorrer a esta propriedade:
- Variáveis CSS e API ::part – prefira personalizar por meio das partes e variáveis expostas.
- Elementos `<link>` – para folhas de estilo maiores, injete-os dentro do Shadow DOM.
- Tags `<style>` inline – para substituições de estilo pequenas e com escopo.

#### Exemplo

```css
igc-chat::part(header) {
  background-color: var(--ig-gray-800);
  color: var(--ig-warn-400);
}

igc-chat::part(message-container) {
  background: var(--ig-warn-200);
  color: var(--ig-warn-200-contrast);
}

igc-chat::part(message-sent) {
  background: var(--ig-warn-500);
  color: var(--ig-warn-500-contrast);
}

igc-chat::part(message-header) {
  color: var(--ig-warn-A700); 
}
```

Isso permite estilizar o <ApiLink pkg="core" type="Chat" /> para combinar com a sua marca, sem substituir sua funcionalidade.
