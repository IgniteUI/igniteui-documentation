# Visão geral e configuração do Tree Grid {Platform}

O Tree Grid {Platform} é um componente de UI que combina a funcionalidade de um data grid (tabela) com uma visualização em árvore, permitindo que dados hierárquicos sejam exibidos facilmente em um formato tabular. Diferentemente de uma grade comum, um tree grid permite que as linhas sejam expandidas e recolhidas, revelando linhas filhas aninhadas sob linhas pai, o que o torna útil para representar dados estruturados, como exploradores de arquivos, organogramas, tarefas de projeto ou categorias de produtos.

O Tree Grid {ProductName} é usado para exibir e manipular dados hierárquicos ou planos com facilidade. Vincule rapidamente os seus dados com muito pouco código ou use uma variedade de eventos para personalizar diferentes comportamentos. Este componente oferece um conjunto rico de recursos, como seleção de dados, filtragem estilo Excel, ordenação, paginação, templates e movimentação de colunas. Exibir dados tabulares nunca foi tão fácil e bonito, graças ao Tree Grid de UI baseado na Material Table.

## Uso

O tree grid compartilha muitos recursos com a grade, mas também acrescenta a capacidade de exibir seus dados de forma hierárquica.
Para isso, o tree grid nos oferece algumas formas de definir as relações entre os nossos objetos de dados: usando uma [coleção de filhos](./overview.mdx#coleção-filha) para cada objeto de dados ou usando [chaves primárias e estrangeiras](./overview.mdx#chaves-primárias-e-estrangeiras) para cada objeto de dados.

### Células de árvore

Independentemente da opção usada para construir a hierarquia do tree grid (coleção filha ou chaves primárias e estrangeiras), as linhas do tree grid são construídas com dois tipos de células:

- `GridCell` - Célula comum que contém um valor.
- `TreeGridCell` - Célula de árvore que contém um valor, um indicador de expandir/recolher e um elemento div de indentação, baseado no nível da linha da célula. O nível de um componente de linha pode ser acessado pela propriedade `level` do seu `treeRow` interno.

<DocsAside type="info">
Cada linha pode ter apenas uma célula de árvore, mas pode ter várias células comuns (ou nenhuma).
</DocsAside>

### Profundidade de expansão inicial

Inicialmente, o tree grid expande e mostra todos os níveis de nó. Esse comportamento pode ser configurado pela propriedade <ApiLink type="TreeGrid" member="expansionDepth" label="ExpansionDepth" />. Por padrão, o valor é **Infinity**, o que significa que todos os níveis de nó serão expandidos. Você pode controlar a profundidade de expansão inicial definindo essa propriedade como um valor numérico. Por exemplo, **0** mostrará apenas os nós do nível raiz, **1** mostrará os nós do nível raiz e os seus nós filhos, e assim por diante.

### Coleção filha

Quando usamos a opção de coleção de filhos, cada objeto de dados contém uma coleção de filhos, preenchida com itens do mesmo tipo do objeto de dados pai. Assim, cada registro no tree grid terá uma referência direta a qualquer um dos seus filhos. Nesse caso, a propriedade data do nosso tree grid, que contém a fonte de dados original, será uma coleção definida de forma hierárquica.

### Chaves primárias e estrangeiras
Quando usamos a opção de **chaves primárias e estrangeiras**, cada objeto de dados contém uma chave primária e uma chave estrangeira. A chave primária é o identificador exclusivo do objeto de dados atual, e a chave estrangeira é o identificador exclusivo do seu pai. Nesse caso, a propriedade `data` do nosso tree grid, que contém a fonte de dados original, será uma coleção plana.

Nos dados de exemplo acima, todos os registros têm um ID, um ParentID e algumas propriedades adicionais, como Name, JobTitle e Age. Como mencionado anteriormente, o ID dos registros deve ser único, pois será a nossa <ApiLink type="GridBaseDirective" member="primaryKey" label="PrimaryKey" />. A relação pai-filho é configurada pelas propriedades <ApiLink type="GridBaseDirective" member="primaryKey" label="PrimaryKey" /> e <ApiLink type="TreeGrid" member="foreignKey" label="ForeignKey" /> do tree grid.

## Persistência e integração

A indentação da célula do tree grid persiste em outros recursos do tree grid, como filtragem, ordenação e paginação.

- Quando `Sorting` é aplicada a uma coluna, as linhas de dados são ordenadas por níveis. Isso significa que as linhas do nível raiz serão ordenadas independentemente de seus respectivos filhos. As coleções de filhos de cada uma também serão ordenadas de forma independente, e assim por diante.
- A primeira coluna (a que tem <ApiLink type="Column" member="visibleIndex" label="VisibleIndex" /> igual a 0) é sempre a coluna de árvore.
- A coluna que termina com <ApiLink type="Column" member="visibleIndex" label="VisibleIndex" /> igual a 0, após operações como fixação de colunas, ocultação de colunas e movimentação de colunas, torna-se a coluna de árvore.
- As planilhas Excel exportadas refletem a hierarquia, agrupando os registros da mesma forma que são agrupados no próprio tree grid. Os estados de expansão de todos os registros também seriam mantidos e refletidos.
- Ao exportar para CSV, os níveis e os estados de expansão são ignorados, e todos os dados são exportados de forma plana.
