# Visão geral e configuração do Hierarchical Data Grid

O {ProductName} Hierarchical Data Grid é usado para exibir e manipular dados tabulares hierárquicos. Vincule rapidamente os seus dados com muito pouco código ou use uma variedade de eventos para personalizar diferentes comportamentos. Este componente oferece um conjunto rico de recursos, como seleção de dados, filtragem estilo Excel, ordenação, paginação, templates, movimentação de colunas, fixação de colunas, exportação para Excel e CSV, e muito mais. A Grid hierárquica se baseia no componente de Grid plana e amplia sua funcionalidade, permitindo que os usuários expandam ou recolham as linhas da grade pai, revelando as grades filhas correspondentes, quando forem necessárias informações mais detalhadas.

## Usando o Hierarchical Data Grid do {Platform}

### Vinculação de dados

O **{HierarchicalGridSelector}** deriva de {GridSelector} e compartilha a maior parte da sua funcionalidade. A principal diferença é que ele permite definir vários níveis de hierarquia. Eles são configurados por meio de uma tag separada dentro da definição de **{HierarchicalGridSelector}**, chamada **{RowIslandSelector}**. O componente **{RowIslandSelector}** define a configuração de cada grade filha para o nível em particular. Também há suporte a várias ilhas de linhas por nível.
A Grid hierárquica oferece suporte a duas formas de fazer data binding:

### Usando dados hierárquicos

Se a aplicação carregar todos os dados hierárquicos como um array de objetos que referenciam arrays de objetos filhos, a Grade Hierárquica pode ser configurada para lê-los e vincular-se a eles automaticamente. Aqui está um exemplo de uma fonte de dados hierárquica com a estrutura correta:

### Usando carregamento sob demanda

A maioria das aplicações é projetada para carregar o mínimo possível de dados inicialmente, o que resulta em tempos de carregamento mais rápidos. Nesses casos, {HierarchicalGridSelector} pode ser configurado para permitir que serviços criados pelo usuário o alimentem com dados sob demanda.


<PlatformBlock for="Angular">


```html
<!-- hierarchicalGridSample.component.html -->

<igx-hierarchical-grid #hGrid [primaryKey]="'customerId'" [autoGenerate]="true" [height]="'600px'" [width]="'100%'">
    <igx-row-island [key]="'Orders'" [primaryKey]="'orderId'" [autoGenerate]="true"  (gridCreated)="gridCreated($event, 'Customers')">
        <igx-row-island [key]="'Details'" [primaryKey]="'productId'" [autoGenerate]="true" (gridCreated)="gridCreated($event, 'Orders')">
        </igx-row-island>
    </igx-row-island>
</igx-hierarchical-grid>
```

```typescript
//  hierarchicalGridSample.component.ts

@Component({...})
export class HierarchicalGridLoDSampleComponent implements AfterViewInit {
    @ViewChild("hGrid")
    public hGrid: IgxHierarchicalGridComponent;

    constructor(private remoteService: RemoteLoDService) { }

    public ngAfterViewInit() {
        this.hGrid.isLoading = true;
        this.remoteService.getData({ parentID: null, rootLevel: true, key: "Customers" }).subscribe((data) => {
            this.hGrid.isLoading = false;
            this.hGrid.data = data;
            this.hGrid.cdr.detectChanges();
        });
    }

    public gridCreated(event: IGridCreatedEventArgs, _parentKey: string) {
        const dataState = {
            key: event.owner.key,
            parentID: event.parentID,
            parentKey: _parentKey,
            rootLevel: false
        };
        event.grid.isLoading = true;
        this.remoteService.getData(dataState).subscribe(
            (data) => {
                event.grid.isLoading = false;
                event.grid.data = data;
                event.grid.cdr.detectChanges();
            }
        );
    }
}
```

```typescript
// remote-load-on-demand.service.ts

@Injectable()
export class RemoteLoDService {
    public url = `https://data-northwind.indigo.design/`;

    constructor(private http: HttpClient) { }

    public getData(dataState: any): Observable<any[]> {
        return this.http.get(this.buildUrl(dataState)).pipe(
            map((response) => response)
        );
    }

    public buildUrl(dataState) {
        let qS = "";
        if (dataState) {
            if (dataState.rootLevel) {
                qS += `${dataState.key}`;
            } else {
                qS += `${dataState.parentKey}/${dataState.parentID}/${dataState.key}`;
            }
        }
        return `${this.url}${qS}`;
    }
}
```

```ts
export class HierarchicalGridLoadOnDemand {
    constructor() {
        const hierarchicalGrid = document.getElementById("hGrid") as IgcHierarchicalGridComponent;
        const ordersRowIsland = document.getElementById("ordersRowIsland");
        const orderDetailsRowIsland = document.getElementById("orderDetailsRowIsland");

        ordersRowIsland.addEventListener("gridCreated", (event: any) => {
            this.gridCreated(event, "Customers");
        });
        orderDetailsRowIsland.addEventListener("gridCreated", (event: any) => {
            this.gridCreated(event, "Orders");
        });

        hierarchicalGrid.isLoading = true;

        getData({ parentID: null, rootLevel: true, key: "Customers" }).then((data: any) => {
            hierarchicalGrid.isLoading = false;
            hierarchicalGrid.data = data;
            hierarchicalGrid.markForCheck();
        });
    }

    public gridCreated(event: CustomEvent<IgcGridCreatedEventArgs>, _parentKey: string) {
        const context = event.detail;
        const dataState = {
            key: context.owner.childDataKey,
            parentID: context.parentID,
            parentKey: _parentKey,
            rootLevel: false
        };
        context.grid.isLoading = true;
        getData(dataState).then((data: any[]) => {
            context.grid.isLoading = false;
            context.grid.data = data;
            context.grid.markForCheck();
```

## Mostrar/ocultar indicadores de expansão de linha

Se você tiver uma forma de informar se uma linha tem filhos antes de ela ser expandida, pode usar a propriedade de entrada <ApiLink type="HierarchicalGridBaseDirective" member="hasChildrenKey" label="HasChildrenKey" />. Assim, você pode fornecer uma propriedade booleana dos objetos de dados que indica se um indicador de expansão deve ser exibido.

Observe que definir a propriedade <ApiLink type="HierarchicalGridBaseDirective" member="hasChildrenKey" label="HasChildrenKey" /> não é obrigatório. Caso você não a forneça, os indicadores de expansão serão exibidos em cada linha.

Além disso, se você quiser mostrar/ocultar o indicador de expandir/recolher tudo no cabeçalho, pode usar a propriedade <ApiLink type="HierarchicalGridBaseDirective" member="showExpandAll" label="ShowExpandAll" />.
Essa UI fica desabilitada por padrão, por motivos de desempenho, e não é recomendado habilitá-la em grades com grandes volumes de dados ou com carregamento sob demanda.

Os recursos da grade a seguir funcionam no nível de cada grade, o que significa que cada instância de grade os gerencia de forma independente das demais grades:

- Ordenação
- Filtragem
- Paginação
- Cabeçalhos de várias colunas
- Ocultação
- Fixação
- Movimentação
- Resumos
- Pesquisa

Os recursos de Seleção e de Navegação funcionam globalmente para toda a {HierarchicalGridTitle}

- Seleção
    A seleção não permite que células selecionadas estejam presentes em duas grades filhas diferentes ao mesmo tempo.
- Navegação
    Ao navegar com <kbd>↑</kbd> + <kbd>↓</kbd>, se o próximo/anterior elemento for uma grade filha, a navegação continuará na grade filha relacionada, marcando a célula relacionada como selecionada e focada. Se a célula filha estiver fora da área de visualização atual, ela é rolada para ficar visível, de modo que a célula selecionada esteja sempre visível.

## Estilização
O igxHierarchicalGrid permite a estilização por meio da [Ignite UI for Angular Theme Library](../themes/sass/component-themes.mdx). O <ApiLink type="function-grid-theme" label="theme" kind="sass" module="index.html" /> da grade expõe uma grande variedade de propriedades, que permitem personalizar todos os recursos da grade.

Nas etapas abaixo, vamos percorrer as etapas de personalização da estilização do igxHierarchicalGrid.

### Importando o tema global
Para começar a personalização da grade hierárquica, você precisa importar o arquivo `index`, onde estão localizadas todas as funções de estilo e mixins.

```scss
@import '~igniteui-angular/lib/core/styles/themes/index'
```

### Definindo um tema personalizado
Em seguida, crie um novo tema que estenda o <ApiLink type="function-grid-theme" label="grid-theme" kind="sass" module="index.html" /> e aceite os parâmetros necessários para personalizar a grade hierárquica como desejado.

 <DocsAside type="info">
 Não há uma função específica de grade hierárquica `sass`.
 </DocsAside>


```scss
$custom-theme: grid-theme(
  $cell-active-border-color: #ffcd0f,
  $cell-selected-background: #6f6f6f,
  $row-hover-background: #f8e495,
  $row-selected-background: #8d8d8d,
  $header-background: #494949,
  $header-text-color: #fff,
  $expand-icon-color: #ffcd0f,
  $expand-icon-hover-color: #e0b710,
  $resize-line-color: #ffcd0f,
  $row-highlight: #ffcd0f
);
```

### Definindo uma paleta de cores personalizada
Na abordagem descrita acima, os valores de cor estavam fixos no código. Como alternativa, você pode obter mais flexibilidade usando as funções <ApiLink type="function-igx-palette" label="igx-palette" kind="sass" module="index.html" /> e <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" />.
`igx-palette` gera uma paleta de cores com base nas cores primária e secundária fornecidas.

 ```scss
$black-color: #494949;
$yellow-color: #FFCD0F;

$custom-palette: palette(
  $primary: $black-color,
  $secondary: $yellow-color
);
```

Depois que uma paleta personalizada é gerada, a função `igx-color` pode ser usada para obter diferentes variações das cores primária e secundária.

```scss
$custom-theme: grid-theme(
    $cell-active-border-color: (igx-color($custom-palette, "secondary", 500)),
    $cell-selected-background: (igx-color($custom-palette, "primary", 300)),
    $row-hover-background: (igx-color($custom-palette, "secondary", 100)),
    $row-selected-background: (igx-color($custom-palette, "primary", 100)),
    $header-background: (igx-color($custom-palette, "primary", 500)),
    $header-text-color: (igx-contrast-color($custom-palette, "primary", 500)),
    $expand-icon-color: (igx-color($custom-palette, "secondary", 500)),
    $expand-icon-hover-color: (igx-color($custom-palette, "secondary", 600)),
    $resize-line-color: (igx-color($custom-palette, "secondary", 500)),
    $row-highlight: (igx-color($custom-palette, "secondary", 500))
);
```

### Definindo schemas personalizados
Você pode ir além e construir uma estrutura flexível que tenha todos os benefícios de um [**schema**](../themes/sass/schemas.mdx). O **schema** é a receita de um tema.
Estenda um dos dois schemas predefinidos, fornecidos para cada componente. No nosso caso, usaremos `$_light_grid`.

```scss
$custom-grid-schema: extend($_light-grid,(
    cell-active-border-color: (igx-color:('secondary', 500)),
    cell-selected-background: (igx-color:('primary', 300)),
    row-hover-background: (igx-color:('secondary', 100)),
    row-selected-background: (igx-color:('primary', 100)),
    header-background: (igx-color:('primary', 500)),
    header-text-color: (igx-contrast-color:('primary', 500)),
    expand-icon-color: (igx-color:('secondary', 500)),
    expand-icon-hover-color: (igx-color:('secondary', 600)),
    resize-line-color: (igx-color:('secondary', 500)),
    row-highlight: (igx-color:('secondary', 500))
));
```

Para que o schema personalizado seja aplicado, é preciso estender um dos globais `light` ou `dark`. O processo, na prática, consiste em fornecer a um componente um schema personalizado e, depois, adicioná-lo ao tema do respectivo componente.

```scss
$my-custom-schema: extend($light-schema, (
    igx-grid: $custom-grid-schema
));

$custom-theme: grid-theme(
    $palette: $custom-palette,
    $schema: $my-custom-schema
);
```

### Aplicando o tema personalizado
A forma mais fácil de aplicar o seu tema é com uma instrução `sass` `@include` no arquivo de estilos globais:

```scss
@include grid($custom-theme);
```

### Tema de componente com escopo

Para que o tema personalizado afete apenas um componente específico, você pode mover todos os estilos que acabou de definir do arquivo de estilos global para o arquivo de estilos do componente personalizado (incluindo a importação do arquivo `index`).

Dessa forma, por causa do [ViewEncapsulation](https://angular.io/api/core/Component#encapsulation) do Angular, os seus estilos serão aplicados somente ao seu componente personalizado.

 <DocsAside type="info">
 Se o componente usar um [`Emulated`](../themes/sass/component-themes.mdx#view-encapsulation) ViewEncapsulation, é necessário penetrar essa encapsulação usando `::ng-deep` para estilizar a grade.
 </DocsAside>

 <DocsAside type="info">
 Envolva a instrução em um seletor `:host` para impedir que os seus estilos afetem elementos fora do nosso componente:
 </DocsAside>

```scss
:host {
    ::ng-deep {
        @include grid($custom-theme);
    }
}
```
