# Operações remotas do Pivot Grid {Platform}

Em cenários em que os dados dinâmicos já estão agrupados e agregados por um serviço remoto, e não é necessário nenhum processamento adicional no cliente, o pivot grid pode ser configurado para usar uma estratégia vazia personalizada, que ignora o processamento de dados no cliente e exibe diretamente os dados como estão:


<PlatformBlock for="Angular">


```typescript
public pivotConfigHierarchy: IPivotConfiguration = {
    columnStrategy: NoopPivotDimensionsStrategy.instance(),
    rowStrategy: NoopPivotDimensionsStrategy.instance(),
}
```

</PlatformBlock>



<PlatformBlock for="WebComponents">


```typescript
public pivotConfigHierarchy: IgcPivotConfiguration = {
    columnStrategy: IgcNoopPivotDimensionsStrategy.instance(),
    rowStrategy: IgcNoopPivotDimensionsStrategy.instance(),
}
```

</PlatformBlock>


O exemplo a seguir mostra como tratar cenários em que os dados já estão agregados e como a sua estrutura deve ser:
<Sample src="/{PivotGridSample}/remote" height={530} alt="Exemplo de agregações predefinidas personalizadas do Pivot Grid {Platform}" />




Os usuários podem obter determinados cenários alimentando o pivot grid com dados já agregados.
Há algumas exigências sobre como os dados devem ser e algumas especificidades sobre hierarquias na visualização dinâmica. Por exemplo, para declarar uma hierarquia na dimensão **rows**:

```typescript
rows: [
    {
        memberName: 'AllProducts',
        memberFunction: () => 'All Products',
        enabled: true,
        childLevel: {
            memberName: 'ProductCategory',
            enabled: true
        }
    }
]
```

E um exemplo dos dados agregados seria:

```typescript
public aggregatedData = [
    {
        ProductCategory: 'All', AllProducts: 'All Products', All: 1000, 'All-Bulgaria': 774, 'All-USA': 829, 'All-Uruguay': 524, AllProducts_records: [
            { ProductCategory: 'Clothing', 'All-Bulgaria': 774, 'All-USA': 296, 'All-Uruguay': 456 },
            { ProductCategory: 'Bikes', 'All-Uruguay': 68 },
            { ProductCategory: 'Accessories', 'All-USA': 293 },
            { ProductCategory: 'Components', 'All-USA': 240 }
        ]
    }
];
```

O Pivot grid fornece as chaves de objeto que usa para fazer os seus cálculos dinâmicos.
- <ApiLink type="PivotKeys" member="children" label="Children" /> - Campo que armazena os filhos para a construção da hierarquia. Ele representa um mapa dos valores agrupados e de todos os pivotGridRecords baseados nesse valor. Pode ser usado em cenários muito específicos, em que é necessário fazer algo durante a criação das hierarquias. Não é preciso alterar isso para uso comum.
- <ApiLink type="PivotKeys" member="records" label="Records" /> - Campo que armazena a referência aos registros de dados originais. Pode ser visto no exemplo acima - **AllProducts_records**. Evite definir campos nos dados com o mesmo nome desta propriedade. Se os seus registros de dados tiverem uma propriedade **records**, você pode especificar um valor diferente e único para ela usando <ApiLink type="PivotConfiguration" member="pivotKeys" label="PivotKeys" />.
- <ApiLink type="PivotKeys" member="aggregations" label="Aggregations" /> - Campo que armazena os valores de agregação. Ele é aplicado durante a criação das hierarquias e também não deve ser alterado em cenários comuns.
- <ApiLink type="PivotKeys" member="level" label="Level" /> - Campo que armazena o nível da dimensão com base na sua hierarquia. Evite definir campos nos dados com o mesmo nome desta propriedade. Se os seus registros de dados tiverem uma propriedade **level**, você pode especificar um valor diferente e único para ela usando <ApiLink type="PivotConfiguration" member="pivotKeys" label="PivotKeys" />.
- <ApiLink type="PivotKeys" member="columnDimensionSeparator" label="ColumnDimensionSeparator" /> - Separador usado na geração dos valores únicos dos campos de coluna. É o traço (**-**) do exemplo acima - **All-Bulgaria**.
- <ApiLink type="PivotKeys" member="rowDimensionSeparator" label="RowDimensionSeparator" /> - Separador usado na geração dos valores únicos dos campos de linha. É o sublinhado (**_**) do exemplo acima - **AllProducts_records**. Ele é usado na criação dos campos <ApiLink type="PivotKeys" member="records" label="Records" /> e <ApiLink type="PivotKeys" member="level" label="Level" />.

Todos eles são armazenados na propriedade <ApiLink type="PivotConfiguration" member="pivotKeys" label="PivotKeys" />, que faz parte de <ApiLink type="PivotGrid" member="pivotConfiguration" label="PivotConfiguration" />, e podem ser usados para alterar as chaves dinâmicas padrão.
Esses são os valores padrão:

```typescript
export const DEFAULT_PIVOT_KEYS = {
    aggregations: 'aggregations', records: 'records', children: 'children', level: 'level',
    rowDimensionSeparator: '_', columnDimensionSeparator: '-'
};
```

Definir <ApiLink type="NoopPivotDimensionsStrategy" /> para <ApiLink type="PivotConfiguration" member="columnStrategy" label="ColumnStrategy" /> e <ApiLink type="PivotConfiguration" member="rowStrategy" label="RowStrategy" /> ignora o agrupamento e a agregação de dados feitos pelos pipes de dados, mas o pivot grid ainda precisa de declarações para as linhas, colunas, valores e filtros, para renderizar a visualização dinâmica como esperado:


<PlatformBlock for="Angular">


```typescript
public pivotConfig: IPivotConfiguration = {
    rows: [
        {
            memberName: 'AllProducts',
            memberFunction: () => 'All Products',
            enabled: true,
            childLevel: {
                memberName: 'ProductCategory',
                enabled: true
            }
        }
    ],
    columns: [
        {
            memberName: 'All',
            enabled: true,
            childLevel: {
                memberName: 'Country',
                enabled: true
            }
        }
    ],
    values: [
        {
            member: 'UnitsSold',
            aggregate: {
                aggregator: IgxPivotNumericAggregate.sum,
                key: 'sum',
                label: 'Sum'
            },
            enabled: true
        },
    ]
}
```

</PlatformBlock>

É importante que os dados correspondam à configuração. Para obter os melhores resultados, nenhum campo adicional deve ser incluído nos dados agregados, e nenhum campo dos dados fornecidos deve ficar sem declaração como linha ou coluna. O componente <ApiLink type="PivotGrid" /> cria os seus dados com base em <ApiLink type="PivotGrid" member="pivotConfiguration" label="PivotConfiguration" />, e espera-se que a configuração e os dados agregados correspondam entre si.

Da mesma forma, para outras operações remotas de dados, como ordenação e filtragem, o processamento de dados pode ser ignorado definindo as estratégias vazias correspondentes - <ApiLink type="GridBaseDirective" member="filterStrategy" label="FilterStrategy" />, <ApiLink type="GridBaseDirective" member="sortStrategy" label="SortStrategy" />:


<PlatformBlock for="Angular">


```html
<{PivotGridSelector} [filterStrategy]="noopFilterStrategy" [sortStrategy]="noopSortStrategy">
</{PivotGridSelector}>
```

</PlatformBlock>



<PlatformBlock for="WebComponents">


```html
<{PivotGridSelector} filter-strategy="noopFilterStrategy" sort-strategy="noopSortStrategy">
</{PivotGridSelector}>
```

</PlatformBlock>


```typescript
public noopFilterStrategy = NoopFilteringStrategy.instance();
public noopSortStrategy = NoopSortingStrategy.instance();
```
