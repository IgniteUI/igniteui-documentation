## Uso

Agora que importamos os pacotes da grade, vamos começar com a configuração básica e vincular a dados locais:

<PlatformBlock for="Blazor">

```razor

```

</PlatformBlock>

<PlatformBlock for="Angular">

```html

```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html

```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```typescript
constructor() {

    grid1.data = data;

```

</PlatformBlock>

<PlatformBlock for="React">

```tsx

```

</PlatformBlock>

A propriedade <ApiLink type="Grid" member="id" label="Id" /> é um valor string e é o identificador único da grade, que será gerado automaticamente se não for informado, enquanto <ApiLink type="Grid" member="data" label="data" /> vincula a grade, neste caso, a dados locais.

A propriedade <ApiLink type="GridBaseDirective" member="autoGenerate" label="AutoGenerate" /> faz com que a grade gere automaticamente os componentes <ApiLink type="Column" /> da grade com base nos campos da fonte de dados. Ela também tentará deduzir o tipo de dado apropriado para a coluna, se possível. Caso contrário, o desenvolvedor precisa definir explicitamente as colunas e o mapeamento para os campos da fonte de dados.

## Definição de grade Bootstrap

O {ProductName} inclui um sistema de layout poderoso, semelhante à grade do bootstrap e baseado em flex. Hoje, espera-se que qualquer aplicação moderna siga uma abordagem de web design responsivo, ou seja, que ajuste com elegância o layout dos elementos HTML conforme o tamanho do dispositivo ou apenas ao redimensionar o navegador. Um layout de grade bootstrap era a abordagem mais usada no passado, mas um sistema de layout baseado em flex, como o CSS grid, ficou mais popular, pois funciona em qualquer navegador. A diretiva de layout {ProductName} permite fluxo vertical e horizontal, incluindo quebra de conteúdo e texto, justificação e alinhamento. A grade {ProductName} oferece suporte a layout responsivo usando CSS, dando a máxima flexibilidade sobre como a grade se comporta ao redimensionar.


</PlatformBlock>


## Grade {Platform} editável

Cada operação de edição da grade inclui operações em lote, o que significa que a API oferece a opção de agrupar edições em uma única chamada ao servidor, ou de realizar as operações de edição e atualização da grade conforme elas ocorrem com as interações na grade. Além de uma ótima experiência para o desenvolvedor, como uma grade editável com operações de CRUD, a grade inclui navegação por teclado semelhante à do Excel. A navegação padrão comum da grade está incluída, além da opção de substituir qualquer opção de navegação para atender às necessidades dos seus clientes. Uma grade editável com um bom esquema de navegação é essencial para qualquer aplicação de negócios moderna; com a grade do Ignite UI, isso fica fácil.

Neste tópico, você vai saber mais sobre o [template de célula](./data-grid.mdx#template-de-célula) e o [template de edição de célula](./data-grid.mdx#template-de-edição-de-célula), bem como sobre a edição.

### Template de célula

Quando um template de célula é definido, ele altera todas as células da coluna. O objeto de contexto fornecido no template consiste no valor da célula, fornecido implicitamente, e no próprio objeto da célula. Ele pode ser usado para definir um template em que o texto das células seja formatado, por exemplo, em title case.

<PlatformBlock for="Angular">

```html
<igx-column field="Name">
    <ng-template igxCell let-value>
        {{ value | titlecase }}
    </ng-template>
</igx-column>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

```html
<igc-column id="name" field="Name"></igc-column>
```

</PlatformBlock>

<PlatformBlock for="WebComponents">

    <igx-column dataType="boolean" field="Subscribtion">
        <ng-template igxCell let-cell="cell">
            <!-- Bind the cell value through the ngModel directive and update the data source when the value is changed in the template -->

constructor() {
    var grid = this.grid = document.getElementById('grid') as IgcGridComponent;
    var name = this.name = document.getElementById('name') as IgcColumnComponent;

    grid.data = this.data;
    name.bodyTemplate = this.nameCellTemplate;
    subscription.bodyTemplate = this.subscriptionCellTemplate;
}

public nameCellTemplate = (ctx: IgcCellTemplateContext) => {
    return html`
        <span tabindex="0" @keydown="${() => this.deleteRow(ctx.cell.id.rowIndex)}">${this.formatTitleCase(ctx.cell.value)}</span>

    if (ctx.cell.value) {
            return html` <input type="checkbox" checked /> `;

            return html` <input type="checkbox"/> `;

}

     this.grid.deleteRow(rowIndex);
}

    return value.toLowerCase().replace(/\b\w/g, c => c.toUpperCase());
}

<PlatformBlock for="Angular">



Ao alterar dados pelo **template de célula** usando `ngModel`, você precisa chamar os métodos de API apropriados para garantir que o valor seja atualizado corretamente na coleção de dados subjacente da grade Angular. No trecho acima, a chamada `ngModelChange` passa pela [API de edição](./_shared/cell-editing.mdx#editing-through-api) da grade e pelo pipeline de edição da grade, disparando corretamente as [transações](./_shared/batch-editing.mdx) (se aplicável) e tratando os [resumos](./_shared/summaries.mdx), a [seleção](./_shared/selection.mdx) etc. No entanto, este `ngModelChange` será disparado sempre que o valor da célula mudar, e não apenas quando o usuário terminar a edição, resultando em muito mais chamadas de API.


</PlatformBlock>


> **Observação**:
> A grade expõe um tratamento padrão para os tipos de coluna number, string, date e boolean. Por exemplo, para o tipo de coluna boolean, a coluna exibirá por padrão um ícone `check` ou `close`, em vez de true/false.


<PlatformBlock for="Angular">



Se os dados de uma célula forem vinculados com `[(ngModel)]` e a mudança de valor não for tratada, o novo valor **não** será atualizado corretamente na fonte de dados subjacente da grade Angular. Ao lidar com a edição de células com um template personalizado, recomenda-se fortemente usar o **template de edição de célula** da célula.


</PlatformBlock>


Quando implementado corretamente, o template de edição de célula também garante que o <ApiLink type="CellType" member="editValue" label="EditValue" /> da célula passe corretamente pelo [ciclo de eventos de edição](./_shared/editing.mdx#event-arguments-and-sequence) da grade.

### Template de edição de célula

A coluna também aceita um último template, que será usado quando uma célula estiver em modo de edição. Assim como nos outros templates de coluna, o objeto de contexto fornecido é, novamente, o valor da célula e o próprio objeto da célula. Para tornar o template do modo de edição acessível aos usuários finais, é preciso definir a propriedade <ApiLink type="Column" member="editable" label="Editable" /> da coluna como true.

### Formato de exibição personalizado

Há parâmetros opcionais para formatação:

- <ApiLink type="ColumnPipeArgs" member="format" label="Format" /> - determina quais partes de data e hora são exibidas; o padrão é `'mediumDate'`, equivalente a **'MMM d, y'**
- <ApiLink type="ColumnPipeArgs" member="timezone" label="Timezone" /> - o deslocamento de fuso horário para datas. Por padrão, usa o fuso horário local do sistema do usuário final
- <ApiLink type="ColumnPipeArgs" member="digitsInfo" label="DigitsInfo" /> - objetos de representação decimal. O padrão é **1.0-3**

Para permitir personalizar o formato de exibição por meio desses parâmetros, a entrada <ApiLink type="Column" member="pipeArgs" label="PipeArgs" /> é exposta. Uma coluna respeitará apenas as propriedades correspondentes ao seu tipo de dado, se <ApiLink type="Column" member="pipeArgs" label="PipeArgs" /> estiver definido. Exemplo:

Uma boa prática é separar toda a lógica relacionada à busca de dados em um serviço de dados separado; por isso, vamos criar um serviço que cuidará da busca de dados no servidor.

Vamos implementar o nosso serviço em um arquivo separado

```typescript
// northwind.service.ts

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs/Observable';
import { of } from 'rxjs/observable/of';
import { catchError, map } from 'rxjs/operators';
```

Estamos importando o decorador `Injectable`, que é um [ingrediente essencial](https://angular.io/guide/dependency-injection) em toda definição de serviço {Platform}. O `HttpClient` nos dará a funcionalidade para se comunicar com serviços de backend. Ele retorna um `Observable` de algum resultado, ao qual vamos assinar no nosso componente de grade.

**Observação**: antes do Angular 5, o `HttpClient` ficava em `@angular/http` e se chamava `Http`.

Como vamos receber uma resposta JSON contendo um array de registros, podemos nos ajudar especificando qual tipo de dado esperamos que seja retornado no observable, definindo uma interface com o formato correto. A verificação de tipo é sempre recomendada e pode poupar muitas dores de cabeça no futuro.

```typescript
// northwind.service.ts

export interface NorthwindRecord {
    ProductID: number;
    ProductName: string;
    SupplierID: number;
    CategoryID: number;
    QuantityPerUnit: string;
    UnitPrice: number;
    UnitsInStock: number;
    UnitsOnOrder: number;
    ReorderLevel: number;
    Discontinued: boolean;
    CategoryName: string;
}
```

O serviço em si é bem simples e consiste em um método: `FetchData`, que retornará um `Observable<NorthwindRecord[]>`. Quando a requisição falhar por qualquer motivo (servidor indisponível, erro de rede etc.), o `HttpClient` retornará um erro. Usaremos o operador `CatchError`, que intercepta um Observable que falhou e passa o erro para um handler de erro. Nosso handler de erro registrará o erro e retornará um valor seguro.

```typescript
// northwind.service.ts

@Injectable()
export class NorthwindService {
    private url = 'http://services.odata.org/V4/Northwind/Northwind.svc/Alphabetical_list_of_products';

    constructor(private http: HttpClient) {}

    public fetchData(): Observable<NorthwindRecord[]> {
        return this.http
            .get(this.url)
            .pipe(
                map(response => response['value']),
                catchError(
                    this.errorHandler('Error loading Northwind data', [])
                )
            );
    }

    private errorHandler<T>(message: string, result: T) {
        return (error: any): Observable<any> => {
            console.error(`${message}: ${error.message}`);
            return of(result as T);
        };
    }
}
```

Certifique-se de importar tanto o `HttpClientModule` quanto o nosso serviço no módulo da aplicação e de registrar o serviço como provider.

```typescript
// app.module.ts

import { HttpClientModule } from '@angular/common/http';
import { NorthwindService } from './northwind.service';

@NgModule({
    imports: [
        HttpClientModule
    ],
    providers: [
        NorthwindService
    ]
})
export class AppModule {}
```

Depois de implementar o serviço, vamos injetá-lo no construtor do nosso componente e usá-lo para recuperar os dados. O gancho de ciclo de vida `ngOnInit` é um bom lugar para disparar a requisição inicial.

**Observação**: no código abaixo, você pode se perguntar por que estamos definindo a propriedade _records_ como um array vazio antes de nos inscrevermos no serviço. A requisição Http é assíncrona e, até ser concluída, a propriedade _records_ será _undefined_, o que resultará em erro quando a grade tentar se vincular a ela. Você deve inicializá-la com um valor padrão ou usar um `BehaviorSubject`.

```typescript
// my.component.ts

@Component({

})
export class MyComponent implements OnInit {

    public records: NorthwindRecord[];

    constructor(private northwindService: NorthwindService) {}

    ngOnInit() {
        this.records = [];
        this.northwindService.fetchData().subscribe((records) => this.records = records);
    }
}
```

e no template do componente:

```html
    <igx-grid [data]="records">
        <igx-column field="ProductId"></igx-column>
        <!-- rest of the column definitions -->
    </igx-grid>
```

</PlatformBlock>

**Observação**: é melhor evitar, por enquanto, a propriedade <ApiLink type="GridBaseDirective" member="autoGenerate" label="AutoGenerate" /> da grade ao se vincular a dados remotos. Ela pressupõe que os dados estejam disponíveis para inspecioná-los e gerar as colunas adequadas. Isso geralmente não é o caso até que o serviço remoto responda, e a grade vai lançar um erro. Tornar <ApiLink type="GridBaseDirective" member="autoGenerate" label="AutoGenerate" /> disponível ao se vincular a um serviço remoto está no nosso roadmap para versões futuras.

## Desempenho (experimental)

O design do <ApiLink type="GridToolbar" member="grid" label="Grid" /> permite que ele aproveite o recurso Event Coalescing que o Angular introduziu. Esse recurso melhora o desempenho em cerca de **20%** em termos de interações e responsividade. Ele pode ser habilitado no nível da aplicação simplesmente definindo as propriedades `ngZoneEventCoalescing` e `ngZoneRunCoalescing` como **true** no método `bootstrapModule`:

```typescript
platformBrowserDynamic()
  .bootstrapModule(AppModule, { ngZoneEventCoalescing: true, ngZoneRunCoalescing: true })
  .catch(err => console.error(err));
```

<DocsAside type="info">
Isso ainda é um recurso experimental para o `IgxGridComponent`. Isso significa que podem ocorrer comportamentos inesperados na grade. Se encontrar algum comportamento desse tipo, entre em contato conosco na nossa página do [Github]({GithubLink}/discussions).
</DocsAside>

## Estilizando a grade {Platform}
> **Observação**:
> A grade usa **css grid layout**, que **não é suportado no IE sem prefixos**; consequentemente, ela não será renderizada corretamente.


<PlatformBlock for="WebComponents, Blazor, React">


Além dos temas predefinidos, a grade pode ser personalizada ainda mais definindo algumas das propriedades CSS disponíveis. Para criar um tema completo a partir de poucas cores, consulte o [tópico de temas](./_shared/theming.mdx).
Se quiser alterar o fundo e a cor do texto do cabeçalho, primeiro você precisa definir uma classe para a grade:

<PlatformBlock for="WebComponents">
```html
<igc-grid class="grid"></igc-grid>
```
</PlatformBlock>

<PlatformBlock for="React">
```tsx
<IgrGrid className="grid"></IgrGrid>
```
</PlatformBlock>

<PlatformBlock for="Blazor">
```razor
 <IgbGrid Class="grid"></IgbGrid>
```
</PlatformBlock>

Em seguida, defina as propriedades CSS `--header-background` e `--header-text-color` para essa classe:

```css
.grid {
    --header-background: #494949;
    --header-text-color: #FFF;
}
```


</PlatformBlock>


<PlatformBlock for="Angular">

No [**Angular**](https://angular.io/), a maioria dos estilos recebe prefixos implicitamente, graças ao plugin [Autoprefixer](https://www.npmjs.com/package/autoprefixer).

Para aplicar prefixos aos **layouts de grade**, porém, você precisa habilitar a **propriedade grid** do [Autoprefixer](https://www.npmjs.com/package/autoprefixer) com o comentário ```autoprefixer grid:on```.

Para facilitar o seu trabalho, aplique o comentário no arquivo `src/styles.scss`.

```scss
// src/styles.scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
@include core();
/* autoprefixer grid:on */
@include theme($default-palette);
```

## Limitações conhecidas

|Limitação|Descrição|
|--- |--- |
|Larguras de coluna definidas em `percentage` e `px`|No momento, não oferecemos suporte à combinação de larguras de coluna com `%` e `px`.|
|Ao tentar filtrar uma coluna do tipo `number`|Se um valor diferente de `number` for digitado no campo de filtragem, `NaN` será retornado devido a uma conversão incorreta.|
|A `width` da grade não depende das larguras das colunas | A `width` de todas as colunas não determina a extensão da própria grade. Ela é determinada pelas dimensões do contêiner pai ou pela `width` definida da grade.|
|Grade aninhada em um contêiner pai | Quando a `width` da grade não é definida e ela é colocada em um contêiner pai com dimensões definidas, a grade ocupa esse contêiner.|
| As colunas têm uma largura mínima permitida. Dependendo da variável CSS `--ig-size`, elas são as seguintes: <br/>"small": 56px <br/> "medium": 64px <br/> "large ": 80px | Se for definida uma largura menor que a mínima permitida, isso não afetará os elementos renderizados. Eles serão renderizados com a largura mínima permitida para o `--ig-size` correspondente. Isso pode levar a um comportamento inesperado com a virtualização horizontal e, por isso, não é suportado.
| A altura da linha não é afetada pela altura das células que não estão renderizadas na visualização atual. | Por causa da virtualização, uma coluna com template personalizado (que altera a altura da célula) que não está na visualização não afetará a altura da linha. A altura da linha só será afetada enquanto a coluna relacionada estiver visível na visualização por rolagem.
