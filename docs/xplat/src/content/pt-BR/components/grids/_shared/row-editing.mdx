# Edição de linhas do {Platform} {ComponentTitle}

O recurso de Edição de linhas do {ProductName} em {Platform} {ComponentTitle} permite editar dados diretamente dentro da `{ComponentName}`. Além dessa forma prática de manipular dados, há uma API poderosa para operações de CRUD completas. Você pode editar uma linha da grade clicando nela e pressionando a tecla **Enter**. Outra forma rápida é dar um duplo clique com o mouse na linha que precisa ser modificada.

## Exemplo de edição de linhas do {Platform} {ComponentTitle}

O exemplo a seguir demonstra como habilitar a edição de linhas no `{ComponentName}`. Alterar o valor de uma célula e depois clicar ou navegar para outra célula da mesma linha não atualiza o valor da linha até que seja confirmado pelo botão **Done**, ou descartado pelo botão **Cancel**.

<Sample src="/{ComponentSample}/row-editing-options" height={550} alt="Exemplo de edição de linhas do {Platform} {ComponentTitle}" />



<DocsAside type="info">
Quando uma linha está em modo de edição, clicar em uma célula de outra linha se comporta como se o botão "Done" fosse pressionado, enviando todas as alterações feitas na linha anterior. Se a nova célula focada for editável, a nova linha também entra em modo de edição. No entanto, se a célula não for editável, apenas a linha anterior sai do modo de edição.
</DocsAside>

## Posicionamento

- A posição padrão do overlay fica abaixo da linha que está em modo de edição.

- Se não houver espaço abaixo da linha, o overlay aparecerá acima dela.

- Depois de exibido — acima ou abaixo —, o overlay manterá essa posição durante a rolagem, até ser fechado.

## Comportamento

- Se a linha estiver em modo de edição, a edição continuará se uma célula da mesma linha for clicada.

- Clicar no botão "Done" finalizará a edição da linha e enviará as alterações ao data source ou a uma transação, se houver uma disponível. Além disso, a linha sairá do modo de edição.

- Clicar no botão "Cancel" reverterá todas as alterações atuais da linha, e a linha sairá do modo de edição.

- Se a linha estiver em modo de edição, clicar em uma célula de outra linha finalizará a edição da linha atual e enviará as novas alterações da linha (o mesmo comportamento de clicar no botão "Done"). Se a nova célula que recebe o foco for editável, a nova linha também entra em modo de edição; se a célula não for editável, apenas a linha anterior sai do modo de edição.

- Se a linha estiver em modo de edição e o `{ComponentName}` for rolado de forma que a linha saia da área visível, ela continuará em modo de edição. Quando o `{ComponentName}` for rolado de volta, de modo que a linha fique visível novamente, ela continuará em modo de edição. Clicar fora do `{ComponentName}` também manterá a célula em modo de edição.

- Ao realizar operações de **ordenação**, **filtragem**, **pesquisa** e **ocultação**, todas as alterações atuais da linha serão revertidas, e a linha sairá do modo de edição.

- Ao realizar operações de **paginação**, **redimensionamento**, **fixação** e **movimentação**, a linha sairá do modo de edição e o valor mais recente será enviado.

- Cada célula modificada recebe o estilo de edição até que a edição da linha seja concluída. Este é o comportamento quando o `{ComponentName}` não é fornecido com transações. Quando há transações disponíveis, o estilo de edição da célula é aplicado até que todas as alterações sejam confirmadas.


## Navegação pelo teclado

- <kbd>ENTER</kbd> e <kbd>F2</kbd> entram no modo de edição da linha

- <kbd>ESC</kbd> sai do modo de edição da linha e não envia nenhuma das alterações de célula feitas enquanto a linha estava em modo de edição.

- <kbd>TAB</kbd> move o foco de uma célula editável da linha para a próxima e da célula editável mais à direita para os botões CANCEL e DONE. A navegação a partir do botão DONE vai para a célula editável mais à esquerda da linha que está sendo editada.


## Integração de recursos

- Qualquer operação que altere os dados encerrará as operações de edição de linha e enviará as alterações atuais da linha. Isso inclui operações como ordenação, mudança de critérios de agrupamento e filtragem, paginação etc.

- Os resumos serão atualizados depois que a edição da linha for concluída. O mesmo vale para outros recursos, como ordenação, filtragem etc.

<ComponentBlock for="Grid">
- Expandir e recolher linhas agrupadas não encerrará a edição da linha atual.

</ComponentBlock>

## Estilização

Usando a [{ProductName} Theme Library](themes/index.mdx), podemos alterar bastante a sobreposição de edição de linha.

A sobreposição de edição de linha é um elemento composto: sua interface é formada por alguns outros componentes:

- [igx-banner](banner.mdx) para renderizar o seu conteúdo
- [igx-button](button.mdx)s são renderizados no template padrão (para os botões `Done` e `Cancel`).

No exemplo abaixo, vamos usar as opções de estilo desses dois componentes ([estilo de botão](button.mdx#styling) e [estilo de banner](../banner.mdx#styling)) para personalizar a experiência da edição de linhas da nossa `{ComponentName}`.

Também vamos estilizar o editor e o fundo da célula atual para torná-los mais distintos. Você pode saber mais sobre estilização de células neste [tópico](cell-editing.mdx#styling).

### Importar o tema

A forma mais fácil de estilizar o banner de edição de linha é definir estilos no arquivo de estilos globais do nosso `app` (normalmente `styles.scss`).
O primeiro passo é importar o arquivo `themes/index`, que nos dá acesso a todas as ferramentas poderosas do framework Sass {ProductName}:

```scss
@use "igniteui-{Platform}/theming" as *;

// IMPORTANT: Prior to {ProductName} version 13 use:
// @import '~igniteui-{Platform}/lib/core/styles/themes/index';
```

Depois de importar o arquivo de temas, podemos criar temas personalizados.

#### Defina o tema

Agora podemos definir um <ApiLink type="function-banner-theme" label="Tema do banner" kind="sass" module="index.html" /> personalizado que afetará o fundo da edição de linhas e usará uma das paletas predefinidas, a saber `$purple-palette`:

```scss
    $my-light-gray: #e3e3e3;
    $my-banner-palette: $purple-palette;

    $banner-theme: banner-theme(
        $banner-background: $my-light-gray,
        $banner-message-color: color($my-banner-palette, "secondary", 600)
    );
```

Aqui estamos usando `my-banner-palette` em conjunto com `igx-color` (exposto pela biblioteca de temas) para gerar as nossas cores.

### Inclua o tema

Tudo o que precisamos fazer agora é aplicar o tema com a instrução Sass `@include`. Passamos nosso `$banner-theme` recém-definido pelo **mixin igx-banner**:

```scss
@include banner($banner-theme);
```

Isso aplicará nosso tema de banner personalizado à sobreposição de edição de linha. No entanto, como definimos esses estilos no arquivo de estilos globais, eles também se aplicarão a **todos** os banners da nossa aplicação.

### Estilos de componente

Como a sobreposição de edição de linha usa temas de vários outros componentes, estilizá-la pelos estilos globais pode afetar outras partes da aplicação (por exemplo, banners, botões etc.). A melhor forma de evitar isso é restringir o escopo do nosso tema de banner. Podemos definir nossos estilos (incluindo a [importação do tema](#importar-o-tema)) no componente que contém nossa `{ComponentName}`.

<DocsAside type="info">
Se o componente usar um ViewEncapsulation [Emulated](themes/styles.mdx#view-encapsulation), é necessário penetrar essa encapsulação usando `::ng-deep` para estilizar a grade.
Envolvemos a instrução dentro de um seletor `:host` para evitar que nossos estilos afetem elementos fora do nosso componente:
</DocsAside>

```scss
// custom.component.scss

:host {
    ::ng-deep {
        @include banner($banner-theme);
    }
}
```

Com a sintaxe acima, o nosso tema de banner personalizado se aplica corretamente ao overlay de edição de linhas do grid.

### Templates personalizados

Para personalizar ainda mais o nosso overlay de edição de linhas, podemos passar um template personalizado, para estilizar os botões `Done` e `Cancel` separadamente:

```html
<!-- in component.html -->
<{ComponentSelector}>
    <ng-template igxRowEditActions let-endRowEdit>
        <div class="custom-buttons">
            <button igxIconButton="flat" class="custom-button" igxRowEditTabStop (click)="endRowEdit(false)">
                <igx-icon>clear</igx-icon>
            </button>
            <button igxIconButton="flat" class="custom-button" igxRowEditTabStop (click)="endRowEdit(true)">
                <igx-icon>check</igx-icon>
            </button>
        </div>
    </ng-template>
</{ComponentSelector}>
```

Depois de definir nossos botões personalizados, podemos usar o <ApiLink type="function-flat-icon-button-theme" label="flat-icon-button-theme" kind="sass" module="index.html" /> para estilizá-los. Você pode saber mais sobre estilização de `igx-icon-button` neste [tópico](../icon-button.mdx#styling). Podemos criar um tema personalizado para nossos `Done` e `Cancel`:

```scss
// custom.component.scss
// ...

$button-theme: flat-icon-button-theme(
  $background: #e3e3e3,
  $foreground: #423589
);

.custom-buttons {
  @include tokens($button-theme);
}
```

Restringimos a nossa instrução `@include` em `.custom-buttons`, para que ela seja aplicada somente aos botões `Done` e `Cancel`.
