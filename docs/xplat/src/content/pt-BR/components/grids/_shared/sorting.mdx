# Ordenação do {Platform} {ComponentTitle}

O recurso de Ordenação de dados do {ProductName} em {Platform} {ComponentTitle} é habilitado por coluna, o que significa que a <ApiLink type="{ComponentName}" /> pode ter uma combinação de colunas ordenáveis e não ordenáveis. Executar ações de ordenação {Platform} permite alterar a ordem de exibição dos registros com base em critérios especificados.

<PlatformBlock for="Angular">
<DocsAside type="info">
Até agora, agrupamento e ordenação funcionavam em conjunto. Na versão 13.2, foi introduzido um novo comportamento que desacopla o agrupamento da ordenação. Por exemplo, limpar o agrupamento não limpará as expressões de ordenação da grade, e vice-versa. Ainda assim, se uma coluna estiver ordenada e agrupada ao mesmo tempo, as expressões de agrupamento têm precedência.
</DocsAside>

</PlatformBlock>

## Ordenando pela API

Você pode ordenar qualquer coluna ou uma combinação de colunas pela API do <ApiLink type="{ComponentName}" /> usando o método <ApiLink type="{ComponentName}" member="sort" label="Sort" />:

<PlatformBlock for="Angular">
```typescript

```
</PlatformBlock>

<PlatformBlock for="WebComponents">

</PlatformBlock>

<ComponentBlock for="Grid">
<PlatformBlock for="Angular">
```typescript

// Perform a case insensitive ascending sort on the ProductName column.

    { fieldName: 'ProductName', dir: SortingDirection.Asc, ignoreCase: true },
```

```typescript
    this.grid.sortingExpressions = [
```

## Estilização

Para começar a estilizar o comportamento de ordenação, precisamos importar o arquivo `index`, onde ficam todas as funções de tema e os mixins de componente:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Seguindo a abordagem mais simples, criamos um novo tema que estende o <ApiLink type="function-grid-theme" label="grid-theme" kind="sass" module="index.html" /> e aceita os parâmetros `$sorted-header-icon-color` e `sortable-header-icon-hover-color`.

```scss
$custom-theme: grid-theme(
    $sorted-header-icon-color: #ffb06a,
    $sortable-header-icon-hover-color: black
);
```

O último passo é **incluir** os mixins de componente:

```scss
 @include grid($custom-theme);
```

<DocsAside type="info">
Se o componente estiver usando um ViewEncapsulation [Emulated](../themes/styles.mdx#view-encapsulation), é necessário `penetrate` esse encapsulamento usando `::ng-deep`:
</DocsAside>

 ```scss
:host {
    ::ng-deep {
        @include grid($custom-theme);
    }
}
```

### Definindo uma paleta de cores

Em vez de fixar os valores de cor como acabamos de fazer, podemos obter mais flexibilidade em relação às cores usando as funções <ApiLink type="function-igx-palette" label="igx-palette" kind="sass" module="index.html" /> e <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" />.

`igx-palette` gera uma paleta de cores com base nas cores primária e secundária que são passadas:

```scss
$black-color: black;
$orange-color: #ffb06a;

$custom-palette: palette($primary: $black-color, $secondary: $orange-color);
```

E então, com <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" />, podemos obter facilmente uma cor da paleta.

```scss
$custom-theme: grid-theme(
    $sorted-header-icon-color: color($custom-palette, "secondary", 500),
    $sortable-header-icon-hover-color: color($custom-palette, "primary", 500)
);
```

<DocsAside type="info">
As funções `igx-color` e `igx-palette` são poderosas para gerar e obter cores. Consulte o tópico [Paletas](../themes/sass/palettes.mdx) para orientações detalhadas sobre como usá-las.
</DocsAside>

### Usando schemas

Indo além do mecanismo de temas, você pode criar uma estrutura robusta e flexível que se beneficia dos [**schemas**](../themes/sass/schemas.mdx). Um **schema** é uma receita de tema.

Estenda um dos dois schemas predefinidos fornecidos para cada componente; neste caso, <ApiLink type="variable-_light-grid" label="_light-grid" kind="sass" module="index.html" />:

```scss
// Extending the light grid schema
$custom-grid-schema: extend($_light-grid,
    (
        sorted-header-icon-color: (igx-color:('secondary', 500)),
        sortable-header-icon-hover-color: (igx-color:('primary', 500))
    )
);
```

Para aplicar nosso schema personalizado, precisamos **estender** um dos globais (<ApiLink type="variable-light-schema" label="light" kind="sass" module="index.html" /> ou <ApiLink type="variable-dark-schema" label="dark" kind="sass" module="index.html" />), o que basicamente aponta os componentes com um schema personalizado; depois disso, adicione-o aos respectivos temas dos componentes:

```scss
// Extending the global light-schema
$my-custom-schema: extend($light-schema,
    (
        igx-grid: $custom-grid-schema
    )
);

// Defining our custom theme with the custom schema
$custom-theme: grid-theme(
  $palette: $custom-palette,
  $schema: $my-custom-schema
);
```

Não se esqueça de incluir os temas da mesma forma como foi demonstrado acima.

## Estilização

Além dos temas predefinidos, a grade pode ser personalizada ainda mais definindo algumas das propriedades CSS disponíveis. Para criar um tema completo a partir de apenas algumas cores, consulte o [tópico de temas](theming.mdx).
