# Fixação de colunas do {Platform} {ComponentTitle}

O recurso de Fixação de colunas do {ProductName} em {Platform} {ComponentTitle} permite que os desenvolvedores travem colunas específicas em uma ordem desejada, garantindo que elas fiquem sempre visíveis, mesmo quando os usuários rolam horizontalmente pela `{ComponentName}`. Há uma interface integrada para a Fixação de colunas, acessível pela barra de ferramentas {Platform} {ComponentTitle}. Além disso, os desenvolvedores têm a flexibilidade de criar uma interface personalizada que altera o estado de fixação das colunas.

## Exemplo de fixação de colunas do {Platform} {ComponentTitle}

Este exemplo demonstra como fixar uma coluna ou várias colunas no lado esquerdo ou direito do <ApiLink type="{ComponentName}" />.

## API de fixação de colunas

A fixação de colunas é controlada pela propriedade <ApiLink type="Column" member="pinned" /> de <ApiLink type="Column" />. As colunas fixadas são renderizadas no lado esquerdo do <ApiLink type="{ComponentName}" /> por padrão e permanecem fixas durante a rolagem horizontal das colunas não fixadas no corpo do <ApiLink type="{ComponentName}" />.

## Posição da fixação

Você pode alterar a posição da fixação de colunas pela opção de configuração <ApiLink type="Column" member="pinningPosition" />. Ela permite definir a posição das colunas como Start ou End.
Quando definida como End, as colunas são renderizadas no fim do grid, depois das colunas não fixadas. As colunas não fixadas podem ser roladas horizontalmente, enquanto as colunas fixadas permanecem fixas à direita.

## Interface personalizada de fixação de colunas

Você pode definir a sua interface personalizada e alterar o estado de fixação das colunas pela API relacionada.

Digamos que, em vez de uma barra de ferramentas, você queira definir ícones de fixação nos cabeçalhos das colunas, que o usuário final pode clicar para alterar o estado de fixação de cada coluna.

Isso pode ser feito criando um template de cabeçalho para as colunas, com um ícone personalizado.

// In JavaScript
igRegisterScript("WebGridPinHeaderTemplate", (ctx) => {
    var html = window.igTemplating.html;
    window.toggleColumnPin = function toggleColumnPin(field) {
        var grid = document.getElementsByTagName["igc-grid"](0);
        var col = grid.getColumnByName(field);
        col.pinned = !col.pinned;
        grid.markForCheck();
    }
    return html`<div>
    <span style="float:left">${ctx.column.field}</span>
    <span style="float:right" @pointerdown="${() => toggleColumnPin(ctx.column.field)}">📌</span>
</div>`;
}, false);

## Limitações da fixação

- Definir explicitamente larguras de colunas em porcentagem (%) faz com que o corpo do <ApiLink type="{ComponentName}" /> e o conteúdo do cabeçalho fiquem desalinhados quando há colunas fixadas. Para que a fixação de colunas funcione corretamente, as larguras das colunas devem estar em pixels (px) ou ser atribuídas automaticamente pelo <ApiLink type="{ComponentName}" />.

## Estilização

O <ApiLink type="{ComponentName}" /> permite estilização por meio da [{ProductName} Theme Library](../themes/styles.mdx). A propriedade <ApiLink type="function-grid-theme" label="theme" kind="sass" module="index.html" /> da grade expõe uma grande variedade de propriedades, que permitem personalizar todos os recursos da grade.

Nas etapas abaixo, vamos percorrer os passos para personalizar a estilização da fixação do grid.

### Importando o tema global
Para começar a personalizar o recurso de fixação, você precisa importar o arquivo `index`, onde estão todas as funções e mixins de estilização.

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

### Definindo um tema personalizado
Em seguida, crie um novo tema que estenda o <ApiLink type="function-grid-theme" label="grid-theme" kind="sass" module="index.html" /> e aceite os parâmetros necessários para personalizar o recurso de fixação como desejar.

```scss
$custom-theme: grid-theme(
    /* Pinning properties that affect styling */
    $pinned-border-width: 5px,
    $pinned-border-style: double,
    $pinned-border-color: #FFCD0F,
    $cell-active-border-color: #FFCD0F
    /* add other features properties here... */
);
```

### Definindo uma paleta de cores personalizada
Na abordagem descrita acima, os valores de cor estavam fixos no código. Como alternativa, você pode obter mais flexibilidade usando as funções <ApiLink type="function-igx-palette" label="igx-palette" kind="sass" module="index.html" /> e <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" />.
`igx-palette` gera uma paleta de cores com base nas cores primária e secundária fornecidas.

 ```scss
$primary-color: #292826;
$secondary-color: #ffcd0f;

$custom-palette: palette(
  $primary: $primary-color,
  $secondary: $secondary-color
);
```

Depois que uma paleta personalizada é gerada, a função `igx-color` pode ser usada para obter diferentes variações das cores primária e secundária.


```scss
$custom-theme: grid-theme(
    $pinned-border-width: 5px,
    $pinned-border-style: double,
    $pinned-border-color: color($custom-palette, "secondary", 500),
    $cell-active-border-color: color($custom-palette, "secondary", 500)
);
```

O `$custom-theme` contém as mesmas propriedades da seção anterior, mas desta vez as cores não estão fixas. Em vez disso, foi usada a `igx-palette` personalizada e as cores foram obtidas por meio das suas cores primária e secundária, com uma determinada variante de cor.

### Definindo schemas personalizados
Você pode ir ainda mais longe e criar uma estrutura flexível que tenha todos os benefícios de um [**schema**](../themes/sass/schemas.mdx). O **schema** é a receita de um tema.
Estenda um dos dois schemas predefinidos, fornecidos para cada componente. No nosso caso, usaríamos `$_light_grid`.

```scss
$custom-grid-schema: extend($_light-grid,(
    pinned-border-width: 5px,
    pinned-border-style: double,
    pinned-border-color: color: ("secondary", 500),
    cell-active-border-color: color: ("secondary", 500)
));
```

Para que o schema personalizado seja aplicado, é preciso estender um dos globais `light` ou `dark`. O processo, na prática, consiste em fornecer a um componente um schema personalizado e, depois, adicioná-lo ao tema do respectivo componente.

```scss
$my-custom-schema: extend($light-schema, (
    igx-grid: $custom-grid-schema
));
$custom-theme: grid-theme(
    $palette: $custom-palette,
    $schema: $my-custom-schema
);
```

### Aplicando o tema personalizado
A forma mais fácil de aplicar o seu tema é com uma instrução `sass` `@include` no arquivo de estilos globais:

```scss
@include grid($custom-theme);
```

### Tema limitado ao componente

Para que o tema personalizado afete apenas um componente específico, você pode mover todos os estilos que acabou de definir do arquivo de estilos globais para o arquivo de estilos do componente personalizado (incluindo a importação do arquivo `index`).

Dessa forma, por causa do [ViewEncapsulation](https://angular.io/api/core/Component#encapsulation) do Angular, os seus estilos serão aplicados somente ao seu componente personalizado.
 <DocsAside type="info">
 Se o componente estiver usando um ViewEncapsulation [Emulated](../themes/styles.mdx#view-encapsulation), é necessário atravessar esse encapsulamento usando `::ng-deep` para estilizar a grade.
 </DocsAside>

 <DocsAside type="info">
 Envolva a instrução em um seletor `:host` para impedir que os seus estilos afetem elementos fora do nosso componente:
 </DocsAside>

```scss
:host {
    ::ng-deep {
        @include grid($custom-theme);
    }
}
```
