# Resumos do {Platform} {ComponentTitle}

O recurso de Resumos do {ProductName} em {Platform} {ComponentTitle} funciona por coluna, como rodapé do grupo. Os resumos {Platform} {ComponentName} são um recurso poderoso que permite ao usuário ver informações da coluna em um contêiner separado, com um conjunto predefinido de itens de total padrão, dependendo do tipo de dado da coluna, ou implementando um template personalizado na <ApiLink type="{ComponentName}" />.

## Exemplo de visão geral de resumos do {Platform} {ComponentTitle}

<DocsAside type="info">
O resumo da coluna é uma **função de todos os valores da coluna**, a menos que haja filtragem aplicada; nesse caso, o resumo da coluna será uma **função dos valores filtrados**
</DocsAside>

Os resumos <ApiLink type="{ComponentName}" /> também podem ser habilitados por coluna no {ProductName}, o que significa que você pode ativá-los apenas para as colunas de que precisa. Os resumos <ApiLink type="{ComponentName}" /> oferecem um conjunto predefinido de resumos padrão, dependendo do tipo de dado da coluna, para economizar tempo:


Para `string` e `boolean` <ApiLink type="Column" member="dataType" />, a seguinte função está disponível:
- Contagem

Para os tipos de dados `number`, `currency` e `percent`, as seguintes funções estão disponíveis:

- Contagem
- Mínimo
- Máximo
- Média
- Soma

Para o tipo de dado `date`, as seguintes funções estão disponíveis:
- Contagem
- Mais antigo
- Mais recente

Todos os tipos de dados de coluna disponíveis podem ser encontrados no tópico oficial [Tipos de coluna](column-types.mdx#template-padrão).

Os resumos <ApiLink type="{ComponentName}" /> são habilitados por coluna definindo a propriedade <ApiLink type="ColumnState" member="hasSummary" /> como **true**. Também é importante lembrar que os resumos de cada coluna são resolvidos de acordo com o tipo de dado da coluna. Na <ApiLink type="{ComponentName}" />, o tipo de dado padrão da coluna é `string`; portanto, se você quiser resumos específicos de `number` ou de `date`, deve especificar a propriedade <ApiLink type="Column" member="dataType" /> como `number` ou `date`. Observe que os valores dos resumos serão exibidos localizados, de acordo com o <ApiLink type="GridBaseDirective" member="locale" label="Locale" /> da grade e o <ApiLink type="Column" member="pipeArgs" /> da coluna.

## {ComponentTitle} Summaries personalizados

Se essas funções não atenderem aos seus requisitos, você pode fornecer um total personalizado para colunas específicas.


<PlatformBlock for="WebComponents">
Para isso, você precisa sobrescrever uma das classes base <ApiLink type="SummaryOperand" />, <ApiLink type="NumberSummaryOperand" /> ou <ApiLink type="DateSummaryOperand" />, de acordo com o tipo de dado da coluna e com as suas necessidades. Assim, você pode redefinir a função existente ou adicionar novas funções. A classe <ApiLink type="SummaryOperand" /> fornece a implementação padrão apenas para o método <ApiLink type="SummaryOperand" member="count" label="Count" />. <ApiLink type="NumberSummaryOperand" /> estende <ApiLink type="SummaryOperand" /> e fornece a implementação para <ApiLink type="NumberSummaryOperand" member="min" label="Min" />, <ApiLink type="NumberSummaryOperand" member="max" label="Max" />, <ApiLink type="NumberSummaryOperand" member="sum" label="Sum" /> e <ApiLink type="NumberSummaryOperand" member="average" label="Average" />. <ApiLink type="DateSummaryOperand" /> estende <ApiLink type="SummaryOperand" /> e, além disso, oferece <ApiLink type="DateSummaryOperand" member="earliest" label="Earliest" /> e <ApiLink type="DateSummaryOperand" member="latest" label="Latest" />.

</PlatformBlock>

<PlatformBlock for="Angular">
```typescript
import { IgxSummaryResult, IgxSummaryOperand, IgxNumberSummaryOperand, IgxDateSummaryOperand } from 'igniteui-angular';

class MySummary extends IgxNumberSummaryOperand {
    constructor() {
        super();
    }

    operate(data?: any[]): IgxSummaryResult[] {
        const result = super.operate(data);
        result.push({
            key: 'test',
            label: 'Test',
            summaryResult: data.filter(rec => rec > 10 && rec < 30).length
        });
        return result;
    }
}

```
</PlatformBlock>

## Formatando resumos
Por padrão, os resultados de resumo produzidos pelos operandos de resumo integrados são localizados e formatados de acordo com a <ApiLink type="GridBaseDirective" member="locale" label="Locale" /> do grid e a <ApiLink type="Column" member="pipeArgs" /> da coluna. Ao usar operandos personalizados, a <ApiLink type="GridBaseDirective" member="locale" label="Locale" /> e a <ApiLink type="Column" member="pipeArgs" /> não são aplicadas. Se você quiser alterar a aparência padrão dos resultados de resumo, pode formatá-los usando a propriedade <ApiLink type="Column" member="summaryFormatter" label="SummaryFormatter" />.

```typescript
public dateSummaryFormat(summary: IgxSummaryResult, summaryOperand: IgxSummaryOperand): string {
    const result = summary.summaryResult;
    if (summaryOperand instanceof IgxDateSummaryOperand && summary.key !== 'count'
        && result !== null && result !== undefined) {
        const pipe = new DatePipe('en-US');
        return pipe.transform(result,'MMM YYYY');
    }
    return result;
}
```

## Resumos com Group By

Quando você agrupou por colunas, a <ApiLink type="{ComponentName}" /> permite alterar a posição do resumo e o modo de cálculo usando as propriedades <ApiLink type="{ComponentName}" member="summaryCalculationMode" label="SummaryCalculationMode" /> e <ApiLink type="{ComponentName}" member="summaryPosition" label="SummaryPosition" />. Junto com essas duas propriedades, a <ApiLink type="{ComponentName}" /> expõe também a propriedade <ApiLink type="{ComponentName}" member="showSummaryOnCollapse" label="ShowSummaryOnCollapse" />, que permite determinar se a linha de resumo permanece visível quando a linha de grupo a que se refere está recolhida.

Os valores disponíveis da propriedade <ApiLink type="{ComponentName}" member="summaryCalculationMode" label="SummaryCalculationMode" /> são:

- <ApiLink type="GridSummaryCalculationMode" label="RootLevelOnly" /> - Os resumos são calculados apenas para o nível raiz.
- <ApiLink type="GridSummaryCalculationMode" label="ChildLevelsOnly" /> - Os resumos são calculados apenas para os níveis filhos.
- <ApiLink type="GridSummaryCalculationMode" label="RootAndChildLevels" /> - Os resumos são calculados para os níveis raiz e filhos. Este é o valor padrão.

Os valores disponíveis da propriedade <ApiLink type="{ComponentName}" member="summaryPosition" label="SummaryPosition" /> são:

- <ApiLink type="GridSummaryPosition" label="Top" /> - A linha de resumos aparece antes dos filhos da linha de agrupamento.
- <ApiLink type="GridSummaryPosition" label="Bottom" /> - A linha de resumos aparece depois dos filhos da linha de agrupamento. Este é o valor padrão.

A propriedade <ApiLink type="{ComponentName}" member="showSummaryOnCollapse" label="ShowSummaryOnCollapse" /> é booleana. Seu valor padrão é **false**, o que significa que a linha de resumo ficará oculta quando a linha de grupo estiver recolhida. Se a propriedade for definida como **true**, a linha de resumo permanece visível quando a linha de grupo está recolhida.


<DocsAside type="info">
A propriedade <ApiLink type="{ComponentName}" member="summaryPosition" label="SummaryPosition" /> se aplica apenas aos resumos do nível filho. Os resumos do nível raiz aparecem sempre fixos na parte inferior do <ApiLink type="{ComponentName}" />.
</DocsAside>

## Estilização

Para começar a estilizar o comportamento de ordenação, precisamos importar o arquivo `index`, onde ficam todas as funções de tema e os mixins de componente:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Seguindo a abordagem mais simples, criamos um novo tema que estende o <ApiLink type="function-grid-summary-theme" label="grid-summary-theme" kind="sass" module="index.html" /> e aceita os parâmetros `$background-color`, `$focus-background-color`, `$label-color`, `$result-color`, `$pinned-border-width`, `$pinned-border-style` e `$pinned-border-color`.

```scss
$custom-theme: grid-summary-theme(
    $background-color: #e0f3ff,
    $focus-background-color: rgba( #94d1f7, .3 ),
    $label-color: #e41c77,
    $result-color: black,
    $pinned-border-width: 2px,
    $pinned-border-style: dotted,
    $pinned-border-color: #e41c77
);
```

O último passo é **incluir** os mixins de componente:

```scss
@include grid-summary($custom-theme);
```

<DocsAside type="info">
Se o componente estiver usando um ViewEncapsulation [Emulated](../themes/styles.mdx#view-encapsulation), é necessário `penetrate` esse encapsulamento usando `::ng-deep`:
</DocsAside>

 ```scss
:host {
    ::ng-deep {
        @include grid-summary($custom-theme);
    }
}
```

### Definindo uma paleta de cores

Em vez de fixar os valores de cor como acabamos de fazer, podemos obter mais flexibilidade em relação às cores usando as funções <ApiLink type="function-igx-palette" label="igx-palette" kind="sass" module="index.html" /> e <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" />.

`igx-palette` gera uma paleta de cores com base nas cores primária e secundária que são passadas:

```scss
$blue-color: #7793b1;
$green-color: #00ff2d;

$my-custom-palette: palette($primary: $blue-color, $secondary: $green-color);
```

E então, com <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" />, podemos obter facilmente uma cor da paleta.

```scss
$custom-theme: grid-summary-theme(
    $background-color: color($my-custom-palette, "primary", 700),
    $focus-background-color: color($my-custom-palette, "primary", 800),
    $label-color: color($my-custom-palette, "secondary", 500),
    $result-color: color($my-custom-palette, "grays", 900),
    $pinned-border-width: 2px,
    $pinned-border-style: dotted,
    $pinned-border-color: color($my-custom-palette, "secondary", 500)
);
```

<DocsAside type="info">
As funções `igx-color` e `igx-palette` são poderosas para gerar e obter cores. Consulte o tópico [Paletas](../themes/palettes.mdx) para orientações detalhadas sobre como usá-las.
</DocsAside>

### Usando schemas

Indo além do mecanismo de temas, você pode criar uma estrutura robusta e flexível que se beneficia dos [**schemas**](../themes/sass/schemas.mdx). Um **schema** é uma receita de tema.

Estenda um dos dois schemas predefinidos fornecidos para cada componente; neste caso, <ApiLink type="variable-_light-grid-summary" label="_light-grid-summary" kind="sass" module="index.html" />:

```scss
// Extending the light grid summary schema
$my-summary-schema: extend($_light-grid-summary,
    (
        background-color: (igx-color: ('primary', 700)),
        focus-background-color: (igx-color: ('primary', 800)),
        label-color: (igx-color: ('secondary', 500)),
        result-color: (igx-color: ('grays', 900)),
        pinned-border-width: 2px,
        pinned-border-style: dotted,
        pinned-border-color: (igx-color: ('secondary', 500))
    )
);
```

Para aplicar nosso schema personalizado, precisamos **estender** um dos globais (<ApiLink type="variable-light-schema" label="light" kind="sass" module="index.html" /> ou <ApiLink type="variable-dark-schema" label="dark" kind="sass" module="index.html" />), o que basicamente aponta os componentes com um schema personalizado; depois disso, adicione-o aos respectivos temas dos componentes:

```scss
// Extending the global light-schema
$my-custom-schema: extend($light-schema,
    (
        igx-grid-summary: $my-summary-schema
    )
);

// Defining our custom theme with the custom schema
$custom-theme: grid-summary-theme(
    $palette: $my-custom-palette,
    $schema: $my-custom-schema
);
```

Não se esqueça de incluir os temas da mesma forma como foi demonstrado acima.
