# Edição e validação do {Platform} {ComponentTitle}

A {Platform} {ComponentName} oferece edição com um mecanismo de validação integrado para os dados digitados pelo usuário ao editar células ou linhas. Ela estende a funcionalidade de validação de formulários para permitir uma integração mais fácil com uma funcionalidade bem conhecida. Quando o estado do editor muda, indicadores visuais são aplicados à célula editada na `{ComponentName}`.

## Configuração

### Configurar por meio de configuração orientada por template

Estendemos alguns dos validadores de {Platform} Forms para funcionar diretamente com a <ApiLink type="Column" />. Os mesmos validadores estão disponíveis como atributos, para serem definidos de forma declarativa em <ApiLink type="Column" />. Os seguintes validadores são suportados de imediato:

- Required
- Mínimo
- Máximo
- Email
- MinLength
- MaxLength
- Pattern

Para validar que a entrada de uma coluna foi preenchida e que o valor será formatado como e-mail, você pode usar as diretivas correspondentes:

## API do serviço de validação

A grade expõe um serviço de validação por meio da propriedade <ApiLink type="{ComponentName}" member="validation" />.

Esse serviço tem as seguintes APIs públicas:

- `Valid` - retorna se o estado de validação do grid é válido.
- `GetInvalid` - retorna os registros com estados inválidos.
- `Clear` - limpa o estado de um registro pelo id ou limpa todos os estados se nenhum id for informado.
- <ApiLink type="{ComponentName}" member="markAsTouched" /> - marca o registro/campo relacionado como tocado.

Estados inválidos persistem até que os erros de validação neles sejam corrigidos de acordo com a regra de validação ou sejam limpos.

## Gatilhos de validação

A validação será disparada nos seguintes cenários:

- Durante a edição pelo editor de célula, com base na <ApiLink type="GridValidationTrigger" /> do grid. Seja em `Change` enquanto se digita no editor, seja em `Blur` quando o editor perde o foco ou é fechado.
- Ao atualizar células ou linhas por meio da API - <ApiLink type="{ComponentName}" member="updateRow" />, <ApiLink type="{ComponentName}" member="updateCell" /> etc.
- Ao usar a edição em lote e a API `Undo`/`Redo` do serviço de transações.

<DocsAside type="info">
A validação não será disparada para registros que não foram editados pela entrada do usuário ou pela API de edição. Os indicadores visuais na célula só serão exibidos se a entrada relacionada for considerada tocada — seja por interação do usuário, seja pela API <ApiLink type="{ComponentName}" member="markAsTouched" /> do serviço de validação.
</DocsAside>

## Opções de personalização de validação do {Platform} {ComponentTitle}

### Definir um validador personalizado

Você pode definir a sua própria diretiva de validação para usar em uma <ApiLink type="Column" /> no template.

```ts
@Directive({
    selector: '[phoneFormat]',
    providers: [{ provide: NG_VALIDATORS, useExisting: PhoneFormatDirective, multi: true }]
})
export class PhoneFormatDirective extends Validators {
    @Input('phoneFormat')
    public phoneFormatString = '';

    public validate(control: AbstractControl): ValidationErrors | null {
        return this.phoneFormatString ? phoneFormatValidator(new RegExp(this.phoneFormatString, 'i'))(control)
            : null;
    }
}
```

Depois de definida e adicionada ao módulo da sua aplicação, você pode defini-la de forma declarativa para uma coluna específica do grid:

```html
<igx-column phoneFormat="\+\d{1}\-(?!0)(\d{3})\-(\d{3})\-(\d{4})\b"></igx-column>
```

### Alterar o template de erro padrão

Você pode definir seu próprio template de erro, que será exibido no tooltip de erro quando a célula entrar em estado inválido. Isso é útil em cenários em que você quer adicionar sua própria mensagem de erro ou alterar de outra forma a aparência ou o conteúdo da mensagem.

```html
<igx-column>
  <ng-template igxCellValidationError let-cell='cell' let-defaultErr="defaultErrorTemplate">
      <ng-container *ngTemplateOutlet="defaultErr">
      </ng-container>
      @if (cell.validation.errors?.['phoneFormat']) {
        <div>
          Please enter correct phone format
        </div>
      }
  </ng-template>
</igx-column>
```

### Impedir a saída do modo de edição em estado inválido

Em alguns casos, você pode querer impedir o envio de um valor inválido aos dados. Nesse cenário, você pode usar os eventos <ApiLink type="{ComponentName}" member="cellEdit" /> ou <ApiLink type="{ComponentName}" member="rowEdit" /> e cancelar o evento caso o novo valor seja inválido.

Os argumentos de ambos os eventos têm uma propriedade `Valid` e podem ser cancelados de acordo.


```ts
    evt.cancel = true;
  }
}
```

### Validação entre campos

Em alguns cenários, a validação de um campo pode depender do valor de outro campo do registro.

Nesse caso, um validador personalizado pode ser usado para comparar os valores do registro por meio de sua <PlatformBlock for="Angular"><ApiLink type="IGridFormGroupCreatedEventArgs" member="formGroup" label="FormGroup" /></PlatformBlock><PlatformBlock for="WebComponents,Blazor"><ApiLink type="FormGroup" /></PlatformBlock>.

<ComponentBlock for="Grid">
O exemplo a seguir demonstra uma validação entre campos de diferentes campos do mesmo registro. Ele verifica a validade das datas em relação à data atual e entre a data ativa e a data de criação do registro, além da proporção de negócios ganhos/perdidos de cada funcionário. Todos os erros são reunidos em uma coluna fixada separada, que mostra que o registro é inválido e exibe os erros relacionados.

As próximas linhas de código mostram a função validadora entre campos, que contém as comparações e define os erros relacionados a elas.

<PlatformBlock for="Blazor">
```razor
private rowValidator(): ValidatorFn {
    return (formGroup: FormGroup): ValidationErrors | null => {
        let returnObject = {};
        const createdOnRecord = formGroup.get('created_on');
        const lastActiveRecord = formGroup.get('last_activity');
        const winControl = formGroup.get('deals_won');
        const loseControl = formGroup.get('deals_lost');
        const actualSalesControl = formGroup.get('actual_sales');

        // Validate dates
        const curDate = new Date();
        if (new Date(createdOnRecord.value) > curDate) {
            // The created on date should not be greater than current date.
            returnObject['createdInvalid'] =  true;
        }
        if (new Date(lastActiveRecord.value) > curDate) {
            // The last active date should not be greater than current date.
            returnObject['lastActiveInvalid'] = true;
        }
        if (new Date(createdOnRecord.value) > new Date(lastActiveRecord.value)) {
            // The created on date should not be greater than last active date.
            returnObject['createdLastActiveInvalid'] = true;
        }

        // Validate deals
        const dealsRatio = this.calculateDealsRatio(winControl.value, loseControl.value);
        if (actualSalesControl.value === 0 && dealsRatio > 0) {
            // If the actual sales value is 0 but there are deals made.
            returnObject['salesZero'] = true;
        }
        if (actualSalesControl.value > 0 && dealsRatio === 0) {
            // If the deals ratio based on deals won is 0 but the actual sales is bigger than 0.
            returnObject['salesNotZero'] = true;
        }

        return returnObject;
    };
}

public calculateDealsRatio(dealsWon, dealsLost) {
    if (dealsLost === 0) return dealsWon + 1;
    return Math.round(dealsWon / dealsLost * 100) / 100;
}

```

Validadores entre campos podem ser adicionados ao formGroup no evento `FormGroupCreated`. Neles, vários campos podem ser comparados quanto à validade.

```ts
  public formCreateCustomerHandler(event: IGridFormGroupCreatedEventArgs) {
        const formGroup = event.formGroup;
        formGroup.addValidators(this.addressValidator());
    }

    public formCreateOrderHandler(event: IGridFormGroupCreatedEventArgs) {
        const formGroup = event.formGroup;
        formGroup.addValidators(this.dateValidator());
    }

    public addressValidator(): ValidatorFn {
        return (control: AbstractControl): ValidationErrors | null => {
            const formGroup = control;
            let returnObject = {};
            const city = formGroup.get('City');
            const country = formGroup.get('Country');
            const validCities = this.countryData.get(country.value);
            if (!validCities || !validCities[city.value]) {
                returnObject['invalidAddress'] = true;
            }
            return returnObject;
        }
    }

    public dateValidator(): ValidatorFn {
        return (control: AbstractControl): ValidationErrors | null => {
            const formGroup = control;
            let returnObject = {};
            const orderDate = formGroup.get('OrderDate').value;
            const shippedDate = formGroup.get('ShippedDate').value;
            if (new Date(shippedDate) < new Date(orderDate)) {
                returnObject['invalidRange'] = true;
            }
            return returnObject;
        }
    }
```

```ts
    public isRowValid(cell: IgxGridCell) {
        const hasErrors = !!cell.row.validation.errors || cell.row.cells.some(x => !!x.validation.errors);
        return !hasErrors;
    }

    public stateMessage(cell: IgxGridCell) {
        const messages = [];
        const row = cell.row;
        if  (row.validation.errors?.invalidAddress) {
            messages.push('The address information is invalid. City does not match the Country.');
        }
        if  (row.validation.errors?.invalidRange) {
            messages.push('The ShippedDate cannot be before the OrderDate.');
        }
        const cellValidationErrors = row.cells.filter(x => !!x.validation.errors);
        if (cellValidationErrors && cellValidationErrors.length > 0) {
            const fields = cellValidationErrors.map(x => x.column.field).join(',');
            messages.push('The following fields are required: ' + fields);
        }

        if (messages.length === 0) {
            // no errors
            return ['Valid'];
        }
        return messages;
    }
```
