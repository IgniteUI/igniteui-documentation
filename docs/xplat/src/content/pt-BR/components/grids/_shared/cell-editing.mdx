# Edição de células do {Platform} {ComponentTitle}

A edição de células do {ProductName} em {Platform} {ComponentTitle} oferece uma ótima capacidade de manipulação do conteúdo de células individuais dentro do componente {Platform} {ComponentTitle} e vem com uma API poderosa para operações CRUD no React. É um recurso fundamental em aplicativos como planilhas, tabelas de dados e grades de dados, que permite aos usuários adicionar, editar ou atualizar dados em células específicas.
Por padrão, a Grid em {ProductName} é usada na edição de células. E, devido ao **template padrão de edição de células**, haverá editores diferentes conforme o tipo de dado da coluna, no topo do formulário.

Além disso, você pode definir templates personalizados para as ações de atualização de dados e substituir o comportamento padrão para confirmar ou descartar quaisquer alterações.

## Edição de células

### Edição pela UI

Você pode entrar no modo de edição de uma célula específica, quando uma célula editável está com foco, de uma das seguintes formas:
- com um duplo clique;
- com um clique simples — o clique simples entra no modo de edição somente se a célula selecionada anteriormente estava em modo de edição e a célula selecionada no momento for editável. Se a célula selecionada anteriormente não estava em modo de edição, o clique simples apenas seleciona a célula, sem entrar no modo de edição;
- ao pressionar a tecla <kbd>ENTER</kbd>;
- ao pressionar a tecla <kbd>F2</kbd>;

Você pode sair do modo de edição **sem confirmar** as alterações de uma das seguintes formas:
- ao pressionar a tecla <kbd>Escape</kbd>;
- ao realizar operações de **ordenação**, **filtragem**, **pesquisa** e **ocultação**;

Você pode sair do modo de edição e **confirmar** as alterações de uma das seguintes formas:
- ao pressionar a tecla <kbd>ENTER</kbd>;
- ao pressionar a tecla <kbd>F2</kbd>;
- ao pressionar a tecla <kbd>TAB</kbd>;
- com um clique simples em outra célula — quando você clica em outra célula no <ApiLink type="{ComponentName}" />, as suas alterações são enviadas.
- operações como paginação, redimensionamento, fixação ou movimentação saem do modo de edição e as alterações são enviadas.


<DocsAside type="info">
A célula permanece em modo de edição quando você rola na vertical ou na horizontal, ou clica fora do <ApiLink type="{ComponentName}" />. Isso vale tanto para a edição de célula quanto para a edição de linha.
</DocsAside>

### Edição estilo Excel do {ComponentTitle}


Usar a edição estilo Excel permite ao usuário navegar pelas células como faria no Excel, editando-as com grande rapidez.

Implementar essa funcionalidade personalizada pode ser feito usando os eventos do <ApiLink type="{ComponentName}" />. Primeiro, conectamos os eventos keydown da grade e, a partir daí, podemos implementar duas funcionalidades:

<PlatformBlock for="React">
```tsx
const gridRef = useRef<IgrGrid>();
useEffect(() => {
    gridRef.current.addEventListener("keydown", handleKeyDown);
    return () => {
        gridRef.current.removeEventListener("keydown", handleKeyDown);
    };
}, []);
<IgrGrid ref={gridRef} autoGenerate={false} data={nwindData} primaryKey="ProductID">
</IgrGrid>
```

<DocsAside type="info">
Estamos usando o evento keydown nativo do navegador, em vez do evento sintético onKeyDown do React. Quando uma célula entra no modo de edição e a tecla ENTER é pressionada para ir para a próxima linha, o recurso de edição da grade atualiza o valor da célula e fecha o modo de edição. Como resultado, o elemento de entrada usado para edição é removido do DOM. Devido às otimizações do sistema de eventos do React, o evento sintético onKeyDown não se propaga até a grade, porque o elemento não existe mais na árvore do React naquele momento. Por isso, é necessário usar o listener de evento nativo para garantir o comportamento esperado.
</DocsAside>

</PlatformBlock>

```typescript
public keydownHandler(event) {
  const key = event.keyCode;
  const grid = this.grid;
  const activeElem = grid.navigation.activeNode;

  if ((key >= 48 && key <= 57) ||
      (key >= 65 && key <= 90) ||
      (key >= 97 && key <= 122)) {
        // Number or Alphabet upper case or Alphabet lower case
        const columnName = grid.getColumnByVisibleIndex(activeElem.column).field;
        const cell = grid.getCellByColumn(activeElem.row, columnName);
        if (cell && !grid.crudService.cellInEditMode) {
            grid.crudService.enterEditMode(cell);
            cell.editValue = event.key;
        }
    }
}
```

```typescript
function handleKeyDown(event: KeyBoardEvent) {
    const code = event.code;
    const grid = event.currentTarget as IgrGrid;
    const activeElem = grid.selectedCells[0];

    if ((event.code >= "Digit0" && event.code <= "Digit9") || (event.code >= "KeyA" && event.code <= "KeyZ")
        || (event.code >= "Numpad0" && event.code <= "Numpad9" && event.code !== "Enter" && event.code !== "NumpadEnter")) {
        if (activeElem && !activeElem.editMode) {
            activeElem.editMode = true;
            activeElem.editValue = event.key;
        } else if (activeElem && activeElem.editMode) {
            event.preventDefault();
            activeElem.editValue = activeElem.editValue + event.key;
        }
    }
}
```

- As linhas que não são de dados são ignoradas ao navegar com <kbd>ENTER</kbd>/<kbd>SHIFT</kbd> + <kbd>ENTER</kbd>. Isso permite que os usuários percorram rapidamente os seus valores.

</ComponentBlock>

### Exemplo de estilização

<Sample src="/{ComponentSample}/cell-editing-styling" height={650} alt="{Platform} {ComponentTitle} Exemplo de estilização da edição de células" />

<PlatformBlock for="Angular">
O <ApiLink type="{ComponentName}" /> permite estilizar as suas células por meio da [{ProductName} Theme Library](../themes/styles.mdx). A propriedade <ApiLink type="function-grid-theme" label="theme" kind="sass" module="index.html" /> da grade expõe uma ampla gama de propriedades, que permitem ao usuário estilizar muitos aspectos diferentes da grade.

Nas etapas abaixo, vamos ver como estilizar a célula do grid em modo de edição e como restringir esses estilos a um escopo.

Para usar a [Ignite UI Theming Library](../themes/styles.mdx), primeiro precisamos importar o arquivo de tema `index` nos nossos estilos globais:


### Importando a biblioteca de estilos

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to {ProductName} version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Agora podemos usar todas as funções expostas pelo mecanismo de temas {ProductName}.

### Definindo uma paleta

Depois de importar corretamente o arquivo de índice, criamos uma paleta personalizada que podemos usar. Vamos definir duas cores que gostamos e usá-las para criar uma paleta com [igx-palette](../themes/palettes.mdx):

```scss
$white: #fff;
$blue: #4567bb;

$color-palette: palette($primary: $white, $secondary: $blue);
```

### Definindo temas

Agora podemos definir o tema usando a nossa paleta. As células são estilizadas pelo <ApiLink type="function-grid-theme" label="grid-theme" kind="sass" module="index.html" />; por isso, podemos usá-lo para gerar um tema para o nosso <ApiLink type="{ComponentName}" />:

```scss
$custom-grid-theme: grid-theme(
    $cell-editing-background: $blue,
    $cell-edited-value-color: $white,
    $cell-active-border-color: $white,
    $edit-mode-color: color($color-palette, "secondary", 200)
);
```

### Aplicando o tema

A forma mais fácil de aplicar o nosso tema é com uma instrução `sass` `@include` no arquivo de estilos globais:

```scss
@include grid($custom-grid-theme);
```

Desta forma, o tema será aplicado a **todas** as grades do nosso aplicativo. Se quisermos aplicar essa estilização personalizada apenas a um componente específico, precisamos limitar o escopo do tema.

### Tema limitado ao componente

Para que o tema personalizado afete apenas o nosso componente específico, podemos mover todos os estilos que acabamos de definir do arquivo de estilos globais para o arquivo de estilo do nosso componente personalizado (incluindo o [import](#importing-style-library) do arquivo `index`).

Desta forma, por causa do {Platform} [ViewEncapsulation](https://angular.io/api/core/Component#encapsulation), os nossos estilos serão aplicados apenas ao nosso componente personalizado.

 <DocsAside type="info">
 Se o componente estiver usando um ViewEncapsulation [Emulated](../themes/styles.mdx#view-encapsulation), é necessário atravessar esse encapsulamento usando `::ng-deep` para estilizar a grade.
 </DocsAside>

 <DocsAside type="info">
 Envolvemos a instrução em um seletor `:host` para impedir que os nossos estilos afetem elementos fora do nosso componente:
 </DocsAside>

```scss
:host {
    ::ng-deep {
            @include grid($custom-grid-theme);
        }
    }
}
```
