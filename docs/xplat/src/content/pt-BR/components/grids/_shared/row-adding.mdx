# Adição de linhas do {Platform} {ComponentTitle}

<ComponentBlock for="Grid, HierarchicalGrid">
O recurso de Adição de linhas do {ProductName} em {Platform} {ComponentTitle} permite que os usuários insiram e enviem novos registros de dados sem navegar para um formulário ou página separada. Com o <ApiLink type="{ComponentName}" />, os usuários podem manipular dados por meio da adição de linhas inline e de uma API poderosa para operações de CRUD.
Adicione um componente <ApiLink type="ActionStrip" /> com as ações de edição habilitadas no template da grade. Depois, passe o mouse sobre uma linha e use o botão fornecido. Por fim, pressione <kbd>ALT</kbd> + <kbd>+</kbd> para exibir a interface de adição de linhas.

</ComponentBlock>

<ComponentBlock for="TreeGrid">
O <ApiLink type="{ComponentName}" /> oferece uma forma prática de realizar manipulações de dados por meio da adição de linhas inline e de uma API poderosa para operações de CRUD de {Platform}. O `BaseTransactionService` interno é fornecido automaticamente para <ApiLink type="{ComponentName}" />. Ele mantém as alterações pendentes de célula até que o estado da linha seja enviado ou cancelado.

## Iniciando a adição de linhas programaticamente

<ApiLink type="{ComponentName}" /> permite abrir a interface de adição de linha programaticamente, usando dois métodos públicos diferentes. Um aceita um ID de linha para especificar a linha abaixo da qual a interface deve aparecer, e outro funciona por índice. Você pode usar esses métodos para abrir a interface em qualquer ponto da visualização de dados atual. Mudar a página ou especificar uma linha que, por exemplo, esteja filtrada não é suportado.

<ComponentBlock for="Grid, HierarchicalGrid">
Usar <ApiLink type="{ComponentName}" member="beginAddRowById" /> exige que você especifique a linha que será usada como contexto da operação pela sua `RowID` (PK). O método então funciona como se o usuário final tivesse clicado no botão de adicionar linha do action strip para a linha especificada, exibindo a interface abaixo dela. Você também pode fazer com que a interface apareça como a primeira linha da grade passando `null` como primeiro parâmetro.

<PlatformBlock for="WebComponents">
```typescript
this.grid.beginAddRowById('ALFKI');  // Spawns the add row UI under the row with PK 'ALFKI'
this.grid.beginAddRowById(null);     // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="React">
```typescript
gridRef.current.beginAddRowById('ALFKI');  // Spawns the add row UI under the row with PK 'ALFKI'
gridRef.current.beginAddRowById(null);     // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="Blazor">
```razor
@code {
    await this.grid.BeginAddRowByIdAsync('ALFKI', false);  // Spawns the add row UI under the row with PK 'ALFKI'
    await this.grid.BeginAddRowByIdAsync(null, false);     // Spawns the add row UI as the first record
}
```
</PlatformBlock>

O método <ApiLink type="{ComponentName}" member="beginAddRowByIndex" /> funciona de forma semelhante, mas exige que você especifique o índice em que a interface deve aparecer. Os valores permitidos vão de 0 até o tamanho da visualização de dados menos 1.

<PlatformBlock for="WebComponents">
```typescript
this.grid.beginAddRowByIndex(10);   // Spawns the add row UI at index 10
this.grid.beginAddRowByIndex(0);    // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="React">
```typescript
gridRef.current.beginAddRowByIndex(10);   // Spawns the add row UI at index 10
gridRef.current.beginAddRowByIndex(0);    // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="Blazor">
```razor
@code {
    await this.grid.BeginAddRowByIndexAsync(10);   // Spawns the add row UI at index 10
    await this.grid.BeginAddRowByIndexAsync(0);    // Spawns the add row UI as the first record
}
```
</PlatformBlock>

</ComponentBlock>

<ComponentBlock for="TreeGrid">
Usar <ApiLink type="{ComponentName}" member="beginAddRowById" /> exige que você especifique a linha que será usada como contexto da operação pela sua `RowID` (PK). O método então funciona como se o usuário final tivesse clicado no botão de adicionar linha do action strip para a linha especificada, exibindo a interface abaixo dela. O segundo parâmetro controla se a linha é adicionada como filha da linha de contexto ou como irmã. Você também pode fazer com que a interface apareça como a primeira linha da grade passando `null` como primeiro parâmetro.

<PlatformBlock for="WebComponents">
```typescript
this.treeGrid.beginAddRowById('ALFKI', true);   // Spawns the add row UI to add a child for the row with PK 'ALFKI'
this.treeGrid.beginAddRowById(null);            // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="Blazor">
```razor
@code {
    await this.treeGrid.BeginAddRowByIdAsync('ALFKI', true);  // Spawns the add row UI to add a child for the row with PK 'ALFKI'
    await this.treeGrid.BeginAddRowByIdAsync(null, false);     // Spawns the add row UI as the first record
}
```
</PlatformBlock>

O método <ApiLink type="{ComponentName}" member="beginAddRowByIndex" /> funciona de forma semelhante, mas a linha usada como contexto é especificada pelo índice.

<PlatformBlock for="WebComponents">
```typescript
this.treeGrid.beginAddRowByIndex(10, true);   // Spawns the add row UI to add a child for the row at index 10
this.treeGrid.beginAddRowByIndex(null);       // Spawns the add row UI as the first record
```
</PlatformBlock>

<PlatformBlock for="Blazor">

## Posicionamento

- A posição padrão da interface de adição de linha é abaixo da linha para a qual o usuário final clicou no botão de adicionar linha.

- O <ApiLink type="{ComponentName}" /> rola automaticamente para exibir totalmente a interface de adição de linha.

- O overlay da interface de adição de linha mantém a sua posição durante a rolagem.

## Comportamento

A interface de adição de linha tem o mesmo comportamento da edição de linha, pois foi projetada para oferecer uma experiência de edição consistente aos usuários finais. Consulte o tópico [{ComponentTitle} Row Editing](row-editing.mdx) para mais informações.

Depois que uma nova linha é adicionada pela interface de adição de linha, a sua posição e/ou visibilidade é determinada pelo estado de ordenação, filtragem e agrupamento do <ApiLink type="{ComponentName}" />. Em um <ApiLink type="{ComponentName}" /> que não tenha nenhum desses estados aplicados, ela aparece como o último registro. Um snackbar é exibido brevemente, contendo um botão que o usuário final pode usar para rolar o <ApiLink type="{ComponentName}" /> até a posição da linha, caso ela não esteja visível.

## Navegação pelo teclado

- <kbd>ALT</kbd> + <kbd>+</kbd> - Entra no modo de edição para adicionar uma linha

<ComponentBlock for="TreeGrid">
- <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>+</kbd> - Entra no modo de edição para adicionar um filho

</ComponentBlock>
- <kbd>ESC</kbd> sai do modo de adição de linha sem enviar nenhuma alteração

- <kbd>TAB</kbd> move o foco de uma célula editável da linha para a próxima e da célula editável mais à direita para os botões CANCEL e DONE. A navegação a partir do botão DONE vai para a célula editável mais à esquerda da linha que está sendo editada.

## Integração de recursos

- Qualquer operação de adição de linha será interrompida se a visualização de dados do <ApiLink type="{ComponentName}" /> for modificada. Todas as alterações feitas pelo usuário final são enviadas. Operações que alteram a visualização de dados incluem, entre outras, ordenação, agrupamento, filtragem, paginação etc.

- Os resumos são atualizados depois que a operação de adição de linha termina. O mesmo vale para os outros recursos que dependem da visualização de dados, como ordenação, filtragem etc.

- Ao exibir a interface para o <ApiLink type="{ComponentName}" />, qualquer layout filho atualmente expandido para uma linha em que o usuário final clica no botão de adicionar linha é recolhido.

## Cenários remotos

Na maioria dos cenários de dados remotos, a atribuição da chave primária acontece na requisição de criação ao servidor. Nesse caso, os registros adicionados no cliente não terão o valor final da chave primária até serem salvos no banco de dados do servidor. Nesse caso, a forma recomendada de tratar essa atualização no <ApiLink type="{ComponentName}" /> é a seguinte:

- Se o <ApiLink type="{ComponentName}" /> não usar transações.

    Depois que a requisição de criação for concluída com sucesso e retornar os dados do registro adicionado, você pode substituir o id desse registro na instância local do registro de dados.

- Se o <ApiLink type="{ComponentName}" /> usar transações.

    Depois que a requisição de criação ou de atualização em lote for concluída com sucesso e retornar as instâncias de registro adicionadas (com seus ids gerados pelo banco de dados), as transações ADD relacionadas devem ser removidas do log de transações usando o método de API `Clear`. Isso é necessário porque a transação local terá um campo id gerado, que pode ser diferente do criado no banco de dados; por isso, elas devem ser removidas. Depois, você pode adicionar à instância local de dados os registros passados na resposta.

Isso garantirá que os ids gerados remotamente sejam sempre refletidos nos dados locais, e que as operações subsequentes de atualização/exclusão tenham como alvo os ids de registro corretos.
</PlatformBlock>
