# Reordenação e movimentação de colunas do {ComponentTitle}

O recurso de Movimentação de colunas do {Platform} {ComponentTitle} em {ProductName} permite reordenar colunas de forma rápida e fácil. Isso pode ser feito pela API de Movimentação de colunas ou arrastando e soltando os cabeçalhos para outra posição com o mouse ou por gestos de toque. Na {Platform} {ComponentTitle}, você pode habilitar a Movimentação de colunas para colunas fixadas e não fixadas, e também para [Cabeçalhos de várias colunas](multi-column-headers.mdx).

<DocsAside type="info">
A reordenação entre colunas e grupos de colunas só é permitida quando estão no mesmo nível da hierarquia e ambos estão no mesmo grupo. A movimentação é permitida entre colunas/grupos de colunas, se forem colunas de nível superior.
</DocsAside>

<DocsAside type="info">
Se um cabeçalho de coluna tiver template e a Movimentação de colunas estiver habilitada, ou se a coluna correspondente for agrupável, os elementos com template precisam ter o atributo **draggable** definido como **false**!
</DocsAside>

<PlatformBlock for="Angular">
Isso permite anexar manipuladores a qualquer evento emitido pelo elemento; caso contrário, o evento é consumido pela diretiva `igxDrag`.
</PlatformBlock>


<DocsAside type="info">
Se a área fixada exceder a sua largura máxima permitida (80% da largura total do <ApiLink type="{ComponentName}" />), uma dica visual informará ao usuário final que a operação de soltar é proibida e que a fixação não é possível. Isso significa que você não poderá soltar uma coluna na área fixada.
</DocsAside>

## API

Além da funcionalidade de arrastar e soltar, o recurso de Movimentação de colunas também oferece métodos de API para mover uma coluna ou reordenar colunas programaticamente:

<ApiLink type="GridBaseDirective" member="moveColumn" /> - Move uma coluna antes ou depois de outra coluna (um alvo). O primeiro parâmetro é a coluna a ser movida, e o segundo é a coluna alvo. Também aceita um terceiro parâmetro opcional `Position` (representando um valor <ApiLink type="DropPosition" />), que determina se a coluna deve ser colocada antes ou depois da coluna alvo.


<PlatformBlock for="React, Angular, WebComponents">
```typescript
// Move the ID column after the Name column
const idColumn = grid.getColumnByName("ID");
const nameColumn = grid.getColumnByName("Name");

grid.moveColumn(idColumn, nameColumn, DropPosition.AfterDropTarget);

```
</PlatformBlock>

<PlatformBlock for="Blazor">
```csharp
    public async void HandleClick()
    {
        IgbColumn Col1 = await this.grid.GetColumnByVisibleIndexAsync(0);
        IgbColumn Col2 = await this.grid.GetColumnByVisibleIndexAsync(1);
        this.Grid.MoveColumn(Col1,Col2, DropPosition.AfterDropTarget);
    }
```

</PlatformBlock>


<ApiLink type="Column" member="move" label="Move" /> - Move uma coluna para um índice visível especificado. Se o parâmetro de índice passado for inválido (for negativo ou exceder o número de colunas), ou se a coluna não puder ser movida para esse índice (se estiver dentro de outro grupo), nenhuma operação será realizada.

<PlatformBlock for="WebComponents">
```typescript
// Move the ID column at 3rd position.
const idColumn = grid.getColumnByName("ID");
idColumn.move(3);
```
</PlatformBlock>

<PlatformBlock for="Blazor">
```csharp
    public async void HandleClick()
    {
        IgbColumn Col1 = await this.grid.GetColumnByVisibleIndexAsync(0);
        this.Col1.Move(3);
    }
```
</PlatformBlock>

Observe que, ao usar o recurso de movimentação de colunas, o <PlatformBlock for="Angular,WebComponents"><ApiLink type="GridComponentEventMap" member="columnMovingEnd" /></PlatformBlock><PlatformBlock for="React"><ApiLink type="Grid" member="onColumnMovingEnd" /></PlatformBlock><PlatformBlock for="Blazor"><ApiLink type="Grid" member="columnMovingEnd" /></PlatformBlock> evento será emitido se a operação for bem-sucedida. Observe também que, em comparação com a funcionalidade de arrastar e soltar, usar o recurso de movimentação de colunas não exige definir a propriedade <ApiLink type="{ComponentName}" member="moving" /> como true.

## Estilização

Para começar a estilizar os cabeçalhos de movimentação de colunas do <ApiLink type="{ComponentName}" />, precisamos importar o arquivo `index`, onde ficam todas as funções de tema e os mixins dos componentes:

```scss
@use "igniteui-{Platform}/theming" as *;

// IMPORTANT: Prior to {ProductName} version 13 use:
// @import '~igniteui-{Platform}/lib/core/styles/themes/index';
```

Usando a abordagem mais simples, criamos um novo tema que estende o <ApiLink type="function-grid-theme" label="grid-theme" kind="sass" module="index.html" /> e aceita os parâmetros `$ghost-header-background`, `$ghost-header-text-color` e `$ghost-header-icon-color`.

```scss
// Define dark theme for the column moving
$dark-grid-column-moving-theme: grid-theme(
    $ghost-header-text-color: #F4D45C,
    $ghost-header-background: #575757,
    $ghost-header-icon-color: #f4bb5c
);
```

A última etapa é **incluir** os mixins dos componentes com o seu tema correspondente:

```scss
@include grid($dark-grid-column-moving-theme);
```

<DocsAside type="info">
Dependendo da estratégia de [**View Encapsulation**](/components/themes/sass/component-themes.html#view-encapsulation) do componente, pode ser necessário `penetrate` esse encapsulamento usando `::ng-deep`
</DocsAside>

```scss
:host {
    ::ng-deep {
        @include grid($dark-grid-column-moving-theme);
    }
}
```

### Definindo uma paleta de cores

Em vez de fixar os valores de cor como acabamos de fazer, podemos obter mais flexibilidade em relação às cores usando as funções <ApiLink type="function-igx-palette" label="igx-palette" kind="sass" module="index.html" /> e <ApiLink type="function-igx-color" label="igx-color" kind="sass" module="index.html" />.


**igx-palette** gera uma paleta de cores com base nas cores primária e secundária que são passadas:

```scss
$yellow-color: #F4D45C;
$black-color: #575757;

$dark-palette: palette($primary: $yellow-color, $secondary: $black-color);
```

E então, com <ApiLink type="function-igx-color" label="**igx-color**" kind="sass" module="index.html" />, podemos obter facilmente uma cor da paleta.

```scss
$dark-grid-column-moving-theme: grid-theme(
    $palette: $dark-palette,
    $ghost-header-text-color: color($dark-palette, "primary", 400),
    $ghost-header-background: color($dark-palette, "secondary", 200),
    $ghost-header-icon-color: color($dark-palette, "primary", 500)
);
```


<DocsAside type="info">
As funções de cor e de paleta são poderosas para gerar e obter cores. Consulte o tópico [Paletas](/components/themes/palettes.html) para orientações detalhadas sobre como usá-las.
</DocsAside>

### Usando schemas

Indo além do mecanismo de temas, você pode criar uma estrutura robusta e flexível que se beneficia dos [schemas](/components/themes/sass/schemas.html). Um **schema** é uma receita de tema.

Estenda um dos dois schemas predefinidos fornecidos para cada componente, neste caso - <ApiLink type="variable-_light-grid" label="light-grid" kind="sass" module="index.html" />.

```scss
// Extending the dark grid schema
$dark-grid-column-moving-schema: extend($_light-grid,
        (
            ghost-header-text-color:(
               color: ("primary", 400)
            ),
            ghost-header-background:(
               color: ("secondary", 200)
            ),
            ghost-header-icon-color:(
               color: ("primary", 500)
            )
        )
);
```

Para aplicar o nosso schema personalizado, precisamos **estender** um dos globais (<ApiLink type="variable-light-schema" label="light" kind="sass" module="index.html" /> ou <ApiLink type="variable-dark-schema" label="dark" kind="sass" module="index.html" />), o que basicamente indica os componentes com um schema personalizado, e depois adicioná-lo ao tema do respectivo componente:

```scss
// Extending the global dark-schema
$custom-light-schema: extend($light-schema,(
    igx-grid: $dark-grid-column-moving-schema,
));

// Defining dark-grid-theme with the global dark schema
$dark-grid-column-moving-theme: grid-theme(
  $palette: $dark-palette,
  $schema: $custom-light-schema
);
```

Não se esqueça de incluir o tema da mesma forma como foi demonstrado acima.
