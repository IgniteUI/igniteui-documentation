# Visão geral de cabeçalhos de várias colunas do {Platform} {ComponentTitle}

O recurso de Cabeçalhos de várias colunas do {ProductName} em {Platform} {ComponentTitle} permite agrupar colunas colocando-as sob um cabeçalho múltiplo comum. Cada grupo de cabeçalhos de várias colunas na <ApiLink type="{ComponentName}" /> pode representar combinações de outros grupos ou colunas. Esse recurso é especialmente útil ao lidar com grandes conjuntos de dados, nos quais rolar horizontalmente pode ser trabalhoso.

Cada <ApiLink type="ColumnGroup" /> oferece suporte a [mover](column-moving.mdx), [fixar](column-pinning.mdx) e [ocultar](column-hiding.mdx).
<DocsAside type="info">
Quando há um conjunto de colunas e grupos de colunas, a fixação funciona apenas para os pais de colunas de nível superior. Mais especificamente, a fixação por grupos de colunas ou colunas aninhados não é permitida. <br />
Mover entre colunas e grupos de colunas é permitido somente quando estão no mesmo nível da hierarquia e ambos estão no mesmo `group`. <br />
Quando `columns/column-groups` não estão envolvidas pelo `group` atual, ou seja, são **de nível superior** `columns`, o movimento é permitido entre todas as colunas visíveis.
</DocsAside>

## Template de cabeçalho de várias colunas

<PlatformBlock for="Angular">
Cada um dos grupos de colunas do grid pode ter template definido separadamente. O grupo de colunas espera uma tag `ng-template` decorada com a diretiva `igxHeader`.
O `ng-template` recebe o objeto do grupo de colunas como contexto.

```html
<igx-column-group header="General Information">
    <ng-template igxHeader let-columnGroup>
        {{ columnGroup.header | uppercase }}
    </ng-template>
</igx-column-group>
```

Se você quiser reutilizar um único template para vários grupos de colunas, pode definir a propriedade <ApiLink type="ColumnGroup" member="headerTemplate" label="HeaderTemplate" /> do grupo de colunas assim:

```html
<ng-template #columnGroupHeaderTemplate let-columnGroup>
    {{ columnGroup.header | uppercase }}
</ng-template>

<igx-column-group header="General Information" [headerTemplate]="columnGroupHeaderTemplate">
</igx-column-group>
<igx-column-group header="Address Information" [headerTemplate]="columnGroupHeaderTemplate">
</igx-column-group>
```

</PlatformBlock>

## Estilização

Para começar a estilizar o comportamento de ordenação, precisamos importar o arquivo `index`, onde ficam todas as funções de tema e os mixins de componente:

```scss
@import '~igniteui-angular/lib/core/styles/themes/index';
```

Seguindo a abordagem mais simples, criamos um novo tema que estende o <ApiLink type="function-igx-grid-theme" label="igx-grid-theme" kind="sass" module="index.html" /> e aceita os parâmetros `$header-background`, `$header-text-color`, `$header-border-width`, `$header-border-style` e `$header-border-color`.

```scss
$custom-theme: igx-grid-theme(
    $header-background: #e0f3ff,
    $header-text-color: #e41c77,
    $header-border-width: 1px,
    $header-border-style: solid,
    $header-border-color: rgba(0, 0, 0, 0.08)
);
```

O último passo é **incluir** os mixins de componente:

```scss
@include igx-grid($custom-theme);
```

<DocsAside type="info">
Se o componente estiver usando um ViewEncapsulation [Emulated](../themes/styles.mdx#view-encapsulation), é necessário `penetrate` esse encapsulamento usando `::ng-deep`:
</DocsAside>

 ```scss
:host {
    ::ng-deep {
        @include igx-grid($custom-theme);
    }
}
```

### Definindo uma paleta de cores

Em vez de fixar os valores de cor diretamente no código, como fizemos acima, podemos obter mais flexibilidade com cores usando as funções `igx-palette` e `igx-color`.

`igx-palette` gera uma paleta de cores com base nas cores primária e secundária que são passadas:

```scss
$light-blue-color: #e0f3ff;
$deep-pink-color: #e41c77;

$custom-palette: igx-palette($primary: $light-blue-color, $deep-pink-color);
```

E então, com `igx-color`, podemos obter facilmente uma cor da paleta.

```scss
$custom-theme: igx-grid-theme(
    $header-background: igx-color($custom-palette, "primary", 500),
    $header-text-color: igx-color($custom-palette, "secondary", 500),
    $header-border-width: 1px,
    $header-border-style: solid,
    $header-border-color: igx-color($custom-palette, "grays", 200)
);
```

<DocsAside type="info">
As funções `igx-color` e `igx-palette` são poderosas para gerar e obter cores. Consulte o tópico [Paletas](../themes/palette.mdx) para orientações detalhadas sobre como usá-las.
</DocsAside>

### Usando schemas

Avançando com o mecanismo de temas, você pode construir uma estrutura robusta e flexível que se beneficia de [schemas](../themes/schemas.mdx). Um schema é uma receita de tema.

Estenda um dos dois schemas predefinidos fornecidos para cada componente; neste caso, `_light-grid`:

```scss
// Extending the light grid schema
$custom-grid-schema: extend($_light-grid,
    (
        header-background: (igx-color:('primary', 500)),
        header-text-color: (igx-color:('secondary', 500)),
        header-border-width: 1px,
        header-border-style: solid,
        header-border-color: (igx-color:('grays', 200))
    )
);
```

Para aplicar nosso schema personalizado, precisamos **estender** um dos globais `light` ou `dark`, o que basicamente aponta os componentes com um schema personalizado; depois disso, adicione-o aos respectivos temas dos componentes:

```scss
Extending the global light-schema
$my-custom-schema: extend($light-schema,
    (
        igx-grid: $custom-grid-schema
    )
);

// Defining our custom theme with the custom schema
$custom-theme: igx-grid-theme(
  $palette: $custom-palette,
  $schema: $my-custom-schema
);
```

Não se esqueça de incluir os temas da mesma forma como foi demonstrado acima.
