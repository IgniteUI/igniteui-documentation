# Filtragem do {Platform} {ComponentTitle}

A filtragem {ProductName} em {Platform} {ComponentTitle} é um recurso que permite exibir ou ocultar dados seletivamente, com base em critérios ou condições específicos. Há um contêiner de dados vinculado por meio do qual o componente <ApiLink type="{ComponentName}" /> oferece uma API de filtragem completa e todos os recursos de filtragem. Os tipos de filtragem disponíveis aqui são três:

- Filtragem rápida
- [Filtragem no estilo Excel](excel-style-filtering.mdx)
- [Filtragem avançada](advanced-filtering.mdx)

## Configuração

Para especificar se a filtragem está ativada e qual modo de filtragem deve ser usado, <ApiLink type="{ComponentName}" /> expõe as seguintes propriedades: <ApiLink type="{ComponentName}" member="allowFiltering" />, <ApiLink type="{ComponentName}" member="allowAdvancedFiltering" />, <ApiLink type="{ComponentName}" member="filterMode" /> e <ApiLink type="Column" member="filterable" />.

A propriedade <ApiLink type="{ComponentName}" member="allowFiltering" /> permite especificar as seguintes opções:
- **false** - a filtragem da grade correspondente será desativada. Este é o valor padrão.
- **true** - a filtragem da grade correspondente será ativada.

A propriedade <ApiLink type="{ComponentName}" member="allowAdvancedFiltering" /> permite especificar as seguintes opções:
- **false** - a filtragem avançada da grade correspondente será desativada. Este é o valor padrão.
- **true** - a filtragem avançada da grade correspondente será ativada.

A propriedade <ApiLink type="{ComponentName}" member="filterMode" /> permite especificar as seguintes opções:
- **QuickFilter** - uma interface de filtragem simplificada. Este é o valor padrão.
- **ExcelStyleFilter** - uma interface de filtragem semelhante à do Excel.

A propriedade <ApiLink type="Column" member="filterable" /> permite especificar as seguintes opções:
- **true** - a filtragem da coluna correspondente será ativada. Este é o valor padrão.
- **false** - a filtragem da coluna correspondente será desativada.

## Interação

Para abrir a linha de filtro de uma coluna específica, clique no chip 'Filter' abaixo do cabeçalho dela. Para adicionar condições, escolha o operando de filtro no dropdown à esquerda do input e informe o valor. Para colunas **number** e **date**, 'Equals' é selecionado por padrão; para **string**, 'Contains'; e para **boolean**, 'All'. Pressionar 'Enter' confirma a condição, e você pode adicionar outra. Entre os chips de condição há um dropdown que determina o operador lógico entre elas; 'AND' é selecionado por padrão. Para remover uma condição, clique no botão 'X' do chip; para editá-la, selecione o chip, e o input será preenchido com os dados dele. Enquanto a linha de filtro estiver aberta, você pode clicar no cabeçalho de qualquer coluna filtrável para selecioná-la e adicionar condições de filtro a ela.

Enquanto algumas condições de filtro tiverem sido aplicadas a uma coluna e a linha de filtro estiver fechada, você pode remover as condições clicando no botão de fechar do chip, ou abrir a linha de filtro selecionando qualquer um dos chips. Quando não há espaço suficiente para mostrar todas as condições, aparece um ícone de filtro com um badge que indica quantas condições adicionais existem. Ele também pode ser clicado para abrir a linha de filtro.

## Uso

Há uma estratégia de filtragem padrão disponível desde o início, assim como todas as condições de filtragem padrão, que o desenvolvedor pode substituir por sua própria implementação. Além disso, oferecemos uma forma fácil de plugar suas próprias condições de filtragem personalizadas. O <ApiLink type="{ComponentName}" /> atualmente oferece não apenas uma interface de filtragem simplificada, mas também opções de filtragem mais complexas. Dependendo do <ApiLink type="Column" member="dataType" /> definido para a coluna, o conjunto correto de **operações de filtragem** é carregado no dropdown da interface de filtro. Além disso, você pode definir <ApiLink type="FilteringExpression" member="ignoreCase" label="IgnoreCase" /> e as propriedades iniciais <ApiLink type="BooleanFilteringOperand" member="condition" label="Condition" />.

O recurso de filtragem é ativado para o componente <ApiLink type="{ComponentName}" /> ao definir o input <ApiLink type="{ComponentName}" member="allowFiltering" /> como **true**. O padrão de <ApiLink type="{ComponentName}" member="filterMode" /> é `QuickFilter`, e ele **não pode** ser alterado em tempo de execução. Para desativar esse recurso em uma coluna específica, defina o input <ApiLink type="Column" member="filterable" /> como **false**.

Você pode filtrar qualquer coluna ou combinação de colunas pela API <ApiLink type="{ComponentName}" />. O <ApiLink type="{ComponentName}" /> expõe vários métodos para essa tarefa — <ApiLink type="Filter" />, `FilterGlobal` e `ClearFilter`.

- <ApiLink type="Filter" /> - filtra uma única coluna ou uma combinação de colunas.

São expostas cinco classes de operandos de filtragem:

- <ApiLink type="FilteringOperand" />: este é um operando de filtragem base, que pode ser herdado ao definir condições de filtragem personalizadas.
- <ApiLink type="BooleanFilteringOperand" /> define todas as condições de filtragem padrão para o tipo **boolean**.
- <ApiLink type="NumberFilteringOperand" /> define todas as condições de filtragem padrão para o tipo **numeric**.
- <ApiLink type="StringFilteringOperand" /> define todas as condições de filtragem padrão para o tipo **string**.
- <ApiLink type="DateFilteringOperand" /> define todas as condições de filtragem padrão para o tipo **date**.

```typescript
// Single column filtering

// Filter the `ProductName` column for values which `contains` the `myproduct` substring, ignoring case
this.grid.filter('ProductName', 'myproduct', IgcStringFilteringOperand.instance().condition('contains'), true);
```

Os únicos parâmetros obrigatórios são a chave do campo da coluna e o termo de filtragem. Tanto a condição quanto a diferenciação de maiúsculas e minúsculas serão inferidas das propriedades da coluna, caso não sejam informadas. No caso de várias filtragens, o método aceita um array de expressões de filtro.

## Operandos de filtragem personalizados

Você pode personalizar o menu de filtragem adicionando, removendo ou modificando os operandos de filtragem. Por padrão, o menu de filtragem contém determinados operandos com base no tipo de dado da coluna (<ApiLink type="BooleanFilteringOperand" />, <ApiLink type="DateFilteringOperand" />, <ApiLink type="NumberFilteringOperand" /> e <ApiLink type="StringFilteringOperand" />). Você pode estender essas classes ou a sua classe base <ApiLink type="FilteringOperand" /> para alterar o comportamento dos itens do menu de filtragem.

No exemplo abaixo, inspecione os menus de filtro das colunas “Product Name” e “Discontinued”. Para o filtro da coluna “Discontinued”, limitamos os operandos a All, True e False. Para o filtro da coluna “Product Name”, modificamos a lógica dos operandos Contains e Does Not Contain para realizar uma pesquisa que diferencia maiúsculas de minúsculas, e também adicionamos os operandos Empty e Not Empty.

Para isso, estenda o <ApiLink type="StringFilteringOperand" /> e o <ApiLink type="BooleanFilteringOperand" />, modifique as operações e a lógica delas, e defina a entrada `filters` da coluna com os novos operandos.

<PlatformBlock for="Angular">
```typescript
// grid-custom-filtering.component.ts

export class GridCustomFilteringComponent {
    public caseSensitiveFilteringOperand = CaseSensitiveFilteringOperand.instance();
    public booleanFilteringOperand = BooleanFilteringOperand.instance();
}

export class CaseSensitiveFilteringOperand extends IgxStringFilteringOperand {
    private constructor() {
        super();
        const customOperations = [
            {
                iconName: 'contains',
                isUnary: false,
                logic: (target: string, searchVal: string, ignoreCase?: boolean) => {
                    ignoreCase = false;
                    const search = IgxStringFilteringOperand.applyIgnoreCase(searchVal, ignoreCase);
                    target = IgxStringFilteringOperand.applyIgnoreCase(target, ignoreCase);
                    return target.indexOf(search) !== -1;
                },
                name: 'Contains (case sensitive)'
            },
            {
                iconName: 'does_not_contain',
                isUnary: false,
                logic: (target: string, searchVal: string, ignoreCase?: boolean) => {
                    ignoreCase = false;
                    const search = IgxStringFilteringOperand.applyIgnoreCase(searchVal, ignoreCase);
                    target = IgxStringFilteringOperand.applyIgnoreCase(target, ignoreCase);
                    return target.indexOf(search) === -1;
                },
                name: 'Does Not Contain (case sensitive)'
            }
        ];

        const emptyOperators = [
            // 'Empty'
            this.operations[6],
            // 'Not Empty'
            this.operations[7]
        ];

        this.operations = customOperations.concat(emptyOperators);
    }
}

export class BooleanFilteringOperand extends IgxBooleanFilteringOperand {
    private constructor() {
        super();
        this.operations = [
            // 'All'
            this.operations[0],
            // 'TRUE'
            this.operations[1],
            // 'FALSE'
            this.operations[2]
        ];
    }
}
```

```typescript
            // 'Not Empty'
            this.operations[7]
        ];

        this.operations = customOperations.concat(emptyOperators);
    }
}

export class BooleanFilteringOperand extends IgcBooleanFilteringOperand {
    private constructor() {
        super();
        this.operations = [
            // 'All'
            this.operations[0],
            // 'TRUE'
            this.operations[1],
            // 'FALSE'
            this.operations[2]
        ];
    }
}
```

## Estilização

Para começar a estilizar a linha de filtro, precisamos importar o arquivo `index`, onde ficam todas as funções de tema e os mixins de componente:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Seguindo a abordagem mais simples, criamos um novo tema que estende o `grid-theme` e aceita os parâmetros `$filtering-row-text-color`, `$filtering-row-background`, `$filtering-header-text-color` e `$filtering-header-background`.

```scss
$custom-grid: grid-theme(
    $filtering-row-text-color: #292826,
    $filtering-row-background: #FFCD0F,
    $filtering-header-text-color: #292826,
    $filtering-header-background: #FFCD0F
);
```

Como visto, `grid-theme` controla apenas as cores da linha de filtro e do respectivo cabeçalho de coluna que está sendo filtrada. Obviamente, há muito mais componentes dentro da linha de filtro, como input group, chips, botões e outros. Para estilizá-los, precisamos criar um tema separado para cada um; então vamos criar um novo tema de input group e um novo tema de botão:

```scss
$dark-input-group: input-group-theme(
    $box-background: #FFCD0F,
    $idle-text-color: #292826,
    $focused-text-color: #292826,
    $filled-text-color: #292826
);

$dark-button: flat-button-theme(
    $background: #FFCD0F,
    $foreground: #292826,
    $hover-background: #292826,
    $hover-foreground: #FFCD0F
);
```

Neste exemplo, alteramos apenas alguns parâmetros do input group e do botão, mas o `input-group-theme` e o `flat-button-theme` oferecem muito mais parâmetros para controlar a estilização de cada um.

O último passo é **incluir** os mixins de componente, cada um com seu respectivo tema. Também definiremos a propriedade color para o placeholder do input.

```scss
@include grid($custom-grid);
.igx-grid__filtering-row {
    @include button($dark-button);
    @include input-group($dark-input-group);

    .igx-input-group__input::placeholder {
        color: #FFCD0F;
    }
}
```

<DocsAside type="info">
Restringimos os mixins **igx-button** e **igx-input-group** a `.igx-grid__filtering-row`, para que apenas os botões da linha de filtro e o input group dela sejam estilizados. Caso contrário, outros botões e input groups da grade também seriam afetados.
</DocsAside>

 <DocsAside type="info">
 Se o componente usar um ViewEncapsulation `Emulated`, é necessário `penetrate` essa encapsulação usando `::ng-deep`:
 </DocsAside>

```scss
:host {
     ::ng-deep {
        @include grid($custom-grid);
        .igx-grid__filtering-row {
            @include button($dark-button);
            @include input-group($dark-input-group);

            .igx-input-group__input::placeholder {
                color: #FFCD0F;
            }
        }
    }
}
```

### Definindo uma paleta de cores

Em vez de fixar os valores de cor como acabamos de fazer, podemos obter mais flexibilidade em relação às cores usando as funções `igx-palette` e `igx-color`.

`igx-palette` gera uma paleta de cores com base nas cores primária e secundária que são passadas:

```scss
$yellow-color: #FFCD0F;
$black-color: #292826;

$dark-palette: palette($primary: $black-color, $secondary: $yellow-color);
```

E então, com `igx-color`, podemos obter facilmente uma cor da paleta.

```scss
$custom-grid: grid-theme(
    $filtering-row-text-color: color($dark-palette, "primary", 400),
    $filtering-row-background: color($dark-palette, "secondary", 400),
    $filtering-header-text-color: color($dark-palette, "primary", 400),
    $filtering-header-background: color($dark-palette, "secondary", 400)
);

$dark-input-group: input-group-theme(
    $box-background: color($dark-palette, "secondary", 400),
    $idle-text-color: color($dark-palette, "primary", 400),
    $focused-text-color: color($dark-palette, "primary", 400),
    $filled-text-color: color($dark-palette, "primary", 400)
);

$dark-button: flat-button-theme(
    $background: color($dark-palette, "secondary", 400),
    $foreground: color($dark-palette, "primary", 400),
    $hover-background: color($dark-palette, "primary", 400),
    $hover-foreground: color($dark-palette, "secondary", 400)
);
```

<DocsAside type="info">
As funções `igx-color` e `igx-palette` são poderosas para gerar e obter cores. Consulte o tópico [Paletas](../themes/sass/palettes.mdx) para orientações detalhadas sobre como usá-las.
</DocsAside>

### Usando schemas

Avançando com o mecanismo de temas, você pode construir uma estrutura robusta e flexível que se beneficia de [Schemas](../themes/sass/schemas.mdx). Um **schema** é uma receita de tema.

Estenda um dos dois schemas predefinidos fornecidos para cada componente, neste caso os schemas `light-grid`, `light-input-group` e `light-button`:

```scss
// Extending the light grid schema
$custom-grid-schema: extend($_light-grid,
    (
        filtering-row-text-color:(
           color: ("primary", 400)
        ),
        filtering-row-background:(
           color: ("secondary", 400)
        ),
        filtering-header-text-color:(
           color: ("primary", 400)
        ),
        filtering-header-background:(
           color: ("secondary", 400)
        )
    )
);

// Extending the light input group schema
$custom-input-group-schema: extend($_light-input-group,
    (
        box-background:(
           color: ("secondary", 400)
        ),
        idle-text-color:(
           color: ("primary", 400)
        ),
        focused-text-color:(
           color: ("primary", 400)
        ),
        filled-text-color:(
           color: ("primary", 400)
        )
    )
);

// Extending the light button schema
$custom-button-schema: extend($_light-button,
    (
        flat-background:(
           color: ("secondary", 400)
        ),
        flat-text-color:(
           color: ("primary", 400)
        ),
        flat-hover-background:(
           color: ("primary", 400)
        ),
        flat-hover-text-color:(
           color: ("secondary", 400)
        )
    )
);
```

Para aplicar os nossos schemas personalizados, precisamos **estender** um dos globais (`light` ou `dark`), o que basicamente indica os componentes com um schema personalizado, e depois adicioná-lo aos temas dos respectivos componentes:

```scss
// Extending the global light-schema
$custom-light-schema: extend($light-schema,(
    igx-grid: $custom-grid-schema,
    igx-input-group: $custom-input-group-schema,
    igx-button: $custom-button-schema
));

// Defining grid-theme with the global light schema
$custom-grid: grid-theme(
  $schema: $custom-light-schema
);

// Defining flat-button-theme with the global light schema
$custom-button: flat-button-theme(
  $schema: $custom-light-schema
);

// Defining input-group-theme with the global light schema
$custom-input-group: input-group-theme(
  $schema: $custom-light-schema
);
```

Não se esqueça de incluir os temas da mesma forma como foi demonstrado acima.

## Limitações conhecidas

<DocsAside type="info">
Alguns navegadores, como o Firefox, não conseguem interpretar separadores decimais específicos de cada região, pois os tratam como separadores de agrupamento; assim, esses valores ficam inválidos. Ao informar esses valores como filtro de uma coluna numérica, somente a parte válida do número será aplicada à expressão de filtro. Para mais informações, consulte o [problema](https://bugzilla.mozilla.org/show_bug.cgi?id=1199665) do Firefox.
</DocsAside>

### Mudanças incompatíveis na versão 6.1.0
- A propriedade <ApiLink type="{ComponentName}" /> `filteringExpressions` foi removida. Use <ApiLink type="FilteringExpressionsTree" /> no lugar.
- O método `filter_multiple` foi removido. Use o método <ApiLink type="Filter" /> e a propriedade <ApiLink type="FilteringExpressionsTree" /> no lugar.
- O método <ApiLink type="Filter" /> tem uma nova assinatura. Agora ele aceita os seguintes parâmetros:
  - <ApiLink type="Column" member="name" label="Name" /> - o nome da coluna a ser filtrada.
  - `Value` - o valor a ser usado para a filtragem.
  - `ConditionOrExpressionTree` (opcional) - este parâmetro aceita um objeto do tipo <ApiLink type="FilteringOperation" /> ou <ApiLink type="FilteringExpressionsTree" />. Se for necessária apenas uma filtragem simples, uma operação de filtragem pode ser passada como argumento. No caso de filtragem avançada, uma árvore de expressões contendo uma lógica de filtragem complexa pode ser passada como argumento.
  - <ApiLink type="FilteringExpression" member="ignoreCase" label="IgnoreCase" /> (opcional) - se a filtragem diferencia ou não maiúsculas de minúsculas.
- O evento `FilteringDone` agora tem apenas um parâmetro, do tipo <ApiLink type="FilteringExpressionsTree" />, que contém o estado de filtragem da coluna filtrada.
- Operandos de filtragem: a propriedade <ApiLink type="FilteringExpression" /> da condição não é mais uma referência direta a um método de condição de filtragem; em vez disso, é uma referência a um <ApiLink type="FilteringOperation" />.
- <ApiLink type="ColumnComponent" /> agora expõe uma propriedade <ApiLink type="Column" member="filters" label="Filters" />, que recebe uma referência a uma classe <ApiLink type="FilteringOperand" />.
- Filtros personalizados podem ser fornecidos às colunas {ComponentTitle} preenchendo a propriedade <ApiLink type="BooleanFilteringOperand" member="operations" label="Operations" /> do <ApiLink type="FilteringOperand" /> com operações do tipo <ApiLink type="FilteringOperation" />.
