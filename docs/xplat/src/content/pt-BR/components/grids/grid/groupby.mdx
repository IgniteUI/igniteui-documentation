# Group By da grade {Platform}

O comportamento de Group By do {ProductName} em {Platform} {GridName} cria linhas de dados agrupadas com base nos valores das colunas. O Group By na <ApiLink type="Grid" /> permite visualizar os grupos em uma estrutura hierárquica. As linhas de dados agrupadas podem ser expandidas ou recolhidas, e a ordem de agrupamento pode ser alterada pela interface ou pela API. Quando a Seleção de linhas está habilitada, um seletor de linha do Group By é renderizado na área mais à esquerda da linha de grupo. Se a propriedade <ApiLink type="Grid" member="rowSelection" label="RowSelection" /> estiver definida como single, as caixas de seleção são desabilitadas e servem apenas como indicação do grupo onde a seleção está posicionada. Se a propriedade <ApiLink type="Grid" member="rowSelection" label="RowSelection" /> estiver definida como multiple, clicar no seletor de linha do Group By seleciona todos os registros pertencentes a esse grupo.

## Exemplo de Group By da grade {Platform}
Este exemplo apresenta os recursos de agrupamento de uma grande quantidade de dados. Arrastar os cabeçalhos das colunas para o topo (área de agrupamento) permite que os usuários vejam os dados da coluna selecionada em uma estrutura hierárquica. Eles podem agrupar por vários campos arrastando mais cabeçalhos de colunas para o topo. Essas opções de agrupamento são úteis quando você tem tabelas com muitas linhas e colunas e os usuários querem apresentar os dados de forma muito mais rápida e visualmente agradável.

### API de expandir/recolher

Além das expressões de agrupamento, você também pode controlar os estados de expansão das linhas de grupo. Eles são armazenados em uma propriedade separada do componente <ApiLink type="Grid" /> <ApiLink type="Grid" member="groupingExpansionState" label="GroupingExpansionState" />, que é uma coleção de <ApiLink type="GroupByExpandState" />. Cada estado de expansão é definido de forma única pelo nome do campo para o qual foi criado e pelo valor que representa em cada nível de agrupamento; ou seja, o identificador é um array hierárquico de <ApiLink type="GroupByKey" />.

Assim como com <ApiLink type="Grid" member="groupingExpressions" label="GroupingExpressions" />, definir uma lista de <ApiLink type="GroupByExpandState" /> diretamente em <ApiLink type="Grid" member="groupingExpansionState" label="GroupingExpansionState" /> alterará a expansão de acordo. Além disso, <ApiLink type="Grid" /> expõe um método <ApiLink type="Grid" member="toggleGroup" label="ToggleGroup" /> que alterna um grupo pela instância do registro do grupo ou pela propriedade <ApiLink type="RowDirective" member="expanded" label="Expanded" /> da linha.

## Templates

### Templates de linha de grupo

A linha de grupo, exceto a interface de expandir/recolher, é totalmente personalizável por template. Por padrão, ela renderiza um ícone de agrupamento e exibe o nome do campo e o valor que ele representa. O contexto para renderizar o template é do tipo <ApiLink type="GroupByRecord" />.

Como exemplo, o template a seguir tornaria o resumo das linhas de grupo mais detalhado:

<PlatformBlock for="Angular">

```html
</ng-template>
```

## Group By com paginação da grade {Platform}

As linhas de grupo participam do processo de paginação junto com as linhas de dados. Elas contam para o tamanho da página em cada página. As linhas recolhidas não são incluídas no processo de paginação. Qualquer operação de expandir ou recolher força a Paginação a recalcular o número de páginas e ajustar o índice da página, se necessário.
Grupos que abrangem várias páginas são divididos entre elas. A linha do grupo fica visível somente na página em que começa e não se repete nas páginas seguintes. As informações de resumo das linhas de grupo são calculadas com base no grupo inteiro e não são afetadas pela Paginação.

## Navegação pelo teclado

A UI de agrupamento oferece suporte às seguintes interações pelo teclado:

- Para linhas de grupo (o foco deve estar na linha ou na célula de expandir/recolher)
  - <kbd>ALT</kbd> + <kbd>RIGHT</kbd> - expande o grupo
  - <kbd>ALT</kbd> + <kbd>LEFT</kbd> - recolhe o grupo
  - <kbd>SPACE</kbd> - seleciona todas as linhas do grupo, se a propriedade <kbd>rowSelection</kbd> estiver definida como multiple

- Para componentes <ApiLink pkg="core" type="Chip" /> de grupo na área de Agrupar por (o foco deve estar no chip)
  - <kbd>SHIFT</kbd> + <kbd>LEFT</kbd> - move o chip focado para a esquerda, alterando a ordem de agrupamento, se possível
  - <kbd>SHIFT</kbd> + <kbd>RIGHT</kbd> - move o chip focado para a direita, alterando a ordem de agrupamento, se possível
  - <kbd>SPACE</kbd> - altera a direção da ordenação
  - <kbd>DELETE</kbd> - desagrupa o campo
  - Os elementos separados do chip também podem receber o foco e podem ser usados com a tecla <kbd>ENTER</kbd>.

Depois que os dados forem ordenados, os grupos personalizados podem ser determinados especificando um <ApiLink type="GroupingExpression" member="groupingComparer" label="GroupingComparer" /> para a coluna ou para a expressão de agrupamento específica.

```typescript
        month: date.getMonth() + 1,
        year: date.getFullYear()
    };
}
```

</PlatformBlock>


A <PlatformBlock for="React"><ApiLink type="GroupingExpression" member="groupingComparer" label="GroupingComparer" /></PlatformBlock>A função <ApiLink type="GroupingExpression" member="groupingComparer" label="GroupingComparer" /> é definida para as expressões de agrupamento e determina os itens que pertencem ao mesmo grupo com base no modo de agrupamento selecionado. Os valores nos dados ordenados para os quais essa função retorna 0 são marcados como parte do mesmo grupo.

```typescript
grid.groupingExpressions = [
    { fieldName: 'OrderDate', dir: SortingDirection.Desc,
    groupingComparer: (a, b) => {
            const dateA = this.getParsedDate(a);
            const dateB = this.getParsedDate(b);
            if (this.groupByMode === 'Month') {
                return dateA.month === dateB.month ? 0 : -1;
            } else if (this.groupByMode === "Year") {
                return dateA.year === dateB.year ? 0 : -1;
            } else if (this.groupByMode === 'Week') {
                return this.getWeekOfDate(a) === this.getWeekOfDate(b) ? 0 : -1;
            }
            return dateA.day === dateB.day && dateA.month === dateB.month ? 0 : -1;
        }
    }
];
```

A Grid permite a estilização por meio da [{ProductName} Theme Library](../themes/styles.mdx). O tema da grade expõe uma grande variedade de propriedades, que permitem personalizar todos os recursos da grade.

Nas etapas abaixo, vamos percorrer as etapas de personalização da estilização de Agrupar por da grade.

### Importando o tema global

Para começar a personalização do recurso Agrupar por, você precisa importar o arquivo `index`, onde estão localizadas todas as funções de estilo e mixins.

```scss
@use "igniteui-{Platform}/theming" as *;

// IMPORTANT: Prior to {ProductName} version 13 use:
// @import '~igniteui-{Platform}/lib/core/styles/themes/index';
```

### Definindo um tema personalizado

Em seguida, crie um novo tema que estenda o `grid-theme` e aceite os parâmetros necessários para personalizar o Agrupar por como desejado. Você também precisa estender o `chip-theme`, porque ele é usado no recurso Agrupar por.

```scss

$custom-theme: grid-theme(
    /* Group By properties that affect styling */
    $group-row-background: #494949,
    $group-row-selected-background: #383838,
    $group-label-column-name-text: #f8f8f8,
    $group-label-icon: #FFCD0F,
    $group-label-text: #f8f8f8,
    $group-count-background: #FFCD0F,
    $group-count-text-color: #000,
    $expand-icon-color: #FFCD0F,
    $expand-icon-hover-color: rgb(223, 181, 13),
    $cell-active-border-color: #FFCD0F,
    $row-selected-background: #fff6d3,
    $row-selected-text-color: #000,
    $drop-indicator-color: #FFCD0F
    /* add other features properties here... */
);

/* Chip theme will style the chips in the Group By area */
$custom-chips-theme: chip-theme(
    $background: #494949,
    $text-color: #f8f8f8,
    $hover-text-color: #e7e7e7
);
```

### Definindo uma paleta de cores personalizada

Na abordagem que descrevemos acima, os valores de cor estavam fixos no código. Alternativamente, você pode obter mais flexibilidade usando as funções `palette` e `color`.
`palette` gera uma paleta de cores com base nas cores primária e secundária informadas.

```scss
$black-color: #292826;
$yellow-color: #FFCD0F;

$custom-palette: palette(
  $primary: $black-color,
  $secondary: $yellow-color
);
```

Depois que uma paleta personalizada é gerada, a função `color` pode ser usada para obter diferentes variações das cores primária e secundária.

```scss
$custom-theme: grid-theme(
    $group-row-background: color($custom-palette, "primary", 300),
    $group-row-selected-background: color($custom-palette, "primary", 400),
    $group-label-column-name-text:contrast-color($custom-palette, "primary", 500),
    $group-label-icon: color($custom-palette, "secondary", 600),
    $group-label-text:contrast-color($custom-palette, "primary", 500),
    $group-count-background: color($custom-palette, "secondary", 600),
    $group-count-text-color: color($custom-palette, "primary", 400),
    $expand-icon-color: color($custom-palette, "secondary", 600),
    $expand-icon-hover-color: color($custom-palette, "secondary", 300),
    $cell-active-border-color: color($custom-palette, "secondary", 600)
);

$custom-chips-theme: chip-theme(
    $background: color($custom-palette, "primary", 300),
    $text-color:contrast-color($custom-palette, "primary", 500),
    $hover-text-color:contrast-color($custom-palette, "primary", 600)
);
```

### Definindo schemas personalizados

Você pode ir ainda mais longe e criar uma estrutura flexível que tenha todos os benefícios de um [**schema**](../themes/sass/schemas.mdx). O **schema** é a receita de um tema.
Estenda um dos dois schemas predefinidos, fornecidos para cada componente. No nosso caso, usaríamos `$_light_grid`.

```scss
$custom-grid-schema: extend($_light-grid,(
    group-row-background: (-color:('secondary', 100)),
    group-row-selected-background: (-color:('primary', 400)),
    group-label-column-name-text: (-color:('primary', 600)),
    group-label-icon: (-color:('primary', 600)),
    group-label-text: (-color:('secondary', 700)),
    group-count-background: (-color:('primary', 600)),
    group-count-text-color: (-color:('secondary', 400)),
    expand-icon-color: (-color:('primary', 600)),
    expand-icon-hover-color: (-color:('primary', 400))
));
```

Para que o schema personalizado seja aplicado, é preciso estender um dos globais `light` ou `dark`. O processo, na prática, consiste em fornecer a um componente um schema personalizado e, depois, adicioná-lo ao tema do respectivo componente.

```scss
$my-custom-schema: extend($light-schema, (
    -grid: $custom-grid-schema
));

$custom-theme: grid-theme(
    $palette: $custom-palette,
    $schema: $my-custom-schema
);
```

### Aplicando o tema personalizado

A forma mais fácil de aplicar o seu tema é com uma instrução `sass` `@include` no arquivo de estilos globais:

```scss
@include grid($custom-theme);
@include chip($custom-chips-theme);
```

### Tema limitado ao componente

Para que o tema personalizado afete apenas um componente específico, você pode mover todos os estilos que acabou de definir do arquivo de estilos globais para o arquivo de estilos do componente personalizado (incluindo a importação do arquivo `index`).

Dessa forma, devido ao [ViewEncapsulation](https://{Platform}.io/api/core/Component#encapsulation) de {Platform}, seus estilos serão aplicados somente ao seu componente personalizado.

 <DocsAside type="info">
 Se o componente estiver usando um ViewEncapsulation [Emulated](../themes/styles.mdx#view-encapsulation), é necessário atravessar esse encapsulamento usando `::ng-deep` para estilizar a grade.
 </DocsAside>

 <DocsAside type="info">
 Envolva a instrução em um seletor `:host` para impedir que os seus estilos afetem elementos fora do nosso componente:
 </DocsAside>

```scss
:host {
    ::ng-deep {
        @include grid($custom-theme);
        @include chip($custom-chips-theme);
    }
}
```
