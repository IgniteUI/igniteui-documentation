# Paginação de grade/tabela {Platform}

Interfaces de tabela tabular são comumente usadas em muitos produtos web. Criar uma interface de tabela do zero não é fácil; porém, com a grade {ProductName}, criar uma interface de tabela é simples, e vincular grandes volumes de dados locais ou remotos à grade {Platform} é fácil. Como a grade é virtualizada por padrão, não é necessário incluir paginação de tabela para exibir grandes conjuntos de dados. Ela é usada principalmente por causa da forma mais eficiente de organizar dados complexos na interface. Com a paginação de tabela, os dados podem ser exibidos em um número definido de linhas, permitindo que os usuários “rolem” pelos dados sem precisar de uma barra de rolagem. A interface da paginação de tabela geralmente inclui itens como a página atual, o total de páginas e setas/botões clicáveis Anterior e Próximo, que permitem que os usuários avancem pelas páginas, como demonstrado aqui:

A paginação de linhas é habilitada no {ProductName} Data Table / Data Grid definindo a propriedade `IsPagerVisible`. Além disso, você pode limitar o número máximo de linhas visíveis definindo `PageSize`.

## Visão geral

Do ponto de vista da UX, a paginação de tabela tem prós e contras. De acordo com um [artigo recente](https://www.uxmatters.com/mt/archives/2018/11/paging-scrolling-and-infinite-scroll.php) da UX Matters, veja a seguir uma análise dos pontos positivos e negativos da paginação de tabela.

Benefícios da paginação de tabela:

- Limita a escolha do usuário
- Os cliques são mensuráveis

Pontos negativos da paginação de tabela:

- Os usuários ainda precisam rolar
- Os paginadores funcionam e se comportam de forma diferente de site para site
- Controles de interface demais podem confundir
- Os usuários percebem a paginação como lenta e trabalhosa
- Os usuários podem não notar os controles de paginação
- O carregamento de páginas pode ser lento
- Os usuários ficam em dúvida se as ações se aplicam à página ou a todo o conjunto de dados

Com o {ProductName} Data Grid, você pode adicionar paginação. No entanto, como o Data Grid tem rolagem infinita integrada por padrão, recomendamos a rolagem infinita (ou virtual) em vez de adicionar um paginador. Com a rolagem infinita virtualizada como experiência padrão do usuário, você obtém:

- O melhor desempenho, mantendo ainda o controle sobre a quantidade de dados ‘paginados’ pela interação de rolagem
- Uma abordagem natural para rolar todo o conteúdo
- Todas as interações são claras para o usuário final
- Corresponde às interações naturais de uma UX mobile

## Sincronização de grade/página {Platform}

Quando os usuários interagem com a grade, como ordenando e agrupando, e você habilitou o Pager {Platform} na grade, é preciso usar as funções a seguir para garantir que os dados da paginação {Platform} fiquem sincronizados com a exibição da tabela {Platform}.

- applySorts
- applyGroups
- applyFilters
