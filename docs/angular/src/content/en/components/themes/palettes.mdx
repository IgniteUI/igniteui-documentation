# Palettes

Ignite UI for Angular palettes are sets of `--ig-*` CSS variables, generated from seed colors, that supply the colors of every component theme.

## Overview

An Ignite UI for Angular palette has eight color families: `primary`, `secondary`, `gray`, `surface`, `info`, `success`, `warn`, and `error`. Each family exposes its shades as CSS variables named `--ig-<family>-<variant>`, for example `--ig-primary-500`.

| Family | Variants |
|---|---|
| `primary`, `secondary`, `info`, `success`, `warn`, `error` | `50`, `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900`, `A100`, `A200`, `A400`, `A700`, `seed` |
| `gray` | `50`–`900`, `seed` |
| `surface` | `base`, `sunken`, `raised`, `overlay`, `container`, `seed` |

The numbered shades run from `50`, the lightest, to `900`, the darkest. The `A100`–`A700` accent shades are vivid variants for emphasis. The `seed` variant holds the color the family was generated from. The `surface` family describes layers rather than shades: `base` is the page and component background, `sunken`, `raised`, and `overlay` are layers relative to it, and `container` is a translucent fill. Palettes also include numbered `surface` shades for compatibility, but they are deprecated, and component themes read the roles.

Every variant has a matching `-contrast` variable, such as `--ig-primary-500-contrast`, that resolves to black or white, whichever reads better against that shade at the configured WCAG level.

<DocsAside type="info">
Contrast colors are CSS relative colors calculated by the browser from their shade, so a contrast color follows any change to its shade. The translucent `container` is the exception: its contrast color is calculated from the container laid over `base`, which is what text on it is read against, so it follows changes to either.
</DocsAside>

Here is an excerpt of the `primary` family in the light Material palette:

```css
:root {
  --ig-primary-500: #09f;
  --ig-primary-500-contrast: hsla(from color(from var(--ig-primary-500) var(--y-contrast)) h 0 l / 1);
  --ig-primary-600: hsl(from var(--ig-primary-500) h calc(s * 1.26) calc(l * 0.89));
  --ig-primary-600-contrast: hsla(from color(from var(--ig-primary-600) var(--y-contrast)) h 0 l / 1);
  --ig-primary-seed: #09f;
  /* ... */
  --ig-wcag-a: 0.31;
  --ig-wcag-aa: 0.185;
  --ig-wcag-aaa: 0.178;
  --ig-contrast-level: var(--ig-wcag-aa);
  --y: clamp(0, (y / var(--ig-contrast-level) - 1) * -infinity, 1);
  --y-contrast: xyz-d65 var(--y) var(--y) var(--y);
}
```

The contrast threshold is held in `--ig-contrast-level`, which defaults to `var(--ig-wcag-aa)`. Override it on any selector to switch to `var(--ig-wcag-a)` or `var(--ig-wcag-aaa)`. In Sass, the `palette()` and `adaptive-contrast()` mixins accept `'a'`, `'aa'`, or `'aaa'` directly:

```scss
@include palette($palette, $contrast-level: 'aaa');
```

## How Palettes Are Generated

Every Ignite UI for Angular palette, including the predefined ones behind the prebuilt themes, is generated by the `palette()` function of the `igniteui-theming` Sass library. The function has two generators, and they produce CSS variables that behave differently at runtime:

| Generator | Shades are emitted as | Used by |
|---|---|---|
| `legacy` | CSS relative colors of `500`. Overriding `--ig-primary-500` updates every primary shade in the browser. | The predefined palettes and the prebuilt themes. |
| `fitted` | Fixed colors solved for contrast targets. Overriding one variable changes only that shade. | Palettes you generate with `palette()` in Sass, by default. |

The `legacy` generator multiplies the `500` shade's saturation and lightness by fixed values, so the quality of its shades depends on how light or dark the `500` color is. A very dark or very pale `500` produces shades that bunch together or resolve to white. The `fitted` generator builds every family to a contrast scale instead, so very dark and very pale seeds still produce ten distinct shades. [Palette Generation](./palette-generation.mdx) explains both generators, and [Palettes with Sass](./sass/palettes.mdx) shows how to generate a palette.

The rest of this topic describes runtime overrides, which derive new shades only in palettes built with the `legacy` generator, such as the prebuilt themes.

## Defining Palettes

Change a color family by overriding its `500` variant. Every other numbered and accent shade of the family is a relative color of `500`, so it updates with it:

```css
:root {
  --ig-primary-500: #09f;
}
```

The derived shades keep the hue of `500` and change only its saturation and lightness, so each family is monochromatic:

```css
:root {
  --ig-primary-600: hsl(from var(--ig-primary-500) h calc(s * 1.26) calc(l * 0.89));
}
```

The `seed` variable is not derived from `500`; it records the color the palette was built from. Override the shades you use, not `seed`.

## Scoping

Override palette variables on `:root` in your application's `styles.css` to change the global palette. Any CSS color syntax works:

```css
:root {
  --ig-primary-500: #9f349c;
}
```

Scope overrides to other selectors to run several palettes side by side. For example, define a blue and a red palette on classes:

```css
/* styles.css */

.blue-theme {
  --ig-primary-500: #0008ff;
}

.red-theme {
  --ig-primary-500: #ff0400;
}
```

```html
<app-component class="blue-theme"></app-component>
```

Change the class from `blue-theme` to `red-theme` to switch the palette of everything inside the element.

The same approach changes a palette color for a single component. The Material avatar, for example, takes its background from the `gray` `400` shade, so overriding that shade on the avatar changes its background without touching the rest of the palette:

```css
igx-avatar {
  --ig-gray-400: #efefef;
}
```

## Dark vs. Light

<DocsAside type="warning">
The `gray` and `surface` families are displayed against each other in most components. Keep the `gray` shades contrasting with the `surface` color.
</DocsAside>

The `gray` and `surface` families decide whether an Ignite UI for Angular palette is light or dark. Light palettes pair a light surface with grays built from a dark color; dark palettes pair a dark surface with grays built from white. Text, borders, and icons take their colors from the grays, so the two families must stay on opposite ends of the gray scale.

Since Ignite UI for Angular 22.3.0, component backgrounds read the `surface` roles instead of `--ig-surface-500`, so override the roles to change the surface at runtime. The roles are fixed colors under both generators, and they are not derived from `--ig-surface-500`:

_Material light:_

```css
:root {
  /* the surface roles are light */
  --ig-surface-base: #fff;
  --ig-surface-raised: #fff;
  --ig-surface-overlay: #fff;
  --ig-surface-sunken: #f7f7f7;
  /* grays are built from a dark color to contrast the surface */
  --ig-gray-500: hsl(0, 0%, 62%);
}
```

_Material dark:_

```css
:root {
  /* the surface roles are dark */
  --ig-surface-base: #222;
  --ig-surface-raised: #282828;
  --ig-surface-overlay: #2f2f2f;
  --ig-surface-sunken: #1c1c1c;
  /* grays are built from white to contrast the surface */
  --ig-gray-500: hsl(0, 0%, 74%);
}
```

Change `gray` and `surface` carefully: most components use them, and they have the largest effect on the overall look of a theme.

## Other Colors

The `info`, `success`, `warn`, and `error` families color states, such as the validation states of the `igx-input-group`. Override their `500` variants to change them, and the rest of each family follows:

```css
:root {
  --ig-info-500: #1377d5;
  --ig-success-500: #4eb862;
  --ig-warn-500: #faa419;
  --ig-error-500: #ff134a;
}
```
