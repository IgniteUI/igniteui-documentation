# Data Grid

The Ignite UI for Angular Data Grid (<ApiLink type="Grid" label="IgxGridComponent" />) displays and edits flat tabular data: an array of records, one row per record. It is the grid to start with for lists of orders, customers and transactions. You enable features such as sorting, filtering, grouping, editing, paging and Excel export per column or per grid, and the Data Grid virtualizes its rows and columns by default.

For hierarchical data, use the [Tree Grid](/treegrid/tree-grid) or the [Hierarchical Grid](/hierarchicalgrid/hierarchical-grid), which offer most of the same features. To summarize data in a cross-tabular layout, use the [Pivot Grid](/pivotgrid/pivot-grid).

The selector of the Angular Data Grid is `igx-grid`, and each `igx-column` in it defines one column.

## Getting Started

Install Ignite UI for Angular with `ng add igniteui-angular`, or follow the [Getting Started](/general/getting-started) topic. Then add the [`IGX_GRID_DIRECTIVES`](https://github.com/IgniteUI/igniteui-angular/blob/master/projects/igniteui-angular/grids/grid/src/grid.module.ts) token to the `imports` of your component. It holds the <ApiLink type="Grid" />, the column, toolbar and paginator components and the template directives; to import only the grid, use `IgxGridComponent`:

```typescript
// home.component.ts

import { Component } from '@angular/core';
import { IGX_GRID_DIRECTIVES } from 'igniteui-angular/grids/grid';
// import { IGX_GRID_DIRECTIVES } from '@infragistics/igniteui-angular/grids/grid'; for licensed package

@Component({
    selector: 'app-home',
    template: `<igx-grid [data]="localData" [autoGenerate]="true"></igx-grid>`,
    styleUrls: ['home.component.scss'],
    imports: [IGX_GRID_DIRECTIVES]
    /* or imports: [IgxGridComponent] */
})
export class HomeComponent {
    public localData = [
        { ProductName: 'Chai', UnitPrice: 18, Discontinued: false },
        { ProductName: 'Chang', UnitPrice: 19, Discontinued: true }
    ];
}
```

## Usage

Use the Angular Data Grid to display, edit and analyze records that share the same fields.

### Basic Configuration

Add the `igx-grid` element to the template of your component and bind its data:

```html
<igx-grid #grid1 id="grid1" [data]="localData" [autoGenerate]="true"></igx-grid>
```

The <ApiLink type="Grid" member="data" /> property binds the grid, here to a local array of objects. With <ApiLink type="Grid" member="autoGenerate" />, the grid creates a <ApiLink type="Column" /> for each field of the first record and infers its data type: a number, a Boolean, a `Date` object and a string that ends with an image file extension, such as `.png`, give number, boolean, date and image columns, and any other value gives a string column. To set the columns and their mapping to the data fields yourself, [define the columns](#column-configuration).

The Data Grid is a data component, not a page layout grid. For a responsive, Bootstrap-like page layout, Ignite UI for Angular has the flex-based [Layout Manager](/layout) directives. The size of the Data Grid itself follows its container and its `width` and `height`; see [Grid Sizing](/grid/sizing).

### Column Configuration

Each <ApiLink type="Column" /> in the <ApiLink type="Grid" member="columns" /> collection of the grid defines one column and the features enabled for it, such as **sorting** and **filtering**, and can have cell, header and footer templates.

#### Defining Columns

To define the columns yourself, leave <ApiLink type="Grid" member="autoGenerate" /> off and declare them in the markup:

```html
<igx-grid #grid1 [data]="data | async" [autoGenerate]="false" (columnInit)="initColumns($event)"
    (selected)="selectCell($event)" [allowFiltering]="true">
    <igx-column field="Name" [sortable]="true" header=" "></igx-column>
    <igx-column field="AthleteNumber" [sortable]="true" header="Athlete number" [filterable]="false"></igx-column>
    <igx-column field="TrackProgress" header="Track progress" [filterable]="false">
        <ng-template igxCell let-value>
            <igx-linear-bar [striped]="false" [value]="value" [max]="100"></igx-linear-bar>
        </ng-template>
    </igx-column>
    <igx-paginator [perPage]="6">
    </igx-paginator>
</igx-grid>
```

Each column takes its templates as `ng-template` elements marked with the template directives of the grid.

To pass your own data to the templates of a column, set its <ApiLink type="Column" member="additionalTemplateContext" /> input:

```html
<igx-column [additionalTemplateContext]="contextObject">
    <ng-template igxCell let-cell="cell" let-props="additionalTemplateContext">
        {{ props.firstProperty }}
    </ng-template>
</igx-column>
```

```ts
public contextObject = { firstProperty: 'testValue', secondProperty: 'testValue1'};
```

#### Header Template

The `igxHeader` template replaces the content of the column header. Its context is the column object:

```html
<igx-column field="Name">
    <ng-template igxHeader let-column>
        {{ column.field | uppercase }}
    </ng-template>
</igx-column>
```

When the header template is used along with grouping or moving, see [Why can't I click the elements in my column header template?](#why-cant-i-click-the-elements-in-my-column-header-template)

#### Cell Template

The `igxCell` template applies to all cells of the column. Its context is the cell value, provided implicitly (`$implicit`), and the cell object (`cell`):

```html
<igx-column field="Name">
    <ng-template igxCell let-value>
        {{ value | titlecase }}
    </ng-template>
</igx-column>
```

The `uppercase` and `titlecase` pipes come from `@angular/common`. Add `UpperCasePipe` and `TitleCasePipe` to the `imports` of your component.

The implicit value is enough to format or style what the cell shows. To read other fields of the record or to call the API of the grid, take the <ApiLink kind="interface" type="CellType" /> instance instead:

```html
<igx-grid #grid [data]="data">
    <igx-column dataType="string" field="Name">
        <ng-template igxCell let-cell="cell">
            <!-- Implement row deleting inside the cell template itself -->
            <span tabindex="0" (keydown.delete)="grid.deleteRow(cell.row.key)">{{ cell.value | titlecase }}</span>
        </ng-template>
    </igx-column>
    <igx-column dataType="boolean" field="Subscription">
        <ng-template igxCell let-cell="cell">
            <!-- Bind the cell value through the ngModel directive and update the data source when the value is changed in the template -->
            <input type="checkbox" [ngModel]="cell.value" (ngModelChange)="cell.update($event)" />
        </ng-template>
    </igx-column>
</igx-grid>
```

When a cell template changes the value with `ngModel`, update it through the grid's [editing API](/grid/cell-editing#editing-through-api), as the `ngModelChange` handler above does. The change then goes through the editing pipeline and reaches [transactions](/grid/batch-editing), [summaries](/grid/summaries) and [selection](/grid/selection). `ngModelChange` fires on every change of the value, not only when the user finishes editing, so it makes more API calls.

<DocsAside type="info">
The grid has default templates for the number, string, date and boolean column types. A boolean column, for example, shows a `check` or a `close` icon instead of true/false.
</DocsAside>

A value bound with `[(ngModel)]` whose change you don't handle is **not** written to the data of the grid. For editing with a custom template, use the [cell editing template](#cell-editing-template): it passes the cell's <ApiLink kind="interface" type="CellType" member="editValue" /> through the grid's [editing event cycle](/grid/editing#event-arguments-and-sequence).

#### Cell Editing Template

The `igxCellEditor` template replaces the editor that a cell shows in edit mode. Its context is again the cell value and the cell object. The template applies only when the <ApiLink type="Column" member="editable" /> property of the column is `true`:

```html
<igx-column dataType="number" editable="true" field="Price">
    <ng-template igxCellEditor let-cell="cell">
        <label for="price">
            Enter the new price tag
        </label>
        <input name="price" type="number" [(ngModel)]="cell.editValue" />
    </ng-template>
</igx-column>
```

The <ApiLink kind="interface" type="CellType" /> API lists the properties that you can use in the templates.

#### Column Template API

You can change the templates of a column in code at any time through the <ApiLink type="Column" /> object. The example below declares two templates for the user data, gets references to them and assigns the one that fits a condition:

```html
<igx-grid>
    <!-- Column declarations -->
</igx-grid>

<ng-template #normalView let-value>
    <div class="user-details">{{ value }}</div>
    <user-details-component></user-details-component>
</ng-template>

<ng-template #smallView let-value>
    <div class="user-details-small">{{ value }}</div>
</ng-template>
```

```typescript
@ViewChild("normalView", { read: TemplateRef })
public normalView: TemplateRef<any>;

@ViewChild("smallView", { read: TemplateRef })
public smallView: TemplateRef<any>;

// ...

const column = this.grid.getColumnByName("User");
// Return the appropriate template based on some condition.
// For example saved user settings, viewport size, etc.
column.bodyTemplate = this.smallView;
```

You can also set column properties in the <ApiLink type="Grid" member="columnInit" /> event, which the grid emits when it initializes each column:

```typescript
public initColumns(column: IgxColumnComponent) {
    if (column.field === 'ProductName') {
        column.sortable = true;
        column.editable = true;
    }
}
```

This makes the **ProductName** column sortable and editable, and the grid shows the UI of those features for it.

#### Custom Display Format

The grid formats the values of date, number, currency and percent columns with the Angular [`DatePipe`](https://angular.dev/api/common/DatePipe), [`DecimalPipe`](https://angular.dev/api/common/DecimalPipe), [`CurrencyPipe`](https://angular.dev/api/common/CurrencyPipe) and [`PercentPipe`](https://angular.dev/api/common/PercentPipe). Formatting changes only what the column displays; data operations use the values in your data source. The format follows the <ApiLink type="Grid" member="locale" /> of the grid, which falls back to the application locale (`'en-US'` by default); see [Setting up the locale of your app](https://angular.dev/guide/i18n/locale-id).

The optional formatting parameters are:

- `format` - determines what date/time parts are displayed, defaults to `'mediumDate'`, equivalent to `'MMM d, y'`
- `timezone` - the timezone offset for dates. By default uses the end-user's local system timezone
- `digitsInfo` - decimal representation objects. Default to `'1.0-3'`

Set them through the <ApiLink type="Column" member="pipeArgs" /> input of the column. A column uses only the parameters that apply to its data type:

```typescript
const pipeArgs: IColumnPipeArgs = {
     format: 'longDate',
     timezone: 'UTC',
     digitsInfo: '1.1-2'
}
```

```html
<igx-column field="OrderDate" dataType="date" [pipeArgs]="pipeArgs"></igx-column>
<igx-column field="UnitPrice" dataType="number" [pipeArgs]="pipeArgs"></igx-column>
```

Here the `OrderDate` column uses only `format` and `timezone`, and the `UnitPrice` column only `digitsInfo`. For details, see [Localizing your app](https://angular.dev/guide/i18n) in the Angular documentation.

The [Column Types](/grid/column-types#default-template) topic lists all column data types.

### Data Binding

The Angular Data Grid binds to an array of objects.

#### Data Structure

The <ApiLink type="Grid" /> displays flat records and records with nested objects.

<DocsAside type="warning">
**The key values must not contain arrays**. To show an array value, give its column a cell template, as the [Complex Data Binding](#complex-data-binding) section shows.
If you use <ApiLink type="Grid" member="autoGenerate" /> columns **the data keys must be identical.**
</DocsAside>

#### Remote Data Binding

To bind the grid to remote data, keep the data fetching in a separate service. The example below creates one for the Northwind products:

```typescript
// northwind.service.ts

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable, of } from 'rxjs';
import { catchError, map } from 'rxjs/operators';
```

The [`Injectable`](https://angular.dev/guide/di) decorator makes the class a service, and the `HttpClient` requests the data and returns an `Observable` that the grid component subscribes to.

The response is a JSON array of records, so describe a record with an interface to get type checking:

```typescript
// northwind.service.ts

export interface NorthwindRecord {
    ProductID: number;
    ProductName: string;
    SupplierID: number;
    CategoryID: number;
    QuantityPerUnit: string;
    UnitPrice: number;
    UnitsInStock: number;
    UnitsOnOrder: number;
    ReorderLevel: number;
    Discontinued: boolean;
    CategoryName: string;
}
```

The service has one method, `fetchData`, which returns an `Observable<NorthwindRecord[]>`. When the request fails, the `catchError` operator passes the error to a handler that logs it and returns a safe value:

```typescript
// northwind.service.ts

@Injectable()
export class NorthwindService {
    private url = 'https://services.odata.org/V4/Northwind/Northwind.svc/Alphabetical_list_of_products';

    constructor(private http: HttpClient) {}

    public fetchData(): Observable<NorthwindRecord[]> {
        return this.http
            .get<{ value: NorthwindRecord[] }>(this.url)
            .pipe(
                map(response => response.value),
                catchError(
                    this.errorHandler('Error loading northwind data', [])
                )
            );
    }

    private errorHandler<T>(message: string, result: T) {
        return (error: any): Observable<any> => {
            console.error(`${message}: ${error.message}`);
            return of(result as T);
        };
    }
}
```

Provide the `HttpClient` with `provideHttpClient()` and register the service in the application configuration:

```typescript
// app.config.ts

import { ApplicationConfig } from '@angular/core';
import { provideHttpClient } from '@angular/common/http';
import { NorthwindService } from './northwind.service';

export const appConfig: ApplicationConfig = {
    providers: [
        provideHttpClient(),
        NorthwindService
    ]
};
```

Inject the service in the component and request the data in the `ngOnInit` lifecycle hook. The request is asynchronous, so `records` starts as an empty array; without an initial value it would be `undefined` until the response arrives (a `BehaviorSubject` works as well):

```typescript
// my.component.ts

@Component({
    // ...
})
export class MyComponent implements OnInit {

    public records: NorthwindRecord[] = [];

    constructor(private northwindService: NorthwindService) {}

    ngOnInit() {
        this.northwindService.fetchData().subscribe((records) => this.records = records);
    }
}
```

Bind the grid to `records` in the template of the component:

```html
<igx-grid [data]="records">
    <igx-column field="ProductID"></igx-column>
    <!-- rest of the column definitions -->
</igx-grid>
```

With <ApiLink type="Grid" member="autoGenerate" />, the grid generates the columns when the data arrives from the service.

For real-time updates, see [Live Data](/grid/live-data). For sorting, filtering and paging on the server, see [Remote Data Operations](/grid/remote-data-operations).

#### Complex Data Binding

The <ApiLink type="Grid" /> binds to complex objects, including objects nested deeper than one level, through a path of properties in the data record.

Take this data model:

```typescript
interface AminoAcid {
    name: string;
    abbreviation: {
        short: string;
        long: string;
    }
    weight: {
        molecular: number;
        residue: number;
    },
    formula: {
        molecular: string;
        residue: string;
    }
    // ...
}
```

To display the weights of an amino acid, set the path as the field of the column:

```html
<igx-column field="weight.molecular"></igx-column>
<igx-column field="weight.residue"></igx-column>
```

Sorting, filtering, grouping, editing with or without transactions, and cell templates all work with a column bound this way, without additional configuration.

<DocsAside type="warning">
The grids **do not** support this kind of binding for <ApiLink type="Grid" member="primaryKey" />, `foreignKey` and `childDataKey` properties where applicable.
</DocsAside>

- the `value` of the cell, which holds the nested data
- the `cell` object, to read any value of the record through `cell.row.data[field]` and `cell.row.data[field][nestedField]`

```html
<igx-column field="abbreviation.long" header="Long">
    <ng-template igxCell let-cell="cell">
        <div>
            <div>
                {{ cell.value }}
                {{ cell.row.data['name'] }}
                {{ cell.row.data['weight']['molecular'] }}
            </div>
        </div>
    </ng-template>
</igx-column>
```

#### Working with Flat Data

With flat data the approach is the same, but the template reads the whole record from the <ApiLink type="GridRow" member="data" /> property of the <ApiLink type="GridRow" /> instead of the cell value, so one column can show several fields of the record.

The example uses this data:

```typescript
export const DATA: any[] = [
    {
        Address: "Obere Str. 57",
        City: "Berlin",
        CompanyName: "Alfreds Futterkiste",
        ContactName: "Maria Anders",
        ContactTitle: "Sales Representative",
        Country: "Germany",
        Fax: "030-0076545",
        ID: "ALFKI",
        Phone: "030-0074321",
        PostalCode: "12209",
        Region: null
    },
    // ...
];
```

The cell template:

```html
<igx-column field="Address" header="Address" width="25%" editable="true">
    <ng-template #compositeTemp igxCell let-cell="cell">
        <div class="address-container">
        <!-- In the Address column combine the Country, City and PostCode values of the corresponding data record -->
            <span><strong>Country:</strong> {{cell.row.data.Country}}</span>
            <br/>
            <span><strong>City:</strong> {{cell.row.data.City}}</span>
            <br/>
            <span><strong>Postal Code:</strong> {{cell.row.data.PostalCode}}</span>
        </div>
    </ng-template>
</igx-column>
```

This template only displays the fields; to edit them, add a cell editing template:

```html
<igx-column field="Address" header="Address" width="25%" editable="true">
    <ng-template igxCellEditor let-cell="cell">
        <div class="address-container">
            <span>
                <strong>Country:</strong> {{cell.row.data.Country}}
                <igx-input-group width="100%">
                        <input igxInput [(ngModel)]="cell.row.data.Country" />
                </igx-input-group>
            </span>
            <br/>
            <span><strong>City:</strong> {{cell.row.data.City}}</span>
            <igx-input-group width="100%">
                    <input igxInput [(ngModel)]="cell.row.data.City" />
            </igx-input-group>
            <br/>
```

### Performance (Experimental)

The `IgxGridComponent` works with the event coalescing of Angular, which improves the responsiveness of interactions by roughly **20%**. Enable it for the application by setting the `eventCoalescing` and `runCoalescing` options of `provideZoneChangeDetection` to `true`:

```typescript
// main.ts

bootstrapApplication(AppComponent, {
    providers: [provideZoneChangeDetection({ eventCoalescing: true, runCoalescing: true })]
}).catch(err => console.error(err));
```

Event coalescing is an option of the zone.js-based change detection, while Angular 21 and later use zoneless change detection by default. In an NgModule-based application, pass the same provider in the `applicationProviders` option of `bootstrapModule()`.

<DocsAside type="info">
Event coalescing is experimental for the `IgxGridComponent` and can cause unexpected behavior in the grid; if it does, report it on [GitHub](https://github.com/IgniteUI/igniteui-angular/discussions). It applies to the whole application, so it can also affect parts that don't use the grid.
</DocsAside>

### Sass Theming

The recommended way to style the grid is the <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} /> function with three colors: `background`, `foreground` and `accent-color`.

All parts of the grid and its nested components, such as buttons, icons, inputs, drop-downs, checkboxes, scrollbars and chips, derive their colors from these three values:

```scss
@use "igniteui-angular/theming" as *;

$custom-grid: grid-theme(
  $background: #292826,
  $foreground: #eeece1,
  $accent-color: #ffcd0f
);

igx-grid {
  @include tokens($custom-grid);
}
```

The <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} /> function has more parameters, such as `$header-background` and `$row-hover-background`, for more specific changes.

## Accessibility

The Angular Data Grid can be operated with the keyboard and exposes its structure and state to assistive technology through ARIA roles and attributes.

### Keyboard Interaction

Keyboard navigation covers every element of the grid: cells, rows, column headers, the toolbar and the footer. The header row and the body are separate tab stops, and inside each of them the arrow keys move the active cell. The following keys work while the header row or the body has the focus:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Outside edit mode, the Data Grid doesn't handle these keys, so they move the focus to the next or the previous tab stop. While a cell or a row is in edit mode, they move to the next or the previous editable cell. |
| <kbd>Arrow Up</kbd> / <kbd>Arrow Down</kbd> | Move the active cell one row up or down. |
| <kbd>Arrow Left</kbd> / <kbd>Arrow Right</kbd> | Move the active cell, or the active column header, one column to the left or to the right. |
| <kbd>Home</kbd> / <kbd>End</kbd> | Move to the first or the last cell of the row. |
| <kbd>Ctrl</kbd> + <kbd>Home</kbd> / <kbd>Ctrl</kbd> + <kbd>End</kbd> | Move to the first cell of the first data row, or to the last cell of the last data row. |
| <kbd>Ctrl</kbd> + <kbd>Arrow Up</kbd> / <kbd>Ctrl</kbd> + <kbd>Arrow Down</kbd> | In the body, move to the first or the last data row in the column. On the header of a sortable column, sort the column in ascending or descending order, or clear the sorting when the column is already sorted in that order. |
| <kbd>Page Up</kbd> / <kbd>Page Down</kbd> | Scroll the body one page up or down. |
| <kbd>Enter</kbd> / <kbd>F2</kbd> | Enter edit mode in an editable cell. |
| <kbd>Esc</kbd> | Exit edit mode and discard the change. |
| <kbd>Space</kbd> | Select or deselect the row when row selection is on. |
| <kbd>Alt</kbd> + <kbd>Arrow Left</kbd> / <kbd>Alt</kbd> + <kbd>Arrow Up</kbd> | Collapse the group row. |
| <kbd>Alt</kbd> + <kbd>Arrow Right</kbd> / <kbd>Alt</kbd> + <kbd>Arrow Down</kbd> | Expand the group row. |

More about keyboard navigation:

- [Grid Keyboard Navigation](/grid/keyboard-navigation)
- [Tree Grid Keyboard Navigation](/treegrid/keyboard-navigation)
- [Hierarchical Grid Keyboard Navigation](/hierarchicalgrid/keyboard-navigation)
- [Blog post](https://www.infragistics.com/community/blogs/b/engineering/posts/grid-keyboard-navigation-accessibility) - Improving Usability, Accessibility and ARIA Compliance with Grid keyboard navigation

### Screen Readers / ARIA

The Angular Data Grid renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| `igx-grid` | `grid` | `aria-rowcount` and `aria-colcount` |
| `igx-grid-header-row` | `rowgroup` | `aria-activedescendant` that points to the active column header |
| `div.igx-grid__tr` in the header row | `row` | `aria-rowindex="1"` |
| `igx-grid-header` | `columnheader` | `aria-sort` (`ascending` or `descending`) when the column is sorted, `aria-selected`, `aria-colindex` and `aria-rowindex` |
| `div.igx-grid__tbody-content` | `rowgroup` | `aria-activedescendant` that points to the active cell |
| `igx-grid-row` | `row` | `aria-selected` and `aria-disabled` |
| `igx-grid-cell` | `gridcell` | `aria-rowindex`, `aria-colindex`, `aria-selected`, `aria-readonly` when the cell can't be edited, and `aria-invalid` and `aria-describedby` when the value fails validation |
| `igx-grid-groupby-row` | `row` | The expand indicator of the group row is a `gridcell` with `aria-expanded`. |
| `igx-grid-summary-row` | `row` | The summary cells have the `cell` role. |
| `igx-page-nav` in the paginator | `navigation` | The page buttons have accessible names, such as "Next page". |

The Angular Data Grid also behaves as follows for assistive technology:

- The focus stays on the header row or on the body while the active cell moves, and `aria-activedescendant` points to the active column header or cell.
- Only the rows and the columns in view are in the DOM. `aria-rowindex` and `aria-colindex` give each rendered cell its position in the data.

### Accessibility Compliance

The [Accessibility Compliance](/interactivity/accessibility-compliance) topic lists the standards that Ignite UI for Angular targets, WCAG 2.1 Level AA among them, and records what the Data Grid documentation covers. It is a support summary, not a formal conformance statement.

| Criterion | How the component complies |
| --- | --- |
| [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships) | The `grid`, `rowgroup`, `row`, `columnheader` and `gridcell` roles expose the structure, and `aria-rowindex` and `aria-colindex` give the position of each cell in the data. |
| [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | The arrow keys, Home, End, Page Up and Page Down move through the cells, Enter and F2 start editing, Space selects rows, and Ctrl + Arrow Up and Ctrl + Arrow Down sort from a column header. |
| [2.1.2 No Keyboard Trap](https://www.w3.org/WAI/WCAG21/Understanding/no-keyboard-trap) | Outside edit mode, the Data Grid doesn't handle the Tab key, so Tab and Shift + Tab move the focus out of the header row and the body. |
| [2.4.3 Focus Order](https://www.w3.org/WAI/WCAG21/Understanding/focus-order) | The header row and the body are separate tab stops, in their visual order. |
| [2.4.7 Focus Visible](https://www.w3.org/WAI/WCAG21/Understanding/focus-visible) | The active cell and the active column header show a border in the `--cell-active-border-color` color. |
| [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | Cells expose the `gridcell` role and their selected and read-only states through `aria-selected` and `aria-readonly`. Column headers expose the sort direction through `aria-sort`, and group rows expose their expanded state through `aria-expanded`. |

Your responsibilities:

- Give the Data Grid an accessible name, for example with `aria-label` or `aria-labelledby` on the grid element. The Data Grid doesn't set one.
- Give icons and icon-only buttons that you place in cell and header templates an accessible name.
- Test the focusable elements that you place in cell templates with the keyboard. The Data Grid handles the arrow keys, Enter, F2, Esc and Space on the body, so these elements may need to handle the keys that they use.
- When you override the theme colors, keep a contrast ratio of at least 4.5:1 for the text of the headers and the cells, as [1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum) requires, and keep the border of the active cell visible. See [Styling](#styling).

## Troubleshooting

These questions cover common problems when you set up the Angular Data Grid.

### Why can't I click the elements in my column header template?

When column moving is on or the column is groupable, the header of the Angular Data Grid is draggable, so pressing the pointer on the header starts a drag instead of reaching the elements in your header template. Set `draggable="false"` on the element that the user clicks:

```html
<igx-column field="ProductName" header="Product name" [groupable]="true">
    <ng-template igxHeader let-column>
        <span>{{ column.header }}</span>
        <button type="button" draggable="false" (click)="column.hasSummary = !column.hasSummary">Summary</button>
    </ng-template>
</igx-column>
```

### How do I import the Data Grid in an NgModule-based application?

The `IGX_GRID_DIRECTIVES` token in [Getting Started](#getting-started) is for standalone components, which the Data Grid supports as of version `16.0.0`. An application that still declares its components in NgModules can import the `IgxGridModule` in its **app.module.ts** file instead, which the package keeps for backward compatibility:

```typescript
// app.module.ts

import { NgModule } from '@angular/core';
import { IgxGridModule } from 'igniteui-angular/grids/grid';
// import { IgxGridModule } from '@infragistics/igniteui-angular/grids/grid'; for licensed package

@NgModule({
    imports: [IgxGridModule]
})
export class AppModule {}
```

## Known Limitations

The Angular Data Grid has the following limitations.

| Limitation | Description |
| --- | --- |
| Column widths in `%` and `px` | Mixing percentage and pixel column widths is not supported. |
| Filtering a number column | A value that is not a number in the filter input returns `NaN`. |
| Data Grid width and column widths | Unless the <ApiLink type="Grid" member="width" /> of the Data Grid is `null`, the column widths do not determine the width of the Data Grid; the width of the Data Grid or of its parent container does. |
| `OnPush` change detection | The Data Grid uses `ChangeDetectionStrategy.OnPush`. When a customization changes what the Data Grid shows, make sure that the Data Grid is notified about the change. |
| Minimum column width | Resizing or auto-sizing doesn't make a column narrower than 56 px (small), 64 px (medium) or 80 px (large), depending on `--ig-size`, unless the column has a minimum width of its own. A narrower width that you set yourself applies. |
| Row height and virtualization | A custom cell template that is outside the viewport does not affect the row height until it scrolls into view. |

<DocsAside type="info">
The grid uses the `igxForOf` directive internally, so the [`igxForOf` known limitations](/for-of#known-limitations) apply to it too.
</DocsAside>

These questions cover common Angular Data Grid data binding, editing and performance scenarios.

<Faq>
  <FaqItem question="How do I bind the Angular Data Grid to remote data?" indicatorPosition="end">
    Fetch the data and assign the array to the data property of the Angular Data Grid. The [Remote Data Binding](#remote-data-binding) section shows the complete example and links to the topics about live data and server-side data operations.
  </FaqItem>
  <FaqItem question="When should I use the Tree Grid or the Hierarchical Grid instead of the Data Grid?" indicatorPosition="end">
    Use the Tree Grid or the Hierarchical Grid for records that form a hierarchy; the [Related Components](#related-components) section explains when each one fits.
  </FaqItem>
  <FaqItem question="How do I change what a cell of the Data Grid displays?" indicatorPosition="end">
    Set the data type of a column of the Angular Data Grid to format numbers, dates, currencies and Booleans, and its pipe arguments to change the format, as [Custom Display Format](#custom-display-format) shows. To render your own content, give the column a [cell template](#cell-template).
  </FaqItem>
  <FaqItem question="How do I make the Data Grid editable?" indicatorPosition="end">
    Set a column of the Angular Data Grid as editable to edit single cells, or turn on row editing to edit a row and confirm it as a whole. Editing rows through the API or with row editing requires a primary key. To replace the default editor of a column, give it a [cell editing template](#cell-editing-template).
  </FaqItem>
  <FaqItem question="Does the Data Grid handle large data sets?" indicatorPosition="end">
    The Angular Data Grid virtualizes rows and columns: it renders only the cells in the viewport and reuses them while users scroll. For data that does not fit in memory, load it on demand as the [Remote Data Operations](/grid/remote-data-operations) topic shows.
  </FaqItem>
</Faq>
