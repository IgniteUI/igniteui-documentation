# Data Grid

The Ignite UI for Angular Data Grid (<ApiLink type="Grid" />) displays and edits flat tabular data: an array of records, one row per record. It is the grid to start with for lists of orders, customers, transactions and any other data that has one row per record. You enable features such as sorting, filtering, grouping, editing, paging and Excel export per column or per grid, and the Data Grid virtualizes its rows and columns by default.

For hierarchical data, use the [Tree Grid](/treegrid/tree-grid) or the [Hierarchical Grid](/hierarchicalgrid/hierarchical-grid), which offer most of the same features. To summarize data in a cross-tabular layout, use the [Pivot Grid](/pivotgrid/pivot-grid).

The selector of the Angular Data Grid is `igx-grid`, and each `igx-column` in it defines one column.

## Getting Started

To use the Angular Data Grid, follow the [Ignite UI for Angular Getting Started](/general/getting-started) topic for the basic project setup, then import the Data Grid into your component.

If your project doesn't use Ignite UI for Angular yet, run `ng add igniteui-angular`. Then import the [`IGX_GRID_DIRECTIVES`](https://github.com/IgniteUI/igniteui-angular/blob/master/projects/igniteui-angular/grids/grid/src/grid.module.ts) token and add it to the `imports` of your component. The token holds the <ApiLink type="Grid" />, the column, toolbar and paginator components, and the cell, header and cell editor template directives. To import only the grid itself, add the `IgxGridComponent` standalone component instead:

```typescript
// home.component.ts

import { Component } from '@angular/core';
import { IGX_GRID_DIRECTIVES } from 'igniteui-angular/grids/grid';
// import { IGX_GRID_DIRECTIVES } from '@infragistics/igniteui-angular/grids/grid'; for licensed package

@Component({
    selector: 'app-home',
    template: `<igx-grid [data]="localData" [autoGenerate]="true"></igx-grid>`,
    styleUrls: ['home.component.scss'],
    imports: [IGX_GRID_DIRECTIVES]
    /* or imports: [IgxGridComponent] */
})
export class HomeComponent {
    public localData = [
        { ProductName: 'Chai', UnitPrice: 18, Discontinued: false },
        { ProductName: 'Chang', UnitPrice: 19, Discontinued: true }
    ];
}
```

To change the look of the Data Grid, see [Styling](#styling).

## Usage

Use the Angular Data Grid to display, edit and analyze records that share the same fields.

### Basic Configuration

Now that you have the Ignite UI for Angular Grid module or directives imported, you can start using the `igx-grid` component.

```html
<igx-grid #grid1 id="grid1" [data]="localData" [autoGenerate]="true"></igx-grid>
```

The **data** property binds the grid, in this case to local array of objects.

The <ApiLink type="Grid" member="autoGenerate" /> property tells the `igx-grid` to auto generate the grid's <ApiLink type="Column" /> based on the data source fields. It will also try to deduce the appropriate data type for the column if possible. Developers can also explicitly [define the columns](#column-configuration) and the mapping to the data source fields.

The grid reads the fields and their values from the first record. A number, a Boolean, a `Date` object and a string that ends with an image file extension, such as `.png`, give number, boolean, date and image columns; any other value gives a string column.

Ignite UI for Angular includes a powerful bootstrap grid like flex-based layout system. Any modern application today is expected to follow a responsive web design approach, meaning it can gracefully adjust layout of HTML elements based on the device size, or from simply resizing the browser. An Angular bootstrap grid layout was the most used approach in the past, but a flex-based layout system like CSS grid has become more popular, as it works in any browser. The Ignite UI for Angular Layout Directive allows vertical and horizontal flow, including content / text wrapping, justification, and alignment. The Ignite UI for Angular grid supports a responsive layout using CSS, giving you the ultimate flexibility in how the grid behaves on resize.

Each operation for Angular grid editing includes Batch operations, meaning the API gives you the option to group edits into a single server call, or you can perform grid edit / update operations as they occur with grid interactions. Along with a great developer experience as an editable Angular grid with CRUD operations, the Angular grid includes Excel-like keyboard navigation. Common default grid navigation is included, plus the option to override any navigation option to meet the needs of your customers. An editable grid in Angular with a great navigation scheme is critical to any modern line of business application, with the Ignite UI grid we make it easy.

Following this topic you will learn more about [cell template](#cell-template) and [cell editing template](#cell-editing-template) and editing.

### Column Configuration

<ApiLink type="Column" /> is used to define the grid's <ApiLink type="Grid" member="columns" /> collection and to enable features per column like **sorting** and **filtering**. Cell, header, and footer templates are also available.

#### Defining Columns

Let's turn the <ApiLink type="Grid" member="autoGenerate" /> property off and define the columns collection in the markup:

```html
<igx-grid #grid1 [data]="data | async" [autoGenerate]="false" (columnInit)="initColumns($event)"
    (selected)="selectCell($event)" [allowFiltering]="true">
    <igx-column field="Name" [sortable]="true" header=" "></igx-column>
    <igx-column field="AthleteNumber" [sortable]="true" header="Athlete number" [filterable]="false"></igx-column>
    <igx-column field="TrackProgress" header="Track progress" [filterable]="false">
        <ng-template igxCell let-value>
            <igx-linear-bar [striped]="false" [value]="value" [max]="100"></igx-linear-bar>
        </ng-template>
    </igx-column>
    <igx-paginator [perPage]="6">
    </igx-paginator>
</igx-grid>
```

Each of the columns of the grid can be templated separately. The column expects `ng-template` Angular grid module directives.

It also exposes the <ApiLink type="Column" member="additionalTemplateContext" /> input that can be used for custom properties and any type of data context that you want to pass to the column itself:

```html
<igx-column [additionalTemplateContext]="contextObject">
    <ng-template igxCell let-cell="cell" let-props="additionalTemplateContext">
        {{ props.firstProperty }}
    </ng-template>
</igx-column>
```

```ts
public contextObject = { firstProperty: 'testValue', secondProperty: 'testValue1'};
```

#### Header Template

`igxHeader` targets the column header providing as a context the column object itself.

```html
<igx-column field="Name">
    <ng-template igxHeader let-column>
        {{ column.field | uppercase }}
    </ng-template>
</igx-column>
```

When the header template is used along with grouping or moving, see [Why can't I click the elements in my column header template?](#why-cant-i-click-the-elements-in-my-column-header-template)

#### Cell Template

`igxCell` applies the provided template to all cells in the column. The context object provided in the template consists of the cell value provided implicitly (`$implicit`) and the cell object itself (`cell`). It can be used to define a template where the cells can grow according to their content, as in the below example.

```html
<igx-column field="Name">
    <ng-template igxCell let-value>
        {{ value | titlecase }}
    </ng-template>
</igx-column>
```

The `uppercase` and `titlecase` pipes come from `@angular/common`. Add `UpperCasePipe` and `TitleCasePipe` to the `imports` of your component.

In the snippet above we "take" a reference to the implicitly provided cell value. This is sufficient if you just want to present some data and maybe apply some custom styling or pipe transforms over the value of the cell. However even more useful is to take the <ApiLink kind="interface" type="CellType" /> instance itself as shown below:

```html
<igx-grid #grid [data]="data">
    <igx-column dataType="string" field="Name">
        <ng-template igxCell let-cell="cell">
            <!-- Implement row deleting inside the cell template itself -->
            <span tabindex="0" (keydown.delete)="grid.deleteRow(cell.row.key)">{{ cell.value | titlecase }}</span>
        </ng-template>
    </igx-column>
    <igx-column dataType="boolean" field="Subscription">
        <ng-template igxCell let-cell="cell">
            <!-- Bind the cell value through the ngModel directive and update the data source when the value is changed in the template -->
            <input type="checkbox" [ngModel]="cell.value" (ngModelChange)="cell.update($event)" />
        </ng-template>
    </igx-column>
</igx-grid>
```

When changing data through the **cell template** using `ngModel`, you need to call the appropriate API methods to make sure the value is correctly updated in the Angular grid's underlying data collection. In the snippet above, the `ngModelChange` call passes through the grid's [editing API](/grid/cell-editing#editing-through-api) and goes through the grid's editing pipeline, properly triggering [transactions](/grid/batch-editing) (if applicable) and handling of [summaries](/grid/summaries), [selection](/grid/selection), etc. However, this `ngModelChange` will fire every time the value of the cell changes, not just when the user is done editing, resulting in a lot more API calls.

<DocsAside type="info">
The grid exposes a default handling for number, string, date and boolean column types. For example, the column will display `check` or `close` icon, instead of true/false by default, for boolean column type.
</DocsAside>

If the data in a cell is bound with `[(ngModel)]` and the value change is not handled, the new value will **not** be properly updated in the Angular grid's underlying data source. When dealing with cell editing with a custom template, it is strongly advised to use the cell's **cell editing template**.

When properly implemented, the cell editing template also ensures that the cell's `editValue` will correctly pass through the grid [editing event cycle](/grid/editing#event-arguments-and-sequence).

#### Cell Editing Template

The column also accepts one last template that will be used when a cell is in edit mode. As with the other column templates, the provided context object is again the cell value and the cell object itself. Of course in order to make the edit-mode template accessible to end users, you need to set the <ApiLink type="Column" member="editable" /> property of the <ApiLink type="Column" /> to `true`.

```html
<igx-column dataType="number" editable="true" field="Price">
    <ng-template igxCellEditor let-cell="cell">
        <label for="price">
            Enter the new price tag
        </label>
        <input name="price" type="number" [(ngModel)]="cell.editValue" />
    </ng-template>
</igx-column>
```

Make sure to check the API for the <ApiLink kind="interface" type="CellType" /> in order to get accustomed with the provided properties you can use in your templates.

#### Column Template API

Each of the column templates can be changed programmatically at any point through the <ApiLink type="Column" /> object itself. For example in the code below, we have declared two templates for our user data. In our TypeScript code we'll get references to the templates themselves and then based on some condition we will render the appropriate template for the column in our application.

```html
<igx-grid>
    <!-- Column declarations -->
</igx-grid>

<ng-template #normalView let-value>
    <div class="user-details">{{ value }}</div>
    <user-details-component></user-details-component>
</ng-template>

<ng-template #smallView let-value>
    <div class="user-details-small">{{ value }}</div>
</ng-template>
```

```typescript
@ViewChild("normalView", { read: TemplateRef })
public normalView: TemplateRef<any>;

@ViewChild("smallView", { read: TemplateRef })
public smallView: TemplateRef<any>;

// ...

const column = this.grid.getColumnByName("User");
// Return the appropriate template based on some condition.
// For example saved user settings, viewport size, etc.
column.bodyTemplate = this.smallView;
```

Column properties can also be set in code in the <ApiLink type="Grid" member="columnInit" /> event which is emitted when the columns are initialized in the grid.

```typescript
public initColumns(column: IgxColumnComponent) {
    if (column.field === 'ProductName') {
        column.sortable = true;
        column.editable = true;
    }
}
```

The code above will make the **ProductName** column sortable and editable and will instantiate the corresponding features UI (like inputs for editing, etc.).

#### Custom Display Format

All values for a date, numeric, currency and percent column are transformed through the Angular [`DatePipe`](https://angular.dev/api/common/DatePipe), [`DecimalPipe`](https://angular.dev/api/common/DecimalPipe), [`CurrencyPipe`](https://angular.dev/api/common/CurrencyPipe) and [`PercentPipe`](https://angular.dev/api/common/PercentPipe) accordingly. This does not modify the original value, just the value that is displayed in the column. So please keep in mind that all data operations and manipulations are done based on the values in your data source. By default, values will be displayed according to the grid <ApiLink type="Grid" member="locale" /> (if not specified, it fallbacks to the application locale, which defaults to `'en-US'`).

See [Setting up the locale of your app](https://angular.dev/guide/i18n/locale-id) for more details.

Also, there are optional parameters for formatting:

- `format` - determines what date/time parts are displayed, defaults to `'mediumDate'`, equivalent to `'MMM d, y'`
- `timezone` - the timezone offset for dates. By default uses the end-user's local system timezone
- `digitsInfo` - decimal representation objects. Default to `'1.0-3'`

To allow customizing the display format by these parameters, the <ApiLink type="Column" member="pipeArgs" /> input is exposed. A column will respect only the corresponding properties for its data type, if `pipeArgs` is set. Example:

```typescript
const pipeArgs: IColumnPipeArgs = {
     format: 'longDate',
     timezone: 'UTC',
     digitsInfo: '1.1-2'
}
```

```html
<igx-column field="OrderDate" dataType="date" [pipeArgs]="pipeArgs"></igx-column>
<igx-column field="UnitPrice" dataType="number" [pipeArgs]="pipeArgs"></igx-column>
```

The `OrderDate` column will respect only the `format` and `timezone` properties, while the `UnitPrice` will only respect the `digitsInfo`. For further details, please check the official Angular documentation at [Localizing your app](https://angular.dev/guide/i18n).

All available column data types could be found in the official [Column types topic](/grid/column-types#default-template).

### Data Binding

The Angular Data Grid binds to an array of objects.

#### Data Structure

The <ApiLink type="Grid" /> handles **flat data** and nested **POJOs (Plain old Java objects)**. The data structure specific for rendering is in the form:

```typescript
const OBJECT_ARRAY = [{
        ObjectKey1: value1,
        ObjectKey2: value2,
        // ...
        ObjectKeyN: valueN
    },
    // ...
];

const POJO = [{
        ObjectKey1: value1,
        ObjectKey2: value2,
        // ...
        ObjectKeyN: {
          ObjectKeyN1: value1,
          ObjectKeyN2: value2,
          // ...
          ObjectKeyNM: valueNM,
        }
    },
    // ...
];
```

<DocsAside type="warning">
**The key values must not contain arrays**. To show an array value, give its column a cell template, as the [Complex Data Binding](#complex-data-binding) section shows.
If you use <ApiLink type="Grid" member="autoGenerate" /> columns **the data keys must be identical.**
</DocsAside>

#### Remote Data Binding

Before going any further with the grid we want to change the Angular grid to bind to remote data service, which is the common scenario in large-scale applications. A good practice is to separate all data fetching related logic in a separate data service, so we are going to create a service which will handle the fetching of data from the server.

Let's implement our service in a separate file

```typescript
// northwind.service.ts

import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable, of } from 'rxjs';
import { catchError, map } from 'rxjs/operators';
```

We're importing the `Injectable` decorator which is an [essential ingredient](https://angular.dev/guide/di) in every Angular service definition. The `HttpClient` will provide us with the functionality to communicate with backend services. It returns an `Observable` of some result to which we will subscribe in our grid component.

Since we will receive a JSON response containing an array of records, we may as well help ourselves by specifying what kind of data we're expecting to be returned in the observable by defining an interface with the correct shape. Type checking is always recommended and can save you some headaches down the road.

```typescript
// northwind.service.ts

export interface NorthwindRecord {
    ProductID: number;
    ProductName: string;
    SupplierID: number;
    CategoryID: number;
    QuantityPerUnit: string;
    UnitPrice: number;
    UnitsInStock: number;
    UnitsOnOrder: number;
    ReorderLevel: number;
    Discontinued: boolean;
    CategoryName: string;
}
```

The service itself is pretty simple consisting of one method: `fetchData` that will return an `Observable<NorthwindRecord[]>`. In cases when the request fails for any reason (server unavailable, network error, etc), the `HttpClient` will return an error. We'll leverage the `catchError` operator which intercepts an _Observable_ that failed and passes the error to an error handler. Our error handler will log the error and return a safe value.

```typescript
// northwind.service.ts

@Injectable()
export class NorthwindService {
    private url = 'https://services.odata.org/V4/Northwind/Northwind.svc/Alphabetical_list_of_products';

    constructor(private http: HttpClient) {}

    public fetchData(): Observable<NorthwindRecord[]> {
        return this.http
            .get<{ value: NorthwindRecord[] }>(this.url)
            .pipe(
                map(response => response.value),
                catchError(
                    this.errorHandler('Error loading northwind data', [])
                )
            );
    }

    private errorHandler<T>(message: string, result: T) {
        return (error: any): Observable<any> => {
            console.error(`${message}: ${error.message}`);
            return of(result as T);
        };
    }
}
```

Make sure to provide the `HttpClient` with `provideHttpClient()` and to register our service as a provider in the application configuration.

```typescript
// app.config.ts

import { ApplicationConfig } from '@angular/core';
import { provideHttpClient } from '@angular/common/http';
import { NorthwindService } from './northwind.service';

export const appConfig: ApplicationConfig = {
    providers: [
        provideHttpClient(),
        NorthwindService
    ]
};
```

After implementing the service we will inject it in our component's constructor and use it to retrieve the data. The `ngOnInit` lifecycle hook is a good place to dispatch the initial request.

**Note**: In the code below, you may wonder why are we setting the _records_ property to an empty array before subscribing to the service. The Http request is asynchronous, and until it completes, the _records_ property would otherwise be _undefined_. You should either initialize it with a default value or use a `BehaviorSubject`.

```typescript
// my.component.ts

@Component({
    // ...
})
export class MyComponent implements OnInit {

    public records: NorthwindRecord[] = [];

    constructor(private northwindService: NorthwindService) {}

    ngOnInit() {
        this.northwindService.fetchData().subscribe((records) => this.records = records);
    }
}
```

and in the template of the component:

```html
<igx-grid [data]="records">
    <igx-column field="ProductID"></igx-column>
    <!-- rest of the column definitions -->
</igx-grid>
```

**Note**: The grid <ApiLink type="Grid" member="autoGenerate" /> property inspects the data in order to generate the appropriate columns. When the grid is bound to a remote service, the data is usually not available until the service responds, so the grid generates the columns when the data arrives.

For real-time updates, see [Live Data](/grid/live-data). For sorting, filtering and paging on the server, see [Remote Data Operations](/grid/remote-data-operations).

#### Complex Data Binding

The <ApiLink type="Grid" /> supports binding to complex objects (including nesting deeper than one level) through a "path" of properties in the data record.

Take a look at the following data model:

```typescript
interface AminoAcid {
    name: string;
    abbreviation: {
        short: string;
        long: string;
    }
    weight: {
        molecular: number;
        residue: number;
    },
    formula: {
        molecular: string;
        residue: string;
    }
    // ...
}
```

For example, in order to display the weights of a given amino acid in the grid the following snippet will suffice

```html
<igx-column field="weight.molecular"></igx-column>
<igx-column field="weight.residue"></igx-column>
```

Refer to the sample below for additional information. This type of binding supports all the default functionality that you would expect from the grid. That is all sorting and filtering operations work out of the box without any additional configuration. Same goes for grouping and editing operations with or without transactions as well as the ability to template the cells of the bound column.

<DocsAside type="warning">
The grids **do not** support this kind of binding for `primary key`, `foreign key` and `child key` properties where applicable.
</DocsAside>

<Sample src="/grid/grid-nested-data-binding-2" height={460} alt="Angular Data Grid with columns bound to nested properties of amino acid records" />

An alternative way to bind complex data, or to visualize composite data (from more than one column) in the **IgxGrid** is to use a custom body template for the column. Generally, one can:

- use the `value` of the cell, that contains the nested data
- use the `cell` object in the template, from which to access the `row.data`, therefore retrieve any value from it, i.e `cell.row.data[field]` and `cell.row.data[field][nestedField]`

and interpolate those in the template.

```html
<igx-column field="abbreviation.long" header="Long">
    <ng-template igxCell let-cell="cell">
        <div>
            <div>
                {{ cell.value }}
                {{ cell.row.data['name'] }}
                {{ cell.row.data['weight']['molecular'] }}
            </div>
```

### Performance (Experimental)

The `IgxGridComponent`'s design allows it to take advantage of the Event Coalescing feature that has Angular introduced. This feature allows for improved performance with roughly around **`20%`** in terms of interactions and responsiveness. This feature can be enabled on application level by setting the `eventCoalescing` and `runCoalescing` options of `provideZoneChangeDetection` to `true` in the providers of the application:

```typescript
// main.ts

bootstrapApplication(AppComponent, {
    providers: [provideZoneChangeDetection({ eventCoalescing: true, runCoalescing: true })]
}).catch(err => console.error(err));
```

Event coalescing is an option of the zone.js-based change detection, while Angular 21 and later use zoneless change detection by default. In an NgModule-based application, pass the same provider in the `applicationProviders` option of `bootstrapModule()`.

## Styling

The Angular Data Grid takes its colors from the theme of the application.

### Sass Theming

The easiest and recommended way to style the `igxGrid` is to use the <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} /> and provide just the three main colors: `background`, `foreground`, and `accent-color`.

These are the core theme properties. When you set them, all grid parts and internal components derive their colors from those values, resulting in a consistent appearance throughout the entire grid. Nested components such as buttons, icons, inputs, dropdowns, checkboxes, scrollbars, chips, and other helper components also derive their styling tokens from the main <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} /> for a unified look.

```scss
@use "igniteui-angular/theming" as *;

$custom-grid: grid-theme(
  $background: #292826,
  $foreground: #eeece1,
  $accent-color: #ffcd0f
);

igx-grid {
  @include tokens($custom-grid);
}
```

There are also additional parameters in the <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} />, such as `$header-background` and `$row-hover-background`, that you can use if you want more specific customizations.

#### Additional Themes

If you want more control over nested components, the grid also provides additional themes. Use them when you want a specific nested component to have a different style from the rest of the grid theme.

Available standalone themes include:

- <ApiLink kind="sass" module="themes" type="function-excel-filtering-theme" label="excel-filtering-theme" code={true} /> for the Excel-style filtering component
- <ApiLink kind="sass" module="themes" type="function-grid-toolbar-theme" label="grid-toolbar-theme" code={true} /> for the grid toolbar component
- <ApiLink kind="sass" module="themes" type="function-paginator-theme" label="paginator-theme" code={true} /> for the paginator component
- <ApiLink kind="sass" module="themes" type="function-column-actions-theme" label="column-actions-theme" code={true} /> for the column actions component
- <ApiLink kind="sass" module="themes" type="function-query-builder-theme" label="query-builder-theme" code={true} /> for the advanced filtering dialog

```scss
$excel-filtering-theme: excel-filtering-theme(
  $background: #3c6eda,
  $foreground: #f5f5f5,
  $accent-color: #8e11fb
);

$query-builder-theme: query-builder-theme(
  $background: #f59906,
  $foreground: #050505,
```

By providing only the three main colors, all parts of the component are styled consistently. These themes also expose additional parameters if you need more detailed customization.

If you want to target only smaller nested components within the grid, such as buttons, icons, inputs, or chips, you can apply their standalone themes directly. Make sure your selector scope is specific enough so the provided theme affects only the intended element. The [Dependencies](#dependencies) section lists the component themes that apply inside the grid.

## Accessibility

The Angular Data Grid can be operated with the keyboard and exposes its structure and state to assistive technology through ARIA roles and attributes.

### Keyboard Interaction

Grid's keyboard navigation provides a rich variety of keyboard interactions for the user. It enhances accessibility and allows intuitive navigation through any type of elements inside (cell, row, column header, toolbar, footer, etc.).

The header row and the body of the Angular Data Grid are separate tab stops, and inside each of them the arrow keys move the active cell. The following keys work while the header row or the body has the focus:

| Key | Action |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd> + <kbd>Tab</kbd> | Outside edit mode, the Data Grid doesn't handle these keys, so they move the focus to the next or the previous tab stop. While a cell or a row is in edit mode, they move to the next or the previous editable cell. |
| <kbd>Arrow Up</kbd> / <kbd>Arrow Down</kbd> | Move the active cell one row up or down. |
| <kbd>Arrow Left</kbd> / <kbd>Arrow Right</kbd> | Move the active cell, or the active column header, one column to the left or to the right. |
| <kbd>Home</kbd> / <kbd>End</kbd> | Move to the first or the last cell of the row. |
| <kbd>Ctrl</kbd> + <kbd>Home</kbd> / <kbd>Ctrl</kbd> + <kbd>End</kbd> | Move to the first cell of the first data row, or to the last cell of the last data row. |
| <kbd>Ctrl</kbd> + <kbd>Arrow Up</kbd> / <kbd>Ctrl</kbd> + <kbd>Arrow Down</kbd> | In the body, move to the first or the last data row in the column. On the header of a sortable column, sort the column in ascending or descending order, or clear the sorting when the column is already sorted in that order. |
| <kbd>Page Up</kbd> / <kbd>Page Down</kbd> | Scroll the body one page up or down. |
| <kbd>Enter</kbd> / <kbd>F2</kbd> | Enter edit mode in an editable cell. |
| <kbd>Esc</kbd> | Exit edit mode and discard the change. |
| <kbd>Space</kbd> | Select or deselect the row when row selection is on. |
| <kbd>Alt</kbd> + <kbd>Arrow Left</kbd> / <kbd>Alt</kbd> + <kbd>Arrow Up</kbd> | Collapse the group row. |
| <kbd>Alt</kbd> + <kbd>Arrow Right</kbd> / <kbd>Alt</kbd> + <kbd>Arrow Down</kbd> | Expand the group row. |

Check out these resources for more information:

- [Grid Keyboard Navigation](/grid/keyboard-navigation)
- [Tree Grid Keyboard Navigation](/treegrid/keyboard-navigation)
- [Hierarchical Grid Keyboard Navigation](/hierarchicalgrid/keyboard-navigation)
- [Blog post](https://www.infragistics.com/community/blogs/b/engineering/posts/grid-keyboard-navigation-accessibility) - Improving Usability, Accessibility and ARIA Compliance with Grid keyboard navigation

### Screen Readers / ARIA

The Angular Data Grid renders the following roles and attributes:

| Element | Role | Attributes |
| --- | --- | --- |
| `igx-grid` | `grid` | `aria-rowcount` and `aria-colcount` |
| `igx-grid-header-row` | `rowgroup` | `aria-activedescendant` that points to the active column header |
| `div.igx-grid__tr` in the header row | `row` | `aria-rowindex="1"` |
| `igx-grid-header` | `columnheader` | `aria-sort` (`ascending` or `descending`) when the column is sorted, `aria-selected`, `aria-colindex` and `aria-rowindex` |
| `div.igx-grid__tbody-content` | `rowgroup` | `aria-activedescendant` that points to the active cell |
| `igx-grid-row` | `row` | `aria-selected` and `aria-disabled` |
| `igx-grid-cell` | `gridcell` | `aria-rowindex`, `aria-colindex`, `aria-selected`, `aria-readonly` when the cell can't be edited, and `aria-invalid` and `aria-describedby` when the value fails validation |
| `igx-grid-groupby-row` | `row` | The expand indicator of the group row is a `gridcell` with `aria-expanded`. |
| `igx-grid-summary-row` | `row` | The summary cells have the `cell` role. |
| `igx-page-nav` in the paginator | `navigation` | The page buttons have accessible names, such as "Next page". |

The Angular Data Grid also behaves as follows for assistive technology:

- The focus stays on the header row or on the body while the active cell moves, and `aria-activedescendant` points to the active column header or cell.
- Only the rows and the columns in view are in the DOM. `aria-rowindex` and `aria-colindex` give each rendered cell its position in the data.

You supply the accessible name of the Data Grid, for example with `aria-label` on the grid element, and accessible names for icon-only content in your cell and header templates.

### Accessibility Compliance

The [Accessibility Compliance](/interactivity/accessibility-compliance) topic lists the standards that Ignite UI for Angular targets, WCAG 2.1 Level AA among them, and records what the Data Grid documentation covers. It is a support summary, not a formal conformance statement.

| Criterion | How the component complies |
| --- | --- |
| [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships) | The `grid`, `rowgroup`, `row`, `columnheader` and `gridcell` roles expose the structure, and `aria-rowindex` and `aria-colindex` give the position of each cell in the data. |
| [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) | The arrow keys, Home, End, Page Up and Page Down move through the cells, Enter and F2 start editing, Space selects rows, and Ctrl + Arrow Up and Ctrl + Arrow Down sort from a column header. |
| [2.1.2 No Keyboard Trap](https://www.w3.org/WAI/WCAG21/Understanding/no-keyboard-trap) | Outside edit mode, the Data Grid doesn't handle the Tab key, so Tab and Shift + Tab move the focus out of the header row and the body. |
| [2.4.3 Focus Order](https://www.w3.org/WAI/WCAG21/Understanding/focus-order) | The header row and the body are separate tab stops, in their visual order. |
| [2.4.7 Focus Visible](https://www.w3.org/WAI/WCAG21/Understanding/focus-visible) | The active cell and the active column header show a border in the `--cell-active-border-color` color. |
| [4.1.2 Name, Role, Value](https://www.w3.org/WAI/WCAG21/Understanding/name-role-value) | Cells expose the `gridcell` role and their selected and read-only states through `aria-selected` and `aria-readonly`. Column headers expose the sort direction through `aria-sort`, and group rows expose their expanded state through `aria-expanded`. |

Your responsibilities:

- Give the Data Grid an accessible name, for example with `aria-label` or `aria-labelledby` on the grid element. The Data Grid doesn't set one.
- Give icons and icon-only buttons that you place in cell and header templates an accessible name.
- Test the focusable elements that you place in cell templates with the keyboard. The Data Grid handles the arrow keys, Enter, F2, Esc and Space on the body, so these elements may need to handle the keys that they use.
- When you override the theme colors, keep a contrast ratio of at least 4.5:1 for the text of the headers and the cells, as [1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum) requires, and keep the border of the active cell visible. See [Styling](#styling).

## Troubleshooting

These questions cover common problems when you set up the Angular Data Grid.

### Why can't I click the elements in my column header template?

When column moving is on or the column is groupable, the header of the Angular Data Grid is draggable, so pressing the pointer on the header starts a drag instead of reaching the elements in your header template. Set `draggable="false"` on the element that the user clicks:

```html
<igx-column field="ProductName" header="Product name" [groupable]="true">
    <ng-template igxHeader let-column>
        <span>{{ column.header }}</span>
        <button type="button" draggable="false" (click)="column.hasSummary = !column.hasSummary">Summary</button>
    </ng-template>
</igx-column>
```

### How do I import the Data Grid in an NgModule-based application?

The `IGX_GRID_DIRECTIVES` token in [Getting Started](#getting-started) is for standalone components, which the Data Grid supports as of version `16.0.0`. An application that still declares its components in NgModules can import the `IgxGridModule` in its **app.module.ts** file instead, which the package keeps for backward compatibility:

```typescript
// app.module.ts

import { NgModule } from '@angular/core';
import { IgxGridModule } from 'igniteui-angular/grids/grid';
// import { IgxGridModule } from '@infragistics/igniteui-angular/grids/grid'; for licensed package

@NgModule({
    imports: [IgxGridModule]
})
export class AppModule {}
```

## Known Limitations

The Angular Data Grid has the following limitations.

| Limitation | Description |
| --- | --- |
| Column widths set in `percentage` and `px` | Currently we do not support mixing of column widths with `%` and `px`. |
| When trying to filter a column of type `number` | If a value different than `number` is entered into the filtering input, `NaN` is returned due to an incorrect cast. |
| Grid <ApiLink type="Grid" member="width" /> does not depend on the column widths | Unless the grid's <ApiLink type="Grid" member="width" /> is `null`, the <ApiLink type="Column" member="width" /> of all columns does not determine the spanning of the grid itself. It is determined by the parent container dimensions or the defined grid's <ApiLink type="Grid" member="width" />. |
| Grid nested in parent container | When grid's <ApiLink type="Grid" member="width" /> is not set and it is placed in a parent container with defined dimensions, the grid spans to this container. |
| Grid `OnPush` ChangeDetectionStrategy | The grid operates with `ChangeDetectionStrategy.OnPush` so whenever some customization appears make sure that the grid is notified about the changes that happens. |
| Columns have a minimum allowed column width. Depending on the value of the `--ig-size` CSS variable, they are as follows: <br/>"small": 56px <br/> "medium": 64px <br/> "large": 80px | Resizing or auto-sizing doesn't make a column narrower than the minimum allowed width for the corresponding `--ig-size`, unless the column has a minimum width of its own. A narrower width that you set yourself applies. |
| Row height is not affected by the height of cells that are not currently rendered in view. | Because of virtualization a column with a custom template (that changes the cell height) that is not in the view will not affect the row height. The row height will be affected only while the related column is scrolled in the view. |

<DocsAside type="info">
`igxGrid` uses `igxForOf` directive internally hence all `igxForOf` limitations are valid for `igxGrid`. For more details see [igxForOf Known Issues](/for-of#known-limitations) section.
</DocsAside>

## Related Components

The Angular Data Grid displays flat records. Use these components when the data needs a different structure:

- [Tree Grid](/treegrid/tree-grid) — hierarchical data in which parent and child records have the same fields.
- [Hierarchical Grid](/hierarchicalgrid/hierarchical-grid) — parent records that each own a child grid with its own columns.
- [Pivot Grid](/pivotgrid/pivot-grid) — data summarized by dimensions and measures in a cross-tabular layout.
- [Grid Lite](/grid-lite/overview) — a lightweight, high-performance data grid that is free to use and open source.
- [List](/list) — a short read-only list that needs no grid features.

## FAQ

These questions cover common Angular Data Grid data binding, editing and performance scenarios.

<Faq>
  <FaqItem question="How do I bind the Angular Data Grid to remote data?" indicatorPosition="end">
    Fetch the data and assign the array to the data property of the Angular Data Grid. The [Remote Data Binding](#remote-data-binding) section shows the complete example and links to the topics about live data and server-side data operations.
  </FaqItem>
  <FaqItem question="When should I use the Tree Grid or the Hierarchical Grid instead of the Data Grid?" indicatorPosition="end">
    Use the Tree Grid or the Hierarchical Grid for records that form a hierarchy; the [Related Components](#related-components) section explains when each one fits.
  </FaqItem>
  <FaqItem question="How do I change what a cell of the Data Grid displays?" indicatorPosition="end">
    Set the data type of a column of the Angular Data Grid to format numbers, dates, currencies and Booleans, and its pipe arguments to change the format, as [Custom Display Format](#custom-display-format) shows. To render your own content, give the column a [cell template](#cell-template).
  </FaqItem>
  <FaqItem question="How do I make the Data Grid editable?" indicatorPosition="end">
    Set a column of the Angular Data Grid as editable to edit single cells, or turn on row editing to edit a row and confirm it as a whole. Editing rows through the API or with row editing requires a primary key. To replace the default editor of a column, give it a [cell editing template](#cell-editing-template).
  </FaqItem>
  <FaqItem question="Does the Data Grid handle large data sets?" indicatorPosition="end">
    The Angular Data Grid virtualizes rows and columns: it renders only the cells in the viewport and reuses them while the reader scrolls. For data that does not fit in memory, load it on demand as the [Remote Data Operations](/grid/remote-data-operations) topic shows.
  </FaqItem>
</Faq>
