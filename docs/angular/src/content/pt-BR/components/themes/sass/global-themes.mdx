# Temas globais

<div class="highlight">
O tema global permite gerar rapidamente um tema que usa a sua paleta de cores, o seu esquema e as suas elevações personalizadas. A paleta de cores, o esquema e as elevações serão propagados para todos os componentes que não tenham temas personalizados criados para eles.
</div>
<igc-divider></igc-divider>

## Visão geral

Se você incluiu o arquivo _`igniteui-angular.css`_ no seu projeto de aplicação, agora é um bom momento para removê-lo. Vamos usar o nosso próprio arquivo _`my-app-theme.scss`_ para gerar um tema global para todos os componentes da aplicação.

Por padrão, o **Ignite UI for Angular** usa um tema global para aplicar estilo a todo o conjunto de componentes. Você pode, porém, criar temas com escopo nos componentes da sua aplicação, conforme o seu caso de uso. Por enquanto, vamos incluir todos os nossos temas em um único arquivo.
Para gerar um tema global, vamos incluir dois mixins, `core` e `theme`. Ambos os mixins aceitam alguns argumentos:

### Mixin core  

<hr/>

|                   Nome    |   Tipo  | Padrão |                                                       Descrição         |
| :-----------------------: | :-----: | :-----: | :-----------------------------------------------------------------------: |
|         `$print-layout`   | boolean |   true  |                             Inclui ou exclui os estilos para impressão.      |
| `$enhanced-accessibility` | boolean |  false  | Troca os pincéis de cor dos gráficos por uma paleta adequada para daltonismo.            |


### Mixins de tema

<hr/>

|        Nome   |   Tipo  |               Padrão    |                                                                                     Descrição              |
| :-----------: | :-----: | :----------------------: | :----------------------------------------------------------------------------------------------------------: |
|   `$palette`  |    map  |                `null`    |                                  O mapa de paleta a ser usado pelos temas padrão de todos os componentes.      |
|    `$schema`  |    map  | `$light-material-schema` |                                                  O esquema usado como base para a estilização dos componentes.        |
|   `$exclude`  |   list  |                  `()`    |                                       Uma lista de temas de componentes a serem excluídos do tema global.       |
| `$roundness`  | Número  |                `null`    | Define o fator de arredondamento global para todos os componentes (o valor pode ser qualquer fração decimal entre 0 e 1). |
| `$elevation`  | boolean |                `true`    |                                              Liga/desliga as elevações de todos os componentes do tema.        |
| `$elevations` |    Mapa  |  `$material-elevations`  |                                                 O mapa de elevação a ser usado por todos os temas de componentes.        |

Vamos criar um tema global personalizado que use as cores primária, secundária e de superfície da nossa empresa.

```scss
// Import the theming module
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';

$primary-color: #2ab759;
$secondary-color: #f96a88;
$surface-color: #fff;

$my-color-palette: palette(
    $primary: $primary-color,
    $secondary: $secondary-color,
    $surface: $surface-color
);

// IMPORTANT: Make sure you always include core first!
@include core();
@include typography();
// Pass the color palette we generated to the theme mixin.
@include theme($my-color-palette);
```

O mixin `core()` configura a infraestrutura compartilhada, como dimensionamento, espaçamento, acessibilidade aprimorada, estilos globais de diretivas e estilos de impressão. O mixin `theme()` emite a paleta, as elevações, os metadados do tema e as declarações de tokens dos componentes para o esquema selecionado. Os estilos estruturais dos componentes não são gerados por `theme()` a partir da versão 22.1.0; eles são entregues em cada pacote de componente e são eliminados automaticamente quando não utilizados.

<DocsAside type="info">
Incluir `core` antes de `theme` é essencial. Os mixins `core` fornecem todas as definições base necessárias para que o mixin `theme` funcione corretamente.
</DocsAside>

## Excluindo componentes

<hr/>

<DocsAside type="info">
Desde o Ignite UI for Angular 22.1.0, os estilos estruturais dos componentes são entregues dentro do pacote de cada componente e já são eliminados automaticamente com base no que a sua aplicação importa — você não precisa de `$exclude` para manter o CSS de componentes não usados fora do seu build. A lista `$exclude` do mixin `theme` agora controla apenas os **tokens** de design compartilhados (propriedades personalizadas do CSS `--ig-*`) emitidos no seu stylesheet global, uma quantidade de CSS muito menor do que a dos estilos estruturais jamais foi.
</DocsAside>

O mixin `theme` permite fornecer uma lista de nomes de componentes a serem excluídos da saída de tokens do tema global. Por exemplo, se você quiser remover os tokens que geramos para `igx-avatar` e `igx-badge` porque sabe que a sua aplicação nunca os usará, pode fazê-lo passando a lista de componentes assim:

```scss
// ...
$unnecessary: (igx-avatar, igx-badge);

@include theme($my-color-palette, $exclude: $unnecessary);
```

Se você sabe que a sua aplicação não usará alguns componentes, pode adicioná-los a `$exclude` para omitir as declarações de tokens deles. Isso não controla o CSS estrutural; os pacotes de componentes não usados já são removidos pelo build da aplicação.

Você pode fazer o inverso e emitir tokens apenas para os componentes desejados, usando o método abaixo:

```scss
@use 'sass:map';

@function include($items, $register) {
    @return map.keys(map.remove($register, $items...));
}

$allowed: (igx-avatar, igx-badge);

@include theme(
    $exclude: include($allowed, $components)
);
```

## Resets de terceiros

O Ignite UI declara as suas camadas na ordem `ig.reset` → `ig.base` → a camada ativa do design system → `ig.derived`. Envolva os stylesheets de reset ou normalize de terceiros na camada `ig.reset`, de menor precedência:

```scss
@layer ig.reset {
  @import "minireset.css";
}
```

Os estilos de aplicação sem camada continuam tendo precedência sobre os estilos em camadas do Ignite UI.

## Temas claros e escuros

Também oferecemos versões _**clara**_ e _**escura**_ dos nossos quatro temas — Material, Fluent, Indigo e Bootstrap.

Para usar qualquer uma das versões, basta passá-la para o nosso mixin <ApiLink kind="sass" module="themes" type="mixin-theme" label="theme" />:

_**Clara**_

```scss
@include core();
@include typography(
    $font-family: $material-typeface,
    $type-scale: $material-type-scale
);
@include theme(
    $schema: $light-material-schema,
    $palette: $light-material-palette,
);
```

***Escura**_

```scss
@include core();
@include typography(
    $font-family: $material-typeface,
    $type-scale: $material-type-scale
);
@include theme(
    $schema: $dark-material-schema,
    $palette: $dark-material-palette,
);
```
