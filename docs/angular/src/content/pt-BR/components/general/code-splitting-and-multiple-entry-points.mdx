# Divisão de código e múltiplos pontos de entrada

A partir da versão 21.0.0, o Ignite UI for Angular oferece suporte a múltiplos pontos de entrada, permitindo melhor tree-shaking, divisão de código e carregamento preguiçoso (lazy loading) de componentes. Essa melhoria de arquitetura permite importar somente os componentes e utilitários de que você precisa, reduzindo significativamente o tamanho do bundle da sua aplicação.

## Visão geral

Antes, todos os componentes do Ignite UI for Angular eram exportados de um único ponto de entrada (`igniteui-angular`). Embora conveniente, essa abordagem agrupava todos os componentes, dificultando para as ferramentas de build eliminar com eficiência o código não utilizado.

Com a nova arquitetura de múltiplos pontos de entrada, cada componente ou grupo de componentes relacionados tem seu próprio ponto de entrada dedicado. Isso permite que os bundlers modernos:

- **Habilitem a divisão de código** - cada componente pode ser carregado de forma preguiçosa, separadamente, sob demanda
- **Reduzam o tamanho do bundle inicial** - importe apenas o que a sua aplicação realmente precisa no carregamento inicial
- **Melhorem o desempenho do build** - grafos de dependência menores levam a builds mais rápidos

## Benefícios

✅ **Divisão de código** - cada componente pode ser carregado de forma preguiçosa  
✅ **Bundles iniciais menores** - importe apenas o que você precisa  
✅ **Melhor desempenho** - tamanhos de bundle individuais reduzidos significam tempos de carregamento mais rápidos  
✅ **Arquitetura limpa** - sem dependências circulares  
✅ **Compatibilidade total com versões anteriores** - o ponto de entrada principal continua funcionando  
✅ **Importações granulares de grades** - carregue apenas o tipo específico de grade de que você precisa

## Estrutura dos pontos de entrada

### Pontos de entrada principais

- `igniteui-angular/core` - utilitários principais, serviços e tipos base (por exemplo, `IgxOverlayService`)
- `igniteui-angular/directives` - diretivas comuns

### Pontos de entrada das grades

Os componentes de grade são divididos em pontos de entrada granulares para uma divisão de código ideal:

- `igniteui-angular/grids/core` - infraestrutura compartilhada das grades (colunas, barra de ferramentas, filtragem, ordenação, pipes e utilitários)
- `igniteui-angular/grids/grid` - componente Data Grid (`IgxGridComponent`)
- `igniteui-angular/grids/tree-grid` - componente Tree Grid (`IgxTreeGridComponent`)
- `igniteui-angular/grids/hierarchical-grid` - componente Hierarchical Grid (`IgxHierarchicalGridComponent`, `IgxRowIslandComponent`)
- `igniteui-angular/grids/pivot-grid` - componente Pivot Grid (`IgxPivotGridComponent`, `IgxPivotDataSelectorComponent`)

## Migração

### Migração automática

A abordagem recomendada é migrar as suas importações automaticamente durante o processo de `ng update`. Ao atualizar para a versão 21.0.0, você será solicitado a migrar as importações:

```cmd
ng update igniteui-angular
```

Quando solicitado, escolha **"Yes"** para migrar as importações para os novos pontos de entrada, a fim de obter os melhores tamanhos de bundle.

Como alternativa, você pode executar a migração separadamente:

```cmd
ng update igniteui-angular --migrate-only --from=20.1.0 --to=21.0.0
```

### Migração manual

Se você preferir migrar manualmente ou precisar atualizar importações específicas, siga este padrão:

#### Antes (v20.x e anteriores)

```typescript
import { 
  IgxGridComponent,
  IgxTreeGridComponent,
  IgxInputDirective,
  IgxBottomNavComponent,
  Direction, 
  GridBaseAPIService,
  IgxOverlayService,
  IFilteringExpression
} from 'igniteui-angular';
```

#### Depois (v21.0.0)

```typescript
import { IgxOverlayService, IFilteringExpression } from 'igniteui-angular/core';
import { GridBaseAPIService } from 'igniteui-angular/grids/core';
import { IgxGridComponent } from 'igniteui-angular/grids/grid';
import { IgxTreeGridComponent } from 'igniteui-angular/grids/tree-grid';
import { IgxInputDirective } from 'igniteui-angular/input-group';
import { IgxBottomNavComponent } from 'igniteui-angular/bottom-nav';
import { CarouselAnimationDirection } from 'igniteui-angular/carousel';
```

### Renomeações de tipos

Para evitar conflitos de nomes com a nova arquitetura, alguns tipos foram renomeados:

- `Direction` → `CarouselAnimationDirection` (no ponto de entrada do carousel)

```typescript
// Before
import { Direction } from 'igniteui-angular';

// After
import { CarouselAnimationDirection } from 'igniteui-angular/carousel';
```

## Compatibilidade com versões anteriores

O ponto de entrada principal (`igniteui-angular`) mantém **compatibilidade total com versões anteriores**, reexportando todos os pontos de entrada granulares. Você pode continuar usando importações do ponto de entrada principal sem nenhuma alteração:

```typescript
// This still works and will continue to work
import { IgxGridComponent, IgxButtonDirective } from 'igniteui-angular';
```

No entanto, **recomendamos fortemente migrar para os novos pontos de entrada** para aproveitar o melhor tree-shaking e os bundles menores.

## Exemplos de uso

### Exemplo 1: uso simples de componente

Se você precisar apenas de um botão e de uma entrada, importe apenas esses pontos de entrada:

```typescript
import { Component } from '@angular/core';
import { IgxButtonDirective } from 'igniteui-angular/directives';
import { 
  IgxInputGroupComponent, 
  IgxInputDirective, 
  IgxLabelDirective 
} from 'igniteui-angular/input-group';

@Component({
  selector: 'app-form',
  standalone: true,
  imports: [
    IgxButtonDirective,
    IgxInputGroupComponent,
    IgxInputDirective,
    IgxLabelDirective
  ],
  template: `
    <igx-input-group>
      <label igxLabel>Name</label>
      <input igxInput type="text" />
    </igx-input-group>
    <button igxButton="contained">Submit</button>
  `
})
export class FormComponent {}
```

### Exemplo 2: grade com recursos específicos

Importe apenas o tipo de grade de que você precisa, junto com os utilitários principais da grade:

```typescript
import { Component } from '@angular/core';
import { IgxGridComponent } from 'igniteui-angular/grids/grid';
import { IgxGridToolbarComponent } from 'igniteui-angular/grids/core';

@Component({
  selector: 'app-data-grid',
  standalone: true,
  imports: [IgxGridComponent, IgxGridToolbarComponent],
  template: `
    <igx-grid [data]="data" [autoGenerate]="true">
      <igx-grid-toolbar></igx-grid-toolbar>
    </igx-grid>
  `
})
export class DataGridComponent {
  public data = [
    { id: 1, name: 'John' },
    { id: 2, name: 'Jane' }
  ];
}
```

### Exemplo 3: carregamento preguiçoso de componentes

Com os novos pontos de entrada, você pode carregar componentes de forma preguiçosa com facilidade:

```typescript
// app.routes.ts
import { Routes } from '@angular/router';

export const routes: Routes = [
  {
    path: 'grid',
    loadComponent: () => 
      import('./features/grid/grid.component')
        .then(m => m.GridComponent)
  },
  {
    path: 'tree-grid',
    loadComponent: () => 
      import('./features/tree-grid/tree-grid.component')
        .then(m => m.TreeGridComponent)
  }
];
```

```typescript
// features/grid/grid.component.ts
import { Component } from '@angular/core';
import { IgxGridComponent } from 'igniteui-angular/grids/grid';

@Component({
  selector: 'app-grid',
  standalone: true,
  imports: [IgxGridComponent],
  template: `<igx-grid [data]="data" [autoGenerate]="true"></igx-grid>`
})
export class GridComponent {
  public data = [];
}
```

## Resumo das opções de migração

Você tem três opções ao atualizar para a versão 21.0.0:

### Opção 1: migrar durante a atualização (recomendado)

```cmd
ng update igniteui-angular
```

Quando solicitado, escolha **"Yes"** para migrar as importações.

### Opção 2: continuar usando o ponto de entrada principal

```cmd
ng update igniteui-angular
```

Quando solicitado, escolha **"No"** para continuar usando o ponto de entrada principal. A biblioteca continua totalmente compatível com versões anteriores, mas você não terá os melhores tamanhos de bundle.

### Opção 3: migrar depois

Atualize sem migrar (escolha "No" quando for solicitado):

```cmd
ng update igniteui-angular
```

Migre manualmente depois:

```cmd
ng update igniteui-angular --migrate-only --from=20.1.0 --to=21.0.0
```

## Boas práticas

1. **Use pontos de entrada específicos** - importe do ponto de entrada mais específico possível (por exemplo, `igniteui-angular/grids/grid` em vez de `igniteui-angular`)
2. **Aproveite o carregamento preguiçoso** - combine os pontos de entrada com o carregamento preguiçoso do Angular para um desempenho ainda melhor
3. **Importe apenas o que você precisa** - não importe o ponto de entrada `core` inteiro se você precisar apenas de um serviço
4. **Verifique o analisador de bundle** - use ferramentas como [webpack-bundle-analyzer](https://www.npmjs.com/package/webpack-bundle-analyzer) para confirmar as melhorias no tamanho do seu bundle
5. **Atualize regularmente** - mantenha a versão do Ignite UI for Angular atualizada para se beneficiar das otimizações mais recentes
