# FAQ de licença e instalação

O Ignite UI for Angular é oferecido em um modelo de licença dupla, que permite tanto o uso comercial quanto o uso de código aberto permissivo, dependendo dos componentes, módulos, diretivas e serviços utilizados.

É fundamental entender qual licença se aplica a cada parte do pacote. O tópico [Código aberto vs Premium](/general/open-source-vs-premium) traz detalhes sobre qual tipo de licença se aplica a cada componente e, portanto, se você precisa comprar uma licença comercial com base nos componentes que usa nos seus projetos.

## Contratos de licença

Para os componentes sob licença comercial, é importante conhecer todos os [termos e condições legais](https://www.infragistics.com/legal/license/igultimate-la) que se aplicam à compra e ao uso deles.

<DocsAside type="info">
Atualizamos nossos termos de licença e nosso modelo de assinatura no quarto trimestre de 2025.
</DocsAside>

Se o seu período de avaliação terminou ou se a sua assinatura [expirou](http://www.infragistics.com/renewal), cada desenvolvedor da sua equipe que usa componentes sob licença comercial do Ignite UI precisará [comprar](https://www.infragistics.com/how-to-buy/product-pricing) uma assinatura. Isso permitirá que você use o nosso feed npm privado, hospedado em [https://packages.infragistics.com/npm/js-licensed/](https://packages.infragistics.com/npm/js-licensed/), para o desenvolvimento. Lá você encontra as versões mais recentes dos pacotes do Ignite UI for Angular. Se você tiver uma assinatura vigente, poderá usar esse feed privado e terá acesso à versão completa do Ignite UI for Angular.


A Infragistics oferece licenças gratuitas, não comerciais e não revendáveis (NFR) para:

- Se você participa de um programa para desenvolvedores, como o Microsoft MVP, o Microsoft Regional Director, o Google Developer Expert etc.  
- Se você é estudante de ensino fundamental, médio ou universitário, uma instituição de ensino ou um professor.  

Se você se qualifica para uma licença gratuita, não comercial ou NFR, ou se tem qualquer dúvida sobre licenciamento, por favor [entre em contato conosco](https://www.infragistics.com/about-us/contact-us).

## Pacotes npm do Ignite UI for Angular - usando o feed npm privado

O npm é o gerenciador de pacotes mais popular e também o padrão do ambiente de execução Node.js. Muito adotado, é uma das formas mais rápidas e simples de gerenciar os pacotes dos quais o seu projeto depende. Para mais informações sobre como o npm funciona, leia a [documentação oficial do npm](https://docs.npmjs.com/).

O Infragistics Ignite UI for Angular está disponível como pacote npm, e você pode adicioná-lo como dependência ao seu projeto em [`few easy steps using the Ignite UI CLI`](/general/cli/step-by-step-guide-using-cli) ou [usando o Ignite UI for Angular Schematics](/general/cli/step-by-step-guide-using-angular-schematics). Essa abordagem não exige configurar o npm. Se você pretende usar apenas componentes do Ignite UI for Angular sob licença MIT, não há mais nada a fazer. No entanto, se você usar componentes sob uma licença comercial, baixar o pacote pelo npm inicia o seu [período de avaliação](https://www.infragistics.com/products/ignite-ui-angular) do produto.

<DocsAside type="info">
O que significa começar a usar uma versão de avaliação? Significa que você vai usar uma versão do nosso produto com uma **marca d'água** na sua visualização web. Não significa que você vai usar o pacote licenciado por um período determinado antes de ele expirar, por exemplo, um mês.
</DocsAside>

O Infragistics Ignite UI Dock Manager Web Component está disponível como um pacote npm separado, e, ao instalá-lo, você começa a usar a [versão de avaliação do Ignite UI Dock Manager Web Component](https://www.infragistics.com/products/ignite-ui-angular) do produto.

> Mais informações sobre como começar a usar o pacote npm do Ignite UI for Angular podem ser encontradas [neste tópico](/general/getting-started#instalar-o-ignite-ui-for-angular). Informações adicionais sobre o Ignite UI Dock Manager Web Component podem ser encontradas na [documentação do Dock Manager](/dock-manager).

### Atualizando pacotes com o nosso Angular Schematics ou o Ignite UI CLI

Se o Ignite UI for Angular foi adicionado ao projeto com [`ng add`](/general/getting-started), ou se o projeto foi criado pela nossa [coleção de schematics](/general/cli/getting-started-with-angular-schematics) ou pelo [Ignite UI CLI](/general/cli/getting-started-with-cli), você pode usar o nosso `upgrade-packages` para atualizar automaticamente a sua aplicação para os pacotes licenciados. As dependências de pacote do seu projeto vão incluir `@igniteui/angular-schematics` ou `igniteui-cli`, e ambos oferecem suporte ao comando de atualização.

<DocsAside type="info">
Como o processo muda os pacotes, recomendamos que você atualize o projeto primeiro, antes de trocar. Assim, você evita pegar uma versão mais alta do Ignite UI Angular e perder possíveis migrações de atualização. Siga o nosso [Guia de atualização](/general/update-guide).
</DocsAside>

Dependendo da configuração do seu projeto, execute o seguinte schematic no seu projeto:

```bash
ng g @igniteui/angular-schematics:upgrade-packages
```

ou use `igniteui-cli`:

```bash
ig upgrade-packages
```

O schematic ou o comando vai cuidar de trocar as dependências de pacote do projeto e atualizar as referências no código-fonte.
Você será solicitado a fazer login no nosso registro npm, caso ainda não esteja configurado.

<DocsAside type="info">
Se o seu projeto estiver usando [`yarn`](https://yarnpkg.com/), certifique-se de executar `upgrade-packages` com a flag `--skip-install`. Depois, execute `yarn install` para atualizar corretamente o seu `yarn.lock`, já que o comando de atualização atualmente usa `npm` para a instalação.
</DocsAside>

### Como configurar o seu ambiente para usar o feed npm privado (guia passo a passo)

#### Primeiro, você precisa configurar o registro privado e associar esse registro ao escopo da Infragistics

Isso permitirá que você use, sem problemas, uma combinação de pacotes do registro npm público e do registro privado da Infragistics.

<DocsAside type="info">
Se a sua conta não for licenciada (se você ainda estiver usando uma conta de avaliação), o feed privado de pacotes não ficará acessível para você, por exemplo, retornará uma mensagem de erro 404 ou 403. **Somente contas licenciadas podem acessar o feed privado packages.infragistics.**
</DocsAside>

### Agora, para fazer login no nosso feed privado usando o npm

#### npm versão 9+

O nosso feed privado atualmente não oferece suporte aos comandos `login/adduser` com o npm v9; por isso, recomendamos os seguintes passos para adicionar os campos de autenticação necessários à configuração:

```cmd
npm config set @infragistics:registry https://packages.infragistics.com/npm/js-licensed/
npm config set //packages.infragistics.com/npm/js-licensed/:username=YOUR_USERNAME
npm config set //packages.infragistics.com/npm/js-licensed/:email=YOUR_IG_EMAIL
npm config set //packages.infragistics.com/npm/js-licensed/:_auth=YOUR_IG_AUTH_TOKEN
```

Você pode gerar um [Access Token](#uso-do-access-token) pelo seu perfil na Infragistics.

Esta abordagem é aplicável a todas as versões anteriores de `npm`.

#### npm até a versão v8

Execute o comando `adduser` e informe uma conta de usuário e uma senha:

```cmd
npm adduser --registry=https://packages.infragistics.com/npm/js-licensed/ --scope=@infragistics
```

Você será solicitado a informar o nome de usuário e a senha que usa para entrar na sua conta da Infragistics. Você também deve informar o e-mail cadastrado no seu perfil da Infragistics.

<DocsAside type="info">
`npm` não permite o uso do símbolo `"@"` dentro do seu nome de usuário, pois ele é considerado "não seguro para a rede". Como o seu nome de usuário é, na verdade, o e-mail que você usa na conta da Infragistics, ele sempre contém o símbolo `"@"`. Por isso, você precisa contornar essa limitação substituindo o símbolo `"@"` por `"!!"` (dois pontos de exclamação). Por exemplo, se o seu nome de usuário for `"username@example.com"`, quando for solicitado o nome de usuário, você deve informar: `"username!!example.com"`.
</DocsAside>

<DocsAside type="info">
**Comportamento do shell no macOS**: se você usa macOS e define o token `:_auth` manualmente com `npm config set`, certifique-se de **envolver o token entre aspas duplas**, assim:

```bash
npm config set //packages.infragistics.com/npm/js-licensed/:_auth="YOUR_IG_AUTH_TOKEN"
```

Isso é necessário por causa das diferenças de interpretação do shell no macOS, que podem causar problemas de autenticação se caracteres especiais do token não forem devidamente entre aspas. Esse problema normalmente não ocorre no Windows.
</DocsAside>

#### Depois disso, você estará conectado e poderá instalar as versões mais recentes dos pacotes do Ignite UI no seu projeto

```cmd
npm uninstall igniteui-angular
npm install @infragistics/igniteui-angular

npm uninstall igniteui-dockmanager
npm install @infragistics/igniteui-dockmanager
```

Lembre-se de que definimos o pacote Ignite UI for Angular com escopo; por isso, não são necessárias alterações no registro se você quiser instalar pacotes do nosso feed privado e do npmjs.org ao mesmo tempo.

#### Algumas alterações adicionais podem ser necessárias no código-fonte do seu projeto

Se você estiver atualizando de um pacote de avaliação para um pacote licenciado e não estiver usando as migrações automatizadas do CLI:

- Adicione um mapeamento de **paths** no **tsconfig.json** do projeto.

```json
{
  /* ... */
  "compilerOptions": {
    "baseUrl": "./",
    "outDir": "./dist/out-tsc",
    /* ... */
    "paths": {
      "igniteui-dockmanager": ["./node_modules/@infragistics/igniteui-dockmanager"],
      "igniteui-dockmanager/*": ["./node_modules/@infragistics/igniteui-dockmanager/*"],
    }
  }
}
```

- Adicione um mapeamento de `stylePreprocessorOptions` no `angular.json` do seu projeto

```json
{
  "projects": {
    ..
    "prefix": "app",
      "architect": {
        "build": {
          "builder": "@angular-devkit/build-angular:browser",
          "options": {
            ...
            "aot": true,
            "stylePreprocessorOptions": {
                "includePaths": [
                    "node_modules/@infragistics"
                ]
            }
            ...
},
```

- Remova o sinal `~` das importações Sass do seu projeto para a origem `igniteui-angular/lib`:

```scss
@use "~igniteui-angular/lib/core/styles/themes/index" as *;

// Should be changed to
@use "igniteui-angular/lib/core/styles/themes/index" as *;
```

Se você já adotou o npm e tem uma licença do Ignite UI for Angular, configure o feed privado da Infragistics para aumentar a sua produtividade e aproveitar todo o potencial do Ignite UI for Angular.


## Uso do access token

Você também pode se autenticar no nosso feed npm privado usando um access token, que pode ser obtido pela sua [conta de usuário do infragistics.com](https://account.infragistics.com/package-feeds). A autenticação por access token é a alternativa preferida quando você quer integrar um processo de CI em um repositório publicamente acessível que usa os pacotes licenciados do Ignite UI for Angular.

As informações a seguir mostram como configurar a autenticação no nosso registro npm privado usando um access token na configuração local, nos procedimentos de build do Azure Pipelines e no processo de build do Travis CI:

- Gere um token em https://account.infragistics.com/package-feeds

<Image src={generateToken} alt="Novo token gerado" class="responsive-img" style="-webkit-box-shadow: 8px 9px 9px 5px #ccc; -moz-box-shadow: 8px 9px 9px 5px #ccc; box-shadow: 8px 9px 9px 5px #ccc; width: calc(100% - 250px)" />

<DocsAside type="info">
Cada token é codificado em Base64.
</DocsAside>

- Adicione o seguinte ao seu arquivo [.npmrc](https://docs.npmjs.com/configuring-npm/npmrc.html)

```cmd
@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/
//packages.infragistics.com/npm/js-licensed/:_auth=YOUR_ACCESS_TOKEN
//packages.infragistics.com/npm/js-licensed/:username=YOUR_USERNAME
```

### Configuração do Azure Pipelines

Atualize `azure-pipelines.yml` com as seguintes etapas:

```cmd
steps:

- script: npm config set @infragistics:registry $(npmRegistry)
  displayName: 'Npm add registry'
- script: npm config set $(igScope):_auth=$(token)
  displayName: 'Npm config auth'
```

Agora, adicione variáveis para o _registro npm_, o _escopo_ e o _token_. Há duas formas de fazer isso:

#### Defina um Variable Group na página Library, em Pipelines

### Configuração do Travis CI

Siga uma abordagem semelhante aqui. A única diferença é que a configuração é definida na etapa `before_install`:

```cmd
before_install:
- echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- echo "//packages.infragistics.com/npm/js-licensed/:_auth=$TOKEN" >> ~/.npmrc
```

A melhor forma de definir uma variável de ambiente depende do tipo de informação que ela vai conter. Por isso, [você tem duas opções](https://docs.travis-ci.com/user/environment-variables/):

- criptografá-la e adicioná-la [ao seu .travis.yml](https://docs.travis-ci.com/user/environment-variables/#defining-encrypted-variables-in-travisyml)
- adicioná-la às [configurações do repositório](https://docs.travis-ci.com/user/environment-variables/#defining-variables-in-repository-settings)

### Configuração do GitHub Actions

Adicione os seguintes scripts antes da etapa `npm install` (ou `npm ci`) na sua [configuração do fluxo de CI](https://help.github.com/en/actions/language-and-framework-guides/using-nodejs-with-github-actions):

```cmd
- run: echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- run: echo "//packages.infragistics.com/npm/js-licensed/:_auth=${{ secrets.NPM_TOKEN }}" >> ~/.npmrc
```

Defina [_secrets_ (variáveis de ambiente criptografadas)](https://help.github.com/en/actions/configuring-and-managing-workflows/creating-and-storing-encrypted-secrets) e use-os no fluxo do GitHub Actions para informações sensíveis, como o access token.
