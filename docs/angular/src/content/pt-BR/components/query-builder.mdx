# Visão geral do componente Angular Query Builder

O Angular Query Builder faz parte dos nossos [componentes Angular](https://www.infragistics.com/products/ignite-ui-angular) e oferece uma UI rica, que permite aos desenvolvedores criar consultas complexas de filtragem de dados para um conjunto de dados específico. Com este componente, eles podem criar uma árvore de expressões e definir condições E/OU entre elas, com editores e listas de condições determinados pelo tipo de dado de cada campo. A árvore de expressões pode então ser facilmente transformada em uma consulta no formato que o backend oferece suporte.

<div class="highlight">

O componente <ApiLink type="QueryBuilder" /> oferece uma forma de criar consultas complexas pela UI. Ao especificar operadores E/OU, condições e valores, o usuário cria uma árvore de expressões que descreve a consulta.

</div>

## Primeiros passos com o Ignite UI for Angular Query Builder

Para começar com o componente Ignite UI for Angular Query Builder, primeiro é preciso instalar o Ignite UI for Angular. Em um aplicativo Angular existente, digite o seguinte comando:

```cmd
ng add igniteui-angular
```

Para uma introdução completa ao Ignite UI for Angular, leia o tópico [_primeiros passos_](./general/getting-started.mdx).

O próximo passo é importar o `IgxQueryBuilderModule` no arquivo **app.module.ts**.

```typescript
// app.module.ts

import { IgxQueryBuilderModule } from 'igniteui-angular/query-builder';
// import { IgxQueryBuilderModule } from '@infragistics/igniteui-angular'; for licensed package

@NgModule({
    ...
    imports: [..., IgxQueryBuilderModule],
    ...
})
export class AppModule {}
```

Alternativamente, a partir de `16.0.0` você pode importar o `IgxQueryBuilderComponent` como uma dependência independente, ou usar o token [`IGX_QUERY_BUILDER_DIRECTIVES`](https://github.com/IgniteUI/igniteui-angular/blob/master/projects/igniteui-angular/query-builder/src/query-builder/public_api.ts) para importar o componente e todos os seus componentes e diretivas de apoio.

```typescript
// home.component.ts

import { IGX_QUERY_BUILDER_DIRECTIVES } from 'igniteui-angular/query-builder';
import { FilteringExpressionsTree, FieldType } from 'igniteui-angular/core';
// import { IGX_QUERY_BUILDER_DIRECTIVES, FilteringExpressionsTree, FieldType } from '@infragistics/igniteui-angular'; for licensed package

@Component({
    selector: 'app-home',
    template: `
    <igx-query-builder #queryBuilder
        [entities]="entities"
        [(expressionTree)]="expressionTree"
        (expressionTreeChange)="onExpressionTreeChange()">
    </igx-query-builder>
    `,
    styleUrls: ['home.component.scss'],
    standalone: true,
    imports: [IGX_QUERY_BUILDER_DIRECTIVES]
    /* or imports: [IgxQueryBuilderComponent] */
})
export class HomeComponent {
    public expressionTree: FilteringExpressionsTree;
    public entities: Array<any>;

    public onExpressionTreeChange() {
        ...
    }
}
```

Agora que você importou o módulo ou as diretivas do Ignite UI for Angular Query Builder, pode começar a usar o componente `igx-query-builder`.

## Usando o Angular Query Builder

Se nenhuma árvore de expressões for definida inicialmente, você começa escolhendo uma entidade e quais de seus campos a consulta deve retornar. Depois disso, condições ou subgrupos podem ser adicionados.

Para adicionar uma condição, você seleciona um campo, um operando baseado no tipo de dado do campo e um valor, caso o operando não seja unário. Os operandos `In` e `Not In` permitem criar uma consulta interna com condições para outra entidade, em vez de simplesmente informar um valor. Depois que a condição é confirmada, aparece um chip com as informações da condição. Ao clicar ou passar o mouse sobre o chip, você tem opções para modificá-lo ou adicionar outra condição ou grupo logo após ele.

Clicar no botão (<ApiLink kind="enum" type="FilteringLogic" member="And" /> ou <ApiLink kind="enum" type="FilteringLogic" member="Or" />) posicionado acima de cada grupo abrirá um menu com opções para alterar o tipo do grupo ou desagrupar as condições internas.

Como cada condição está relacionada a um campo específico de uma entidade particular, alterar a entidade redefinirá todas as condições e grupos predefinidos. Ao selecionar uma nova entidade, será exibida uma caixa de diálogo de confirmação, a menos que a propriedade de entrada <ApiLink type="QueryBuilder" member="showEntityChangeDialog" label="showEntityChangeDialog" /> esteja definida como false.

Você pode começar a usar o componente definindo a propriedade <ApiLink type="QueryBuilder" member="entities" label="entities" /> como um array que descreve o nome da entidade e um array dos seus campos, em que cada campo é definido pelo seu nome e tipo de dado. Assim que um campo for selecionado, os operandos correspondentes serão atribuídos automaticamente com base no tipo de dado.
O Query Builder tem a propriedade de entrada <ApiLink type="QueryBuilder" member="expressionTree" label="expressionTree" />. Você pode usá-la para definir um estado inicial do controle e acessar a lógica de filtragem especificada pelo usuário.

```typescript
ngAfterViewInit(): void {
    const innerTree = new FilteringExpressionsTree(FilteringLogic.And, undefined, 'Companies', ['ID']);
    innerTree.filteringOperands.push({
        fieldName: 'Employees',
        condition: IgxNumberFilteringOperand.instance().condition('greaterThan'),
        conditionName: 'greaterThan',
        searchVal: 100
    });
    innerTree.filteringOperands.push({
        fieldName: 'Contact',
        condition: IgxBooleanFilteringOperand.instance().condition('true'),
        conditionName: 'true'
    });

    const tree = new FilteringExpressionsTree(FilteringLogic.And, undefined, 'Orders', ['*']);
    tree.filteringOperands.push({
        fieldName: 'CompanyID',
        condition: IgxStringFilteringOperand.instance().condition('inQuery'),
        conditionName: 'inQuery',
        searchTree: innerTree
    });
    tree.filteringOperands.push({
        fieldName: 'OrderDate',
        condition: IgxDateFilteringOperand.instance().condition('before'),
        conditionName: 'before',
        searchVal: new Date('2024-01-01T00:00:00.000Z')
    });
    tree.filteringOperands.push({
        fieldName: 'ShippedDate',
        condition: IgxDateFilteringOperand.instance().condition('null'),
        conditionName: 'null'
    });

    this.queryBuilder.expressionTree = tree;
}
```

A propriedade <ApiLink type="QueryBuilder" member="expressionTree" label="expressionTree" /> é vinculável nos dois sentidos, o que significa que há uma saída <ApiLink type="QueryBuilder" member="expressionTreeChange" label="expressionTreeChange" /> correspondente, que emite um evento quando o usuário final altera a UI criando, editando ou removendo condições. Ela também pode ser assinada separadamente para receber notificações e reagir a essas mudanças.

```html
<igx-query-builder #queryBuilder
    [entities]="entities"
    [(expressionTree)]="expressionTree"
    (expressionTreeChange)="onExpressionTreeChange()">
</igx-query-builder>
```

## Arrastar expressões

Os chips de condição podem ser facilmente reposicionados com [_arrastar e soltar_](./drag-drop.mdx) com o mouse, ou com [_reordenação pelo teclado_](#interação-pelo-teclado). Assim, os usuários podem ajustar a lógica da consulta dinamicamente.

- Arrastar um chip não altera a sua condição ou o seu conteúdo, apenas a sua posição.
- O chip também pode ser arrastado ao longo de grupos e subgrupos. Por exemplo, agrupar ou desagrupar expressões é feito pela funcionalidade de arrastar expressões.
Para agrupar condições já existentes, primeiro é preciso adicionar um novo grupo pelo botão de grupo 'add'. Depois, arrastando, as expressões necessárias podem ser movidas para esse grupo. Para desagrupar, você pode arrastar todas as condições para fora do grupo atual; quando a última condição for movida para fora, o grupo será excluído.

<DocsAside type="info">
Chips de uma árvore de consulta não podem ser arrastados para outra, por exemplo, do pai para o interno e vice-versa.
</DocsAside>

## Interação pelo teclado

**Combinações de teclas**

- <kbd>Tab</kbd> / <kbd>Shift + Tab</kbd> - navega para o próximo/anterior chip, indicador de arrastar, botão de remover ou botão de expressão 'add'.
- <kbd>Arrow Down</kbd>/<kbd>Arrow Up</kbd> - quando o indicador de arrastar do chip está com foco, o chip pode ser movido para cima/baixo.
- <kbd>Space</kbd> / <kbd>Enter</kbd> - a expressão com foco entra no modo de edição. Se o chip tiver sido movido, isso confirma a sua nova posição.
- <kbd>Esc</kbd> - a reordenação do chip é cancelada e ele volta à sua posição original.

<DocsAside type="info">
A reordenação pelo teclado oferece a mesma funcionalidade do arrastar e soltar com o mouse. Depois que um chip é movido, o usuário precisa confirmar a nova posição ou cancelar a reordenação.
</DocsAside>

## Templates

O componente Ignite UI for Angular Query Builder permite definir templates para o cabeçalho do componente e para o valor de pesquisa, usando os seguintes nomes de referência predefinidos:

### Template de cabeçalho

Por padrão, o cabeçalho <ApiLink type="QueryBuilder" /> não é exibido. Para defini-lo, deve-se adicionar o <ApiLink type="QueryBuilderHeader" /> dentro de `igx-query-builder`.

Em seguida, para definir o título do cabeçalho, pode-se usar a entrada <ApiLink type="QueryBuilderHeader" member="title" label="title" />, e passar conteúdo dentro de `igx-query-builder-header` permite criar um template para o cabeçalho do query builder.

 O trecho de código abaixo ilustra como fazer isso:

```html
<igx-query-builder #queryBuilder [entities]="this.entities">
        <igx-query-builder-header [title]="'Query Builder Template Sample'">  
        </igx-query-builder-header>
</igx-query-builder>
```

### Valor de pesquisa

O valor de pesquisa de uma condição pode ter um template definido pela diretiva <ApiLink type="QueryBuilderSearchValueTemplateDirective" label="igxQueryBuilderSearchValue" />, aplicada a um `<ng-template>` dentro do corpo de `igx-query-builder`:

```html
<igx-query-builder #queryBuilder
    [entities]="entities"
    [expressionTree]="expressionTree">
    <ng-template #searchValueTemplate
                igxQueryBuilderSearchValue 
                let-searchValue
                let-selectedField = "selectedField" 
                let-selectedCondition = "selectedCondition"
                let-defaultSearchValueTemplate = "defaultSearchValueTemplate">
        @if (
            selectedField?.field === 'Region' &&
            (selectedCondition === 'equals' || selectedCondition === 'doesNotEqual')
            ){
            <igx-select [placeholder]="'Select region'" [(ngModel)]="searchValue.value">
                <igx-select-item *ngFor="let reg of regionOptions" [value]="reg">
                    {{ reg.text }}
                </igx-select-item>
            </igx-select>
        } 
        @else if (
            selectedField?.field === 'OrderStatus' &&
            (selectedCondition === 'equals' || selectedCondition === 'doesNotEqual')
            ){
            <igx-radio-group>
                <igx-radio class="radio-sample"
                           *ngFor="let stat of statusOptions"
                           value="{{stat.value}}"
                           [(ngModel)]="searchValue.value">
                    {{stat.text}}
                </igx-radio>
            </igx-radio-group>
        }
            @else {  
            <ng-container #defaultTemplate *ngTemplateOutlet="defaultSearchValueTemplate"></ng-container>
        }
    </ng-template>
</igx-query-builder>
```

### Formatador

Para alterar a aparência do valor de pesquisa no chip exibido quando uma condição não está em modo de edição, você pode definir uma função formatadora no array de campos. O valor de pesquisa e a condição selecionada podem ser acessados pelos argumentos value e rowData, da seguinte forma:

```ts
this.ordersFields = [
    { field: "CompanyID", dataType: "string" },
    { field: "OrderID", dataType: "number" },
    { field: "EmployeeId", dataType: "number" },
    { field: "OrderDate", dataType: "date" },
    { field: "RequiredDate", dataType: "date" },
    { field: "ShippedDate", dataType: "date" },
    { field: "ShipVia", dataType: "number" },
    { field: "Freight", dataType: "number" },
    { field: "ShipName", dataType: "string" },
    { field: "ShipCity", dataType: "string" },
    { field: "ShipPostalCode", dataType: "string" },
    { field: "ShipCountry", dataType: "string" },
    { field: "Region", dataType: "string", formatter: (value: any, rowData: any) => rowData === 'equals' || rowData === 'doesNotEqual' ? `${value.value}` : value }},
    { field: "OrderStatus", dataType: "number" }
];
```

## Estilização

### Mapa de propriedades de tema do Query Builder

Quando você modifica uma propriedade primária, todas as propriedades dependentes relacionadas são atualizadas automaticamente para refletir a mudança:

| Propriedade primária | Propriedade dependente | Descrição |
| --- | --- | --- |
| **$background** | $label-foreground | A cor dos rótulos "from" e "select" do query builder |
|  | $header-background | A cor de fundo do cabeçalho do query builder |
|  | $header-foreground | A cor do texto do cabeçalho do query builder |
|  | $subquery-header-background | A cor de fundo do cabeçalho da subconsulta |
|  | $subquery-border-color | A cor da borda do bloco de consulta |
|  | $separator-color | A cor do separador do bloco de consulta |
|  | $header-border (somente Bootstrap) | A cor da borda do cabeçalho do query builder |

Para começar a estilizar o Query Builder, precisamos importar o arquivo `index`, onde são exportadas todas as funções de tema e o mixin `tokens()`:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

O Query Builder obtém a sua cor de fundo do seu tema, usando o parâmetro `background`. Para alterar o fundo, precisamos criar um tema personalizado:

```scss

$custom-query-builder: query-builder-theme(
  $schema: $dark-material-schema,
  $background: #292826,
  ...
);
```

Como há outros componentes dentro do Query Builder, como botões, chips, drop-downs e inputs, precisamos criar um tema separado para cada um deles:

```scss
$custom-button: flat-button-theme(
  $schema: $dark-material-schema,
  $foreground: #ffcd0f,
);

$custom-input-group: input-group-theme(
  $schema: $dark-material-schema,
  $focused-secondary-color: #ffcd0f
);

$custom-chip: chip-theme(
  $schema: $dark-material-schema,
  $background: #ffcd0f,
);

$custom-icon-button: outlined-icon-button-theme(
  $schema: $dark-material-schema,
  $foreground: #ffcd0f,
);
```

Neste exemplo, alteramos apenas alguns parâmetros dos componentes listados, mas os temas <ApiLink kind="sass" module="themes" type="function-flat-button-theme" label="flat-button-theme" code={true} />, <ApiLink kind="sass" module="themes" type="function-chip-theme" label="chip-theme" code={true} />, <ApiLink kind="sass" module="themes" type="function-drop-down-theme" label="drop-down-theme" code={true} /> e <ApiLink kind="sass" module="themes" type="function-input-group-theme" label="input-group-theme" code={true} /> oferecem muito mais parâmetros para controlar a estilização de cada um.

<DocsAside type="info">
Em vez de definir os valores de cor diretamente, como acabamos de fazer, podemos obter mais flexibilidade em relação às cores usando as funções <ApiLink kind="sass" module="palettes" type="function-palette" label="palette" code={true} /> e <ApiLink kind="sass" module="palettes" type="function-color" label="color" code={true} />. Consulte o tópico [`Palettes`](./themes/sass/palettes.mdx) para orientações detalhadas sobre como usá-las.
</DocsAside>

A última etapa é **incluir** os novos temas dos componentes usando o mixin `tokens`.

```scss
:host {
    @include tokens($custom-query-builder);
    @include tokens($custom-input-group);
    @include tokens($custom-chip);
    @include tokens($custom-icon-button);

    .igx-filter-tree__buttons {
      @include tokens($custom-button);
    }
}
```

<DocsAside type="info">
As substituições de tokens normalmente são herdadas pelo Emulated View Encapsulation, mas os seletores gerados para controles aninhados do query builder ainda podem exigir `::ng-deep`. Se o tema local não tiver efeito, envolva essa inclusão em `::ng-deep` ou mova-a para uma folha de estilos global. Se um drop-down estiver anexado a uma saída de overlay desanexada, emita o tema dele a partir de um seletor que consiga corresponder à saída, ou configure a saída abaixo do contêiner com tema.
</DocsAside>

### Estilizando com Tailwind

Você pode estilizar o query builder usando as nossas classes utilitárias personalizadas do Tailwind. Antes, certifique-se de [configurar o Tailwind](./themes/tailwind.mdx).

Junto com a importação do tailwind na sua folha de estilos global, você pode aplicar os utilitários de tema desejados da seguinte forma:

```scss
@import "tailwindcss";
...
@use 'igniteui-theming/tailwind/utilities/material.css';
```

O arquivo de utilitários inclui as variantes de tema `light` e `dark`.

- Use as classes `light-*` para o tema claro.
- Use as classes `dark-*` para o tema escuro.
- Acrescente o nome do componente depois do prefixo, por exemplo, `light-query-builder`, `dark-query-builder`.

Depois de aplicadas, essas classes habilitam cálculos dinâmicos de tema. A partir daí, você pode substituir as variáveis CSS geradas usando `arbitrary properties`. Depois dos dois-pontos, informe qualquer formato de cor CSS válido (HEX, variável CSS, RGB etc.).

Você pode encontrar a lista completa de propriedades em <ApiLink kind="sass" module="themes" type="function-query-builder-theme" label="query-builder-theme" />. A sintaxe é a seguinte:

```html
<igx-query-builder
  class="!light-query-builder ![--background:#90B69F]">
  ...
</igx-query-builder>
```

<DocsAside type="info">
O ponto de exclamação (`!`) é obrigatório para garantir que a classe utilitária tenha precedência. O Tailwind aplica estilos em camadas e, sem marcar esses estilos como importantes, eles serão sobrescritos pelo tema padrão do componente.
</DocsAside>
