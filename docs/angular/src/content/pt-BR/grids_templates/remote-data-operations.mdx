## Virtualização remota

O <ApiLink type="{ComponentApiType}" /> oferece suporte ao cenário em que os blocos de dados são solicitados a um serviço remoto, expondo o comportamento implementado na diretiva <ApiLink type="ForOfDirective" label="igxForOf" /> que ele usa internamente.

Para utilizar este recurso, você precisa se inscrever na saída <ApiLink type="{ComponentApiType}" member="dataPreLoad" label="dataPreLoad" />, para fazer a requisição apropriada com base nos argumentos recebidos, além de definir a propriedade pública <ApiLink type="{ComponentApiType}" /> <ApiLink type="{ComponentApiType}" member="totalItemCount" label="totalItemCount" /> com as informações correspondentes vindas do serviço.

```html
<igx-grid #grid [data]="remoteData | async" [autoGenerate]="false"
          (dataPreLoad)="processData(false)"
          (sortingDone)="processData(true)">
    <igx-column [field]="'ProductID'" [sortable]="true"></igx-column>
    <igx-column [field]="'ProductName'" [sortable]="true"></igx-column>
    <igx-column [field]="'UnitPrice'" [dataType]="'number'" [formatter]="formatCurrency" [sortable]="true"></igx-column>
</igx-grid>
```

## Rolagem infinita

 Um padrão popular para cenários que exigem buscar dados em blocos a partir de um endpoint é a chamada rolagem infinita. Para grids de dados, ela se caracteriza pelo aumento contínuo dos dados carregados, disparado pelo usuário final ao rolar até o fim. Os próximos parágrafos explicam como você pode usar a API disponível para obter facilmente a rolagem infinita no `IgxGrid`.

Para implementar a rolagem infinita, você precisa buscar os dados em blocos. Os dados já buscados devem ser armazenados localmente, e você precisa determinar o tamanho de um bloco e quantos blocos existem. Também precisa acompanhar o índice da última linha de dados visível no grid. Dessa forma, usando as propriedades `startIndex` e `chunkSize`, você pode determinar se o usuário está rolando para cima, e precisa mostrar dados já buscados, ou se está rolando para baixo, e você precisa buscar mais dados do endpoint.

A primeira coisa a fazer é usar o hook de ciclo de vida `ngAfterViewInit` para buscar o primeiro bloco de dados. Definir a propriedade `totalItemCount` é importante, pois permite que o grid dimensione corretamente a sua barra de rolagem.

```typescript
public ngAfterViewInit() {
    this._remoteService.loadDataForPage(this.page, this.pageSize, (request) => {
        if (request.data) {
            this.grid.totalItemCount = this.page * this.pageSize;
            this.grid.data = this._remoteService.getCachedData({startIndex: 0, chunkSize: 10});
            this.totalItems = request.data['@odata.count'];
            this.totalPageCount = Math.ceil(this.totalItems / this.pageSize);
            this.grid.isLoading = false;
        }
    });
}
```

Além disso, você precisa se inscrever na saída `dataPreLoad`, para fornecer os dados necessários ao grid quando ele tentar exibir um bloco diferente do atualmente carregado. No manipulador de evento, você deve determinar se deve buscar novos dados ou retornar dados que já estão armazenados localmente.

```typescript
public handlePreLoad() {
    const isLastChunk = this.grid.totalItemCount ===
                        this.grid.virtualizationState.startIndex + this.grid.virtualizationState.chunkSize;
    // when last chunk reached load another page of data
    if (isLastChunk) {
        if (this.totalPageCount === this.page) {
            this.grid.data = this._remoteService.getCachedData(this.grid.virtualizationState);
            return;
        }
        this.page++;
        this.grid.isLoading = true;
        this._remoteService.loadDataForPage(this.page, this.pageSize, (request) => {
            if (request.data) {
                this.grid.totalItemCount = Math.min(this.page * this.pageSize, this.totalItems);
                this.grid.data = this._remoteService.getCachedData(this.grid.virtualizationState);
                this.grid.isLoading = false;
            }
        });
    } else {
        this.grid.data = this._remoteService.getCachedData(this.grid.virtualizationState);
    }
}
```

## Ordenação/filtragem remota

Para fornecer ordenação e filtragem remotas, você precisa se inscrever nas saídas <ApiLink type="{ComponentApiType}" member="dataPreLoad" label="dataPreLoad" />, <ApiLink type="{ComponentApiType}" member="sortingExpressionsChange" label="sortingExpressionsChange" /> e <ApiLink type="{ComponentApiType}" member="filteringexpressionstreechange" label="filteringExpressionsTreeChange" />, para fazer a requisição apropriada com base nos argumentos recebidos, além de definir a propriedade pública <ApiLink type="{ComponentApiType}" /> <ApiLink type="{ComponentApiType}" member="totalItemCount" label="totalItemCount" /> com as informações correspondentes vindas do serviço.

Também vamos aproveitar a função **rxjs** `debounceTime`, que emite um valor do Observable de origem somente depois que determinado intervalo de tempo passou sem outra emissão da origem. Assim, a operação remota só será disparada quando o tempo especificado tiver passado sem que o usuário a interrompa.

```typescript
const DEBOUNCE_TIME = 300;
...
public ngAfterViewInit() {
    ...
    this.grid.dataPreLoad.pipe(
        debounceTime(DEBOUNCE_TIME),
        takeUntil(this.destroy$)
    ).subscribe(() => {
        this.processData();
    });

    this.grid.filteringExpressionsTreeChange.pipe(
        debounceTime(DEBOUNCE_TIME),
        takeUntil(this.destroy$)
    ).subscribe(() => {
        this.processData(true);
    });

    this.grid.sortingExpressionsChange.pipe(
        debounceTime(DEBOUNCE_TIME),
        takeUntil(this.destroy$)
    ).subscribe(() => {
        this.processData();
    });
}
```

Quando a ordenação e a filtragem remotas são fornecidas, normalmente não precisamos da ordenação e da filtragem integradas do grid. Podemos desabilitá-las definindo as entradas <ApiLink type="{ComponentApiType}" member="sortStrategy" label="sortStrategy" /> e <ApiLink type="{ComponentApiType}" member="filterStrategy" label="filterStrategy" /> do grid com as instâncias `NoopSortingStrategy` e `NoopFilteringStrategy` correspondentes.

```html
<igx-grid #grid [data]="remoteData | async" [height]="'500px'" [width]="'100%'" [autoGenerate]='false'
        [filterStrategy]="noopFilterStrategy"
        [sortStrategy]="noopSortStrategy"
        [allowFiltering]="true">
    ...
</igx-grid>
```

```typescript
public noopFilterStrategy = NoopFilteringStrategy.instance();
public noopSortStrategy = NoopSortingStrategy.instance();
```

Vamos usar uma coleção plana como fonte de dados para o nosso Tree Grid, fornecendo um <ApiLink type="{ComponentApiType}" member="primaryKey" label="primaryKey" /> e um <ApiLink type="{ComponentApiType}" member="foreignKey" label="foreignKey" />.

Também vamos aproveitar a função **rxjs** `debounceTime`, que emite um valor do Observable de origem somente depois que determinado intervalo de tempo passou sem outra emissão da origem. Assim, a operação remota só será disparada quando o tempo especificado tiver passado sem que o usuário a interrompa.

```typescript
const DEBOUNCE_TIME = 300;
```

### Estratégia de valores exclusivos da coluna

</ComponentBlock>

Os itens da lista dentro da caixa de diálogo de filtragem estilo Excel representam os valores exclusivos da respectiva coluna. Por padrão, o {ComponentTitle} gera esses valores com base na sua fonte de dados. No caso de filtragem remota, os dados do grid não contêm todos os dados do servidor. Para fornecer os valores exclusivos manualmente e carregá-los sob demanda, podemos aproveitar a entrada {ComponentTitle} do <ApiLink type="{ComponentApiType}" member="uniqueColumnValuesStrategy" label="uniqueColumnValuesStrategy" />. Essa entrada é, na prática, um método que recebe três argumentos:

- **column** - A respectiva instância da coluna.
- **filteringExpressionsTree** - A árvore de expressões de filtragem, reduzida com base na respectiva coluna.
- **done** - Callback que deve ser chamado com os novos valores da coluna quando eles forem obtidos do servidor.

O desenvolvedor pode gerar manualmente os valores exclusivos necessários da coluna com base nas informações fornecidas pelos argumentos **column** e **filteringExpressionsTree**, e depois invocar o callback **done**.

<DocsAside type="info">
Quando a entrada <ApiLink type="{ComponentApiType}" member="uniqueColumnValuesStrategy" label="uniqueColumnValuesStrategy" /> é fornecida, o processo padrão de geração de valores exclusivos na filtragem estilo Excel não será usado.
</DocsAside>

## Paginação remota

<ComponentBlock for="Grid, HierarchicalGrid">

O recurso de paginação pode operar com dados remotos. Para demonstrar isso, primeiro vamos declarar o nosso serviço, responsável pela obtenção dos dados. Precisaremos da contagem de todos os itens de dados para calcular a quantidade de páginas. Essa lógica será adicionada ao nosso serviço.

```typescript
@Injectable()
export class RemotePagingService {
    public remoteData: BehaviorSubject<any[]>;
    public dataLenght: BehaviorSubject<number> = new BehaviorSubject(0);
    public url = 'https://www.igniteui.com/api/products';

    constructor(private http: HttpClient) {
        this.remoteData = new BehaviorSubject([]) as any;
    }

    public getData(index?: number, perPage?: number): any {
        let qS = '';

        if (perPage) {
            qS = `?$skip=${index}&$top=${perPage}&$count=true`;
        }

        this.http
            .get(`${this.url + qS}`).pipe(
                map((data: any) => data)
            ).subscribe((data) => this.remoteData.next(data));
    }

    public getDataLength(): any {
        return this.http.get(this.url).pipe(
            map((data: any) => data.length)
        );
    }
}
```

Depois de declarar o serviço, precisamos criar um componente, responsável pela construção do {ComponentTitle} e pela assinatura dos dados.

### Paginação remota com template padrão

Se você quiser usar o _template de paginação padrão_, precisa definir a propriedade <ApiLink type="Paginator" member="totalRecords" label="totalRecords" /> do Paginator; somente assim o grid conseguirá calcular o _número total de páginas_ com base no total de registros remotos. Ao executar uma paginação remota, o Paginator passará ao Grid somente os dados da página atual; por isso, o grid não tentará paginar a fonte de dados fornecida. Por isso, devemos definir a propriedade <ApiLink type="{ComponentApiType}" member="pagingMode" label="pagingMode" /> do grid como _GridPagingMode.remote_. Também é necessário se inscrever em <ApiLink type="Paginator" member="pagingDone" label="pagingDone" /> ou em <ApiLink type="Paginator" member="perPageChange" label="perPageChange" /> para buscar os dados do seu serviço remoto; qual evento usar depende do caso de uso.

A seguir, os métodos que definimos para implementar as nossas próprias ações de página `next` e `previous`.

```typescript
@ViewChild('grid1', { static: true }) public grid1: IgxGridComponent;

public ngAfterViewInit() {
    this.grid1.isLoading = true;
    this.remoteService.getData(0, this.perPage);
}

public nextPage() {
    this.firstPage = false;
    this.page++;
    const skip = this.page * this.perPage;
    const top = this.perPage;
    this.remoteService.getData(skip, top);
    if (this.page + 1 >= this.totalPages) {
        this.lastPage = true;
    }
    this.setNumberOfPagingItems(this.page, this.totalPages);
}

public previousPage() {
    this.lastPage = false;
    this.page--;
    const skip = this.page * this.perPage;
    const top = this.perPage;
    this.remoteService.getData(skip, top);
    if (this.page <= 0) {
        this.firstPage = true;
    }
    this.setNumberOfPagingItems(this.page, this.totalPages);
}

public paginate(page: number, recalculate = false) {
    this.page = page;
    const skip = this.page * this.perPage;
    const top = this.perPage;
    if (recalculate) {
        this.totalPages = Math.ceil(this.totalCount / this.perPage);
    }
    this.setNumberOfPagingItems(this.page, this.totalPages);
    this.remoteService.getData(skip, top);
    this.buttonDeselection(this.page, this.totalPages);
}
```

### Paginação remota com edição em lote

Com os exemplos até aqui, esclarecemos como configurar o {ComponentName} com dados remotos. Agora, vamos focar em habilitar a edição em lote no grid, seguindo o [tópico/guia de Edição em Lote](/{igPath}/batch-editing).

Antes de continuar com o exemplo, vale esclarecer o caso de uso atual. Quando a paginação é feita no servidor, o grid contém apenas os dados da página atual; se adicionarmos novas linhas, as linhas recém-adicionadas (com Edição em Lote) serão concatenadas com os dados atuais do grid. Portanto, se o servidor não retornar dados para determinada página, a fonte de dados do grid será composta somente pelas linhas recém-adicionadas, que o grid paginará com base nas configurações de paginação definidas (page, perPage).

```typescript
public ngOnInit() {
    this._dataLengthSubscriber = this.remoteService.getDataLength().subscribe((data) => {
        this.totalCount = data;
        this._recordOnServer = data;
        this._totalPagesOnServer = Math.floor(this.totalCount / this.perPage);
        this.grid1.isLoading = false;
    });
}
```

Para tratar esse caso de uso corretamente, precisamos implementar alguma lógica personalizada.
Primeiro, precisamos saber o número total de registros que estão no servidor. Com isso, calculamos o número total de páginas de dados no servidor (veja `this._totalPagesOnServer`) e, com base nesse valor, implementaremos a lógica de paginação personalizada.

```typescript

public paginate(page: number) {
    this.grid1.endEdit(true);
    if (page > this._totalPagesOnServer) {
        if (this.page !== this._totalPagesOnServer) {
            const skipEl = this._totalPagesOnServer * this.perPage;
            this.remoteService.getData(skipEl, this.perPage);
        }
        this.page = page - this._totalPagesOnServer;
        this.page = page;
        return;
    } else {
        this.page = 0;
    }
    this.page = page;
    const skip = this.page * this.perPage;
    this.remoteService.getData(skip, this.perPage);
}

```

Como você pode ver no método **paginate**, a lógica de paginação personalizada é executada com base no valor de `_totalPagesOnServer`.

## Problemas conhecidos e limitações

- Quando o grid não tem `primaryKey` definido e os cenários de dados remotos estão habilitados (quando paginação, ordenação, filtragem ou rolagem disparam requisições a um servidor remoto para obter os dados a serem exibidos no grid), uma linha perderá o seguinte estado após a conclusão de uma requisição de dados:
  - Seleção de linha
  - Expandir/recolher linha
  - Edição de linha
  - Fixação de linha
- Em cenários de dados remotos, quando o grid tem um `primaryKey` definido, o argumento do evento <ApiLink kind="interface" type="IRowSelectionEventArgs" member="oldSelection" /> não conterá o objeto de dados completo da linha para as linhas que estão fora da visualização de dados no momento. Nesse caso, o objeto `rowSelectionChanging.oldSelection` conterá apenas uma propriedade, que é o campo `primaryKey`. Para as demais linhas, presentes na visualização de dados, `rowSelectionChanging.oldSelection` conterá todos os dados da linha.
