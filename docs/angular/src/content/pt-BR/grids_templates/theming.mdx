# Temas do {ComponentTitle} do Angular

O {ComponentTitle} do Ignite UI for Angular é temado por meio de <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} />, que deriva cada cor de um token de fundo, de primeiro plano e de destaque. Esses três tokens primários alcançam tudo o que o componente renderiza: o cabeçalho, as linhas, as bordas, os resumos, a barra de ferramentas, o paginador e os popups de filtragem.

<DocsAside type="info">
Não há uma função de tema separada para cada grid. O Data Grid, o Tree Grid, o Hierarchical Grid e o Pivot Grid usam todos `grid-theme()`; por isso, o mesmo tema se aplica a qualquer um deles sem modificação.
</DocsAside>

## Primeiros passos

Importe o ponto de entrada de temas, onde são exportadas as funções de tema e o mixin `tokens()`:

```scss
@use "igniteui-angular/theming" as *;
```

Em seguida, declare um tema e inclua-o no elemento que você quer afetar:

```scss
:host {
  @include tokens(grid-theme(
    $background: #08002e,
    $accent-color: #ff7d52
  ));
}
```

Esse é um tema completo. O {ComponentTitle} agora é índigo escuro com um destaque coral, e o texto, o cabeçalho, as bordas das linhas, os estados de hover, os tons de seleção e os elementos dos popups foram todos calculados para você.

## Tokens primários

O tema do {ComponentTitle} é construído a partir de três tokens; todas as outras cores são derivadas deles.

| Token | O que controla |
| -- | -- |
| `$background` | A superfície sobre a qual todo o componente é construído. Todas as outras superfícies e o primeiro plano padrão são derivados dela. |
| `$foreground` | Texto e ícones. Derivado de `$background` por contraste quando não definido. |
| `$accent-color` | Cor interativa: indicadores de ordenação, seleção, tons de hover, foco. |

`$foreground` está listado como primário, mas raramente precisa ser definido. Se deixado de lado, é escolhido por contraste com o fundo; assim, um fundo escuro produz texto claro, e um fundo claro produz texto escuro, sem uma segunda declaração.

## Como a derivação funciona

Ao declarar um tema, os tokens derivados não são resolvidos em cores fixas no momento do build. Eles são emitidos como expressões CSS sobre os tokens primários que você forneceu:

```css
.my-grid {
  --ig-grid-foreground: hsla(from color(from var(--ig-grid-background) var(--y-contrast)) h 0 l/1);
  --ig-grid-header-background: color-mix(in srgb, var(--ig-grid-foreground) 6%, var(--ig-grid-background));
  --ig-grid-row-hover-background: color-mix(in srgb, var(--ig-grid-accent-color) 8%, var(--ig-grid-row-odd-background));
  --ig-grid-sorted-header-icon-color: hsl(from var(--ig-grid-accent-color) h s l/0.7);
}
```

Duas consequências decorrem disso. Alterar um token primário recalcula tudo o que depende dele, inclusive em tempo de execução, por meio de propriedades personalizadas do CSS. E as relações se mantêm independentemente do valor que você fornecer; assim, um tema não consegue sair de sintonia consigo mesmo.

## Aprofundando

Alguns tokens são raízes de derivação por si só. Declarar um deles o desvincula do fundo, e o que estiver sobre ele passa a derivar do novo valor.

`$header-background` é o exemplo mais claro. Se deixado de lado, é misturado a partir de `$background`, e o texto do cabeçalho segue `$foreground`. Ao declará-lo, o texto do cabeçalho é derivado novamente para ter contraste em relação ao próprio cabeçalho:

```scss
:host {
  @include tokens(grid-theme(
    $background: #08002e,
    $accent-color: #ff7d52,
    $header-background: #ff7d52
  ));
}
```

<DocsAside type="note">
Recorra a isso somente quando quiser que uma superfície deixe de acompanhar o fundo. A maioria dos tokens que o tema documenta como derivados automaticamente é melhor deixar de lado — substituir um deles fixa um valor que, de outra forma, permaneceria em sintonia com o restante do tema.
</DocsAside>

## Estrutura

A cor é apenas metade de um tema. Densidade e arredondamento são controlados por tokens globais do design system, e não por parâmetros de `grid-theme()`; por isso, são definidos como propriedades personalizadas simples:

```scss
:host {
  --ig-size: var(--ig-size-small);   // small | medium | large
  --ig-radius-factor: 0;             // 0 to 1

  @include tokens(grid-theme(
    $background: #08002e,
    $accent-color: #ff7d52
  ));
}
```

As linhas de grade são parâmetros do tema. Para ocultar uma delas, aplique a ela um tom da superfície atrás dela, em vez de removê-la, para que as métricas das linhas não mudem entre os temas:

```scss
@include tokens(grid-theme(
  // horizontal dividers, blended away
  $row-border-color: var(--ig-grid-background),
  // vertical dividers, drawn in the same color the theme derives for rows
  $body-column-border-color-odd: hsl(from color-mix(in srgb, var(--ig-grid-foreground) 16%, var(--ig-grid-background)) h s l/0.38),
  $body-column-border-color-even: hsl(from color-mix(in srgb, var(--ig-grid-foreground) 16%, var(--ig-grid-background)) h s l/0.38)
));
```

## Componentes dentro do {ComponentTitle}

O {ComponentTitle} também aplica tema aos componentes que renderiza: seletores de linha, chips, badges, botões, entradas, drop-downs, tooltips, o paginador, a barra de ferramentas e os popups de filtragem. Ele declara os tokens deles no próprio host, derivados dos seus tokens primários; por isso, os tokens definidos para esses componentes em um ancestral não chegam até eles. `.promo { @include tokens(checkbox-theme($fill-color: #ff7d52)); }` recolore as caixas de seleção em `.promo`, mas não os seletores de linha de um {ComponentTitle} dentro dele.

Para recolorir os componentes internos, aplique tema ao {ComponentTitle}. Cada componente interno segue um ou mais dos seus tokens primários. A cor de destaque alcança os seletores de linha, badges, botões e entradas, enquanto os tooltips seguem o primeiro plano e os chips seguem tanto o fundo quanto o primeiro plano:

```scss
.promo {
  @include tokens(grid-theme($accent-color: #ff7d52));
}
```

Para substituir um componente sem alterar as cores do {ComponentTitle}, direcione esse componente. Os tokens declarados no próprio componente têm precedência sobre os que o {ComponentTitle} declara:

```scss
.promo igx-checkbox {
  @include tokens(checkbox-theme($fill-color: #ff7d52));
}

.promo .igx-tooltip {
  @include tokens(tooltip-theme($background: #ff7d52));
}
```

## Variáveis CSS

A aparência padrão é intencional, não derivada: por padrão, o {ComponentTitle} corresponde exatamente à especificação de design do Ignite UI, resolvendo com base na paleta base, em vez de calcular cores a partir de um fundo. A derivação é o que você escolhe quando declara um tema próprio.

Isso tem uma consequência prática para o tema só com CSS. Até que um tema seja declarado, não há expressões derivadas para substituir — o componente lê `var(--ig-grid-header-background, var(--ig-gray-100))` e os seus irmãos —, por isso definir algumas propriedades personalizadas manualmente **não** tem efeito em cascata:

```css
/* Not enough on its own: the background changes, the header stays grey. */
.my-grid {
  --ig-grid-background: #08002e;
  --ig-grid-accent-color: #ff7d52;
}
```

Para aplicar tema sem um build com Sass, declare o **conjunto completo de tokens** — as raízes mais as expressões derivadas que as referenciam. Esse bloco é autossuficiente, porque cada token derivado é uma expressão sobre as raízes:

```css
.my-grid {
  --ig-grid-background: #08002e;
  --ig-grid-accent-color: #ff7d52;
  --ig-grid-foreground: hsla(from color(from var(--ig-grid-background) var(--y-contrast)) h 0 l/1);
  --ig-grid-header-background: color-mix(in srgb, var(--ig-grid-foreground) 6%, var(--ig-grid-background));
  /* … and the rest of the theme's tokens */
}
```

Gerar isso à mão é impraticável; por isso, use o playground abaixo: ele emite o bloco completo para as cores que você escolher.

<DocsAside type="note">
Prefira a abordagem com Sass sempre que possível. `grid-theme()` escreve os tokens derivados por você e os mantém em sintonia com a biblioteca; um bloco CSS mantido à mão é um instantâneo que não acompanhará as mudanças no tema.
</DocsAside>
