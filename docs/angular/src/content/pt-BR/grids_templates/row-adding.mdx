# Adicionando linhas no {ComponentTitle} do Angular

<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">

O {ComponentTitle} oferece uma forma prática de realizar manipulações de dados por meio da adição de linhas inline e uma API poderosa para operações CRUD do Angular. Adicione um componente [Action Strip](/action-strip) com ações de edição habilitadas no template do grid, passe o mouse sobre uma linha e use o botão fornecido ou pressione <kbd>ALT</kbd> + <kbd>+</kbd> para abrir a interface de adição de linha.
</ComponentBlock>
<ComponentBlock for="TreeGrid">

Adicione um componente [Action Strip](/action-strip) com ações de edição habilitadas no template do grid, passe o mouse sobre uma linha e use o botão fornecido, pressione <kbd>ALT</kbd> + <kbd>+</kbd> para abrir a interface de adição de linha, ou <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>+</kbd> para abrir a interface de adição de um filho para a linha selecionada.
</ComponentBlock>

## Uso da adição de linhas

Para começar, importe o `{ComponentName}Module` no arquivo **app.module.ts**:

```typescript
// app.module.ts

...
import { {ComponentName}Module } from 'igniteui-angular';

@NgModule({
    ...
    imports: [..., {ComponentName}Module],
    ...
})
export class AppModule {}
```

Em seguida, defina um {ComponentTitle} com fonte de dados vinculada e <ApiLink type="{ComponentApiType}" member="rowEditable" label="rowEditable" /> definido como true, e um componente [Action Strip](../action-strip.mdx) com ações de edição habilitadas. A entrada <ApiLink type="GridEditingActions" member="addRow" label="addRow" /> controla a visibilidade do botão que abre a interface de adição de linhas.

## Iniciando a adição de linhas programaticamente

{ComponentTitle} permite abrir a interface de adição de linha programaticamente, usando dois métodos públicos diferentes. Um aceita um ID de linha para especificar a linha abaixo da qual a interface deve aparecer, e outro funciona por índice. Você pode usar esses métodos para abrir a interface em qualquer ponto da visualização de dados atual. Mudar a página ou especificar uma linha que, por exemplo, esteja filtrada não é suportado.

<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">
Usar `beginAddRowById` exige que você especifique a linha a ser usada como contexto da operação pelo seu rowID (PK). O método então funciona como se o usuário final tivesse clicado no botão de adicionar linha do action strip para a linha especificada, abrindo a interface abaixo dela. Você também pode fazer a interface aparecer como a primeira linha do grid, passando `null` como primeiro parâmetro.
</ComponentBlock>
<ComponentBlock for="TreeGrid">
Usar `beginAddRowById` exige que você especifique a linha a ser usada como contexto da operação pelo seu rowID (PK). O método então funciona como se o usuário final tivesse clicado no botão de adicionar linha do action strip para a linha especificada, abrindo a interface abaixo dela. O segundo parâmetro controla se a linha é adicionada como filha da linha de contexto ou como irmã. Você também pode fazer a interface aparecer como a primeira linha do grid, passando `null` como primeiro parâmetro.
</ComponentBlock>

<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">

```typescript
this.grid.beginAddRowById('ALFKI');  // spawns the add row UI under the row with PK 'ALFKI'
this.grid.beginAddRowById(null);     // spawns the add row UI as the first record
```

</ComponentBlock>
<ComponentBlock for="TreeGrid">

```typescript
this.treeGrid.beginAddRowById('ALFKI', true);   // spawns the add row UI to add a child for the row with PK 'ALFKI'
this.treeGrid.beginAddRowById(null);            // spawns the add row UI as the first record
```

</ComponentBlock>

<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">

O método `beginAddRowByIndex` funciona de forma semelhante, mas exige que você especifique o índice _em_ que a interface deve aparecer. Os valores permitidos vão de 0 até o tamanho da visualização de dados menos 1.

```typescript
this.grid.beginAddRowByIndex(10);   // spawns the add row UI at index 10
this.grid.beginAddRowByIndex(0);    // spawns the add row UI as the first record
```

</ComponentBlock>
<ComponentBlock for="TreeGrid">

O método `beginAddRowByIndex` funciona de forma semelhante, mas a linha usada como contexto é especificada pelo índice.

```typescript
this.treeGrid.beginAddRowByIndex(10, true);   // spawns the add row UI to add a child for the row at index 10
this.treeGrid.beginAddRowByIndex(null);       // spawns the add row UI as the first record
```

</ComponentBlock>

## Posicionamento

- A interface de adição de linha na posição padrão fica abaixo da linha para a qual o usuário final clicou no botão de adicionar linha.

- O {ComponentTitle} rola automaticamente para exibir totalmente a interface de adição de linha.

- O overlay da interface de adição de linha mantém a sua posição durante a rolagem.

## Comportamento

A interface de adição de linha tem o mesmo comportamento da edição de linha, pois foi projetada para oferecer uma experiência de edição consistente aos usuários finais. Consulte o tópico [{ComponentTitle} Row Editing](/{igPath}/row-editing) para mais informações.

Depois que uma nova linha é adicionada pela interface de adição de linha, a sua posição e/ou visibilidade é determinada pelo estado de ordenação, filtragem e agrupamento do {ComponentTitle}. Em um {ComponentTitle} que não tenha nenhum desses estados aplicados, ela aparece como o último registro. Um snackbar é exibido brevemente, contendo um botão que o usuário final pode usar para rolar o {ComponentTitle} até a posição da linha, caso ela não esteja visível.

## Navegação pelo teclado

- <kbd>ALT</kbd> + <kbd>+</kbd> - Entra no modo de edição para adicionar uma linha
<ComponentBlock for="TreeGrid">

- <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>+</kbd> - Entra no modo de edição para adicionar um filho
</ComponentBlock>

- <kbd>ESC</kbd> sai do modo de adição de linha sem enviar nenhuma alteração

- <kbd>TAB</kbd> move o foco de uma célula editável da linha para a próxima e da célula editável mais à direita para os botões CANCEL e DONE. A navegação a partir do botão DONE vai para a célula editável mais à esquerda da linha que está sendo editada.

## Integração de recursos

- Qualquer operação de adição de linha será interrompida se a visualização de dados do {ComponentTitle} for modificada. Todas as alterações feitas pelo usuário final são enviadas. Operações que alteram a visualização de dados incluem, entre outras, ordenação, agrupamento, filtragem, paginação etc.

- Os resumos são atualizados depois que a operação de adição de linha termina. O mesmo vale para os outros recursos que dependem da visualização de dados, como ordenação, filtragem etc.
<ComponentBlock for="HierarchicalGrid">

- Ao abrir a interface para Hierarchical Grids, qualquer layout filho atualmente expandido para a linha para a qual o usuário final clicou no botão de adicionar linha é recolhido.
</ComponentBlock>


## Personalizando o overlay de adição de linhas

### Personalizando o texto

Personalizar o texto do overlay de adição de linhas é possível usando `igxRowAddTextDirective`.

```html
<ng-template igxRowAddText>
 Adding Row
</ng-template>
 ```

### Personalizando botões

Personalizar os botões do overlay de edição de linha é possível usando `igxRowEditActionsDirective`.
Se você quiser que os botões façam parte da navegação por teclado, cada um deles deve ter o `igxRowEditTabStopDirective`.

 ```html
 <ng-template igxRowEditActions let-endRowEdit>
 <button igxButton igxRowEditTabStop (click)="endRowEdit(false)">Cancel</button>
 <button igxButton igxRowEditTabStop (click)="endRowEdit(true)">Apply</button>
</ng-template>
 ```

<DocsAside type="info">
Usar a diretiva `igxRowEditActions` alterará as ações de edição dos botões dos overlays de edição e de adição.
</DocsAside>

## Cenários remotos

Na maioria dos cenários de dados remotos, a atribuição da chave primária acontece na requisição de criação ao servidor. Nesse caso, os registros adicionados no cliente não terão o valor final da chave primária até serem salvos no banco de dados do servidor. Nesse caso, a forma recomendada de tratar essa atualização no {ComponentTitle} é a seguinte:

- Se o {ComponentTitle} não usar transações.

    Depois que a requisição de criação for concluída com sucesso e retornar os dados do registro adicionado, você pode substituir o id desse registro na instância local do registro de dados.

- Se o {ComponentTitle} usar transações.

    Depois que a requisição de criação ou de atualização em lote for concluída com sucesso e retornar as instâncias de registro adicionadas (com seus ids gerados pelo banco de dados), as transações ADD relacionadas devem ser removidas do log de transações usando o método de API <ApiLink kind="interface" type="TransactionService" member="clear" />. Isso é necessário porque a transação local terá um campo id gerado, que pode ser diferente do criado no banco de dados; por isso, elas devem ser removidas. Depois, você pode adicionar à instância local de dados os registros passados na resposta.

Isso garantirá que os ids gerados remotamente sejam sempre refletidos nos dados locais, e que as operações subsequentes de atualização/exclusão tenham como alvo os ids de registro corretos.
