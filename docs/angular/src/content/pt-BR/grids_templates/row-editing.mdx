# Edição de linhas do {ComponentTitle} do Angular

O {ComponentTitle} oferece uma forma prática de realizar manipulações de dados por meio da edição inline e uma API poderosa para operações CRUD do Angular. Clique em uma linha e pressione a tecla **Enter**, ou simplesmente dê um duplo clique com o mouse na linha que precisa ser modificada.

## Exemplo de edição de linhas do {ComponentTitle} do Angular

O exemplo a seguir demonstra como habilitar a edição de linhas no {ComponentTitle}. Alterar o valor de uma célula e depois clicar ou navegar para outra célula da mesma linha não atualiza o valor da linha até que seja confirmado pelo botão **Done**, ou descartado pelo botão **Cancel**.

<DocsAside type="info">
Quando uma linha está em modo de edição, clicar em uma célula de outra linha funcionará como se o botão Done fosse pressionado: envia todas as alterações da linha anterior. Se a nova célula que recebe o foco for editável, a nova linha também entra em modo de edição; se a célula não for editável, apenas a linha anterior sai do modo de edição.

## Uso da edição de linhas

Para começar, importe o `{ComponentName}Module` no arquivo **app.module.ts**:

```typescript

@NgModule({
    ...
    imports: [..., {ComponentName}Module],
    ...
})
export class AppModule {}
```

Definir a chave primária é obrigatório para as operações de edição de linhas.

<DocsAside type="info">
Não é necessário habilitar a edição para colunas individuais. Usar a propriedade <ApiLink type="{ComponentApiType}" member="rowEditable" label="rowEditable" /> no {ComponentTitle} fará com que todas as linhas, com a propriedade `field` definida, excluindo a chave primária, sejam editáveis. Se você quiser desabilitar a edição de uma coluna específica, deve definir a entrada <ApiLink type="Column" member="editable" label="editable" /> da coluna como `false`.
</DocsAside>

## Posicionamento

- A posição padrão do overlay fica abaixo da linha que está em modo de edição.

- Se não houver espaço abaixo da linha, o overlay aparecerá acima dela.

- Depois de exibido — acima ou abaixo —, o overlay manterá essa posição durante a rolagem, até ser fechado.

## Comportamento

- Se a linha estiver em modo de edição, a edição continuará se uma célula da mesma linha for clicada.

- Clicar no botão "Done" finalizará a edição da linha e enviará as alterações ao data source ou a uma transação, se houver uma disponível. Além disso, a linha sairá do modo de edição.

- Clicar no botão "Cancel" reverterá todas as alterações atuais da linha, e a linha sairá do modo de edição.

- Se a linha estiver em modo de edição, clicar em uma célula de outra linha finalizará a edição da linha atual e enviará as novas alterações da linha (o mesmo comportamento de clicar no botão "Done"). Se a nova célula que recebe o foco for editável, a nova linha também entra em modo de edição; se a célula não for editável, apenas a linha anterior sai do modo de edição.

- Se a linha estiver em modo de edição e o {ComponentTitle} for rolado de forma que a linha saia da área visível, ela continuará em modo de edição. Quando o {ComponentTitle} for rolado de volta, de modo que a linha fique visível novamente, ela continuará em modo de edição. Clicar fora do {ComponentTitle} também manterá a célula em modo de edição.

- Ao realizar operações de _ordenação_, _filtragem_, _pesquisa_ e _ocultação_, todas as alterações atuais da linha serão revertidas, e a linha sairá do modo de edição.

- Ao realizar operações de _paginação_, _redimensionamento_, _fixação_ e _movimentação_, a linha sairá do modo de edição e o valor mais recente será enviado.

- Cada célula modificada recebe o estilo de edição até que a edição da linha seja concluída. Este é o comportamento quando o {ComponentTitle} não é fornecido com transações. Quando há transações disponíveis, o estilo de edição da célula é aplicado até que todas as alterações sejam confirmadas.

## Navegação pelo teclado

- `Enter` e `F2` entram no modo de edição de linha

- `Esc` sai do modo de edição de linha e não envia nenhuma das alterações de célula feitas enquanto a linha estava em modo de edição.

- `Tab` move o foco de uma célula editável da linha para a próxima, e da célula editável mais à direita para os botões CANCEL e DONE. A navegação a partir do botão DONE vai para a célula editável mais à esquerda da linha que está sendo editada.

## Integração de recursos

- Qualquer operação que altere os dados encerrará as operações de edição de linha e enviará as alterações atuais da linha. Isso inclui operações como ordenação, mudança de critérios de agrupamento e filtragem, paginação etc.

- Os resumos serão atualizados depois que a edição da linha for concluída. O mesmo vale para outros recursos, como ordenação, filtragem etc.

<ComponentBlock for="Grid">

- Expandir e recolher linhas agrupadas não encerrará a edição da linha atual.
</ComponentBlock>

## Personalizando o overlay de edição de linhas

### Personalizando o texto

Personalizar o texto do overlay de edição de linhas é possível usando `igxRowEditTextDirective`.
A propriedade `rowChangesCount` é exposta e contém a quantidade de células alteradas.

```html
<ng-template igxRowEditText let-rowChangesCount>
 Changes: {{rowChangesCount}}
</ng-template>
 ```

### Personalizando botões

Personalizar os botões do overlay de edição de linha é possível usando `igxRowEditActionsDirective`.
Se você quiser que os botões façam parte da navegação por teclado, cada um deles deve ter o `igxRowEditTabStopDirective`.

 ```html
 <ng-template igxRowEditActions let-endRowEdit>
 <button igxButton igxRowEditTabStop (click)="endRowEdit(false)">Cancel</button>
 <button igxButton igxRowEditTabStop (click)="endRowEdit(true)">Apply</button>
</ng-template>
 ```

## Estilização

Usando a [Ignite UI for Angular Theme Library](/themes), podemos alterar bastante o overlay de edição de linhas.
O overlay de edição de linhas é um elemento composto — a sua UI é formada por alguns outros componentes:
    - [`igx-banner`](/banner) para renderizar o seu conteúdo
    - [`igx-button`](inputs/button)s são renderizados no template padrão (para os botões `Done` e `Cancel`).

No exemplo abaixo, vamos usar as opções de estilização desses dois componentes, [`button styling`](inputs/button#styling) e [`banner-styling`](/banner#estilização), para personalizar a experiência da edição de linhas do nosso {ComponentName}.
Também vamos estilizar o editor e o fundo da célula atual para que ela se destaque mais.

<ComponentBlock for="Grid, TreeGrid, HierarchicalGrid">
Você pode saber mais sobre a estilização de células na seção [Cell Styling](/{igPath}/cell-editing#estilização).
</ComponentBlock>

### Importar o tema

A forma mais fácil de estilizar o banner de edição de linhas é definir os estilos no arquivo de estilos global do nosso `app` (normalmente `styles.scss`).
A primeira coisa que precisamos fazer é importar o arquivo `themes/index` — isso nos dá acesso a todas as ferramentas poderosas do framework Sass do Ignite UI for Angular:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Depois de importar o arquivo de temas, podemos criar temas personalizados.

#### Definir o tema

Agora podemos definir um <ApiLink kind="sass" module="themes" type="function-banner-theme" label="Tema do banner" code={true} /> personalizado que afetará o fundo da edição de linhas e usará uma das paletas predefinidas, a saber `$purple-palette`:

```scss
$banner-theme: banner-theme(
  $banner-background: #e3e3e3,
  $banner-message-color: color($purple-palette, "secondary", 600)
);
```

Aqui estamos usando `my-banner-palette` em conjunto com <ApiLink kind="sass" module="palettes" type="function-color" label="igx-color" code={true} /> (exposto pela biblioteca de temas) para gerar as nossas cores.

### Incluir o tema

Tudo o que precisamos fazer agora é aplicar o tema com uma instrução Sass `@include`. Passamos o `$banner-theme` recém-definido por meio de <ApiLink kind="sass" module="themes" type="mixin-tokens" label="mixin de tokens" code={true} />:

```scss
:host {
  @include tokens($banner-theme);
}
```

### Estilos de componente

Como o overlay de edição de linhas usa temas de muitos outros componentes, estilizá-lo pelos estilos globais pode afetar outras partes da aplicação (por exemplo, banners, botões etc.). A melhor forma de evitar isso é restringir o tema do banner ao arquivo de estilos do componente específico ao qual ele se aplica.

<DocsAside type="info">
Em alguns templates de componentes, o Emulated View Encapsulation ainda pode impedir que as declarações de token geradas cheguem aos elementos aninhados do Ignite UI. Se o tema não tiver efeito, use `::ng-deep` conforme mostrado abaixo ou mova o tema para uma folha de estilos global.
</DocsAside>

```scss
// custom.component.scss

:host {
  ::ng-deep {
    @include tokens($banner-theme);
  }
}
```

Com a sintaxe acima, o nosso tema de banner personalizado se aplica corretamente ao overlay de edição de linhas do grid.

### Templates personalizados

Para personalizar ainda mais o nosso overlay de edição de linhas, podemos passar um template personalizado, para estilizar os botões `Done` e `Cancel` separadamente:

```html
<!-- in component.html -->
<{ComponentSelector}>
    <ng-template igxRowEditActions let-endRowEdit>
        <div class="custom-buttons">
            <button igxIconButton="flat" class="custom-button" igxRowEditTabStop (click)="endRowEdit(false)">
                <igx-icon>clear</igx-icon>
            </button>
            <button igxIconButton="flat" class="custom-button" igxRowEditTabStop (click)="endRowEdit(true)">
                <igx-icon>check</igx-icon>
            </button>
        </div>
    </ng-template>
</{ComponentSelector}>
```

Depois de definir os nossos botões personalizados, podemos usar o <ApiLink kind="sass" module="themes" type="function-flat-icon-button-theme" label="flat-icon-button-theme" code={true} /> para estilizá-los. Você pode saber mais sobre a estilização de `igx-icon-button` na [documentação de estilização do Icon Button](/icon-button#estilização-do-botão-de-ícone). Podemos criar um tema personalizado para o nosso `Done` e para o nosso `Cancel`:

```scss
// custom.component.scss
...

$button-theme: flat-icon-button-theme(
  $background: #e3e3e3,
  $foreground: #423589
);

...
.custom-buttons {
  @include tokens($button-theme);
}
```

Restringimos a nossa instrução `@include` em `.custom-buttons`, para que ela seja aplicada somente aos botões `Done` e `Cancel`.

## Problemas conhecidos e limitações

- Quando o grid não tem `primaryKey` definido e os cenários de dados remotos estão habilitados (quando paginação, ordenação, filtragem ou rolagem disparam requisições a um servidor remoto para obter os dados a serem exibidos no grid), uma linha perderá o seguinte estado após a conclusão de uma requisição de dados:
  - Seleção de linha
  - Expandir/recolher linha
  - Edição de linha
  - Fixação de linha
