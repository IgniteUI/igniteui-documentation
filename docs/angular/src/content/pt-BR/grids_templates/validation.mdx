# Edição e validação do {ComponentTitle} do Angular

A edição do {ComponentTitle} expõe um mecanismo de validação integrado da entrada do usuário ao editar células/linhas. Ele estende a funcionalidade de [validação de formulários do Angular](https://angular.io/guide/form-validation), para permitir uma integração mais fácil com um recurso bem conhecido. Quando o estado do editor muda, indicadores visuais são aplicados à célula editada.

## Configuração

### Configurar por meio de configuração orientada a template

Estendemos algumas das diretivas de validadores de Angular Forms para trabalhar diretamente com o `IgxColumn`. Os mesmos validadores estão disponíveis como atributos, para serem definidos de forma declarativa em `igx-column`. Os seguintes validadores são suportados de forma nativa:

- required
- min
- max
- email
- minlength
- maxlength
- pattern

Para validar que a entrada de uma coluna foi preenchida e que o valor será formatado como e-mail, você pode usar as diretivas correspondentes:

```html
<igx-column [field]="email" [header]="User E-mail" required email></igx-column>
```

## API do serviço de validação

O grid expõe um serviço de validação pela propriedade <ApiLink type="Grid" member="validation" label="validation" />.
Esse serviço tem as seguintes APIs públicas:

- <ApiLink type="GridValidationService" member="valid" label="valid" /> - retorna se o estado de validação do grid é válido.
- <ApiLink type="GridValidationService" member="getInvalid" label="getInvalid" /> - retorna os registros com estados inválidos.
- <ApiLink type="GridValidationService" member="clear" label="clear" /> - limpa o estado de um registro pelo id ou limpa todos os estados se nenhum id for informado.
- <ApiLink type="GridValidationService" member="markAsTouched" label="markAsTouched" /> - marca o registro/campo relacionado como tocado.

Os estados inválidos permanecem até que os erros de validação neles sejam corrigidos de acordo com a regra de validação, ou até que sejam limpos.

## Gatilhos de validação

A validação será disparada nos seguintes cenários:

- Durante a edição pelo editor de célula, com base na <ApiLink type="Grid" member="validationTrigger" label="validationTrigger" /> do grid. Seja em `change` enquanto se digita no editor, seja em `blur` quando o editor perde o foco ou é fechado.
- Ao atualizar células/linhas pela API — <ApiLink type="Grid" member="updateRow" label="updateRow" />, <ApiLink type="Grid" member="updateCell" label="updateCell" /> etc..
- Ao usar a edição em lote e a API <ApiLink type="TransactionService" member="undo" label="undo" />/<ApiLink type="TransactionService" member="redo" label="redo" /> do serviço de transações.

<DocsAside type="info">
A validação não será disparada para registros que não foram editados pela entrada do usuário ou pela API de edição. Os indicadores visuais na célula só serão exibidos se a entrada relacionada for considerada tocada — seja por interação do usuário, seja pela API `markAsTouched` do serviço de validação.
</DocsAside>

### Gatilho do tooltip de erro

A entrada {ComponentTitle} do <ApiLink type="Grid" member="validationTooltipTrigger" label="validationTooltipTrigger" /> controla quando o tooltip de erro de uma célula inválida é exibido. Ela não muda quando a validação é executada.

| Valor | Quando o tooltip de erro é exibido |
| --- | --- |
| `active` (padrão) | Quando uma célula inválida se torna ativa, quando a célula ativa se torna inválida e enquanto o usuário passa o mouse sobre o ícone de erro. |
| `hover` | Somente enquanto o usuário passa o mouse sobre o ícone de erro. |

Use `hover` para impedir que o tooltip cubra o conteúdo do grid enquanto o usuário edita ou navega. As células inválidas continuam exibindo o ícone de erro e os estilos de inválido:

```html
<{ComponentSelector} [data]="data" validationTooltipTrigger="hover"></{ComponentSelector}>
```

## Opções de personalização da validação do {ComponentTitle} do Angular

### Definir um validador personalizado

Você pode definir a sua própria diretiva de validação para usar em uma `<igx-column>` no template.

```ts
@Directive({
    selector: '[phoneFormat]',
    providers: [{ provide: NG_VALIDATORS, useExisting: PhoneFormatDirective, multi: true }]
})
export class PhoneFormatDirective extends Validators {
    @Input('phoneFormat')
    public phoneFormatString = '';

    public validate(control: AbstractControl): ValidationErrors | null {
        return this.phoneFormatString ? phoneFormatValidator(new RegExp(this.phoneFormatString, 'i'))(control)
            : null;
    }
}
```

Depois de definida e adicionada ao módulo da sua aplicação, você pode defini-la de forma declarativa para uma coluna específica do grid:

```html
<igx-column phoneFormat="\+\d{1}\-(?!0)(\d{3})\-(\d{3})\-(\d{4})\b" ...>
```

### Alterar o template de erro padrão

Você pode definir o seu próprio template de erro personalizado, que será exibido no tooltip de erro quando a célula entrar em estado inválido.
Isso é útil em cenários em que você quer adicionar a sua própria mensagem de erro ou alterar a aparência ou o conteúdo da mensagem.

```html
<igx-column ... >
  <ng-template igxCellValidationError let-cell='cell' let-defaultErr="defaultErrorTemplate">
      <ng-container *ngTemplateOutlet="defaultErr">
      </ng-container>
      @if (cell.validation.errors?.['phoneFormat']) {
        <div>
          Please enter correct phone format
        </div>
      }
  </ng-template>
</igx-column>
```

## Validação entre campos

Em alguns cenários, a validação de um campo pode depender do valor de outro campo do registro.
Nesse caso, um validador personalizado pode ser usado para comparar os valores do registro por meio do seu `FormGroup` compartilhado.

<ComponentBlock for="Grid">


O exemplo a seguir demonstra uma validação entre campos de diferentes campos do mesmo registro. Ele verifica a validade das datas em relação à data atual e entre a data ativa e a data de criação do registro, além da proporção de negócios ganhos/perdidos de cada funcionário. Todos os erros são reunidos em uma coluna fixada separada, que mostra que o registro é inválido e exibe os erros relacionados.

As próximas linhas de código mostram a função validadora entre campos, que contém as comparações e define os erros relacionados a elas.

```ts
private rowValidator(): ValidatorFn {
    return (formGroup: FormGroup): ValidationErrors | null => {
        let returnObject = {};
        const createdOnRecord = formGroup.get('created_on');
        const lastActiveRecord = formGroup.get('last_activity');
        const winControl = formGroup.get('deals_won');
        const loseControl = formGroup.get('deals_lost');
        const actualSalesControl = formGroup.get('actual_sales');

        // Validate dates
        const curDate = new Date();
        if (new Date(createdOnRecord.value) > curDate) {
            // The created on date shouldn't be greater than current date.
            returnObject['createdInvalid'] =  true;
        }
        if (new Date(lastActiveRecord.value) > curDate) {
            // The last active date shouldn't be greater than current date.
            returnObject['lastActiveInvalid'] = true;
        }
        if (new Date(createdOnRecord.value) > new Date(lastActiveRecord.value)) {
            // The created on date shouldn't be greater than last active date.
            returnObject['createdLastActiveInvalid'] = true;
        }
        
        // Validate deals
        const dealsRatio = this.calculateDealsRatio(winControl.value, loseControl.value);
        if (actualSalesControl.value === 0 && dealsRatio > 0) {
            // If the actual sales value is 0 but there are deals made.
            returnObject['salesZero'] = true;
        }
        if (actualSalesControl.value > 0 && dealsRatio === 0) {
            // If the deals ratio based on deals won is 0 but the actual sales is bigger than 0.
            returnObject['salesNotZero'] = true;
        }
        
        return returnObject;
    };
}

public calculateDealsRatio(dealsWon, dealsLost) {
    if (dealsLost === 0) return dealsWon + 1;
    return Math.round(dealsWon / dealsLost * 100) / 100;
}
```

O validador entre campos pode ser adicionado ao `formGroup` da linha a partir do evento <ApiLink type="Grid" member="formGroupCreated" label="formGroupCreated" />, que retorna o novo `formGroup` de cada linha ao entrar em modo de edição:

public stateMessage(cell: CellType) {
    const messages = [];
    const row = cell.row;
    const cellValidationErrors = row.cells.filter(x => !!x.validation.errors);
    cellValidationErrors.forEach(cell => {
        if (cell.validation.errors) {
            if (cell.validation.errors.required) {
                messages.push(`The \`${cell.column.header}\` column is required.`);
            }
            // Other cell errors ...
        }
    });

    if (row.validation.errors?.createdInvalid) {
        messages.push(`The \`Date of Registration\` date cannot be in the future.`);
    }
    // Other cross-field errors...

    return messages;
}

        return (control: AbstractControl): ValidationErrors | null => {
            const formGroup = control;
            let returnObject = {};

            const country = formGroup.get('Country');
            const validCities = this.countryData.get(country.value);
            if (!validCities || !validCities[city.value]) {
                returnObject['invalidAddress'] = true;
            }
            return returnObject;
        }
    }

    public dateValidator(): ValidatorFn {
        return (control: AbstractControl): ValidationErrors | null => {
            const formGroup = control;
            let returnObject = {};
            const orderDate = formGroup.get('OrderDate').value;
            const shippedDate = formGroup.get('ShippedDate').value;

```ts
    public isRowValid(cell: CellType) {
        const hasErrors = !!cell.row.validation.errors || cell.row.cells.some(x => !!x.validation.errors);
        return !hasErrors;
    }

    public stateMessage(cell: CellType) {
        const messages = [];
        const row = cell.row;
        if  (row.validation.errors?.invalidAddress) {
            messages.push('The address information is invalid. City does not match the Country.');
        }
        if  (row.validation.errors?.invalidRange) {
            messages.push('The ShippedDate cannot be before the OrderDate.');
        }
        const cellValidationErrors = row.cells.filter(x => !!x.validation.errors);
        if (cellValidationErrors && cellValidationErrors.length > 0) {
            const fields = cellValidationErrors.map(x => x.column.field).join(',');
            messages.push('The following fields are required: ' + fields);
        }

        if (messages.length === 0) {
            // no errors
            return ['Valid'];
        }
        return messages;
    }
```

## Estilização

Usando a [Ignite UI for Angular Theme Library](/themes), podemos alterar os estilos de validação padrão durante a edição.

No exemplo abaixo, usaremos o template exposto para a mensagem de validação, que aparece em um tooltip, e substituiremos a cor de erro para modificar a aparência padrão da validação.
Também estilizaremos o fundo das linhas inválidas para destacá-las mais.

### Importar o tema

A forma mais fácil de estilizar e acessar variáveis CSS é definir os estilos no arquivo de estilos global do nosso `app` (normalmente `styles.scss`).
A primeira coisa que precisamos fazer é importar o arquivo `themes/index` — isso nos dá acesso a todas as ferramentas poderosas do framework Sass do Ignite UI for Angular:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

### Incluir os estilos

Para alterar a cor de erro, você pode usar a variável CSS `--ig-error-500`:

```scss
--ig-error-500: 34, 80%, 63%;
```
