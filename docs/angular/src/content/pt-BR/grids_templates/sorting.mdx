# Ordenação do {ComponentTitle} do Angular

No Ignite UI for Angular {ComponentTitle}, a ordenação de dados é habilitada por coluna, o que significa que a **{ComponentSelector}** pode ter uma combinação de colunas ordenáveis e não ordenáveis. Executar ações de ordenação do Angular permite alterar a ordem de exibição dos registros com base em critérios especificados.

<DocsAside type="info">
Até agora, agrupamento e ordenação funcionavam em conjunto. Na versão 13.2, foi introduzido um novo comportamento que desacopla o agrupamento da ordenação. Por exemplo, limpar o agrupamento não limpará as expressões de ordenação da grade, e vice-versa. Ainda assim, se uma coluna estiver ordenada e agrupada ao mesmo tempo, as expressões de agrupamento têm precedência.
</DocsAside>

## Ordenando pela API

Você pode ordenar qualquer coluna ou combinação de colunas pela API {ComponentTitle}, usando o método {ComponentTitle} <ApiLink type="{ComponentApiType}" member="sort" label="sort" />:

<ComponentBlock for="TreeGrid">

```typescript
import { SortingDirection } from 'igniteui-angular/grids/core';
// import { SortingDirection } from '@infragistics/igniteui-angular'; for licensed package

// Perform a case insensitive ascending sort on the ProductName column.
this.{ComponentObjectRef}.sort({ fieldName: 'Name', dir: SortingDirection.Asc, ignoreCase: true });

// Perform sorting on both the ProductName and Price columns.
this.{ComponentObjectRef}.sort([
    { fieldName: 'Name', dir: SortingDirection.Asc, ignoreCase: true },
    { fieldName: 'UnitPrice', dir: SortingDirection.Desc }
]);
```

</ComponentBlock>
<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">

```typescript
import { SortingDirection } from 'igniteui-angular/grids/core';
// import { SortingDirection } from '@infragistics/igniteui-angular'; for licensed package

// Perform a case insensitive ascending sort on the ProductName column.
this.{ComponentObjectRef}.sort({ fieldName: 'ProductName', dir: SortingDirection.Asc, ignoreCase: true });

// Perform sorting on both the ProductName and Price columns.
this.{ComponentObjectRef}.sort([
    { fieldName: 'ProductName', dir: SortingDirection.Asc, ignoreCase: true },
    { fieldName: 'Price', dir: SortingDirection.Desc }
]);
```

</ComponentBlock>

<DocsAside type="info">
A ordenação é realizada com o nosso algoritmo <ApiLink type="DefaultSortingStrategy" />. Qualquer <ApiLink type="Column" member="sortStrategy" label="IgxColumnComponent" /> ou <ApiLink type="ISortingExpression" kind="interface" member="strategy" label="ISortingExpression" /> pode usar uma implementação personalizada de <ApiLink type="ISortingStrategy" kind="interface" /> como algoritmo substituto. Isso é útil quando é preciso definir uma ordenação personalizada para colunas com templates complexos ou colunas de imagem, por exemplo.
</DocsAside>

Assim como no comportamento de filtragem, você pode limpar o estado de ordenação usando o método <ApiLink type="{ComponentApiType}" member="clearsort" label="clearSort" />:

<ComponentBlock for="TreeGrid">

```typescript
// Removes the sorting state from the ProductName column
this.{ComponentObjectRef}.clearSort('Name');

// Removes the sorting state from every column in the {ComponentTitle}
this.{ComponentObjectRef}.clearSort();
```

</ComponentBlock>
<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">

```typescript
// Removes the sorting state from the ProductName column
this.{ComponentObjectRef}.clearSort('ProductName');

// Removes the sorting state from every column in the {ComponentTitle}
this.{ComponentObjectRef}.clearSort();
```

</ComponentBlock>

<DocsAside type="info">
O <ApiLink type="{ComponentApiType}" member="sortStrategy" label="sortStrategy" /> da **{ComponentTitle}** é de tipo diferente do <ApiLink type="Column" member="sortStrategy" label="sortStrategy" /> da **coluna**, pois elas funcionam em escopos diferentes e expõem parâmetros diferentes.
</DocsAside>

<DocsAside type="info">
A operação de ordenação **NÃO** altera a fonte de dados subjacente do {ComponentTitle}.
</DocsAside>

## Estado inicial de ordenação

É possível definir o estado inicial de ordenação do {ComponentTitle} passando um array de expressões de ordenação para a propriedade <ApiLink type="{ComponentApiType}" member="sortingExpressions" label="sortingExpressions" /> do {ComponentTitle}.

<ComponentBlock for="Grid">

```typescript
public ngAfterViewInit(): void {
    this.{ComponentObjectRef}.sortingExpressions = [
        {
            dir: SortingDirection.Asc, fieldName: 'CategoryName',
            ignoreCase: true, strategy: DefaultSortingStrategy.instance()
        }
    ];
}
```

</ComponentBlock>

<ComponentBlock for="TreeGrid">

```typescript
public ngAfterViewInit(): void {
    this.{ComponentObjectRef}.sortingExpressions = [
        { 
            dir: SortingDirection.Asc, fieldName: 'UnitPrice',
            ignoreCase: true, strategy: DefaultSortingStrategy.instance() 
        }
    ];
}
```

</ComponentBlock>

<ComponentBlock for="HierarchicalGrid">

```typescript
public ngOnInit(): void {
    this.{ComponentObjectRef}.sortingExpressions = [
        { 
            dir: SortingDirection.Asc, fieldName: 'Artist',
            ignoreCase: true, strategy: DefaultSortingStrategy.instance() 
        }
    ];
}
```

</ComponentBlock>

<DocsAside type="info">
Se valores do tipo `string` forem usados por uma coluna de <ApiLink type="Column" member="dataType" label="dataType" /> `Date`, o {ComponentTitle} não os converterá em objetos `Date`, e o uso de {ComponentTitle} `sorting` não funcionará como esperado. Se você quiser usar objetos `string`, é preciso implementar uma lógica adicional no nível da aplicação, para converter os valores em objetos `Date`.
</DocsAside>

## Templates dos indicadores de ordenação

O ícone indicador de ordenação no cabeçalho da coluna pode ser personalizado usando um template. As seguintes diretivas estão disponíveis para criar templates do indicador de ordenação em qualquer estado (ascendente, descendente, nenhum):

- `IgxSortHeaderIconDirective` – redefine o template do ícone de ordenação quando nenhuma ordenação é aplicada.

```html
<ng-template igxSortHeaderIcon>
    <igx-icon>unfold_more</igx-icon>
</ng-template>
```

- `IgxSortAscendingHeaderIconDirective` – redefine o template do ícone de ordenação quando a coluna está ordenada em ordem crescente.

```html
<ng-template igxSortAscendingHeaderIcon>
    <igx-icon>expand_less</igx-icon>
</ng-template>
```

- `IgxSortDescendningHeaderIconDirective` – redefine o template do ícone de ordenação quando a coluna está ordenada em ordem decrescente.

```html
<ng-template igxSortDescendingHeaderIcon>
    <igx-icon>expand_more</igx-icon>
</ng-template>
```


## Estilização

Para começar a estilizar o comportamento de ordenação, precisamos importar o arquivo `index`, onde são exportadas todas as funções de tema e o mixin `tokens()`:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Seguindo a abordagem mais simples, criamos um novo tema que estende o <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} /> e aceita os parâmetros `$sorted-header-icon-color` e `sortable-header-icon-hover-color`.

<ComponentBlock for="Grid, HierarchicalGrid">

```scss
$custom-theme: grid-theme(
  $sorted-header-icon-color: #ffb06a,
  $sortable-header-icon-hover-color: black
);
```

</ComponentBlock>

<ComponentBlock for="TreeGrid">

```scss
$custom-theme: grid-theme(
  $sorted-header-icon-color: #dc38e8,
  $sortable-header-icon-hover-color: #5d1461
);
```

</ComponentBlock>

<DocsAside type="info">
Em vez de definir os valores de cor diretamente, como acabamos de fazer, podemos obter mais flexibilidade em relação às cores usando as funções <ApiLink kind="sass" module="palettes" type="function-palette" label="palette" code={true} /> e <ApiLink kind="sass" module="palettes" type="function-color" label="color" code={true} />. Consulte o tópico [`Palettes`](/themes/sass/palettes) para orientações detalhadas sobre como usá-las.
</DocsAside>

A última etapa é aplicar o tema do componente com `tokens()`:

```scss
:host {
  @include tokens($custom-theme);
}
```
