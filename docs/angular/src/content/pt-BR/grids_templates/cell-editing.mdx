# Edição de célula do {ComponentTitle} do Angular

O componente {ComponentTitle} do Ignite UI for Angular oferece recursos poderosos de manipulação de dados e uma API robusta para operações CRUD do Angular. Por padrão, o {ComponentTitle} usa edição **dentro da célula**, e diferentes editores são exibidos conforme o tipo de dado da coluna, graças ao **template padrão de edição de célula**. Além disso, você pode definir os seus próprios templates personalizados para as ações de atualização de dados e substituir o comportamento padrão de confirmação e descarte de alterações.

## Edição de células

### Edição pela UI

Você pode entrar no modo de edição de uma célula específica, quando uma célula editável está com foco, de uma das seguintes formas:

- com um duplo clique;
- com um clique simples — o clique simples entra no modo de edição somente se a célula selecionada anteriormente estava em modo de edição e a célula selecionada no momento for editável. Se a célula selecionada anteriormente não estava em modo de edição, o clique simples apenas seleciona a célula, sem entrar no modo de edição;
- ao pressionar uma tecla `Enter`;
- ao pressionar uma tecla `F2`;

Você pode sair do modo de edição **sem confirmar** as alterações de uma das seguintes formas:

- ao pressionar uma tecla `Escape`;
- ao realizar operações de _ordenação_, _filtragem_, _pesquisa_ e _ocultação_;

Você pode sair do modo de edição e **confirmar** as alterações de uma das seguintes formas:

- ao pressionar uma tecla `Enter`;
- ao pressionar uma tecla `F2`;
- ao pressionar uma tecla `Tab`;
- com um clique simples em outra célula — quando você clica em outra célula no {ComponentTitle}, as suas alterações são enviadas.
- operações como paginação, redimensionamento, fixação ou movimentação saem do modo de edição e as alterações são enviadas.

<DocsAside type="info">
A célula permanece em modo de edição quando você rola na vertical ou na horizontal, ou clica fora do {ComponentTitle}. Isso vale tanto para a edição de célula quanto para a edição de linha.
</DocsAside>

### Templates de edição de célula

Você pode ver e saber mais sobre os templates padrão de edição de célula no [tópico geral de edição](/{igPath}/editing#templates-de-edição).

Se você quiser fornecer um template personalizado que será aplicado quando uma célula estiver no modo de edição, pode usar o <ApiLink type="CellTemplateDirective" label="diretiva igxCellEditor" />. Para isso, você precisa passar um `ng-template` marcado com a diretiva `igxCellEditor` e vincular corretamente o seu controle personalizado ao <ApiLink type="GridCell" member="editValue" label="cell.editValue" />:

```html
<igx-column field="class" header="Class" [editable]="true">
    <ng-template igxCellEditor let-cell="cell" let-value>
        <igx-select class="cell-select" [(ngModel)]="cell.editValue" [igxFocus]="true">
            <igx-select-item *ngFor="let class of classes" [value]="class">
                {{ class }}
            </igx-select-item>
        </igx-select>
    </ng-template>
</igx-column>
```

### Edição estilo Excel do {ComponentTitle}

Usar a edição estilo Excel permite ao usuário navegar pelas células como faria no Excel, editando-as com grande rapidez.

Implementar essa funcionalidade personalizada pode ser feito usando os eventos do grid. Primeiro, conectamos os eventos de keydown do grid e, a partir daí, podemos implementar duas funcionalidades:

- Modo de edição constante

```typescript
public keydownHandler(event) {
  const key = event.keyCode;
  const grid = this.grid;
  const activeElem = grid.navigation.activeNode;

  if(
    (key >= 48 && key <= 57) ||
    (key >= 65 && key <= 90) ||
    (key >= 97 && key <= 122)){
        // Number or Alphabet upper case or Alphabet lower case
        const columnName = grid.getColumnByVisibleIndex(activeElem.column).field;
        const cell = grid.getCellByColumn(activeElem.row, columnName);
        if (cell && !cell.editMode) {
            cell.editMode = true;
            cell.editValue = event.key;
            this.shouldAppendValue = true;
        } else if (cell && cell.editMode && this.shouldAppendValue) {
            event.preventDefault();
            cell.editValue = cell.editValue + event.key;
            this.shouldAppendValue = false;
        }
    }
}
```

- Navegação `Enter`/ `Shift+Enter`

```typescript
if (key == 13) {
    let thisRow = activeElem.row;
    const column = activeElem.column;
    const rowInfo = grid.dataView;

    // to find the next eiligible cell, we will use a custom method that will check the next suitable index
    let nextRow = this.getNextEditableRowIndex(thisRow, rowInfo, event.shiftKey);

    // and then we will navigate to it using the grid's built in method navigateTo
    this.grid.navigateTo(nextRow, column, (obj) => {
        obj.target.activate();
        this.grid.clearCellSelection();
        this.cdr.detectChanges();
    });
}
```

As partes-chave para encontrar o próximo índice elegível são:

```typescript
//first we check if the currently selected cell is the first or the last
if (currentRowIndex < 0 || (currentRowIndex === 0 && previous) || (currentRowIndex >= dataView.length - 1 && !previous)) {
return currentRowIndex;
}
// in case using shift + enter combination, we look for the first suitable cell going up the field
if(previous){
return  dataView.findLastIndex((rec, index) => index < currentRowIndex && this.isEditableDataRecordAtIndex(index, dataView));
}
// or for the next one down the field
return dataView.findIndex((rec, index) => index > currentRowIndex && this.isEditableDataRecordAtIndex(index, dataView));
```

### Validação de célula no evento de edição

Usando os eventos de edição do grid, podemos alterar a forma como o usuário interage com ele.
Neste exemplo, vamos validar uma célula com base nos dados inseridos nela, vinculando-nos ao evento <ApiLink type="{ComponentApiType}" member="cellEdit" label="cellEdit" />. Se o novo valor da célula não atender aos critérios predefinidos, vamos impedir que ele chegue à fonte de dados, cancelando o evento (`event.cancel = true`). Também vamos exibir uma mensagem de erro personalizada usando [`IgxToast`](../toast.mdx).

A primeira coisa que precisamos fazer é vincular ao evento do grid:

```html
<{ComponentSelector} (cellEdit)="handleCellEdit($event)"
...>
...
</{ComponentSelector}>
```

O `cellEdit` é emitido sempre que o valor de **qualquer** célula está prestes a ser confirmado. Na nossa definição de `handleCellEdit`, precisamos garantir que verificamos a nossa coluna específica antes de tomar qualquer ação:

<ComponentBlock for="Grid">

```typescript
export class MyGridEventsComponent {
    public handleCellEdit(event: IGridEditEventArgs): void {
        const column = event.column;
        if (column.field === 'Ordered') {
            const rowData = event.rowData;
            if (!rowData) {
                return;
            }
            if (event.newValue > rowData.UnitsInStock) {
                event.cancel = true;
                this.toast.open();
            }
        }
    }
}
```

Se o valor informado em uma célula da coluna **Ordered** for maior que a quantidade disponível (o valor em **Units in Stock**), a edição será cancelada e será exibido um toast com uma mensagem de erro.
</ComponentBlock>
<ComponentBlock for="TreeGrid">

```typescript
export class MyTreeGridEventsComponent {
    public handleCellEdit(event: IGridEditEventArgs): void {
        const column = event.column;
        if (column.field === 'Age') {
            if (event.newValue < 18) {
                event.cancel = true;
                this.toast.message = 'Employees must be at least 18 years old!';
                this.toast.open();
            }
        } else if (column.field === 'HireDate') {
            if (event.newValue > new Date().getTime()) {
                event.cancel = true;
                this.toast.message = 'The employee hire date must be in the past!';
                this.toast.open();
            }
        }
    }
}
```

Aqui, estamos validando duas colunas. Se o usuário tentar definir um valor inválido para a **Idade** de um funcionário (abaixo de 18) ou para a sua **Data de contratação** (uma data futura), a edição será cancelada (o valor não será enviado) e será exibido um toast com uma mensagem de erro.
</ComponentBlock>
<ComponentBlock for="HierarchicalGrid">

```typescript
export class MyHGridEventsComponent {
    public handleCellEdit(event: IGridEditEventArgs) {
        const today = new Date();
        const column = event.column;
        if (column.field === 'Debut') {
            if (event.newValue > today.getFullYear()) {
                this.toast.message = 'The debut date must be in the past!';
                this.toast.open();
                event.cancel = true;
            }
        } else if (column.field === 'LaunchDate') {
            if (event.newValue > new Date()) {
                this.toast.message = 'The launch date must be in the past!';
                this.toast.open();
                event.cancel = true;
            }
        }
    }
}
```

Aqui, estamos validando duas colunas. Se o usuário tentar alterar o ano de **estreia** de um artista ou a **data de lançamento** de um álbum, o grid não permitirá datas posteriores à data de hoje.
</ComponentBlock>

## Estilização

O {ComponentName} permite que as suas células sejam estilizadas por meio de [`Ignite UI for Angular Theme Library`](/themes/sass/component-themes). A propriedade <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} /> do grid expõe uma grande variedade de propriedades, que permitem estilizar muitos aspectos diferentes do grid.

Nas etapas abaixo, vamos ver como estilizar a célula do grid em modo de edição e como restringir esses estilos a um escopo.

Para usar o [`Ignite UI Theming Library`](/themes/sass/component-themes), primeiro precisamos importar o arquivo de tema `index` nos nossos estilos globais:

### Importando a biblioteca de estilos

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Agora podemos usar todas as funções expostas pelo mecanismo de temas do Ignite UI for Angular.

### Definindo uma paleta

Depois de importar corretamente o arquivo index, criamos uma paleta personalizada que podemos usar. Vamos definir três cores de que gostamos e usá-las para construir uma paleta com [`palette`](/themes/palettes):

```scss
$white: #fff;
$blue: #4567bb;
$gray: #efefef;

$color-palette: palette(
  $primary: $white, 
  $secondary: $blue, 
  $surface: $gray
);
```

### Definindo temas

Agora podemos definir o tema usando a nossa paleta. As células são estilizadas pelo <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} />; por isso, podemos usá-lo para gerar um tema para o nosso {ComponentName}:

```scss
$grid-theme: grid-theme(
  $cell-editing-background: $blue,
  $cell-editing-foreground: $white,
  $cell-active-border-color: $blue,
  $cell-edited-value-color: $white,
  $edit-mode-color: color($color: "secondary", $variant: 200)
);
```

### Aplicando o tema

A última etapa é **incluir** a paleta personalizada e os temas do grid.

<ComponentBlock for="Grid">

```scss
igx-grid {
  @include palette($color-palette);
  @include tokens($grid-theme);
}
```

</ComponentBlock>
<ComponentBlock for="TreeGrid">

```scss

```

