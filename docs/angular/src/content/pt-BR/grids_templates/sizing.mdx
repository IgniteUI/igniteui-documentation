# Dimensionamento do Angular Grid

Há muitas formas diferentes de dimensionar o <ApiLink type="{ComponentApiType}" /> para atender aos vários cenários que os usuários podem ter. Enquanto algumas são diretas, outras podem ser mais complexas; por isso, veremos cada uma com mais profundidade. Vamos tratar da definição de `width` e `height` separadamente, já que há algumas diferenças, por exemplo, ao usar porcentagens em cada uma.

Quando se trata do tamanho de borda e de padding do <ApiLink type="{ComponentApiType}" />, eles são considerados nos cálculos de largura/altura, também conhecidos como dimensionamento [Border box](https://developer.mozilla.org/en-US/docs/Web/CSS/box-sizing). Isso se aplica em todos os cenários.

<DocsAside type="info">
Se o dimensionamento Border box for substituído pelo usuário, não podemos garantir que o <ApiLink type="{ComponentApiType}" /> será dimensionado corretamente.
</DocsAside>

## Largura

Se a entrada `width` não tiver valor atribuído, o seu valor padrão é `100%`, e o <ApiLink type="{ComponentApiType}" /> tenta preencher o espaço disponível. Você pode verificar como o grid reage a isso na seção `Percentages`.

<DocsAside type="info">
Definir manualmente o estilo `width` do próprio <ApiLink type="{ComponentApiType}" /> resultará em um comportamento inesperado.
</DocsAside>

### Null

A propriedade `width` do grid pode aceitar o valor `null`, que, quando definido, renderiza todas as colunas no DOM. O grid se dimensiona de acordo, para que não haja barra de rolagem horizontal, já que a virtualização de colunas não é aplicada.

- Se houver 6 colunas e nenhuma delas tiver largura definida, o grid terá `width` de `816px`, porque cada coluna, por padrão, tem atribuído um `width` de `136px` nesse cenário. O mesmo acontecerá se as colunas tiverem `width` em porcentagens. Se a barra de rolagem vertical for renderizada, ou se houver recursos que renderizem colunas adicionais, a largura delas também será somada.

    <Image src={columnsDefaultGridwidthNullV2} alt="Largura padrão do grid com colunas em null" style="width: 80%" />

- Se houver 6 colunas com largura de coluna definida como `200px`, elas caberão na nossa janela, e todas ficarão visíveis:

    <Image src={widthNullNoScrollV2} alt="Largura null sem rolagem" style="width: 80%" />

- Se houver mais colunas ou colunas com largura maior que saem da visualização do navegador, todas ainda serão renderizadas. Vamos ter a mesma quantidade de colunas, mas cada uma com largura de coluna de `300px`. Como nem todas cabem na área de visualização do navegador, será criada uma barra de rolagem nativa. O próximo exemplo mostra exatamente esse cenário:

    <Image src={widthNullScrollV2} alt="Largura null com rolagem" style="width: 80%" />

- Se o grid tiver um elemento pai de qualquer tipo e este não tiver overflow definido, todas as colunas ainda serão renderizadas e visíveis. Caso contrário, se o elemento pai tiver overflow `auto` ou `scroll`, será renderizada uma barra de rolagem nativa para esse elemento pai. O pai tem altura maior para facilitar a visualização no exemplo a seguir.

    <Image src={widthNullParentScrollV2} alt="Largura null com rolagem no pai" style="width: 80%" />

<DocsAside type="info">
Devido a esse comportamento, se os dados do grid contiverem colunas demais, isso pode ter impacto significativo no desempenho do navegador, já que todas as colunas seriam renderizadas sem virtualização.
</DocsAside>

### Pixels

Quando a entrada <ApiLink type="{ComponentApiType}" /> `width` é definida em pixels, todo o tamanho do grid é definido com esse valor, e ele fica estático. Não reagirá a redimensionamentos do navegador nem a alterações no DOM, embora isso não se aplique ao conteúdo do grid:

- Quando a largura é definida em pixels, para que o grid renderize uma barra de rolagem horizontal, a largura do seu conteúdo precisa exceder a `width` do grid especificada. Por exemplo, vamos fazer a soma das larguras das colunas exceder `1200px`. Nesse caso, será renderizada uma barra de rolagem horizontal.

    <Image src={widthColsScrollbarV2} alt="Largura com colunas e barra de rolagem" style="width: 80%" />

- Para cenários em que o grid tem um elemento pai, depende da estilização do pai se a barra de rolagem será renderizada ou não. Todo o restante relacionado ao próprio grid continua sendo mantido. Se a largura do elemento pai for menor que a largura do grid e o estilo de overflow do pai estiver definido como `auto` ou `scroll`, a barra de rolagem será renderizada nativamente. Por exemplo, se o pai tiver `width` definido como `1000px` e o <ApiLink type="{ComponentApiType}" /> `width` continuar sendo `1200px`, ficará parecido com as ilustrações a seguir:

    <Image src={widthColsScrollParentNoscrollV2} alt="Largura com colunas, rolagem no pai e sem rolagem" style="width: 80%" />
    <Image src={widthColsScrollParentScrollV2} alt="Largura com colunas, rolagem no pai e com rolagem" style="width: 80%" />

### Porcentagens

Quando o `width` do <ApiLink type="{ComponentApiType}" /> é definido em porcentagens, ele dimensiona o grid de acordo com a largura do elemento pai. Se o elemento pai não tiver largura especificada, o <ApiLink type="{ComponentApiType}" /> será dimensionado em relação à janela do navegador.

- Por exemplo, se definirmos a entrada `width` do grid como `100%` e não houver elemento pai, ele preencherá 100% da largura disponível da janela do navegador. Se a janela for redimensionada, o grid também será redimensionado de acordo.

    <Image src={widthPercent100PV2} alt="Largura em porcentagem 100%" style="width: 80%" />

- Se definirmos a largura do grid como `100%` e houver um elemento pai com largura específica de `1200px`, isso significará que o grid será dimensionado em relação a esse elemento, e a sua largura final será `1200px`.

    <Image src={widthPercentParent100PV2} alt="Largura em porcentagem com pai de 100%" style="width: 80%" />

- Se tivermos um elemento pai com `width` de `1000px` e definirmos o `width` do grid como `150%`, a largura calculada do grid será `1500px`. Nesse caso, o grid ainda será renderizado totalmente visível, mas, se definirmos `overflow: auto` do pai, esse pai renderizará uma barra de rolagem por conta própria.

    <Image src={widthPercent150PParentNoscrollV2} alt="Largura em porcentagem 150% com pai sem rolagem" style="width: 80%" />
    <Image src={widthPercent150PParentScrollV2} alt="Largura em porcentagem 150% com pai com rolagem" style="width: 80%" />

## Altura

Por padrão, se nenhuma altura for definida para o <ApiLink type="{ComponentApiType}" />, ela será definida como `100%`. Você pode verificar como o grid reage dependendo da estrutura do DOM na seção `Percentages`.

<DocsAside type="info">
Definir manualmente o estilo `height` do próprio <ApiLink type="{ComponentApiType}" /> resultará em um comportamento inesperado.
</DocsAside>

### Null

A entrada <ApiLink type="{ComponentApiType}" /> `height` pode aceitar o valor `null`, que, quando definido, exibe todas as linhas sem barra de rolagem, não importa quantas sejam. Nesse caso, não há virtualização vertical, já que o grid renderiza todas as linhas de qualquer forma.

- Se tivermos dados com 14 linhas, nesse caso o grid renderizará todas as 14 e se dimensionará para que todas fiquem visíveis, sem nenhum espaço vazio dentro do grid.

    <Image src={heightNull14RowsV2} alt="Altura null com 14 linhas" style="width: 80%" />

- Se tivermos 24 linhas, o grid ainda renderizará todas, mas, como são muitas, elas ultrapassarão os limites do navegador. Por isso, o próprio navegador renderizará uma barra de rolagem vertical por padrão, para que o usuário possa rolar até as demais linhas.

    <Image src={heightNull24RowsV2} alt="Altura null com 24 linhas" style="width: 80%" />

- Se houver um elemento pai com `height` definida, o grid ainda renderizará todas as linhas e não será afetado. Digamos que o pai tenha `height` de `650px`. Se ele tiver `overflow` definido como `auto` ou `scroll`, renderizará uma barra de rolagem vertical, mas o grid continuará não afetado:

    <Image src={heightNull24RowsParentNoscrollV2} alt="Altura null com 24 linhas e pai sem rolagem" style="width: 80%" />
    <Image src={heightNull24RowsParentScrollV2} alt="Altura null com 24 linhas e pai com rolagem" style="width: 80%" />

<DocsAside type="info">
Devido a esse comportamento, se os dados do grid contiverem linhas demais, isso pode ter impacto significativo no desempenho do navegador, já que todas as linhas seriam renderizadas sem virtualização.
</DocsAside>

### Pixels

Definir a <ApiLink type="{ComponentApiType}" /> `height` em pixels é mais direto, já que o grid se dimensionará exatamente para esse tamanho em todas as situações, de forma semelhante a quando `width` é definida em pixels.

- Se definirmos, por exemplo, a altura `500px` com 4 linhas para os nossos dados, o grid terá esse tamanho e, como 4 linhas não são suficientes para preencher a área visível, é esperado que haja uma área vazia.

    <Image src={height500Px4RowsV2} alt="Altura 500px com 4 linhas" style="width: 80%" />

- Se a quantidade de linhas exceder a área visível do grid quando `height` estiver em pixels, será renderizada uma barra de rolagem vertical. Por exemplo, um grid com altura de `500px` e 14 linhas será renderizado da seguinte forma:

    <Image src={height500Px14RowsV2} alt="Altura 500px com 14 linhas" style="width: 80%" />

- Se houver um elemento pai com `height` definido, a menos que ele tenha `overflow` definido como `auto` ou `scroll`, o grid continuará totalmente visível. Caso contrário, renderizará uma barra de rolagem.

    <Image src={height700Px14RowsParentNoscrollV2} alt="Altura 700px com 14 linhas e pai sem rolagem" style="width: 80%" />
    <Image src={height700Px14RowsParentScrollV2} alt="Altura 700px com 14 linhas e pai com rolagem" style="width: 80%" />

### Porcentagens

Quando a entrada `height` é definida em porcentagens, o <ApiLink type="{ComponentApiType}" /> será dimensionado com base na altura do elemento pai. Se o elemento pai tiver a sua `height` definida em pixels ou porcentagens, o grid será dimensionado em relação ao tamanho do pai.

Quando o elemento pai não tem altura definida, o navegador não lhe atribui altura inicialmente e o dimensiona com base nos seus filhos e no tamanho deles. Por isso, não há como o grid saber qual altura base usar para aplicar o dimensionamento em porcentagem. Por esse motivo, ele renderizará no máximo 10 linhas e, se houver mais linhas, será renderizada uma barra de rolagem vertical. Caso contrário, o grid se ajustará à quantidade de linhas renderizadas. Veremos esse cenário com mais detalhes nos próximos exemplos.

Vamos definir `width` como `1200px`, e o elemento pai sem nenhum tamanho aplicado:

- Se houver menos de 10 linhas, o grid tentará encaixar todas as linhas na área visível, sem espaço vazio entre a última linha e a parte inferior da área visível. Por exemplo, vamos supor que os dados do grid tenham 7 linhas. O grid renderizará todas as 7 linhas, sem barra de rolagem vertical e sem espaço vazio dentro do grid.

    <Image src={heightUndefined7RowsV2} alt="Altura indefinida com 7 linhas" style="width: 80%" />

- Se houver mais de 10 linhas, será renderizada uma barra de rolagem vertical para as demais linhas, e apenas 10 linhas podem estar visíveis a qualquer momento. No próximo exemplo, apenas a quantidade de linhas foi aumentada para 14.

    <Image src={heightUndefined14RowsV2} alt="Altura indefinida com 14 linhas" style="width: 80%" />

- Se definirmos a altura do elemento pai como `800px` e a <ApiLink type="{ComponentApiType}" /> com altura `100%`, isso significa que o grid será dimensionado em 100 por cento de `800px`.

    <Image src={heightPercent100Parent800PxV2} alt="Altura em porcentagem 100% com pai de 800px" style="width: 80%" />

- Se a <ApiLink type="{ComponentApiType}" /> `height` for definida como um número maior que `100%` e o elemento pai tiver altura, para que o pai renderize uma barra de rolagem, ele precisa ter novamente `overflow` definido como `auto` ou `scroll`. Caso contrário, o grid ficará totalmente visível e será dimensionado em relação ao tamanho do pai.

    <Image src={heightPercent130PParentNoscrollV2} alt="Altura em porcentagem 130% com pai sem rolagem" style="width: 80%" />
    <Image src={heightPercent130PParentScrollV2} alt="Altura em porcentagem 130% com pai com rolagem" style="width: 80%" />

- Se quisermos que o grid seja dimensionado em `100%` a partir da janela do navegador, precisaremos definir as alturas tanto de `body` quanto do elemento pai do grid como `100%`. Nesse caso, o elemento pai pode ser dimensionado, e o grid se dimensionará de acordo se o navegador for redimensionado.

    <Image src={heightPercent100Parent100V2} alt="Altura em porcentagem 100% com pai de 100%" style="width: 80%" />

## Dimensionamento de colunas

Dependendo do próprio tamanho do grid, as colunas dentro dele também podem ser dimensionadas de forma diferente, o que pode resultar em cenários em que o grid renderiza ou não uma barra de rolagem horizontal. As colunas podem ter largura definida em pixels, em porcentagens ou dimensionamento automático quando nada é definido. Veremos esses cenários com mais detalhes nesta seção.

### Padrão

Por padrão, quando uma coluna não tem largura especificada, ela tenta se dimensionar automaticamente, de modo a preencher qualquer espaço vazio disponível na área de visualização do grid. Colunas com dimensionamento automático têm largura mínima de `136px`; por isso, se a área disponível for menor que `136px` para essa coluna, ela assumirá esse tamanho.

Quando o grid é redimensionado nesses cenários, a largura da coluna também é atualizada para refletir as mudanças, de modo a preencher qualquer novo espaço vazio disponível.

- Se uma coluna não tiver `width` especificada e o <ApiLink type="{ComponentApiType}" /> tiver `width` definido como `null`, ela será dimensionada para o mínimo de `136px`. Isso significa que, para um grid com `width` `null` e 6 colunas sem largura definida, cada coluna será dimensionada para `136px`.

    <Image src={columnsDefaultGridwidthNullV2} alt="Grid padrão de colunas com largura null" style="width: 80%" />

- Quando há várias colunas com dimensionamento automático, elas dividirão igualmente o espaço disponível entre si. Isso significa que, se tivermos 6 colunas e uma área vazia de `1200px`, cada uma será dimensionada para `200px`.

    <Image src={columnsDefaultAllRowSelectorsV2} alt="Colunas padrão com todos os seletores de linha" style="width: 80%" />

- Se houver espaço vazio disponível, mas de forma que cada coluna com dimensionamento automático fique menor que `136px`, todas as colunas com dimensionamento automático assumirão `136px` e o grid renderizará uma barra de rolagem horizontal. No próximo exemplo, vamos ter 12 colunas com dimensionamento automático e o `width` do grid definido como `1000px`.

    <Image src={columnsDefaultAllMin136PxV2} alt="Colunas padrão, todas com mínimo de 136px" style="width: 80%" />

- Se uma coluna não tiver `width` especificada, mas todas as outras colunas tiverem `width` em pixels ou porcentagens, essa coluna também tentará preencher o espaço disponível. Por exemplo, se não definirmos a largura da primeira coluna, e as outras 5 tiverem `width` de `100px`, a primeira preencherá o restante.

    <Image src={columnsDefaultFirstRest100PxV2} alt="Colunas padrão, primeira com o restante em 100px" style="width: 80%" />

- O mesmo se aplica se várias colunas não tiverem `width` especificada: todas dividirão igualmente o espaço disponível entre si. Na ilustração seguinte, a primeira coluna tem `width` definido como `100px`.

    <Image src={columnsDefaultAllFirst100PxV2} alt="Colunas padrão, todas com a primeira em 100px" style="width: 80%" />

<DocsAside type="info">
Colunas de recursos, como a coluna de caixa de seleção do seletor de linha etc., ocupam espaço adicional, que é levado em conta ao dimensionar automaticamente as colunas.
</DocsAside>

### Pixels

Quando as colunas têm `width` específicas em pixels, elas mantêm esse tamanho, a menos que sejam redimensionadas manualmente. Como a soma combinada de `width` das colunas é estática, ela pode ser menor que <ApiLink type="{ComponentApiType}" /> `width` ou excedê-lo.

- Se a soma combinada de `width` de todas as colunas for menor que <ApiLink type="{ComponentApiType}" /> `width`, haverá uma área vazia dentro do grid que as colunas não conseguirão preencher. Esse é o comportamento esperado de <ApiLink type="{ComponentApiType}" />. No próximo exemplo, as colunas têm largura de `150px`.

    <Image src={columns150PxEmptyAreaV2} alt="Colunas de 150px resultando em área vazia" style="width: 80%" />

- Se a soma combinada das `width` de todas as colunas for maior que a <ApiLink type="{ComponentApiType}" /> `width` real, será renderizada uma barra de rolagem horizontal. No próximo exemplo, cada uma das 6 colunas tem largura de `300px` e o grid tem largura de `1200px`, o que significa que as colunas combinadas têm um excesso de `600px` que fica fora dos limites.

    <Image src={columns150PxExtraAreaV2} alt="Colunas de 150px resultando em área extra" style="width: 80%" />

### Auto

Quando as colunas são definidas como `auto`, o seu tamanho se ajusta para caber a palavra mais longa da coluna. Áreas vazias são possíveis se houver células com valores muito curtos, enquanto outras células têm valores muito longos. Nesse cenário, todas as células da coluna se ajustariam para ocupar a largura da célula com o valor mais longo.

<Image src={columns150PxEmptyAreaV2} alt="Largura automática das colunas" style="width: 80%" />

### Porcentagens

Quando as colunas têm `width` definida em porcentagens, o seu tamanho é calculado em relação ao tamanho do grid. É semelhante ao funcionamento da largura em pixels, mas também oferece responsividade às colunas, o que significa que, quando o grid é redimensionado, as colunas também se redimensionam de acordo.

- Se a largura combinada de todas as colunas for menor que `100%`, do mesmo modo que em pixels, pode haver uma área vazia do grid que as colunas não cobrem.

    <Image src={columnsPercentLess100PV2} alt="Colunas em porcentagem com menos de 100%" style="width: 80%" />

- Se a largura combinada for exatamente `100%`, as colunas preencherão todo o espaço disponível do grid.

    <Image src={columnsPercent100PV2} alt="Colunas em porcentagem com 100%" style="width: 80%" />

- Se a largura combinada exceder `100%`, para que o usuário possa ver as colunas fora da área visível, será renderizada uma barra de rolagem horizontal.

    <Image src={columnsPercentBigger100PV2} alt="Colunas em porcentagem maiores que 100%" style="width: 80%" />

- Se as colunas forem definidas em porcentagens e a `width` do grid for definida como `null`, será aplicado`width` de `136px` a cada coluna. Isso acontece porque as colunas não podem ser dimensionadas em relação ao grid, já que ele não tem `width` próprio e depende do seu conteúdo para ser dimensionado quando a sua `width` é `null`. No exemplo a seguir, todas as 6 colunas têm `width` definido como `50%`:

    <Image src={columnsPercentGridwidthNullV2} alt="Colunas em porcentagem com grid de largura null" style="width: 80%" />

## Dimensionamento de grids filhos

Como o <ApiLink type="{ComponentApiType}" /> geralmente contém filhos, eles também podem ter a sua `width` e a sua `height` especificadas, para atender a diferentes cenários. Como os filhos são definidos usando o template `row island`, isso significa que todos os filhos do mesmo nível e ilha terão as mesmas propriedades `width` e `height` aplicadas.

### Largura

A `width` dos filhos não se comporta de forma muito diferente da <ApiLink type="{ComponentApiType}" /> em si, já que cada grid filho também é uma instância de <ApiLink type="{ComponentApiType}" />.

A única diferença é que o usuário não pode alterar o elemento pai do grid filho. Por isso, quando o `width` é definido em porcentagens, a `100%` alocada para o filho é menor que a `width` do grid pai. Isso facilita a distinção quando ele está expandido. A imagem a seguir mostra os tamanhos padrão do grid filho, já que ele usa por padrão a largura `100%`.

<Image src={hgridWidthPercentagesV2} alt="Largura do grid filho em porcentagens" style="width: 80%" />

### Altura

A `height` de cada filho em <ApiLink type="{ComponentApiType}" /> também se comporta de forma semelhante à `height` do grid de nível raiz.

A diferença é que, para o grid filho, quando `height` é definido em porcentagens, ele se comporta como se o elemento pai não tivesse altura definida. Isso significa que, nesse cenário, o grid renderizará no máximo 10 linhas. Quando a quantidade de linhas dos dados for menor que 10, o grid dimensionará a área de visualização para caber todas as linhas. Se os dados tiverem mais linhas, será renderizada uma barra de rolagem vertical e a área de visualização será dimensionada para a altura de 10 linhas.

## Controle do espaçamento das células do grid

O <ApiLink type="{ComponentApiType}" /> ajusta automaticamente o seu espaçamento interno com base na configuração de [tamanho](/{igPath}/display-density). Você pode personalizar ainda mais o padding e as margens das células do cabeçalho e do corpo do grid usando propriedades personalizadas do CSS para controle de espaçamento.

### Espaçamento global do grid

Para reduzir ou aumentar o espaçamento de todas as células do grid na sua aplicação:

```css
/* Reduce all grid spacing by 20% */
igx-grid {
    --ig-spacing: 0.8;
}

/* Increase spacing for better touch accessibility */
igx-grid {
    --ig-spacing: 1.2;
}
```

### Espaçamento específico do grid

Para ajustar o espaçamento de uma instância específica do grid:

```css
/* Make a particular grid more compact */
.my-compact-grid {
    --ig-spacing: 0.6;
}

/* Give a specific grid more breathing room */
.my-spacious-grid {
    --ig-spacing: 1.4;
}
```

### Controle de espaçamento direcional

Você pode controlar o espaçamento horizontal e vertical de forma independente:

```css
/* Reduce only horizontal spacing (left/right padding) */
.my-grid {
    --ig-spacing-inline: 0.5;
    --ig-spacing-block: 1.0; /* Keep vertical spacing normal */
}

/* Adjust vertical spacing for tighter row spacing */
.my-grid {
    --ig-spacing-inline: 1.0; /* Keep horizontal spacing normal */
    --ig-spacing-block: 0.7; /* Reduce vertical spacing (if applicable) */
}
```

### Espaçamento específico por tamanho

Diferentes multiplicadores de espaçamento podem ser aplicados com base na densidade de exibição do grid:

```css
.my-grid {
    /* Compact density gets very tight spacing */
    --ig-spacing-small: 0.5;

    /* Medium density uses normal spacing */
    --ig-spacing-medium: 1.0;

    /* Comfortable density gets extra spacing */
    --ig-spacing-large: 1.3;
}
```

### Espaçamento das células do cabeçalho x do corpo

Embora as propriedades de espaçamento afetem as células do cabeçalho e do corpo, você pode direcioná-las especificamente, se necessário:

```css
/* Reduce padding in header cells specifically */
.my-grid igx-grid-header {
    --ig-spacing: 0.7;
}

/* Adjust spacing in data cells */
.my-grid igx-grid-cell {
    --ig-spacing: 0.9;
}
```

<DocsAside type="info">
Esses ajustes de espaçamento funcionam em conjunto com a densidade de exibição do grid. Os multiplicadores de espaçamento são aplicados aos valores base de espaçamento, que já são determinados pelo modo de densidade compacto, confortável ou espaçoso do grid.
</DocsAside>
