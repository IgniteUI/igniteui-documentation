# アップデート ガイド

Ignite UI for Angular の[バージョニング](https://github.com/IgniteUI/igniteui-angular/wiki/Ignite-UI-for-Angular-versioning)では、最初の数字は常にコードがサポートする Angular のメジャー バージョンと一致し、2 番目の数字はメジャー バージョン リリースに使用されます。メジャー リリース間で重大な変更が導入される場合があります。
**Ignite UI for Angular** の各リリースのすべての変更の一覧は、製品の [CHANGELOG](https://github.com/IgniteUI/igniteui-angular/blob/master/CHANGELOG.md) (英語) をご覧ください。

Ignite UI for Angular パッケージは、`ng update` Schematics による自動バージョン マイグレーションもサポートしています。Schematics は、可能なすべての重大な変更 (セレクター、クラス、@Input/Output プロパティの名前変更) のマイグレーションを試みますが、マイグレーションできない変更が残る場合もあります。通常、これらは TypeScript のアプリケーション ロジックに関連する変更で、[以下](#その他の手動の変更)で説明します。

はじめに [**`ng update`**](https://angular.io/cli/update) コマンドを実行して、アプリケーションとそのパッケージで利用可能なアップデートを確認します。

```cmd
ng update
```

**Ignite UI for Angular** ライセンス版パッケージをアップデートする場合は、以下のコマンドを実行してください。

```cmd
ng update @infragistics/igniteui-angular
```

**Ignite UI for Angular** 無料パッケージをアップデートする場合は、以下のコマンドを実行してください。

```cmd
ng update igniteui-angular
```

`@infragistics/igniteui-angular` または `igniteui-angular` を更新するときは、`@angular/core`、`@angular/cli` および `igniteui-cli` パッケージも一致するバージョンに更新することをお勧めします。
**Ignite UI CLI** パッケージをアップデートする場合は、以下のコマンドを実行してください。

```cmd
ng update igniteui-cli
```

**Angular Core** パッケージをアップデートする場合は、以下のコマンドを実行してください。

```cmd
ng update @angular/core
```

**Angular CLI** パッケージをアップデートするには、以下のコマンドを使用してください。

```cmd
ng update @angular/cli
```

<DocsAside type="info" title="情報">
パッケージの依存関係の不一致が原因で `ng update` コマンドが失敗した場合は、アップデートを元に戻し、`node_modules` フォルダーを削除してから、`--force` フラグを指定してアップデートを再実行します。
</DocsAside>

## その他の手動の変更

残念ながら、すべての変更を自動的にアップデートできるわけではありません。以下の変更は、変更が加えられたバージョンごとにセクションが分かれています。アップデートが必要な場合は、現在のバージョンのセクションから開始し、下から上の順にアップデートを適用してください。

例: 6.2.4 から 7.1.0 にアップデートする場合は、「6.x から ...」のセクションから始めて変更を適用し、上に向かって進めます。

## 22.2.x から 22.3.x の場合

Ignite UI for Angular 22.3.0 は Ignite UI Theming 30 (`igniteui-theming`) を使用します。Ignite UI Theming 30 の `palette()` 関数は、デフォルトで新しい `fitted` ジェネレーターを使用してパレットを作成します。`fitted` ジェネレーターはコントラストに基づいてすべてのシェードを配置し、固定の色として出力するため、同じ `palette()` 呼び出しでも、コンパイル後の色が以前とは変わります。`$light-material-palette` などの事前定義されたパレットとビルド済みの CSS テーマは `legacy` ジェネレーターを維持しており、変更はありません。両方のジェネレーターについては、[パレット生成](../themes/palette-generation.mdx)を参照してください。

`ng update` のマイグレーションは、`.scss` ファイルと `.sass` ファイル内の、ジェネレーターを選択していないすべての `palette()` 関数呼び出しに `$generator: 'legacy'` を追加します。これにより、パレットの色は維持されます。

```scss
// Before
$my-palette: palette(
  $primary: #0099ff,
  $secondary: #df1b74,
  $surface: #ffffff
);

// After
$my-palette: palette(
  $primary: #0099ff,
  $secondary: #df1b74,
  $surface: #ffffff,
  $generator: 'legacy'
);
```

マイグレーションは、パレットを CSS 変数として出力するミックスイン `@include palette(...)` を変更しません。また、`palette($args...)` のように引数を展開する呼び出しには引数を追加できません。そのような呼び出しは、`ng update` の出力の最後にファイルと行番号とともに報告されるため、展開するマップに `generator: 'legacy'` を手動で追加してください。

パレットを `fitted` ジェネレーターに移行するには、`$generator` 引数を削除します。引数を渡さずにすべての `palette()` 呼び出しで `legacy` ジェネレーターを使い続けるには、テーマ ライブラリがほかのモジュールから読み込まれる前に、次のように設定します。

```scss
@use "igniteui-theming" with ($shade-generator: 'legacy');
@use "igniteui-angular/theming" as *;
```

コンポーネント テーマは、背景を `--ig-surface-500` ではなく `base` サーフェス ロール (`--ig-surface-base`) から取得するようになりました。すべてのパレットは `base`、`sunken`、`raised`、`overlay`、`container` のサーフェス ロールを出力します。番号付きのサーフェス シェードは非推奨になりました。現在はどちらのジェネレーターでも引き続き出力され、`fitted` パレットでは `--ig-surface-500` が `--ig-surface-base` を参照しますが、番号付きのシェードは今後のリリースで削除されます。次の項目を手動で確認してください。

- 実行時に `--ig-surface-500` を上書きしている場合 (たとえば、セクションをダークなサーフェスに切り替える場合) は、代わりに `--ig-surface-base` を上書きし、使用している場合は `--ig-surface-raised`、`--ig-surface-overlay`、`--ig-surface-sunken` も上書きしてください。[パレット](../themes/palettes.mdx#ダークとライト)を参照してください。
- 独自のスタイルで `--ig-surface-500` または `color($color: 'surface', $variant: 500)` を参照している場合も、当面はそのまま動作します。番号付きのシェードが削除される前に、`base` を返す `color($color: 'surface')` などのサーフェス ロールに移行してください。
- 手動で作成したパレット マップを渡す場合は、その `surface` エントリにサーフェス ロールを追加してください。[カスタム パレット マップ](../themes/sass/palettes.mdx#カスタム-パレット-マップ)を参照してください。

## 22.0.x から 22.1.x の場合

Ignite UI for Angular 22.1.0 では、`tokens()` ミックスインへの移行が完了し、コンポーネントの構造スタイルが各コンポーネントのバンドルに移動しました。`ng update` のマイグレーションは、次の構文上の変更を自動的に実行します。

- 削除されたコンポーネントごとの Sass ラッパー ミックスイン (`avatar`、`badge`、`banner`、`card`、`dialog`、`tabs`、グリッドとピボットのミックスイン、およびこれまでに非推奨になったその他のラッパー) を `tokens()` に置き換えます。
- `badge-typography`、`dialog-typography`、`checkbox-typography` など、削除されたコンポーネントごとの `-typography` ミックスインの呼び出しを削除します。タイポグラフィは、コンポーネント トークンを通じて適用されるようになりました。コンポーネント固有の上書きについては、[タイポグラフィ](/themes/sass/typography#コンポーネント-タイポグラフィ)を参照してください。
- `igniteui-angular/lib/core/styles/components/avatar/avatar-component` などの構造パーシャルへの深い Sass インポートと、それに対応する `component()` 呼び出しを削除します。構造スタイルは、コンポーネント バンドルに自動的に含まれるようになりました。
- `IgxDividerDirective` の直接インポートと使用箇所の名前を `IgxDividerComponent` に変更します。`IgxDividerModule` は影響を受けません。

マイグレーション後の `tokens()` 呼び出しは手動で確認してください。マイグレーションでは、ラッパー ミックスインが通常のユニバーサル トークンの上書きを表していたのか、コンポーネント ローカルの宣言に依存していたのかを判断できません。テストやテーマの構造からローカル宣言が必要だとわかる場合を除き、生成されたデフォルト モードのままにしてください。ローカル宣言が必要な場合に限り、`$mode: 'scoped'` を追加します。

```scss
// Before
.my-avatar {
  @include avatar(avatar-theme($background: red));
}

// After
.my-avatar {
  @include tokens(
    avatar-theme($background: red),
    $mode: 'scoped'
  );
}
```

まずはデフォルトのグローバル モードを使用してください。ほとんどの `css-vars()` 呼び出しを置き換える場合も同様です。コンポーネントがグローバルな `theme()` の出力に含まれたままであれば、そのローカル宣言がユニバーサル トークンを参照できるため、通常はスコープ モードは必要ありません。

スコープ モードは、カスタマイズに必要なコンポーネント ローカルの宣言がデフォルトの出力で提供されない場合にのみ使用してください。代表的なケースは次のとおりです。

- 削除されたラッパーが完全なローカル テーマを構成しており、その動作がユニバーサル トークンの上書きだけでは維持されない場合。
- コンポーネントが、グローバルな `theme()` ミックスインの `$exclude` リストに含まれている場合。この場合、コンポーネントの構造スタイルシートが参照するローカル宣言は、グローバル テーマから出力されません。
- テーマがコンポーネント ローカルのサイズ式を使用している場合。グローバル モードでは、ローカルのサイズ変数に依存するサイズ値は意図的に省略されます。
- テーマ マップに、コンポーネント ホストとゴーストまたはオーバーレイのセレクターなど、複数のセレクターが含まれている場合。デタッチされたオーバーレイには、アウトレットにあるオーバーレイと一致するセレクターからテーマを適用する必要があります。通常は、グローバル スタイルシートで適用します。
- ローカル テーマでデザイン システムまたはライト/ダークのバリアントを変更する場合。スコープ モードで正しいテーマ メタデータが出力されるよう、対応する `$schema` をコンポーネント テーマ関数に渡してください。

スコープ モードをむやみに追加しないでください。通常の `--ig-<component>-*` の上書きには、アプリケーション全体に適用する場合もセレクターで範囲を限定する場合も、デフォルトのグローバル モードを使用します。コンポーネントのローカル宣言がこれらのユニバーサル トークンを参照できるよう、コンポーネントはグローバルな `theme()` の出力に含めたままにしておく必要があります。

```scss
@include tokens(
  avatar-theme(
    $schema: $dark-material-schema,
    $background: var(--ig-primary-500)
  )
);
```

スコープ モードを使用しても、`::ng-deep` が常に不要になるわけではありません。Angular のエミュレートされたビュー カプセル化により、ネストされた要素や内部要素向けに生成されたセレクターが一致しない場合があります。テストで必要とわかった箇所では `::ng-deep` を残すか、そのテーマの `@include` をグローバル スタイルシートに移動してください。デタッチされたオーバーレイでは `::ng-deep` だけでは不十分で、テーマがオーバーレイのアウトレットで一致するか、アウトレットに継承される必要があります。

Ignite UI のスタイルは、`ig.reset` → `ig.base` → 有効なデザイン システムのレイヤー (`ig.material`、`ig.bootstrap`、`ig.fluent`、`ig.indigo` のいずれか) → `ig.derived` のカスケード順序を使用するようになりました。アプリケーションでリセット用またはノーマライズ用のスタイルシートを読み込んでいる場合は、コンポーネントのスタイルを上書きしないよう、優先順位が最も低い reset レイヤーに配置してください。

```scss
@layer ig.reset {
  @import "minireset.css";
}
```

詳細については、[コンポーネント テーマ](/themes/sass/component-themes)と[グローバル テーマ](/themes/sass/global-themes#コンポーネントの除外)を参照してください。

## 21.1.x から 22.0.x の場合

Angular はタッチ ジェスチャー用の `HammerModule` の提供を終了しました。Ignite UI for Angular コンポーネントでタッチ操作 (パン、スワイプ、タップ) を引き続き使用するには、`angular.json` の `scripts` 配列で HammerJS をグローバル スクリプトとして読み込みます。

```json
"architect": {
  "build": {
    "options": {
      "scripts": [
        "node_modules/hammerjs/hammer.min.js"
      ]
    }
  }
}
```

グローバルに読み込まれると、Ignite UI for Angular は `window.Hammer` を自動検出してタッチ ジェスチャーの処理に使用します。追加のインポートやモジュール登録は不要です。

## 21.0.x から 21.1.x の場合

バージョン 21.1.0 には、Sass テーマ フレームワークの非推奨になった `css-vars` ミックスインの代わりに使用できる新しい `tokens` ミックスインが付属しています。一見すると表面的な変更ですが、新しい `tokens` ミックスインは、すべての Ignite UI フレームワークで機能する汎用的なグローバル コンポーネント テーマ トークンを生成します。`css-vars` ミックスインは非推奨になり、将来のバージョンで削除される予定です。そのため、できるだけ早く新しい `tokens` ミックスインに切り替えることをお勧めします。

`tokens` ミックスインは、汎用的な `--ig-*` フォールバック チェーンとローカル トークン参照の適切な書き換えを使用して、`global` または `scoped` モードでコンポーネントの CSS 変数トークンを生成します。

**グローバル モード** (デフォルト) - ユニバーサル `--ig-{component}-{property}` トークンを出力します。ローカルの `var()` 参照は対応するグローバル トークンに書き換えられるため、派生値 (例: `adaptive-contrast`) は任意のスコープで正しく解決されます。サイズ可能な式はスキップされるため、代わりに具体的な値を渡してください。

```scss
// 入力:
@include tokens(avatar-theme($background: red));

// 出力:
:root {
  --ig-avatar-background: red;
  /* ... 残りのアバター プロパティ ... */
}
```

**スコープ モード** - フォールバック チェーンを持つコンポーネント スコープ変数 (`--{property}`) を出力します。フォールバック チェーンは、構成されたプレフィックス (`--igx-*`) -> ユニバーサル (`--ig-*`) -> スキーマのデフォルトの順です。スタイルシートのルートから呼び出されると、テーマの `selector` がルールの作成に使用されます。セレクター内から呼び出されると、現在のセレクターとコンポーネント セレクターの両方が変数を受け取ります。つまり、非推奨になった `css-vars` ミックスインと同じ結果が得られます。

```scss
// 入力 (ルートから):
@include tokens(avatar-theme($background: red), $mode: 'scoped');

// 出力:
igx-avatar {
  --background: var(--igx-avatar-background, var(--ig-avatar-background, red));
  /* ... 残りのアバター プロパティ ... */
}
```

```scss
// 入力 (セレクター内から):
.my-theme {
  @include tokens(avatar-theme($background: red), $mode: 'scoped');
}

// 出力:
.my-theme,
.my-theme igx-avatar {
  --background: var(--igx-avatar-background, var(--ig-avatar-background, red));
  /* ... */
}
```

<DocsAside type="info" title="情報">
スコープ モードでは、適切な変数スコープのコンポーネント セレクターを決定するために、生成されたテーマ マップの `selector` プロパティが必要です。ミックスインがスタイルシートのルートから呼び出された場合、生成されたルールはテーマの内部 `selector` 値を使用します。セレクター内から呼び出された場合、そのセレクターとコンポーネント セレクターの両方が変数を受け取ります。
</DocsAside>

```scss
// グローバル オーバーライド:
:root {
  @include tokens(avatar-theme($background: orange));
}
// 結果: --ig-avatar-background: orange;

// スコープ消費 (明示的なオーバーライドなし):
@include tokens(avatar-theme($schema: $schema), $mode: 'scoped');
// 結果: --background は var(--igx-avatar-background, var(--ig-avatar-background, #000)) を通じて解決され、
//       --ig-avatar-background からグローバル オレンジ値を取得します。
```

<DocsAside type="info" title="情報">
**グローバル オーバーライドはスコープ モードに流れ込みます。** スコープ変数は `--ig-*` トークンにフォールバックするため、`:root` でグローバル トークンを設定すると、すべてのスコープ インスタンスに伝播されます。
</DocsAside>

## 20.x から 21.0.x の場合

### マルチ エントリ ポイントのサポート

バージョン 21.0.0 では、より効果的なツリー シェイキングとコード分割のために**マルチ エントリ ポイント**が導入されました。メイン エントリ ポイント (`igniteui-angular`) は完全な下位互換性を維持していますが、最適なバンドル サイズを得るためには、粒度の細かいエントリ ポイントへの移行が推奨されます。

**主な変更点:**
- コンポーネントが専用のエントリ ポイントに整理されました (例: `igniteui-angular/grids/grid`、`igniteui-angular/button`)
- 一部のコンポーネントの再配置 (入力ディレクティブ、オートコンプリート、ラジオ グループ)
- 型名の変更: `Direction` → `CarouselAnimationDirection`

**移行:**

更新時に、インポートを自動的に移行するかどうかを確認するプロンプトが表示されます。

```cmd
ng update igniteui-angular
```

プロンプトが表示されたら **「Yes」** を選択するか、後から次のコマンドで移行します。

```cmd
ng update igniteui-angular --migrate-only --from=20.1.0 --to=21.0.0
```

エントリ ポイント、移行オプション、重大な変更、および使用例の詳細については、[コード分割とマルチ エントリ ポイント ガイド](/general/code-splitting-and-multiple-entry-points)を参照してください。

### 依存性注入のリファクタリング

すべての内部依存性注入は `inject()` API を使用するようになりました。通常、アプリケーション コードには影響しませんが、Ignite UI コンポーネントやサービスを拡張している場合は、コンストラクターのパラメーターの代わりに `inject()` を使用するように、コンストラクターの更新が必要になる場合があります。

## 17.2.x から 18.0.x の場合

### 重大な変更

- バージョン 18.0.x では、非推奨の `displayDensity` プロパティが削除され、代わりにカスタム CSS プロパティ `--ig-size` が採用されました。詳細については、[16.0.x から 16.1.x へのアップデート ガイド](#160x-から-161x-の場合)を参照してください。

### 一般

- `IgxPivotGrid`

### 重大な変更

- ピボット グリッドの `showPivotConfigurationUI` プロパティが変更され、`pivotUI` に拡張されました。

```html
// version 17.2.x
<igx-pivot-grid [data]="data" [pivotConfiguration]="pivotConfig" [showPivotConfigurationUI]="false">
</igx-pivot-grid>

// version 18.0.x
<igx-pivot-grid [data]="data" [pivotConfiguration]="pivotConfig" [pivotUI]="{ showConfiguration: false }">
</igx-pivot-grid>
```

## 17.0.x から 17.1.x の場合

### 一般

**重大な変更**

- `IgxCombo` の `selectionChanging` イベント引数の型 `IComboSelectionChangingEventArgs` には、次の変更があります。

  - `added` と `removed` プロパティには、`valueKey` が設定されているかどうかに関係なく、常にデータ項目が含まれるようになりました。これにより、更新された `newSelection` および `oldSelection` プロパティと動作がそろいます。

`selectionChanging` イベント ハンドラーのコードがイベント引数からの `valueKeys` の読み取りに依存していた場合は、次のように更新します。

```typescript

    this.addedItems = e.added;
    this.removedItems = e.removed;
  }

  // version 17.0.x
  public handleSelectionChanging(e: IComboSelectionChangingEventArgs): void {
    this.addedItems = e.added.map(i => {
       return i[e.owner?.valueKey]
    });
    this.removedItems = e.removed.map(i => {
       return i[e.owner?.valueKey]
    });
  }
```

### テーマ設定

- Icon コンポーネントの `color` プロパティは非推奨になりました。デフォルトの色を変更するには、`style.color` CSS プロパティを使用してください。例:

```html
<igx-icon [style.color]="'#e41c77'">home</igx-icon>
```

```html
<igx-icon style.color="{{ col.hasSummary ? '#e41c77' : '' }}">functions</igx-icon>
```

- Sass モジュール:
テーマ エンジンは [Sass モジュール](https://sass-lang.com/documentation/at-rules/use)に切り替わりました。この変更により、すべてのテーマ ライブラリ関数 (コンポーネント テーマなど)、ミックスイン (コンポーネント ミックスインなど)、および変数が、単一のファイルから転送 (`forwarded`) されるようになりました。Sass テーマ ライブラリを正しく使用するには、プロジェクトで Dart Sass バージョン 1.33.0 以降を使用し、テーマ ライブラリのすべてのインポートを次の記述から:

```scss
// free version
@import '~igniteui-angular/lib/core/styles/themes/index';

// licensed version
@import '~@infragistics/igniteui-angular/lib/core/styles/themes/index';
```

次の記述に変更する必要があります:

```scss
// free version
@use 'igniteui-angular/theming' as *;

// licensed version:
@use '@infragistics/igniteui-angular/theming' as *;
```

テーマ ライブラリ全体を一度だけインポートし、アプリ内の他の Sass ファイルで使用する場合は、必ず転送 (forward) してください。インポートされた Sass ファイルは自動的には転送されません。

変更前:

```scss
// _variables.scss
// free version
@import '~igniteui-angular/lib/core/styles/themes/index';

// licensed version
@import '~@infragistics/igniteui-angular/lib/core/styles/themes/index';

// _other-file.scss
@import 'variables';
```

変更後:

```scss
// _variables.scss
// free versioin
@use 'igniteui-angular/theming' as *;
@forward 'igniteui-angular/theming';

// licensed version
@use '@infragistics/igniteui-angular/theming' as *;
@forward '@infragistics/igniteui-angular/theming';

// _other-file.scss
@use 'variables' as *;
```

- パレットとスキーマ:

- CSS パレット変数は HEX 値を参照しなくなり、代わりに H、S、L の 3 つの値のリストを表すようになりました。そのため、`hsl` または `hsla` CSS 関数に渡す必要があります。

変更前:

```scss
.some-class {
    background: var(--igx-surface-500); // returns HEX color
}
```

変更後:

```scss
.some-class {
    background: hsl(var(--igx-surface-500)); // returns a list of H, S, L
}
```

これは、CSS 変数のみを使用して実行時にパレットを変更できるようにするためです。これにより、基になるパレット カラーに影響を与えずに、特定のパレット カラーのアルファ チャネルを実行時に変更できます。

- カスタム コンポーネント テーマとグローバル テーマに、正しいパレットとコンポーネント スキーマが渡されていることを確認してください。グローバルなダーク テーマを作成する場合は、グレー カラーに明るい色合いを選択してください。例:

```scss
$my-dark-palette: palette(
    $primary: olive,
    $secondary: yellow,
    $grays: #fff
);

@include dark-theme($palette: $my-dark-palette);
```

同様に、ライト テーマには暗めのグレーの色合いとライト カラー スキーマが必要です。

グローバル テーマからコンポーネント テーマを除外していないものの、`css-vars` ミックスインを使用して独自のカスタム置換テーマを作成する場合は、テーマに正しいパレットと対応するスキーマが渡されていることを確認してください:

```scss
$my-custom-grid: grid-theme(
    $palette: $my-dark-palette,
    $schema: $dark-schema
);

@include css-vars($my-custom-grid);
```

- 除外されたコンポーネント テーマ:

グローバル テーマから一部のコンポーネント テーマを除外し、カスタム置換テーマを作成した場合は、コンポーネント ミックスインが含まれていて、正しいコンポーネント テーマが渡されていることを確認してください:

```scss
$my-dark-palette: palette(
    ...
    $exclude: ('igx-grid')
);

$my-custom-grid: grid-theme(
    $palette: $my-dark-palette,
    $schema: $dark-schema
);

// Ensuregrid is included:
@include grid($my-custom-grid);
```

カスタム コンポーネント テーマがグローバルな `styles.scss` 以外の別のコンポーネント Sass ファイルで宣言されている場合は、`core` ミックスインも含まれていることを確認してください。

```scss
// free version
@use 'igniteui-angular/theming' as *;

// licensed version
@use '@infragistics/igniteui-angular/theming' as *;

// Include the core module mixin.
@include core();

// Create your theme.
$my-custom-grid: grid-theme(
    $palette: $my-dark-palette,
    $schema: $dark-schema
);

// Include your custom theme styles.
@include grid($my-custom-grid);
```

Sass モジュール システムについて理解を深めるには、[Miriam Suzanne](https://css-tricks.com/author/miriam/) による[こちらの記事 (英語)](https://css-tricks.com/introducing-sass-modules/) を参照してください。

## 12.0.x から 12.1.x の場合

    ```html
    <igx-paginator #paginator>

            [My custom text]
            <igx-page-nav></igx-page-nav>
        </igx-paginator-content>
    </igx-paginator>
    ```

  - ページング コンポーネントの API はリファクタリング中に変更され、古いプロパティの多くは非推奨になりました。残念ながら、これらの変更の一部を適切に移行することは控えめに言っても複雑であるため、エラーはアプリケーション レベルで処理する必要があります。
  - 次のプロパティはグリッドで非推奨になりました:
    - paging、perPage page、totalPages、isFirstPage、isLastPage、pageChange、perPageChange、pagingDone
  - 次のメソッドも非推奨になりました:
    - nextPage()
    - previousPage()
  - 次のプロパティが削除されました:
    - paginationTemplate - カスタム テンプレートを定義するには、`igx-paginator-content` を使用します。
  - HierarchicalGrid 固有の変更 - RowIslands でページングを有効にする場合は、次のように `*igxPaginator` ディレクティブを使用する必要があります:

    ```html
        <igx-column *ngFor="let c of hColumns" [field]="c.field">
        </igx-column>
        <igx-row-island [key]="'childData'" [autoGenerate]="true">
            <igx-row-island [key]="'childData'" [autoGenerate]="true">
                <igx-paginator *igxPaginator></igx-paginator>
            </igx-row-island>
            <igx-paginator *igxPaginator></igx-paginator>
        </igx-row-island>
        <igx-row-island [key]="'childData2'" [autoGenerate]="true">

        </igx-row-island>
    ```

    _変更前:_


    _変更後:_

    ```html
    <igx-paginator #paginator *ngIf="!isPagerDisabled">
        <igx-paginator-content>
            <igx-page-size *ngIf="isDropdownHidden"></igx-page-size>
    ```

- グリッドの非推奨:
  - `IgxGridTransaction` を提供するための DI パターンは非推奨になりました。以下は引き続き機能しますが、将来のバージョンで**削除される可能性が高い**ため、リファクタリングすることをお勧めします:

    ```typescript
    @Component({
        template: `<igx-grid [data]="data">
        ...
        </igx-grid>`,
        providers: [{ provide: IgxGridTransaction, useClass: IgxTransactionService }],
        ...
    })
    export class MyCustomComponent {
        ...
    }
    ```

    上記の動作を実現するには、新しく追加された [`batchEditing`](/grid/batch-editing) 入力を使用する必要があります:

    ```typescript
    @Component({
        template: `<igx-grid [data]="data" [batchEditing]="true">
        ...
        </igx-grid>`
        ...
    })
    export class MyCustomComponent {
        ...
    }
    ```

### IgxGridCell の移行

- _IgxGridCellComponent_、_IgxTreeGridCellComponent_、_IgxHierarchicalGridCellComponent_、_IgxGridExpandableCellComponent_ はパブリック API で公開されなくなりました。

- 以前は上記のいずれかのインスタンスを返していたパブリック API は、<ApiLink type="GridCell" /> のインスタンスを返すようになりました:

```ts
const cell = grid.getCellByColumn(0, 'ProductID');     // returns IgxGridCell
const cell = grid.getCellByKey('ALFKI', 'ProductID');  // returns IgxGridCell
const cell = grid.getCellByColumnVisibleIndex(0, 0);   // returns IgxGridCell
const rowCells = grid.getRowByIndex(0).cells;          // returns IgxGridCell[]
const selectedCells = grid.selectedCells;              // returns IgxGridCell[]
const cells = grid.getColumnByName('ProductID').cells; // returns IgxGridCell[]
```

- _cellClick_、_selected_、_contextMenu_、および _doubleClick_ イベントによって発行される `IGridCellEventArgs` イベント引数の `cell` プロパティは、<ApiLink type="GridCell" /> のインスタンスになりました。
- セル テンプレートの `let-cell` プロパティは `IgxGridCell` になりました。
- `getCellByColumnVisibleIndex` は非推奨になり、次のメジャー バージョンで削除される予定です。代わりに `getCellByKey`、`getCellByColumn` を使用してください。

次の点に注意してください:

- _ng update_ は、_IgxGridCellComponent_、_IgxTreeGridCellComponent_、_IgxHierarchicalGridCellComponent_、_IgxGridExpandableCellComponent_ のインポート、型指定、キャストなどの使用箇所を移行します。上記のいずれかを使用しているコード内の箇所が移行されない場合は、型指定やキャストを削除するか、<ApiLink type="GridCell" /> に変更してください。
- _getCellByIndex_ などのメソッドは、そのインデックスの行がデータ行ではなく、IgxGroupByRow、IgxSummaryRow、詳細行などである場合、undefined を返します。

### テーマ

コンパイル時の警告に関する報告 ([#9793](https://github.com/IgniteUI/igniteui-angular/issues/9793) を参照) を受けて、[`math.div`](https://sass-lang.com/documentation/modules/math#div) 関数を使用するようになりました。この機能は、バージョン 1.33.0 以降の [Dart Sass (英語)](https://sass-lang.com/dart-sass) でサポートされています。

#### 解決方法

`math.div` が既知の関数ではないという Sass のコンパイル エラーが表示される場合は、プロジェクトで古いバージョンの Sass を使用しています。

1. `ng update` を使用して Angular を最新バージョンに更新します。Angular 12.1.0 以降は、デフォルトで dart-sass コンパイラーを使用します。

    ```sh
    ng update [options]
    ```

    何らかの理由で Ignite UI/Angular CLI を使用していない場合は、Node プロジェクトで `node-sass` を `sass` に置き換える必要があります。

    ```sh
    npm uninstall node-sass
    npm install sass --save-dev
    ```

2. 何らかの理由で、上記の方法で Angular の最新バージョンにアップグレードできない場合は、Sass ファイルにグローバル フラグを設定することで、古い Sass の除算方法にフォールバックできます:

    ```scss
    $__legacy-libsass: true;
    ```

## 11.1.x から 12.0.x の場合

### テーマ

- 重大な変更:
  - `IgxAvatar` テーマが簡略化されました。テーマ パラメーター (`avatar-theme`) の数が大幅に削減され、接頭辞付きのパラメーター (`icon-*`、`initials-*`、`image-*`) と接尾辞付きのパラメーター (`border-radius-*`) が含まれなくなりました。`ng update` による更新で既存のアバター テーマは移行されますが、接頭辞付きと接尾辞付きのパラメーターがなくなったことに対応するため、追加の調整が必要になる場合があります。

    既存のタイプ固有のアバター テーマを次のように変更する必要があります。

    たとえば、次のコードは:

    ```scss
    $avatar-theme: avatar-theme(
        $initials-background: blue,
        $initials-color: orange,
        $icon-background: blue,
        $icon-color: orange,
    );

    @include avatar($avatar-theme);
    ```

    次のように変換する必要があります:

    ```scss
    $initials-avatar: avatar-theme(
        $background: blue,
        $color: orange,
    );

    $icon-avatar: avatar-theme(
        $background: blue,
        $color: orange,
    );

    .initials-avatar {
        @include avatar($initials-avatar);
    }

    .icon-avatar {
        @include avatar($icon-avatar);
    }
    ```

  - `IgxButton` テーマが簡略化されました。テーマ パラメーター (`button-theme`) の数が大幅に削減され、接頭辞付きのパラメーター (`flat-*`、`raised-*` など) が含まれなくなりました。`ng update` による更新で既存のボタン テーマは移行されますが、接頭辞付きのパラメーターがなくなったことに対応するため、追加の調整が必要になる場合があります。

    以下のコード スニペットと同じ結果を得るには:

    ```html
    <button igxButton="raised">Raised button</button>
    <button igxButton="outlined">Outlined button</button>
    ```

    ```scss
    $my-button-theme: button-theme(
        $raised-background: red,
        $outlined-outline-color: green
    );

    @include css-vars($my-button-theme);
    ```

    ボタン タイプごとに個別のテーマを作成し、CSS セレクターにスコープする必要があります。

    ```html
    <div class="my-raised-btn">

    <button igxButton="raised">Raised button</button>
    
    </div>
    <div class="my-outlined-btn">

        <button igxButton="outlined">Outlined button</button>
    
    </div>
    ```

    ```scss
    $my-raised-button: button-theme(
        $background: red
    );

    $my-outlined-button: button-theme(
        $border-color: red
    );

    .my-raised-btn {
        @include css-vars($my-raised-button);
     }

    .my-outlined-btn {
        @include css-vars($my-outlined-button);
    }
    ```

    ご覧のとおり、`button-theme` のパラメーターはボタン タイプごとに同じ名前になったため、タイプごとに異なる色を使用するには、ボタン テーマを CSS セレクターにスコープする必要があります。

    `button-theme` の<ApiLink kind="sass" module="themes" type="function-button-theme" label="利用可能なすべてのプロパティ" />を参照してください。

  - `typography` ミックスインは、`core` に暗黙的に含まれなくなりました。タイポグラフィ スタイルを使用するには、`core` の後、`theme` の前にミックスインを明示的に含める必要があります:

    ```scss
    // in styles.scss

    @include core();

    @include typography(
        $font-family: $material-typeface,
        $type-scale: $material-type-scale
    );

    @include theme();
    ```

    <DocsAside type="info" title="情報">
    `core` ミックスインは常に最初に含める必要があります。
    </DocsAside>

    Ignite UI for Angular に含まれるテーマごとに、使用できる `font-family` 変数と `type-scale` 変数を提供しています:

| **テーマ** | **フォント ファミリ** | **タイプ スケール** |
| :-------- | :------------------ | :-------------------- |
| Material  | $material-typeface  | $material-type-scale  |
| Fluent    | $fluent-typeface    | $fluent-type-scale    |

### IgxBottomNav コンポーネント

<ApiLink type="BottomNav" label="**IgxBottomNavComponent**" /> は、タブ ヘッダーとコンテンツをより柔軟でわかりやすい方法で定義できるよう、完全にリファクタリングされました。既存の **igx-bottom-nav** 定義を新しい定義に移行するには、**ng update** で更新することをお勧めします。

- テンプレート
  - 新しい構造では、ヘッダー コンポーネントとコンテンツ コンポーネントをそれぞれラップする下部ナビゲーション項目コンポーネントを定義します。ヘッダーには通常、アイコン ([`マテリアル ガイドライン`](https://material.io/components/bottom-navigation#usage)) が含まれますが、ラベルやその他のカスタム コンテンツを含めることもできます。
  - ヘッダーのスタイル設定のために、`igxBottomNavHeaderLabel` と `igxBottomNavHeaderIcon` の 2 つの新しいディレクティブを導入しました。
  - ヘッダー コンポーネントで任意のコンテンツを追加できるようになったため、以前はタブのヘッダーを再テンプレート化するために使用されていた `igxTab` ディレクティブは、不要になったため削除されました。
  - コンポーネントをナビゲーション シナリオで使用する場合、`routerLink` ディレクティブをヘッダー コンポーネントにアタッチする必要があります。

    ```html
    <igx-bottom-nav>
        <igx-bottom-nav-item>
            <igx-bottom-nav-header>
                <igx-icon igxBottomNavHeaderIcon>folder</igx-icon>
                <span igxBottomNavHeaderLabel>Tab 1</span>
            </igx-bottom-nav-header>
            <igx-bottom-nav-content>
                Content 1
            </igx-bottom-nav-content>
        </igx-bottom-nav-item>
        ...
    </igx-bottom-nav>
    ```

- API の変更
  - `id`、`itemStyle`、`panels`、`viewTabs`、`contentTabs`、`tabs` プロパティが削除されました。現在は、<ApiLink type="BottomNav" member="items" label="items" /> プロパティがタブのコレクションを返します。
  - 次のプロパティが変更されました:
    - タブ項目の `isSelected` プロパティの名前が `selected` に変更されました。
    - `selectedTab` プロパティの名前が <ApiLink type="BottomNav" member="selectedItem" label="selectedItem" /> に変更されました。
  - `onTabSelected` および `onTabDeselected` イベントが削除されました。<ApiLink type="BottomNav" member="selectedIndexChanging" label="selectedIndexChanging" />、<ApiLink type="BottomNav" member="selectedIndexChange" label="selectedIndexChange" />、<ApiLink type="BottomNav" member="selectedItemChange" label="selectedItemChange" /> の 3 つの新しいイベントが導入されました。これらのイベントにより、タブの選択をより柔軟に制御できます。残念ながら、これらのイベント変更を適切に移行することは控えめに言っても複雑であるため、エラーはプロジェクト レベルで処理する必要があります。

### IgxTabs コンポーネント

<ApiLink type="Tabs" label="**IgxTabsComponent**" /> は、タブ ヘッダーとコンテンツをより柔軟でわかりやすい方法で定義できるよう、完全にリファクタリングされました。既存の **igx-tabs** 定義を新しい定義に移行するには、**ng update** で更新することをお勧めします。

- テンプレート
  - 新しい構造では、ヘッダー コンポーネントとコンテンツ コンポーネントをそれぞれラップするタブ項目コンポーネントを定義します。ヘッダーには通常、アイコンとラベルが含まれますが、その他のカスタム コンテンツを含めることもできます。
  - ヘッダーのスタイル設定のために、`igxTabHeaderLabel` と `igxTabHeaderIcon` の 2 つの新しいディレクティブを導入しました。
  - ヘッダー コンポーネントで任意のコンテンツを追加できるようになったため、以前はタブのヘッダーを再テンプレート化するために使用されていた `igxTab` ディレクティブは、不要になったため削除されました。
  - コンポーネントをナビゲーション シナリオで使用する場合、`routerLink` ディレクティブをヘッダー コンポーネントにアタッチする必要があります。

    ```html

        <igx-tab-item>
            <igx-tab-header>
                <igx-icon igxTabHeaderIcon>folder</igx-icon>
                <span igxTabHeaderLabel>Tab 1</span>
            </igx-tab-header>
            <igx-tab-content>
                <h1>Tab 1 Content</h1>
                <p>Lorem ipsum dolor sit amet, consectetur adipiscing elit.</p>
            </igx-tab-content>
        </igx-tab-item>
    ...
    </igx-tabs>
    ```

- API の変更
  - `id`、`groups`、`viewTabs`、`contentTabs`、および `tabs` プロパティが削除されました。現在は、<ApiLink type="Tabs" member="items" label="items" /> プロパティがタブのコレクションを返します。

    - タブ項目の `isSelected` プロパティの名前が <ApiLink type="TabItem" member="selected" label="selected" /> に変更されました。
    - `selectedTabItem` プロパティの名前が <ApiLink type="Tabs" member="selectedItem" label="selectedItem" /> に短縮されました。
    - contentFit と fixed のオプションを持つ `type` プロパティは使用できなくなりました。ヘッダーのサイズ設定と配置のモードは、現在は <ApiLink type="Tabs" member="tabAlignment" label="tabAlignment" /> 入力プロパティで制御します。この入力プロパティには、start (デフォルト)、center、end、justify の 4 つの値のいずれかを設定できます。以前の `contentFit` タイプは現在の `start` 配置値に対応し、以前の `fixed` タイプは現在の `justify` 値に対応します。
  - `tabItemSelected` および `tabItemDeselected` イベントが削除されました。<ApiLink type="Tabs" member="selectedIndexChanging" label="selectedIndexChanging" />、<ApiLink type="Tabs" member="selectedindexchange" label="selectedIndexChange" />、<ApiLink type="Tabs" member="selectedIndexChange" label="selectedItemChange" /> の 3 つの新しいイベントが導入されました。これらのイベントにより、タブの選択をより柔軟に制御できます。残念ながら、これらのイベント変更を適切に移行することは控えめに言っても複雑であるため、エラーはプロジェクト レベルで処理する必要があります。

### IgxGridComponent、IgxTreeGridComponent、IgxHierarchicalGridComponent

- _IgxGridRowComponent_、_IgxTreeGridRowComponent_、_IgxHierarchicalRowComponent_、_IgxGridGroupByRowComponent_ はパブリック API で公開されなくなりました。
- 以前は上記のいずれかのインスタンスを返していたパブリック API は、パブリックな <ApiLink type="RowType" kind="interface" /> インターフェイスを実装するオブジェクトを返すようになりました:

```ts
const row = grid.getRowByIndex(0);
const row = grid.getRowByKey(2);
const row = cell.row;
```

<ApiLink type="RowType" kind="interface" /> のパブリック API は、_IgxRowComponent_ などが公開していたものと同じですが、次の点に注意してください:

- _IgxHierarchicalRowComponent_ によって公開されていた _toggle_ メソッドは使用できません。すべての行タイプで <ApiLink kind="interface" type="RowType" member="expanded" /> プロパティを使用してください:

```ts
grid.getRowByIndex(0).expanded = false;
```

_row.rowData_ および _row.rowID_ は非推奨となり、バージョン 13 で完全に削除されます。代わりに _row.data_ と _row.key_ を使用してください。

- _onRowPinning_ によって発行されるイベント引数の _row_ プロパティ、および _onRowDragStart_、_onRowDragEnd_ によって発行されるイベント引数の _dragData_ プロパティは、<ApiLink type="RowType" kind="interface" /> を実装するようになりました。
- _ng update_ は、_IgxGridRowComponent_、_IgxTreeGridRowComponent_、_IgxHierarchicalRowComponent_、_IgxGridGroupByRowComponent_ のインポート、型指定、キャストなど、ほとんどの使用箇所を移行します。上記のいずれかを使用しているコード内の箇所が移行されない場合は、型指定やキャストを削除するか、<ApiLink type="RowType" kind="interface" /> に変更してください。
- _getRowByIndex_ は、そのインデックスの行が集計行である場合に <ApiLink type="RowType" kind="interface" /> オブジェクトを返すようになりました (以前は _undefined_ を返していました)。_row.isSummaryRow_ および _row.isGroupByRow_ は、そのインデックスの行が集計行またはグループ行の場合に true を返します。

### IgxInputGroupComponent

- `disabled` プロパティは削除されました。入力グループの状態は常に基になる `igxInput` によって管理されていたため、このプロパティは誤解を招くものでした。

    ```typescript
        public input: IgxInputDirective
        ...
        this.input.disabled = false;
    }
    ```

- IgxDrag

    ```typescript
    public targetDragged = false;

        this.targetDragged = false;
    ```

    **すべて**の選択イベントは、データ項目の `valueKey` プロパティの値で処理されます。
    `valueKey` が指定されているすべての Combo では、選択/双方向バインディングを、入力で指定されたオブジェクト プロパティの値のみで構成する必要があります:

    ```html
    <igx-combo [data]="cities" valueKey="id" displayKey="name"></igx-combo>
    ```

    ```typescript
    export class MyExampleCombo {
        public data: { name: string, id: string }[] = [{ name: 'London', id: 'UK01' }, { name: 'Sofia', id: 'BG01' }, ...];
        ...
        selectFavorites() {
            // Selection is handled with the data entries' id properties
            this.combo.selectItems(['UK01', 'BG01']);
        }
    }
    ```

    ```html
    <igx-combo [data]="cities" displayKey="name"></igx-combo>
    ```

    ```typescript
    export class MyExampleCombo {
        public data: { name: string, id: string }[] = [{ name: 'London', id: 'UK01' }, { name: 'Sofia', id: 'BG01' }, ...];
        ...
        selectFavorites() {
            // Selection is handled with references to the data entries
            this.combo.selectItems([this.data[0], this.data[1]]);
        }
    }
    ```

    Combo の設定の詳細については、[readme](https://github.com/IgniteUI/igniteui-angular/blob/master/projects/igniteui-angular/src/lib/combo/README.md#value-binding) (英語) および[公式ドキュメント](/inputs/combo/overview#値と選択)を参照してください。

## 7.3.x から 8.0.x の場合

- アップデート中に `Package "@angular/compiler-cli" has an incompatible peer dependency to "typescript" (requires ">=3.1.1 <3.3", would install "3.4.5").` というエラーが発生した場合は、最初に `@angular/core` パッケージを更新する必要があります。これは、既知の [Angular CLI の問題](https://github.com/angular/angular-cli/issues/13095) (英語) に関連しています。
- `igniteui-angular` パッケージの更新中に `Package "igniteui-angular" has an incompatible peer dependency to "web-animations-js" (requires "^2.3.1", would install "2.3.2-pr208")` というエラーが表示された場合は、`ng update igniteui-angular --force` を使用して更新する必要があります。これは、`igniteui-angular` を更新する前に `@angular/core` と `@angular/cli` を更新した場合に発生することがあります。

## 7.2.x または 7.3.x から 7.3.4 の場合

- `IgxGrid`、`IgxTreeGrid`、または `IgxHierarchicalGrid` の `filterGlobal` メソッドを使用している場合は、`condition` パラメーターが省略可能ではなくなったことに注意してください。無効な条件で `filterGlobal` メソッドを呼び出しても、すべての列の既存のフィルターはクリアされません。

## 7.1.x から 7.2.x の場合

- `combo.value` を使用して IgxCombo を使用している場合は、`combo.value` がゲッターのみになったことに注意してください。
- `IgxTextHighlightDirective` を使用している場合は、`page` 入力プロパティが非推奨になったことに注意してください。`IActiveHighlightInfo` インターフェイスの `rowIndex`、`columnIndex`、`page` プロパティも非推奨になりました。代わりに、省略可能な `row` プロパティと `column` プロパティが追加されています。
- `button-theme` を使用している場合は、`$button-roundness` が、ボタン タイプごとに `$flat-border-radius`、`$raised-border-radius`、`$outline-border-radius`、`$fab-border-radius`、`$icon-border-radius` に置き換えられたことに注意してください。

## 7.0.x から 7.1.x の場合

- アプリケーションで集計を含む IgxGrid を使用している場合は、集計行に必要な高さを計算するために、`IgxSummaryOperand.operate()` メソッドが空のデータで呼び出されるようになったことに注意してください。カスタム集計オペランドでは、このメソッドが常に適切な長さの IgxSummaryResult の配列を返す必要があります。

 バージョン 7.1 より前:

```typescript
export class CustomSummary extends IgxNumberSummaryOperand {
 public operate(data?: any[]): IgxSummaryResult[] {
  return [{
   key: 'average',
   label: 'average',
   summaryResult: IgxNumberSummaryOperand.average(data).toFixed(2)
  }];
 }
}
```

 バージョン 7.1 以降:

```typescript
export class CustomSummary extends IgxNumberSummaryOperand {
 public operate(data?: any[]): IgxSummaryResult[] {
  return [{
   key: 'average',
   label: 'average',
   summaryResult: data.length ?  IgxNumberSummaryOperand.average(data).toFixed(2) : null
  }];
 }
}
```

## 6.0.x から 6.1.x の場合

- アプリケーションで IgxCombo コントロールを使用していて、`itemsMaxWidth` オプションを設定している場合は、このオプションを `itemsWidth` に変更してください。
