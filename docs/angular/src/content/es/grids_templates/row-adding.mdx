# Añadir filas en {ComponentTitle} de Angular

<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">

El {ComponentTitle} ofrece una forma cómoda de realizar manipulaciones de datos mediante la adición de filas en línea y una API potente para las operaciones CRUD de Angular. Añada un componente [Action Strip](/action-strip) con las acciones de edición habilitadas en la plantilla de la cuadrícula, pase el cursor sobre una fila y use el botón proporcionado, o pulse <kbd>ALT</kbd> + <kbd>+</kbd> para mostrar la interfaz de adición de filas.
</ComponentBlock>
<ComponentBlock for="TreeGrid">

</ComponentBlock>

## Uso de la adición de filas

Para empezar, importe `{ComponentName}Module` en el archivo **app.module.ts**:

```typescript
// app.module.ts

...
import { {ComponentName}Module } from 'igniteui-angular';

@NgModule({
    ...
    imports: [..., {ComponentName}Module],
    ...
})
export class AppModule {}
```

A continuación, defina un {ComponentTitle} con el origen de datos enlazado y <ApiLink type="{ComponentApiType}" member="rowEditable" label="rowEditable" /> establecido en true, y un componente [Action Strip](../action-strip.mdx) con las acciones de edición habilitadas. La entrada <ApiLink type="GridEditingActions" member="addRow" label="addRow" /> controla la visibilidad del botón que muestra la interfaz de adición de filas.

## Iniciar la adición de filas mediante programación

{ComponentTitle} permite mostrar mediante programación la interfaz de añadir fila usando dos métodos públicos distintos. Uno acepta un ID de fila para especificar la fila debajo de la que debe mostrarse la interfaz, y otro funciona por índice. Puede usar estos métodos para mostrar la interfaz en cualquier punto de la vista de datos actual. No se admite cambiar de página ni especificar una fila que, por ejemplo, esté filtrada.

<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">
Usar `beginAddRowById` requiere que especifique la fila que se usará como contexto para la operación mediante su rowID (PK). El método funciona entonces como si el usuario final hubiera hecho clic en el botón de añadir fila del Action Strip para la fila especificada, mostrando la interfaz debajo de ella. También puede hacer que la interfaz aparezca como la primera fila del grid pasando `null` como primer parámetro.
</ComponentBlock>
<ComponentBlock for="TreeGrid">
Usar `beginAddRowById` requiere que especifique la fila que se usará como contexto para la operación mediante su rowID (PK). El método funciona entonces como si el usuario final hubiera hecho clic en el botón de añadir fila del Action Strip para la fila especificada, mostrando la interfaz debajo de ella. El segundo parámetro controla si la fila se añade como hija de la fila de contexto o como hermana. También puede hacer que la interfaz aparezca como la primera fila del grid pasando `null` como primer parámetro.
</ComponentBlock>

<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">

```typescript
this.grid.beginAddRowById('ALFKI');  // spawns the add row UI under the row with PK 'ALFKI'
this.grid.beginAddRowById(null);     // spawns the add row UI as the first record
```

</ComponentBlock>
<ComponentBlock for="TreeGrid">

```typescript
this.treeGrid.beginAddRowById('ALFKI', true);   // spawns the add row UI to add a child for the row with PK 'ALFKI'
this.treeGrid.beginAddRowById(null);            // spawns the add row UI as the first record
```

</ComponentBlock>

<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">

El método `beginAddRowByIndex` funciona de forma similar, pero requiere que especifique el índice _en_ el que debe mostrarse la interfaz. Los valores permitidos van de 0 al tamaño de la vista de datos menos 1.

```typescript
this.grid.beginAddRowByIndex(10);   // spawns the add row UI at index 10
this.grid.beginAddRowByIndex(0);    // spawns the add row UI as the first record
```

</ComponentBlock>
<ComponentBlock for="TreeGrid">

El método `beginAddRowByIndex` funciona de forma similar, pero la fila que se usará como contexto se especifica por índice.

```typescript
this.treeGrid.beginAddRowByIndex(10, true);   // spawns the add row UI to add a child for the row at index 10
this.treeGrid.beginAddRowByIndex(null);       // spawns the add row UI as the first record
```

</ComponentBlock>

## Posicionamiento

- La posición predeterminada de la interfaz de añadir fila es debajo de la fila para la que el usuario final hizo clic en el botón de añadir fila.

- {ComponentTitle} se desplaza automáticamente para mostrar por completo la interfaz de añadir fila.

- La superposición de la interfaz de añadir fila mantiene su posición durante el desplazamiento.

## Comportamiento

La interfaz de añadir fila tiene el mismo comportamiento que la de edición de filas, ya que están diseñadas para ofrecer una experiencia de edición coherente a los usuarios finales. Consulte el tema [{ComponentTitle} Row Editing](/{igPath}/row-editing) para más información.

Después de añadir una nueva fila a través de la interfaz de adición de filas, su posición o visibilidad se determina según el estado de ordenación, filtrado y agrupación de {ComponentTitle}. En un {ComponentTitle} que no tiene ninguno de estos estados aplicados, aparece como el último registro. Se muestra brevemente un snackbar con un botón que el usuario final puede usar para desplazar {ComponentTitle} hasta su posición si no está a la vista.

## Navegación por teclado

- <kbd>ALT</kbd> + <kbd>+</kbd>: entra en el modo de edición para añadir una fila
<ComponentBlock for="TreeGrid">

- <kbd>ALT</kbd> + <kbd>SHIFT</kbd> + <kbd>+</kbd>: entra en el modo de edición para añadir un hijo
</ComponentBlock>

- <kbd>ESC</kbd> sale del modo de adición de filas sin enviar ningún cambio

- <kbd>TAB</kbd> mueve el foco de una celda editable de la fila a la siguiente, y desde la celda editable más a la derecha a los botones CANCEL y DONE. La navegación desde el botón DONE va a la celda editable más a la izquierda de la fila que se está editando.

## Integración de funciones

- Cualquier operación de adición de filas se detendrá si cambia la vista de datos de {ComponentTitle}. Los cambios realizados por el usuario final se envían. Las operaciones que cambian la vista de datos incluyen, entre otras, la ordenación, la agrupación, el filtrado, la paginación, etc.

- Los resúmenes se actualizan después de terminar la operación de añadir fila. Lo mismo ocurre con las demás funciones que dependen de la vista de datos, como la ordenación, el filtrado, etc.
<ComponentBlock for="HierarchicalGrid">

- Al mostrar la interfaz en Hierarchical Grids, cualquier disposición hija que esté expandida actualmente para una fila en la que el usuario final hace clic en el botón de añadir fila se contrae.
</ComponentBlock>


## Personalizar la superposición de añadir fila

### Personalizar el texto

Es posible personalizar el texto de la superposición de añadir fila usando `igxRowAddTextDirective`.

```html
<ng-template igxRowAddText>
 Adding Row
</ng-template>
 ```

### Personalizar los botones

Es posible personalizar los botones de la superposición de edición de filas usando `igxRowEditActionsDirective`.
Si quiere que los botones formen parte de la navegación por teclado, cada uno de ellos debe tener `igxRowEditTabStopDirective`.

 ```html
 <ng-template igxRowEditActions let-endRowEdit>
 <button igxButton igxRowEditTabStop (click)="endRowEdit(false)">Cancel</button>
 <button igxButton igxRowEditTabStop (click)="endRowEdit(true)">Apply</button>
</ng-template>
 ```

<DocsAside type="info">
Usar la directiva `igxRowEditActions` cambiará las acciones de edición tanto de los botones de la superposición de edición como de la de adición.
</DocsAside>

## Escenarios remotos

En la mayoría de los escenarios de datos remotos, la asignación de la clave primaria se produce en la solicitud de creación al servidor. En este caso, los registros añadidos en el cliente no tendrán el valor final de la clave primaria hasta que se guarden en la base de datos del servidor. En ese caso, la forma recomendada de gestionar esta actualización en {ComponentTitle} es la siguiente:

- Si {ComponentTitle} no usa transacciones.

    Cuando la solicitud de creación se completa correctamente y devuelve los datos del registro añadido, puede reemplazar el id de ese registro en la instancia de registro de datos local.

- Si {ComponentTitle} usa transacciones.

    Cuando la solicitud de creación o de actualización por lotes se completa correctamente y devuelve las instancias de registro añadidas (con sus ids generados por la base de datos), las transacciones ADD relacionadas deben borrarse del registro de transacciones usando el método de la API <ApiLink kind="interface" type="TransactionService" member="clear" />. Esto es necesario porque la transacción local tendrá un campo id generado, que puede ser distinto del creado en la base de datos, así que deben borrarse. Después puede añadir el registro o registros incluidos en la respuesta a la instancia de datos local.

Así se garantiza que los ids generados de forma remota siempre se reflejen en los datos locales, y que las operaciones posteriores de actualización o eliminación apunten a los ids de registro correctos.
