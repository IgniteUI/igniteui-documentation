## Virtualización remota

<ApiLink type="{ComponentApiType}" /> admite el escenario en el que los fragmentos de datos se solicitan a un servicio remoto, exponiendo el comportamiento implementado en la directiva <ApiLink type="ForOfDirective" label="igxForOf" /> que usa internamente.

Para usar esta función, debe suscribirse a la salida <ApiLink type="{ComponentApiType}" member="dataPreLoad" label="dataPreLoad" /> para realizar la solicitud adecuada según los argumentos recibidos, así como establecer la propiedad pública <ApiLink type="{ComponentApiType}" /> <ApiLink type="{ComponentApiType}" member="totalItemCount" label="totalItemCount" /> con la información correspondiente procedente del servicio.

```html
<igx-grid #grid [data]="remoteData | async" [autoGenerate]="false"
          (dataPreLoad)="processData(false)"
          (sortingDone)="processData(true)">
    <igx-column [field]="'ProductID'" [sortable]="true"></igx-column>
    <igx-column [field]="'ProductName'" [sortable]="true"></igx-column>
    <igx-column [field]="'UnitPrice'" [dataType]="'number'" [formatter]="formatCurrency" [sortable]="true"></igx-column>
</igx-grid>
```

## Desplazamiento infinito

 Un diseño muy habitual en los escenarios que requieren obtener datos por fragmentos desde un punto final es el denominado desplazamiento infinito. En las cuadrículas de datos se caracteriza por el aumento continuo de los datos cargados, provocado por el usuario final al desplazarse hasta el final. Los siguientes párrafos explican cómo puede usar la API disponible para lograr fácilmente el desplazamiento infinito en `IgxGrid`.

Para implementar el desplazamiento infinito, debe obtener los datos por fragmentos. Los datos que ya se han obtenido deben almacenarse localmente, y debe determinar la longitud de un fragmento y cuántos fragmentos hay. También debe llevar un registro del índice de la última fila de datos visible en la cuadrícula. De este modo, usando las propiedades `startIndex` y `chunkSize`, puede determinar si el usuario se desplaza hacia arriba, en cuyo caso debe mostrar los datos ya obtenidos, o hacia abajo, en cuyo caso debe obtener más datos del punto final.

Lo primero que hay que hacer es usar el hook de ciclo de vida `ngAfterViewInit` para obtener el primer fragmento de datos. Es importante establecer la propiedad `totalItemCount`, ya que permite a la cuadrícula dimensionar correctamente su barra de desplazamiento.

```typescript
public ngAfterViewInit() {
    this._remoteService.loadDataForPage(this.page, this.pageSize, (request) => {
        if (request.data) {
            this.grid.totalItemCount = this.page * this.pageSize;
            this.grid.data = this._remoteService.getCachedData({startIndex: 0, chunkSize: 10});
            this.totalItems = request.data['@odata.count'];
            this.totalPageCount = Math.ceil(this.totalItems / this.pageSize);
            this.grid.isLoading = false;
        }
    });
}
```

Además, debe suscribirse a la salida `dataPreLoad`, para poder proporcionar al grid los datos que necesita cuando intenta mostrar un fragmento distinto del cargado actualmente. En el controlador del evento, debe determinar si debe obtener datos nuevos o devolver datos que ya están en caché local.

```typescript
public handlePreLoad() {
    const isLastChunk = this.grid.totalItemCount ===
                        this.grid.virtualizationState.startIndex + this.grid.virtualizationState.chunkSize;
    // when last chunk reached load another page of data
    if (isLastChunk) {
        if (this.totalPageCount === this.page) {
            this.grid.data = this._remoteService.getCachedData(this.grid.virtualizationState);
            return;
        }
        this.page++;
        this.grid.isLoading = true;
        this._remoteService.loadDataForPage(this.page, this.pageSize, (request) => {
            if (request.data) {
                this.grid.totalItemCount = Math.min(this.page * this.pageSize, this.totalItems);
                this.grid.data = this._remoteService.getCachedData(this.grid.virtualizationState);
                this.grid.isLoading = false;
            }
        });
    } else {
        this.grid.data = this._remoteService.getCachedData(this.grid.virtualizationState);
    }
}
```

## Ordenación/filtrado remoto

Para proporcionar ordenación y filtrado remotos, debe suscribirse a las salidas <ApiLink type="{ComponentApiType}" member="dataPreLoad" label="dataPreLoad" />, <ApiLink type="{ComponentApiType}" member="sortingExpressionsChange" label="sortingExpressionsChange" /> y <ApiLink type="{ComponentApiType}" member="filteringexpressionstreechange" label="filteringExpressionsTreeChange" />, para realizar la solicitud adecuada según los argumentos recibidos, así como establecer la propiedad pública <ApiLink type="{ComponentApiType}" /> <ApiLink type="{ComponentApiType}" member="totalItemCount" label="totalItemCount" /> con la información correspondiente procedente del servicio.

También aprovecharemos la función **rxjs** `debounceTime`, que emite un valor del Observable de origen solo después de que haya pasado un periodo de tiempo concreto sin que se emita otro valor. Así, la operación remota solo se disparará cuando haya transcurrido el tiempo especificado sin que el usuario la interrumpa.

```typescript
const DEBOUNCE_TIME = 300;
...
public ngAfterViewInit() {
    ...
    this.grid.dataPreLoad.pipe(
        debounceTime(DEBOUNCE_TIME),
        takeUntil(this.destroy$)
    ).subscribe(() => {
        this.processData();
    });

    this.grid.filteringExpressionsTreeChange.pipe(
        debounceTime(DEBOUNCE_TIME),
        takeUntil(this.destroy$)
    ).subscribe(() => {
        this.processData(true);
    });

    this.grid.sortingExpressionsChange.pipe(
        debounceTime(DEBOUNCE_TIME),
        takeUntil(this.destroy$)
    ).subscribe(() => {
        this.processData();
    });
}
```

Cuando se proporcionan ordenación y filtrado remotos, normalmente no necesitamos la ordenación y el filtrado integrados de la cuadrícula. Podemos deshabilitarlos estableciendo las entradas <ApiLink type="{ComponentApiType}" member="sortStrategy" label="sortStrategy" /> y <ApiLink type="{ComponentApiType}" member="filterStrategy" label="filterStrategy" /> de la cuadrícula en las instancias `NoopSortingStrategy` y `NoopFilteringStrategy` respectivas.

```html
<igx-grid #grid [data]="remoteData | async" [height]="'500px'" [width]="'100%'" [autoGenerate]='false'
        [filterStrategy]="noopFilterStrategy"
        [sortStrategy]="noopSortStrategy"
        [allowFiltering]="true">
    ...
</igx-grid>
```

```typescript
public noopFilterStrategy = NoopFilteringStrategy.instance();
public noopSortStrategy = NoopSortingStrategy.instance();
```

### Filtrado remoto

Para proporcionar filtrado remoto, debe suscribirse a la salida <ApiLink type="{ComponentApiType}" member="filteringExpressionsTreeChange" label="filteringExpressionsTreeChange" /> para realizar la solicitud adecuada según los argumentos recibidos. Usemos una colección plana como origen de datos de nuestro Tree Grid proporcionando un <ApiLink type="{ComponentApiType}" member="primaryKey" label="primaryKey" /> y un <ApiLink type="{ComponentApiType}" member="foreignKey" label="foreignKey" />.

También aprovecharemos la función **rxjs** `debounceTime`, que emite un valor del Observable de origen solo después de que haya pasado un periodo de tiempo concreto sin que se emita otro valor. Así, la operación remota solo se disparará cuando haya transcurrido el tiempo especificado sin que el usuario la interrumpa.

```typescript
const DEBOUNCE_TIME = 300;
...
public ngAfterViewInit() {
    ...
    this.treeGrid.filteringExpressionsTreeChange.pipe(
        debounceTime(DEBOUNCE_TIME),
        takeUntil(this.destroy$)
    ).subscribe(() => {
        this.processData();
    });
}
```

### Estrategia de valores únicos de columna

</ComponentBlock>

Los elementos de la lista del cuadro de diálogo de filtrado al estilo de Excel representan los valores únicos de la columna correspondiente. De forma predeterminada, {ComponentTitle} genera estos valores a partir de su origen de datos. En el caso del filtrado remoto, los datos del grid no contienen todos los datos del servidor. Para proporcionar los valores únicos manualmente y cargarlos a demanda, podemos aprovechar la entrada <ApiLink type="{ComponentApiType}" member="uniqueColumnValuesStrategy" label="uniqueColumnValuesStrategy" /> de {ComponentTitle}. Esta entrada es en realidad un método que proporciona tres argumentos:

- **column**: la instancia de la columna correspondiente.
- **filteringExpressionsTree**: el árbol de expresiones de filtrado, que se reduce según la columna correspondiente.
- **done**: callback que debe llamarse con los valores de columna recién generados cuando se recuperen del servidor.

El desarrollador puede generar manualmente los valores únicos de columna necesarios según la información proporcionada por los argumentos **column** y **filteringExpressionsTree**, y después invocar el callback **done**.

<DocsAside type="info">
Cuando se proporciona la entrada <ApiLink type="{ComponentApiType}" member="uniqueColumnValuesStrategy" label="uniqueColumnValuesStrategy" />, no se usará el proceso predeterminado de generación de valores únicos del filtrado al estilo de Excel.
</DocsAside>

## Paginación remota

<ComponentBlock for="Grid, HierarchicalGrid">

La función de paginación puede funcionar con datos remotos. Para demostrarlo, declaremos primero nuestro servicio, responsable de la obtención de datos. Necesitaremos el número de todos los elementos de datos para calcular el número de páginas. Esta lógica se añadirá a nuestro servicio.

```typescript
@Injectable()
export class RemotePagingService {
    public remoteData: BehaviorSubject<any[]>;
    public dataLenght: BehaviorSubject<number> = new BehaviorSubject(0);
    public url = 'https://www.igniteui.com/api/products';

    constructor(private http: HttpClient) {
        this.remoteData = new BehaviorSubject([]) as any;
    }

    public getData(index?: number, perPage?: number): any {
        let qS = '';

        if (perPage) {
            qS = `?$skip=${index}&$top=${perPage}&$count=true`;
        }

        this.http
            .get(`${this.url + qS}`).pipe(
                map((data: any) => data)
            ).subscribe((data) => this.remoteData.next(data));
    }

    public getDataLength(): any {
        return this.http.get(this.url).pipe(
            map((data: any) => data.length)
        );
    }
}
```

Después de declarar el servicio, debemos crear un componente, responsable de la construcción de {ComponentTitle} y de la suscripción a los datos.

### Paginación remota con la plantilla predeterminada

Si quiere usar la _plantilla de paginación predeterminada_, debe establecer la propiedad <ApiLink type="Paginator" member="totalRecords" label="totalRecords" /> del Paginator; solo entonces el grid podrá calcular el _número total de páginas_ a partir de los registros remotos totales. Al realizar una paginación remota, el Paginator solo pasará al grid los datos de la página actual, de modo que el grid no intentará paginar el origen de datos proporcionado. Por eso debemos establecer la propiedad <ApiLink type="{ComponentApiType}" member="pagingMode" label="pagingMode" /> del grid en _GridPagingMode.remote_. Además, es necesario suscribirse a los eventos <ApiLink type="Paginator" member="pagingDone" label="pagingDone" /> o <ApiLink type="Paginator" member="perPageChange" label="perPageChange" /> para obtener los datos de su servicio remoto; qué evento se usa depende del caso de uso.

```typescript
@ViewChild('grid1', { static: true }) public grid1: IgxGridComponent;

public ngAfterViewInit() {
    this.grid1.isLoading = true;
    this.remoteService.getData(0, this.perPage);
}

public nextPage() {
    this.firstPage = false;
    this.page++;
    const skip = this.page * this.perPage;
    const top = this.perPage;
    this.remoteService.getData(skip, top);
    if (this.page + 1 >= this.totalPages) {
        this.lastPage = true;
    }
    this.setNumberOfPagingItems(this.page, this.totalPages);
}

public previousPage() {
    this.lastPage = false;
    this.page--;
    const skip = this.page * this.perPage;
    const top = this.perPage;
    this.remoteService.getData(skip, top);
    if (this.page <= 0) {
        this.firstPage = true;
    }
    this.setNumberOfPagingItems(this.page, this.totalPages);
}

public paginate(page: number, recalculate = false) {
    this.page = page;
    const skip = this.page * this.perPage;
    const top = this.perPage;
    if (recalculate) {
        this.totalPages = Math.ceil(this.totalCount / this.perPage);
    }
    this.setNumberOfPagingItems(this.page, this.totalPages);
    this.remoteService.getData(skip, top);
    this.buttonDeselection(this.page, this.totalPages);
}
```

### Paginación remota con edición por lotes

Con los ejemplos vistos hasta ahora hemos aclarado cómo configurar {ComponentName} con datos remotos. Ahora centrémonos en habilitar la edición por lotes del grid siguiendo la [guía o tema de edición por lotes](/{igPath}/batch-editing).

Antes de continuar con el ejemplo conviene aclarar el caso de uso actual. Cuando la paginación se realiza en el servidor, el grid contiene los datos solo de la página actual, y si añadimos filas nuevas, las filas añadidas (con edición por lotes) se concatenarán con los datos actuales del grid. Por tanto, si el servidor no devuelve datos para una página determinada, el origen de datos del grid estará compuesto solo por las filas recién añadidas, que el grid paginará según la configuración de paginación definida (page, perPage).

```typescript
public ngOnInit() {
    this._dataLengthSubscriber = this.remoteService.getDataLength().subscribe((data) => {
        this.totalCount = data;
        this._recordOnServer = data;
        this._totalPagesOnServer = Math.floor(this.totalCount / this.perPage);
        this.grid1.isLoading = false;
    });
}
```

Para gestionar correctamente este caso de uso, necesitamos implementar cierta lógica personalizada.
Primero, tenemos que conocer el número total de registros que hay en el servidor. Con ese dato, calculamos el número total de páginas de datos en el servidor (véase `this._totalPagesOnServer`) y, según su valor, implementaremos la lógica de paginación personalizada.

```typescript

public paginate(page: number) {
    this.grid1.endEdit(true);
    if (page > this._totalPagesOnServer) {
        if (this.page !== this._totalPagesOnServer) {
            const skipEl = this._totalPagesOnServer * this.perPage;
            this.remoteService.getData(skipEl, this.perPage);
        }
        this.page = page - this._totalPagesOnServer;
        this.page = page;
        return;
    } else {
        this.page = 0;
    }
    this.page = page;
    const skip = this.page * this.perPage;
    this.remoteService.getData(skip, this.perPage);
}

```

Como puede ver en el método **paginate**, se realiza la lógica de paginación personalizada según el valor de `_totalPagesOnServer`.

## Problemas conocidos y limitaciones

- Cuando el grid no tiene `primaryKey` establecido y los escenarios de datos remotos están habilitados (cuando la paginación, la ordenación, el filtrado o el desplazamiento provocan solicitudes a un servidor remoto para obtener los datos que se mostrarán en el grid), una fila perderá el siguiente estado tras completarse una solicitud de datos:
  - Selección de filas
  - Expandir/contraer filas
  - Edición de filas
  - Anclaje de filas
- En escenarios de datos remotos, cuando el grid tiene un `primaryKey` establecido, el argumento del evento <ApiLink kind="interface" type="IRowSelectionEventArgs" member="oldSelection" /> no contendrá el objeto completo de datos de la fila para las filas que están actualmente fuera de la vista de datos. En este caso, el objeto `rowSelectionChanging.oldSelection` contendrá solo una propiedad, que es el campo `primaryKey`. Para el resto de filas, que están en la vista de datos, `rowSelectionChanging.oldSelection` contendrá los datos completos de la fila.
