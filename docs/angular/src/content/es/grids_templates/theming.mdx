# Temas de {ComponentTitle} en Angular

El {ComponentTitle} de Ignite UI for Angular se tematiza mediante <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} />, que deriva cada color a partir de un token de fondo, de primer plano y de acento. Esos tres tokens primarios llegan a todo lo que renderiza el componente: el encabezado, las filas, los bordes, los resúmenes, la barra de herramientas, el paginador y los menús emergentes de filtrado.

<DocsAside type="info">
No hay una función de tema independiente por grid. Data Grid, Tree Grid, Hierarchical Grid y Pivot Grid usan todos `grid-theme()`, de modo que el mismo tema se aplica a cualquiera de ellos sin modificaciones.
</DocsAside>

## Primeros pasos

Importe el punto de entrada de temas, donde se exportan las funciones de tema y el mixin `tokens()`:

```scss
@use "igniteui-angular/theming" as *;
```

Después, declare un tema e inclúyalo en el elemento que quiera afectar:

```scss
:host {
  @include tokens(grid-theme(
    $background: #08002e,
    $accent-color: #ff7d52
  ));
}
```

Eso es un tema completo. El {ComponentTitle} es ahora índigo oscuro con un acento coral, y el texto, el encabezado, los bordes de las filas, los estados al pasar el ratón, los tintes de selección y el aspecto de los menús emergentes se han calculado automáticamente.

## Tokens primarios

El tema {ComponentTitle} se construye a partir de tres tokens; todos los demás colores se derivan de ellos.

| Token | Qué controla |
| -- | -- |
| `$background` | La superficie sobre la que se construye todo el componente. Todas las demás superficies y el primer plano predeterminado se derivan de ella. |
| `$foreground` | Texto e iconos. Se deriva de `$background` por contraste cuando no se establece. |
| `$accent-color` | Color interactivo: indicadores de ordenación, selección, tintes al pasar el ratón, foco. |

`$foreground` figura como primario, pero rara vez necesita establecerse. Si no se toca, se elige por contraste con el fondo, de modo que un fondo oscuro produce texto claro y uno claro produce texto oscuro sin necesidad de una segunda declaración.

## Cómo funciona la derivación

Cuando declara un tema, los tokens derivados no se resuelven en colores fijos durante la compilación. Se emiten como expresiones CSS sobre los tokens primarios que usted ha proporcionado:

```css
.my-grid {
  --ig-grid-foreground: hsla(from color(from var(--ig-grid-background) var(--y-contrast)) h 0 l/1);
  --ig-grid-header-background: color-mix(in srgb, var(--ig-grid-foreground) 6%, var(--ig-grid-background));
  --ig-grid-row-hover-background: color-mix(in srgb, var(--ig-grid-accent-color) 8%, var(--ig-grid-row-odd-background));
  --ig-grid-sorted-header-icon-color: hsl(from var(--ig-grid-accent-color) h s l/0.7);
}
```

De ello se derivan dos consecuencias. Cambiar un token primario recalcula todo lo que depende de él, incluso en tiempo de ejecución mediante propiedades personalizadas CSS. Y las relaciones se mantienen con cualquier valor que proporcione, de modo que un tema no puede desincronizarse consigo mismo.

## Profundizando

Algunos tokens son raíces de derivación por derecho propio. Al declarar uno, se separa del fondo, y lo que se apoya en él se deriva del nuevo valor.

`$header-background` es el ejemplo más claro. Si no se toca, se mezcla a partir de `$background`, y el texto del encabezado sigue a `$foreground`. Si lo declara, el texto del encabezado se vuelve a derivar para tomar contraste con el propio encabezado:

```scss
:host {
  @include tokens(grid-theme(
    $background: #08002e,
    $accent-color: #ff7d52,
    $header-background: #ff7d52
  ));
}
```

<DocsAside type="note">
Recurra a estos tokens solo cuando quiera que una superficie deje de seguir al fondo. La mayoría de los tokens que el tema documenta como derivados automáticamente conviene dejarlos como están: sobrescribir uno fija un valor que, de otro modo, seguiría sincronizado con el resto del tema.
</DocsAside>

## Estructura

El color es solo la mitad de un tema. La densidad y el redondeo se controlan mediante tokens globales del sistema de diseño, en lugar de parámetros de `grid-theme()`, por lo que se establecen como propiedades personalizadas sencillas:

```scss
:host {
  --ig-size: var(--ig-size-small);   // small | medium | large
  --ig-radius-factor: 0;             // 0 to 1

  @include tokens(grid-theme(
    $background: #08002e,
    $accent-color: #ff7d52
  ));
}
```

Las líneas de cuadrícula son parámetros del tema. Para ocultar una, tíñala con el color de la superficie que tiene detrás en lugar de eliminarla, de modo que las métricas de las filas no cambien entre temas:

```scss
@include tokens(grid-theme(
  // horizontal dividers, blended away
  $row-border-color: var(--ig-grid-background),
  // vertical dividers, drawn in the same color the theme derives for rows
  $body-column-border-color-odd: hsl(from color-mix(in srgb, var(--ig-grid-foreground) 16%, var(--ig-grid-background)) h s l/0.38),
  $body-column-border-color-even: hsl(from color-mix(in srgb, var(--ig-grid-foreground) 16%, var(--ig-grid-background)) h s l/0.38)
));
```

## Componentes dentro de {ComponentTitle}

{ComponentTitle} también aplica el tema a los componentes que renderiza: selectores de fila, chips, distintivos, botones, campos de entrada, desplegables, información emergente, el paginador, la barra de herramientas y los menús emergentes de filtrado. Declara sus propios tokens en su host, derivados de sus tokens primarios, de modo que los tokens establecidos para esos componentes en un ancestro no les llegan. `.promo { @include tokens(checkbox-theme($fill-color: #ff7d52)); }` cambia el color de las casillas de `.promo`, pero no de los selectores de fila de un {ComponentTitle} que contiene.

Para cambiar el color de los componentes internos, aplique el tema a {ComponentTitle}. Cada componente interno sigue uno o más de sus tokens primarios. El color de acento llega a los selectores de fila, los distintivos, los botones y los campos de entrada, mientras que las informaciones emergentes siguen al primer plano y los chips siguen al fondo y al primer plano a la vez:

```scss
.promo {
  @include tokens(grid-theme($accent-color: #ff7d52));
}
```

Para sobrescribir un componente sin cambiar los colores de {ComponentTitle}, apunte a ese componente. Los tokens declarados en el propio componente prevalecen sobre los que declara {ComponentTitle}:

```scss
.promo igx-checkbox {
  @include tokens(checkbox-theme($fill-color: #ff7d52));
}

.promo .igx-tooltip {
  @include tokens(tooltip-theme($background: #ff7d52));
}
```

## Variables CSS

El aspecto predeterminado es deliberado y no derivado: de serie, {ComponentTitle} coincide exactamente con la especificación de diseño de Ignite UI, resolviéndose según la paleta base en lugar de calcular colores a partir de un fondo. La derivación es lo que se activa cuando declara un tema propio.

Esto tiene una consecuencia práctica para el tema solo con CSS. Hasta que se declare un tema no hay expresiones derivadas que sobrescribir: el componente lee `var(--ig-grid-header-background, var(--ig-gray-100))` y sus equivalentes; por tanto, establecer un par de propiedades personalizadas a mano **no** se propaga en cascada:

```css
/* Not enough on its own: the background changes, the header stays grey. */
.my-grid {
  --ig-grid-background: #08002e;
  --ig-grid-accent-color: #ff7d52;
}
```

Para aplicar el tema sin una compilación de Sass, declare el **conjunto completo de tokens**: las raíces más las expresiones derivadas que las referencian. Ese bloque es autónomo, porque cada token derivado es una expresión sobre las raíces:

```css
.my-grid {
  --ig-grid-background: #08002e;
  --ig-grid-accent-color: #ff7d52;
  --ig-grid-foreground: hsla(from color(from var(--ig-grid-background) var(--y-contrast)) h 0 l/1);
  --ig-grid-header-background: color-mix(in srgb, var(--ig-grid-foreground) 6%, var(--ig-grid-background));
  /* … and the rest of the theme's tokens */
}
```

Generar eso a mano no es práctico, así que use el playground de abajo: emite el bloque completo para los colores que elija.

<DocsAside type="note">
Prefiera la vía de Sass siempre que pueda. `grid-theme()` escribe los tokens derivados por usted y los mantiene sincronizados con la biblioteca; un bloque CSS mantenido a mano es una instantánea que no recogerá los cambios del tema.
</DocsAside>
