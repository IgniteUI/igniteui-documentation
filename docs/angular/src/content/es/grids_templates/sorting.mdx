# Ordenación de {ComponentTitle} en Angular

En Ignite UI for Angular {ComponentTitle}, la ordenación de datos se habilita por columna, lo que significa que el **{ComponentSelector}** puede tener una combinación de columnas ordenables y no ordenables. Las acciones de ordenación de Angular le permiten cambiar el orden de visualización de los registros según los criterios especificados.

<DocsAside type="info">
Hasta ahora, la agrupación y la ordenación funcionaban conjuntamente. En la versión 13.2 se introduce un nuevo comportamiento que desacopla la agrupación de la ordenación. Por ejemplo, borrar la agrupación no borrará las expresiones de ordenación de la cuadrícula, o viceversa. Aun así, si una columna está ordenada y agrupada a la vez, las expresiones de agrupación tienen prioridad.
</DocsAside>

## Ordenar mediante la API

Puede ordenar cualquier columna o una combinación de columnas mediante la API {ComponentTitle}, usando el método {ComponentTitle} <ApiLink type="{ComponentApiType}" member="sort" label="sort" />:

<ComponentBlock for="TreeGrid">

```typescript
import { SortingDirection } from 'igniteui-angular/grids/core';
// import { SortingDirection } from '@infragistics/igniteui-angular'; for licensed package

// Perform a case insensitive ascending sort on the ProductName column.
this.{ComponentObjectRef}.sort({ fieldName: 'Name', dir: SortingDirection.Asc, ignoreCase: true });

// Perform sorting on both the ProductName and Price columns.
this.{ComponentObjectRef}.sort([
    { fieldName: 'Name', dir: SortingDirection.Asc, ignoreCase: true },
    { fieldName: 'UnitPrice', dir: SortingDirection.Desc }
]);
```

</ComponentBlock>
<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">

```typescript
import { SortingDirection } from 'igniteui-angular/grids/core';
// import { SortingDirection } from '@infragistics/igniteui-angular'; for licensed package

// Perform a case insensitive ascending sort on the ProductName column.
this.{ComponentObjectRef}.sort({ fieldName: 'ProductName', dir: SortingDirection.Asc, ignoreCase: true });

// Perform sorting on both the ProductName and Price columns.
this.{ComponentObjectRef}.sort([
    { fieldName: 'ProductName', dir: SortingDirection.Asc, ignoreCase: true },
    { fieldName: 'Price', dir: SortingDirection.Desc }
]);
```

</ComponentBlock>

<DocsAside type="info">
La ordenación se realiza con nuestro algoritmo <ApiLink type="DefaultSortingStrategy" />. Cualquier <ApiLink type="Column" member="sortStrategy" label="IgxColumnComponent" /> o <ApiLink type="ISortingExpression" kind="interface" member="strategy" label="ISortingExpression" /> puede usar una implementación personalizada de <ApiLink type="ISortingStrategy" kind="interface" /> como algoritmo sustituto. Esto resulta útil cuando hay que definir una ordenación personalizada para columnas de plantilla complejas o columnas de imagen, por ejemplo.
</DocsAside>

Al igual que con el comportamiento de filtrado, puede borrar el estado de ordenación usando el método <ApiLink type="{ComponentApiType}" member="clearsort" label="clearSort" />:

<ComponentBlock for="TreeGrid">

```typescript
// Removes the sorting state from the ProductName column
this.{ComponentObjectRef}.clearSort('Name');

// Removes the sorting state from every column in the {ComponentTitle}
this.{ComponentObjectRef}.clearSort();
```

</ComponentBlock>
<ComponentBlock for="Grid, HierarchicalGrid, PivotGrid">

```typescript
// Removes the sorting state from the ProductName column
this.{ComponentObjectRef}.clearSort('ProductName');

// Removes the sorting state from every column in the {ComponentTitle}
this.{ComponentObjectRef}.clearSort();
```

</ComponentBlock>

<DocsAside type="info">
El <ApiLink type="{ComponentApiType}" member="sortStrategy" label="sortStrategy" /> del **{ComponentTitle}** es de un tipo distinto al <ApiLink type="Column" member="sortStrategy" label="sortStrategy" /> de la **columna**, ya que trabajan en ámbitos distintos y exponen parámetros diferentes.
</DocsAside>

<DocsAside type="info">
La operación de ordenación **NO** cambia el origen de datos subyacente de {ComponentTitle}.
</DocsAside>

## Estado de ordenación inicial

Es posible establecer el estado de ordenación inicial de {ComponentTitle} pasando un array de expresiones de ordenación a la propiedad <ApiLink type="{ComponentApiType}" member="sortingExpressions" label="sortingExpressions" /> de {ComponentTitle}.

<ComponentBlock for="Grid">

```typescript
public ngAfterViewInit(): void {
    this.{ComponentObjectRef}.sortingExpressions = [
        {
            dir: SortingDirection.Asc, fieldName: 'CategoryName',
            ignoreCase: true, strategy: DefaultSortingStrategy.instance()
        }
    ];
}
```

</ComponentBlock>

<ComponentBlock for="TreeGrid">

```typescript
public ngAfterViewInit(): void {
    this.{ComponentObjectRef}.sortingExpressions = [
        { 
            dir: SortingDirection.Asc, fieldName: 'UnitPrice',
            ignoreCase: true, strategy: DefaultSortingStrategy.instance() 
        }
    ];
}
```

</ComponentBlock>

<ComponentBlock for="HierarchicalGrid">

```typescript
public ngOnInit(): void {
    this.{ComponentObjectRef}.sortingExpressions = [
        { 
            dir: SortingDirection.Asc, fieldName: 'Artist',
            ignoreCase: true, strategy: DefaultSortingStrategy.instance() 
        }
    ];
}
```

</ComponentBlock>

<DocsAside type="info">
Si una columna de <ApiLink type="Column" member="dataType" label="dataType" /> `Date` usa valores de tipo `string`, {ComponentTitle} no los interpretará como objetos `Date`, y el uso de {ComponentTitle} `sorting` no funcionará como se espera. Si quiere usar objetos `string`, debe implementarse lógica adicional en el nivel de la aplicación para interpretar los valores como objetos `Date`.
</DocsAside>

## Plantillas de indicadores de ordenación

El icono indicador de ordenación del encabezado de columna puede personalizarse mediante una plantilla. Están disponibles las siguientes directivas para crear plantillas del indicador de ordenación en cualquier estado de ordenación (ascendente, descendente, ninguno):

- `IgxSortHeaderIconDirective` – vuelve a crear la plantilla del icono de ordenación cuando no se aplica ninguna ordenación.

```html
<ng-template igxSortHeaderIcon>
    <igx-icon>unfold_more</igx-icon>
</ng-template>
```

- `IgxSortAscendingHeaderIconDirective` – vuelve a crear la plantilla del icono de ordenación cuando la columna está ordenada de forma ascendente.

```html
<ng-template igxSortAscendingHeaderIcon>
    <igx-icon>expand_less</igx-icon>
</ng-template>
```

- `IgxSortDescendningHeaderIconDirective` – vuelve a crear la plantilla del icono de ordenación cuando la columna está ordenada de forma descendente.

```html
<ng-template igxSortDescendingHeaderIcon>
    <igx-icon>expand_more</igx-icon>
</ng-template>
```


## Estilos

Para empezar a dar estilo al comportamiento de ordenación, debemos importar el archivo `index`, donde se exportan todas las funciones de tema y el mixin `tokens()`:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Siguiendo el enfoque más sencillo, creamos un tema nuevo que extiende <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} /> y acepta los parámetros `$sorted-header-icon-color` y `sortable-header-icon-hover-color`.

<ComponentBlock for="Grid, HierarchicalGrid">

```scss
$custom-theme: grid-theme(
  $sorted-header-icon-color: #ffb06a,
  $sortable-header-icon-hover-color: black
);
```

</ComponentBlock>

<ComponentBlock for="TreeGrid">

```scss
$custom-theme: grid-theme(
  $sorted-header-icon-color: #dc38e8,
  $sortable-header-icon-hover-color: #5d1461
);
```

</ComponentBlock>

<DocsAside type="info">
En lugar de codificar los valores de color como acabamos de hacer, podemos lograr más flexibilidad con los colores usando las funciones <ApiLink kind="sass" module="palettes" type="function-palette" label="palette" code={true} /> y <ApiLink kind="sass" module="palettes" type="function-color" label="color" code={true} />. Consulte el tema [`Palettes`](/themes/sass/palettes) para obtener orientación detallada sobre cómo usarlas.
</DocsAside>

El último paso es aplicar el tema del componente con `tokens()`:

```scss
:host {
  @include tokens($custom-theme);
}
```
