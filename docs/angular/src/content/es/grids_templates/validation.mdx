# Edición y validación de {ComponentTitle} en Angular

La edición de {ComponentTitle} incluye un mecanismo de validación integrado de la entrada del usuario al editar celdas o filas. Amplía la función de [validación de formularios de Angular](https://angular.io/guide/form-validation) para facilitar la integración con una función muy conocida. Cuando cambia el estado del editor, se aplican indicadores visuales a la celda editada.

## Configuración

- required
- min
- max
- email

## API del servicio de validación

El grid expone un servicio de validación mediante la propiedad <ApiLink type="Grid" member="validation" label="validation" />.
Ese servicio tiene las siguientes API públicas:

- <ApiLink type="GridValidationService" member="valid" label="valid" />: devuelve si el estado de validación del grid es válido.
- <ApiLink type="GridValidationService" member="getInvalid" label="getInvalid" />: devuelve los registros con estados no válidos.
- <ApiLink type="GridValidationService" member="clear" label="clear" />: borra el estado de un registro por id, o borra todo el estado si no se proporciona ningún id.
- <ApiLink type="GridValidationService" member="markAsTouched" label="markAsTouched" />: marca el registro/campo correspondiente como tocado.

Los estados no válidos persistirán hasta que se corrijan los errores de validación según la regla de validación, o hasta que se borren.

## Disparadores de la validación

La validación se disparará en los siguientes escenarios:

- Mientras se edita mediante el editor de celdas, según el <ApiLink type="Grid" member="validationTrigger" label="validationTrigger" /> de la cuadrícula. Ya sea en `change` mientras se escribe en el editor, o en `blur` cuando el editor pierde el foco o se cierra.
- Al actualizar celdas o filas mediante la API: <ApiLink type="Grid" member="updateRow" label="updateRow" />, <ApiLink type="Grid" member="updateCell" label="updateCell" />, etc.
- Al usar la edición por lotes y la API <ApiLink type="TransactionService" member="undo" label="undo" />/<ApiLink type="TransactionService" member="redo" label="redo" /> del servicio de transacciones.

<DocsAside type="info">
La validación no se disparará para los registros que no se han editado mediante la entrada del usuario o mediante la API de edición. Los indicadores visuales de la celda solo se mostrarán si el campo correspondiente se considera tocado, ya sea por la interacción del usuario o mediante la API `markAsTouched` del servicio de validación.
</DocsAside>

### Disparador de la información emergente de error

La entrada <ApiLink type="Grid" member="validationTooltipTrigger" label="validationTooltipTrigger" /> de {ComponentTitle} controla cuándo se muestra la información emergente de error de una celda no válida. No cambia el momento en que se ejecuta la validación.

| Valor | Cuándo se muestra la información emergente de error |
| --- | --- |
| `active` (predeterminado) | Cuando una celda no válida pasa a estar activa, cuando la celda activa pasa a ser no válida y mientras el usuario pasa el cursor sobre el icono de error. |
| `hover` | Solo mientras el usuario pasa el cursor sobre el icono de error. |

Use `hover` para evitar que la información emergente tape el contenido de la cuadrícula mientras el usuario edita o navega. Las celdas no válidas seguirán mostrando el icono de error y los estilos de no válido:

```html
<{ComponentSelector} [data]="data" validationTooltipTrigger="hover"></{ComponentSelector}>
```

## Opciones de personalización de la validación de {ComponentTitle} en Angular

### Establecer un validador personalizado

Puede definir su propia directiva de validación para usarla en una `<igx-column>` de la plantilla.

```ts
@Directive({
    selector: '[phoneFormat]',
    providers: [{ provide: NG_VALIDATORS, useExisting: PhoneFormatDirective, multi: true }]
})
export class PhoneFormatDirective extends Validators {
    @Input('phoneFormat')
    public phoneFormatString = '';

    public validate(control: AbstractControl): ValidationErrors | null {
        return this.phoneFormatString ? phoneFormatValidator(new RegExp(this.phoneFormatString, 'i'))(control)
            : null;
    }
}
```

Una vez definida y añadida en el módulo de su aplicación, puede asignarla de forma declarativa a una columna concreta de la cuadrícula:

```html
<igx-column phoneFormat="\+\d{1}\-(?!0)(\d{3})\-(\d{3})\-(\d{4})\b" ...>
```

### Cambiar la plantilla de error predeterminada

Puede definir su propia plantilla de error personalizada, que se mostrará en la información emergente de error cuando la celda pase a un estado no válido.
Esto es útil en escenarios en los que quiere añadir su propio mensaje de error o cambiar de otra forma el aspecto o el contenido del mensaje.

```html
<igx-column ... >
  <ng-template igxCellValidationError let-cell='cell' let-defaultErr="defaultErrorTemplate">
      <ng-container *ngTemplateOutlet="defaultErr">
      </ng-container>
      @if (cell.validation.errors?.['phoneFormat']) {
        <div>
          Please enter correct phone format
        </div>
      }
  </ng-template>
</igx-column>
```

## Validación entre campos

En algunos escenarios, la validación de un campo puede depender del valor de otro campo del registro.
En ese caso puede usarse un validador personalizado para comparar los valores del registro a través de su `FormGroup` compartido.

<ComponentBlock for="Grid">


El ejemplo siguiente muestra una validación entre campos de distintos campos del mismo registro. Comprueba la validez de las fechas respecto a la fecha actual y entre la fecha de activación y la de creación del registro, así como la proporción de acuerdos ganados/perdidos de cada empleado. Todos los errores se recogen en una columna anclada aparte que indica que el registro no es válido y muestra los errores correspondientes.

Las siguientes líneas de código muestran la función validadora entre campos, que contiene las comparaciones y establece los errores correspondientes.

```ts
private rowValidator(): ValidatorFn {
    return (formGroup: FormGroup): ValidationErrors | null => {
        let returnObject = {};
        const createdOnRecord = formGroup.get('created_on');
        const lastActiveRecord = formGroup.get('last_activity');
        const winControl = formGroup.get('deals_won');
        const loseControl = formGroup.get('deals_lost');
        const actualSalesControl = formGroup.get('actual_sales');

        // Validate dates
        const curDate = new Date();
        if (new Date(createdOnRecord.value) > curDate) {
            // The created on date shouldn't be greater than current date.
            returnObject['createdInvalid'] =  true;
        }
        if (new Date(lastActiveRecord.value) > curDate) {
            // The last active date shouldn't be greater than current date.
            returnObject['lastActiveInvalid'] = true;
        }
        if (new Date(createdOnRecord.value) > new Date(lastActiveRecord.value)) {
            // The created on date shouldn't be greater than last active date.
            returnObject['createdLastActiveInvalid'] = true;
        }
        
        // Validate deals
        const dealsRatio = this.calculateDealsRatio(winControl.value, loseControl.value);
        if (actualSalesControl.value === 0 && dealsRatio > 0) {
            // If the actual sales value is 0 but there are deals made.
            returnObject['salesZero'] = true;
        }
        if (actualSalesControl.value > 0 && dealsRatio === 0) {
            // If the deals ratio based on deals won is 0 but the actual sales is bigger than 0.
            returnObject['salesNotZero'] = true;
        }
        
        return returnObject;
    };
}

public calculateDealsRatio(dealsWon, dealsLost) {
    if (dealsLost === 0) return dealsWon + 1;
    return Math.round(dealsWon / dealsLost * 100) / 100;
}
```

El validador entre campos puede añadirse al `formGroup` de la fila desde el evento <ApiLink type="Grid" member="formGroupCreated" label="formGroupCreated" />, que devuelve el nuevo `formGroup` para cada fila al entrar en modo de edición:

```html
</igx-grid>

```

```typescript
            // Other cell errors ...
        }

        messages.push(`The \`Date of Registration\` date cannot be in the future.`);
    }
    // Other cross-field errors...

    return messages;
```

  ```ts
    public addressValidator(): ValidatorFn {
        return (control: AbstractControl): ValidationErrors | null => {
            const formGroup = control;
            let returnObject = {};
            const city = formGroup.get('City');
            const country = formGroup.get('Country');
            const validCities = this.countryData.get(country.value);
            if (!validCities || !validCities[city.value]) {
                returnObject['invalidAddress'] = true;
            }
            return returnObject;
        }
    }

    public dateValidator(): ValidatorFn {
        return (control: AbstractControl): ValidationErrors | null => {
            const formGroup = control;
            let returnObject = {};
            const orderDate = formGroup.get('OrderDate').value;
            const shippedDate = formGroup.get('ShippedDate').value;
            if (new Date(shippedDate) < new Date(orderDate)) {
                returnObject['invalidRange'] = true;
            }
            return returnObject;
        }
  ```

```ts
    public isRowValid(cell: CellType) {
        const hasErrors = !!cell.row.validation.errors || cell.row.cells.some(x => !!x.validation.errors);
        return !hasErrors;
    }

    public stateMessage(cell: CellType) {
        const messages = [];
        const row = cell.row;
        if  (row.validation.errors?.invalidAddress) {
            messages.push('The address information is invalid. City does not match the Country.');
        }
        if  (row.validation.errors?.invalidRange) {
            messages.push('The ShippedDate cannot be before the OrderDate.');
        }
        const cellValidationErrors = row.cells.filter(x => !!x.validation.errors);
        if (cellValidationErrors && cellValidationErrors.length > 0) {
            const fields = cellValidationErrors.map(x => x.column.field).join(',');
            messages.push('The following fields are required: ' + fields);
        }

        if (messages.length === 0) {
            // no errors
            return ['Valid'];
        }
        return messages;
    }
```

### Estilos de filas y celdas no válidas

Las filas y las celdas ofrecen una API para que los desarrolladores sepan si una fila o celda no es válida y qué tipo de errores están activos.
<ComponentBlock for="Grid">


```ts
public rowStyles = {
    background: (row: RowType) => row.validation.status === 'INVALID' ? '#FF000033' : '#00000000'
};
public cellStyles = {
  'invalid-cell': (rowData, columnKey) => {
    const pKey = this.grid.primaryKey;
    const cell = this.grid.getCellByKey(rowData[pKey], columnKey);
    return cell && cell.validation.status === 'INVALID';
  }
}
```

```html
<igx-grid [rowStyles]="rowStyles">
  <igx-column field="ReorderLevel" header="Reorder Level" required [cellClasses]="cellStyles">
  </igx-column>
</igx-grid>
```

</ComponentBlock>

<ComponentBlock for="HierarchicalGrid">


```ts
public rowStyles = {
    background: (row: RowType) => row.validation.status === 'INVALID' ? '#FF000033' : '#00000000'
};
public cellStyles = {
  'invalid-cell': (rowData, columnKey) => {
    let cell = this.hierarchicalGrid.getCellByKey(rowData, columnKey);
    // search in child grids
    if (!cell) {
      for (let grid of this.childGrid.gridAPI.getChildGrids()) {
        cell = grid.getCellByKey(rowData, columnKey);
        if (cell) break;
      }
    }
    return cell && cell.validation.status === 'INVALID';
  }
}
```

```html
<igx-hierarchical-grid [rowStyles]="rowStyles">
  <igx-column field="Artist" [editable]="true" [dataType]="'string'" required [cellClasses]="cellStyles">
  </igx-column>
  <igx-row-island [key]="'Albums'" [rowStyles]="rowStyles">
    <igx-column field="Album" [editable]="true" [dataType]="'string'" required [cellClasses]="cellStyles">
    </igx-column>
  </igx-row-island>
</igx-hierarchical-grid>
```

</ComponentBlock>
