# Edición de celdas de {ComponentTitle} en Angular

El componente {ComponentTitle} de Ignite UI for Angular ofrece potentes capacidades de manipulación de datos y una API potente para las operaciones CRUD de Angular. De forma predeterminada, {ComponentTitle} usa la edición **dentro de la celda** y se muestran distintos editores según el tipo de datos de la columna, gracias a la **plantilla de edición de celdas predeterminada**. Además, puede definir sus propias plantillas personalizadas para las acciones de actualización de datos y para sustituir el comportamiento predeterminado al confirmar o descartar cualquier cambio.

## Edición de celdas

### Edición a través de la interfaz

Puede entrar en el modo de edición de una celda específica cuando una celda editable tiene el foco, de una de las siguientes formas:

- con doble clic;
- con un clic simple: el clic simple solo entrará en el modo de edición si la celda seleccionada anteriormente estaba en modo de edición y la celda seleccionada actualmente es editable. Si la celda seleccionada anteriormente no estaba en modo de edición, el clic simple solo selecciona la celda sin entrar en el modo de edición;
- al pulsar una tecla `Enter`;
- al pulsar una tecla `F2`;

Puede salir del modo de edición **sin confirmar** los cambios de una de las siguientes formas:

- al pulsar una tecla `Escape`;
- al realizar operaciones de _ordenación_, _filtrado_, _búsqueda_ y _ocultación_;

Puede salir del modo de edición y **confirmar** los cambios de una de las siguientes formas:

- al pulsar una tecla `Enter`;
- al pulsar una tecla `F2`;
- al pulsar una tecla `Tab`;
- con un clic simple en otra celda: cuando hace clic en otra celda de {ComponentTitle}, sus cambios se enviarán.
- las operaciones como la paginación, el redimensionamiento, el anclaje o el movimiento salen del modo de edición y los cambios se envían.

<DocsAside type="info">
La celda permanece en modo de edición cuando se desplaza vertical u horizontalmente, o cuando se hace clic fuera de {ComponentTitle}. Esto es válido tanto para la edición de celdas como para la edición de filas.
</DocsAside>

### Plantillas de edición de celdas

Puede ver y conocer más sobre las plantillas de edición de celdas predeterminadas en el tema [edición general](/{igPath}/editing#plantillas-de-edición).

Si quiere proporcionar una plantilla personalizada que se aplique cuando una celda esté en modo de edición, puede usar <ApiLink type="CellTemplateDirective" label="directiva igxCellEditor`" />. Para ello, tiene que pasar un `ng-template` marcado con la directiva `igxCellEditor` y enlazar correctamente su control personalizado a <ApiLink type="GridCell" member="editValue" label="cell.editValue" />:

```html
    <ng-template igxCellEditor let-cell="cell" let-value>
        <igx-select class="cell-select" [(ngModel)]="cell.editValue" [igxFocus]="true">
            <igx-select-item *ngFor="let class of classes" [value]="class">
                {{ class }}
            </igx-select-item>
        </igx-select>
    </ng-template>
</igx-column>
```

### Edición al estilo de Excel de {ComponentTitle}

Con la edición al estilo de Excel, el usuario puede desplazarse por las celdas como lo haría en Excel, y editarlas muy rápidamente.

Esta funcionalidad personalizada puede implementarse usando los eventos de la cuadrícula. Primero nos conectamos a los eventos keydown de la cuadrícula y, a partir de ahí, podemos implementar dos funciones:

- Modo de edición constante

```typescript
public keydownHandler(event) {
  const key = event.keyCode;
  const grid = this.grid;
  const activeElem = grid.navigation.activeNode;

  if(
    (key >= 48 && key <= 57) ||
    (key >= 65 && key <= 90) ||
    (key >= 97 && key <= 122)){
        // Number or Alphabet upper case or Alphabet lower case
        const columnName = grid.getColumnByVisibleIndex(activeElem.column).field;
        const cell = grid.getCellByColumn(activeElem.row, columnName);
        if (cell && !cell.editMode) {
            cell.editMode = true;
            cell.editValue = event.key;
            this.shouldAppendValue = true;
        } else if (cell && cell.editMode && this.shouldAppendValue) {
            event.preventDefault();
            cell.editValue = cell.editValue + event.key;
            this.shouldAppendValue = false;
        }
    }
}
```

- Navegación con `Enter` / `Shift+Enter`

```typescript
if (key == 13) {
    let thisRow = activeElem.row;
    const column = activeElem.column;
    const rowInfo = grid.dataView;

    // to find the next eiligible cell, we will use a custom method that will check the next suitable index
    let nextRow = this.getNextEditableRowIndex(thisRow, rowInfo, event.shiftKey);

    // and then we will navigate to it using the grid's built in method navigateTo
    this.grid.navigateTo(nextRow, column, (obj) => {
        obj.target.activate();
        this.grid.clearCellSelection();
        this.cdr.detectChanges();
    });
}
```

Las partes clave para encontrar el siguiente índice válido serían:

```typescript
//first we check if the currently selected cell is the first or the last
if (currentRowIndex < 0 || (currentRowIndex === 0 && previous) || (currentRowIndex >= dataView.length - 1 && !previous)) {
return currentRowIndex;
}
// in case using shift + enter combination, we look for the first suitable cell going up the field
if(previous){
return  dataView.findLastIndex((rec, index) => index < currentRowIndex && this.isEditableDataRecordAtIndex(index, dataView));
}
// or for the next one down the field
return dataView.findIndex((rec, index) => index > currentRowIndex && this.isEditableDataRecordAtIndex(index, dataView));
```

### Validación de celdas en el evento de edición

Usando los eventos de edición del grid podemos cambiar la forma en que el usuario interactúa con el grid.
En este ejemplo validaremos una celda según los datos introducidos en ella, enlazándonos al evento <ApiLink type="{ComponentApiType}" member="cellEdit" label="cellEdit" />. Si el nuevo valor de la celda no cumple nuestros criterios predefinidos, evitaremos que llegue al origen de datos cancelando el evento (`event.cancel = true`). También mostraremos un mensaje de error personalizado usando [`IgxToast`](../toast.mdx).

Lo primero que debemos hacer es enlazarnos al evento de la cuadrícula:

```html
<{ComponentSelector} (cellEdit)="handleCellEdit($event)"
...>
...
</{ComponentSelector}>
```

El `cellEdit` se emite cada vez que el valor de **cualquier** celda está a punto de confirmarse. En la definición de nuestro `handleCellEdit` debemos asegurarnos de comprobar nuestra columna específica antes de realizar cualquier acción:

<ComponentBlock for="Grid">

```typescript
export class MyGridEventsComponent {
    public handleCellEdit(event: IGridEditEventArgs): void {
        const column = event.column;
        if (column.field === 'Ordered') {
            const rowData = event.rowData;
            if (!rowData) {
                return;
            }
            if (event.newValue > rowData.UnitsInStock) {
                event.cancel = true;
                this.toast.open();
            }
        }
    }
}
```

Si el valor introducido en una celda de la columna **Ordered** es mayor que la cantidad disponible (el valor de **Units in Stock**), la edición se cancelará y se mostrará un toast con un mensaje de error.
</ComponentBlock>
<ComponentBlock for="TreeGrid">

```typescript
export class MyTreeGridEventsComponent {
    public handleCellEdit(event: IGridEditEventArgs): void {
        const column = event.column;
        if (column.field === 'Age') {
            if (event.newValue < 18) {
                event.cancel = true;
                this.toast.message = 'Employees must be at least 18 years old!';
                this.toast.open();
            }
        } else if (column.field === 'HireDate') {
            if (event.newValue > new Date().getTime()) {
                event.cancel = true;
                this.toast.message = 'The employee hire date must be in the past!';
                this.toast.open();
            }
        }
    }
}
```

Aquí validamos dos columnas. Si el usuario intenta establecer un valor no válido para la **edad** de un empleado (menor de 18) o para su **fecha de contratación** (una fecha futura), la edición se cancelará (el valor no se enviará) y se mostrará un toast con un mensaje de error.
</ComponentBlock>
<ComponentBlock for="HierarchicalGrid">

```typescript
export class MyHGridEventsComponent {
    public handleCellEdit(event: IGridEditEventArgs) {
        const today = new Date();
        const column = event.column;
        if (column.field === 'Debut') {
            if (event.newValue > today.getFullYear()) {
                this.toast.message = 'The debut date must be in the past!';
                this.toast.open();
                event.cancel = true;
            }
        } else if (column.field === 'LaunchDate') {
            if (event.newValue > new Date()) {
                this.toast.message = 'The launch date must be in the past!';
                this.toast.open();
                event.cancel = true;
            }
        }
    }
}
```

Aquí validamos dos columnas. Si el usuario intenta cambiar el año de **debut** de un artista o la **fecha de lanzamiento** de un álbum, el grid no permitirá ninguna fecha posterior a hoy.
</ComponentBlock>

## Estilos

{ComponentName} permite dar estilo a sus celdas mediante [`Ignite UI for Angular Theme Library`](/themes/sass/component-themes). La <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} /> de la cuadrícula expone una amplia gama de propiedades que permiten dar estilo a muchos aspectos diferentes de la cuadrícula.

En los pasos siguientes veremos cómo dar estilo a la celda de la cuadrícula en modo de edición y cómo limitar el alcance de esos estilos.

Para usar el [`Ignite UI Theming Library`](/themes/sass/component-themes), primero debemos importar el archivo de tema `index` en nuestros estilos globales:

### Importar la biblioteca de estilos

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

Ahora podemos usar todas las funciones que expone el motor de temas de Ignite UI for Angular.

### Definir una paleta

Una vez importado correctamente el archivo index, creamos una paleta personalizada que podemos usar. Definamos tres colores que nos gusten y usémoslos para construir una paleta con [`palette`](/themes/palettes):

```scss
$white: #fff;
$blue: #4567bb;
$gray: #efefef;

$color-palette: palette(
  $primary: $white, 
  $secondary: $blue, 
  $surface: $gray
);
```

### Definir temas

Ahora podemos definir el tema usando nuestra paleta. Las celdas se estilan mediante <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} />, así que podemos usarlo para generar un tema para nuestro {ComponentName}:

```scss
$grid-theme: grid-theme(
  $cell-editing-background: $blue,
  $cell-editing-foreground: $white,
  $cell-active-border-color: $blue,
  $cell-edited-value-color: $white,
  $edit-mode-color: color($color: "secondary", $variant: 200)
);
```

### Aplicar el tema

El último paso es **incluir** la paleta personalizada y los temas de la cuadrícula.

<ComponentBlock for="Grid">

```scss
igx-grid {
  @include palette($color-palette);
  @include tokens($grid-theme);
}
```

</ComponentBlock>
<ComponentBlock for="TreeGrid">

```scss

  @include palette($color-palette);
  @include tokens($grid-theme);
}
```

</ComponentBlock>

```scss

  @include palette($color-palette);
```
