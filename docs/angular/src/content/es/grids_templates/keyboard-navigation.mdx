# Navegación por teclado de {ComponentTitle} en Angular

 La navegación por teclado en **{ComponentName}** ofrece una gran variedad de interacciones de teclado para el usuario. Mejora la accesibilidad de **{ComponentName}** y permite desplazarse por cualquier tipo de elemento que contenga (celda, fila, encabezado de columna, barra de herramientas, pie, etc.). Esta funcionalidad está habilitada de forma predeterminada, y el desarrollador puede sobrescribir cualquiera de los comportamientos predeterminados de forma sencilla.

Se ha reducido el número de paradas de tabulación de {ComponentName}, de modo que la navegación cumpla los estándares de accesibilidad del W3C y sea cómoda de usar.

Actualmente, {ComponentName} introduce las siguientes paradas de tabulación:

- **Área de agrupación o de la barra de herramientas** (si está habilitada);
- **Encabezado de {ComponentName}**;
- **Cuerpo de {ComponentName}**;
- **Resúmenes de columnas** (si están habilitados);
- **Paginador de {ComponentName}** (si está habilitado);

<DocsAside type="info">
Debido a este cambio, ya no se admite la navegación entre celdas con <kbd>tab</kbd> y <kbd>Shift + Tab</kbd> en {ComponentName}.
Al pulsar la tecla <kbd>Tab</kbd>, ahora se recorren las paradas de tabulación en el orden siguiente: **GroupBy** / **barra de herramientas** -> **encabezados** -> **cuerpo** -> **resúmenes** -> **pie / paginador**.
</DocsAside>

<DocsAside type="info">
Exponer cualquier elemento **enfocable** en el cuerpo de **{ComponentName}** mediante una plantilla puede introducir **efectos secundarios** en la navegación por teclado, ya que no se impide el comportamiento predeterminado del navegador. Es responsabilidad del desarrollador impedirlo o modificarlo de forma adecuada.
</DocsAside>

## Navegación por encabezados

Ahora se incluye una compatibilidad completa con la _navegación por teclado_ en el encabezado de **{ComponentName}**. Los encabezados de columna pueden recorrerse fácilmente con las teclas de flecha. Además, hay varias combinaciones de teclas que activan acciones sobre las columnas, como **filtrado**, **ordenación**, **agrupación**, etc.
Cuando el contenedor de encabezados **{ComponentName}** tiene el foco, están disponibles las siguientes combinaciones de teclas:

### Combinaciones de teclas

- <kbd>Arrow Up</kbd> se desplaza una celda hacia arriba en los encabezados (sin volver al final). Solo está disponible cuando se definen Multi-row Layout (MRL) o Multi-column Headers (MCH)
- <kbd>Arrow Down</kbd> se desplaza una celda hacia abajo en los encabezados (sin volver al principio). Solo está disponible cuando se definen Multi-row Layout (MRL) o Multi-column Headers (MCH)
- <kbd>Arrow Left</kbd> se desplaza una celda a la izquierda (sin volver al final)
- <kbd>Arrow Right</kbd> se desplaza una celda a la derecha (sin pasar a la línea siguiente)
- <kbd>Ctrl + Arrow Left</kbd> se desplaza a la celda más a la izquierda de la fila; si MRL o MCH están habilitados, se desplaza a la celda más a la izquierda del mismo nivel
- <kbd>Home</kbd> se desplaza a la celda más a la izquierda de la fila; si MRL o MCH están habilitados, se desplaza a la celda más a la izquierda del mismo nivel
- <kbd>Ctrl + Arrow Right</kbd> se desplaza a la celda más a la derecha de la fila; si MRL o MCH están habilitados, se desplaza a la celda más a la derecha del mismo nivel
- <kbd>End</kbd> se desplaza a la celda más a la derecha de la fila; si MRL o MCH están habilitados, se desplaza a la celda más a la derecha del mismo nivel
- <kbd>Alt + L</kbd> abre el cuadro de diálogo de filtrado avanzado si el filtrado avanzado está habilitado
- <kbd>Ctrl + Shift + L</kbd> abre el cuadro de diálogo de filtrado al estilo de Excel o el filtro predeterminado (de fila) si la columna es filtrable
- <kbd>Ctrl + Arrow Up</kbd> ordena el encabezado de columna activo en orden ASC. Si la columna ya está ordenada en ASC, se borra el estado de ordenación
- <kbd>Ctrl + Arrow Down</kbd> ordena el encabezado de columna activo en orden DSC. Si la columna ya está ordenada en DSC, se borra el estado de ordenación
- <kbd>Space</kbd> selecciona la columna; si la columna ya está seleccionada, se borra la selección
<ComponentBlock for="Grid">
- <kbd>Shift + Alt + Arrow Left</kbd> agrupa la columna, si la columna está marcada como agrupable
- <kbd>Shift + Alt + Arrow Right</kbd> desagrupa la columna, si la columna está marcada como agrupable
- <kbd>Alt + Arrow Left</kbd> o <kbd>Alt + Arrow Up</kbd> contrae el encabezado del grupo de columnas, si el encabezado no está ya contraído
- <kbd>Alt + Arrow Right</kbd> o <kbd>Alt + Arrow Down</kbd> expande el encabezado del grupo de columnas, si el encabezado no está ya expandido

## Navegación por teclado personalizada

Sobrescribir el comportamiento predeterminado de una tecla o de una combinación de teclas es una de las ventajas que ofrece la función **Navegación por teclado**. Por ejemplo: pulse la tecla <kbd>Enter</kbd> o <kbd>Tab</kbd> para desplazarse a la siguiente celda o a la celda de debajo. Este escenario, o cualquier otro escenario de navegación, se consigue fácilmente con la API de **Navegación por teclado**:

Probemos la API para mostrar cómo lograr escenarios habituales, como la validación de la entrada del usuario y la navegación personalizada. Primero necesitamos registrar un controlador de eventos para el evento <ApiLink type="Grid" member="gridKeydown" label="gridKeydown" />:

<ComponentBlock for="Grid">

```html
<igx-grid #grid1 [data]="data" [primaryKey]="'ProductID'" (gridKeydown)="customKeydown($event)"></igx-grid>
```

</ComponentBlock>

<ComponentBlock for="HierarchicalGrid">

```html
<igx-hierarchical-grid #grid1 [data]="data" (gridKeydown)="customKeydown($event, grid1)">
    <igx-row-island [key]="'Albums'" (gridCreated)="childGridCreated($event)">
    </igx-row-island>
</igx-hierarchical-grid>
```

Para añadir navegación por teclado personalizada también a los grids hijos de igxHierarchicalGrid, cada grid hijo debe suscribirse al evento <ApiLink type="HierarchicalGrid" member="gridKeydown" label="gridKeydown" />. Por eso, en el ejemplo anterior hemos registrado un controlador de eventos para el evento <ApiLink type="HierarchicalGrid" member="gridCreated" label="gridCreated" />:

```typescript
public childGridCreated(event: IGridCreatedEventArgs) {
    const grid = event.grid;
    event.grid.gridKeydown.subscribe((args) => {
        this.customKeydown(args, grid);
    });
}
```

```typescript
public customKeydown(args: IGridKeydownEventArgs) {
    const target: IgxGridCell = args.target as IgxGridCell;
    const evt: KeyboardEvent = args.event as KeyboardEvent;
    const type = args.targetType;

    if (type === 'dataCell' && target.inEditMode && evt.key.toLowerCase() === 'tab') {
        // 1. USER INPUT VALIDATION ON TAB
    }
    if (type === 'dataCell' && evt.key.toLowerCase() === 'enter') {
        // 2. CUSTOM NAVIGATION ON ENTER KEY PRESS
    }
}
```

Según los valores de <ApiLink type="IGridKeydownEventArgs" kind="interface" />, identificamos dos casos en los que proporcionar nuestra propia lógica (véase más arriba). Ahora, usando los métodos de la API, hagamos lo deseado: si el usuario pulsa la tecla <kbd>Tab</kbd> sobre una celda en modo de edición, validaremos la entrada. Si el usuario pulsa la tecla <kbd>Enter</kbd> sobre una celda, moveremos el foco a la celda de la fila siguiente:

<ComponentBlock for="Grid">

```typescript
    // 1. USER INPUT VALIDATION ON TAB
    if (target.column.dataType === 'number' && target.editValue < 10) {
        // alert the user that the input is invalid
        return;
    }
    // 2. CUSTOM NAVIGATION ON ENTER KEY PRESS
    this.grid1.navigateTo(target.row.index + 1, target.column.visibleIndex, (obj) => {
            obj.target.activate();
        });
```
