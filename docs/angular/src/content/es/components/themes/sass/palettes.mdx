# Paletas con Sass

Las paletas Sass de Ignite UI for Angular son mapas de tonos de color que la función `palette()` genera a partir de colores semilla, y que el mixin `palette()` emite como variables CSS.

## Descripción general

Una paleta de Ignite UI for Angular es un [mapa Sass](https://sass-lang.com/documentation/values/maps) indexado por familia de color: `primary`, `secondary`, `gray`, `surface`, `info`, `success`, `warn` y `error`. Cada familia es un mapa de sus tonos, y cada tema de componente lee sus colores de esos tonos mediante variables CSS `--ig-*`.

La función `palette()` construye el mapa completo a partir de colores semilla. Con el generador `fitted` predeterminado, cada familia contiene estas variantes:

| Familia | Variantes |
|---|---|
| `primary`, `secondary`, `info`, `success`, `warn`, `error` | `50`–`900`, `A100`, `A200`, `A400`, `A700`, `seed` |
| `gray` | `50`–`900`, `seed` |
| `surface` | `base`, `sunken`, `raised`, `overlay`, `container`, `seed` |

Cada variante tiene una variante `-contrast` correspondiente, como `500-contrast`: negro o blanco, que el navegador resuelve para lograr un contraste legible sobre ese tono. El color `primary` suele ser el color de su marca y da estilo a elementos estáticos destacados como `igx-navbar`; `secondary` da estilo a elementos accionables como botones, interruptores y controles deslizantes; `surface` es el fondo de componentes como tarjetas, menús y selectores.

Para entender cómo se colocan los tonos y por qué la familia `surface` tiene roles en lugar de números, consulte [Generación de paletas](../palette-generation.mdx).

## Generar una paleta

Llame a `palette()` con las tres semillas obligatorias, `$primary`, `$secondary` y `$surface`, y luego pase el resultado al mixin `palette()` para emitirlo como variables CSS:

```scss
@use "igniteui-angular/theming" as *;

$brand-palette: palette(
  $primary: #0099ff,
  $secondary: #df1b74,
  $surface: #ffffff
);

:root {
  @include palette($brand-palette);
}
```

Las semillas opcionales son `$gray`, `$info` (`#1377d5`), `$success` (`#4eb862`), `$warn` (`#faa419`) y `$error` (`#ff134a`). El mixin `theme()` incluye el mixin `palette()` por usted, así que inclúyalo directamente solo cuando emita una paleta por sí sola, por ejemplo para acotar una segunda paleta a una clase.

<DocsAside type="warning">
Cada semilla que pase a `palette()` **debe ser un color de Sass**. Las variables CSS no pueden pasarse como argumentos, porque la paleta se calcula en tiempo de compilación.
</DocsAside>

El mixin `palette()` también establece el nivel WCAG para el que se eligen los colores de `-contrast`. Pase `$contrast-level` con `'a'`, `'aa'` (predeterminado) o `'aaa'`:

```scss
:root {
  @include palette($brand-palette, $contrast-level: 'aaa');
}
```

Con el generador `fitted`, cada tono se emite como un color fijo:

```css
:root {
  --ig-primary-100: rgb(172, 207, 251);
  --ig-primary-500: rgb(9, 109, 183);
  --ig-primary-600: rgb(6, 89, 150);
  --ig-primary-seed: #0099ff;
  --ig-surface-base: rgb(255, 255, 255);
  --ig-surface-sunken: rgb(247, 247, 247);
  /* ... */
}
```

Como los tonos son fijos, si sobrescribe una de estas variables en CSS solo cambia ese tono. Para cambiar una familia, cambie su semilla y vuelva a compilar.

## Escalas

Una escala define hasta dónde llegan los tonos de una familia y cómo están espaciados. Pase `$scales` a `palette()` para reemplazar los valores predeterminados: `even` para todas las familias, `material` para `gray`.

Indique un preajuste para una familia, o pase un preajuste para todas las familias:

```scss
// The grays follow IBM Carbon's rhythm; every other family keeps its default
$brand-palette: palette(#0099ff, #df1b74, #ffffff, $scales: ('gray': 'carbon'));

// Every family uses the tailwind preset
$brand-palette: palette(#0099ff, #df1b74, #ffffff, $scales: 'tailwind');
```

Los preajustes son `even`, `material`, `tailwind` y `carbon`. [Generación de paletas](../palette-generation.mdx#scale-shapes) los compara.

Describa una escala en línea con estas claves:

| Clave | Valor | Efecto |
|---|---|---|
| `range` | Dos relaciones de contraste, como `1.1 14` | El contraste del tono `50` y del tono `900`. Por defecto, el rango `even`, `1.182 18.232`. |
| `curve` | Cuatro números, como `0.5 0 0.8 0.8` | Redistribuye los tonos a lo largo del rango; se lee como una `cubic-bezier()` de CSS. Omítalo para un espaciado uniforme. |
| `anchor` | `'surface'` o `'white'` | Respecto a qué se mide el rango `gray`. El valor predeterminado es `'surface'`. Las demás familias siempre se miden respecto al blanco. |

```scss
$brand-palette: palette(
  #0099ff,
  #df1b74,
  #121212,
  $scales: (
    'primary': (range: 1.1 14, curve: 0.5 0 0.8 0.8),
    'gray': (range: 1.1 14, anchor: 'white')
  )
);
```

Una lista de cuatro números sin más se interpreta como una curva sobre el rango `even`. Un rango o una curva personalizados cambian el contraste entre los tonos: compruebe los pares que usa después de modificar uno.

## Generadores

La función `palette()` tiene dos generadores. `fitted`, el predeterminado, calcula cada tono para un objetivo de contraste. `legacy` sitúa la semilla en `500` y deriva los demás tonos con multiplicadores HSL fijos, emitidos como colores relativos CSS de `500`:

```css
:root {
  --ig-primary-500: #0099ff;
  --ig-primary-600: hsl(from var(--ig-primary-500) h calc(s * 1.26) calc(l * 0.89));
}
```

Mantenga el generador `legacy` para una paleta con `$generator`, o para cada llamada a `palette()` de la compilación, configurando `$shade-generator` antes de que cargue cualquier otra cosa la biblioteca:

```scss
// One palette
$brand-palette: palette(#0099ff, #df1b74, #ffffff, $generator: 'legacy');
```

```scss
// Every palette() call in the build
@use "igniteui-theming" with ($shade-generator: 'legacy');
@use "igniteui-angular/theming" as *;
```

Una paleta `legacy` ignora el argumento `$scales`.

## Paletas predefinidas

Ignite UI for Angular ofrece paletas predefinidas claras y oscuras que combinan con los esquemas correspondientes:

- Paletas claras
  - `$light-material-palette`
  - `$light-fluent-excel-palette`
  - `$light-fluent-word-palette`
  - `$light-fluent-palette`
  - `$light-bootstrap-palette`
  - `$light-indigo-palette`
- Paletas oscuras
  - `$dark-material-palette`
  - `$dark-fluent-excel-palette`
  - `$dark-fluent-word-palette`
  - `$dark-fluent-palette`
  - `$dark-bootstrap-palette`
  - `$dark-indigo-palette`

Combine cualquier paleta clara con un esquema claro, y cualquier paleta oscura con un esquema oscuro. Las paletas predefinidas se crean con el generador `legacy`, así que un tema creado con alguna de ellas conserva sus tonos de color relativos y responde a las sobrescrituras en tiempo de ejecución de las variantes `500`.

## Colores en escala de grises

La familia `gray` aporta la mayoría de los colores de texto, borde y deshabilitado, y sus tonos se definen en relación con la superficie. Pase `$gray` para elegir el color a partir del cual se construyen los grises:

```scss
$brand-palette: palette(
  $primary: #2ab759,
  $secondary: #f96a88,
  $surface: #222222,
  $gray: #ffffff
);
```

Cuando se omite `$gray`, la semilla gris es negra sobre una superficie clara y blanca sobre una oscura. Con la escala `material` predeterminada, el tono `50` es el gris más cercano a una superficie blanca o casi negra, y `900` es el más alejado de ella. Consulte [Grises y la página](../palette-generation.mdx#grays-and-the-page) para ver cómo afecta el ancla de la escala de grises a los temas oscuros.

## Variantes de color

La función `color()` devuelve un tono de la paleta. Acepta hasta cuatro argumentos: `$palette`, `$color`, `$variant` y `$opacity`.

```scss
// A reference to the CSS variable: var(--ig-primary-500)
$primary-500: color();

// var(--ig-primary-600)
$primary-600: color($variant: 600);

// The primary 600 shade at 50% opacity, as a CSS relative color
$primary-600-translucent: color($variant: 600, $opacity: 0.5);

// The surface's raised role: var(--ig-surface-raised)
$raised: color($color: 'surface', $variant: 'raised');

// The resolved color of the secondary A700 shade in $brand-palette
$secondary-a700: color($brand-palette, 'secondary', 'A700');

.panel {
  background: $raised;
  border-color: $primary-600;
}
```

Sin `$palette`, `color()` devuelve una referencia a la variable CSS, de modo que el valor sigue a la paleta que se emita en tiempo de ejecución. Con `$palette`, devuelve el color resuelto de ese mapa. `$color` toma por defecto `primary`, y `$variant` toma por defecto `500`, o `base` cuando `$color` es `surface`.

## Colores de texto de contraste

La función `contrast-color()` devuelve el color de contraste de un tono y acepta los mismos argumentos que `color()`:

```scss
.callout {
  background: color($color: 'primary', $variant: 600);
  color: contrast-color($color: 'primary', $variant: 600);
}
```

El resultado es un color relativo CSS que el navegador resuelve a negro o blanco según el nivel de contraste establecido por el mixin `palette()`.

## Clases de color

El mixin `color-classes()` genera una clase CSS para cada tono de la paleta, asignándola a la propiedad CSS que elija:

- `$prop`: la propiedad CSS a la que se asigna el color.
- `$prefix`: un prefijo para los nombres de clase generados. Por defecto, `'igx'`.
- `$suffix`: un sufijo para los nombres de clase generados.
- `$palette`: la paleta que se va a usar.

```scss
@include color-classes(
  $prop: 'background-color',
  $prefix: 'bg'
);
```

El tono `500` de `primary` se convierte en la clase `.bg-primary-500`:

```html
<div class="bg-primary-500">...</div>
```

## Mapas de paleta personalizados

Los temas de componente solo leen la forma del mapa de paleta, así que un mapa que escriba a mano funciona siempre que tenga las claves que leen los temas. Ponga entre comillas cada clave, incluidas las variantes numéricas, y asigne a `surface` sus roles:

```scss
$handmade-palette: (
  'primary': (
    '50': #e6eff8,
    '50-contrast': black,
    // ... '100' through '900', then 'A100', 'A200', 'A400', 'A700', each with a '-contrast' entry
    '500': #6797de,
    '500-contrast': white,
  ),
  // 'secondary', 'gray', 'info', 'success', 'warn', and 'error' follow the same pattern
  'surface': (
    'base': #ffffff,
    'base-contrast': black,
    'sunken': #f7f7f7,
    'sunken-contrast': black,
    'raised': #ffffff,
    'raised-contrast': black,
    'overlay': #ffffff,
    'overlay-contrast': black,
    'container': rgba(0, 0, 0, 0.03),
    'container-contrast': black,
  ),
);
```

Los temas de componente de Ignite UI for Angular 22.3.0 leen los tonos numerados de las familias de color y de `gray`, los tonos de acento de `primary` y `secondary`, y el rol de superficie `base`. Los demás roles de superficie están para sus propios estilos. Incluya todas las variantes enumeradas en [Descripción general](#descripción-general), para que los estilos que leen el resto sigan resolviéndose.

## Solución de problemas

**¿Por qué al sobrescribir `--ig-primary-500` no se actualizan los demás tonos primarios?** Una paleta generada con el generador `fitted` emite colores fijos. Cambie la semilla que pasa a `palette()` y vuelva a compilar, o genere la paleta con `$generator: 'legacy'` para mantener el cálculo en tiempo de ejecución a partir de `500`.

**¿Cómo migro las referencias a `--ig-surface-500` o `color($color: 'surface', $variant: 500)`?** Los tonos de superficie numerados están obsoletos en favor de los roles. Cada paleta sigue emitiéndolos, así que las referencias seguirán funcionando mientras migra. Use `base` para el fondo de la página o del componente, `raised` o `overlay` para las capas por encima de él, `sunken` para las capas insertadas en él y `container` para un relleno translúcido. `color($color: 'surface')` ya devuelve `base`.

**¿Por qué la compilación muestra `Shade "gray-900" wanted 18.232:1 but its hue only reaches …`?** La escala exige más contraste del que permiten el color y su ancla, lo que suele ocurrir con una escala de grises anclada a la superficie sobre una superficie oscura. El generador usó el tono más cercano que pudo alcanzar. Reduzca el extremo superior de `range` o establezca `anchor: 'white'`.
