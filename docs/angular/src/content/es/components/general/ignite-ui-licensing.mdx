# Preguntas frecuentes sobre licencias e instalación

Ignite UI for Angular se ofrece con un modelo de doble licencia, que permite tanto el uso comercial como el uso de código abierto con licencia permisiva, según los componentes, módulos, directivas y servicios que se utilicen.

Es fundamental entender qué licencia se aplica a cada parte del paquete. El tema [Código abierto frente a Premium](/general/open-source-vs-premium) incluye detalles sobre el tipo de licencia que se aplica a cada componente y, por tanto, sobre si necesita comprar una licencia comercial según los componentes que use en sus proyectos.

## Acuerdos de licencia

Para los componentes con licencia comercial, es importante conocer todos los [términos y condiciones legales](https://www.infragistics.com/legal/license/igultimate-la) que se aplican a su compra y uso.

<DocsAside type="info">
Actualizamos nuestras condiciones de licencia y nuestro modelo de suscripción en el cuarto trimestre de 2025.
</DocsAside>

Si su prueba ha terminado o su suscripción [ha caducado](http://www.infragistics.com/renewal), cada desarrollador de su equipo que use componentes con licencia comercial de Ignite UI deberá [comprar](https://www.infragistics.com/how-to-buy/product-pricing) una suscripción. Esto le permitirá usar nuestro feed npm privado, alojado en [https://packages.infragistics.com/npm/js-licensed/](https://packages.infragistics.com/npm/js-licensed/), para el desarrollo. Allí encontrará las versiones más recientes de los paquetes de Ignite UI for Angular. Si tiene una suscripción vigente, puede usar este feed privado y tendrá acceso a la versión completa de Ignite UI for Angular.


Infragistics ofrece licencias gratuitas, no comerciales y no revendibles (NFR) para lo siguiente:

- Si forma parte de un programa para desarrolladores, como Microsoft MVP, Microsoft Regional Director, Google Developer Expert, etc.  
- Si es estudiante de primaria, secundaria o universidad, o pertenece a una institución académica o es profesor.  

Si cumple los requisitos para una licencia gratuita, no comercial o NFR, o si tiene alguna pregunta sobre licencias, [póngase en contacto con nosotros](https://www.infragistics.com/about-us/contact-us).

## Paquetes npm de Ignite UI for Angular: usar el feed npm privado

npm es el gestor de paquetes más popular y también el predeterminado para el entorno de ejecución Node.js. Muy extendido, es una de las formas más rápidas y sencillas de gestionar los paquetes de los que depende su proyecto. Para más información sobre el funcionamiento de npm, lea la [documentación oficial de npm](https://docs.npmjs.com/).

Infragistics Ignite UI for Angular está disponible como paquete npm, y puede añadirlo como dependencia de su proyecto con [`few easy steps using the Ignite UI CLI`](/general/cli/step-by-step-guide-using-cli) o [usando Ignite UI for Angular Schematics](/general/cli/step-by-step-guide-using-angular-schematics). Elegir este enfoque no requiere configurar npm. Si solo va a usar componentes de Ignite UI for Angular con licencia MIT, no tendrá que hacer nada más. Sin embargo, si usa componentes con licencia comercial, la descarga del paquete desde npm inicia su [periodo de prueba](https://www.infragistics.com/products/ignite-ui-angular) del producto.

<DocsAside type="info">
¿Qué significa empezar a usar una versión de prueba? Significa que usará una versión de nuestro producto con una **marca de agua** en parte de su vista web. No significa que vaya a usar el paquete con licencia durante un tiempo determinado antes de que caduque, por ejemplo, un mes.
</DocsAside>

El componente web Infragistics Ignite UI Dock Manager está disponible como paquete npm independiente, y al instalarlo empezará a usar la [versión de prueba del componente web Ignite UI Dock Manager](https://www.infragistics.com/products/ignite-ui-angular) del producto.

> Puede encontrar más información sobre cómo empezar a usar el paquete npm de Ignite UI for Angular en [este tema](/general/getting-started#instalar-ignite-ui-for-angular). Información adicional sobre el componente web Ignite UI Dock Manager se encuentra en la [documentación de Dock Manager](/dock-manager).

### Actualizar paquetes con nuestros Angular Schematics o Ignite UI CLI

Si Ignite UI for Angular se añadió al proyecto con [`ng add`](/general/getting-started), o si el proyecto se creó con nuestra [colección de schematics](/general/cli/getting-started-with-angular-schematics) o con [Ignite UI CLI](/general/cli/getting-started-with-cli), puede usar nuestro `upgrade-packages` para actualizar automáticamente su aplicación a los paquetes con licencia. Las dependencias de paquetes de su proyecto incluirán `@igniteui/angular-schematics` o `igniteui-cli`, y ambos admiten el comando de actualización.

<DocsAside type="info">
Como el proceso cambia los paquetes, le recomendamos actualizar primero su proyecto antes de cambiar. Así evitará adoptar una versión superior de Ignite UI Angular y perder posibles migraciones de actualización. Siga nuestra [guía de actualización](/general/update-guide).
</DocsAside>

Según la configuración de su proyecto, ejecute el siguiente schematic en su proyecto:

```bash
ng g @igniteui/angular-schematics:upgrade-packages
```

o use `igniteui-cli`:

```bash
ig upgrade-packages
```

El schematic o el comando se encargará de cambiar las dependencias de paquetes del proyecto y de actualizar las referencias del código fuente.
Se le pedirá que inicie sesión en nuestro registro npm si todavía no está configurado.

<DocsAside type="info">
Si su proyecto usa [`yarn`](https://yarnpkg.com/), asegúrese de ejecutar `upgrade-packages` con el flag `--skip-install`. Después ejecute `yarn install` para actualizar correctamente su `yarn.lock`, ya que el comando de actualización usa actualmente `npm` para la instalación.
</DocsAside>

### Cómo configurar su entorno para usar el feed npm privado (guía paso a paso)

#### Primero debe configurar el registro privado y asociarlo con el ámbito de Infragistics

Esto le permitirá usar de forma transparente una combinación de paquetes del registro npm público y del registro privado de Infragistics.

<DocsAside type="info">
Si su cuenta no tiene licencia (todavía usa una cuenta de prueba), el feed privado de paquetes no le será accesible; por ejemplo, devolverá un error 404 o 403. **Solo las cuentas con licencia pueden acceder al feed privado de packages.infragistics.**
</DocsAside>

### Ahora, para iniciar sesión en nuestro feed privado con npm

#### npm versión 9 o posterior

Nuestro feed privado no admite actualmente los comandos `login/adduser` con npm v9, así que le recomendamos seguir estos pasos para añadir los campos de autenticación necesarios a la configuración:

```cmd
npm config set @infragistics:registry https://packages.infragistics.com/npm/js-licensed/
npm config set //packages.infragistics.com/npm/js-licensed/:username=YOUR_USERNAME
npm config set //packages.infragistics.com/npm/js-licensed/:email=YOUR_IG_EMAIL
npm config set //packages.infragistics.com/npm/js-licensed/:_auth=YOUR_IG_AUTH_TOKEN
```

Puede generar un [token de acceso](#uso-del-token-de-acceso) desde su perfil de Infragistics.

Este enfoque es aplicable a todas las versiones anteriores de `npm`.

#### npm hasta la versión 8

Ejecute el comando `adduser` e indique una cuenta de usuario y una contraseña:

```cmd
npm adduser --registry=https://packages.infragistics.com/npm/js-licensed/ --scope=@infragistics
```

Se le pedirá el nombre de usuario y la contraseña que usa para iniciar sesión en su cuenta de Infragistics. También debe indicar el correo electrónico registrado en su perfil de Infragistics.

<DocsAside type="info">
`npm` no permite usar el símbolo `"@"` dentro de su nombre de usuario, porque se considera "no seguro para la red". Como su nombre de usuario es en realidad el correo electrónico que usa para su cuenta de Infragistics, siempre contiene el símbolo `"@"`. Por eso debe salvar esta limitación sustituyendo el símbolo `"@"` por `"!!"` (dos signos de exclamación). Por ejemplo, si su nombre de usuario es `"username@example.com"`, cuando se le pida el nombre de usuario debe indicar lo siguiente: `"username!!example.com"`.
</DocsAside>

<DocsAside type="info">
**Comportamiento del shell de macOS**: si usa macOS y establece el token `:_auth` manualmente mediante `npm config set`, asegúrese de **encerrar el token entre comillas dobles**, así:

```bash
npm config set //packages.infragistics.com/npm/js-licensed/:_auth="YOUR_IG_AUTH_TOKEN"
```

Esto es necesario por las diferencias en el análisis del shell en macOS, que pueden causar problemas de autenticación si los caracteres especiales del token no se entrecomillan correctamente. Este problema normalmente no ocurre en Windows.
</DocsAside>

#### Una vez hecho esto, habrá iniciado sesión y podrá instalar las versiones más recientes de los paquetes de Ignite UI en su proyecto

```cmd
npm uninstall igniteui-angular
npm install @infragistics/igniteui-angular

npm uninstall igniteui-dockmanager
npm install @infragistics/igniteui-dockmanager
```

Tenga en cuenta que hemos definido el paquete de Ignite UI for Angular con ámbito, lo que significa que no hacen falta cambios en el registro si quiere instalar paquetes del feed privado y de npmjs.org al mismo tiempo.

#### Es posible que haya que hacer algunos cambios adicionales en el código fuente del proyecto

Si está actualizando de un paquete de prueba a uno con licencia y no usa las migraciones automáticas de la CLI:

- Añada una asignación de **paths** en el **tsconfig.json** del proyecto.

```json
{
  /* ... */
  "compilerOptions": {
    "baseUrl": "./",
    "outDir": "./dist/out-tsc",
    /* ... */
    "paths": {
      "igniteui-dockmanager": ["./node_modules/@infragistics/igniteui-dockmanager"],
      "igniteui-dockmanager/*": ["./node_modules/@infragistics/igniteui-dockmanager/*"],
    }
  }
}
```

- Añada una asignación `stylePreprocessorOptions` en el `angular.json` de su proyecto

```json
{
  "projects": {
    ..
    "prefix": "app",
      "architect": {
        "build": {
          "builder": "@angular-devkit/build-angular:browser",
          "options": {
            ...
            "aot": true,
            "stylePreprocessorOptions": {
                "includePaths": [
                    "node_modules/@infragistics"
                ]
            }
            ...
},
```

- Elimine el signo `~` de las importaciones de Sass de su proyecto para el origen `igniteui-angular/lib`:

```scss
@use "~igniteui-angular/lib/core/styles/themes/index" as *;

// Should be changed to
@use "igniteui-angular/lib/core/styles/themes/index" as *;
```

Si ya ha adoptado npm y tiene una licencia de Ignite UI for Angular, configure el feed privado de Infragistics para aumentar su productividad y aprovechar todo el potencial de Ignite UI for Angular.


## Uso del token de acceso

También puede autenticarse en nuestro feed npm privado con un token de acceso, que puede obtener desde su [cuenta de usuario de infragistics.com](https://account.infragistics.com/package-feeds). La autenticación con token de acceso es la alternativa preferida cuando quiere integrar un proceso de CI en un repositorio de acceso público que usa los paquetes con licencia de Ignite UI for Angular.

La siguiente información explica cómo configurar la autenticación en nuestro registro npm privado con un token de acceso en la configuración local, en los procedimientos de compilación de Azure Pipelines y en el proceso de compilación de Travis CI:

- Genere un token desde https://account.infragistics.com/package-feeds

<Image src={generateToken} alt="Nuevo token generado" class="responsive-img" style="-webkit-box-shadow: 8px 9px 9px 5px #ccc; -moz-box-shadow: 8px 9px 9px 5px #ccc; box-shadow: 8px 9px 9px 5px #ccc; width: calc(100% - 250px)" />

<DocsAside type="info">
Cada token está codificado en Base64.
</DocsAside>

- Añada lo siguiente a su archivo [.npmrc](https://docs.npmjs.com/configuring-npm/npmrc.html)

```cmd
@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/
//packages.infragistics.com/npm/js-licensed/:_auth=YOUR_ACCESS_TOKEN
//packages.infragistics.com/npm/js-licensed/:username=YOUR_USERNAME
```

### Configuración de Azure Pipelines

Actualice `azure-pipelines.yml` con los pasos siguientes:

```cmd
steps:

- script: npm config set @infragistics:registry $(npmRegistry)
  displayName: 'Npm add registry'
- script: npm config set $(igScope):_auth=$(token)
  displayName: 'Npm config auth'
```

Ahora añada variables para el _registro npm_, el _ámbito_ y el _token_. Hay dos formas de hacerlo:

#### Defina un grupo de variables desde la página Library, en Pipelines

[Este artículo](https://docs.microsoft.com/en-us/azure/devops/pipelines/library/variable-groups?view=azure-devops&tabs=yaml) explica cómo usar un grupo de variables para guardar valores que quiere controlar y que estén disponibles en varios pipelines.

### Configuración de Travis CI

Siga aquí un enfoque similar. La única diferencia es que la configuración se establece en el paso `before_install`:

```cmd
before_install:
- echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- echo "//packages.infragistics.com/npm/js-licensed/:_auth=$TOKEN" >> ~/.npmrc
```

La mejor forma de definir una variable de entorno depende del tipo de información que vaya a contener. Por tanto, [tiene dos opciones](https://docs.travis-ci.com/user/environment-variables/):

- cifrarla y añadirla [a su .travis.yml](https://docs.travis-ci.com/user/environment-variables/#defining-encrypted-variables-in-travisyml)
- añadirla a la [configuración del repositorio](https://docs.travis-ci.com/user/environment-variables/#defining-variables-in-repository-settings)

### Configuración de GitHub Actions

Añada los scripts siguientes antes del paso `npm install` (o `npm ci`) en la [configuración de su flujo de CI](https://help.github.com/en/actions/language-and-framework-guides/using-nodejs-with-github-actions):

```cmd
- run: echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- run: echo "//packages.infragistics.com/npm/js-licensed/:_auth=${{ secrets.NPM_TOKEN }}" >> ~/.npmrc
```

Defina [_secretos_ (variables de entorno cifradas)](https://help.github.com/en/actions/configuring-and-managing-workflows/creating-and-storing-encrypted-secrets) y úselos en el flujo de trabajo de GitHub Actions para información sensible, como el token de acceso.
