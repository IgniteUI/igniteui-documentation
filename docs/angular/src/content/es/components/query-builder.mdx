# Información general del componente Angular Query Builder

Angular Query Builder forma parte de nuestros [componentes de Angular](https://www.infragistics.com/products/ignite-ui-angular) y ofrece una interfaz rica que permite a los desarrolladores crear consultas complejas de filtrado de datos para un conjunto de datos determinado. Con este componente pueden construir un árbol de expresiones y establecer condiciones Y/O entre ellas, con editores y listas de condiciones determinados por el tipo de datos de cada campo. El árbol de expresiones puede transformarse fácilmente en una consulta con el formato que admite el backend.

<div class="highlight">

El componente <ApiLink type="QueryBuilder" /> permite crear consultas complejas a través de la interfaz. Con los operadores AND/OR, las condiciones y los valores, el usuario crea un árbol de expresiones que describe la consulta.

</div>

## Primeros pasos con Ignite UI for Angular Query Builder

Para empezar a usar el componente Ignite UI for Angular Query Builder, primero debe instalar Ignite UI for Angular. En una aplicación Angular existente, escriba el siguiente comando:

```cmd
ng add igniteui-angular
```

Para una introducción completa a Ignite UI for Angular, lea el tema [_primeros pasos_](./general/getting-started.mdx).

El siguiente paso es importar `IgxQueryBuilderModule` en el archivo **app.module.ts**.

```typescript
// app.module.ts

import { IgxQueryBuilderModule } from 'igniteui-angular/query-builder';
// import { IgxQueryBuilderModule } from '@infragistics/igniteui-angular'; for licensed package

@NgModule({
    ...
    imports: [..., IgxQueryBuilderModule],
    ...
})
export class AppModule {}
```

Como alternativa, a partir de `16.0.0` puede importar `IgxQueryBuilderComponent` como dependencia independiente, o usar el token [`IGX_QUERY_BUILDER_DIRECTIVES`](https://github.com/IgniteUI/igniteui-angular/blob/master/projects/igniteui-angular/query-builder/src/query-builder/public_api.ts) para importar el componente y todos sus componentes y directivas de apoyo.

```typescript
// home.component.ts

import { IGX_QUERY_BUILDER_DIRECTIVES } from 'igniteui-angular/query-builder';
import { FilteringExpressionsTree, FieldType } from 'igniteui-angular/core';
// import { IGX_QUERY_BUILDER_DIRECTIVES, FilteringExpressionsTree, FieldType } from '@infragistics/igniteui-angular'; for licensed package

@Component({
    selector: 'app-home',
    template: `
    <igx-query-builder #queryBuilder
        [entities]="entities"
        [(expressionTree)]="expressionTree"
        (expressionTreeChange)="onExpressionTreeChange()">
    </igx-query-builder>
    `,
    styleUrls: ['home.component.scss'],
    standalone: true,
    imports: [IGX_QUERY_BUILDER_DIRECTIVES]
    /* or imports: [IgxQueryBuilderComponent] */
})
export class HomeComponent {
    public expressionTree: FilteringExpressionsTree;
    public entities: Array<any>;

    public onExpressionTreeChange() {
        ...
    }
}
```

Ahora que ha importado el módulo o las directivas de Ignite UI for Angular Query Builder, puede empezar a usar el componente `igx-query-builder`.

## Uso de Angular Query Builder

Si no hay ningún árbol de expresiones establecido inicialmente, empiece eligiendo una entidad y los campos de esta que debe devolver la consulta. Después pueden añadirse condiciones o subgrupos.

Para añadir una condición, seleccione un campo, un operando según el tipo de datos del campo y un valor si el operando no es unario. Los operandos `In` y `Not In` le permitirán crear una consulta interna con condiciones para una entidad distinta, en lugar de proporcionar simplemente un valor. Una vez confirmada la condición, aparece un chip con la información de la condición. Al hacer clic o pasar el cursor sobre el chip, tiene las opciones de modificarlo o de añadir otra condición o grupo justo después.

Al hacer clic en el botón (<ApiLink kind="enum" type="FilteringLogic" member="And" /> o <ApiLink kind="enum" type="FilteringLogic" member="Or" />) situado encima de cada grupo, se abre un menú con opciones para cambiar el tipo de grupo o desagrupar las condiciones que contiene.

Como cada condición está relacionada con un campo concreto de una entidad determinada, cambiar la entidad restablecerá todas las condiciones y grupos preestablecidos. Al seleccionar una nueva entidad se mostrará un cuadro de diálogo de confirmación, salvo que la propiedad de entrada <ApiLink type="QueryBuilder" member="showEntityChangeDialog" label="showEntityChangeDialog" /> se establezca en false.

Puede empezar a usar el componente estableciendo la propiedad <ApiLink type="QueryBuilder" member="entities" label="entities" /> en un array que describa el nombre de la entidad y un array de sus campos, donde cada campo se define por su nombre y su tipo de datos. Una vez seleccionado un campo, se asignan automáticamente los operandos correspondientes según su tipo de datos.
El Query Builder tiene la propiedad de entrada <ApiLink type="QueryBuilder" member="expressionTree" label="expressionTree" />. Puede usarla para establecer un estado inicial del control y acceder a la lógica de filtrado especificada por el usuario.

```typescript
ngAfterViewInit(): void {
    const innerTree = new FilteringExpressionsTree(FilteringLogic.And, undefined, 'Companies', ['ID']);
    innerTree.filteringOperands.push({
        fieldName: 'Employees',
        condition: IgxNumberFilteringOperand.instance().condition('greaterThan'),
        conditionName: 'greaterThan',
        searchVal: 100
    });
    innerTree.filteringOperands.push({
        fieldName: 'Contact',
        condition: IgxBooleanFilteringOperand.instance().condition('true'),
        conditionName: 'true'
    });

    const tree = new FilteringExpressionsTree(FilteringLogic.And, undefined, 'Orders', ['*']);
    tree.filteringOperands.push({
        fieldName: 'CompanyID',
        condition: IgxStringFilteringOperand.instance().condition('inQuery'),
        conditionName: 'inQuery',
        searchTree: innerTree
    });
    tree.filteringOperands.push({
        fieldName: 'OrderDate',
        condition: IgxDateFilteringOperand.instance().condition('before'),
        conditionName: 'before',
        searchVal: new Date('2024-01-01T00:00:00.000Z')
    });
    tree.filteringOperands.push({
        fieldName: 'ShippedDate',
        condition: IgxDateFilteringOperand.instance().condition('null'),
        conditionName: 'null'
    });

    this.queryBuilder.expressionTree = tree;
}
```

<ApiLink type="QueryBuilder" member="expressionTree" label="expressionTree" /> es una propiedad de enlace bidireccional, lo que significa que se implementa una salida <ApiLink type="QueryBuilder" member="expressionTreeChange" label="expressionTreeChange" /> correspondiente que se emite cuando el usuario final modifica la interfaz creando, editando o eliminando condiciones. También puede suscribirse por separado para recibir notificaciones y reaccionar a esos cambios.

```html
<igx-query-builder #queryBuilder
    [entities]="entities"
    [(expressionTree)]="expressionTree"
    (expressionTreeChange)="onExpressionTreeChange()">
</igx-query-builder>
```

## Arrastrar expresiones

Los chips de condición pueden recolocarse fácilmente con los métodos de [_arrastrar y soltar_](./drag-drop.mdx) con el ratón o de [_reordenación con el teclado_](#interacción-por-teclado). Con ellos, los usuarios pueden ajustar dinámicamente la lógica de su consulta.

- Arrastrar un chip no modifica su condición ni su contenido, solo su posición.
- Los chips también pueden arrastrarse entre grupos y subgrupos. Por ejemplo, agrupar y desagrupar expresiones se logra con la función de arrastre de expresiones.
Para agrupar condiciones ya existentes, primero hay que añadir un grupo nuevo con el botón de grupo "add". Después, arrastrando, se pueden mover las expresiones necesarias a ese grupo. Para desagrupar, puede arrastrar todas las condiciones fuera de su grupo actual; cuando se mueva la última condición fuera, el grupo se eliminará.

<DocsAside type="info">
Los chips de un árbol de consulta no pueden arrastrarse a otro, por ejemplo, de la consulta principal a una interna y viceversa.
</DocsAside>

## Interacción por teclado

**Combinaciones de teclas**

- <kbd>Tab</kbd> / <kbd>Shift + Tab</kbd>: navega al chip, indicador de arrastre, botón de eliminar o botón de expresión 'add' siguiente o anterior.
- <kbd>Arrow Down</kbd> / <kbd>Arrow Up</kbd>: cuando el indicador de arrastre del chip tiene el foco, el chip puede moverse hacia abajo o hacia arriba.
- <kbd>Space</kbd> / <kbd>Enter</kbd>: la expresión enfocada entra en modo de edición. Si el chip se ha movido, esto confirma su nueva posición.
- <kbd>Esc</kbd>: se cancela la reordenación del chip y vuelve a su posición original.

<DocsAside type="info">
La reordenación con el teclado ofrece la misma funcionalidad que arrastrar y soltar con el ratón. Una vez movido un chip, el usuario debe confirmar la nueva posición o cancelar la reordenación.
</DocsAside>

## Plantillas

El componente Ignite UI for Angular Query Builder permite definir plantillas para el encabezado del componente y para el valor de búsqueda, usando los siguientes nombres de referencia predefinidos:

### Plantilla de encabezado

De forma predeterminada no se muestra el encabezado <ApiLink type="QueryBuilder" />. Para definirlo, hay que añadir <ApiLink type="QueryBuilderHeader" /> dentro de `igx-query-builder`.

Después, para establecer el título del encabezado puede usarse la entrada <ApiLink type="QueryBuilderHeader" member="title" label="title" />, y pasar contenido dentro de `igx-query-builder-header` permite crear una plantilla para el encabezado del Query Builder.

 El fragmento de código siguiente muestra cómo hacerlo:

```html
<igx-query-builder #queryBuilder [entities]="this.entities">
        <igx-query-builder-header [title]="'Query Builder Template Sample'">  
        </igx-query-builder-header>
</igx-query-builder>
```

### Valor de búsqueda

El valor de búsqueda de una condición puede tener una plantilla usando la directiva <ApiLink type="QueryBuilderSearchValueTemplateDirective" label="igxQueryBuilderSearchValue" />, aplicada a un `<ng-template>` dentro del cuerpo de `igx-query-builder`:

```html
<igx-query-builder #queryBuilder
    [entities]="entities"
    [expressionTree]="expressionTree">
    <ng-template #searchValueTemplate
                igxQueryBuilderSearchValue 
                let-searchValue
                let-selectedField = "selectedField" 
                let-selectedCondition = "selectedCondition"
                let-defaultSearchValueTemplate = "defaultSearchValueTemplate">
        @if (
            selectedField?.field === 'Region' &&
            (selectedCondition === 'equals' || selectedCondition === 'doesNotEqual')
            ){
            <igx-select [placeholder]="'Select region'" [(ngModel)]="searchValue.value">
                <igx-select-item *ngFor="let reg of regionOptions" [value]="reg">
                    {{ reg.text }}
                </igx-select-item>
            </igx-select>
        } 
        @else if (
            selectedField?.field === 'OrderStatus' &&
            (selectedCondition === 'equals' || selectedCondition === 'doesNotEqual')
            ){
            <igx-radio-group>
                <igx-radio class="radio-sample"
                           *ngFor="let stat of statusOptions"
                           value="{{stat.value}}"
                           [(ngModel)]="searchValue.value">
                    {{stat.text}}
                </igx-radio>
            </igx-radio-group>
        }
            @else {  
            <ng-container #defaultTemplate *ngTemplateOutlet="defaultSearchValueTemplate"></ng-container>
        }
    </ng-template>
</igx-query-builder>
```

### Formateador

Para cambiar el aspecto del valor de búsqueda en el chip que se muestra cuando una condición no está en modo de edición, puede establecer una función formateadora en el array de campos. Se puede acceder al valor de búsqueda y a la condición seleccionada a través de los argumentos value y rowData, así:

```ts
this.ordersFields = [
    { field: "CompanyID", dataType: "string" },
    { field: "OrderID", dataType: "number" },
    { field: "EmployeeId", dataType: "number" },
    { field: "OrderDate", dataType: "date" },
    { field: "RequiredDate", dataType: "date" },
    { field: "ShippedDate", dataType: "date" },
    { field: "ShipVia", dataType: "number" },
    { field: "Freight", dataType: "number" },
    { field: "ShipName", dataType: "string" },
    { field: "ShipCity", dataType: "string" },
    { field: "ShipPostalCode", dataType: "string" },
    { field: "ShipCountry", dataType: "string" },
    { field: "Region", dataType: "string", formatter: (value: any, rowData: any) => rowData === 'equals' || rowData === 'doesNotEqual' ? `${value.value}` : value }},
    { field: "OrderStatus", dataType: "number" }
];
```

## Estilos

### Mapa de propiedades del tema Query Builder

Al modificar una propiedad principal, todas las propiedades dependientes relacionadas se actualizan automáticamente para reflejar el cambio:

| Propiedad principal | Propiedad dependiente | Descripción |
| --- | --- | --- |
| **$background** | $label-foreground | El color de las etiquetas "from" y "select" del Query Builder |
|  | $header-background | El color de fondo del encabezado del Query Builder |
|  | $header-foreground | El color de primer plano del encabezado del Query Builder |
|  | $subquery-header-background | El color de fondo del encabezado de la subconsulta |
|  | $subquery-border-color | El color del borde del bloque de consulta |
|  | $separator-color | El color del separador del bloque de consulta |
|  | $header-border (solo Bootstrap) | El color del borde del encabezado del Query Builder |

Para empezar a dar estilo al Query Builder, debemos importar el archivo `index`, donde se exportan todas las funciones de tema y el mixin `tokens()`:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

El Query Builder toma su color de fondo de su tema, mediante el parámetro `background`. Para cambiar el fondo, necesitamos crear un tema personalizado:

```scss

$custom-query-builder: query-builder-theme(
  $schema: $dark-material-schema,
  $background: #292826,
  ...
);
```

Como dentro del Query Builder tenemos otros componentes, como botones, chips, desplegables y campos de entrada, necesitamos crear un tema separado para cada uno:

```scss
$custom-button: flat-button-theme(
  $schema: $dark-material-schema,
  $foreground: #ffcd0f,
);

$custom-input-group: input-group-theme(
  $schema: $dark-material-schema,
  $focused-secondary-color: #ffcd0f
);

$custom-chip: chip-theme(
  $schema: $dark-material-schema,
  $background: #ffcd0f,
);

$custom-icon-button: outlined-icon-button-theme(
  $schema: $dark-material-schema,
  $foreground: #ffcd0f,
);
```

En este ejemplo solo hemos cambiado algunos parámetros de los componentes indicados, pero los temas <ApiLink kind="sass" module="themes" type="function-flat-button-theme" label="flat-button-theme" code={true} />, <ApiLink kind="sass" module="themes" type="function-chip-theme" label="chip-theme" code={true} />, <ApiLink kind="sass" module="themes" type="function-drop-down-theme" label="drop-down-theme" code={true} /> y <ApiLink kind="sass" module="themes" type="function-input-group-theme" label="input-group-theme" code={true} /> ofrecen muchos más parámetros para controlar su estilo respectivo.

<DocsAside type="info">
En lugar de codificar los valores de color como acabamos de hacer, podemos lograr más flexibilidad con los colores usando las funciones <ApiLink kind="sass" module="palettes" type="function-palette" label="palette" code={true} /> y <ApiLink kind="sass" module="palettes" type="function-color" label="color" code={true} />. Consulte el tema [`Palettes`](./themes/sass/palettes.mdx) para obtener orientación detallada sobre cómo usarlas.
</DocsAside>

El último paso es **incluir** los nuevos temas de componente usando el mixin `tokens`.

```scss
:host {
    @include tokens($custom-query-builder);
    @include tokens($custom-input-group);
    @include tokens($custom-chip);
    @include tokens($custom-icon-button);

    .igx-filter-tree__buttons {
      @include tokens($custom-button);
    }
}
```

<DocsAside type="info">
Las sobrescrituras de tokens normalmente se heredan a través de Emulated View Encapsulation, pero los selectores generados para los controles anidados del Query Builder pueden seguir necesitando `::ng-deep`. Si el tema local no surte efecto, envuelva esa inclusión en `::ng-deep` o muévala a una hoja de estilos global. Si un desplegable está vinculado a una salida de superposición separada, emita su tema desde un selector que pueda coincidir con la salida, o configure la salida por debajo del contenedor con tema.
</DocsAside>

### Dar estilo con Tailwind

Puede dar estilo al Query Builder con nuestras clases de utilidad de Tailwind personalizadas. Asegúrese de [configurar Tailwind](./themes/tailwind.mdx) primero.

Junto con la importación de tailwind en su hoja de estilos global, puede aplicar las utilidades de tema deseadas de la siguiente manera:

```scss
@import "tailwindcss";
...
@use 'igniteui-theming/tailwind/utilities/material.css';
```

El archivo de utilidades incluye las variantes de tema `light` y `dark`.

- Use las clases `light-*` para el tema claro.
- Use las clases `dark-*` para el tema oscuro.
- Añada el nombre del componente después del prefijo, por ejemplo, `light-query-builder`, `dark-query-builder`.

Una vez aplicadas, estas clases habilitan los cálculos dinámicos del tema. A partir de ahí, puede sobrescribir las variables CSS generadas usando `arbitrary properties`. Después de los dos puntos, indique cualquier formato de color CSS válido (HEX, variable CSS, RGB, etc.).

Puede encontrar la lista completa de propiedades en <ApiLink kind="sass" module="themes" type="function-query-builder-theme" label="query-builder-theme" />. La sintaxis es la siguiente:

```html
<igx-query-builder
  class="!light-query-builder ![--background:#90B69F]">
  ...
</igx-query-builder>
```

<DocsAside type="info">
El signo de exclamación (`!`) es obligatorio para asegurar que la clase de utilidad tenga prioridad. Tailwind aplica los estilos por capas y, si no se marcan estos estilos como importantes, los sobrescribirá el tema predeterminado del componente.
</DocsAside>
