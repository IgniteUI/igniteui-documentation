# Angular {ComponentTitle} 필터링

IgniteUI for [Angular {ComponentTitle} 컴포넌트](https://www.infragistics.com/products/ignite-ui-angular/angular/components/grid/grid)는 세 가지 서로 다른 필터링 유형을 제공합니다 - 빠른 필터링, [Excel 스타일 필터링](/{igPath}/excel-style-filtering) 및 [고급 필터링](/{igPath}/advanced-filtering). 이들을 통해 지정된 기준을 충족하는 레코드만 표시할 수 있습니다. Ignite UI의 Material UI 그리드 컴포넌트는 {ComponentTitle}이(가) 바인딩된 데이터 컨테이너를 통해 Angular 필터 기능과 광범위한 필터링 API를 제공합니다.

## 설정

필터링이 활성화되어 있는지와 어떤 필터링 모드를 사용해야 하는지 지정하기 위해, {ComponentTitle}은(는) 다음 불리언 속성을 노출합니다 - <ApiLink type="{ComponentApiType}" member="allowFiltering" label="allowFiltering" />, <ApiLink type="{ComponentApiType}" member="allowAdvancedFiltering" label="allowAdvancedFiltering" />, <ApiLink type="{ComponentApiType}" member="filterMode" label="filterMode" /> 및 <ApiLink type="Column" member="filterable" label="filterable" />.

**<ApiLink type="{ComponentApiType}" member="allowfiltering" label="allowFiltering" />** 속성을 사용하면 다음 옵션을 지정할 수 있습니다:

- **false** - 해당 그리드의 필터링이 비활성화됩니다; /기본값/
- **true** - 해당 그리드의 필터링이 활성화됩니다;

**<ApiLink type="{ComponentApiType}" member="allowAdvancedFiltering" label="allowAdvancedFiltering" />** 속성을 사용하면 다음 옵션을 지정할 수 있습니다:

- **false** - 해당 그리드의 고급 필터링이 비활성화됩니다; /기본값/
- **true** - 해당 그리드의 고급 필터링이 활성화됩니다;

**<ApiLink type="{ComponentApiType}" member="filterMode" label="filterMode" />** 속성을 사용하면 다음 옵션을 지정할 수 있습니다:

- **quickFilter** - 단순한 필터링 UI; /기본값/
- **excelStyleFilter** - Excel과 비슷한 필터링 UI;

**<ApiLink type="Column" member="filterable" label="filterable" />** 속성을 사용하면 다음 옵션을 지정할 수 있습니다:

- **true** - 해당 열의 필터링이 활성화됩니다; /기본값/
- **false** - 해당 열의 필터링이 비활성화됩니다;

## 상호 작용

특정 열의 필터 행을 열려면 머리글 아래의 'Filter' 칩을 클릭해야 합니다. 조건을 추가하려면 입력 왼쪽의 드롭다운으로 필터 피연산자를 선택하고 값을 입력합니다. `number` 및 `date` 열에서는 기본적으로 'Equals'가 선택되고, `string`에서는 'Contains', `boolean`에서는 'All'이 선택됩니다. 'Enter'를 누르면 조건이 확정되고, 다른 조건을 추가할 수 있습니다. '조건' 칩 사이에는 드롭다운이 있으며, 이는 그 사이의 논리 연산자를 결정하고, 기본값은 'AND'입니다. 조건을 제거하려면 칩의 'X' 버튼을 클릭하면 되고, 편집하려면 칩을 선택하면 입력에 칩의 데이터가 채워집니다. 필터 행이 열려 있는 동안에는 필터링 가능한 열의 머리글을 아무거나 클릭하여 선택하고, 그 열에 필터 조건을 추가할 수 있습니다.

열에 필터 조건이 적용되어 있고 필터 행이 닫혀 있을 때는, 칩의 닫기 버튼을 클릭하여 조건을 제거하거나, 칩 중 하나를 선택하여 필터 행을 열 수 있습니다. 모든 조건을 표시할 공간이 부족하면, 몇 개의 조건이 더 있는지 나타내는 배지가 붙은 필터 아이콘이 표시됩니다. 이 아이콘을 클릭해도 필터 행이 열립니다.

## 사용법

기본 필터링 전략이 기본으로 제공되며, 표준 필터링 조건도 모두 포함되어 있습니다. 개발자는 이를 자신의 구현으로 바꿀 수 있습니다. 또한 자신만의 사용자 지정 필터링 조건을 쉽게 연결할 수 있는 방법도 제공합니다. {ComponentTitle}은(는) 현재 단순한 필터링 UI뿐 아니라 더 복잡한 필터링 옵션도 제공합니다. 열의 설정된 <ApiLink type="Column" member="dataType" label="dataType" />에 따라, 필터 UI 드롭다운 안에 올바른 <ApiLink kind="interface" type="IFilteringOperation" label="필터링 작업" /> 집합이 로드됩니다. 또한 <ApiLink kind="interface" type="IFilteringExpression" /> 및 초기 <ApiLink kind="interface" type="IFilteringExpression" member="condition" /> 속성을 설정할 수 있습니다.

필터링 기능은 <ApiLink type="{ComponentApiType}" member="allowFiltering" label="allowFiltering" /> 입력을 `true`(으)로 설정하여 {ComponentTitle} 컴포넌트에 활성화됩니다. 기본 <ApiLink type="{ComponentApiType}" member="filterMode" label="filterMode" />은(는) `quickFilter`이며, 실행 중에 바꿀 **수 없습니다**. 특정 열에 대해 이 기능을 비활성화하려면 <ApiLink type="Column" member="filterable" label="filterable" /> 입력을 `false`(으)로 설정하십시오.

<DocsAside type="info">
`string` 유형의 값이 dataType `Date`인 열에서 사용되면, {ComponentTitle}은(는) 이를 `Date` 객체로 구문 분석하지 않으므로 필터링 조건을 사용할 수 없습니다. `string` 객체를 사용하고 싶다면, 값을 `Date` 객체로 구문 분석하기 위한 추가 로직을 애플리케이션 수준에서 구현해야 합니다.
</DocsAside>

{ComponentTitle} API를 통해 어떤 열이든 또는 여러 열의 조합이든 필터링할 수 있습니다. {ComponentTitle}은(는) 이 작업을 위한 여러 메서드를 노출합니다 - <ApiLink type="{ComponentApiType}" member="filter" label="filter" />, <ApiLink type="{ComponentApiType}" member="filterglobal" label="filterGlobal" /> 및 <ApiLink type="{ComponentApiType}" member="clearFilter" label="clearFilter" />.

- <ApiLink type="{ComponentApiType}" member="filter" label="filter" /> - 단일 열 또는 여러 열의 조합을 필터링합니다.

노출된 필터링 피연산자 클래스는 다섯 가지입니다:

- <ApiLink type="FilteringOperand" />: 사용자 지정 필터링 조건을 정의할 때 상속할 수 있는 기본 필터링 피연산자입니다.
- <ApiLink type="BooleanFilteringOperand" />은(는) `boolean` 유형의 모든 기본 필터링 조건을 정의합니다.
- <ApiLink type="NumberFilteringOperand" />은(는) `numeric` 유형의 모든 기본 필터링 조건을 정의합니다.
- <ApiLink type="StringFilteringOperand" />은(는) `string` 유형의 모든 기본 필터링 조건을 정의합니다.
- <ApiLink type="DateFilteringOperand" />은(는) `Date` 유형의 모든 기본 필터링 조건을 정의합니다.

## 초기 필터링 상태

{ComponentTitle}의 초기 필터링 상태를 설정하려면, 필터링할 각 열에 대해 <ApiLink type="{ComponentApiType}" /> <ApiLink type="{ComponentApiType}" member="filteringExpressionsTree" label="filteringExpressionsTree" /> 속성을 <ApiLink type="IFilteringExpressionsTree" kind="interface" />의 배열로 설정하십시오.

<ComponentBlock for="TreeGrid">

```typescript
constructor(private cdr: ChangeDetectorRef) { }

public ngAfterViewInit() {
    const gridFilteringExpressionsTree = new FilteringExpressionsTree(FilteringLogic.And);
    const productFilteringExpressionsTree = new FilteringExpressionsTree(FilteringLogic.And, 'Order Product');
    const productExpression = {
        condition: IgxStringFilteringOperand.instance().condition('contains'),
        fieldName: 'Order Product',
        ignoreCase: true,
        searchVal: 'c'
    };
    productFilteringExpressionsTree.filteringOperands.push(productExpression);
    gridFilteringExpressionsTree.filteringOperands.push(productFilteringExpressionsTree);

    this.{ComponentObjectRef}.filteringExpressionsTree = gridFilteringExpressionsTree;
    this.cdr.detectChanges();
}
```

</ComponentBlock>

```typescript
    gridFilteringExpressionsTree.filteringOperands.push(productFilteringExpressionsTree);

    this.{ComponentObjectRef}.filteringExpressionsTree = gridFilteringExpressionsTree;
    this.cdr.detectChanges();
}
```

## 사용자 지정 필터링 피연산자

필터링 피연산자를 추가, 제거 또는 수정하여 필터링 메뉴를 사용자 지정할 수 있습니다. 기본적으로 필터링 메뉴에는 열의 데이터 유형(<ApiLink type="BooleanFilteringOperand" />, <ApiLink type="DateFilteringOperand" />, <ApiLink type="NumberFilteringOperand" /> 및 <ApiLink type="StringFilteringOperand" />)에 따른 특정 피연산자가 포함됩니다. 이 클래스들이나 그 기본 클래스인 <ApiLink type="FilteringOperand" />을(를) 확장하여 필터링 메뉴 항목의 동작을 바꿀 수 있습니다.

</ComponentBlock>
<ComponentBlock for="TreeGrid">

</ComponentBlock>

이를 하려면 <ApiLink type="StringFilteringOperand" />과(와) <ApiLink type="BooleanFilteringOperand" />을(를) 확장하고, 작업과 그 논리를 수정한 다음, 열의 <ApiLink type="Column" member="filters" label="filters" /> 입력을 새 피연산자로 설정하십시오.

```typescript
// grid-custom-filtering.component.ts

export class GridCustomFilteringComponent {
    public caseSensitiveFilteringOperand = CaseSensitiveFilteringOperand.instance();
    public booleanFilteringOperand = BooleanFilteringOperand.instance();
}

export class CaseSensitiveFilteringOperand extends IgxStringFilteringOperand {
    private constructor() {
        super();
        const customOperations = [
            {
                iconName: 'contains',
                isUnary: false,
                logic: (target: string, searchVal: string, ignoreCase?: boolean) => {
                    ignoreCase = false;
                    const search = IgxStringFilteringOperand.applyIgnoreCase(searchVal, ignoreCase);
                    target = IgxStringFilteringOperand.applyIgnoreCase(target, ignoreCase);
                    return target.indexOf(search) !== -1;
                },
                name: 'Contains (case sensitive)'
            },
            {
                iconName: 'does_not_contain',
                isUnary: false,
                logic: (target: string, searchVal: string, ignoreCase?: boolean) => {
                    ignoreCase = false;
                    const search = IgxStringFilteringOperand.applyIgnoreCase(searchVal, ignoreCase);
                    target = IgxStringFilteringOperand.applyIgnoreCase(target, ignoreCase);
                    return target.indexOf(search) === -1;
                },
                name: 'Does Not Contain (case sensitive)'
            }
        ];

        const emptyOperators = [
            // 'Empty'
            this.operations[6],
            // 'Not Empty'
            this.operations[7]
        ];

        this.operations = customOperations.concat(emptyOperators);
    }
}

export class BooleanFilteringOperand extends IgxBooleanFilteringOperand {
    private constructor() {
        super();
        this.operations = [
            // 'All'
            this.operations[0],
            // 'TRUE'
            this.operations[1],
            // 'FALSE'
            this.operations[2]
        ];
    }
}
```

## 스타일링

필터링 행의 스타일 지정을 시작하려면 모든 테마 함수와 `tokens()` 믹스인이 내보내진 `index` 파일을 가져와야 합니다:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

가장 간단한 방법으로, <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} />을(를) 확장하고 `$filtering-row-text-color`, `$filtering-row-background`, `$filtering-header-text-color` 및 `$filtering-header-background` 매개변수를 받는 새 테마를 만듭니다.

```scss
$custom-grid: grid-theme(
  $filtering-row-text-color: #292826,
  $filtering-row-background: #ffcd0f,
  $filtering-header-text-color: #292826,
  $filtering-header-background: #ffcd0f
);
```

보시다시피 `grid-theme`은(는) 필터링 행과 필터링되고 있는 해당 열 머리글의 색상만 제어합니다. 필터링 행 안에는 입력 그룹, 칩, 버튼 등 훨씬 더 많은 컴포넌트가 있습니다. 이들의 스타일을 지정하려면 각각에 대해 별도의 테마를 만들어야 하므로, 새 <ApiLink kind="sass" module="themes" type="input-group-theme" label="input-group-theme" code={true} />과 새 <ApiLink kind="sass" module="themes" type="flat-button-theme" label="flat-button-theme" code={true} />을 만들어 보겠습니다:

```scss
$dark-input-group: input-group-theme(
  $box-background: #ffcd0f,
  $idle-text-color: #292826,
  $focused-text-color: #292826,
  $filled-text-color: #292826
);

$dark-button: flat-button-theme(
  $background: #ffcd0f,
  $foreground: #292826,
  $hover-background: #292826,
  $hover-foreground: #ffcd0f
);
```

<DocsAside type="info">
방금 한 것처럼 색상 값을 직접 하드코딩하는 대신, <ApiLink kind="sass" module="palettes" type="function-palette" label="palette" code={true} /> 및 <ApiLink kind="sass" module="palettes" type="function-color" label="color" code={true} /> 함수를 사용하면 색상을 훨씬 유연하게 다룰 수 있습니다. 사용 방법에 대한 자세한 안내는 [`Palettes`](/themes/sass/palettes) 항목을 참조하십시오.
</DocsAside>

이 예제에서는 입력 그룹과 버튼의 일부 매개변수만 바꾸었지만, <ApiLink kind="sass" module="themes" type="function-input-group-theme" label="input-group-theme" code={true} />과 <ApiLink kind="sass" module="themes" type="function-flat-button-theme" label="flat-button-theme" code={true} />은(는) 각 스타일을 제어하는 훨씬 더 많은 매개변수를 제공합니다.

마지막 단계는 `tokens()`로 각 컴포넌트 테마를 적용하는 것입니다. 또한 입력의 자리 표시자에 대한 color 속성도 설정하겠습니다.

```scss
:host {
@include tokens($custom-grid);

    .igx-grid__filtering-row {
        @include tokens($dark-button);
        @include tokens($dark-input-group);  

        .igx-input-group__input::placeholder {
            color: #ffcd0f;
        }
    }
}
```

<DocsAside type="info">
생성한 **flat-button-theme**과 **input-group-theme**을 `.igx-grid__filtering-row` 안에 포함하여, 필터링 행의 버튼과 입력 그룹만 스타일이 지정되도록 하겠습니다. 그렇지 않으면 그리드의 다른 버튼과 입력 그룹도 영향을 받습니다.
</DocsAside>

<DocsAside type="info">
이 샘플은 `::ng-deep`을(를) 사용하는데, 버튼, 입력, 자리 표시자 테마가 그리드 내부의 필터링 행 선택기에 의도적으로 제한되어 있기 때문입니다. 이 재정의를 전역 스타일시트로 옮기는 것이 대안입니다:
</DocsAside>

```scss
:host {
  ::ng-deep {
    @include tokens($custom-grid);

    .igx-grid__filtering-row {
      @include tokens($dark-button);
      @include tokens($dark-input-group)

      .igx-input-group__input::placeholder {
        color: #ffcd0f;
      }
    }
  }
}
```

### 6.1.0의 호환성이 깨지는 변경 사항

- {ComponentName} `filteringExpressions` 속성이 제거되었습니다. 대신 <ApiLink type="{ComponentApiType}" member="filteringexpressionstree" label="filteringExpressionsTree" />을(를) 사용하십시오.
- `filter_multiple` 메서드가 제거되었습니다. 대신 <ApiLink type="{ComponentApiType}" member="filter" label="filter" /> 메서드와 <ApiLink type="{ComponentApiType}" member="filteringExpressionsTree" label="filteringExpressionsTree" /> 속성을 사용하십시오.
- <ApiLink type="{ComponentApiType}" member="filter" label="filter" /> 메서드는 새 시그니처를 가집니다. 이제 다음 매개변수를 받습니다:
  - `name` - 필터링할 열의 이름입니다.
  - `value` - 필터링에 사용할 값입니다.
  - `conditionOrExpressionTree`(선택 사항) - 이 매개변수는 <ApiLink type="IFilteringOperation" kind="interface" /> 또는 <ApiLink type="IFilteringExpressionsTree" kind="interface" /> 유형의 객체를 받습니다. 단순 필터링만 필요하면 필터링 작업을 인수로 전달할 수 있습니다. 고급 필터링의 경우, 복잡한 필터링 로직을 담은 식 트리를 인수로 전달할 수 있습니다.
  - `ignoreCase`(선택 사항) - 필터링이 대소문자를 구분하는지 여부입니다.
- <ApiLink type="{ComponentApiType}" member="filteringDone" label="filteringDone" /> 이벤트는 이제 필터링된 열의 필터링 상태를 담은 <ApiLink type="IFilteringExpressionsTree" kind="interface" /> 유형의 매개변수 하나만 가집니다.
- 필터링 피연산자: <ApiLink type="IFilteringExpression" kind="interface" /> condition 속성은 더 이상 필터링 조건 메서드에 대한 직접 참조가 아니라, <ApiLink type="IFilteringOperation" kind="interface" />에 대한 참조입니다.
- <ApiLink type="Column" />은(는) 이제 <ApiLink type="FilteringOperand" /> 클래스 참조를 받는 <ApiLink type="Column" member="filters" label="filters" /> 속성을 노출합니다.
- <ApiLink type="FilteringOperand" />의 <ApiLink type="FilteringOperand" member="operations" label="operations" /> 속성을 <ApiLink type="IFilteringOperation" kind="interface" /> 유형의 작업으로 채우면, {ComponentTitle} 열에 사용자 지정 필터를 제공할 수 있습니다.
</ComponentBlock>
