# Query Builder 모델 사용하기

Angular Query Builder는 직렬화 및 역직렬화가 가능한 JSON 형식 모델을 제공하여 SQL 쿼리를 쉽게 만들 수 있게 합니다.

## 개요

이 Angular Query Builder 예제는 <ApiLink type="QueryBuilder" /> 식 트리를 사용하여 엔드포인트 [Northwind WebAPI](https://data-northwind.indigo.design/swagger/index.html)에서 데이터를 요청하고 이를 <ApiLink type="Grid" /> 데이터 소스로 설정하는 방법을 보여 줍니다.

## Query Builder 모델

식 트리를 <ApiLink type="QueryBuilder" />에 설정하려면 <ApiLink type="FilteringExpressionsTree" />을(를) 정의해야 합니다. 각 <ApiLink type="FilteringExpressionsTree" />에는 데이터 레코드가 트리에 대해 어떻게 판정되는지를 나타내는 필터링 로직이 있어야 하며, 사용 사례에 따라 필드 이름, 엔티티 이름, 반환 필드 배열을 전달할 수 있습니다. 특정 엔티티의 모든 필드를 반환해야 한다면 `returnFields` 속성을 ['*']로 설정할 수 있습니다:

```ts
const tree = new FilteringExpressionsTree(FilteringLogic.And, undefined, 'Entity A', ['*']);
```

루트 <ApiLink type="FilteringExpressionsTree" />을(를) 만든 후에는 `filteringOperands` 속성을 <ApiLink type="IFilteringExpression" kind="interface" />(단일 식 또는 그룹) 또는 <ApiLink type="IFilteringExpressionsTree" kind="interface" />(하위 쿼리)의 배열로 설정하여 조건, 그룹 또는 하위 쿼리를 추가할 수 있습니다.
각 <ApiLink type="IFilteringExpression" kind="interface" />과(와) <ApiLink type="IFilteringExpressionsTree" kind="interface" />에는 필터링 식이 놓일 열의 이름인 `fieldName`이(가) 있어야 하며, <ApiLink type="IFilteringOperation" kind="interface" /> 유형의 `condition` 또는 `conditionName` 중 하나가 있어야 합니다. 필요하다면 `searchVal`, <ApiLink type="IExpressionTree" kind="interface" /> 유형의 `searchTree`, 그리고 `ignoreCase` 속성도 설정할 수 있습니다.

- 단순 **식** 정의하기:

```ts
tree.filteringOperands.push({
            fieldName: 'Name',
            conditionName: IgxStringFilteringOperand.instance().condition('endsWith').name,
            searchVal: 'a'
        });
```

- 식의 **그룹** 정의하기:

```ts
const group = new FilteringExpressionsTree(FilteringLogic.Or, undefined, 'Entity A', ['*']);
group.filteringOperands.push({
    fieldName: 'Name',
    conditionName: IgxStringFilteringOperand.instance().condition('endsWith').name,
    searchVal: 'a'
});
group.filteringOperands.push({
    fieldName: 'DateTime created',
    conditionName: IgxDateFilteringOperand.instance().condition('today').name
});
tree.filteringOperands.push(group);
```

- **하위 쿼리** 정의하기:

```ts
const innerTree = new FilteringExpressionsTree(FilteringLogic.And, undefined, 'Entity B', ['Number']);
innerTree.filteringOperands.push({
    fieldName: 'Number',
    conditionName: 'equals',
    searchVal: 123
});
 tree.filteringOperands.push({
    fieldName: 'Id',
    conditionName: 'inQuery',
    searchTree: innerTree
});
```

모델은 JSON 형식으로 직렬화 및 역직렬화할 수 있으므로 클라이언트와 서버 간에 쉽게 전송할 수 있습니다:

```ts
JSON.stringify(tree, null, 2);
```

## 하위 쿼리 사용하기

<ApiLink type="QueryBuilder" />의 맥락에서 _IN / NOT-IN_ 연산자는 _WHERE_ 절에서 새로 노출된 하위 쿼리 기능과 함께 사용됩니다.

<DocsAside type="info">
하위 쿼리는 다른 쿼리 안에 중첩되어, 바깥 쿼리의 조건으로 사용될 데이터를 가져오는 데 쓰이는 쿼리입니다.
</DocsAside>

`FilteringExpression`에서 _IN / NOT-IN_ 연산자를 선택하면 하위 쿼리가 만들어집니다. 반환할 엔티티와 열을 선택하면, 바깥 쿼리의 지정된 열 값이 하위 쿼리가 반환한 값 중 하나와 일치하는지 확인합니다.

다음 식 트리는 다음과 같습니다:

```ts
const innerTree = new FilteringExpressionsTree(FilteringLogic.And, undefined, 'Products', ['supplierId']);
innerTree.filteringOperands.push({
    fieldName: 'supplierId',
    conditionName: IgxNumberFilteringOperand.instance().condition('greaterThan').name,
    searchVal: 10
});

const tree = new FilteringExpressionsTree(FilteringLogic.And, undefined, 'Suppliers', ['supplierId']);
tree.filteringOperands.push({
    fieldName: 'supplierId',
    conditionName: IgxStringFilteringOperand.instance().condition('inQuery').name,
    searchTree: innerTree
});
```

다음을 호출하여 직렬화할 수 있습니다:

```ts
JSON.stringify(tree, null, 2);
```

이는 다음과 같이 전송됩니다:

```
{
  "filteringOperands": [
    {
      "fieldName": "supplierId",
      "condition": {
        "name": "inQuery",
        "isUnary": false,
        "isNestedQuery": true,
        "iconName": "in"
      },
      "conditionName": "inQuery",
      "searchVal": null,
      "searchTree": {
        "filteringOperands": [
          {
            "fieldName": "supplierId",
            "condition": {
              "name": "greaterThan",
              "isUnary": false,
              "iconName": "filter_greater_than"
            },
            "conditionName": "greaterThan",
            "searchVal": 10,
            "searchTree": null
          }
        ],
        "operator": 0,
        "entity": "Suppliers",
        "returnFields": [
          "supplierId"
        ]
      }
    }
  ],
  "operator": 0,
  "entity": "Products",
  "returnFields": [
    "supplierId"
  ]
}
```

## SQL 예제

Ignite UI for Angular Query Builder 컴포넌트를 사용하여 SQL 쿼리를 만드는 실제 예제를 살펴보겠습니다.

아래 샘플에는 'Suppliers', 'Categories', 'Products'라는 이름의 `entities`이(가) 3개 있습니다.

'Beverages' 범주에 속하는 제품을 공급하는 모든 공급업체를 찾고 싶다고 가정해 보겠습니다. 데이터가 모든 엔티티에 걸쳐 나뉘어 있으므로, _IN_ 연산자를 활용하고 하위 쿼리를 만들어 이 작업을 수행할 수 있습니다. 각 하위 쿼리는 `FilteringExpressionsTree`로 표현되며, `transformExpressionTreeToSqlQuery(tree: IExpressionTree)` 메서드를 통해 SQL 쿼리로 변환할 수 있습니다.

먼저 `name`이(가) `Beverages`인 레코드의 `categoryId`을(를) 반환하는 `categoriesTree`을(를) 만듭니다. 이것이 가장 안쪽의 하위 쿼리입니다:

```ts
const categoriesTree = new FilteringExpressionsTree(0, undefined, 'Categories', ['categoryId']);
categoriesTree.filteringOperands.push({
    fieldName: 'name',
    conditionName: IgxStringFilteringOperand.instance().condition('equals').name,
    searchVal: 'Beverages'
});
```

이 `FilteringExpressionsTree`에 해당하는 SQL 쿼리는 다음과 같습니다:

```
SELECT categoryId FROM Categories WHERE name = 'Beverages'
```

그다음 `categoryId`이(가) 가장 안쪽 하위 쿼리가 반환한 `categoryId`과(와) 일치하는 레코드에 대해 `categoriesTree`의 `supplierId` 필드를 반환하는 `productsTree`을(를) 만듭니다. 이를 위해 `inQuery` 조건과 관련 `searchTree`을(를) 설정합니다. 이것이 중간 하위 쿼리입니다:

```ts
const productsTree = new FilteringExpressionsTree(0, undefined, 'Products', ['supplierId']);
productsTree.filteringOperands.push({
    fieldName: 'categoryId',
    conditionName: IgxStringFilteringOperand.instance().condition('inQuery').name,
    searchTree: categoriesTree
});
```

SQL 쿼리의 업데이트된 상태는 다음과 같습니다:

```
SELECT supplierId FROM Products WHERE categoryId IN (
    SELECT categoryId FROM Categories WHERE name = 'Beverages'
  )
```

마지막으로 `supplierId`이(가) 중간 하위 쿼리가 반환한 `supplierId` 중 하나와 일치하는 `Suppliers` 엔티티의 모든 필드를 반환하는 `suppliersTree`을(를) 만듭니다. 이것이 가장 바깥 쿼리입니다:

```ts
const suppliersTree = new FilteringExpressionsTree(0, undefined, 'Suppliers', ['*']);
suppliersTree.filteringOperands.push({
    fieldName: 'supplierId',
    conditionName: IgxStringFilteringOperand.instance().condition('inQuery').name,
    searchTree: productsTree
});
```

이제 SQL 쿼리가 완성되었습니다:

```
SELECT * FROM Suppliers WHERE supplierId IN (
  SELECT supplierId FROM Products WHERE categoryId IN (
      SELECT categoryId FROM Categories WHERE name = 'Beverages'
    )
)
```

이제 `IgxQueryBuilderComponent`의 `expressionsTree` 속성을 `suppliersTree`(으)로 설정할 수 있습니다. 또한 쿼리가 바뀔 때마다 엔드포인트에 새 요청이 전송되고 그리드에 표시되는 결과 데이터가 새로 고쳐집니다.
