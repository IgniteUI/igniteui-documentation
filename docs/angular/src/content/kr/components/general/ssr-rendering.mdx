# Angular SSR을 사용한 서버 측 렌더링

이 항목은 서버 측 렌더링이 무엇인지 설명하고, Ignite UI for Angular 애플리케이션에서 이를 구성하는 방법을 다룹니다.

## Angular 서버 측 렌더링

모든 Angular 애플리케이션은 클라이언트의 브라우저에서 실행되며, 이로 인해 종종 [LCP(Largest Contentful Paint)](https://web.dev/articles/lcp), 즉 브라우저가 페이지에서 가장 큰 콘텐츠를 처음 렌더링하는 시점에 부정적인 성능 저하가 발생할 수 있습니다. 이때 [Angular SSR](https://angular.dev/guide/ssr)이 유용하며, 서버에서 페이지의 전체 HTML을 생성할 수 있습니다. 클라이언트 측 페이지를 서버에서 HTML로 렌더링하고, 이후 클라이언트에서 부트스트랩합니다. 그렇다면 어떻게 동작할까요?

> [LCP](https://web.dev/articles/lcp)는 페이지의 가장 큰 콘텐츠가 사용자에게 보이는 시점을 측정합니다. [FCP](https://web.dev/first-contentful-paint) 지표는 사용자가 페이지로 이동한 후 브라우저가 첫 번째 DOM 콘텐츠를 렌더링하는 데 걸리는 시간을 측정합니다. 자세한 내용은 [Lighthouse 성능 점수](https://web.dev/performance-scoring)를 참조하십시오.


## 어떻게 동작합니까?

Angular SSR을 사용하면 앱의 랜딩 페이지를 정적 버전으로 제공하는 동시에 전체 Angular 애플리케이션이 백그라운드에서 로드됩니다. 랜딩 페이지는 순수 HTML이므로 JavaScript가 비활성화되어 있어도 표시됩니다. 서버 렌더링에 대한 자세한 내용은 [웹에서의 렌더링 가이드](https://developers.google.com/web/updates/2019/02/rendering-on-the-web)에서 확인할 수 있습니다.

## 사용법

서버 측 렌더링은 다음을 수행할 수 있는, [웹 렌더링](https://developers.google.com/web/updates/2019/02/rendering-on-the-web) 지침에 포함된 여러 기법 중 하나입니다:

- 웹 크롤러가 웹사이트를 인덱싱하기 쉽게 하여 검색 결과에서 순위를 높입니다. 검색 엔진 최적화(SEO)를 개선합니다.
- 첫 페이지를 빠르게 표시합니다. 초기 페이지 로드가 느리면(3초 이상 걸리면) 사용자가 이탈하게 됩니다.
- 앱 성능을 개선합니다. [First Contentful Paint](https://web.dev/first-contentful-paint)와 [Largest Contentful Paint](https://web.dev/articles/lcp) 모두에 긍정적인 영향을 줍니다.

> SEO와 소셜 미디어 미리 보기를 완전히 제어할 수 있으며, 사용자가 초기 렌더링된 화면을 먼저 볼 수 있게 하여 애플리케이션의 전반적인 체감 성능을 개선합니다.

## 기존 Ignite UI 애플리케이션에 SSR 추가하기

### 1단계 - @angular/ssr 추가하기

Angular CLI 스키매틱을 사용하면 다음 명령을 실행할 수 있습니다:

```
ng add @angular/ssr
```

이 스키매틱은 앱의 클라이언트 및 서버 구성에 여러 변경을 수행하고, 프로젝트 구조에 추가 파일도 넣습니다.

### 2단계 - Angular SSR 앱 시작하기

다음 명령을 실행하십시오:

```
ng serve
```

## 처음부터 새 애플리케이션 만들기

1. `ng new` 또는 [Ignite UI CLI](/general/cli/getting-started-with-cli) `ig new` 명령을 사용하십시오. 또는 3단계를 건너뛰고 `ng new --ssr`를 사용하여 새 Angular SSR 프로젝트를 직접 만들 수도 있습니다.
2. `ng add igniteui-angular`을(를) 실행하면 라이브러리의 npm 패키지가 작업 공간에 설치되고, 현재 작업 디렉터리의 프로젝트가 해당 라이브러리를 사용하도록 구성됩니다.
3. `ng add @angular/ssr`로 Angular SSR을 추가하십시오.
4. Ignite UI for Angular 컴포넌트를 추가하십시오. 예: Grid, Calendar

## 기타 고려 사항

- 앱이 브라우저 전용 객체를 사용하고 있다면, 해당 사용을 조건문으로 감싸서 Angular가 브라우저에서만 사용하도록 하십시오. 이를 위해 `@angular/common`에서 `isPlatformBrowser`와 `isPlatformServer` 함수를 import하고, 컴포넌트에 `PLATFORM_ID` 토큰을 주입한 다음, import한 함수를 실행하여 서버에 있는지 브라우저에 있는지 확인할 수 있습니다.
- HTML 요소를 처리하기 위해 ElementRef를 사용한다면, nativeElement로 요소의 속성을 조작하지 마십시오. 대신 [Renderer2 메서드](https://alligator.io/angular/using-renderer2)를 주입하여 사용하십시오.
- 서버 요청의 모든 URL은 절대 경로여야 합니다. 서버에서 실행할 때 상대 URL로의 데이터 요청은 실패한다는 점을 기억하십시오.
- 브라우저 이벤트를 처리하기 위해 Angular 팀은 [withEventReplay()](https://angular.dev/guide/hydration#capturing-and-replaying-events) 함수를 제공합니다. 이 기능은 하이드레이션 전에 발생한 모든 이벤트를 캡처하고, 하이드레이션이 완료되면 해당 이벤트를 재생합니다.
- IgxIconService로 아이콘을 등록하는 경우, 공급자에 [provideHttpClient()](https://angular.dev/api/common/http/provideHttpClient)를 구성했는지 확인하십시오.
- Angular SSR을 사용하면 서버가 사용자에게 보일 페이지를 미리 렌더링하지만, 상호 작용은 제한됩니다. 클라이언트 측 앱이 백그라운드에서 로드되면, 서버에서 렌더링된 페이지에서 클라이언트 측 앱으로 자연스럽게 전환됩니다.
