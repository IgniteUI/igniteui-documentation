# 라이선스 FAQ 및 설치

Ignite UI for Angular는 이중 라이선스 모델로 제공되며, 사용하는 컴포넌트, 모듈, 디렉티브, 서비스에 따라 상업용 사용과 허용적인 오픈 소스 사용을 모두 허용합니다.

패키지의 어느 부분에 어떤 라이선스가 적용되는지 이해하는 것이 중요합니다. [오픈 소스 vs 프리미엄](/general/open-source-vs-premium) 항목에는 각 컴포넌트에 어떤 유형의 라이선스가 적용되는지에 대한 세부 정보가 있으므로, 프로젝트에서 사용하는 컴포넌트에 따라 상업용 라이선스를 구매해야 하는지 판단할 수 있습니다.

## 라이선스 계약

상업용 라이선스에 해당하는 컴포넌트의 경우, 구매와 사용에 적용되는 모든 [법적 약관](https://www.infragistics.com/legal/license/igultimate-la)을 아는 것이 중요합니다.

<DocsAside type="info">
2025년 4분기에 라이선스 약관과 구독 모델을 업데이트했습니다.
</DocsAside>

평가판이 종료되었거나 구독이 [만료된](http://www.infragistics.com/renewal) 경우, Ignite UI의 상용 라이선스에 따라 컴포넌트를 사용하는 팀의 각 개발자는 구독을 [구매](https://www.infragistics.com/how-to-buy/product-pricing)해야 합니다. 구독을 구매하면 개발용으로 [https://packages.infragistics.com/npm/js-licensed/](https://packages.infragistics.com/npm/js-licensed/) 주소에서 호스팅되는 비공개 npm 피드를 사용할 수 있습니다. 여기에서 Ignite UI for Angular 패키지의 최신 버전을 찾을 수 있습니다. 현재 구독 중이라면 이 비공개 피드를 사용할 수 있으며 Ignite UI for Angular의 정식 버전에 액세스할 수 있습니다.


Infragistics는 다음 대상에게 무료 비상업용, 재판매 불가(NFR) 라이선스를 제공합니다:

- Microsoft MVP, Microsoft Regional Director, Google Developer Expert 등 개발자 프로그램에 속해 있는 경우.  
- 초·중·고등학생, 대학생, 교육 기관 또는 교수인 경우.  

무료 비상업용 NFR 라이선스 자격이 있거나 라이선스에 관한 질문이 있다면 [문의하십시오](https://www.infragistics.com/about-us/contact-us).

## Ignite UI for Angular npm 패키지 - 비공개 npm 피드 사용하기

npm은 가장 널리 쓰이는 패키지 관리자이며 Node.js 런타임 환경의 기본 패키지 관리자이기도 합니다. 많은 사람이 사용하며, 프로젝트가 의존하는 패키지를 관리하는 가장 빠르고 쉬운 방법 중 하나입니다. npm의 동작 방식에 대한 자세한 내용은 공식 [npm 문서](https://docs.npmjs.com/)를 읽어 보십시오.

Infragistics Ignite UI for Angular는 npm 패키지로 제공되며, [`few easy steps using the Ignite UI CLI`](/general/cli/step-by-step-guide-using-cli)을 사용하거나 [Ignite UI for Angular Schematics를 사용하여](/general/cli/step-by-step-guide-using-angular-schematics) 프로젝트에 종속성으로 추가할 수 있습니다. 이 방식을 선택하면 npm을 구성할 필요가 없습니다. MIT 라이선스 컴포넌트만 사용할 계획이라면 그 밖에 아무것도 할 필요가 없습니다. 하지만 상업용 라이선스 컴포넌트를 사용하는 경우, npm에서 패키지를 내려받으면 제품의 [체험판 기간](https://www.infragistics.com/products/ignite-ui-angular)이 시작됩니다.

<DocsAside type="info">
체험판 버전을 사용하기 시작한다는 것은 웹 뷰의 일부에 **워터마크**가 표시되는 제품 버전을 사용한다는 뜻입니다. 특정 기간(예: 한 달) 동안 라이선스 패키지를 사용한 뒤 만료된다는 의미는 아닙니다.
</DocsAside>

Infragistics Ignite UI Dock Manager Web Component는 별도의 npm 패키지로 제공되며, 이를 설치하면 제품의 [Ignite UI Dock Manager Web Component 체험판 버전](https://www.infragistics.com/products/ignite-ui-angular)을 사용하기 시작하게 됩니다.

> Ignite UI for Angular npm 패키지 사용을 시작하는 방법에 대한 자세한 정보는 [이 항목](/general/getting-started#ignite-ui-for-angular-설치하기)에서 찾을 수 있습니다. Ignite UI Dock Manager Web Component에 대한 추가 정보는 [Dock Manager 문서](/dock-manager)에서 찾을 수 있습니다.

### Angular Schematics 또는 Ignite UI CLI로 패키지 업그레이드하기

Ignite UI for Angular가 [`ng add`](/general/getting-started)을 사용하여 프로젝트에 추가되었거나, 프로젝트가 [schematics 컬렉션](/general/cli/getting-started-with-angular-schematics) 또는 [Ignite UI CLI](/general/cli/getting-started-with-cli)로 만들어졌다면, `upgrade-packages`를 사용하여 앱을 라이선스 패키지를 사용하도록 자동으로 업그레이드할 수 있습니다. 프로젝트의 패키지 종속성에는 `@igniteui/angular-schematics` 또는 `igniteui-cli`이 포함되며, 두 가지 모두 업그레이드 명령을 지원합니다.

<DocsAside type="info">
이 과정은 패키지를 변경하므로, 전환하기 전에 먼저 프로젝트를 업데이트하는 것을 권장합니다. 그렇게 하면 Ignite UI Angular의 더 높은 버전을 잘못 가져와 잠재적인 업데이트 마이그레이션을 놓치는 일을 피할 수 있습니다. [업데이트 가이드](/general/update-guide)를 따르십시오.
</DocsAside>

프로젝트 설정에 따라 프로젝트에서 다음 스키매틱을 실행하십시오:

```bash
ng g @igniteui/angular-schematics:upgrade-packages
```

또는 `igniteui-cli`을 사용하십시오:

```bash
ig upgrade-packages
```

스키매틱 또는 명령이 프로젝트의 패키지 종속성을 전환하고 소스 참조를 업데이트합니다.
아직 설정하지 않았다면 npm 레지스트리에 로그인하라는 메시지가 표시됩니다.

<DocsAside type="info">
프로젝트가 [`yarn`](https://yarnpkg.com/)을 사용 중이라면 `--skip-install` 플래그와 함께 `upgrade-packages`를 실행하십시오. 그다음 업그레이드 명령이 현재 설치에 `npm`를 사용하므로, `yarn.lock`를 올바르게 업데이트하려면 이후 `yarn install`를 실행하십시오.
</DocsAside>

### 비공개 npm 피드를 사용하도록 환경을 설정하는 방법(단계별 가이드)

#### 먼저 비공개 레지스트리를 설정하고, 이 레지스트리를 Infragistics 범위와 연결해야 합니다

이렇게 하면 공개 npm 레지스트리와 Infragistics 비공개 레지스트리의 패키지를 자연스럽게 혼합하여 사용할 수 있습니다.

<DocsAside type="info">
계정이 라이선스가 없는 상태(여전히 체험판 계정 사용 중)라면 비공개 패키지 피드에 접근할 수 없습니다. 예를 들어 404 또는 403 오류 메시지가 반환됩니다. **라이선스가 있는 계정만 packages.infragistics 비공개 피드에 접근할 수 있습니다.**
</DocsAside>

### 이제 npm을 사용하여 비공개 피드에 로그인하십시오

#### npm 9 이상

비공개 피드는 현재 npm v9의 `login/adduser` 명령을 지원하지 않으므로, 대신 구성에 필요한 인증 필드를 추가하기 위해 다음 단계를 권장합니다:

```cmd
npm config set @infragistics:registry https://packages.infragistics.com/npm/js-licensed/
npm config set //packages.infragistics.com/npm/js-licensed/:username=YOUR_USERNAME
npm config set //packages.infragistics.com/npm/js-licensed/:email=YOUR_IG_EMAIL
npm config set //packages.infragistics.com/npm/js-licensed/:_auth=YOUR_IG_AUTH_TOKEN
```

Infragistics 프로필을 통해 [액세스 토큰](#액세스-토큰-사용)을 생성할 수 있습니다.

이 방식은 `npm`의 모든 이전 버전에 적용됩니다.

#### npm v8 이하 버전

`adduser` 명령을 실행하고 사용자 계정과 비밀번호를 지정하십시오:

```cmd
npm adduser --registry=https://packages.infragistics.com/npm/js-licensed/ --scope=@infragistics
```

Infragistics 계정에 로그인할 때 사용하는 사용자 이름과 비밀번호를 입력하라는 메시지가 표시됩니다. Infragistics 프로필에 등록된 이메일도 제공해야 합니다.

<DocsAside type="info">
`npm`은(는) 사용자 이름에 `"@"` 기호를 사용하는 것을 "인터넷에 안전하지 않은" 것으로 간주하여 허용하지 않습니다. 사용자 이름은 실제로 Infragistics 계정에 사용하는 이메일이므로 항상 `"@"` 기호를 포함합니다. 그래서 `"@"` 기호를 `"!!"`(느낌표 두 개)로 바꾸어 이 제한을 우회해야 합니다. 예를 들어 사용자 이름이 `"username@example.com"`인 경우, 사용자 이름을 묻을 때 다음과 같이 입력해야 합니다: `"username!!example.com"`.
</DocsAside>

<DocsAside type="info">
**macOS 셸 동작**: macOS를 사용하고 `npm config set`를 통해 `:_auth` 토큰을 수동으로 설정하는 경우, 다음과 같이 토큰을 **큰따옴표로 감싸십시오**:

```bash
npm config set //packages.infragistics.com/npm/js-licensed/:_auth="YOUR_IG_AUTH_TOKEN"
```

이는 macOS의 셸 구문 분석 차이 때문에 필요하며, 토큰의 특수 문자가 올바르게 인용되지 않으면 인증 문제가 생길 수 있습니다. 이 문제는 일반적으로 Windows에서는 발생하지 않습니다.
</DocsAside>

#### 이 과정이 끝나면 로그인되어 프로젝트에 최신 버전의 Ignite UI 패키지를 설치할 수 있습니다

```cmd
npm uninstall igniteui-angular
npm install @infragistics/igniteui-angular

npm uninstall igniteui-dockmanager
npm install @infragistics/igniteui-dockmanager
```

Ignite UI for Angular 패키지는 범위(scoped)로 설정되어 있으므로, 비공개 피드와 npmjs.org의 패키지를 동시에 설치하려고 해도 레지스트리 변경이 필요하지 않다는 점을 기억하십시오.

#### 프로젝트 소스에서 추가 변경이 필요할 수 있습니다

체험판에서 라이선스 패키지로 업그레이드하면서 자동 CLI 마이그레이션을 사용하지 않는 경우:

- 프로젝트의 **tsconfig.json**에 **paths** 매핑을 추가하십시오.

```json
{
  /* ... */
  "compilerOptions": {
    "baseUrl": "./",
    "outDir": "./dist/out-tsc",
    /* ... */
    "paths": {
      "igniteui-dockmanager": ["./node_modules/@infragistics/igniteui-dockmanager"],
      "igniteui-dockmanager/*": ["./node_modules/@infragistics/igniteui-dockmanager/*"],
    }
  }
}
```

- 프로젝트의 `angular.json`에 `stylePreprocessorOptions` 매핑을 추가하십시오

```json
{
  "projects": {
    ..
    "prefix": "app",
      "architect": {
        "build": {
          "builder": "@angular-devkit/build-angular:browser",
          "options": {
            ...
            "aot": true,
            "stylePreprocessorOptions": {
                "includePaths": [
                    "node_modules/@infragistics"
                ]
            }
            ...
},
```

- `igniteui-angular/lib` 소스의 Sass import에서 `~` 기호를 제거하십시오:

```scss
@use "~igniteui-angular/lib/core/styles/themes/index" as *;

// Should be changed to
@use "igniteui-angular/lib/core/styles/themes/index" as *;
```

이미 npm을 도입했고 Ignite UI for Angular 라이선스가 있다면, Ignite UI for Angular의 전체 잠재력을 활용하고 생산성을 높이기 위해 Infragistics 비공개 피드를 설정하십시오.

### Travis CI 구성

여기서도 비슷한 방식을 따르십시오. 유일한 차이점은 구성이 `before_install` 단계에서 설정된다는 것입니다:

```cmd
before_install:
- echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- echo "//packages.infragistics.com/npm/js-licensed/:_auth=$TOKEN" >> ~/.npmrc
```

환경 변수를 정의하는 가장 좋은 방법은 그 안에 담길 정보의 유형에 따라 달라집니다. 따라서 [두 가지 옵션이 있습니다](https://docs.travis-ci.com/user/environment-variables/):

- 암호화하여 [.travis.yml에](https://docs.travis-ci.com/user/environment-variables/#defining-encrypted-variables-in-travisyml) 추가하기
- [저장소 설정](https://docs.travis-ci.com/user/environment-variables/#defining-variables-in-repository-settings)에 추가하기

### GitHub Actions 구성

[CI 워크플로 구성](https://help.github.com/en/actions/language-and-framework-guides/using-nodejs-with-github-actions)에서 `npm install`(또는 `npm ci`) 단계 앞에 다음 스크립트를 추가하십시오:

```cmd
- run: echo "@infragistics:registry=https://packages.infragistics.com/npm/js-licensed/" >> ~/.npmrc
- run: echo "//packages.infragistics.com/npm/js-licensed/:_auth=${{ secrets.NPM_TOKEN }}" >> ~/.npmrc
```

[_secrets_(암호화된 환경 변수)](https://help.github.com/en/actions/configuring-and-managing-workflows/creating-and-storing-encrypted-secrets)를 정의하고, 액세스 토큰과 같은 민감한 정보에는 GitHub Actions 워크플로에서 이를 사용하십시오.
