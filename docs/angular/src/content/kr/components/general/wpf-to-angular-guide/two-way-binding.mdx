# Angular의 양방향 데이터 바인딩이란 무엇입니까

Angular의 양방향 데이터 바인딩은 데이터가 컴포넌트에서 뷰로, 그리고 그 반대로 흐르게 합니다. 이는 최종 사용자에게 정보를 표시하고, UI를 사용하여 기반 데이터를 변경할 수 있게 하는 데 사용됩니다. 이것은 뷰(템플릿)와 이미 언급한 컴포넌트 클래스 사이에 양방향 연결을 만듭니다. 이 과정은 WPF의 양방향 바인딩과 비슷합니다.

## Angular에서 데이터 바인딩은 어떻게 동작합니까?

Angular 데이터 바인딩은 [Angular 컴포넌트](https://www.infragistics.com/products/ignite-ui-angular)의 데이터를 UI와 동기화하는 방식으로 동작합니다. 이렇게 하면 항상 데이터의 현재 값을 보여 줄 수 있습니다. 양방향 바인딩에서는 모델과 뷰 사이에 자동 데이터 동기화가 일어나 두 쪽이 항상 동기화된 상태를 유지합니다. 그 결과 모델에서 이루어진 변경은 즉시 뷰에도 반영됩니다. 그 반대도 마찬가지입니다. 뷰에서 이루어진 변경은 모델에도 업데이트됩니다.
Angular의 양방향 데이터 바인딩은 최종 사용자에게 정보를 표시하고, 최종 사용자가 UI를 사용하여 기반 데이터를 변경할 수 있게 하는 데 사용됩니다. 이것은 뷰(템플릿)와 컴포넌트 클래스 사이에 양방향 연결을 만듭니다. 이는 WPF의 양방향 바인딩과 비슷합니다.

단방향 바인딩은 컴포넌트 클래스의 상태를 가져와 뷰에 표시하는 것입니다. 이 코드를 살펴보겠습니다:

```html
<input #myTitle (keyup)="keyup(myTitle.value)"/>
<h2>{{ text }}</h2>
```

```typescript
export class SampleComponent implements OnInit {

text = 'default value';

keyup(value) {
  this.text = value;
}
...
```

여기서는 `interpolation`을(를) 사용하여 text 속성을 HTML에 바인딩하기만 합니다. 이렇게 하면 UI에 text 속성의 값이 표시됩니다. `input` 요소는 사용자 상호 작용을 처리하고, [이벤트 바인딩](/general/wpf-to-angular-guide/angular-events)을 통해 UI를 사용하여 기반 `text` 속성을 업데이트합니다. 본질적으로 입력은 단방향 바인딩과 반대로 동작합니다. UI에서 정보를 받아 컴포넌트 클래스의 속성을 업데이트합니다. 입력의 keyup 이벤트에 연결된 메서드는 이벤트가 발생할 때마다 text 속성을 업데이트합니다. 이벤트 메서드에 의해 text 속성 값이 바뀌면, 그 변경은 h2 요소의 `interpolation`를 사용한 단방향 바인딩을 통해 UI에 반영됩니다. 따라서 사용자가 입력 요소에 무언가를 입력하면 h2 텍스트가 즉시 업데이트되며, 이 동작은 기본적으로 양방향 바인딩을 흉내 낸 것입니다. WPF에서도 단방향 바인딩과 keyup 이벤트 핸들러를 사용하면 같은 것을 구현할 수 있지만, 양방향 바인딩이 사용하기 훨씬 편리합니다.

## Angular에서 양방향 데이터 바인딩을 구현하는 방법

다행히 위 샘플의 로직을 훨씬 쉬운 방법으로 구현할 수 있으며, 이때 양방향 바인딩이 등장합니다!

양방향 바인딩의 방향은 **컴포넌트 클래스에서 UI**로만 가는 것이 아니라 **UI에서 컴포넌트 클래스**로도 갑니다. 이를 위해 [`ngModel`](https://angular.io/api/forms/NgModel)라는 [디렉티브](https://angular.io/api/core/Directive)를 사용하겠습니다. 위 샘플을 `ngModel` 디렉티브로 업데이트해 보겠습니다. 구문은 여는 대괄호 다음에 여는 괄호, 그리고 당연히 닫는 괄호와 대괄호입니다. 이를 **상자 속의 바나나**라고 부르므로, 실제로 실행되는 것을 봅시다!

```html
<input [(ngModel)]="text"/>
<h2>{{ text }}</h2>
```

WPF에서 이에 해당하는 바인딩은 다음과 같습니다:

```xml
<TextBox Text="{Binding Path=Text, Mode=TwoWay}"></TextBox>
<TextBlock Text="{Binding Path=Text, Mode=OneWay}"></TextBlock>
```

Angular의 바인딩은 구문의 문제인 반면, WPF에서는 설정에 더 가깝습니다. 특히 `Binding.Mode`의 값이 그렇습니다.

이 코드를 실행하면 콘솔에 오류가 발생하며, `ngModel`이(가) input 요소의 알 수 없는 속성이라는 내용이 나옵니다. 이는 `ngModel` 디렉티브를 사용하려면 [`FormsModule`](https://angular.io/api/forms/FormsModule)을(를) import해야 하기 때문입니다. 이것은 `app.module.ts` 파일에 import해야 합니다:

```typescript
import { FormsModule } from '@angular/forms';
...
@NgModule({
  imports: [
    BrowserModule,
    FormsModule
  ]
...
```

샘플을 실행하면 입력의 초기 값은 **기본값**과 같으며, 이는 `text` 속성의 값입니다. 입력은 편집 가능하므로 값을 바꾸면 h2 요소에 즉시 반영됩니다. 따라서 입력에 입력하면 `text` 속성이 업데이트되고, h2 요소는 `interpolation`를 통해 그 값을 표시합니다.

이를 달성하는 또 다른 동등한 방법은 다음과 같습니다:

```html
<input [ngModel]="text" (ngModelChange)="text = $event"/>
```

이것은 속성 바인딩과 이벤트 바인딩을 사용한 첫 번째 샘플과 실제로 비슷합니다.
