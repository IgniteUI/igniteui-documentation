# Angular 애플리케이션 만들기

<iframe width="100%" height="600" src="https://www.youtube.com/embed/dhjrAPPad54">
</iframe>

WPF에서 Angular로 마이그레이션할 때 Angular 애플리케이션을 만들기 시작하는 방법을 알아보십시오.

## 사전 요구 사항

Angular 애플리케이션 작성을 시작하려면 Node.js와 npm 패키지 관리자를 설치해야 합니다. Node.js는 브라우저 밖에서 JavaScript 코드를 실행하는 JavaScript 런타임 환경입니다. Node.js는 [nodejs.org](https://nodejs.org)에서 받을 수 있습니다. NPM은 .NET의 NuGet 패키지 관리자와 비슷한 패키지 관리자입니다. 기본적으로 Node.js와 함께 설치됩니다. 또한 IDE도 필요합니다. Angular 애플리케이션 개발에 가장 좋은 환경 중 하나는 Visual Studio Code입니다. 무료이고 오픈 소스이며 모든 플랫폼에서 실행됩니다. [code.visualstudio.com](https://code.visualstudio.com/)에서 받을 수 있습니다.

## 새 프로젝트 만들기

WPF 개발자라면 Visual Studio 안에서 새 프로젝트를 만드는 것이 매우 간단합니다. File -> New Project를 클릭하고, 프로젝트 유형을 선택하고, 이름을 입력한 다음 OK를 누르면 됩니다. Angular 세계로 들어가는 만큼, Visual Studio Code 안에 새 프로젝트를 만들고 싶을 것입니다. 하지만 여기에는 새 프로젝트 옵션이 없습니다. Visual Studio Code는 프로젝트 기반이 아니라 파일 기반이기 때문입니다. 새 Angular 애플리케이션을 만들기 위해서는 명령 프롬프트를 사용합니다.

먼저 [Angular CLI](https://cli.angular.io/)를 설치해야 합니다.

```cmd
npm install -g @angular/cli
```

그다음 명령 프롬프트에서 애플리케이션을 만들 폴더로 이동하고 다음 명령을 실행하십시오:

```cmd
ng new demo-app
```

"Would we like to add Angular routing?"라는 질문이 표시됩니다. 이 데모에서는 NO를 선택합니다. 다음으로 어떤 스타일시트 형식을 사용할지 묻습니다. 지금은 기본 CSS를 그대로 사용합니다. 몇 분이 걸리지만 결국 과정이 완료되고 새 애플리케이션이 디스크에 생성됩니다.

이제 방금 만들어진 demo-app 폴더로 이동하여 Visual Studio Code를 여는 명령을 실행해야 합니다.

```cmd
cd demo-app
code .
```

그러면 Angular 애플리케이션을 담은 Visual Studio Code의 새 인스턴스가 실행됩니다. 이제 Angular를 배우려는 데스크톱 개발자에게 아마 가장 부담스럽게 느껴질 부분인 폴더 구조가 나옵니다.

## 프로젝트 구조

이 파일들을 하나씩 살펴보고 WPF 애플리케이션과 어떻게 관련되는지 알아보겠습니다. 가장 좋은 방법은 각 프로젝트를 나란히 비교하는 것입니다. 왼쪽에는 WPF 앱이, 오른쪽에는 Angular 앱이 있습니다.

<Image src={wpfProjectStructure} alt="WPF 프로젝트 구조" class="responsive-img" />
<Image src={angularProjectStructure} alt="Angular 프로젝트 구조" class="responsive-img" />

Angular 애플리케이션은 단일 페이지 애플리케이션(SPA)이라는 점을 기억하는 것이 중요합니다. 즉 앱 전체에 페이지가 하나만 있으며, 그것이 바로 `index.html`입니다. `index.html` 파일은 WPF 애플리케이션의 `App.xaml`에 비유할 수 있습니다. 둘 다 전역이며, 그 안에 넣는 모든 것은 애플리케이션의 모든 페이지에 표시됩니다. `index.html` 파일에는 `StartupUri`(`App.xaml` 파일의)와 비슷하며 앱이 시작될 때 보여 줄 첫 페이지를 지정하는 `<app-root></app-root>` 섹션이 있습니다.

기술적으로 무슨 일이 일어나는지 설명하면, `index.html`로 이동하면 `main.ts` JavaScript 파일이 호출되어 `AppModule`을(를) 로드합니다. Angular 애플리케이션은 모듈과 컴포넌트로 구성됩니다. 기본적으로 루트 모듈과 루트 컴포넌트가 생성되며, 이들은 `app` 폴더에 위치합니다. `main.ts` 파일이 호출되면 `app` 폴더의 `app.module.ts` 파일에 있는 `AppModule`을(를) 부트스트랩합니다.

앱 모듈은 이어서 자체 `AppComponent`을(를) 부트스트랩합니다. `AppComponent`는 `app.component.ts` 파일에 정의되어 있으며 셀렉터는 `app-root`(으)로 설정됩니다. `AppComponent`의 HTML 템플릿은 `app.component.html` 파일에 정의되어 있습니다. 기본적으로 `index.html` 페이지의 `<app-root></app-root>` 섹션은 `app.component.html` 파일의 콘텐츠를 시각화합니다.

`main.ts` 파일은 `App.xaml.cs` 파일과 비슷합니다. 일종의 코드 비하인드이기 때문입니다. 애플리케이션이 실행될 때 기본으로 표시되는 컴포넌트인 `app.component.html`은 WPF의 `MainWindow.xaml`와 매우 비슷합니다.

WPF에는 NuGet 패키지에 대한 모든 종속성을 정의하는 `packages.config` 파일이 있는 반면, Angular에는 애플리케이션이 실행하는 데 필요한 종속성을 담은 `package.json` 파일이 있습니다. `package.json` 파일에는 또한 테스트, 시작 또는 빌드를 할 때 콘솔에서 실행할 수 있는 스크립트 섹션이 있습니다.

`References` 폴더를 살펴보겠습니다. WPF에는 솔루션에서 이 프로젝트에 추가된 모든 참조를 보여 주는 `References` 노드가 있습니다. Angular 애플리케이션에서는 실제로 `nodes_module` 폴더가 이 역할을 합니다. WPF에서 왔다면 Angular 프로젝트에 얼마나 많은 종속성이 있는지 놀랄 수 있습니다. 이들은 `npm`를 사용하여 채워집니다.

안타깝게도 여기서 유사점은 끝납니다. 생성된 다른 파일과 폴더도 살펴보겠습니다:

- `e2e` - end-to-end 테스트를 의미하며, 로그인 과정 같은 통합 테스트나 실제 시나리오의 테스트를 포함합니다.
- `src` - 애플리케이션 코드의 대부분이 여기에 있습니다.
- `assets` - 이미지나 기타 에셋을 포함합니다.
- `environment` - 빌드 환경에 대한 정보를 포함합니다.
- `favicon.ico` - 사이트에 접속했을 때 브라우저에 나타나는 아이콘입니다.
- `karma.conf.js` - 단위 테스트 구성을 포함합니다.
- `style.css` - 애플리케이션 전역 스타일을 담은 스타일시트로, WPF의 `App.xaml`에 정의된 리소스 딕셔너리와 비슷합니다.

## 애플리케이션 실행하기

이제 애플리케이션을 실행할 준비가 되었지만, Visual Studio Code에서는 F5를 누를 수 없습니다. 메뉴에서 Terminal -> New Terminal을 클릭하거나 <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>`</kbd>를 눌러 Visual Studio Code 터미널을 엽니다. 애플리케이션을 실행하려면 다음 명령을 실행해야 합니다:

```cmd
ng serve
```

애플리케이션이 시작된 후에는 http://localhost:4200/ 주소로 브라우저에서 열 수 있습니다. 앱이 브라우저에서 자동으로 열리도록 하려면 다음 명령을 사용하십시오:

```cmd
ng serve -o
```

이 경우 `-o`은(는) open을 의미합니다. 애플리케이션을 시작하는 또 다른 방법은 npm 명령을 사용하는 것입니다:

```cmd
npm start
```

이 스크립트는 `package.json` 파일에 정의되어 있으며, `-o` 옵션을 추가하여 `start` 명령을 수정할 수 있습니다:

```json
  "scripts": {
    "ng": "ng",
    "start": "ng serve -o",
```
