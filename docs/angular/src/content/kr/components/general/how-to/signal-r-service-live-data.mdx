# ASP.NET Core SignalR을 사용한 실시간 웹 앱

이 항목에서는 **ASP.NET Core SignalR**로 데이터를 *스트리밍*하고 *수신*하는 애플리케이션을 만드는 방법을 살펴봅니다.

필요한 것:

- ASP.NET Core와 Angular에 대한 기본 지식.
- .NET Core 3.1이 설치되어 있고 Visual Studio 같은 IDE가 있어야 합니다.

이 문서를 끝내면 알게 될 내용:

- SignalR을 추가하고 사용하는 방법.
- 클라이언트 연결을 열고 _메서드 호출_ 개념을 사용하여 클라이언트별로 데이터를 스트리밍하는 방법.
- Observable을 사용하여 Angular 애플리케이션에서 SignalR 서비스를 사용하는 방법.

SignalR은 여러 전송 방식을 활용하며, 클라이언트와 서버의 기능에 따라 사용 가능한 최선의 전송 방식을 자동으로 선택합니다 - [WebSockets, Server Send Events 또는 Long-polling](https://stackoverflow.com/a/12855533/2940502).

[WebSockets](https://docs.microsoft.com/en-us/aspnet/core/fundamentals/websockets?view=aspnetcore-5.0)을 기준으로 말하면(SSE와 Long-polling은 제외), 클라이언트가 서버와 실시간으로 연결되어 있으면 무언가 일어날 때마다 서버는 그 WebSocket을 통해 클라이언트에 메시지를 보낼 수 있습니다. 구형 클라이언트와 서버에서는 Long-polling 전송이 사용됩니다.

SignalR은 최신 클라이언트와 서버를 이렇게 처리합니다. 사용 가능하면 내부적으로 WebSockets를 사용하고, 사용할 수 없으면 다른 기술로 자연스럽게 대체합니다:

### SignalR 구성 설정

다음 코드를 [Startup.cs 파일](https://github.com/IgniteUI/finjs-web-api/blob/master/WebAPI/Startup.cs)에 추가하십시오:

- `Configure` 메서드의 엔드포인트 부분입니다.

```cs
app.UseEndpoints(endpoints =>
{
    endpoints.MapControllers();
    endpoints.MapHub<StreamHub>("/streamHub");
});
```

- `ConfigureServices` 메서드에 SignalR 사용을 추가하십시오.

```cs
services.AddSignalR(options =>
{
    options.EnableDetailedErrors = true;
});
```

위 변경 사항은 SignalR을 ASP.NET Core 의존성 주입 및 라우팅 시스템에 추가합니다.

이제 기본 구성을 더 설정하겠습니다. [properties/launchSettings.json](https://github.com/IgniteUI/finjs-web-api/blob/master/WebAPI/Properties/launchSettings.json#L11) 파일을 열고 그에 맞게 수정하십시오:

```json
"profiles": {
    "WebAPI": {
      "commandName": "Project",
      "launchBrowser": false,
      "applicationUrl": "https://localhost:5001;http://localhost:5000",
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      }
    }
  }
```

서버 측 프로젝트는 `localhost:5001`에서 실행되고 클라이언트 측은 `localhost:4200`에서 실행되므로, 둘 사이의 통신을 설정하려면 CORS를 활성화해야 합니다. [Startup.cs](https://github.com/IgniteUI/finjs-web-api/blob/master/WebAPI/Startup.cs#L31) 클래스를 열고 다음과 같이 수정하십시오:

```cs
public void ConfigureServices(IServiceCollection services)
{
    services.AddCors(options =>
    {
        options.AddPolicy("CorsPolicy", builder => builder
        .AllowAnyMethod()
        .AllowAnyHeader()
        .AllowCredentials()
        .WithOrigins("http://localhost:4200"));
    });
    ...

    public void Configure(IApplicationBuilder app, IWebHostEnvironment env)
    {
        ...
        app.UseCors("CorsPolicy");
        ...
```

교차 출처 리소스 공유(CORS)를 활성화하는 데 특정 문제가 있다면 [Microsoft 공식 항목](https://docs.microsoft.com/en-us/aspnet/core/signalr/security?view=aspnetcore-5.0#cross-origin-resource-sharing)을 확인하십시오.

### SignalR 허브 설정

먼저 [SignalR 허브란 무엇인지](https://docs.microsoft.com/en-us/aspnet/core/signalr/hubs?view=aspnetcore-5.0#what-is-a-signalr-hub) 설명하겠습니다.
SignalR Hub API를 사용하면 서버에서 연결된 클라이언트의 메서드를 호출할 수 있습니다. 서버 코드에서는 클라이언트가 호출하는 메서드를 정의합니다. SignalR에는 *Invocation*이라는 개념이 있는데, 클라이언트에서 특정 메서드로 허브를 실제로 호출할 수 있습니다. 클라이언트 코드에서는 서버에서 호출되는 메서드를 정의합니다.

실제 허브는 서버 측에 있습니다. *클라이언트*들이 있고 *허브*가 그들 모두 사이에 있다고 생각해 보십시오. 허브의 메서드를 호출하여 `Clients.All.doWork()`로 모든 클라이언트에게 메시지를 보낼 수 있습니다. 이는 연결된 모든 클라이언트에게 전달됩니다. 또한 해당 메서드를 호출한 쪽인 호출자(Caller) 한 클라이언트에게만 통신할 수도 있습니다.

<Image src={wsHubCallers} alt="호출자가 있는 SignalR 허브 설정" style="-webkit-box-shadow: 8px 9px 9px 5px #ccc; -moz-box-shadow: 8px 9px 9px 5px #ccc; box-shadow: 8px 9px 9px 5px #ccc; min-width: calc(100% - 650px); max-width: calc(100% - 400px);" />

기본 Hub 클래스를 상속하며 연결, 그룹, 메시징을 관리하는 [StreamHub 클래스](https://github.com/IgniteUI/finjs-web-api/blob/d493f159e0a6f14b5ffea3e893f543f057fdc92a/WebAPI/Models/StreamHub.cs#L9)를 만들었습니다. Hub 클래스는 상태를 가지지 않으며, 특정 메서드가 호출될 때마다 이 클래스의 새 인스턴스가 생성된다는 점을 기억하는 것이 좋습니다. 인스턴스 속성에 상태를 저장하는 것은 쓸모가 없으며, 대신 정적 속성을 사용하는 것을 권장합니다. 우리 예제에서는 연결된 각 클라이언트의 데이터를 저장하기 위해 정적 키-값 쌍 컬렉션을 사용합니다.

이 클래스의 다른 유용한 속성은 _Clients_, _Context_, *Groups*입니다. 이들은 고유한 *ConnectionID*를 기준으로 특정 동작을 관리하는 데 도움이 될 수 있습니다. 또한 이 클래스는 다음과 같은 유용한 메서드를 제공합니다:

- OnConnectedAsync() - 허브와 새 연결이 설정될 때 호출됩니다.
- OnDisconnectedAsync(Exception) - 허브와의 연결이 종료될 때 호출됩니다.

이 메서드들은 연결이 설정되거나 닫힐 때 추가 로직을 수행할 수 있게 해 줍니다. 우리 애플리케이션에서는 *Context 연결 ID*를 받아 일정한 간격으로 데이터를 되돌려 보내는 데 사용하는 _UpdateParameters_ 메서드도 추가했습니다. 보시다시피 우리는 고유한 *ConnectionID*를 통해 통신하므로 다른 클라이언트가 스트리밍에 간섭하지 못합니다.

```cs
public async void UpdateParameters(int interval, int volume, bool live = false, bool updateAll = true)
{
    ...
    var connection = Context.ConnectionId;
    var clients = Clients;
    ...
    if (!clientConnections.ContainsKey(connection))
    {
        clientConnections.Add(connection, new TimerManager(async() =>
        {
            ...
            await Send(newDataArray, client, connection);
        }, interval));
    } else
    {
        clientConnections[connection].Stop();
        clientConnections[connection] = new TimerManager(async () =>
        {
            var client = clients.Client(connection);
            ..
            await Send(newDataArray, client, connection);
        }, interval);
    }
    ...
}
```

데이터가 준비되면 `SendAsync` 메서드의 도움을 받아 `transferdata` 이벤트를 발생시켜 데이터를 전송합니다.

```cs
public async Task Send(FinancialData[] array, IClientProxy client, string connection)
{
    await client.SendAsync("transferdata", array);
}
...

// Called when a connection with the hub is terminated
public override Task OnDisconnectedAsync(Exception exception)
{
    StopTimer();
    clientConnections.Remove(Context.ConnectionId);
    return base.OnDisconnectedAsync(exception);
}
```

클라이언트 애플리케이션은 등록된 이벤트를 수신합니다:

```ts
private registerSignalEvents() {
    this.hubConnection.onclose(() => {
        this.hasRemoteConnection = false;
    });
    this.hubConnection.on('transferdata', (data) => {
        this.data.next(data);
    })
}
```

## SignalR 클라이언트 라이브러리 만들기

SignalR 서비스를 사용하기 위해 Angular 프로젝트를 만들겠습니다.
[실제 애플리케이션이 있는 GitHub 저장소](https://github.com/IgniteUI/igniteui-angular-samples/tree/master/projects/app-lob/src/app/grid-finjs-dock-manager)는 igniteui-angular-samples 저장소에서 찾을 수 있습니다.

먼저 SignalR을 설치하십시오:

```
npm install @microsoft/signalr
```

서버로 HTTP 요청을 보내야 하므로 HttpClientModule도 필요하다는 점을 기억하십시오.

아래는 허브 연결 빌더를 처리하는 [signal-r.service.ts](https://github.com/IgniteUI/igniteui-angular-samples/blob/master/projects/app-lob/src/app/services/signal-r.service.ts#L10) 파일입니다.

```ts
export class SignalRService implements OnDestroy {
    public data: BehaviorSubject<any[]>;
    public hasRemoteConnection: boolean;
    private hubConnection: signalR.HubConnection;
    ...

    constructor(private zone: NgZone, private http: HttpClient) {
        this.data = new BehaviorSubject([]);
    }
    ...

    // Start Hub Connection and Register events
    public startConnection = (interval = 500, volume = 1000, live = false,  updateAll = true) => {
        this.hubConnection = new signalR.HubConnectionBuilder()
            .configureLogging(signalR.LogLevel.Trace)
            .withUrl('https://www.infragistics.com/angular-apis/webapi/streamHub')
            .build();
        this.hubConnection
            .start()
            .then(() => {
                ...
                this.registerSignalEvents();
                this.broadcastParams(interval, volume, live, updateAll);
            })
            .catch(() => { ... });
    }

    // Change the broadcast parameters like frequency and data volume
    public broadcastParams = (frequency, volume, live, updateAll = true) => {
        this.hubConnection.invoke('updateparameters', frequency, volume, live, updateAll)
            .then(() => console.log('requestLiveData', volume))
            .catch(err => {
                console.error(err);
            });
    }

    // Register events
    private registerSignalEvents() {
        this.hubConnection.onclose(() => {
            this.hasRemoteConnection = false;
        });
        this.hubConnection.on('transferdata', (data) => {
            this.data.next(data);
        });
    }
    ...
```

app.component에서 새로 만든 `startConnection` 메서드를 사용하도록 추가하십시오

```ts
constructor(public dataService: SignalRService) {}
public ngOnInit() {
    this.dataService.startConnection(this.frequency, this.dataVolume, true, false);
}
...
```

### 그리드 데이터 바인딩

지금까지 클라이언트 코드에서 `transferdata` 이벤트에 대한 리스너를 설정했으며, 이 리스너는 업데이트된 데이터 배열을 인수로 받습니다. 새로 받은 데이터를 그리드에 전달하기 위해 Observable을 사용합니다. 이를 설정하려면 다음과 같이 그리드의 데이터 소스를 데이터 Observable에 바인딩해야 합니다:

```html
<igx-grid [data]='data | async'> ... </igx-grid>
```

서버에서 클라이언트로 새 데이터가 수신될 때마다 데이터 Observable의 `next()` 메서드를 호출합니다.

```ts
    this.hubConnection.on('transferdata', (data) => {
        this.data.next(data);
    })
```

## 주요 내용

애플리케이션을 새로 고치지 않고 데이터가 업데이트되는 것만 보고 싶다면 ASP.NET Core SignalR을 고려해 보십시오. 데이터가 크다고 생각되거나, 끝없는 스피너를 표시해 클라이언트를 막지 않고 매끄러운 사용자 경험을 원한다면 스트리밍 콘텐츠를 적극 권장합니다.

SignalR 허브 통신은 쉽고 직관적이며, Angular Observable의 도움을 받으면 WebSockets로 데이터를 스트리밍하는 강력한 애플리케이션을 만들 수 있습니다.
