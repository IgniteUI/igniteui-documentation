# 업데이트 가이드

Ignite UI for Angular의 [버전 체계](https://github.com/IgniteUI/igniteui-angular/wiki/Ignite-UI-for-Angular-versioning)에서 첫 번째 숫자는 항상 코드가 지원하는 Angular의 메이저 버전과 일치하며, 두 번째 숫자는 메이저 버전 릴리스 전용입니다. 메이저 릴리스 사이에는 호환성이 깨지는 변경이 도입될 수 있습니다.
**Ignite UI for Angular**의 각 릴리스에 대한 변경 사항의 전체 목록은 제품 [CHANGELOG](https://github.com/IgniteUI/igniteui-angular/blob/master/CHANGELOG.md)에서 확인할 수 있습니다

Ignite UI for Angular 패키지는 `ng update` 스키매틱을 통한 자동 버전 마이그레이션도 지원합니다. 이 스키매틱은 가능한 모든 호환성 깨짐 변경(이름이 바뀐 셀렉터, 클래스, @Input/Output 속성)을 마이그레이션하려고 시도합니다. 그러나 여전히 마이그레이션할 수 없는 변경이 있을 수 있습니다. 이는 보통 TypeScript 애플리케이션 로직과 관련되며, [아래에 추가로](#추가-수동-변경-사항) 설명합니다.

먼저 [**`ng update`**](https://angular.io/cli/update) 명령을 실행하십시오. 이 명령은 애플리케이션과 패키지의 사용 가능한 업데이트를 분석합니다.

```cmd
ng update
```

**Ignite UI for Angular** 라이선스 패키지를 업데이트하려면 다음 명령을 실행하십시오:

```cmd
ng update @infragistics/igniteui-angular
```

**Ignite UI for Angular** 무료 패키지를 업데이트하려면 다음 명령을 실행하십시오:

```cmd
ng update igniteui-angular
```

`@infragistics/igniteui-angular` 또는 `igniteui-angular`를 업데이트할 때는 `@angular/core`, `@angular/cli`, `igniteui-cli` 패키지도 일치하는 버전으로 업데이트하는 것을 권장합니다.
**Ignite UI CLI** 패키지를 업데이트하려면 다음 명령을 실행하십시오:

```cmd
ng update igniteui-cli
```

**Angular Core** 패키지를 업데이트하려면 다음 명령을 실행하십시오:

```cmd
ng update @angular/core
```

**Angular CLI** 패키지를 업데이트하려면 다음 명령을 사용하십시오:

```cmd
ng update @angular/cli
```

<DocsAside type="info">
패키지 종속성 불일치로 인해 `ng update` 명령이 실패하면, 업데이트를 되돌리고 `node_modules` 폴더를 삭제한 다음 `--force` 플래그와 함께 업데이트를 다시 실행하십시오.
</DocsAside>

## 추가 수동 변경 사항

안타깝게도 모든 변경 사항을 자동으로 업데이트할 수는 없습니다. 아래 변경 사항은 버전별로 나뉘어 있으므로, 업데이트가 필요하다면 현재 버전에서 시작하여 아래에서 위로 차례대로 업데이트를 적용하십시오.

예를 들어 버전 6.2.4에서 7.1.0으로 업데이트하는 경우, "From 6.x .." 섹션부터 시작해 해당 변경 사항을 적용한 다음 위로 올라가십시오:

## 22.2.x에서 22.3.x로

Ignite UI for Angular 22.3.0은 Ignite UI Theming 30(`igniteui-theming`)을 사용하며, 이 버전의 `palette()` 함수는 기본적으로 새로운 `fitted` 생성기로 팔레트를 만듭니다. `fitted` 생성기는 대비에 따라 모든 명도 단계를 배치하고 이를 고정된 색상으로 출력하므로, `palette()` 호출은 이전과 다른 색상으로 컴파일됩니다. `$light-material-palette`과 같은 사전 정의된 팔레트와 미리 빌드된 CSS 테마는 `legacy` 생성기를 유지하며 변경되지 않습니다. [팔레트 생성](../themes/palette-generation.mdx)에서 두 생성기를 모두 설명합니다.

`ng update` 마이그레이션은 `.scss`와 `.sass` 파일에서 생성기를 이미 선택하지 않은 모든 `palette()` 함수 호출에 `$generator: 'legacy'`를 추가하므로, 팔레트의 색상이 유지됩니다:

```scss
// Before
$my-palette: palette(
  $primary: #0099ff,
  $secondary: #df1b74,
  $surface: #ffffff
);

// After
$my-palette: palette(
  $primary: #0099ff,
  $secondary: #df1b74,
  $surface: #ffffff,
  $generator: 'legacy'
);
```

마이그레이션은 팔레트를 CSS 변수로 출력하는 믹스인인 `@include palette(...)`을(를) 변경하지 않습니다. 또한 `palette($args...)`처럼 인수를 펼쳐서 전달하는 호출에는 인수를 추가할 수 없습니다. 이러한 호출은 파일과 줄 번호와 함께 `ng update` 출력의 끝에 보고되므로, 펼쳐지는 맵에 `generator: 'legacy'`를 직접 추가하십시오.

팔레트를 `fitted` 생성기로 옮기려면 `$generator` 인수를 제거하십시오. 인수를 전달하지 않고도 모든 `palette()` 호출에서 `legacy` 생성기를 유지하려면, 다른 것을 로드하기 전에 테마 라이브러리를 구성하십시오:

```scss
@use "igniteui-theming" with ($shade-generator: 'legacy');
@use "igniteui-angular/theming" as *;
```

이제 컴포넌트 테마는 `--ig-surface-500` 대신 `base` 표면 역할인 `--ig-surface-base`에서 배경을 가져옵니다. 모든 팔레트는 표면 역할인 `base`, `sunken`, `raised`, `overlay`, `container`을 출력합니다. 번호가 붙은 표면 명도 단계는 사용 중단되었습니다. 팔레트는 두 생성기 모두에서 여전히 이를 출력하며, `fitted` 팔레트는 `--ig-surface-500`을(를) `--ig-surface-base`에 연결하지만, 향후 릴리스에서 제거될 예정입니다. 다음 항목을 수동으로 검토하십시오:

- 예를 들어 섹션을 어두운 표면으로 전환하기 위해 실행 중에 `--ig-surface-500`을(를) 재정의한다면, 대신 `--ig-surface-base`와 사용하는 곳의 `--ig-surface-raised`, `--ig-surface-overlay`, `--ig-surface-sunken`를 함께 재정의하십시오. [팔레트](../themes/palettes.mdx#dark-vs-light)를 참조하십시오.
- 자체 스타일이 `--ig-surface-500` 또는 `color($color: 'surface', $variant: 500)`를 읽는 경우, 지금은 계속 동작합니다. 번호가 붙은 명도 단계가 제거되기 전에 `color($color: 'surface')`와 같은 표면 역할로 옮기십시오. 이는 `base`를 반환합니다.
- 직접 작성한 팔레트 맵을 전달한다면, 그 `surface` 항목에 표면 역할을 추가하십시오. [사용자 지정 팔레트 맵](../themes/sass/palettes.mdx#사용자-지정-팔레트-맵)을 참조하십시오.

## 22.0.x에서 22.1.x로

Ignite UI for Angular 22.1.0은 `tokens()` 믹스인으로의 마이그레이션을 마치고 컴포넌트 구조 스타일을 각 컴포넌트의 번들로 옮깁니다. `ng update` 마이그레이션은 다음 구문 변경을 자동으로 수행합니다:

- 제거된 컴포넌트별 Sass 래퍼 믹스인(`avatar`, `badge`, `banner`, `card`, `dialog`, `tabs`, 그리드 및 피벗 믹스인, 그 밖에 이전에 사용 중단된 래퍼)을 `tokens()`로 바꿉니다.
- 삭제된 컴포넌트별 `-typography` 믹스인 호출(예: `badge-typography`, `dialog-typography`, `checkbox-typography`)을 제거합니다. 타이포그래피는 이제 컴포넌트 토큰을 통해 적용됩니다. 컴포넌트별 재정의는 [타이포그래피](/themes/sass/typography#컴포넌트-타이포그래피)를 참조하십시오.
- `igniteui-angular/lib/core/styles/components/avatar/avatar-component` 같은 구조 파셜의 깊은 Sass import와, 그에 대응하는 `component()` 호출을 제거합니다. 구조 스타일은 이제 컴포넌트 번들과 함께 자동으로 포함됩니다.
- `IgxDividerDirective`의 직접 import와 사용처를 `IgxDividerComponent`(으)로 이름을 바꿉니다. `IgxDividerModule`은(는) 영향을 받지 않습니다.

마이그레이션된 `tokens()` 호출은 수동으로 검토하십시오. 마이그레이션은 래퍼 믹스인이 일반 범용 토큰 재정의를 나타내는지, 아니면 컴포넌트 로컬 선언에 의존했는지 판단할 수 없습니다. 테스트나 테마 구조에서 로컬 선언이 필요하다는 것이 확인되지 않는 한, 생성된 기본 모드를 유지하십시오. 그러한 특수한 경우에는 `$mode: 'scoped'`를 추가하십시오:

```scss
// Before
.my-avatar {
  @include avatar(avatar-theme($background: red));
}

// After
.my-avatar {
  @include tokens(
    avatar-theme($background: red),
    $mode: 'scoped'
  );
}
```

대부분의 `css-vars()` 호출을 대체할 때도 기본 전역 모드로 시작하십시오. 컴포넌트가 전역 `theme()` 출력에 남아 있다면, 로컬 선언이 범용 토큰을 사용할 수 있으므로 보통 범위 모드는 필요하지 않습니다.

기본 출력이 사용자 지정에 필요한 컴포넌트 로컬 선언을 제공하지 않을 때만 범위 모드를 사용하십시오. 일반적인 경우는 다음과 같습니다:

- 제거된 래퍼는 범용 토큰 재정의만으로는 보존되지 않는 동작을 가진 완전한 로컬 테마를 설정했습니다.
- 컴포넌트가 전역 `theme()` 믹스인의 `$exclude` 목록에 있습니다. 이 경우 전역 테마는 컴포넌트의 구조 스타일시트가 사용하는 로컬 선언을 출력하지 않습니다.
- 테마가 컴포넌트 로컬 크기 식을 사용합니다. 전역 모드는 로컬 크기 변수에 의존하는 크기 값을 의도적으로 생략합니다.
- 테마 맵에 컴포넌트 호스트, 고스트 또는 오버레이 셀렉터처럼 여러 셀렉터가 있습니다. 분리된 오버레이는 보통 전역 스타일시트에서, 오버레이의 outlet과 일치할 수 있는 셀렉터를 통해 테마를 적용해야 합니다.
- 로컬 테마가 디자인 시스템이나 밝은/어두운 변형을 바꿉니다. 범위 모드가 올바른 테마 메타데이터를 출력하도록, 해당하는 `$schema`을(를) 컴포넌트 테마 함수에 전달하십시오.

범위 모드를 무분별하게 추가하지 마십시오. 애플리케이션 전체에 적용하거나 셀렉터로 제한하는 일반적인 `--ig-<component>-*` 재정의에는 기본 전역 모드를 유지하십시오. 컴포넌트는 로컬 선언이 그 범용 토큰을 사용할 수 있도록 전역 `theme()` 출력에 계속 포함되어 있어야 합니다:

```scss
@include tokens(
  avatar-theme(
    $schema: $dark-material-schema,
    $background: var(--ig-primary-500)
  )
);
```

범위 모드가 `::ng-deep`의 필요성을 보편적으로 없애 주지는 않습니다. Angular의 Emulated View Encapsulation 때문에 중첩되거나 내부 요소를 위해 생성된 셀렉터가 여전히 일치하지 않을 수 있습니다. 테스트에서 필요하다고 확인되면 `::ng-deep`를 유지하거나, 그 테마 include를 전역 스타일시트로 옮기십시오. 분리된 오버레이의 경우 `::ng-deep`만으로는 충분하지 않습니다. 테마가 오버레이의 outlet에서 일치하거나 상속되어야 합니다.

Ignite UI 스타일은 이제 `ig.reset` → `ig.base` → 활성 디자인 시스템 레이어(`ig.material`, `ig.bootstrap`, `ig.fluent`, `ig.indigo` 중 하나) → `ig.derived` 순서의 캐스케이드를 사용합니다. 애플리케이션이 reset 또는 normalize 스타일시트를 로드한다면, 컴포넌트 스타일을 재정의하지 못하도록 가장 낮은 우선순위의 reset 레이어에 두십시오:

```scss
@layer ig.reset {
  @import "minireset.css";
}
```

자세한 내용은 [컴포넌트 테마](/themes/sass/component-themes)와 [전역 테마](/themes/sass/global-themes#컴포넌트-제외하기)를 참조하십시오.

## 21.1.x에서 22.0.x로

Angular는 더 이상 터치 제스처용 `HammerModule`을(를) 제공하지 않습니다. Ignite UI for Angular 컴포넌트에서 터치 상호 작용(패닝, 스와이프, 탭)을 계속 동작하게 하려면, `angular.json`의 `scripts` 배열을 통해 HammerJS를 전역 스크립트로 로드하십시오:

```json
"architect": {
  "build": {
    "options": {
      "scripts": [
        "node_modules/hammerjs/hammer.min.js"
      ]
    }
  }
}
```

전역으로 로드되면 Ignite UI for Angular는 `window.Hammer`을(를) 자동으로 감지하고 이를 사용해 터치 제스처를 처리합니다. 추가 import나 모듈 등록은 필요하지 않습니다.

## 21.0.x에서 21.1.x로

버전 21.1.0에는 Sass 테마 프레임워크의 이제 사용 중단된 `css-vars` 믹스인을 대신할 수 있는 새로운 `tokens` 믹스인이 포함되어 있습니다. 겉으로는 외관상의 변경처럼 보이지만, 새 `tokens` 믹스인은 모든 Ignite UI 프레임워크에서 동작하는 범용 전역 컴포넌트 테마 토큰을 생성합니다. `css-vars` 믹스인은 이제 사용 중단되었으며 향후 버전에서 제거될 예정이므로, 가능한 한 빨리 새 `tokens` 믹스인으로 전환하는 것을 권장합니다.

`tokens` 믹스인은 `global` 또는 `scoped` 모드에서 컴포넌트의 CSS 변수 토큰을 생성하며, 범용 `--ig-*` 대체 체인과 로컬 토큰 참조의 올바른 재작성을 포함합니다.

**전역 모드**(기본값) — 범용 `--ig-{component}-{property}` 토큰을 출력합니다. 로컬 `var()` 참조는 전역 대응 항목으로 재작성되어, 파생 값(예: `adaptive-contrast`)이 모든 범위에서 올바르게 해석됩니다. 크기 식은 건너뛰며, 대신 구체적인 값을 전달하십시오.

```scss
// Input:
@include tokens(avatar-theme($background: red));

// Output:
:root {
  --ig-avatar-background: red;
  /* ... remaining avatar properties ... */
}
```

**범위 모드** — 대체 체인이 있는 컴포넌트 범위 변수(`--{property}`)를 출력합니다: 구성된 접두사(`--igx-*`) -> 범용(`--ig-*`) -> 스키마 기본값. 스타일시트 루트에서 호출되면 테마의 `selector`가 규칙을 만드는 데 사용됩니다. 셀렉터 안에서 호출되면 현재 셀렉터와 컴포넌트 셀렉터 모두 변수를 받습니다. 본질적으로 이는 이제 사용 중단된 `css-vars` 믹스인과 같은 결과를 냅니다.

```scss
// Input (from root):
@include tokens(avatar-theme($background: red), $mode: 'scoped');

// Output:
igx-avatar {
  --background: var(--igx-avatar-background, var(--ig-avatar-background, red));
  /* ... remaining avatar properties ... */
}
```

```scss
// Input (from within a selector):
.my-theme {
  @include tokens(avatar-theme($background: red), $mode: 'scoped');
}

// Output:
.my-theme,
.my-theme igx-avatar {
  --background: var(--igx-avatar-background, var(--ig-avatar-background, red));
  /* ... */
}
```

<DocsAside type="info">
범위 모드에서는 변수 범위를 올바르게 지정하기 위해 생성된 테마 맵의 `selector` 속성이 컴포넌트 셀렉터를 결정하는 데 필요합니다. 믹스인이 스타일시트 루트에서 호출되면 생성된 규칙은 테마의 내부 `selector` 값을 사용합니다. 셀렉터 안에서 호출되면 그 셀렉터와 컴포넌트 셀렉터 모두 변수를 받습니다.
</DocsAside>

```scss
// Global override:
:root {
  @include tokens(avatar-theme($background: orange));
}
// Result: --ig-avatar-background: orange;

// Scoped consumption (no explicit override):
@include tokens(avatar-theme($schema: $schema), $mode: 'scoped');
// Result: --background resolves through var(--igx-avatar-background, var(--ig-avatar-background, #000))
//         and picks up the global orange value from --ig-avatar-background.
```

```scss
// _variables.scss
// free versioin
@use 'igniteui-angular/theming' as *;
@forward 'igniteui-angular/theming';

@use '@infragistics/igniteui-angular/theming' as *;
```

- 팔레트와 스키마:

- CSS 팔레트 변수는 더 이상 HEX 값을 나타내지 않으며, 대신 H, S, L 세 값의 목록을 나타냅니다. 따라서 이 값은 `hsl` 또는 `hsla` CSS 함수에 전달되어야 합니다.

이전:

```scss
.some-class {
    background: var(--igx-surface-500); // returns HEX color
}
```

이후:

```scss
.some-class {
    background: hsl(var(--igx-surface-500)); // returns a list of H, S, L
}
```

이는 팔레트를 CSS 변수만으로 실행 중에 바꿀 수 있도록 하기 위해서입니다. 이렇게 하면 기본 팔레트 색상에 영향을 주지 않고 실행 중에 특정 팔레트 색상의 알파 채널을 바꿀 수 있습니다.

- 사용자 지정으로 만든 컴포넌트 및 전역 테마에 올바른 팔레트와 컴포넌트 스키마를 전달했는지 확인하십시오. 전역 어두운 테마를 만들려면, 예를 들어 회색 색상으로 더 밝은 명도 단계를 선택하십시오:

```scss

    $primary: olive,
    $secondary: yellow,
    $grays: #fff
);

@include dark-theme($palette: $my-dark-palette);
```

마찬가지로 밝은 테마에는 더 어두운 회색 명도 단계와 밝은 색상 스키마가 필요합니다.

전역 테마에서 컴포넌트 테마를 하나도 제외하지 않았지만 `css-vars` 믹스인을 사용해 자체 대체 테마를 만들고 싶다면, 테마에 올바른 팔레트와 해당 스키마를 전달했는지 확인하십시오:

```scss
$my-custom-grid: grid-theme(
    $palette: $my-dark-palette,
    $schema: $dark-schema
);

@include css-vars($my-custom-grid);
```

- 제외된 컴포넌트 테마:

전역 테마에서 일부 컴포넌트 테마를 제외하고 자체 대체 테마를 만들었다면, 컴포넌트 믹스인이 포함되어 있고 올바른 컴포넌트 테마가 전달되는지 확인하십시오:

```scss
$my-dark-palette: palette(
    ...
    $exclude: ('igx-grid')
);

$my-custom-grid: grid-theme(
    $palette: $my-dark-palette,
    $schema: $dark-schema
);

// Ensuregrid is included:
@include grid($my-custom-grid);
```

사용자 지정 컴포넌트 테마가 전역 `styles.scss`이(가) 아닌 별도의 컴포넌트 Sass 파일에 선언되어 있다면, `core` 믹스인도 포함되어 있는지 확인하십시오.

```scss
// free version
@use 'igniteui-angular/theming' as *;

// licensed version
@use '@infragistics/igniteui-angular/theming' as *;

// Include the core module mixin.
@include core();

// Create your theme.
$my-custom-grid: grid-theme(
    $palette: $my-dark-palette,
    $schema: $dark-schema
);

// Include your custom theme styles.
@include grid($my-custom-grid);
```

Sass 모듈 시스템을 더 잘 이해하려면 [Miriam Suzanne](https://css-tricks.com/author/miriam/)의 [이 훌륭한 글](https://css-tricks.com/introducing-sass-modules/)을 읽어 보십시오;

### IgxGridCell 마이그레이션

- _IgxGridCellComponent_, _IgxTreeGridCellComponent_, _IgxHierarchicalGridCellComponent_, *IgxGridExpandableCellComponent*는 더 이상 공개 API에 노출되지 않습니다.

```ts
const cell = grid.getCellByColumn(0, 'ProductID');     // returns IgxGridCell

const rowCells = grid.getRowByIndex(0).cells;          // returns IgxGridCell[]
const selectedCells = grid.selectedCells;              // returns IgxGridCell[]
const cells = grid.getColumnByName('ProductID').cells; // returns IgxGridCell[]
```

#### 해결 방법

어떤 이유로든 `math.div`이(가) 알려진 함수가 아니라는 Sass 컴파일 오류가 보인다면, 프로젝트에서 오래된 버전의 Sass를 사용하고 있다는 뜻입니다.

1. `ng update`을(를) 사용하여 최신 버전의 Angular로 업데이트하십시오. Angular 12.1.0 이상은 기본적으로 dart-sass 컴파일러를 사용합니다.

    ```sh
    ng update [options]
    ```

    어떤 이유로 Ignite UI/Angular CLI를 사용하지 않는다면, Node 프로젝트에서 `node-sass`을(를) `sass`(으)로 바꿔야 합니다.

    ```sh
    npm uninstall node-sass
    npm install sass --save-dev
    ```

2. 어떤 이유로 위 방법으로 최신 버전의 Angular로 업그레이드할 수 없다면, Sass 파일에서 전역 플래그를 설정하여 이전 Sass 나눗셈 방식으로 되돌릴 수 있습니다:

    ```scss
    $__legacy-libsass: true;
    ```

## 11.1.x에서 12.0.x로

### 테마

- 호환성 깨짐 변경:
  - `IgxAvatar` 테마가 단순화되었습니다. 테마 매개변수(`avatar-theme`)의 수가 크게 줄었으며, 접두사 매개변수(`icon-*`, `initials-*`, `image-*`)와 접미사 매개변수(`border-radius-*`)를 더 이상 포함하지 않습니다. `ng update`로 수행한 업데이트는 기존 avatar 테마를 마이그레이션하지만, 접두사 및 접미사 매개변수가 없는 것을 고려하여 추가로 조정이 필요할 수 있습니다.

    기존의 타입별 avatar 테마를 다음과 같은 방식으로 수정해야 합니다:

    예를 들어 다음 코드는:

    ```scss
    $avatar-theme: avatar-theme(
        $initials-background: blue,
        $initials-color: orange,
        $icon-background: blue,
        $icon-color: orange,
    );

    @include avatar($avatar-theme);
    ```

    다음 코드로 바꿔야 합니다:

    ```scss
    $initials-avatar: avatar-theme(
        $background: blue,
        $color: orange,
    );

    $icon-avatar: avatar-theme(
        $background: blue,
        $color: orange,
    );

    .initials-avatar {
        @include avatar($initials-avatar);
    }

    .icon-avatar {
        @include avatar($icon-avatar);
    }
    ```

  - `IgxButton` 테마가 단순화되었습니다. 테마 매개변수(`button-theme`)의 수가 크게 줄었으며, 접두사 매개변수(`flat-*`, `raised-*` 등)를 더 이상 포함하지 않습니다. `ng update`로 수행한 업데이트는 기존 button 테마를 마이그레이션하지만, 접두사 매개변수가 없는 것을 고려하여 추가로 조정이 필요할 수 있습니다.

    아래 코드 스니펫과 같은 결과를 얻으려면 다음과 같이 하십시오.

    ```html
    <button igxButton="raised">Raised button</button>
    <button igxButton="outlined">Outlined button</button>
    ```

    ```scss
    $my-button-theme: button-theme(
        $raised-background: red,
        $outlined-outline-color: green
    );

    @include css-vars($my-button-theme);
    ```

    버튼 타입마다 별도의 테마를 만들고, 이를 CSS 셀렉터로 범위를 지정해야 합니다.

    ```html
    <div class="my-raised-btn">

    <button igxButton="raised">Raised button</button>
    
    </div>
    <div class="my-outlined-btn">

        <button igxButton="outlined">Outlined button</button>
    
    </div>
    ```

    ```scss
    $my-raised-button: button-theme(
        $background: red
    );

    $my-outlined-button: button-theme(
        $border-color: red
    );

    .my-raised-btn {
        @include css-vars($my-raised-button);
     }

    .my-outlined-btn {
        @include css-vars($my-outlined-button);
    }
    ```

    보시다시피 `button-theme` 매개변수가 이제 버튼 타입마다 같은 이름을 가지므로, 타입마다 다른 색상을 가지려면 버튼 테마의 범위를 CSS 셀렉터로 지정해야 합니다.

    `button-theme`의 모든 <ApiLink kind="sass" module="themes" type="function-button-theme" label="사용 가능한 속성" />를 여기에서 볼 수 있습니다

  - `typography` 믹스인은 더 이상 `core`와 함께 암시적으로 포함되지 않습니다. 타이포그래피 스타일을 사용하려면 `core` 이후이고 `theme` 이전에 믹스인을 명시적으로 포함해야 합니다:

    ```scss
    // in styles.scss

    @include core();

    @include typography(
        $font-family: $material-typeface,
        $type-scale: $material-type-scale
    );

    @include theme();
    ```

    <DocsAside type="info">
    `core` 믹스인은 항상 먼저 포함해야 합니다.
    </DocsAside>

    Ignite UI for Angular에 포함된 각 테마에 대해 사용할 수 있는 특정 `font-family`과 `type-scale` 변수를 제공합니다:

| **테마** | **글꼴 패밀리**     | **타입 스케일**        |
| :-------- | :------------------ | :-------------------- |
| Material  | $material-typeface  | $material-type-scale  |
| Fluent    | $fluent-typeface    | $fluent-type-scale    |
| Bootstrap | $bootstrap-typeface | $bootstrap-type-scale |
| Indigo    | $indigo-typeface    | $indigo-type-scale    |

### IgxBottomNav 컴포넌트

<ApiLink type="BottomNav" label="**IgxBottomNavComponent**" />은(는) 탭 헤더와 콘텐츠를 더 유연하고 설명적으로 정의할 수 있도록 완전히 리팩터링되었습니다. 기존 **igx-bottom-nav** 정의를 새 정의로 마이그레이션하려면 **ng update**로 업데이트하는 것을 권장합니다.

- 템플릿
  - 새 구조는 헤더 컴포넌트와 콘텐츠 컴포넌트를 각각 감싸는 하단 내비게이션 항목 컴포넌트를 정의합니다. 헤더에는 보통 아이콘([`Material guidelines`](https://material.io/components/bottom-navigation#usage))이 포함되지만, 레이블이나 다른 사용자 지정 콘텐츠를 포함할 수도 있습니다.
  - 헤더 스타일링을 위해 두 개의 새 디렉티브 `igxBottomNavHeaderLabel`과 `igxBottomNavHeaderIcon`를 도입했습니다.
  - 이제 헤더 컴포넌트는 어떤 콘텐츠든 추가할 수 있으므로, 이전에 탭 헤더를 다시 템플릿으로 만드는 데 사용되던 `igxTab` 디렉티브는 더 이상 필요하지 않아 제거되었습니다.
  - 컴포넌트를 내비게이션 시나리오에서 사용할 때는 `routerLink` 디렉티브를 헤더 컴포넌트에 연결해야 합니다.

    ```html
    <igx-bottom-nav>
        <igx-bottom-nav-item>
            <igx-bottom-nav-header>
                <igx-icon igxBottomNavHeaderIcon>folder</igx-icon>
                <span igxBottomNavHeaderLabel>Tab 1</span>
            </igx-bottom-nav-header>
            <igx-bottom-nav-content>
                Content 1
            </igx-bottom-nav-content>
        </igx-bottom-nav-item>
        ...
    </igx-bottom-nav>
    ```

- API 변경 사항
  - `id`, `itemStyle`, `panels`, `viewTabs`, `contentTabs`, `tabs` 속성이 제거되었습니다. 현재 <ApiLink type="BottomNav" member="items" label="items" /> 속성이 탭 컬렉션을 반환합니다.
  - 다음 속성이 변경되었습니다:
    - 탭 항목의 `isSelected` 속성이 `selected`(으)로 이름이 바뀌었습니다.
    - `selectedTab` 속성이 <ApiLink type="BottomNav" member="selectedItem" label="selectedItem" />(으)로 이름이 바뀌었습니다.
  - `onTabSelected`과 `onTabDeselected` 이벤트가 제거되었습니다. 탭 선택을 더 유연하고 세밀하게 제어할 수 있도록 <ApiLink type="BottomNav" member="selectedIndexChanging" label="selectedIndexChanging" />, <ApiLink type="BottomNav" member="selectedIndexChange" label="selectedIndexChange" />, <ApiLink type="BottomNav" member="selectedItemChange" label="selectedItemChange" /> 세 개의 새 이벤트를 도입했습니다. 안타깝게도 이러한 이벤트 변경에 대한 적절한 마이그레이션은 매우 복잡하므로, 오류는 프로젝트 수준에서 처리해야 합니다.

### IgxTabs 컴포넌트

<ApiLink type="Tabs" label="**IgxTabsComponent**" />은(는) 탭 헤더와 콘텐츠를 더 유연하고 설명적으로 정의할 수 있도록 완전히 리팩터링되었습니다. 기존 **igx-tabs** 정의를 새 정의로 마이그레이션하려면 **ng update**로 업데이트하는 것을 권장합니다.

- 템플릿
  - 새 구조는 헤더 컴포넌트와 콘텐츠 컴포넌트를 각각 감싸는 탭 항목 컴포넌트를 정의합니다. 헤더에는 보통 아이콘과 레이블이 포함되지만, 다른 사용자 지정 콘텐츠를 포함할 수도 있습니다.
  - 헤더 스타일링을 위해 두 개의 새 디렉티브 `igxTabHeaderLabel`과 `igxTabHeaderIcon`를 도입했습니다.
  - 이제 헤더 컴포넌트는 어떤 콘텐츠든 추가할 수 있으므로, 이전에 탭 헤더를 다시 템플릿으로 만드는 데 사용되던 `igxTab` 디렉티브는 더 이상 필요하지 않아 제거되었습니다.
  - 컴포넌트를 내비게이션 시나리오에서 사용할 때는 `routerLink` 디렉티브를 헤더 컴포넌트에 연결해야 합니다.

    ```html
    <igx-tabs>
        <igx-tab-item>
            <igx-tab-header>
                <igx-icon igxTabHeaderIcon>folder</igx-icon>
                <span igxTabHeaderLabel>Tab 1</span>
            </igx-tab-header>
            <igx-tab-content>
                <h1>Tab 1 Content</h1>
                <p>Lorem ipsum dolor sit amet, consectetur adipiscing elit.</p>
            </igx-tab-content>
        </igx-tab-item>
    ...
    </igx-tabs>
    ```

- API 변경 사항
  - `id`, `groups`, `viewTabs`, `contentTabs`, `tabs` 속성이 제거되었습니다. 현재 <ApiLink type="Tabs" member="items" label="items" /> 속성이 탭 컬렉션을 반환합니다.
  - 다음 속성이 변경되었습니다:
    - 탭 항목의 `isSelected` 속성이 <ApiLink type="TabItem" member="selected" label="selected" />(으)로 이름이 바뀌었습니다.
    - `selectedTabItem` 속성이 <ApiLink type="Tabs" member="selectedItem" label="selectedItem" />(으)로 줄여졌습니다.
    - `type` 속성은 contentFit 및 fixed 옵션과 함께 더 이상 사용할 수 없습니다. 헤더의 크기 및 위치 지정 모드는 이제 네 가지 값(start(기본값), center, end, justify)을 받는 <ApiLink type="Tabs" member="tabAlignment" label="tabAlignment" /> 입력 속성으로 제어합니다. 이전 `contentFit` 타입은 현재 `start` 정렬 값에, 이전 `fixed` 타입은 현재 `justify` 값에 해당합니다.
  - `tabItemSelected`과 `tabItemDeselected` 이벤트가 제거되었습니다. 탭 선택을 더 유연하고 세밀하게 제어할 수 있도록 <ApiLink type="Tabs" member="selectedIndexChanging" label="selectedIndexChanging" />, <ApiLink type="Tabs" member="selectedindexchange" label="selectedIndexChange" />, <ApiLink type="Tabs" member="selectedIndexChange" label="selectedItemChange" /> 세 개의 새 이벤트를 도입했습니다. 안타깝게도 이러한 이벤트 변경에 대한 적절한 마이그레이션은 매우 복잡하므로, 오류는 프로젝트 수준에서 처리해야 합니다.

### IgxGridComponent, IgxTreeGridComponent, IgxHierarchicalGridComponent

- _IgxGridRowComponent_, _IgxTreeGridRowComponent_, _IgxHierarchicalRowComponent_, *IgxGridGroupByRowComponent*는 더 이상 공개 API에 노출되지 않습니다.
- 위 항목 중 하나의 인스턴스를 반환하던 공개 API는 이제 공개 <ApiLink type="RowType" kind="interface" /> 인터페이스를 구현하는 객체를 반환합니다:

```ts
const row = grid.getRowByIndex(0);
const row = grid.getRowByKey(2);
const row = cell.row;
```

<ApiLink type="RowType" kind="interface" />의 공개 API는 _IgxRowComponent_ 등이 이전에 노출하던 것과 같지만, 다음 사항에 유의하십시오:

- *IgxHierarchicalRowComponent*가 노출하던 _toggle_ 메서드는 사용할 수 없습니다. 모든 행 타입에 대해 <ApiLink kind="interface" type="RowType" member="expanded" /> 속성을 사용하십시오:

```ts
grid.getRowByIndex(0).expanded = false;
```

*row.rowData_ 및 _row.rowID_: 사용 중단되었으며 버전 13에서 완전히 제거될 예정입니다. 대신 다음을 사용하십시오: _row.data_, _row.key_.

- *onRowPinning*이 발생시키는 이벤트 인수의 _row_ 속성과, _onRowDragStart_, *onRowDragEnd*가 발생시키는 이벤트 인수의 _dragData_ 속성은 이제 <ApiLink type="RowType" kind="interface" />을(를) 구현합니다
- *ng update*는 import, 타이핑, 캐스트 같은 _IgxGridRowComponent_, _IgxTreeGridRowComponent_, _IgxHierarchicalRowComponent_, *IgxGridGroupByRowComponent*의 대부분의 사용을 마이그레이션합니다. 코드에서 위 항목 중 하나를 사용하는 곳이 마이그레이션되지 않았다면, 타이핑/캐스트를 제거하거나 <ApiLink type="RowType" kind="interface" />(으)로 바꾸십시오.
- 해당 인덱스의 행이 요약 행이면 *getRowByIndex*는 이제 <ApiLink type="RowType" kind="interface" /> 객체를 반환합니다(이전에는 *undefined*를 반환했습니다). 인덱스의 행이 요약 행이거나 그룹화 행이면 *row.isSummaryRow*와 *row.isGroupByRow*는 true를 반환합니다.

### IgxInputGroupComponent

- `disabled` 속성이 제거되었습니다. 이 속성은 입력 그룹의 상태가 항상 기반이 되는 `igxInput`에 의해 관리되었기 때문에 오해를 불러일으켰습니다.

### IgxDateTimeDirective, IgxDatePickerComponent, IgxTimePickerComponent, IgxDateRangePickerComponent

    ```typescript
    export class MyExampleCombo {
        public data: { name: string, id: string }[] = [{ name: 'London', id: 'UK01' }, { name: 'Sofia', id: 'BG01' }, ...];
        ...
        selectFavorites() {
            // Selection is handled with the data entries' id properties
            this.combo.selectItems(['UK01', 'BG01']);
        }
    }
    ```

  - combo에 `valueKey`가 정의되어 **있지 않다면**, **모든** 선택 이벤트는 **동등성 비교(===)**로 처리됩니다.
    `valueKey`가 지정**되지 않은** 모든 combo는 선택/양방향 바인딩을 데이터 항목에 대한 **참조**로 처리해야 합니다:

    ```html
    <igx-combo [data]="cities" displayKey="name"></igx-combo>
    ```

    ```typescript
    export class MyExampleCombo {
        public data: { name: string, id: string }[] = [{ name: 'London', id: 'UK01' }, { name: 'Sofia', id: 'BG01' }, ...];
        ...
        selectFavorites() {
            // Selection is handled with references to the data entries
            this.combo.selectItems([this.data[0], this.data[1]]);
        }
    }
    ```

    combo 설정에 대한 자세한 내용은 [readme](https://github.com/IgniteUI/igniteui-angular/blob/master/projects/igniteui-angular/src/lib/combo/README.md#value-binding)와 [공식 문서](/inputs/combo/overview#value-and-selection)에서 읽을 수 있습니다.

## 8.0.x에서 8.1.x로

- `igx-paginator` 컴포넌트가 독립형 컴포넌트로 도입되었으며, 그리드 컴포넌트에서도 사용됩니다.
`paginationTemplate`을(를) 설정했다면 페이지네이션이 올바르게 표시되도록 CSS를 수정해야 할 수도 있다는 점을 유의하십시오. 템플릿이 이제 콘텐츠를 가운데 정렬하는 CSS 규칙이 있는 페이징 전용 컨테이너 아래에 적용되지 않기 때문입니다. 따라서 이러한 규칙을 직접 추가해야 할 수 있습니다.
스타일은 다음과 비슷해야 합니다:

```html
<igx-grid #grid [data]="data" [paging]="true" [perPage]="10" [paginationTemplate]="pager">
</igx-grid>
<ng-template #pager>
    <div class="pagination-container"></div>
</ng-template>
```

```css
.pagination-container {
 display: flex;
 justify-content: center;
 align-items: center;
}
```

 버전 7.1 이전:

```typescript
export class CustomSummary extends IgxNumberSummaryOperand {
 public operate(data?: any[]): IgxSummaryResult[] {

   key: 'average',
   label: 'average',
   summaryResult: IgxNumberSummaryOperand.average(data).toFixed(2)
  }];
 }
}
```

 버전 7.1 이후:

```typescript
export class CustomSummary extends IgxNumberSummaryOperand {
```
