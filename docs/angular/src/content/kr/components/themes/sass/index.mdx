# Sass로 테마 적용하기

<div class="highlight">
Ignite UI for Angular는 애플리케이션의 스타일을 완전히 제어할 수 있도록 Sass 테마 API를 노출하는 것을 주저하지 않습니다. 우리가 노출하는 API는 대체로 제품과 함께 번들로 제공되는 모든 테마를 내부적으로 만들 때 사용하는 것과 정확히 같은 API입니다. 이는 추상적이며, 단일 컴포넌트부터 전체 애플리케이션 제품군에 이르기까지 여러 수준에서 세밀한 테마 적용을 가능하게 합니다.
</div>
<igc-divider></igc-divider>

## 개요

**IgniteUI for Angular**는 컴포넌트 디자인을 [Material Design 원칙](https://material.io/guidelines/material-design/introduction.html)에 기반하므로, 기본 테마에 대해 Google이 만든 것에 최대한 가깝도록 컴포넌트의 색상, 크기, 타이포그래피, 전반적인 모양과 느낌을 맞추려고 합니다. Material Design 시스템은 계속 변하며 주요 변경을 피하지 않으므로, 이것이 결국 우리가 제공하는 컴포넌트의 스타일을 작성하고 수정하는 방식에 영향을 줍니다. Microsoft Fluent, Bootstrap, 그리고 우리 자체 Indigo Design 시스템이라는 세 가지 추가 테마를 지원하므로, Material Design 시스템을 맞추는 일은 간단하지 않습니다. 그래서 완전히 다른 컴포넌트 스타일을 생성할 수 있는 매우 모듈화되고, 구성 가능하며, 그러면서도 유지 관리가 쉬운 기반을 구축해야 했습니다. 또한 오래된 브라우저와 최신 브라우저를 모두 지원해야 하므로, Sass는 변수, 함수, 믹스인으로 이루어진 체계적인 시스템을 만들 수 있는 도구를 제공하여 이 작업에 큰 도움이 되었습니다.

우리의 테마 접근 방식은 여러 개념, 즉 테마 스키마, 팔레트, 타이포그래피, 둥근 정도, 고도, 애니메이션을 기반으로 합니다. 이 개념들을 혼합하여 최종 테마를 만듭니다. 각 개념은 보다 세밀한 스타일 지정이 가능하도록 더 세분화됩니다.

디자인 시스템의 특정 측면이 손상되지 않도록 하기 위해, 우리가 노출한 API를 사용하여 모든 것을 바꾸거나 스타일을 완전히 다시 쓰도록 허용하지는 않습니다. 하지만 충분히 파고든다면 가능할 것입니다.

테마 엔진을 진정으로 제어할 수 있도록 모든 개념과 관련 API를 자세히 설명하겠습니다.

<DocsAside type="info">
[**Sass**](https://sass-lang.com) 테마 라이브러리는 강력하지만, 대부분의 사람은 기본 테마를 사용자 지정하기 위해 몇 가지 CSS 변수만 수정하면 될 것입니다. 먼저 CSS 변수 문서를 읽어 볼 것을 권장합니다. 생성된 테마를 더 깊은 수준에서 수정하고 싶을 때만 Sass를 사용해야 합니다. 좋은 예로, 같은 컴포넌트에 대해 재사용 가능한 여러 테마 변형을 만들어야 하거나, 생성된 CSS를 트리 셰이킹하여 앱에서 사용하는 컴포넌트의 스타일만 포함하도록 하고 싶은 경우가 있습니다.
</DocsAside>

## 팔레트

먼저 이해해야 할 개념은 팔레트입니다. 모든 시각적 도구에서와 마찬가지로, 색상은 한 애플리케이션과 다른 애플리케이션을 구별하는 주요 요소입니다. Material Design 지침은 주어진 기본 색상에 대해 색조, 명도, 채도가 다양한 미리 정의된 색상 팔레트를 규정합니다. 여기에는 충분한 이유가 있습니다. 배경색과 전경 텍스트 색상 사이의 좋은 색상 조화와 대비를 보장하려는 것입니다. 이는 훌륭하지만 동시에 제약이기도 합니다. Material 지침을 기반으로 브랜드에 맞는 자체 사용자 지정 팔레트를 원한다면, 아마도 운이 없을 것입니다. 우리는 이것이 문제임을 인식하여, 제공하는 기본 색상에서 Material과 비슷한 팔레트를 생성하는 알고리즘을 만들었습니다. 또한 팔레트의 각 색조에 대해 대비 텍스트 색상도 생성합니다.

## 스키마

두 번째 중요한 개념은 테마 스키마입니다. 테마 스키마는 개별 컴포넌트 테마를 위한 레시피와 같습니다. 개별 컴포넌트 테마에 어떤 팔레트 색상을 사용해야 하고 전반적인 둥근 정도와 그림자가 어떠해야 하는지에 대한 정보를 제공합니다. 예를 들어 컴포넌트 스키마는 사용자가 컴포넌트 테마에 어떤 팔레트를 전달하든 상관없이, 요소의 배경색이 `primary` 색상의 `500` 변형이어야 한다고 컴포넌트 테마에 알려 줍니다.

## 타이포그래피

타이포그래피는 Sass 테마 라이브러리의 별도 모듈이며 개별 컴포넌트 테마와 분리되어 있습니다. 기본 서체를 선택해 두었지만, 애플리케이션을 모든 면에서 스타일링할 수 있는 힘을 여러분에게 주고 싶습니다. 타이포그래피는 그 중요한 부분입니다. 앱에서 글꼴 패밀리, 제목, 부제목, 버튼, 본문 텍스트 등의 크기와 굵기를 바꿀 수 있는 방법을 제공합니다.

## 둥근 정도

Sass 테마 시스템은 각 컴포넌트에 대해 최소 및 최대 둥근 정도를 정의합니다. CSS 맥락에서는 `border-radius`이라는 용어에 더 익숙할 수 있습니다. 둥근 정도도 비슷하게 컴포넌트의 요소를 스타일링하기 위해 `border-radius`을(를) 사용하지만, 테마 시스템의 맥락에서 둥근 정도는 0과 1 사이의 숫자입니다. 둥근 정도가 0인 컴포넌트는 컴포넌트 테마가 정의한 최소 border-radius를 사용합니다. 이는 0일 수도 있고 0이 아닌 값일 수도 있습니다. 마찬가지로 둥근 정도를 1로 설정하면 border-radius가 컴포넌트에 허용되는 최대 반경으로 설정됩니다. 최소 및 최대 border-radius는 컴포넌트 테마 자체에서 정의되지만, 기본 둥근 정도 값은 컴포넌트 스키마에서 설정됩니다.

## 고도

고도는 각 컴포넌트 테마의 여러 부분에 설정되는 그림자입니다. Material Design 지침에 따라 25(0-24) 수준을 기반으로 합니다. 유한한 개수의 그림자를 사용하면 애플리케이션에서 깊이 계층을 일관되게 정의할 수 있습니다. Sass에서 이는 24개의 고도 수준을 가진 맵으로 정의되며, 값은 `box-shadows`이고 나중에 컴포넌트 테마에 전달됩니다. 컴포넌트 스키마는 특정 요소가 사용해야 하는 고도 수준에 대한 일반적인 정보를 테마에 제공합니다.

## 애니메이션

일부 컴포넌트는 상태 변화를 명확하게 전달하기 위해 keyframe 전환과 애니메이션을 사용합니다. 애플리케이션 전체에서 가져와 사용할 수 있는 대규모 keyframe 애니메이션 및 타이밍 함수 라이브러리를 포함하고 있습니다. 이들은 트리 셰이킹되므로 같은 애니메이션 믹스인을 두 번 포함하더라도 출력 스타일시트에는 하나의 CSS 선언만 생성됩니다.

## 테마

마지막으로 컴포넌트 테마가 있습니다. 팔레트, 스키마, 고도, 둥근 정도, 애니메이션은 테마에서 사용되지 않으면 그 자체로는 큰 역할을 하지 못합니다. 우리는 개별 컴포넌트용 테마와, 애플리케이션과 그 안의 모든 컴포넌트 전체의 스타일을 지정하는 전역 테마를 제공합니다. 팔레트와 스키마를 전역 테마에 전달하기만 하면, 나머지는 우리가 처리합니다. 물론 사용자 지정 스키마와 고도를 만들고 컴포넌트 테마 믹스인에 다른 둥근 정도와 색상 값을 전달하여, 각 컴포넌트의 스타일을 원하는 대로 개별적으로 지정할 수도 있습니다.
