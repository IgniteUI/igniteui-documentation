# 컴포넌트 테마

<div class="highlight">
컴포넌트 테마를 사용하면 전역으로 정의된 테마를 재정의하여 특정 컴포넌트 인스턴스의 스타일을 바꿀 수 있습니다.
</div>

## 개요

<hr/>

Ignite UI for Angular 컴포넌트 테마는 CSS 사용자 지정 속성을 사용합니다. 각 컴포넌트는 자신의 번들에 구조적 CSS를 포함하고, Sass 테마 함수와 `tokens()` 믹스인은 그 스타일이 사용하는 디자인 토큰 값을 생성합니다. 이렇게 하면 컴포넌트 CSS를 트리 셰이킹할 수 있으며, 애플리케이션은 구조적 규칙을 다시 생성하지 않고도 실행 중에 테마를 재정의할 수 있습니다.

<igc-divider></igc-divider>

## 테마 만들기

<hr/>

컴포넌트 테마는 두 부분으로 구성됩니다:

- **컴포넌트 테마 함수** — 제공된 값을 정규화하고 테마 맵을 반환합니다.
- **`tokens()` 믹스인** — 그 맵을 사용하여 전역 또는 범위 모드에서 CSS 사용자 지정 속성을 생성합니다.

Ignite UI for Angular 22.1.0부터 컴포넌트별 기존 래퍼 믹스인은 더 이상 존재하지 않습니다. 모든 컴포넌트 테마에는 `tokens()`을(를) 사용하십시오.

### 토큰 믹스인

모드는 `tokens()`이(가) 범용 재정의를 내보낼지, 아니면 컴포넌트의 구조적 스타일시트가 사용하는 완전한 로컬 변수를 내보낼지 결정합니다.

**전역 모드(기본값)** — 범용 `--ig-{component}-{property}` 토큰을 내보냅니다. 로컬 var() 참조는 해당 전역 값으로 다시 작성되므로, 파생 값(예: `adaptive-contrast`)은 모든 범위에서 올바르게 해석됩니다. 크기가 큰 식은 건너뛰므로, 대신 구체적인 값을 전달해야 합니다.

```scss
// Input:
@include tokens(avatar-theme($background: red));

// Output:
:root {
  --ig-avatar-background: red;
  /* ... remaining avatar properties ... */
}
```

**범위 지정 모드** — 구성된 접두사(`--igx-*`)에서 범용 토큰(`--ig-*`)을 거쳐 마지막으로 스키마 기본값으로 이어지는 대체 체인을 갖춘 컴포넌트 로컬 변수(`--{property}`)를 내보냅니다. 스타일시트 루트에서 호출되면 테마 맵의 선택기가 사용됩니다. 다른 선택기 안에서 호출되면 현재 선택기와 컴포넌트 선택기에 대해 선언이 내보내집니다.

```scss
// Input (from root):
@include tokens(avatar-theme($background: red), $mode: 'scoped');

// Output:
igx-avatar {
  --background: var(--igx-avatar-background, var(--ig-avatar-background, red));
  /* ... remaining avatar properties ... */
}


// Input (from within a selector):
.my-theme {
  @include tokens(avatar-theme($background: red), $mode: 'scoped');
}

// Output:
.my-theme,
.my-theme igx-avatar {
  --background: var(--igx-avatar-background, var(--ig-avatar-background, red));
  /* ... */
}
```

애플리케이션 전체에 적용되거나 여러 컴포넌트 인스턴스가 상속해야 하는 범용 재정의에는 기본 전역 모드를 사용하십시오. 컴포넌트의 로컬 선언이 범용 토큰을 사용할 수 있도록, 해당 컴포넌트는 전역 [`theme()`](/themes/sass/global-themes) 출력에 계속 포함되어 있어야 합니다.

avatar 테마 정의하기:

```scss
// Change the background of the avatar to purple.
$avatar-purple-theme: avatar-theme(
  $background: purple,
);

// Pass the theme to tokens() in its default global mode.
@include tokens($avatar-purple-theme);
```

이 코드는 `:root`에서 범용 `--ig-avatar-*` 재정의를 내보냅니다. 나중에 avatar에 대한 다른 전역 `tokens()` 호출이 나타나면, 일반적인 캐스케이드 순서에 따라 나중 값이 우선합니다.

예를 들어:

```scss
// ...
@include tokens($avatar-purple-theme);

// Later
$avatar-royalblue-theme: avatar-theme(
  $background: royalblue,
);

@include tokens($avatar-royalblue-theme);
```

위 코드에서 사실상의 전역 테마는 이제 `$avatar-royalblue-theme`입니다. 이전에 포함된 `tokens` 믹스인을 모두 덮어쓰기 때문입니다.

`$mode: 'scoped'`은(는) 테마가 전역 테마에서 아직 제공되지 않은 컴포넌트 로컬 선언을 내보내야 할 때에만 사용하십시오. 일반적인 경우는 `theme()`에서 제외된 컴포넌트, 컴포넌트 로컬 크기 식, 여러 선택기에 로컬 선언이 필요한 테마 맵, 그리고 다른 스키마나 밝은/어두운 변형을 설정하는 테마입니다. 해당 변형의 `$schema`을(를) 컴포넌트 테마 함수에 전달하십시오.

`tokens()`이(가) 선택기 안에 중첩되어 있거나 `css-vars()` 호출을 대체한다는 이유만으로 범위 지정 모드를 선택하지 마십시오. 컴포넌트가 전역 `theme()` 출력에 남아 있다면, 기본 전역 모드가 대체 토큰 체인을 통해 의도한 재정의를 보통 제공합니다. 사용자 지정이 기본 모드가 내보내지 않는 선언에 의존한다고 확인된 경우에만 범위 지정 모드를 사용하십시오.

분리된 오버레이는 자신을 연 컴포넌트에서 토큰 재정의를 상속하지 않습니다. 재정의를 전역으로 내보내거나 아웃레트를 테마가 적용된 컨테이너 아래로 옮기십시오. 오버레이 사용자 지정에도 전역 테마가 제공하지 않는 컴포넌트 로컬 선언이 필요한 경우에만 범위 지정 모드를 사용하십시오. [오버레이 스타일 지정](/overlay-styling)을 참조하십시오.

## 테마 범위 지정

<hr/>

앞의 예제에서 본 것처럼, 같은 수준에서 같은 컴포넌트를 대상으로 하는 테마를 여러 개 추가하면 마지막 테마 믹스인이 우선합니다. 이는 CSS 캐스케이드의 작동 방식 때문입니다. 같은 유형의 컴포넌트를 대상으로 하는 테마를 둘 이상 사용하려면, 이들을 선택기에 범위 지정해야 합니다. 예를 들어 여러 `igx-avatar` 테마를 만들고, 나중에 컴포넌트 마크업에서 사용할 특정 CSS 선택기에 범위를 지정할 수 있습니다.

```scss
// ...
// CSS class selectors
.avatar-royalblue {
  @include tokens($avatar-royalblue-theme);
}

.avatar-purple {
  @include tokens($avatar-purple-theme);
}
```

컴포넌트 템플릿에서:

```html
<div class="avatar-royalblue">

  <igx-avatar initials="AZ"></igx-avatar>
</div>

<div class="avatar-purple">

  <igx-avatar icon="home"></igx-avatar>
</div>
```

<DocsAside type="note">
일부 컴포넌트는 자신이 렌더링하는 컴포넌트의 테마를 지정하고, 그 토큰을 자신의 호스트에 선언합니다: [Grid](../../grid/theming.mdx), Tree Grid, Hierarchical Grid, Pivot Grid, [Query Builder](../../query-builder.mdx), [Excel Style Filtering](../../grid/excel-style-filtering.mdx), [열 숨기기](../../grid/column-hiding.mdx) 및 고정 UI, [Paginator](../../paginator.mdx) 및 Grid Toolbar. 상위 요소에 범위가 지정된 토큰은 그 안에 있는 컴포넌트에 도달하지 않습니다. 대신 상위 컴포넌트에 테마를 적용하거나, 예를 들어 `.promo igx-checkbox` 또는 `.promo .igx-tooltip`처럼 안쪽 컴포넌트를 직접 대상으로 하십시오. [Grid 안의 컴포넌트](../../grid/theming.mdx#grid-안의-컴포넌트)를 참조하십시오.
</DocsAside>

## 캐스케이드 레이어

<hr/>

구조적 스타일, 디자인 시스템 재정의, 파생/상황별 토큰은 컴포넌트 번들과 전역 프리셋에 나뉘어 있습니다. Ignite UI는 이들을 다음 [캐스케이드 레이어](https://developer.mozilla.org/en-US/docs/Web/CSS/@layer) 순서로 선언합니다: `ig.reset` → `ig.base` → `ig.material`/`ig.bootstrap`/`ig.fluent`/`ig.indigo` → `ig.derived`. 번들이 로드된 순서와 관계없이, 나중 레이어가 이전 레이어보다 우선합니다.

컴포넌트나 타이포그래피 스타일을 재정의하지 못하도록 서드파티 리셋 또는 노멀라이즈 스타일시트를 `ig.reset`로 감싸십시오:

```scss
@layer ig.reset {
  @import "minireset.css";
}
```

<DocsAside type="warning">
레이어에 속하지 않은 애플리케이션 규칙은 Ignite UI의 레이어 규칙보다 우선합니다. 일반적인 애플리케이션 재정의는 Ignite UI 레이어 순서에 의도적으로 참여시키고 싶은 경우가 아니라면 레이어에 속하지 않도록 두십시오.
</DocsAside>

## 뷰 캡슐화

<hr/>

지금까지는 전역 범위의 테마를 만들고 단일 Sass 파일에 포함하는 방법을 살펴보았습니다. 하지만 이것이 항상 바람직한 것은 아니며, 경우에 따라 Sass 파일을 특정 컴포넌트에 묶고 싶을 것입니다. 이런 경우에는 뷰 캡슐화, 특히 Angular가 이를 에뮬레이션하는 방식을 고려해야 합니다.

Angular 팀은 뷰 캡슐화에 세 가지 전략을 채택했습니다 - Emulated(기본값), ShadowDom, None. 이 각 전략에 대해 자세히 알아보려면 [Angular 문서](https://angular.dev/api/core/ViewEncapsulation)를 참조하십시오. 여기서는 뷰 캡슐화된 상위 컴포넌트의 일부인 Ignite UI for Angular 컴포넌트의 테마를 처리하는 방법을 자세히 살펴보겠습니다.

`Emulated` 뷰 캡슐화는 정확히 무엇을 의미할까요? 이 유형의 뷰 캡슐화는 Shadow DOM 명세를 활용하지 않고, 호스트 요소에 적용된 고유 속성 식별자를 사용하여 컴포넌트와 그 하위 요소에 스타일을 바인딩하는 방식을 사용합니다.

CSS 변수를 사용한 예제를 살펴보겠습니다. 특정 상위 컴포넌트에 묶인 avatar 테마를 만들어 보겠습니다.

다음은 간단한 컴포넌트입니다:

```typescript
import { Component, Input } from "@angular/core";

@Component({
  selector: "app-avatar",
  styleUrls: ["./app-avatar.component.scss"],
  template: `<igx-avatar [initials]="initials"></igx-avatar>`,
})
export class AvatarComponent extends Component {
  @Input() public initials = "AZ";
}
```

그리고 Sass 스타일시트는 다음과 같습니다:

```scss
// app-avatar.component.scss

// Import the theming module
@use "igniteui-angular/theming" as *;

// !IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';

$avatar-royalblue-theme: avatar-theme(
  $background: royalblue,
);

:host {
  @include tokens($avatar-royalblue-theme);
}
```

범용 avatar 토큰은 이 호스트에 선언되고 그 avatar가 상속합니다. 다만 Angular가 생성한 캡슐화 속성 때문에, 더 복잡한 컴포넌트 테마가 내보내는 선택기가 중첩되거나 내부에 있는 요소와 일치하지 않을 수 있습니다. 로컬 테마가 적용되지 않으면, 해당 include를 `::ng-deep`로 감싸거나 전역 스타일시트로 옮기십시오. 전역으로 내보내지 않는 한 테마는 이 `app-avatar` 하위 트리로 제한됩니다.

Shadow DOM 경계와 분리된 오버레이 아웃레트에서는, 대상이 상속할 수 있거나 그 선택기가 일치할 수 있는 위치에 테마를 내보내야 합니다.

위 인스턴스는 Sass를 전혀 사용하지 않고도 구현할 수 있습니다. 필요한 것은 `--ig-avatar-background` CSS 변수의 값을 원하는 색상으로 설정하는 것뿐입니다:

```css
/* app-avatar.component.css */
:host {
  --ig-avatar-background: royalblue;
}
```
