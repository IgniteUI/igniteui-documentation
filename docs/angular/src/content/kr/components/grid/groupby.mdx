# Angular 그리드 그룹화

Ignite UI for Angular 테이블 또는 UI 그리드의 그룹화 동작은 열 값을 기준으로 그룹화된 데이터 행을 만듭니다. <ApiLink type="Grid" />의 그룹화는 그룹을 계층 구조로 시각화할 수 있게 합니다. 그룹화된 데이터 행은 펼치거나 접을 수 있으며, 그룹화 순서는 UI 또는 API를 통해 바꿀 수 있습니다. 행 선택이 활성화되면 그룹 행의 가장 왼쪽 영역에 그룹화 행 선택기가 렌더링됩니다. <ApiLink type="Grid" member="rowSelection" /> 속성이 single로 설정된 경우 체크박스는 비활성화되며 선택이 놓인 그룹을 표시하는 역할만 합니다. <ApiLink type="Grid" member="rowSelection" /> 속성이 multiple로 설정된 경우, 그룹화 행 선택기를 클릭하면 이 그룹에 속한 모든 레코드가 선택됩니다.

## Angular 그리드 그룹화 예제

이 예제는 많은 양의 데이터에 대한 그룹화 기능을 보여 줍니다. 열 헤더를 맨 위(그룹화 영역)로 드래그하면 사용자는 선택한 열의 데이터를 계층 구조로 볼 수 있습니다. 더 많은 열 헤더를 맨 위로 드래그하여 여러 필드로 그룹화할 수도 있습니다. 이러한 그룹화 옵션은 행과 열이 많은 표에서 사용자가 데이터를 훨씬 빠르고 시각적으로 보기 좋은 방식으로 제시하고 싶을 때 유용합니다.

## 초기 그룹화 상태

그리드의 <ApiLink type="Grid" member="groupingExpressions" /> 속성에 표현식 배열을 할당하여 그리드의 초기 그룹화를 정의할 수 있습니다.

```typescript
public ngOnInit() {
    grid.groupingExpressions = [
        { fieldName: 'ProductName', dir: SortingDirection.Desc },
        { fieldName: 'Released', dir: SortingDirection.Desc }
    ];
}
```

그룹화 표현식은 <ApiLink kind="interface" type="ISortingExpression" /> 인터페이스를 구현합니다.

## Group By API

### 그룹화 API

그룹화는 UI와 그리드 컴포넌트가 제공하는 강력한 API를 통해 사용할 수 있습니다. 개발자는 각 열의 <ApiLink type="Column" member="groupable" /> 속성을 `true`(으)로 설정하여 최종 사용자가 특정 열을 기준으로 그리드 데이터를 그룹화할 수 있도록 허용할 수 있습니다.

```html
<igx-grid [data]="data">
    <igx-column *ngFor="let c of columns" [field]="c.field" [groupable]="true">
    </igx-column>
</igx-grid>
```

```typescript
public ngOnInit() {
    grid.columns.forEach((column) => {
        column.groupable = true;
    });
}
```

실행 중에 표현식은 <ApiLink type="Grid" member="groupingExpressions" /> 속성에서 가져오고 설정할 수 있습니다. 기존 표현식을 추가하거나 변경해야 하는 경우 단일 <ApiLink kind="interface" type="ISortingExpression" /> 또는 그 배열을 받는 <ApiLink type="Grid" member="groupby" /> 메서드를 사용할 수도 있습니다.

```typescript
grid.groupBy({ fieldName: 'ProductName', dir: SortingDirection.Desc, ignoreCase: true });
```

<DocsAside type="info">
지금까지는 그룹화와 정렬이 함께 동작했습니다. 13.2 버전에서는 그룹화를 정렬과 분리하는 새 동작이 도입되었습니다. 예를 들어 그룹화를 지워도 그리드의 정렬 표현식은 지워지지 않으며, 그 반대도 마찬가지입니다. 다만 열이 정렬되고 그룹화되어 있다면 그룹화 표현식이 우선합니다.
</DocsAside>

### 펼치기/접기 API

그룹화 표현식 외에도 그룹 행의 펼침 상태를 제어할 수 있습니다. 이 상태는 <ApiLink type="Grid" /> 컴포넌트 <ApiLink type="Grid" member="groupingExpansionState" />의 별도 속성에 저장됩니다. 그룹 행은 생성된 필드 이름과 그룹화의 각 수준에서 나타내는 값을 기준으로 고유하게 식별됩니다. 즉 펼침 상태 인터페이스의 시그니처는 다음과 같습니다:

```typescript
export interface IGroupByKey {
    fieldName: string;
    value: any;
}

export interface IGroupByExpandState {
    hierarchy: Array<IGroupByKey>;
    expanded: boolean;
}
```

<ApiLink type="Grid" member="groupingExpressions" />과 마찬가지로, <ApiLink kind="interface" type="IGroupByExpandState" />의 목록을 <ApiLink type="Grid" member="groupingExpansionState" />에 직접 설정하면 펼침이 그에 따라 바뀝니다. 또한 <ApiLink type="Grid" />는 그룹 레코드 인스턴스를 기준으로 그룹을 토글하는 메서드를 노출합니다.

```typescript
    const groupRow = this.grid.groupsRecords.find(r => r.value === "France");
    const groupRow = this.grid.getRowByIndex(0).groupRow;
    grid.toggleGroup(groupRow);
    groupRow.expanded = false;
```

그룹은 펼친 상태(_**기본값**_)나 접힌 상태로 생성할 수 있으며, 펼침 상태에는 보통 기본 동작과 반대되는 상태만 포함됩니다. <ApiLink type="Grid" member="groupsExpanded" /> 속성으로 그룹을 펼쳐서 만들지 여부를 제어할 수 있습니다.

### 그룹의 모든 행 선택/선택 해제 API

그룹의 모든 행을 선택하거나 선택 해제하는 기능은 <ApiLink type="Grid" member="selectRowsInGroup" /> 및 <ApiLink type="Grid" member="deselectRowsInGroup" /> API 메서드를 통해 사용할 수 있습니다.

아래 코드 스니펫은 그룹 레코드 인스턴스의 <ApiLink type="Grid" member="selectRowsInGroup" /> 메서드를 사용하여 그룹 내 모든 행을 선택하는 데 사용할 수 있습니다. 또한 이 메서드의 두 번째 매개변수는 이전 행 선택을 지울지 여부를 선택할 수 있는 불리언 속성입니다. 기본적으로 이전 선택은 유지됩니다.

```typescript
    const groupRow = this.grid.groupsRecords.find(r => r.value === "France");
    const groupRow = this.grid.getRowByIndex(0).groupRow;
    grid.selectRowsInGroup(groupRow);
```

프로그래밍 방식으로 그룹 내 모든 행의 선택을 해제해야 한다면 <ApiLink type="Grid" member="deselectRowsInGroup" /> 메서드를 사용할 수 있습니다.

```typescript
    const groupRow = this.grid.groupsRecords.find(r => r.value === "France");
    const groupRow = this.grid.getRowByIndex(0).groupRow;
    grid.deselectRowsInGroup(groupRow);
```

## 템플릿

### 그룹 행 템플릿

펼치기/접기 UI를 제외한 그룹 행은 완전히 템플릿으로 만들 수 있습니다. 기본적으로 그룹화 아이콘을 렌더링하고, 나타내는 필드 이름과 값을 표시합니다. 템플릿이 렌더링될 때 사용하는 그룹화 레코드는 다음 시그니처를 가집니다:

```typescript
export interface IGroupByRecord {
    expression: ISortingExpression;
    level: number;
    records: GroupedRecords;
    value: any;
    groupParent: IGroupByRecord;
    groups?: IGroupByRecord[];
}
```

예를 들어 다음 템플릿은 그룹 행의 요약을 더 자세하게 만듭니다:

```html
<ng-template igxGroupByRow let-groupRow>
    <span>Total items with value: {{ groupRow.value }} are {{ groupRow.records.length }}</span>
</ng-template>
```

### 그룹 행 선택기 템플릿

위에서 언급했듯이 펼치기/접기 UI를 제외한 그룹 행은 완전히 템플릿으로 만들 수 있습니다. 그리드 안에 사용자 지정 그룹화 행 선택기 템플릿을 만들려면, `igxGroupByRowSelector` 디렉티브를 가진 `<ng-template>`을(를) 선언하십시오. 템플릿에서는 암시적으로 제공되는 컨텍스트 변수에 접근할 수 있으며, 그 속성은 그룹화 행의 상태에 대한 정보를 제공합니다.

`selectedCount` 속성은 현재 선택된 그룹 레코드가 몇 개인지 보여 주고, `totalCount`은(는) 그룹에 속한 레코드가 몇 개인지 보여 줍니다.

```html
<ng-template igxGroupByRowSelector let-groupByRowContext>
    {{ groupByRowContext.selectedCount }} / {{ groupByRowContext.totalCount  }}
</ng-template>
```

`groupRow` 속성은 그룹 행에 대한 참조를 반환합니다.

```html
<ng-template igxGroupByRowSelector let-groupByRowContext>
    <div (click)="handleGroupByRowSelectorClick($event, groupByRowContext.groupRow)">Handle groupRow</div>
</ng-template>
```

`selectedCount`과 `totalCount` 속성을 사용하면 그룹화 행 선택기가 선택됨(체크)으로 표시할지 아니면 불확정(부분 선택)으로 표시할지 결정할 수 있습니다.

```html
<igx-grid #grid [data]="gridData" primaryKey="ProductID" rowSelection="multiple">
    <!-- ... -->
    <ng-template igxGroupByRowSelector let-context>
        <igx-checkbox
            [checked]=" context.selectedCount > 0 && context.selectedCount === context.totalCount"
            [indeterminate]="context.selectedCount > 0 && context.selectedCount !== context.totalCount">
        </igx-checkbox>
    </ng-template>
</igx-grid>
```

## 페이징과 함께하는 Angular 그리드 그룹화

그룹 행은 데이터 행과 함께 페이징 과정에 참여합니다. 각 페이지의 페이지 크기에 포함됩니다. 접힌 행은 페이징 과정에 포함되지 않습니다. 펼치기 또는 접기 작업은 페이징이 페이지 수를 다시 계산하고, 필요하면 페이지 인덱스를 조정하도록 합니다.
여러 페이지에 걸친 그룹은 페이지 사이에서 나뉩니다. 그룹 행은 시작하는 페이지에서만 보이며, 이후 페이지에서는 반복되지 않습니다. 그룹 행의 요약 정보는 그룹 전체를 기준으로 계산되며 페이징의 영향을 받지 않습니다.

## 키보드 탐색

그룹화 UI는 다음 키보드 상호 작용을 지원합니다:

- 그룹 행의 경우(포커스가 행 또는 펼치기/접기 셀에 있어야 함)
  - <kbd>ALT</kbd> + <kbd>RIGHT</kbd> - 그룹을 펼칩니다
  - <kbd>ALT</kbd> + <kbd>LEFT</kbd> - 그룹을 접습니다
  - <kbd>SPACE</kbd> - <kbd>rowSelection</kbd> 속성이 multiple로 설정되어 있으면 그룹의 모든 행을 선택합니다

- 그룹화 영역의 그룹 <ApiLink type="Chip" /> 컴포넌트의 경우(포커스가 칩에 있어야 함)
  - <kbd>SHIFT</kbd> + <kbd>LEFT</kbd> - 가능하다면 포커스된 칩을 왼쪽으로 옮겨 그룹화 순서를 바꿉니다
  - <kbd>SHIFT</kbd> + <kbd>RIGHT</kbd> - 가능하다면 포커스된 칩을 오른쪽으로 옮겨 그룹화 순서를 바꿉니다
  - <kbd>SPACE</kbd> - 정렬 방향을 바꿉니다
  - <kbd>DELETE</kbd> - 필드의 그룹화를 해제합니다
  - 칩의 개별 요소도 포커스할 수 있으며, <kbd>ENTER</kbd> 키로 상호 작용할 수 있습니다.

## Angular 그리드 사용자 지정 그룹화

igxGrid는 열별 또는 그룹화 표현식별로 사용자 지정 그룹화를 정의할 수 있으며, 이는 사용자 지정 조건에 따른 그룹화를 제공합니다. 복잡한 객체로 그룹화해야 하거나 기타 애플리케이션별 시나리오가 필요할 때 유용합니다.

<DocsAside type="info">
사용자 지정 그룹화를 구현하려면 먼저 데이터를 적절히 정렬해야 합니다. 따라서 기본 <ApiLink type="DefaultSortingStrategy" />을(를) 확장하는 사용자 지정 정렬 전략을 적용해야 할 수도 있습니다. 데이터가 정렬된 후에는 열 또는 특정 그룹화 표현식에 <ApiLink kind="interface" type="IGroupingExpression" member="groupingComparer" />을(를) 지정하여 사용자 지정 그룹을 결정할 수 있습니다.
</DocsAside>

아래 샘플은 `Date`을(를) 기준으로 한 사용자 지정 그룹화를 보여 주며, 여기서 날짜 값은 사용자가 선택한 그룹화 모드에 따라 일, 주, 월 또는 년으로 정렬되고 그룹화됩니다.

### Angular 사용자 지정 그룹화 예제


<Sample src="/grid/grid-groupby-custom" height={605} alt="Angular 사용자 지정 그룹화 예제" />


이 샘플은 서로 다른 날짜 조건에 대해 사용자 지정 정렬 전략을 정의합니다.
각 사용자 지정 전략은 기본 <ApiLink type="DefaultSortingStrategy" />을(를) 확장하고 <ApiLink type="DefaultSortingStrategy" member="compareValues" /> 메서드를 정의하는데, 이 메서드는 값을 정렬할 때 사용되는 사용자 지정 비교 함수입니다. 또한 비교에 필요한 날짜에서 값을 추출합니다.

```typescript
class BaseSortingStrategy extends DefaultSortingStrategy {

    public getParsedDate(date: any) {
        return {
            day: date.getDay(),
            month: date.getMonth() + 1,
            year: date.getFullYear()
        };
    }

    compareValues(a: any, b: any) {
        const dateA = this.getParsedDate(a);
        const dateB = this.getParsedDate(b);
        return dateA.year < dateB.year ?
            -1 : dateA.year > dateB.year ?
            1 : dateA.month  < dateB.month ?
            -1 : dateA.month > dateB.month ?
            1 : 0;
    }
}

class DaySortingStrategy extends BaseSortingStrategy {
    compareValues(a: any, b: any) {
        const dateA = this.getParsedDate(a);
        const dateB = this.getParsedDate(b);
        return dateA.year < dateB.year ?
            -1 : dateA.year > dateB.year ?
            1 : dateA.month  < dateB.month ?
            -1 : dateA.month > dateB.month ?
            1 : dateA.day < dateB.day ?
            -1 : dateA.day > dateB.day ?
            1 : 0;
    }
}

class WeekSortingStrategy extends BaseSortingStrategy {

    public getWeekOfDate(a: any) {
       return parseInt(new DatePipe("en-US").transform(a, 'w'), 10);
    }

    compareValues(a: any, b: any) {
        const dateA = this.getParsedDate(a);
        const dateB = this.getParsedDate(b);
        const weekA = this.getWeekOfDate(a);
        const weekB = this.getWeekOfDate(b);
        return dateA.year < dateB.year ?
            -1 : dateA.year > dateB.year ?
            1 : weekA < weekB ?
            -1 : weekA > weekB ?
            1 : 0;
    }
}
```

그룹화 표현식에는 <ApiLink kind="interface" type="IGroupingExpression" member="groupingComparer" /> 함수가 정의되어 있으며, 이 함수는 선택된 그룹화 모드에 따라 같은 그룹에 속하는 항목을 결정합니다. 이 함수가 0을 반환하는 정렬된 데이터의 값은 같은 그룹의 일부로 표시됩니다.

```typescript
 groupingComparer: (a, b) => {
    const dateA = this.sortingStrategy.getParsedDate(a);
    const dateB = this.sortingStrategy.getParsedDate(b);
    if (this.groupByMode === 'Month') {
        return dateA.month === dateB.month ? 0 : -1;
    } else if (this.groupByMode === "Year") {
        return dateA.year === dateB.year ? 0 : -1;
    } else if (this.groupByMode === "Week") {
        return this.sortingStrategy.getWeekOfDate(a) === this.sortingStrategy.getWeekOfDate(b) ? 0 : -1;
    }
    return dateA.day === dateB.day && dateA.month === dateB.month ? 0 : -1;
}
```

15.1.0 버전부터는 내장된 정렬 전략 `GroupMemberCountSortingStrategy`을(를) 사용하여 멤버 수를 기준으로 항목을 정렬할 수도 있습니다.

```typescript
public sortByGroup() {
        const expressions = this.grid1.groupingExpressions;
        if (expressions.length) {
            const fieldName = expressions[0].fieldName;
            const dir = expressions[0].dir === SortingDirection.Asc ? SortingDirection.Desc : SortingDirection.Asc;
            this.grid1.groupBy({ fieldName, dir, ignoreCase: false, strategy: GroupMemberCountSortingStrategy.instance() });
        }
    }
```

## 스타일링

igxGrid는 [`Ignite UI for Angular Theme Library`](/themes/sass/component-themes)을 통해 스타일링을 허용합니다. 그리드의 <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} />은(는) 매우 다양한 속성을 노출하며, 이를 통해 그리드의 모든 기능을 사용자 지정할 수 있습니다.

아래 단계에서는 그리드의 그룹화 스타일링을 사용자 지정하는 과정을 살펴봅니다.

### 전역 테마 가져오기

그룹화 기능의 사용자 지정을 시작하려면 모든 스타일링 함수와 믹스인이 들어 있는 `index` 파일을 가져와야 합니다.

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

### 사용자 지정 테마 정의하기

다음으로 <ApiLink kind="sass" module="themes" type="function-grid-theme" label="grid-theme" code={true} />을(를) 확장하고 원하는 대로 그룹화를 사용자 지정하는 데 필요한 매개변수를 받는 새 테마를 만드십시오. 그룹화 기능에서 사용되므로 <ApiLink kind="sass" module="themes" type="function-chip-theme" label="chip-theme" code={true} />도 확장해야 합니다.

```scss

$custom-theme: grid-theme(
  $group-row-background: #494949,
  $group-row-selected-background: #383838,
  $group-label-column-name-text: #f8f8f8,
  $group-label-icon: #ffcd0f,
  $group-label-text: #f8f8f8,
  $group-count-background: #ffcd0f,
  $group-count-text-color: #000,
  $expand-icon-color: #ffcd0f,
  $expand-icon-hover-color: rgb(223, 181, 13),
  $cell-active-border-color: #ffcd0f,
  $row-selected-background: #fff6d3,
  $row-selected-text-color: #000,
  $drop-indicator-color: #ffcd0f
);

/* Chip theme will style the chips in the Group By area */
$custom-chips-theme: chip-theme(
  $background: #494949,
  $text-color: #f8f8f8,
  $hover-text-color: #e7e7e7
);
```

### 사용자 지정 색상 팔레트 정의하기

앞서 설명한 방식에서는 색상 값이 하드코딩되어 있었습니다. 대신 <ApiLink kind="sass" module="palettes" type="function-palette" label="palette" code={true} />과 <ApiLink kind="sass" module="palettes" type="function-color" label="color" code={true} /> 함수를 사용하면 더 큰 유연성을 얻을 수 있습니다.
`palette`은(는) 제공된 기본, 보조, 표면 색상을 기준으로 색상 팔레트를 생성합니다.  

```scss
$black-color: #292826;
$yellow-color: #ffcd0f;
$grey-color: #efefef;

$custom-palette: palette(
  $primary: $black-color, 
  $secondary: $yellow-color, 
  $surface: $grey-color
);
```

사용자 지정 팔레트가 생성된 후에는 `color` 함수를 사용하여 기본 색상과 보조 색상의 다양한 변형을 얻을 수 있습니다.
  
```scss
$custom-theme: grid-theme(
  $group-row-background: color($custom-palette, "primary", 300),
  $group-row-selected-background: color($custom-palette, "primary", 400),
  $group-label-column-name-text:contrast-color($custom-palette, "primary", 500),
  $group-label-icon: color($custom-palette, "secondary", 600),
  $group-label-text:contrast-color($custom-palette, "primary", 500),
  $group-count-background: color($custom-palette, "secondary", 600),
  $group-count-text-color: color($custom-palette, "primary", 400),
  $expand-icon-color: color($custom-palette, "secondary", 600),
  $expand-icon-hover-color: color($custom-palette, "secondary", 300),
  $cell-active-border-color: color($custom-palette, "secondary", 600)
);

$custom-chips-theme: chip-theme(
  $background: color($custom-palette, "primary", 300),
  $text-color:contrast-color($custom-palette, "primary", 500),
  $hover-text-color:contrast-color($custom-palette, "primary", 600)
);
```

### 사용자 지정 스키마 정의하기

더 나아가 [**스키마**](/themes/sass/schemas)의 모든 장점을 가진 유연한 구조를 만들 수 있습니다. **스키마**는 테마의 레시피입니다.
모든 컴포넌트에 제공되는 두 개의 사전 정의된 스키마 중 하나를 확장하십시오. 이 경우에는 <ApiLink kind="sass" module="schemas" type="variable-light-material-schema" label="light-grid" code={true} />를 사용하겠습니다.

```scss
$custom-grid-schema: extend(
  map.get('grid', $light-material-schema),
  (
    group-row-background: (color:('secondary', 100)),
    group-row-selected-background: (color:('primary', 400)),
    group-label-column-name-text: (color:('primary', 600)),
    group-label-icon: (color:('primary', 600)),
    group-label-text: (color:('secondary', 700)),
    group-count-background: (color:('primary', 600)),
    group-count-text-color: (color:('secondary', 400)),
    expand-icon-color: (color:('primary', 600)),
    expand-icon-hover-color: (color:('primary', 400))
  )
);
```

사용자 지정 스키마를 적용하려면 (<ApiLink kind="sass" module="schemas" type="variable-light-material-schema" label="light" code={true} /> 또는 <ApiLink kind="sass" module="schemas" type="variable-dark-material-schema" label="dark" code={true} />) 전역을 확장해야 합니다. 전체 과정은 사용자 지정 스키마를 컴포넌트에 제공하고, 그 이후에 해당 컴포넌트 테마에 추가하는 것입니다.

```scss
$my-custom-schema: extend(
  $light-material-schema, 
  ( 
    grid: $custom-grid-schema
  )
);

$custom-theme: grid-theme(
  $palette: $custom-palette,
  $schema: $my-custom-schema
);
```

### 사용자 지정 테마 적용하기

테마를 적용하는 가장 쉬운 방법은 전역 스타일 파일에 `sass` `@include` 문을 추가하는 것입니다:

```scss
:host {
  @include tokens($custom-theme);
  @include tokens($custom-chips-theme);
}
```

### 범위가 지정된 컴포넌트 테마

사용자 지정 테마가 특정 컴포넌트에만 영향을 주도록 하려면, 방금 정의한 모든 스타일을 전역 스타일 파일에서 사용자 지정 컴포넌트의 스타일 파일로 옮길 수 있습니다(`index` 파일의 import 포함).

이렇게 하면 Angular의 [ViewEncapsulation](https://angular.io/api/core/Component#encapsulation) 덕분에 스타일이 사용자 지정 컴포넌트에만 적용됩니다.

그룹화된 칩이 렌더링되는 위치에 따라 Emulated View Encapsulation 때문에 칩의 토큰 선언이 일치하지 않을 수 있습니다. 칩 테마가 적용되지 않으면, 그 중첩된 테마에 `::ng-deep`을(를) 사용하거나 전역 스타일시트로 옮기십시오:

```scss
:host {
  @include tokens($custom-theme);

  ::ng-deep {
    @include tokens($custom-chips-theme);
  }
}
```
