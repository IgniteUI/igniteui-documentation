# Angular Grid 편집 및 검증

Grid의 편집 기능은 셀이나 행을 편집할 때 사용자 입력에 대한 내장 검증 메커니즘을 노출합니다. 이는 잘 알려진 기능과 더 쉽게 통합할 수 있도록 [Angular 폼 검증](https://angular.io/guide/form-validation) 기능을 확장합니다. 편집기의 상태가 바뀌면, 편집된 셀에 시각적 표시가 적용됩니다.

## 구성

### 템플릿 기반 구성으로 설정하기

`IgxColumn`에서 직접 작동하도록 일부 Angular Forms 검증 디렉티브를 확장했습니다. 같은 검증기들은 `igx-column`에서 선언적으로 설정할 수 있는 속성으로도 제공됩니다. 다음 검증기들은 기본으로 지원됩니다:

- required
- min
- max
- email
- minlength
- maxlength
- pattern

열 입력이 설정되어 있고 값이 이메일 형식으로 서식이 지정되는지 검증하려면, 관련 디렉티브를 사용할 수 있습니다:

```html
<igx-column [field]="email" [header]="User E-mail" required email></igx-column>
```

다음 샘플은 Grid에서 미리 만들어진 `required`, `email` 및 `min` 검증 디렉티브를 사용하는 방법을 보여 줍니다.

<Sample src="/grid/grid-validator-service" height={600} alt="Angular Grid 검증 기본 예제" />

### 반응형 폼으로 설정하기

`formGroupCreated` 이벤트를 통해 행/셀의 편집이 시작될 때 검증에 사용될 `FormGroup`을(를) 노출합니다. 관련 필드에 자신의 검증기를 추가하여 수정할 수 있습니다:

```html
<igx-grid (formGroupCreated)='formCreateHandler($event)' ...>
```

```ts
    public formCreateHandler(args: IGridFormGroupCreatedEventArgs) {
        const formGroup = args.formGroup;
        const orderDateRecord = formGroup.get('OrderDate');
        const requiredDateRecord = formGroup.get('RequiredDate');
        const shippedDateRecord = formGroup.get('ShippedDate');

        orderDateRecord.addValidators(this.futureDateValidator());
        requiredDateRecord.addValidators(this.pastDateValidator());
        shippedDateRecord.addValidators(this.pastDateValidator());
    }
```

직접 검증 함수를 작성하거나, [내장 Angular 검증 함수](https://angular.io/guide/form-validation#built-in-validator-functions) 중 하나를 사용할 수 있습니다.

## 검증 서비스 API

그리드는 <ApiLink type="Grid" member="validation" label="validation" /> 속성을 통해 검증 서비스를 노출합니다.
이 서비스는 다음 공개 API를 가지고 있습니다:

- <ApiLink type="GridValidationService" member="valid" label="valid" /> - 그리드 검증 상태가 유효한지 여부를 반환합니다.
- <ApiLink type="GridValidationService" member="getInvalid" label="getInvalid" /> - 잘못된 상태의 레코드를 반환합니다.
- <ApiLink type="GridValidationService" member="clear" label="clear" /> - id로 레코드의 상태를 지우고, id가 제공되지 않으면 모든 상태를 지웁니다.
- <ApiLink type="GridValidationService" member="markAsTouched" label="markAsTouched" /> - 관련 레코드/필드를 touched로 표시합니다.

잘못된 상태는 검증 규칙에 따라 그 안의 검증 오류가 수정되거나 지워질 때까지 유지됩니다.

## 검증 트리거

다음 상황에서 검증이 트리거됩니다:

- 그리드의 <ApiLink type="Grid" member="validationTrigger" label="validationTrigger" />을(를) 기반으로 하는 셀 편집기에서 편집하는 동안. 편집기에 입력하는 동안 `change`에서, 또는 편집기가 포커스를 잃거나 닫힐 때 `blur`에서.
- API를 통해 셀/행을 업데이트할 때 - <ApiLink type="Grid" member="updateRow" label="updateRow" />, <ApiLink type="Grid" member="updateCell" label="updateCell" /> 등.
- 일괄 편집을 사용하고 트랜잭션 서비스의 <ApiLink type="TransactionService" member="undo" label="undo" />/<ApiLink type="TransactionService" member="redo" label="redo" /> API를 사용할 때.

<DocsAside type="info">
사용자 입력이나 편집 API를 통해 편집되지 않은 레코드에 대해서는 검증이 트리거되지 않습니다. 셀의 시각적 표시는 관련 입력이 touched로 간주되는 경우에만 나타납니다. 이는 사용자 상호 작용이나 검증 서비스의 `markAsTouched` API를 통해 결정됩니다.
</DocsAside>

### 오류 툴팁 트리거

Grid의 <ApiLink type="Grid" member="validationTooltipTrigger" label="validationTooltipTrigger" /> 입력은 잘못된 셀의 오류 툴팁이 언제 표시되는지를 제어합니다. 검증이 실행되는 시점은 바뀌지 않습니다.

| 값 | 오류 툴팁이 표시되는 시점 |
| --- | --- |
| `active`(기본값) | 잘못된 셀이 활성 상태가 되거나, 활성 셀이 잘못된 상태가 되거나, 사용자가 오류 아이콘 위에 마우스를 올려 놓고 있는 동안. |
| `hover` | 사용자가 오류 아이콘 위에 마우스를 올려 놓고 있는 동안에만. |

사용자가 편집하거나 이동하는 동안 툴팁이 그리드 콘텐츠를 가리지 않도록 하려면 `hover`을(를) 사용하십시오. 잘못된 셀에는 여전히 오류 아이콘과 잘못된 스타일이 표시됩니다:

```html
<igx-grid [data]="data" validationTooltipTrigger="hover"></igx-grid>
```

## Angular Grid 검증 사용자 지정 옵션

### 사용자 지정 검증기 설정하기

템플릿의 `<igx-column>`에 사용할 자신만의 검증 디렉티브를 정의할 수 있습니다.

```ts
@Directive({
    selector: '[phoneFormat]',
    providers: [{ provide: NG_VALIDATORS, useExisting: PhoneFormatDirective, multi: true }]
})
export class PhoneFormatDirective extends Validators {
    @Input('phoneFormat')
    public phoneFormatString = '';

    public validate(control: AbstractControl): ValidationErrors | null {
        return this.phoneFormatString ? phoneFormatValidator(new RegExp(this.phoneFormatString, 'i'))(control)
            : null;
    }
}
```

정의하고 앱 모듈에 추가한 후에는, 그리드의 특정 열에 선언적으로 설정할 수 있습니다:

```html
<igx-column phoneFormat="\+\d{1}\-(?!0)(\d{3})\-(\d{3})\-(\d{4})\b" ...>
```

### 기본 오류 템플릿 변경하기

셀이 잘못된 상태가 되었을 때 오류 툴팁에 표시될 자신만의 사용자 지정 오류 템플릿을 정의할 수 있습니다.
이는 자신만의 사용자 지정 오류 메시지를 추가하거나, 그 밖의 방식으로 메시지의 모양이나 내용을 바꾸고 싶은 시나리오에서 유용합니다.

```html
<igx-column ... >
  <ng-template igxCellValidationError let-cell='cell' let-defaultErr="defaultErrorTemplate">
      <ng-container *ngTemplateOutlet="defaultErr">
      </ng-container>
      @if (cell.validation.errors?.['phoneFormat']) {
        <div>
          Please enter correct phone format
        </div>
      }
  </ng-template>
</igx-column>
```

### 잘못된 상태에서 편집 모드를 벗어나는 것 막기

경우에 따라 데이터에 잘못된 값을 제출하는 것을 허용하지 않으려 할 수 있습니다.
그런 시나리오에서는 <ApiLink type="Grid" member="cellEdit" label="cellEdit" /> 또는 <ApiLink type="Grid" member="rowEdit" label="rowEdit" /> 이벤트를 사용하고, 새 값이 잘못된 경우 이벤트를 취소할 수 있습니다.
두 이벤트의 인수 모두 <ApiLink kind="interface" type="IGridEditEventArgs" member="valid" /> 속성을 가지고 있으며 그에 따라 취소할 수 있습니다. 이것이 어떻게 사용되는지는 [교차 필드 검증 예제](#교차-필드-예제)에서 볼 수 있습니다

```html
<igx-grid (cellEdit)='cellEdit($event)' ...>
```

```ts
public cellEdit(evt) {
  if (!evt.valid) {
    evt.cancel = true;
  }
}
```

## 교차 필드 검증

일부 시나리오에서는 한 필드의 검증이 레코드의 다른 필드 값에 따라 달라질 수 있습니다.
그런 경우 사용자 지정 검증기를 사용하여, 공유하는 `FormGroup`을(를) 통해 레코드의 값을 비교할 수 있습니다.

아래 샘플은 같은 레코드의 서로 다른 필드 사이의 교차 필드 검증을 보여 줍니다. 현재 날짜와 비교하여 날짜의 유효성을 검사하고, 레코드의 활성 날짜와 생성 날짜 사이를 검사하며, 각 직원의 수주/실주 비율도 검사합니다. 모든 오류는 레코드가 잘못되었음을 보여 주고 관련 오류를 표시하는 별도의 고정 열에 모입니다.

다음 코드 줄은 비교를 포함하고 그에 따라 관련 오류를 설정하는 교차 필드 검증 함수를 보여 줍니다.

```ts
private rowValidator(): ValidatorFn {
    return (formGroup: FormGroup): ValidationErrors | null => {
        let returnObject = {};
        const createdOnRecord = formGroup.get('created_on');
        const lastActiveRecord = formGroup.get('last_activity');
        const winControl = formGroup.get('deals_won');
        const loseControl = formGroup.get('deals_lost');
        const actualSalesControl = formGroup.get('actual_sales');

        // Validate dates
        const curDate = new Date();
        if (new Date(createdOnRecord.value) > curDate) {
            // The created on date shouldn't be greater than current date.
            returnObject['createdInvalid'] =  true;
        }
        if (new Date(lastActiveRecord.value) > curDate) {
            // The last active date shouldn't be greater than current date.
            returnObject['lastActiveInvalid'] = true;
        }
        if (new Date(createdOnRecord.value) > new Date(lastActiveRecord.value)) {
            // The created on date shouldn't be greater than last active date.
            returnObject['createdLastActiveInvalid'] = true;
        }
        
        // Validate deals
        const dealsRatio = this.calculateDealsRatio(winControl.value, loseControl.value);
        if (actualSalesControl.value === 0 && dealsRatio > 0) {
            // If the actual sales value is 0 but there are deals made.
            returnObject['salesZero'] = true;
        }
        if (actualSalesControl.value > 0 && dealsRatio === 0) {
            // If the deals ratio based on deals won is 0 but the actual sales is bigger than 0.
            returnObject['salesNotZero'] = true;
        }
        
        return returnObject;
    };
}

public calculateDealsRatio(dealsWon, dealsLost) {
    if (dealsLost === 0) return dealsWon + 1;
    return Math.round(dealsWon / dealsLost * 100) / 100;
}
```

교차 필드 검증기는 편집 모드에 들어갈 때 각 행에 대해 새 `formGroup`을(를) 반환하는 <ApiLink type="Grid" member="formGroupCreated" label="formGroupCreated" /> 이벤트의 행 `formGroup`에 추가할 수 있습니다:

```html
<igx-grid #grid1 [data]="transactionData" [width]="'100%'" [height]="'480px'" [autoGenerate]="false" 
        [batchEditing]="true" [rowEditable]="true" [primaryKey]="'id'"
        (formGroupCreated)='formCreateHandler($event)'>
    <!-- ... -->
</igx-grid>

```

```typescript
public formCreateHandler(evt: IGridFormGroupCreatedEventArgs) {
    evt.formGroup.addValidators(this.rowValidator());
}
```

서로 다른 오류들은 모든 오류를 하나의 툴팁에 합친 템플릿 셀에 표시됩니다. 행의 유효 상태에 따라 서로 다른 아이콘이 표시됩니다:

```html
<igx-column field="row_valid" header=" " [editable]="false" [pinned]="true" [width]="'50px'">
    <ng-template igxCell let-cell="cell">
        @if (isRowValid(cell)) {
            <div [igxTooltipTarget]="tooltipRef"  style="margin-right: '-10px';">
                <img width="18" src="assets/images/grid/active.png"/>
            </div>
        } @else {
            <div [igxTooltipTarget]="tooltipRef" style="margin-right: '-10px';">
                <img width="18" src="assets/images/grid/expired.png"/>
            </div>
        }
        <div #tooltipRef="tooltip" igxTooltip [style.width]="'max-content'">
            <div *ngFor="let message of stateMessage(cell)">
                {{message}}
            </div>
        </div>
    </ng-template>
</igx-column>
```

오류 메시지는 `stateMessage` 함수에 모입니다. 이 함수는 각 셀의 오류를 모으고, 각 열이 템플릿화된 폼 검증을 가질 수 있으므로, 그다음 사용자 지정 `rowValidator`에서 나온 행 자체의 오류를 확인합니다.

```typescript
public stateMessage(cell: CellType) {
    const messages = [];
    const row = cell.row;
    const cellValidationErrors = row.cells.filter(x => !!x.validation.errors);
    cellValidationErrors.forEach(cell => {
        if (cell.validation.errors) {
            if (cell.validation.errors.required) {
                messages.push(`The \`${cell.column.header}\` column is required.`);
            }
            // Other cell errors ...
        }
    });

    if (row.validation.errors?.createdInvalid) {
        messages.push(`The \`Date of Registration\` date cannot be in the future.`);
    }
    // Other cross-field errors...

    return messages;
}

```

## 스타일링

[Ignite UI for Angular 테마 라이브러리](/themes)를 사용하면 편집 중의 기본 검증 스타일을 바꿀 수 있습니다.

아래 예제에서는 툴팁으로 나타나는 검증 메시지용으로 노출된 템플릿을 사용하고, 오류 색상을 재정의하여 검증의 기본 모양을 바꿉니다.
또한 잘못된 행의 배경을 스타일링하여 더 두드러지게 만들겠습니다.

### 테마 가져오기

스타일을 지정하고 CSS 변수에 접근하는 가장 쉬운 방법은 `app`의 전역 스타일 파일(보통 `styles.scss`)에 스타일을 정의하는 것입니다.
가장 먼저 해야 할 일은 `themes/index` 파일을 가져오는 것입니다. 이를 통해 Ignite UI for Angular Sass 프레임워크의 강력한 도구에 접근할 수 있습니다:

```scss
@use "igniteui-angular/theming" as *;

// IMPORTANT: Prior to Ignite UI for Angular version 13 use:
// @import '~igniteui-angular/lib/core/styles/themes/index';
```

### 스타일 포함하기

오류 색상을 바꾸려면 CSS 변수 `--ig-error-500`을(를) 사용할 수 있습니다:

```scss
--ig-error-500: 34, 80%, 63%;
```

### 사용자 지정 템플릿

기본 오류 템플릿을 바꾸면 사용자 지정 클래스와 스타일을 설정할 수 있습니다:

```html
<ng-template igxCellValidationError let-cell='cell' let-defaultErr='defaultErrorTemplate'>
  <div class="validator-container">
    <ng-container *ngTemplateOutlet="defaultErr">
    </ng-container>
  </div>
</ng-template>
```

### 잘못된 행과 셀의 스타일

행과 셀은 행 또는 셀이 잘못되었는지, 그리고 어떤 종류의 오류가 활성 상태인지 개발자가 알 수 있도록 API를 제공합니다.

```ts
public rowStyles = {
    background: (row: RowType) => row.validation.status === 'INVALID' ? '#FF000033' : '#00000000'
};
public cellStyles = {
  'invalid-cell': (rowData, columnKey) => {
    const pKey = this.grid.primaryKey;
    const cell = this.grid.getCellByKey(rowData[pKey], columnKey);
    return cell && cell.validation.status === 'INVALID';
  }
}
```

```html
<igx-grid [rowStyles]="rowStyles">
  <igx-column field="ReorderLevel" header="Reorder Level" required [cellClasses]="cellStyles">
  </igx-column>
</igx-grid>
```
