# Angular Hierarchical Grid에 행 추가하기

Hierarchical Grid은(는) 인라인 행 추가를 통해 데이터를 조작하는 편리한 방법과, Angular CRUD 작업을 위한 강력한 API를 제공합니다. 그리드의 템플릿에 편집 작업이 활성화된 [Action Strip](/action-strip) 컴포넌트를 추가하고, 행 위에 마우스를 올린 다음 제공된 버튼을 사용하거나 <kbd>ALT</kbd> + <kbd>+</kbd>를 누르면 행 추가 UI가 나타납니다.

## Angular Hierarchical Grid 행 추가 예제

다음 샘플은 Hierarchical Grid에서 기본 행 추가를 활성화하는 방법을 보여 줍니다. 셀 값을 바꾼 다음 같은 행의 다른 셀을 클릭하거나 그쪽으로 이동해도, **완료** 버튼으로 확인하거나 **취소** 버튼으로 버리기 전까지는 행 값이 업데이트되지 않습니다.

## 행 추가 사용법

시작하려면 **app.module.ts** 파일에서 `IgxHierarchicalGridModule`을(를) 가져오십시오:

```typescript
// app.module.ts

...
import { IgxHierarchicalGridModule } from 'igniteui-angular';

@NgModule({
    ...
    imports: [..., IgxHierarchicalGridModule],
    ...
})
export class AppModule {}
```

그다음 바인딩된 데이터 소스와 <ApiLink type="HierarchicalGrid" member="rowEditable" label="rowEditable" />을(를) true로 설정하여 Hierarchical Grid을(를) 정의하고, 편집 작업이 활성화된 [Action Strip](../action-strip.mdx) 컴포넌트를 추가합니다. <ApiLink type="GridEditingActions" member="addRow" label="addRow" /> 입력은 행 추가 UI를 나타나게 하는 버튼의 가시성을 제어합니다.

```html
<igx-hierarchical-grid igxPreventDocumentScroll [data]="localdata"
    [autoGenerate]="false" [primaryKey]="'Debut'" [rowEditable]="true">
    <igx-column field="Artist" [dataType]="'string'"></igx-column>
    <igx-column field="HasGrammyAward" header="Has Grammy Award?" [dataType]="'boolean'">
    </igx-column>
    <igx-column field="Debut" dataType="number"></igx-column>
    <igx-column field="GrammyNominations" header="Grammy Nominations" dataType="number"></igx-column>
    <igx-column field="GrammyAwards" header="Grammy Awards" dataType="number"></igx-column>

    <igx-action-strip #actionstrip1>
        <igx-grid-editing-actions [addRow]="true"></igx-grid-editing-actions>
    </igx-action-strip>

    <igx-row-island [key]="'Albums'" [autoGenerate]="false" [primaryKey]="'USBillboard200'" [rowEditable]="true">
        <igx-column field="Album" [dataType]="'string'"></igx-column>
        <igx-column field="LaunchDate" header="Launch Date" [dataType]="'date'"></igx-column>
        <igx-column field="BillboardReview" header="Billboard Review" dataType="number"></igx-column>
        <igx-column field="USBillboard200" header="US Billboard 200" dataType="number"></igx-column>
        <igx-row-island [key]="'Songs'" [autoGenerate]="false" [primaryKey]="'Number'" [rowEditable]="true">
            <igx-column field="Number" header="No." dataType="number"></igx-column>
            <igx-column field="Title" [dataType]="'string'"></igx-column>
            <igx-column field="Released" [dataType]="'date'"></igx-column>
            <igx-column field="Genre" [dataType]="'string'"></igx-column>

            <igx-action-strip #actionstrip3>
                <igx-grid-editing-actions [addRow]="true"></igx-grid-editing-actions>
            </igx-action-strip>

        </igx-row-island>

        <igx-action-strip #actionstrip2>
            <igx-grid-editing-actions [addRow]="true"></igx-grid-editing-actions>
        </igx-action-strip>
    </igx-row-island>
</igx-hierarchical-grid>
```

<DocsAside type="info">
행 추가 작업에는 기본 키를 설정하는 것이 필수입니다.
</DocsAside>

<DocsAside type="info">
기본 키를 제외한 모든 열은 기본적으로 행 추가 UI에서 편집할 수 있습니다. 특정 열의 편집을 비활성화하려면 그 열의 <ApiLink type="Column" member="editable" label="editable" /> 입력을 `false`(으)로 설정해야 합니다.
</DocsAside>

<DocsAside type="info">
행 추가 버튼의 가시성을 제어하는 IgxGridEditingActions 입력은, 버튼이 어떤 레코드에 대해 보일지 세밀하게 조정하기 위해 action strip 컨텍스트(<ApiLink type="RowType" kind="interface" /> 유형)를 사용할 수 있습니다.
</DocsAside>

내부 <ApiLink type="BaseTransactionService" />은(는) Hierarchical Grid에 자동으로 제공됩니다. 행 상태가 제출되거나 취소될 때까지 보류 중인 셀 변경 사항을 보관합니다.

## 프로그래밍 방식으로 행 추가 시작하기

Hierarchical Grid은(는) 두 가지 서로 다른 공개 메서드를 사용하여 프로그래밍 방식으로 행 추가 UI를 나타나게 할 수 있습니다. 하나는 UI가 나타날 아래의 행을 지정하기 위한 행 ID를 받고, 다른 하나는 인덱스로 작동합니다. 이 메서드들을 사용하여 현재 데이터 뷰 안 어디에서든 UI를 나타나게 할 수 있습니다. 페이지를 바꾸거나 예를 들어 필터링으로 숨겨진 행을 지정하는 것은 지원되지 않습니다.

`beginAddRowById`을(를) 사용하려면 작업의 컨텍스트로 사용할 행을 rowID(PK)로 지정해야 합니다. 그러면 메서드는 최종 사용자가 지정된 행의 행 추가 action strip 버튼을 클릭한 것처럼 동작하여, 그 아래에 UI를 나타나게 합니다. 첫 번째 매개변수로 `null`을(를) 전달하면 UI가 그리드의 가장 첫 행으로 나타나게 할 수도 있습니다.

```typescript
this.grid.beginAddRowById('ALFKI');  // spawns the add row UI under the row with PK 'ALFKI'
this.grid.beginAddRowById(null);     // spawns the add row UI as the first record
```

`beginAddRowByIndex` 메서드도 비슷하게 작동하지만, UI가 나타날 _위치_ 인덱스를 지정해야 합니다. 허용되는 값은 0부터 데이터 뷰 크기 - 1 사이입니다.

```typescript
this.grid.beginAddRowByIndex(10);   // spawns the add row UI at index 10
this.grid.beginAddRowByIndex(0);    // spawns the add row UI as the first record
```

## 위치 지정

- 기본 위치의 행 추가 UI는 최종 사용자가 행 추가 버튼을 클릭한 행의 아래에 나타납니다.

- Hierarchical Grid은(는) 행 추가 UI가 완전히 보이도록 자동으로 스크롤합니다.

- 행 추가 UI의 오버레이는 스크롤하는 동안 위치를 유지합니다.

## 동작

행 추가 UI는 행 편집 UI와 같은 동작을 가집니다. 최종 사용자에게 일관된 편집 경험을 제공하도록 설계되었기 때문입니다. 자세한 내용은 [Hierarchical Grid 행 편집](/hierarchicalgrid/row-editing) 주제를 참조하십시오.

행 추가 UI를 통해 새 행을 추가한 후, 그 위치 및/또는 가시성은 Hierarchical Grid의 정렬, 필터링, 그룹화 상태에 따라 결정됩니다. 이러한 상태가 하나도 적용되지 않은 Hierarchical Grid에서는 마지막 레코드로 나타납니다. 최종 사용자가 보이지 않는 위치에 있는 Hierarchical Grid을(를) 그 위치로 스크롤할 수 있는 버튼이 들어 있는 스낵바가 잠깐 표시됩니다.

## 키보드 탐색

- <kbd>ALT</kbd> + <kbd>+</kbd> - 행 추가를 위해 편집 모드로 들어갑니다

- <kbd>ESC</kbd>는 어떤 변경 사항도 제출하지 않고 행 추가 모드를 벗어납니다

- <kbd>TAB</kbd>은 포커스를 행의 편집 가능한 한 셀에서 다음 셀로 옮기고, 가장 오른쪽 편집 가능한 셀에서는 CANCEL 및 DONE 버튼으로 옮깁니다. DONE 버튼에서의 탐색은 현재 편집 중인 행의 가장 왼쪽 편집 가능한 셀로 이동합니다.

## 기능 통합

- Hierarchical Grid의 데이터 뷰가 수정되면 모든 행 추가 작업이 중지됩니다. 최종 사용자가 한 변경 사항은 제출됩니다. 데이터 뷰를 바꾸는 작업에는 정렬, 그룹화, 필터링, 페이징 등이 포함되며, 이에 국한되지 않습니다.

- 요약은 행 추가 작업이 끝난 후 업데이트됩니다. 정렬, 필터링 등 다른 데이터 뷰 의존 기능도 마찬가지입니다.

- Hierarchical Grid에 UI를 나타나게 할 때, 최종 사용자가 행 추가 버튼을 클릭한 행에 대해 현재 펼쳐져 있는 하위 레이아웃은 접힙니다.

## 행 추가 오버레이 사용자 지정하기

### 텍스트 사용자 지정하기

`igxRowAddTextDirective`을(를) 사용하면 행 추가 오버레이의 텍스트를 사용자 지정할 수 있습니다.

```html
<ng-template igxRowAddText>
 Adding Row
</ng-template>
 ```

### 버튼 사용자 지정하기

`igxRowEditActionsDirective`을(를) 사용하면 행 편집 오버레이의 버튼을 사용자 지정할 수 있습니다.
버튼이 키보드 탐색의 일부가 되기를 원한다면, 각 버튼에 `igxRowEditTabStopDirective`를 설정해야 합니다.

 ```html
 <ng-template igxRowEditActions let-endRowEdit>
 <button igxButton igxRowEditTabStop (click)="endRowEdit(false)">Cancel</button>
 <button igxButton igxRowEditTabStop (click)="endRowEdit(true)">Apply</button>
</ng-template>
 ```

<DocsAside type="info">
`igxRowEditActions` 디렉티브를 사용하면 편집 오버레이와 추가 오버레이 버튼의 편집 작업이 모두 바뀝니다.
</DocsAside>

## 원격 시나리오

대부분의 원격 데이터 시나리오에서는 기본 키 할당이 생성 서버 요청에서 이루어집니다. 이 경우 클라이언트에서 추가된 레코드는 서버 데이터베이스에 저장되기 전까지 최종 기본 키 값을 가지지 않습니다. 이때 Hierarchical Grid에서 이 업데이트를 처리하는 권장 방법은 다음과 같습니다:

- Hierarchical Grid이(가) 트랜잭션을 사용하지 않는 경우.

    생성 요청이 성공적으로 완료되어 추가된 레코드 데이터를 반환하면, 로컬 데이터 레코드 인스턴스에서 그 레코드의 id를 교체할 수 있습니다.

- Hierarchical Grid이(가) 트랜잭션을 사용하는 경우.

    생성 요청 또는 일괄 업데이트 요청이 성공적으로 완료되어 추가된 레코드 인스턴스(DB가 생성한 id 포함)를 반환하면, 관련된 ADD 트랜잭션을 <ApiLink kind="interface" type="TransactionService" member="clear" /> API 메서드를 사용하여 트랜잭션 로그에서 지워야 합니다. 로컬 트랜잭션에는 생성된 id 필드가 있으며, 이는 데이터베이스에서 만든 것과 다를 수 있으므로 지워야 하기 때문입니다. 그다음 응답으로 전달된 레코드를 로컬 데이터 인스턴스에 추가할 수 있습니다.

이렇게 하면 원격에서 생성된 id가 항상 로컬 데이터에 반영되고, 이후의 업데이트/삭제 작업이 올바른 레코드 id를 대상으로 하게 됩니다.
