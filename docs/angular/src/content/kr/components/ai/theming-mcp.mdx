# Ignite UI Theming MCP

<p class="highlight">Ignite UI Theming MCP는 AI 어시스턴트가 Ignite UI 애플리케이션을 위해 운영 환경에서 바로 사용할 수 있는 테마 코드를 생성할 수 있도록 하는 <a href="https://modelcontextprotocol.io/" target="_blank">Model Context Protocol</a>(MCP) 서버입니다. MCP는 AI 어시스턴트가 외부 서버가 제공하는 전문 도구를 호출할 수 있게 하는 공개 표준입니다. Ignite UI Theming MCP를 편집기 또는 데스크톱 AI 클라이언트에 연결하고, 생성하려는 테마, 팔레트 또는 컴포넌트 재정의를 설명하십시오.</p>

<igc-divider></igc-divider>

## 개요

Ignite UI Theming MCP 서버는 AI 어시스턴트에 정확한 테마 코드를 생성하는 데 필요한 지식과 도구를 제공합니다. 여기에는 적절한 명도 단계가 생성된 팔레트, 타이포그래피, 고도, 컴포넌트 디자인 토큰 재정의 등이 포함됩니다.

이 서버는 Ignite UI의 네 가지 디자인 시스템(**Material**, **Bootstrap**, **Fluent**, **Indigo**)을 밝은 변형과 어두운 변형 모두에서 지원합니다. 이 가이드는 Angular에 초점을 맞추지만, MCP 서버는 Infragistics의 모든 Ignite UI 컴포넌트 라이브러리와도 함께 작동합니다. `detect_platform` 도구는 프로젝트 프레임워크를 식별하고 올바른 import 경로와 선택기를 자동으로 선택합니다. `package.json`이 없는 Blazor 프로젝트의 경우에는 `generic`을 반환합니다. AI에 명시적으로 알려 주십시오: _"Blazor 플랫폼을 사용하십시오."_

대부분의 도구는 **Sass** 또는 **CSS** 출력을 생성할 수 있습니다. Sass 출력이 기본값이며 `igniteui-theming` Sass 모듈과 통합됩니다. CSS 출력은 바로 사용할 수 있는 CSS 사용자 지정 속성을 생성하며, **로컬 Sass 도구 체인 없이** 사용할 수 있습니다. 서버가 대신 컴파일해 줍니다.

Ignite UI Theming MCP는 Ignite UI CLI MCP와 함께 작동합니다. 실제로 Theming MCP는 팔레트, 테마, 토큰, 타이포그래피, 고도 및 스타일링 작업 흐름을 담당하고, CLI MCP는 프로젝트 생성, 프로젝트 수정, 컴포넌트 작업 및 문서 중심 작업을 담당합니다. 대부분의 팀은 같은 AI 클라이언트에 두 서버를 모두 연결하기를 원합니다.

**연결한 후 시도해 볼 예제 프롬프트:**

> _"primary #2563eb와 코랄색 secondary #f97316을 사용하여 Angular 앱을 위한 완전한 Material Design 어두운 테마를 만들어 주세요."_

> _"button 컴포넌트에 사용할 수 있는 디자인 토큰은 무엇입니까? 브랜드 보라색 #8b5cf6으로 사용자 지정해 주세요."_

> _"브랜드 가이드라인에는 모든 기본 명도 단계의 정확한 hex 값이 지정되어 있습니다. 그 명시적인 값으로 사용자 지정 팔레트를 만들어 주세요."_

> _"calendar 컴포넌트가 더 작은 간격을 사용하도록 해 주세요."_

## 사전 요구 사항

MCP 서버를 구성하기 전에 다음 항목을 준비하십시오:

- **Node.js**(v18 이상)가 설치되어 있어야 합니다. 서버를 시작하는 데 사용하는 `npx` 명령을 제공합니다.
- `package.json`의 종속성으로 **Ignite UI 패키지**가 나열된 프로젝트가 있어야 합니다.
- **MCP를 지원하는 AI 클라이언트**가 있어야 합니다. 예를 들어 GitHub Copilot이 포함된 VS Code, Cursor, Claude Desktop, Claude Code 또는 AI Assistant 플러그인이 설치된 JetBrains IDE가 있습니다.

Ignite UI Theming이 아직 설치되어 있지 않다면 다음을 실행하십시오:

```bash
npm install igniteui-theming
```

## 설정

MCP 서버는 `igniteui-theming` npm 패키지에 포함되어 있으며 `npx`를 통해 실행됩니다. 프로젝트에 이미 Ignite UI 패키지가 있다면 별도로 설치할 필요가 없습니다.

표준 실행 명령은 다음과 같습니다:

```bash
npx -y igniteui-theming igniteui-theming-mcp
```

<DocsAside type="info">
`-y` 플래그는 `npx`에게 패키지 다운로드 확인 메시지를 자동으로 승인하도록 지시하므로, 서버가 수동 개입 없이 시작될 수 있습니다.
</DocsAside>

### 버전 확인 방식

`igniteui-theming`은(는) `igniteui-angular`의 종속성이므로, `npm install` 이후 프로젝트의 `node_modules`에 이미 존재합니다. 위의 실행 명령을 실행하면 `npx`이(가) 로컬에 설치된 복사본을 감지하고 직접 실행합니다. 네트워크 요청은 이루어지지 않습니다. 따라서 MCP 서버 버전은 나머지 Ignite UI 패키지와 항상 동기화된 상태를 유지합니다.

프로젝트 바깥에서(또는 `npm install`을 실행하기 전에) 명령을 실행하면, `npx -y`은(는) 대신 npm에서 **최신** 버전을 임시 캐시로 내려받습니다. 서버는 여전히 시작되지만, 검사할 `package.json`이(가) 없으므로 `detect_platform`은(는) `generic`을(를) 반환합니다.

아래에서 사용 중인 AI 클라이언트를 선택하여 구체적인 구성 단계를 확인하십시오.

### VS Code

GitHub Copilot이 포함된 VS Code는 워크스페이스 수준 구성 파일을 통해 MCP 서버를 지원합니다. 프로젝트 루트에서 `.vscode/mcp.json`을 만들거나 편집하십시오:

```json
{
  "servers": {
    "igniteui-theming": {
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
    }
  }
}
```

저장한 후 GitHub Copilot 채팅 패널을 열고 **Agent** 모드로 전환하면 Ignite UI Theming 도구를 사용할 수 있습니다.

<DocsAside type="info">
VS Code의 MCP 지원에는 GitHub Copilot과 VS Code 1.99 이상이 필요합니다.
</DocsAside>

### Cursor

```json
{
  "mcpServers": {
    "igniteui-theming": {
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
    }
  }
}
```

새 Cursor 채팅 세션을 열면 서버가 자동으로 인식됩니다.

<DocsAside type="info">
Cursor의 **Settings → MCP**에서 MCP 서버를 전역으로 구성할 수도 있습니다.
</DocsAside>

### Claude Desktop

Claude Desktop 구성 파일에 서버를 추가하십시오:

- **macOS**: `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "igniteui-theming": {
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
    }
  }
}
```

저장한 후 Claude Desktop을 다시 시작하십시오. 채팅 입력 영역에 MCP 서버 표시기(슬라이더 아이콘)가 나타나면 MCP 도구가 활성화된 것입니다.

### Claude Code

Claude Code는 CLI와 프로젝트 범위 `.mcp.json` 파일을 통해 MCP 서버를 지원합니다. 구성을 팀과 공유하려면 프로젝트 루트에서 `.mcp.json`를 만들거나 편집하십시오:

```json
{
  "mcpServers": {
    "igniteui-theming": {
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
    }
  }
}
```

또는 로컬 환경에서만 명령줄을 통해 서버를 추가할 수도 있습니다:

```bash
claude mcp add igniteui-theming -- npx -y igniteui-theming igniteui-theming-mcp
```

Claude Code 안에서 `/mcp` 명령을 사용하여 서버가 연결되었는지 확인하십시오.

### JetBrains IDE

JetBrains AI Assistant는 IDE 설정을 통해 MCP 서버를 지원합니다:

1. **Settings**(macOS에서는 **Preferences**)를 엽니다.

2. **Tools → AI Assistant → Model Context Protocol (MCP)**로 이동합니다.

3. **+ Add**를 클릭하고 **As JSON**을 선택하거나 양식 필드를 사용합니다.

4. 다음 구성을 입력합니다:

    ```json
    {
      "mcpServers": {
        "igniteui-theming": {
          "command": "npx",
          "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
        }
      }
    }
    ```

5. **OK**를 클릭한 후 AI Assistant를 다시 시작하십시오.

<DocsAside type="info">
MCP 지원에는 JetBrains IDE에 AI Assistant 플러그인이 설치되어 활성화되어 있어야 합니다.
</DocsAside>

## 프로젝트 규칙으로 AI 동작 사용자 지정하기

이 섹션은 선택 사항입니다. AI가 테마 코드를 기존 코드베이스 규칙에 맞게 _어떻게_ 생성하는지 세밀하게 조정하려는 팀을 위한 내용입니다.

VS Code와 Cursor 같은 편집기에서는 AI 동작을 형성하는 프로젝트 수준 지침 파일을 제공할 수 있습니다. MCP 서버는 이미 AI에 _어떤 도구를 어떤 순서로 호출할지_ 알려 줍니다. 따라서 이를 반복할 필요는 없습니다. 대신 이 지침 파일에 **프로젝트의 디자인 결정, 코드 규칙 및 파일 구성**을 담으면, AI가 처음부터 코드베이스에 맞는 코드를 생성합니다.

### VS Code(`.github/copilot-instructions.md`)

```markdown
## Theming Conventions

### Sass Code Style
- Use `@use` / `@forward` - never `@import`.
- Extract repeated color values into Sass variables (e.g., `$brand-hover: #a78bfa`).
- Prefer setting primary design tokens over overriding many dependent tokens.
  For example, setting `$foreground` on a flat button automatically derives
  `$hover-background`, `$focus-background`, and `$active-background`.
- Keep component overrides scoped - use the component's default selector
  (e.g., `.igx-button--flat`) unless a narrower scope is needed.
```

### Cursor(`.cursor/rules/theming.mdc`)

```markdown
---
description: Ignite UI for Angular theming conventions
globs: ["**/*.scss", "**/styles/**"]
---

## Project Theming Rules

### Code conventions
- `@use` / `@forward` only - no `@import`.
- Extract shared colors into variables; do not repeat hex literals.
- Prefer primary tokens - let dependent tokens derive automatically.
- One component override per file. Name the file after the component.
- Comment every override with the design rationale.
- Never hard-code gray shades for text - use palette grays so dark mode works.
- For dark mode, only the palette changes. Component overrides stay the same.
```

<DocsAside type="info">
두 파일 모두 소스 제어에 커밋되므로, 모든 팀원이 수동 설정 없이 같은 AI 동작을 얻을 수 있습니다. 프로젝트에 맞게 브랜드 색상, 디자인 시스템 및 파일 경로를 조정하십시오.
</DocsAside>

## 사용 가능한 도구

MCP 서버는 여러분의 프롬프트에 따라 AI가 자동으로 사용하는 도구 집합을 제공합니다. 이 도구들을 직접 호출할 필요는 없습니다. 원하는 작업을 설명하기만 하면 됩니다.

현재 전체 도구 목록과 매개변수를 언제든지 확인하려면 AI 어시스턴트에 다음과 같이 질문하십시오:

> _"Ignite UI Theming MCP는 어떤 도구를 제공합니까?"_

각 도구에 대한 간단한 개요는 다음과 같습니다:

<DocsAside type="info">
팔레트를 생성할 때 서버는 표면 색상과 회색 색상 사이의 대비 비율을 WCAG 기준과 비교하여, 조합이 기준에 미치지 못하면 경고합니다. 테마 엔진 자체에 내장된 대비 동작은 [접근성](../themes/accessibility.mdx)을 참조하십시오.
</DocsAside>

| 도구 | 설명 |
|------|-------------|
| `detect_platform` | 프로젝트 프레임워크를 식별하고 올바른 import 경로와 선택기를 선택합니다. Angular, React 및 Web Components 프로젝트의 경우 `package.json`을 읽습니다. `package.json`이 없는 Blazor 프로젝트의 경우에는 `generic`을 반환합니다. AI에 명시적으로 알려 주십시오: _"Blazor 플랫폼을 사용하십시오."_ |
| `create_palette` | 기본 브랜드 색상에서 자동 명도 변형(50-900, A100-A700)이 포함된 색상 팔레트를 생성합니다. `output` 매개변수(`sass` 또는 `css`)와 스키마를 선택하는 `designSystem`를 받습니다. |
| `create_custom_palette` | 세부적인 팔레트 생성입니다. 자동 생성이 적합하지 않을 때 모든 명도 단계에 정확한 hex 값을 지정할 수 있습니다. |
| `create_typography` | 지정한 디자인 시스템에 대해 글꼴 패밀리와 타입 스케일을 설정합니다. |
| `create_elevations` | Material 또는 Indigo 디자인 시스템에 대해 box-shadow 고도 수준(0-24)을 구성합니다. |
| `create_theme` | 팔레트, 타이포그래피 및 고도를 포함한 완전한 테마를 한 번에 생성하며, `styles.scss`에 바로 포함할 수 있습니다. `designSystem`(`material`, `bootstrap`, `fluent` 또는 `indigo`) 및 `variant`(`light` 또는 `dark`)를 받습니다. |
| `set_size` | `--ig-size`을(를) 전역으로 또는 특정 컴포넌트(`small`, `medium` 또는 `large`)에 대해 설정합니다. |
| `set_spacing` | `--ig-spacing`을(를) 설정하고(선택적으로 인라인/블록 재정의 포함) 전역으로 또는 컴포넌트별로 설정합니다. |
| `set_roundness` | `--ig-radius-factor`(0 = 각진 모서리, 1 = 완전히 둥근 모서리)을(를) 전역으로 또는 컴포넌트별로 설정합니다. |
| `get_component_design_tokens` | 컴포넌트에 사용할 수 있는 모든 디자인 토큰을 반환합니다. `create_component_theme`을 호출하기 전에 항상 먼저 이 도구를 호출하십시오. |
| `create_component_theme` | 컴포넌트 토큰(색상, 테두리 등)을 사용자 지정하는 Sass 또는 CSS를 생성합니다. 올바른 스키마를 선택하기 위해 `variant`(`light` 또는 `dark`)을 받습니다. |
| `get_color` | 팔레트 색상에 대한 CSS 변수 참조를 반환합니다(예: `var(--ig-primary-500)`). 선택적 대비 및 불투명도 매개변수를 지원합니다. |
| `read_resource` | 네 가지 범주로 구성된 내장 참조 리소스를 읽습니다. 플랫폼 구성(6), 팔레트/타이포그래피/고도 프리셋(5), 색상 지침(7), 레이아웃/간격 문서(8)입니다. |

<DocsAside type="info">
복합 컴포넌트(예: `combo`, `select`, `grid`)의 경우, `get_component_design_tokens`은(는) 평평한 토큰 목록 대신 관련 하위 테마 목록을 반환합니다. 예를 들어 `grid`을(를) 조회하면 `grid`, `grid-toolbar`, `grid-filtering`, `paginator` 같은 하위 테마가 반환될 수 있습니다. AI는 적절한 범위 선택기를 사용하여 각 하위 테마마다 별도의 `create_component_theme` 호출을 생성합니다.
</DocsAside>

<DocsAside type="info">
프로젝트가 라이선스가 부여된 `@infragistics/igniteui-angular` 패키지를 사용하는 경우 AI에 이를 알려 주면, 팔레트, 테마 및 컴포넌트 도구에서 `licensed` 매개변수를 설정할 수 있습니다. 이에 따라 생성되는 import 경로가 조정됩니다.
</DocsAside>

## 일반적인 작업 흐름

다음 시나리오는 MCP 서버가 연결된 후 AI에 요청할 수 있는 작업을 보여 줍니다.

### 새 프로젝트 테마

> _"Ignite UI를 사용하는 새 Angular 프로젝트를 시작하려고 합니다. primary #2563eb, secondary #f97316, Roboto 글꼴을 사용하여 완전한 Material Design 밝은 테마를 만들어 주세요."_

AI는 `create_theme`을(를) 호출하고 바로 사용할 수 있는 `styles.scss` 파일을 반환합니다. 생성된 출력은 다음과 비슷하게 보입니다:

```scss
/* styles.scss */
@use 'igniteui-angular/theming' as *;

$my-palette: palette(
  $primary: #2563eb,
  $secondary: #f97316,
  $surface: #fff,
  $gray: #9e9e9e,
);

$my-typography: typography(
  $font-family: 'Roboto, sans-serif',
);

@include core();
@include typography($my-typography);
@include theme($my-palette, $schema: $light-material-schema);
```

### 어두운 모드 변형

> _"기존 테마의 어두운 모드 버전이 필요합니다. 기본 파란색은 그대로 유지하고 어두운 표면 색상 #121212를 사용해 주세요."_

### 브랜드 정확 색상 명도 단계

> _"우리 디자인 시스템은 기본 녹색의 14개 명도 단계 모두에 대한 정확한 hex 값을 지정합니다. 값을 붙여 넣을 테니 사용자 지정 팔레트를 만들어 주세요."_

AI는 기본 색상에 `mode: "explicit"`을(를) 지정하여 `create_custom_palette`을(를) 호출하고 나머지는 자동으로 생성합니다. 명도 단계 생성에 대한 자세한 내용은 [팔레트](https://www.infragistics.com/products/ignite-ui-angular/angular/components/themes/sass/palettes)를 참조하십시오.

### 컴포넌트 수준 사용자 지정

> _"flat 버튼의 배경을 보라색 #8b5cf6, 글자색을 흰색으로 스타일링하고, 마우스를 올렸을 때는 더 밝은 보라색 #a78bfa를 사용해 주세요."_

AI는 먼저 `get_component_design_tokens`을(를) 호출하여 유효한 토큰 이름을 찾은 다음, 올바른 값으로 `create_component_theme`을(를) 호출합니다.

### 레이아웃 조정

> _"calendar가 너무 크게 느껴집니다. 간격을 줄이고 모든 컴포넌트를 조금 더 작게 해 주세요."_

AI는 calendar 컴포넌트로 범위를 제한하여 `set_spacing`을(를) 호출하고, `:root` 수준에서 `set_size`을(를) 호출합니다.

## 문제 해결

**플랫폼이 감지되지 않음**

`detect_platform`이(가) `null` 또는 `generic`을 반환하면, `package.json`에 Ignite UI 패키지(예: `igniteui-angular`)가 종속성으로 나열되어 있는지 확인하십시오.

AI에 명시적으로 알려 줄 수도 있습니다: _"Angular 플랫폼을 사용하십시오."_

**색상의 명도 경고**

AI가 색상 명도에 대해 경고하면, 선택한 색상이 자동 명도 단계 생성이 잘 작동하기에는 너무 밝거나 너무 어둡다는 뜻입니다. 중간 명도의 색상을 고르거나, 대신 명시적인 명도 값으로 `create_custom_palette`을(를) 사용하도록 AI에 요청하십시오.

**표면 색상 불일치**

밝은 테마에는 밝은 표면 색상(예: `#fafafa`)을 사용하십시오. 어두운 테마에는 어두운 표면 색상(예: `#121212`)을 사용하십시오. 일치하지 않는 표면 색상은 AI가 경고를 출력하게 합니다.

**생성된 Sass가 컴파일되지 않음**

`igniteui-angular`과 `igniteui-theming`이(가) 설치되어 있는지 확인하십시오:

```bash
ng add igniteui-angular
```

또한 `styles.scss`의 다른 테마 믹스인보다 먼저 `core()`이(가) 호출되는지 확인하십시오. 올바른 파일 설정은 [Sass로 테마 적용하기](https://www.infragistics.com/products/ignite-ui-angular/angular/components/themes/sass/index)를 참조하십시오.
