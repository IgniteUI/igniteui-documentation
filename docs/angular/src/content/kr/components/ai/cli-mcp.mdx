# Ignite UI CLI MCP

<p class="highlight">Ignite UI CLI MCP는 AI 어시스턴트가 Ignite UI for Angular 애플리케이션의 프로젝트를 스캐폴딩하고, 기존 앱을 수정하고, 컴포넌트를 만들고 업데이트하며, 문서 질문에 답할 수 있도록 하는 <a href="https://modelcontextprotocol.io/" target="_blank">Model Context Protocol</a>(MCP) 서버입니다. Ignite UI CLI MCP를 편집기, GitHub 저장소 또는 데스크톱 AI 클라이언트에 연결하고 원하는 작업을 설명하면, 어시스턴트가 CLI 도구를 대신 사용합니다.</p>

<igc-divider></igc-divider>

## 개요

Ignite UI CLI MCP는 채팅 또는 에이전트 모드에서 AI 어시스턴트가 Ignite UI CLI 프로젝트 스캐폴딩, 컴포넌트 생성, 프로젝트 수정 및 문서 기반 작업 흐름에 직접 접근할 수 있도록 합니다. 이 서버는 [Ignite UI Theming MCP](./theming-mcp.mdx)와 함께 작동합니다. CLI MCP는 프로젝트와 컴포넌트 작업을, Theming MCP는 팔레트, 테마, 토큰 및 스타일링을 담당합니다. 대부분의 팀은 같은 AI 클라이언트 세션에서 두 서버를 모두 연결합니다.

권장 설정 방법은 먼저 Ignite UI CLI로 시작하는 것입니다. 이 방법은 프로젝트를 만들고, 필요한 패키지를 설치하며, 구성할 AI 클라이언트와 에이전트를 선택하라는 메시지를 표시합니다. 빈 폴더에서 시작하여 MCP를 통해 어시스턴트가 프로젝트를 만들도록 하거나, 이미 있는 프로젝트에 MCP를 연결할 수도 있습니다.

**연결한 후 시도해 볼 예제 프롬프트:**

> _"이 폴더에 새 Ignite UI for Angular 프로젝트를 만들고, 권장 기본값을 사용하며, 샘플 데이터가 있는 시작용 대시보드 페이지를 추가해 주세요."_

> _"이 프로젝트에 새 그리드 페이지를 추가하고 샘플 데이터에 연결하며, 현재의 탐색 구조는 그대로 유지해 주세요."_

> _"combo 컴포넌트가 노출하는 속성과 이벤트는 무엇이며, 검색 가능한 드롭다운에 가장 유용한 것은 무엇입니까?"_

> _"기존 프로젝트를 업데이트하여 사이드 내비게이션 레이아웃을 추가하고, 현재 페이지와 라우트는 그대로 유지해 주세요."_

## 사전 요구 사항

MCP 서버를 구성하기 전에 다음 항목을 준비하십시오:

- **Node.js**(v18 이상)가 설치되어 있어야 합니다. 서버를 실행하는 데 사용하는 `npx` 명령을 제공합니다.
- **MCP를 지원하는 AI 클라이언트**가 필요합니다. 예를 들어 GitHub Copilot이 포함된 VS Code, GitHub Copilot 클라우드 에이전트, Cursor, Claude Desktop, Claude Code 또는 AI Assistant 플러그인이 설치된 JetBrains IDE가 있습니다.
- 서버가 처음 시작될 때 `npx` 패키지를 확인하고 내려받을 수 있도록 인터넷에 연결되어 있어야 합니다.
- 다음 시작점 중 하나를 준비하십시오:
  - 새 프로젝트를 위한 빈 폴더
  - Ignite UI CLI로 만든 프로젝트
  - 계속 작업하려는 기존 Ignite UI for Angular 프로젝트

같은 클라이언트 세션에서 테마 도구를 사용하려는데 프로젝트에 `igniteui-theming`이(가) 아직 없다면 다음을 실행하십시오:

```bash
npm install igniteui-theming
```

## AI 클라이언트에 Ignite UI CLI MCP 구성하기

MCP 서버는 `npx`을 통해 실행됩니다. Node.js와 `igniteui-cli` 패키지에 접근할 수 있으면 그 밖의 별도 설치는 필요하지 않습니다.

표준 실행 명령은 다음과 같습니다:

```bash
npx -y igniteui-cli mcp
```

<DocsAside type="info">

`-y` 플래그는 `npx`에게 패키지 다운로드 확인 메시지를 자동으로 승인하도록 지시하므로, 서버가 수동 개입 없이 시작될 수 있습니다.

</DocsAside>


### 설정 방법 선택하기

Ignite UI CLI MCP는 다음 세 가지 방법으로 시작할 수 있습니다:

> **권장 - CLI 우선**
> `ig new` 또는 이에 해당하는 `npx --package igniteui-cli igniteui new` 명령을 사용하여 먼저 Ignite UI CLI로 프로젝트를 만드십시오. Ignite UI CLI가 프로젝트를 스캐폴딩하고, 필요한 패키지를 설치하며, MCP용으로 구성할 AI 클라이언트와 스킬 파일을 설정할 에이전트를 선택하라는 메시지를 표시하므로 가장 쉬운 설정 방법입니다. 그 후에는 생성된 구성을 검토하고 AI 클라이언트에서 프로젝트를 열기만 하면 됩니다.

> **빈 폴더**
> 완전히 빈 폴더에서 시작하여 MCP 구성을 직접 추가한 다음, 채팅을 통해 어시스턴트에게 프로젝트를 만들도록 요청하십시오. 이 방법은 CLI를 직접 먼저 실행하지 않고, 처음부터 MCP가 프로젝트 생성 흐름을 주도하기를 원할 때 유용합니다.

> **기존 프로젝트**
> 이미 있는 프로젝트에 MCP 구성을 추가하고 현재 코드베이스에서 계속 작업하십시오. `ig ai-config`(Angular 프로젝트의 경우 `ng generate @igniteui/angular-schematics:ai-config`)을 실행하여 선택한 AI 클라이언트용 MCP 구성을 작성하고 Agent Skills를 프로젝트에 복사하십시오. 이 명령은 구성할 클라이언트와 에이전트를 선택하라는 메시지를 표시합니다.

세 가지 방법 모두 같은 MCP 서버를 사용합니다. 차이는 프롬프트를 입력하기 전에 프로젝트를 준비하는 방식뿐입니다:

- **CLI 우선** 방법에서는 Ignite UI CLI가 프로젝트를 만들고 첫 MCP 구성을 준비합니다.
- **빈 폴더** 방법에서는 먼저 MCP 구성을 만들고, 그 후 어시스턴트가 프로젝트를 만듭니다.
- **기존 프로젝트** 방법에서는 `ig ai-config`를 실행하여 선택한 클라이언트용 MCP 구성을 작성하고 Agent Skills를 자동으로 복사합니다.

어느 경우든 MCP 서버가 연결되어 AI 클라이언트에 표시되면, 어시스턴트는 같은 세션에서 계속 작업할 수 있습니다.

Ignite UI CLI로 프로젝트를 먼저 만드는 경우, 다음 두 가지 방법 중 하나로 CLI를 실행할 수 있습니다:

- **전역 설치**

    ```bash
    npm install -g igniteui-cli
    ```

    이렇게 하면 모든 터미널 세션에서 `ig` 명령을 사용할 수 있으며, 프로젝트를 정기적으로 만들고 스캐폴딩할 계획이라면 가장 명확한 방법입니다.

- **전역 설치 없이**

    ```bash
    npx --package igniteui-cli igniteui new
    ```

    전역 `ig` 명령 대신 `npx`을 통해 CLI를 실행합니다.

**CLI 우선** 방법에서는 안내 모드 또는 직접 명령으로 프로젝트를 만들 수 있습니다.

CLI가 사용 가능한 옵션을 단계별로 안내하기를 원하면 안내 모드를 사용하십시오:

```bash
ig new
```

이에 해당하는 `npx` 형식:

```bash
npx --package igniteui-cli igniteui new
```

프로젝트 설정을 이미 알고 있다면 직접 명령을 사용하십시오:

```bash
ig new my-app --framework=angular --type=igx-ts --template=empty
```

이에 해당하는 `npx` 형식:

```bash
npx ig new my-app --framework=angular --type=igx-ts --template=empty
```

안내 모드에서 Ignite UI CLI는 프로젝트 이름, 프레임워크, 템플릿, 테마 및 컴포넌트 추가 여부 또는 설정 완료 여부를 묻습니다. 직접 모드에서는 명령 자체에 프레임워크와 지원되는 옵션을 입력합니다.

### VS Code

VS Code의 GitHub Copilot은 워크스페이스 수준 구성 파일을 통해 MCP 서버를 지원합니다. 프로젝트 루트에서 `ig ai-config`(또는 `ng generate @igniteui/angular-schematics:ai-config`)을 실행하면 이 파일이 자동으로 생성됩니다. 수동으로 구성하려면 프로젝트 루트에서 `.vscode/mcp.json` 파일을 만들거나 편집하십시오:

```json
{
  "servers": {
    "igniteui-cli": {
      "command": "npx",
      "args": ["-y", "igniteui-cli", "mcp"]
    },
    "igniteui-theming": {
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
    }
  }
}
```

Ignite UI CLI로 프로젝트를 먼저 만든 경우, 생성된 `.vscode/mcp.json`을 검토하고 두 항목이 모두 있는지 확인하십시오.

저장한 후 GitHub Copilot 채팅 패널을 열고 **Agent** 모드로 전환하면 Ignite UI CLI MCP 도구를 사용할 수 있습니다.

<DocsAside type="info">

VS Code의 MCP 지원에는 GitHub Copilot과 VS Code 1.99 이상이 필요합니다.

</DocsAside>


### Cursor

Cursor는 프로젝트 범위 MCP 구성을 지원합니다. 프로젝트 루트에서 `.cursor/mcp.json`을 만들거나 편집하십시오:

```json
{
  "mcpServers": {
    "igniteui-cli": {
      "command": "npx",
      "args": ["-y", "igniteui-cli", "mcp"]
    },
    "igniteui-theming": {
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
    }
  }
}
```

새 Cursor 채팅 세션을 열면 서버가 자동으로 인식됩니다.

<DocsAside type="info">

Cursor의 **Settings → MCP**에서 MCP 서버를 전역으로 구성할 수도 있습니다.

</DocsAside>


### Claude Desktop

Claude Desktop 구성 파일에 서버를 추가하십시오:

- **macOS**: `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "igniteui-cli": {
      "command": "npx",
      "args": ["-y", "igniteui-cli", "mcp"]
    },
    "igniteui-theming": {
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
    }
  }
}
```

저장한 후 Claude Desktop을 다시 시작하십시오. 채팅 입력 영역에 MCP 서버 표시기(슬라이더 아이콘)가 나타나면 MCP 도구가 활성화된 것입니다.

### Claude Code

Claude Code는 CLI와 프로젝트 범위 `.mcp.json` 파일을 통해 MCP 서버를 지원합니다. 구성을 팀과 공유하려면 프로젝트 루트에서 `.mcp.json`를 만들거나 편집하십시오:

```json
{
  "mcpServers": {
    "igniteui-cli": {
      "command": "npx",
      "args": ["-y", "igniteui-cli", "mcp"]
    },
    "igniteui-theming": {
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
    }
  }
}
```

또는 로컬 환경에서만 명령줄을 통해 서버를 추가할 수도 있습니다:

```bash
claude mcp add igniteui-cli -- npx -y igniteui-cli mcp
claude mcp add igniteui-theming -- npx -y igniteui-theming igniteui-theming-mcp
```

Claude Code 안에서 `/mcp` 명령을 사용하여 서버가 연결되었는지 확인하십시오.

### JetBrains IDE

JetBrains AI Assistant는 IDE 설정을 통해 MCP 서버를 지원합니다:

1. **Settings**(macOS에서는 **Preferences**)를 엽니다.

2. **Tools → AI Assistant → Model Context Protocol (MCP)**로 이동합니다.

3. **+ Add**를 클릭하고 **As JSON**을 선택하거나 양식 필드를 사용합니다.

4. 다음 구성을 입력합니다:

    ```json
    {
      "mcpServers": {
        "igniteui-cli": {
          "command": "npx",
          "args": ["-y", "igniteui-cli", "mcp"]
        },
        "igniteui-theming": {
          "command": "npx",
          "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"]
        }
      }
    }
    ```

5. **OK**를 클릭한 후 AI Assistant를 다시 시작하십시오.

<DocsAside type="info">

MCP 지원에는 JetBrains IDE에 AI Assistant 플러그인이 설치되어 활성화되어 있어야 합니다.

</DocsAside>


### 기타 MCP 클라이언트

MCP 호환 클라이언트를 사용하는 경우 다음 실행 명령과 함께 STDIO 전송을 사용하십시오:

```bash
npx -y igniteui-cli mcp
npx -y igniteui-theming igniteui-theming-mcp
```

### GitHub

GitHub Copilot 클라우드 에이전트는 저장소 수준 MCP 구성을 지원합니다. 저장소에서 다음을 수행하십시오:

1. 기본 저장소 페이지를 엽니다.
2. **Settings**를 클릭합니다.
3. 사이드바에서 **Copilot**으로 이동한 다음 **Cloud agent**를 선택합니다.
4. **MCP configuration** 섹션에 JSON을 붙여 넣습니다.
5. **Save**를 클릭합니다.

다음과 같은 저장소 구성을 사용하십시오:

```json
{
  "mcpServers": {
    "igniteui-cli": {
      "type": "local",
      "command": "npx",
      "args": ["-y", "igniteui-cli", "mcp"],
      "tools": ["*"]
    },
    "igniteui-theming": {
      "type": "local",
      "command": "npx",
      "args": ["-y", "igniteui-theming", "igniteui-theming-mcp"],
      "tools": ["*"]
    }
  }
}
```

GitHub 클라우드 에이전트가 저장소 컨텍스트에서 CLI MCP와 Theming MCP 도구를 직접 사용하기를 원할 때 이 설정이 유용합니다.

## 사용 가능한 도구

MCP 서버는 여러분의 프롬프트에 따라 AI가 자동으로 사용하는 도구 집합을 제공합니다. 이 도구들을 직접 호출할 필요는 없습니다. 채팅에서 원하는 작업을 설명하면 어시스턴트가 적절한 도구를 선택합니다. 이 표는 시작하기 전에 어떤 도구를 사용할 수 있는지 확인하기 위한 것입니다.

현재 매개변수가 포함된 최신 목록을 보려면 다음과 같이 질문하십시오:

> _"Ignite UI CLI MCP는 어떤 도구를 제공합니까?"_

각 도구에 대한 간단한 개요는 다음과 같습니다:

| 도구                      | 설명                                                                                                                                                          |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list_components`         | 프레임워크별로 사용 가능한 Ignite UI 컴포넌트 문서를 나열합니다. 선택 사항인 키워드 필터를 받으며, 이름, 키워드 및 요약에 대해 대소문자를 구분하지 않는 부분 문자열 일치를 수행합니다. |
| `get_doc`                 | kebab-case 이름(예: `grid-editing`, `combo-overview`)으로 특정 컴포넌트 문서의 전체 Markdown 내용을 가져옵니다. 코드 샘플, 표 및 링크를 포함합니다.   |
| `search_docs`             | 프레임워크의 Ignite UI 문서 전체에 대해 전체 텍스트 검색을 수행합니다. 발췌문과 함께 순위가 매겨진 최대 20개의 결과를 반환합니다.                                                              |
| `get_project_setup_guide` | 특정 프레임워크에서 새 프로젝트를 만드는 방법을 설명하는 프로젝트 설정 가이드를 반환합니다. CLI 단계와 설치 지침을 포함합니다.                                   |
| `search_api`              | Angular, React, Blazor 및 Web Components에서 키워드 또는 컴포넌트 이름으로 API 항목을 검색합니다.                                                                        |
| `get_api_reference`       | 특정 컴포넌트 또는 클래스의 전체 API 참조를 속성, 메서드 및 이벤트를 포함하여 반환합니다. Angular, React, Blazor 및 Web Components를 지원합니다.           |

전체적으로 CLI MCP 도구는 다음 작업을 돕습니다:

- 새 프로젝트 만들기
- 기존 프로젝트에서 작업하기
- 컴포넌트 추가 및 수정하기
- 프로젝트 구조 및 구성 업데이트하기
- 문서 및 API 질문에 답하기

<DocsAside type="info">

프레임워크 감지는 컴포넌트 접두사를 사용합니다: `for Angular`, `for React`, `for Web Components`, `for Blazor`. 어시스턴트는 열려 있는 파일이나 프롬프트 컨텍스트에서 올바른 프레임워크를 자동으로 파악합니다.

</DocsAside>


테마 서버는 같은 클라이언트 세션에 스타일링, 테마, 팔레트 및 토큰 작업 흐름을 추가합니다.

## 일반적인 작업 흐름

다음 설정 시나리오는 각 시작점을 언제 사용해야 하는지 보여 줍니다.

### CLI 우선 설정

가장 빠른 안내형 설정을 원하면 먼저 Ignite UI CLI로 프로젝트를 만드십시오. `ig new`은 MCP용으로 구성할 AI 클라이언트와 스킬 파일을 설정할 에이전트를 선택하라는 메시지를 표시합니다.

예시 시나리오:

- _"먼저 Ignite UI CLI로 새 프로젝트를 만들고, 생성된 프로젝트를 VS Code에서 연 다음, MCP로 이어서 작업하고 싶습니다."_
- _"React 프로젝트를 만들고 싶다는 것은 이미 정했습니다. CLI로 만든 다음 MCP를 사용해 페이지와 컴포넌트를 추가하고 싶습니다."_

### 빈 폴더 설정

MCP 구성을 직접 추가한 후 채팅에서 어시스턴트가 프로젝트를 만들도록 하려면 빈 폴더에서 시작하십시오.

예시 시나리오:

- _"완전히 빈 폴더가 있고, MCP가 연결된 후 채팅을 통해 어시스턴트가 프로젝트 전체를 만들었으면 합니다."_
- _"Ignite UI CLI를 먼저 수동으로 실행하고 싶지 않습니다. MCP가 첫 번째 프로젝트 생성 단계를 주도했으면 합니다."_

### 기존 프로젝트 설정

현재 코드베이스를 유지하고 프로젝트 변경, 컴포넌트 작업 및 문서 질문에 어시스턴트를 활용하려면 기존 프로젝트에 MCP를 연결하십시오.

예시 시나리오:

- _"이미 프로젝트가 있고, 어시스턴트가 페이지와 컴포넌트를 업데이트하도록 MCP만 추가하고 싶습니다."_
- _"프로젝트는 이미 있고, 현재 코드베이스에서 작업하면서 주로 문서와 API 질문을 하고 싶습니다."_

## 문제 해결

**`npx`을(를) 인식할 수 없습니다**

Node.js가 설치되어 있지 않거나 현재 터미널 환경에서 사용할 수 없습니다. [nodejs.org](https://nodejs.org)에서 Node.js를 설치하고 `node --version`로 확인하십시오.

**`ig`을(를) 인식할 수 없습니다**

전역 `ig` 명령을 사용하려면 먼저 `npm install -g igniteui-cli`로 Ignite UI CLI를 설치하십시오. 전역 설치를 원하지 않으면 대신 `npx --package igniteui-cli igniteui ...` 형식을 사용하십시오.

**구성을 저장한 후 MCP 도구가 나타나지 않습니다**

워크스페이스를 다시 로드하거나, 편집기를 다시 열거나, AI 클라이언트를 다시 시작하십시오. 일부 클라이언트는 새 MCP 구성 파일을 인식하려면 완전히 다시 시작해야 합니다.

**하나의 서버가 시작되지 않습니다**

키 이름과 인수 순서를 포함하여 구성 내용이 예시와 정확히 일치하는지 확인하십시오.

**프로젝트는 만들어졌지만 AI 클라이언트 중 하나에 대해 MCP가 구성되지 않았습니다**

`ig new`은 구성할 클라이언트를 선택하라는 메시지를 표시합니다. 프로젝트를 만드는 동안 클라이언트를 건너뛰었다면 `ig ai-config`를 실행하고 메시지가 표시될 때 누락된 클라이언트를 선택하십시오.

**어시스턴트가 잘못된 폴더에서 작업하거나 프로젝트 파일을 찾을 수 없습니다**

AI 클라이언트가 프로젝트 루트를 가리키고 있는지 확인하십시오. 편집기 기반 클라이언트를 사용한다면 프로젝트 루트 폴더를 여십시오. 데스크톱 또는 채팅 중심 클라이언트를 사용한다면 올바른 프로젝트 폴더를 세션 컨텍스트로 사용할 수 있도록 하십시오.

**빈 폴더 설정이 예상대로 동작하지 않습니다**

시작하기 전에 폴더가 실제로 비어 있는지 확인하십시오. 폴더에 이미 프로젝트 파일이 있다면 새 빈 작업 공간으로 취급하지 말고 기존 프로젝트 방법을 사용하십시오.

**GitHub MCP 구성이 거부됩니다**

JSON이 `mcpServers` 구조를 사용하는지, 그리고 각 로컬 서버 항목에 `type`, `command`, `args`가 포함되어 있는지 확인하십시오. `tools` 필드를 포함하는 경우 올바른 도구 이름 또는 `["*"]`를 사용하십시오.
